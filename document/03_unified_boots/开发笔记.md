## 1. 重构动机

### 1.1 两阶段架构的问题

在 `stage/02_kernel_asm_loader` 中，bootloader 由两个独立文件组成：

```
boot/
├── boot.asm     # Stage 1 (MBR, 512 bytes)
└── boot2.asm    # Stage 2 (加载器)
```

**存在的问题**:

#### 问题 1: 代码重复
```asm
; boot.asm 中
print_string:
    pusha
.loop:
    lodsb
    test al, al
    jz .done
    mov ah, 0x0e
    int 0x10
    jmp .loop
.done:
    popa
    ret

; boot2.asm 中 (几乎完全相同的代码)
print_bios:
    pusha
.loop:
    lodsb
    test al, al
    jz .done
    mov ah, 0x0e
    int 0x10
    jmp .loop
.done:
    popa
    ret
```

#### 问题 2: 构建复杂
```makefile
# 需要分别编译两个文件
$(BOOT_BIN): $(BOOT_ASM)
    $(AS) $(ASFLAGS) $< -o $@

$(BOOT2_BIN): $(BOOT2_ASM)
    $(AS) $(ASFLAGS) $< -o $@

# 然后手动组合
dd if=$(BOOT_BIN) of=$(BOOT_IMG) bs=512 count=1
dd if=$(BOOT2_BIN) of=$(BOOT_IMG) bs=512 seek=1
```

#### 问题 3: 维护困难
- 修改一个函数需要在两个文件中同步
- 难以追踪 Stage 1 到 Stage 2 的跳转
- 代码审查时需要在文件间切换

### 1.2 统一架构的优势

#### 优势 1: 单文件管理
```asm
; bootloader.asm - 包含所有内容
section .mbr
    org 0x7c00
    bits 16
    ; Stage 1 代码

section .stage2 vstart=0x7E00
    bits 16
    ; Stage 2 代码
```

#### 优势 2: 模块化库
```
boot/lib/
├── bios_screen.asm    # 屏幕操作
├── bios_string.asm    # 字符串操作
├── disk_io.asm        # 磁盘 I/O
├── pmode.asm          # 保护模式
└── lmode.asm          # 长模式
```

#### 优势 3: 简化构建
```makefile
# 只需编译一次
$(BOOTLOADER_BIN): $(BOOTLOADER_ASM)
    $(AS) $(ASFLAGS) $< -o $@
```

## 2. 设计决策

### 2.1 单文件 vs 多文件

#### 选项 A: 保持多文件
```
boot/
├── boot.asm
├── boot2.asm
└── lib/
    └── ...
```

**优点**: 职责分离清晰
**缺点**: 仍然需要分别编译

#### 选项 B: 单文件统一 (选择)
```
boot/
├── bootloader.asm
└── lib/
    └── ...
```

**优点**:
- 一次编译完成
- 代码集中管理
- 跳转关系清晰

**缺点**: 文件较大

### 2.2 Section 组织方式

#### NASM Section 语法

```asm
; Stage 1: MBR (加载到 0x7C00)
section .mbr
    org 0x7c00
    bits 16
start:
    ; ... Stage 1 代码

; Stage 2: (加载到 0x7E00)
section .stage2 vstart=0x7E00
    bits 16
stage2_entry:
    ; ... Stage 2 代码
```

**关键概念**:
- `org` - 设置起始地址
- `vstart` - 设置虚拟起始地址 (重要!)
- `bits` - 设置指令模式

#### vstart 的重要性

```asm
; 没有 vstart (错误)
section .stage2
gdt_ptr:
    dd gdt_start    ; 会被计算为相对于文件开头的偏移!

; 有 vstart (正确)
section .stage2 vstart=0x7E00
gdt_ptr:
    dd gdt_start    ; 正确计算为 0x7E00 + 偏移
```

### 2.3 库函数设计

#### 命名规范

```asm
; bios_screen.asm
clear_screen:           ; 清屏
clear_screen64:         ; 清屏 (64位版本)

; bios_string.asm
print_string:           ; 打印字符串 (BIOS)
print_bios:             ; 同上 (别名)

; disk_io.asm
load_second_stage:      ; 加载第二阶段
load_kernel:            ; 加载内核
load_kernel_auto:       # 自动 LBA/CHS 选择

; pmode.asm
setup_page_tables:      ; 设置页表

; lmode.asm
clear_screen64:         ; 清屏 (64位)
print_string64:         ; 打印字符串 (64位)
```

#### 调用约定

```asm
; 统一的调用约定
; Input: 寄存器/内存参数
; Output: 返回值 (如有的话)
; Clobbers: 破坏的寄存器列表

; 示例
; Input: SI = 字符串指针
; Output: none
; Clobbers: AX, SI
print_string:
    ; ...
```

## 3. 实现过程

### 3.1 重构步骤

#### 步骤 1: 提取库函数

**从 boot.asm 提取**:
```asm
; 原始 boot.asm
start:
    call print_string
    call load_second_stage
    jmp 0x7E00

print_string:
    ; ... 打印函数

load_second_stage:
    ; ... 加载函数
```

**重构后**:
```asm
; bootloader.asm
%include "lib/bios_string.asm"
%include "lib/disk_io.asm"

start:
    call print_string
    call load_second_stage
    jmp 0x7E00

; lib/bios_string.asm
print_string:
    ; ... 打印函数

; lib/disk_io.asm
load_second_stage:
    ; ... 加载函数
```

#### 步骤 2: 合并 Stage 1 和 Stage 2

**原始结构**:
```asm
; boot.asm (独立编译)
section .mbr
    org 0x7c00
    ; ... Stage 1
times 510-($-$$) db 0
dw 0xaa55

; boot2.asm (独立编译)
org 0x7E00
    ; ... Stage 2
```

**统一后**:
```asm
; bootloader.asm (一次编译)
section .mbr
    org 0x7c00
    ; ... Stage 1
times 510-($-$$) db 0
dw 0xaa55

section .stage2 vstart=0x7E00
    ; ... Stage 2
```

#### 步骤 3: 更新 Makefile

**之前**:
```makefile
BOOT_ASM = boot.asm
BOOT2_ASM = boot2.asm

BOOT_BIN = build/boot.bin
BOOT2_BIN = build/boot2.bin

all: $(BOOT_IMG)

$(BOOT_BIN): $(BOOT_ASM)
    $(AS) $(ASFLAGS) $< -o $@

$(BOOT2_BIN): $(BOOT2_ASM)
    $(AS) $(ASFLAGS) $< -o $@

$(BOOT_IMG): $(BOOT_BIN) $(BOOT2_BIN) $(KERNEL_BIN)
    dd if=$(BOOT_BIN) of=$@ bs=512 count=1
    dd if=$(BOOT2_BIN) of=$@ bs=512 seek=1
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=3
```

**之后**:
```makefile
BOOTLOADER_ASM = bootloader.asm

BOOTLOADER_BIN = build/bootloader.bin

all: $(BOOT_IMG)

$(BOOTLOADER_BIN): $(BOOTLOADER_ASM)
    $(AS) $(ASFLAGS) $< -o $@

$(BOOT_IMG): $(BOOTLOADER_BIN) $(KERNEL_BIN)
    dd if=$(BOOTLOADER_BIN) of=$@ bs=512 count=2
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=2
```

### 3.2 扇区布局变化

#### 之前 (两阶段)
```
扇区 1:      boot.bin    (Stage 1, 512 bytes)
扇区 2-3:    boot2.bin   (Stage 2, ~740 bytes)
扇区 4+:     kernel.bin  (内核)
```

#### 之后 (统一)
```
扇区 1-2:    bootloader.bin  (Stage 1+2, ~1024 bytes)
扇区 3+:     kernel.bin      (内核)
```

**关键变化**: 内核起始扇区从 4 变为 3

## 4. 挑战与解决

### 4.1 Section 地址计算

#### 问题: vstart 使用不当

```asm
; 错误示例
section .stage2
    org 0x7E00
gdt_ptr:
    dw gdt_end - gdt_start - 1
    dd gdt_start    ; 错误! 会是相对于文件开头的偏移
```

**问题分析**:
- `org` 只影响 `org` 之后定义的标签
- 但 `dd gdt_start` 中的 `gdt_start` 仍然使用文件偏移

#### 解决方案: 使用 vstart

```asm
; 正确示例
section .stage2 vstart=0x7E00
gdt_ptr:
    dw gdt_end - gdt_start - 1
    dd gdt_start    ; 正确! 0x7E00 + gdt_start 的偏移
```

**vstart 工作原理**:
- `vstart` 告诉 NASM 将此 section 的标签加上这个偏移
- 所有在此 section 定义的标签都会加上 `vstart` 值

### 4.2 跨 Section 引用

#### 问题: 数据放在错误的 section

```asm
; 错误
section .stage2 vstart=0x7E00
    bits 16
stage2_main:
    mov si, msg_stage2
    call print_bios

section .text    ; 新 section!
msg_stage2:
    db "Stage 2...", 0
```

**问题**: `msg_stage2` 的地址计算错误

#### 解决方案: 数据放在正确的 section

```asm
; 正确
section .stage2 vstart=0x7E00
    bits 16
stage2_main:
    mov si, msg_stage2
    call print_bios

msg_stage2:
    db "Stage 2...", 0    ; 在同一 section
```

### 4.3 库函数的 bits 模式

#### 问题: 混用不同 bits 模式

```asm
; bios_string.asm
bits 16    ; 16 位模式
print_string:
    ; ...

; pmode.asm
bits 32    ; 32 位模式
setup_page_tables:
    ; ...

; 如果在 bootloader 中这样包含:
%include "lib/bios_string.asm"    ; 设置 bits 16
%include "lib/pmode.asm"          ; 设置 bits 32
; 后续代码会变成 bits 32!
```

#### 解决方案: 显式设置 bits

```asm
; bootloader.asm
section .stage2 vstart=0x7E00
    bits 16
stage2_main:
    ; 16 位代码

; 32 位代码需要显式声明
bits 32
pm_entry:
    ; 32 位代码
```

**最佳实践**: 每个 section 之前显式声明 `bits`

## 5. 模块化设计

### 5.1 库函数职责

| 库文件 | 职责 | 主要函数 |
|--------|------|----------|
| `bios_screen.asm` | BIOS 屏幕操作 | `clear_screen` |
| `bios_string.asm` | BIOS 字符串操作 | `print_string`, `print_bios` |
| `disk_io.asm` | 磁盘 I/O | `load_second_stage`, `load_kernel` |
| `pmode.asm` | 保护模式设置 | `setup_page_tables` |
| `lmode.asm` | 长模式操作 | `clear_screen64`, `print_string64` |

### 5.2 依赖关系

```
bootloader.asm
├── bios_string.asm
│   └── (无依赖)
├── bios_screen.asm
│   └── (无依赖)
├── disk_io.asm
│   └── bios_string.asm
├── pmode.asm
│   └── (无依赖)
└── lmode.asm
    └── (无依赖)
```

### 5.3 接口设计

#### 统一的错误处理

```asm
; disk_io.asm
load_kernel_auto:
    pusha
    call check_lba_support
    jc .try_chs
    ; ...
    clc     ; 成功
    ret
.error:
    stc     ; 失败
    ret
```

**调用者可以检查 CF 标志**:
```asm
call load_kernel_auto
jc load_error    ; 如果 CF=1，加载失败
```

## 6. 经验总结

### 6.1 设计原则

#### 原则 1: 单一职责
每个库文件只负责一类功能：
- `bios_string.asm` 只处理字符串
- `disk_io.asm` 只处理磁盘 I/O

#### 原则 2: 最小依赖
库函数之间的依赖要尽可能少：
- 如果需要其他库的功能，考虑是否应该合并
- 保持接口简单

#### 原则 3: 明确约定
所有库函数都要有清晰的调用约定：
```asm
; 函数说明
; Input: 寄存器参数
; Output: 返回值
; Clobbers: 破坏的寄存器
```

### 6.2 重构经验

#### 经验 1: 小步重构
不要一次性重写所有代码：
1. 先提取一个库函数
2. 测试验证
3. 再提取下一个

#### 经验 2: 保持向后兼容
重构期间保持旧代码可用：
```asm
; 保留旧名称作为别名
print_bios:
    jmp print_string
```

#### 经验 3: 测试驱动
每次修改后立即测试：
```bash
make clean && make
qemu-system-x86_64 -drive format=raw,file=build/boot.img
```

### 6.3 避免的陷阱

#### 陷阱 1: 过度抽象
```asm
; 不要创建不必要的抽象层
; bad:
call print_to_bios_via_string_lib_wrapper

; good:
call print_string
```

#### 陷阱 2: 忽略 bits 模式
```asm
; 总是显式声明 bits
section .stage2 vstart=0x7E00
    bits 16    ; 不要省略!
```

#### 陷阱 3: 忘记更新扇区计算
重构后内存布局变化，要更新:
- 扇区加载地址
- Makefile 中的 dd 命令
- 硬编码的扇区号

### 6.4 未来改进

#### 改进 1: 配置文件
```asm
; boot_config.inc
KERNEL_LBA_START      equ 2
KERNEL_SECTOR_COUNT   equ 1
KERNEL_LOAD_SEGMENT   equ 0x1000
```

#### 改进 2: 错误码定义
```asm
; error_codes.inc
ERROR_SUCCESS       equ 0
ERROR_DISK_READ     equ 1
_ERROR_LBA_NOT_SUPP equ 2
```

#### 改进 3: 单元测试
为每个库函数编写测试：
```asm
; test_disk_io.asm
test_load_kernel:
    call load_kernel
    jc .fail
    ; 验证加载的内容
    ret
.fail:
    mov si, msg_test_fail
    call print_string
    jmp $
```

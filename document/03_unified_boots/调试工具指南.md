## 1. 反汇编验证

### 1.1 基本反汇编

#### 使用 ndisasm

```bash
# 反汇编整个 bootloader
ndisasm -b 16 build/bootloader.bin > bootloader.dis

# 反汇编特定偏移
ndisasm -b 16 -o 0x7C00 build/bootloader.bin > mbr.dis
ndisasm -b 16 -o 0x7E00 build/bootloader.bin > stage2.dis
```

#### 检查 MBR 签名

```bash
# 检查最后两字节是否为 AA55
xxd -s 0x1FE -l 2 build/bootloader.bin

# 预期输出:
# 000001fe: 55aa                                    U.
```

### 1.2 Section 布局验证

#### 查看文件大小

```bash
# 检查 bootloader 大小
ls -lh build/bootloader.bin

# 预期: 约 1-2KB (两个扇区)
# -rw-r--r-- 1 user user 1.5K Feb 16 12:00 bootloader.bin
```

#### 查看各 section 大小

```bash
# 使用 objdump (如果包含调试符号)
nasm -f elf64 boot/bootloader.asm -o build/bootloader.o
objdump -h build/bootloader.o

# 输出示例:
# Idx Name          Size      VMA               LMA               File off
#   0 .mbr          00000200  0000000000007c00  0000000000007c00  00000000
#   1 .stage2       00000400  0000000000007e00  0000000000007e00  00000200
```

### 1.3 验证跳转目标

#### 检查 Stage 1 到 Stage 2 的跳转

```bash
# 反汇编并查找 jmp 0x7E00
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | grep "7E00"

# 预期输出:
# 000007EA  EA00007E00      jmp far 0x0000:0x7E00
```

#### 检查保护模式跳转

```bash
# 查找 far jump 指令
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | grep -E "(EA|66 EA)"

# 预期输出:
# 000007F3  66EA            db 0x66, 0xEA
# 000007F5  [32-bit offset] dd pm_entry
# 000007F9  [segment]      dw 0x0008
```

## 2. Section 偏移计算

### 2.1 计算标签地址

#### 在同一 section 内

```asm
section .mbr
    org 0x7C00
start:
    jmp main
    ; ...

main:
    ; main 的地址 = 0x7C00 + main 相对于 start 的偏移
```

#### 跨 section 引用

```asm
section .mbr
    org 0x7C00
start:
    ; ...

section .stage2 vstart=0x7E00
gdt_start:
    dq 0

gdt_ptr:
    dd gdt_start    ; = 0x7E00 + (gdt_start 在 .stage2 中的偏移)
```

### 2.2 验证 vstart 计算

#### 方法 1: 反汇编

```bash
# 反汇编 Stage 2
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | head -20

# 输出中的地址应该从 0x7E00 开始
```

#### 方法 2: 查看符号表

```bash
# 编译时生成调试信息
nasm -f bin -F dwarf boot/bootloader.asm -o build/bootloader.bin

# 使用 objdump 查看符号
objdump -t build/bootloader.bin
```

### 2.3 手动计算示例

#### 计算 GDT 指针

```asm
section .stage2 vstart=0x7E00
stage2_entry:
    jmp short stage2_main
    nop        ; 偏移 2

gdt_start:
    dq 0       ; 偏移 3-10
gdt_code:
    dq 0x00CF9A000000FFFF  ; 偏移 11-18
gdt_data:
    dq 0x00CF92000000FFFF  ; 偏移 19-26
gdt_code64:
    dq 0x00AF9A000000FFFF  ; 偏移 27-34
gdt_end:                        ; 偏移 35

gdt_ptr:
    dw gdt_end - gdt_start - 1  ; = 35 - 3 - 1 = 31 (0x1F)
    dd gdt_start                ; = 0x7E00 + 3 = 0x7E03
```

**验证**:
```bash
# 反汇编查看
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | grep -A5 "gdt_ptr"

# 应该看到:
# 地址         机器码              汇编
# 000007E23    1F00               dw 0x001F
# 000007E25    037E0000           dd 0x00007E03
```

## 3. 符号调试

### 3.1 生成调试信息

#### NASM 调试选项

```bash
# 生成 DWARF 调试信息
nasm -f bin -F dwarf boot/bootloader.asm -o build/bootloader.bin

# 生成列表文件
nasm -f bin -l build/bootloader.lst boot/bootloader.asm -o build/bootloader.bin
```

### 3.2 使用列表文件

#### 列表文件内容

```
     1  ; CCOS Unified Bootloader
     2
     3  section .mbr
     4      org 0x7C00
     5      bits 16
     6
     7  start:
     7 00000000 FA                        cli
     8 00000001 31C0                      xor ax,ax
     9 00000003 8ED8                      mov ds,ax
    10 00000005 8EC0                      mov es,ax
```

**列说明**:
- 第 1 列: 源代码行号
- 第 2 列: 文件偏移
- 第 3 列: 机器码
- 第 4 列: 汇编指令

### 3.3 GDB 符号调试

#### 创建 GDB 脚本

```gdb
# debug.gdb
# 设置架构
set architecture i386:x86-64

# 加载符号
symbol-file build/bootloader.bin

# 设置断点
break *0x7C00    # Stage 1 入口
break *0x7E00    # Stage 2 入口

# 连接到 QEMU
target remote :1234
```

#### 调试会话

```bash
# 启动 QEMU (等待调试器)
qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S

# 在另一个终端启动 GDB
gdb -x debug.gdb
```

## 4. 运行时验证

### 4.1 添加调试输出

#### VGA 调试

```asm
; 在关键点输出字符到 VGA
mov edi, 0xB8000
mov word [edi], 0x1F41    ; 'A' 白字蓝底
```

#### 串口调试

```asm
; 输出调试字符到串口
mov al, 'A'
call serial_write_char_blocking
```

### 4.2 验证内存布局

#### 检查 GDT 加载

```asm
; 在加载 GDT 后
lgdt [gdt_ptr]

; 验证: 读取 GDTR
store_gdtr:
    ; 使用 80 年代的方法
    mov eax, 0x7E03
    ; ... 比较
```

#### 检查页表设置

```asm
; 在设置页表后验证
; PML4[0] 应该指向 PDPT
mov eax, [0x9000]
; EAX = 0x0000A003 (预期)
```

### 4.3 单步执行验证

#### QEMU 监控命令

```bash
# 启动 QEMU 时启用监控
qemu-system-x86_64 -drive format=raw,file=build/boot.img -monitor stdio

# 在监控器中
(qemu) info registers    # 查看寄存器
(qemu) xp /10x 0x7C00   # 查看内存
(qemu) x/10i $pc        # 反汇编当前指令
```

## 5. QEMU 调试技巧

### 5.1 启动调试模式

#### 基本调试

```bash
# -s: 等待 GDB 连接 (默认端口 1234)
# -S: 启动时暂停 CPU
qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S
```

#### 带 GDB 服务器的调试

```bash
# 指定端口
qemu-system-x86_64 -drive format=raw,file=build/boot.img -gdb tcp::1234
```

### 5.2 GDB 调试会话

#### 连接和设置断点

```gdb
# 连接到 QEMU
(gdb) target remote :1234

# 设置断点
(gdb) break *0x7C00
Breakpoint 1 at 0x7C00

(gdb) break *0x7E00
Breakpoint 2 at 0x7E00

# 继续执行
(gdb) continue
Continuing.

# 断点命中后
Breakpoint 1, 0x00007c00 in ?? ()
(gdb) x/10i $pc    # 反汇编当前指令
=> 0x7c00:    cli
   0x7c01:    xor ax,ax
   0x7c03:    mov ds,ax
```

#### 查看内存和寄存器

```gdb
# 查看寄存器
(gdb) info registers

# 查看特定寄存器
(gdb) print $eax
(gdb) print/x $cr0

# 查看内存
(gdb) x/10xb 0x7C00
(gdb) x/1wd 0x7E00    # 查看 GDT 指针

# 反汇编
(gdb) x/20i 0x7C00
```

#### 单步执行

```gdb
# 单步执行 (跳过函数调用)
(gdb) nexti

# 单步执行 (进入函数调用)
(gdb) stepi

# 继续执行
(gdb) continue
```

### 5.3 多模式调试

#### 16 位实模式

```gdb
# 设置架构
(gdb) set architecture i8086

# 反汇编 16 位代码
(gdb) set disassembly-flavor intel
(gdb) x/10i $cs:0x7C00
```

#### 32 位保护模式

```gdb
# 切换到 32 位模式
(gdb) set architecture i386

# 查看 CR0 寄存器
(gdb) print/x $cr0
$1 = 0x1    ; PE 位已设置
```

#### 64 位长模式

```gdb
# 设置 64 位架构
(gdb) set architecture i386:x86-64

# 查看 64 位寄存器
(gdb) print $rax
(gdb) print $rsp
```

## 6. 常见问题诊断

### 6.1 Stage 1 无法跳转到 Stage 2

#### 症状
- 系统在 Stage 1 后挂起
- VGA 显示停止

#### 诊断步骤

```bash
# 1. 检查 MBR 签名
xxd -s 0x1FE -l 2 build/bootloader.bin

# 2. 检查跳转指令
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | grep jmp

# 3. 检查 Stage 2 是否正确加载
qemu-system-x86_64 -drive format=raw,file=build/boot.img -d int,cpu_reset
```

#### 常见原因

1. **扇区加载错误**
   - 检查 AL 寄存器 (实际读取的扇区数)
   - 检查 CF 标志 (错误指示)

2. **跳转地址错误**
   - 确保 `jmp 0x7E00` (near jump)
   - 或 `jmp 0x0000:0x7E00` (far jump)

### 6.2 GDT 加载失败

#### 症状
- Triple Fault (系统重启)
- 保护模式切换后挂起

#### 诊断步骤

```gdb
# 在 GDT 加载前设置断点
(gdb) break *0x7E50
(gdb) continue

# 查看 GDT 内容
(gdb) x/5wx 0x7E03

# 应该看到 5 个 64 位描述符
```

#### 验证 GDT 指针

```asm
; 添加验证代码
lgdt [gdt_ptr]

; 验证: 读取回 GDTR (使用特殊方法)
; 注意: x86 没有直接读取 GDTR 的指令
; 可以通过尝试加载段选择子来验证
```

### 6.3 Section 地址计算错误

#### 症状
- 跳转到错误地址
- 数据访问异常

#### 诊断方法

```bash
# 生成列表文件
nasm -l bootloader.lst boot/bootloader.asm -o build/bootloader.bin

# 查找标签地址
grep "gdt_ptr" bootloader.lst
```

#### 修复方法

```asm
; 确保 section 有正确的 vstart
section .stage2 vstart=0x7E00    ; 不要省略 vstart!
```

### 6.4 库函数调用失败

#### 症状
- 调用库函数后系统挂起
- 返回值错误

#### 诊断步骤

```gdb
# 在库函数入口设置断点
(gdb) break print_string

# 检查输入参数
(gdb) print $si    ; 字符串指针

# 单步执行
(gdb) stepi
```

#### 常见原因

1. **bits 模式不匹配**
   - 在 32 位模式调用 16 位函数
   - 解决: 显式设置 `bits`

2. **调用约定错误**
   - 寄存器参数位置错误
   - 检查函数文档

3. **栈未正确设置**
   - SP 指向错误位置
   - 解决: 在入口点初始化栈

## 7. 工具速查表

### 7.1 常用命令

| 任务 | 命令 |
|------|------|
| 编译 | `nasm -f bin file.asm -o output.bin` |
| 反汇编 | `ndisasm -b 16 -o 0x7C00 file.bin` |
| 查看十六进制 | `xxd file.bin` 或 `hexdump -C file.bin` |
| 运行 QEMU | `qemu-system-x86_64 -drive file=boot.img,format=raw` |
| 调试模式 | `qemu-system-x86_64 -s -S -drive file=boot.img,format=raw` |
| GDB 连接 | `gdb -ex "target remote :1234"` |

### 7.2 GDB 常用命令

| 命令 | 说明 |
|------|------|
| `break *0x7C00` | 在地址设置断点 |
| `continue` | 继续执行 |
| `stepi` | 单步执行 |
| `nexti` | 单步执行 (跳过调用) |
| `info registers` | 显示所有寄存器 |
| `print $eax` | 显示寄存器值 |
| `x/10i $pc` | 反汇编当前指令 |
| `x/10wx 0x7C00` | 查看内存 (字) |
| `set architecture i386:x86-64` | 设置架构 |

## 1. Section 跳转问题

### 1.1 问题描述

#### 症状
- Stage 1 代码执行完成后系统挂起
- 看不到 Stage 2 的任何输出
- QEMU 显示没有更多活动

#### 背景
从两阶段架构重构为统一架构后，将 Stage 1 和 Stage 2 放在同一文件的不同 section 中。

### 1.2 诊断过程

#### 步骤 1: 检查 MBR 签名

```bash
xxd -s 0x1FE -l 2 build/bootloader.bin

# 输出:
# 000001fe: 55aa                                    U.
```
**结论**: MBR 签名正确

#### 步骤 2: 反汇编检查跳转指令

```bash
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | grep -A5 -B5 "jmp"

# 输出:
# 000007EA  EA00007E00      jmp far 0x0000:0x7E00
```
**结论**: 跳转指令存在，目标是 0x7E00

#### 步骤 3: 检查 Stage 2 是否在正确位置

```bash
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | head -10

# 输出:
# 00007E00  EB00            jmp short 0x7E02
# 00007E02  90              nop
```
**结论**: Stage 2 代码从偏移 512 (0x200) 开始，但反汇编显示地址从 0x7E00 开始

### 1.3 根本原因

**问题**: Section 定义中缺少 `vstart`

```asm
; 错误的代码
section .stage2
    org 0x7E00    ; org 只影响代码段起始，不影响标签计算
stage2_entry:
    ; ...
```

**分析**:
- `org` 设置代码的期望加载地址
- 但标签仍使用文件偏移计算
- 导致跳转目标地址计算错误

### 1.4 解决方案

#### 修复代码

```asm
; 正确的代码
section .stage2 vstart=0x7E00    ; 添加 vstart!
stage2_entry:
    jmp short stage2_main
    nop
```

#### 验证修复

```bash
# 重新编译
make clean && make

# 反汇编验证
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | head -5

# 应该看到:
# 00007E00  EBXX            jmp short ...
```

### 1.5 经验总结

1. **vstart 的作用**
   - `org`: 告诉代码期望加载到哪个地址
   - `vstart`: 告诉 NASM 如何计算此 section 中的标签

2. **何时使用 vstart**
   - 代码加载地址 ≠ 文件偏移时
   - 跨 section 引用时
   - 非标准加载地址时

3. **最佳实践**
   - 每个 section 都显式声明 `org` 和 `vstart`
   - 使用相同的值简化理解: `org 0x7E00` + `vstart=0x7E00`

## 2. vstart 地址计算错误

### 2.1 问题描述

#### 症状
- GDT 加载后立即 Triple Fault
- 保护模式切换失败
- 系统重启

#### 背景
在 Stage 2 中定义 GDT，使用 `gdt_ptr` 加载到 GDTR 寄存器。

### 2.2 诊断过程

#### 步骤 1: 检查 GDT 指针内容

```asm
; 添加调试代码
lgdt [gdt_ptr]

; 读取回显示 (通过尝试访问)
mov eax, [gdt_ptr]    ; EAX 应该包含 limit 和 base
```

#### 步骤 2: 使用 GDB 检查

```gdb
# 在 lgdt 指令前设置断点
(gdb) break *0x7E50
(gdb) continue

# 查看 gdt_ptr 的内容
(gdb) x/2wx 0x7E03

# 实际输出:
# 0x7E03: 0x001f    ; limit (错误!)
# 0x7E07: 0x0000    ; base (错误!)
```

#### 步骤 3: 分析问题

```asm
; 问题代码
section .stage2 vstart=0x7E00
stage2_entry:
    ; 一些代码...

gdt_start:
    dq 0

gdt_ptr:
    dw gdt_end - gdt_start - 1
    dd gdt_start    ; 这里计算错误!
```

**分析**:
- `gdt_start` 在 section 偏移处 (假设偏移 0x10)
- 但 `vstart=0x7E00`，所以 `gdt_start` 应该 = 0x7E10
- 如果没有正确应用 vstart，会得到错误的值

### 2.3 根本原因

**问题**: NASM 版本或使用方式导致 vstart 未正确应用

**可能原因**:
1. 使用了不支持 vstart 的旧 NASM 版本
2. section 定义方式不正确
3. 标签定义在不同 section 中

### 2.4 解决方案

#### 方案 1: 确保正确的 NASM 版本

```bash
nasm --version
# 需要 NASM 2.0 或更高版本
```

#### 方案 2: 使用硬编码地址

```asm
; 如果 vstart 有问题，可以使用硬编码
section .stage2
gdt_ptr:
    dw 5 * 8 - 1      ; 5 个描述符
    dd 0x00007E03     ; 硬编码 GDT 地址
```

#### 方案 3: 正确使用 vstart

```asm
; 确保所有相关代码在同一 section
section .stage2 vstart=0x7E00
    bits 16

stage2_entry:
    ; 代码

gdt_start:
    dq 0
gdt_code:
    dq 0x00CF9A000000FFFF
gdt_data:
    dq 0x00CF92000000FFFF
gdt_code64:
    dq 0x00AF9A000000FFFF
gdt_end:

gdt_ptr:
    dw gdt_end - gdt_start - 1
    dd gdt_start    ; 现在应该正确计算

; 继续使用同一 section
stage2_main:
    ; ...
```

### 2.5 验证修复

```bash
# 重新编译
make clean && make

# 反汇编检查
ndisasm -b 16 -o 0x7E00 build/bootloader.bin | grep -A2 "gdt_ptr"

# 应该看到:
# 00007E2?  1F00            dw 0x001F    ; limit
# 00007E2?  037E0000        dd 0x00007E03 ; base (正确!)
```

## 3. 库函数链接问题

### 3.1 问题描述

#### 症状
- 调用库函数后返回错误值
- 寄存器被意外修改
- 系统行为不可预测

#### 背景
将常用函数提取到独立的库文件中，然后在 bootloader.asm 中包含。

### 3.2 诊断过程

#### 步骤 1: 检查库文件包含

```asm
; bootloader.asm
%include "lib/bios_string.asm"
%include "lib/disk_io.asm"

start:
    call print_string    ; 调用库函数
```

#### 步骤 2: 反汇编验证

```bash
# 反汇编查看调用
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | grep -A10 "call"

# 输出:
# 000007C5  E8XXXX          call 0xXXXX    ; 相对调用
```

**问题**: 相对调用地址可能不正确

#### 步骤 3: 检查库函数位置

```bash
# 在反汇编输出中查找 print_string
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | grep -B5 -A10 "print_string"

# 如果找不到，说明库函数没有正确包含
```

### 3.3 根本原因

**问题**: 库文件被包含到错误的 section

```asm
; lib/bios_string.asm
bits 16    ; 这会设置当前编译模式!

print_string:
    ; ...
```

**分析**:
- `%include` 会插入文件内容
- 库文件中的 `bits 16` 会影响后续代码
- 如果在 `section .stage2` 中包含，可能覆盖该 section 的 `bits` 设置

### 3.4 解决方案

#### 方案 1: 库文件不设置 bits

```asm
; lib/bios_string.asm (修改)
; 移除全局 bits 声明
; 让包含文件决定 bits 模式

print_string:
    pusha
.loop:
    lodsb
    ; ...
```

#### 方案 2: 显式重置 bits

```asm
; bootloader.asm
section .mbr
    org 0x7C00
    bits 16

%include "lib/bios_string.asm"

start:
    ; 确保 bits 仍然是 16
    bits 16    ; 显式声明
```

#### 方案 3: 使用宏代替包含

```asm
; lib/bios_string.asm
%macro PRINT_STRING 0
    pusha
.loop:
    lodsb
    test al, al
    jz %%done
    mov ah, 0x0E
    int 0x10
    jmp %%loop
%%done:
    popa
%endmacro

; bootloader.asm
%include "lib/bios_string.asm"

start:
    mov si, msg
    PRINT_STRING
```

### 3.5 最佳实践

1. **库文件设计原则**
   - 不设置全局 `bits`
   - 使用宏代替函数 (可选)
   - 提供清晰的调用约定文档

2. **包含文件顺序**
   ```asm
   ; 推荐顺序
   section .mbr
       org 0x7C00
       bits 16

   %include "lib/bios_string.asm"
   %include "lib/disk_io.asm"

   start:
       ; ...
   ```

3. **调用约定**
   ```asm
   ; 库函数必须声明:
   ; - Input 参数
   ; - Output 返回值
   ; - Clobbers 破坏的寄存器

   ; print_string - 打印字符串
   ; Input: SI = 字符串指针
   ; Output: none
   ; Clobbers: AX, SI
   ```

## 4. 构建系统问题

### 4.1 问题描述

#### 症状
- 编译成功但运行失败
- 文件大小不正确
- dd 命令输出警告

#### 背景
重构后更新了 Makefile，从编译两个文件变为编译一个文件。

### 4.2 诊断过程

#### 步骤 1: 检查输出文件大小

```bash
ls -lh build/bootloader.bin

# 之前 (两阶段):
# boot.bin   512 bytes
# boot2.bin  740 bytes

# 之后 (统一):
# bootloader.bin  ?

# 预期: 约 1-1.5KB (两个扇区)
```

#### 步骤 2: 检查扇区数量

```bash
# 查看文件大小(字节)
stat -c%s build/bootloader.bin

# 如果是 1024 字节 = 2 个扇区
# 如果是 1536 字节 = 3 个扇区
```

#### 步骤 3: 检查 dd 命令

```makefile
# 问题代码
$(BOOT_IMG): $(BOOTLOADER_BIN) $(KERNEL_BIN)
    dd if=$(BOOTLOADER_BIN) of=$@ bs=512 count=1    # 只复制 1 个扇区!
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=2
```

**问题**: 只复制了 bootloader 的第一个扇区

### 4.3 解决方案

#### 修复 Makefile

```makefile
# 计算 bootloader 扇区数
BOOTLOADER_SIZE := $(shell stat -c%s $(BOOTLOADER_BIN))
BOOTLOADER_SECTORS := $(shell echo $$(( ($(BOOTLOADER_SIZE) + 511) / 512 )))

$(BOOT_IMG): $(BOOTLOADER_BIN) $(KERNEL_BIN)
    @echo "Bootloader size: $(BOOTLOADER_SIZE) bytes ($(BOOTLOADER_SECTORS) sectors)"
    dd if=$(BOOTLOADER_BIN) of=$@ bs=512 count=$(BOOTLOADER_SECTORS) conv=notrunc
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=$(BOOTLOADER_SECTORS) conv=notrunc
```

#### 或者使用固定值

```makefile
# 如果 bootloader 始终是 2 个扇区
BOOTLOADER_SECTORS = 2

$(BOOT_IMG): $(BOOTLOADER_BIN) $(KERNEL_BIN)
    dd if=$(BOOTLOADER_BIN) of=$@ bs=512 count=$(BOOTLOADER_SECTORS) conv=notrunc
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=$(BOOTLOADER_SECTORS) conv=notrunc
```

### 4.4 更新内核加载地址

**重要**: 扇区布局变化后，内核加载地址也要更新

```asm
; 之前: boot1(1) + boot2(2) = 3 扇区，内核从扇区 4 开始
KERNEL_LBA_START equ 3

; 之后: bootloader(2) = 2 扇区，内核从扇区 3 开始
KERNEL_LBA_START equ 2    ; 0-based LBA
```

## 5. 扇区布局错误

### 5.1 问题描述

#### 症状
- 内核加载失败
- 显示 "Failed to load kernel"
- 系统挂起

#### 背景
重构后扇区布局发生变化，但忘记更新相关配置。

### 5.2 扇区布局对比

#### 重构前

```
LBA  扇区(1-based)  内容           大小
────────────────────────────────────────
0    1              boot.bin       512 bytes
1    2              boot2.bin      部分 1
2    3              boot2.bin      部分 2
3    4              kernel.bin     开始
```

#### 重构后

```
LBA  扇区(1-based)  内容                大小
─────────────────────────────────────────────
0    1              bootloader.bin      部分 1
1    2              bootloader.bin      部分 2
2    3              kernel.bin          开始 (变化!)
```

### 5.3 解决方案

#### 更新 boot_config.inc

```asm
; boot_config.inc

; 之前
KERNEL_LBA_START      equ 3    ; 扇区 4 (1-based)

; 之后
KERNEL_LBA_START      equ 2    ; 扇区 3 (1-based)
```

#### 更新 Makefile

```makefile
# 之前
$(BOOT_IMG): $(BOOT_BIN) $(BOOT2_BIN) $(KERNEL_BIN)
    dd if=$(BOOT_BIN) of=$@ bs=512 count=1
    dd if=$(BOOT2_BIN) of=$@ bs=512 seek=1
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=3    # 内核从扇区 4 开始

# 之后
$(BOOT_IMG): $(BOOTLOADER_BIN) $(KERNEL_BIN)
    dd if=$(BOOTLOADER_BIN) of=$@ bs=512 count=2
    dd if=$(KERNEL_BIN) of=$@ bs=512 seek=2    # 内核从扇区 3 开始 (LBA 2)
```

### 5.4 验证布局

```bash
# 查看最终镜像
xxd build/boot.img | head -20

# 检查特定偏移
# MBR 签名应该在 0x1FE
xxd -s 0x1FE -l 2 build/boot.img

# 内核应该在偏移 1024 (0x400)
xxd -s 0x400 -l 32 build/boot.img
```

## 6. 调试技巧总结

### 6.1 快速诊断清单

| 问题 | 检查项 | 命令 |
|------|--------|------|
| 无法启动 | MBR 签名 | `xxd -s 0x1FE -l 2 file.bin` |
| 跳转失败 | 跳转指令 | `ndisasm -b 16 -o 0x7C00 file.bin \| grep jmp` |
| 地址错误 | 反汇编 | `ndisasm -b 16 -o 0x7E00 file.bin \| head` |
| 文件大小 | 文件信息 | `ls -lh file.bin` |
| 扇区问题 | 镜像布局 | `xxd file.img \| head` |

### 6.2 调试输出策略

#### 1. 分阶段标记

```asm
; 在关键点输出不同字符
; Stage 1
mov al, '1'
call serial_write_char

; Stage 2
mov al, '2'
call serial_write_char

; 保护模式
mov al, 'P'
call serial_write_char

; 长模式
mov al, 'L'
call serial_write_char_64
```

#### 2. 进度条

```asm
; 在循环中输出进度
.read_loop:
    mov al, '.'
    call serial_write_char
    ; 读取扇区
    ; ...
    cmp di, 0
    jne .read_loop
```

#### 3. 错误码

```asm
; 定义错误码
ERROR_SUCCESS      equ 0
ERROR_DISK_READ    equ 1
_ERROR_LBA_FAILED  equ 2

; 返回错误码
load_error:
    mov al, ERROR_DISK_READ
    ret
```

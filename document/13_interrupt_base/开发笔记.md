## 1. 阶段背景

### 1.1 前一阶段遗留问题

在 Stage 12 (栈回溯支持) 中，我们实现了：
- 基于帧指针的栈遍历
- 符号解析系统
- 自动符号表生成

但当时缺乏：
- **中断处理能力** - 无法响应硬件事件
- **异常处理机制** - CPU 异常会导致系统崩溃
- **定时器支持** - 无法实现时间相关功能
- **抢占式调度基础** - 无法实现进程切换

### 1.2 本阶段目标

```
核心目标：建立完整的中断处理基础设施

1. 硬件中断支持
   - 8259 PIC 驱动
   - IRQ 路由和处理
   - 中断屏蔽控制

2. 异常处理
   - CPU 异常捕获
   - 异常信息显示
   - 栈回溯集成

3. 中断描述符表
   - IDT 初始化
   - 中断门设置
   - 处理程序注册

4. 定时器中断
   - IRQ0 处理
   - 滴答计数器
   - 时间基准
```

## 2. 设计决策

### 2.1 PIC 控制器选择

#### 问题

x86 架构有多种中断控制器选项：

| 控制器 | 优点 | 缺点 |
|--------|------|------|
| 8259 PIC | 简单、经典、广泛支持 | 性能较低、单核架构 |
| APIC | 性能高、多核支持 | 复杂、配置繁琐 |
| IOAPIC+APIC | 多核、多中断 | 最复杂 |

#### 选择：使用 8259 PIC

**理由**:
1. **学习友好** - 结构简单，易于理解
2. **经典架构** - 大量参考资料和教程
3. **单核足够** - 当前内核处于单核阶段
4. **渐进式开发** - 先掌握基础，再升级 APIC

#### 硬件架构

```
          ┌──────────────┐
          │   CPU        │
          └──────┬───────┘
                 │
        ┌────────┴────────┐
        │                 │
   ┌────▼────┐       ┌────▼────┐
   │ Master  │◄──────►│ Slave   │
   │  PIC    │       │  PIC    │
   └────┬────┘       └────┬────┘
        │                 │
   IRQ 0-7           IRQ 8-15
```

### 2.2 IRQ 重映射方案

#### 问题

8259 PIC 默认映射：
- IRQ 0-7 → 向量 0x08-0x0F
- IRQ 8-15 → 向量 0x70-0x77

但 x86 CPU 规定：
- 向量 0-31 保留给 CPU 异常
- 向量 32-255 可用于用户中断

**冲突！** IRQ 0 与 Divide Error 异常同号。

#### 解决方案：重映射

使用 ICW1-ICW4 初始化命令重新映射：

```c
// 重映射到 32-47
pic_init(32, 40);

// 结果：
// IRQ 0-7   → 向量 32-39
// IRQ 8-15  → 向量 40-47
```

### 2.3 中断处理机制设计

#### 方案 A：纯 C 实现

```c
void interrupt_handler(int vector) {
    switch (vector) {
        case 32: timer_handler(); break;
        case 33: keyboard_handler(); break;
        // ...
    }
}
```

**缺点**：无法保存完整的 CPU 状态。

#### 方案 B：汇编 + C 混合

```asm
; interrupt.asm
isr32:
    pusha                    ; 保存通用寄存器
    push qword 32            ; 中断向量
    call timer_handler       ; C 处理函数
    popa                     ; 恢复寄存器
    iretq                    ; 中断返回
```

**优点**：完整的上下文保存。

**选择**：采用方案 B

## 3. 架构设计

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                     Application Code                     │
│                   interrupt_init()                       │
└─────────────────────┬───────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────┐
│              interrupt.h (Public Interface)             │
│  - interrupt_init()                                      │
│  - timer_get_ticks()                                     │
└─────────────────────┬───────────────────────────────────┘
                      │
        ┌─────────────┴─────────────┐
        │                           │
┌───────▼────────┐         ┌────────▼────────┐
│  PIC Module    │         │   IDT Module    │
│  (pic.c)       │         │   (idt.c)       │
│                │         │                 │
│ - pic_init()   │         │ - idt_init()    │
│ - pic_send_eoi │         │ - idt_set_gate()│
└────────────────┘         └────────┬────────┘
                                    │
                           ┌────────▼────────────────────┐
                           │  interrupt.asm              │
                           │  - ISR stubs (32)           │
                           │  - IRQ stubs (16)           │
                           │  - interrupt_common         │
                           └────────┬────────────────────┘
                                    │
                           ┌────────▼────────────────────┐
                           │  interrupt.c                │
                           │  - interrupt_handler()      │
                           │  - timer_handler()          │
                           └─────────────────────────────┘
```

### 3.2 中断流程

```
硬件事件 → PIC → CPU → ISR Stub → interrupt_common
                                            │
                                            ▼
                                    interrupt_handler()
                                            │
                                    ┌───────┴────────┐
                                    │                │
                            ┌───────▼─────┐  ┌─────▼─────┐
                            │ 默认处理器  │  │注册处理器 │
                            │ (异常显示)  │  │ (定时器等) │
                            └─────────────┘  └───────────┘
```

### 3.3 模块职责

| 模块 | 职责 | 依赖 |
|------|------|------|
| `pic.c` | PIC 初始化、IRQ 屏蔽、EOI | 无 |
| `idt.c` | IDT 管理、异常处理 | 无 |
| `interrupt.asm` | 中断入口、上下文保存 | 无 |
| `interrupt.c` | 中断分发、定时器 | pic, idt |

## 4. 实现细节

### 4.1 PIC 初始化序列

```c
void pic_init(uint8_t offset1, uint8_t offset2) {
    // 1. 保存当前屏蔽状态
    uint8_t mask1 = inb(PIC1_DATA);
    uint8_t mask2 = inb(PIC2_DATA);

    // 2. 开始初始化级联模式
    outb(PIC1_CMD, ICW1_INIT | ICW1_ICW4);
    outb(PIC2_CMD, ICW1_INIT | ICW1_ICW4);

    // 3. 设置向量偏移
    outb(PIC1_DATA, offset1);  // Master PIC: IRQ 0-7 → 32-39
    outb(PIC2_DATA, offset2);  // Slave PIC: IRQ 8-15 → 40-47

    // 4. 配置级联
    outb(PIC1_DATA, 0x04);     // Master: IR2 连接 slave
    outb(PIC2_DATA, 0x02);     // Slave: 标识为级联

    // 5. 设置 8086 模式
    outb(PIC1_DATA, ICW4_8086);
    outb(PIC2_DATA, ICW4_8086);

    // 6. 恢复屏蔽状态
    outb(PIC1_DATA, mask1);
    outb(PIC2_DATA, mask2);
}
```

### 4.2 中断帧结构

```c
typedef struct PACKED {
    uint64_t error_code;      // 错误码（部分异常）
    uint64_t rip;             // 返回地址
    uint64_t cs;              // 代码段选择子
    uint64_t rflags;          // RFLAGS 寄存器
    uint64_t rsp;             // 栈指针
    uint64_t ss;              // 栈段选择子
} interrupt_frame_t;
```

**栈布局**：
```
高地址
    +------------------+
    |   SS (可选)      |
    +------------------+
    |   RSP            |
    +------------------+
    |   RFLAGS         |
    +------------------+
    |   CS             |
    +------------------+
    |   RIP            |
    +------------------+
    |   Error Code     |  (仅部分异常)
    +------------------+
低地址
```

### 4.3 ISR Stub 生成

使用 NASM 宏生成 32 个异常 stub：

```asm
%macro ISR_NOERRCODE 1
  global isr%1
  isr%1:
    push qword 0         ; 虚拟错误码
    push qword %1        ; 中断向量号
    push qword 0         ; 对齐 dummy
    jmp interrupt_common
%endmacro

%assign i 0
%rep 32
  ISR_NOERRCODE i
%assign i i+1
%endrep
```

### 4.4 通用中断入口

```asm
interrupt_common:
    ; 保存所有通用寄存器
    push rax
    push rbx
    push rcx
    push rdx
    push rsi
    push rdi
    push rbp
    push r8
    push r9
    push r10
    push r11
    push r12
    push r13
    push r14
    push r15

    ; 保存段寄存器
    push ds
    push es
    push fs
    push gs

    ; 加载内核数据段
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    ; 调用 C 处理函数
    mov rdi, rsp
    add rdi, 8*8          ; 跳过通用寄存器
    mov rsi, [rdi]        ; error_code
    mov rdx, [rdi-8]      ; vector_number
    call interrupt_handler

    ; 恢复段寄存器
    pop gs
    pop fs
    pop es
    pop ds

    ; 恢复通用寄存器
    pop r15
    pop r14
    pop r13
    pop r12
    pop r11
    pop r10
    pop r9
    pop r8
    pop rbp
    pop rdi
    pop rsi
    pop rdx
    pop rcx
    pop rbx
    pop rax

    ; 清理栈
    add rsp, 24

    ; 中断返回
    iretq
```

## 5. 常见陷阱

### 5.1 忘记发送 EOI

#### 问题

中断处理完成后不发送 EOI，导致后续中断无法触发。

```c
void timer_handler(interrupt_frame_t* frame) {
    g_timer_ticks++;
    // 忘记 pic_send_eoi()！
}
```

#### 解决方案

**必须在处理函数结束时发送 EOI**：

```c
void timer_handler(interrupt_frame_t* frame) {
    g_timer_ticks++;
    pic_send_eoi(0);  // IRQ 0 是定时器
}
```

### 5.2 中断风暴

#### 问题

处理函数耗时过长，导致中断堆积。

```c
void slow_handler(interrupt_frame_t* frame) {
    for (int i = 0; i < 1000000; i++) {
        // 大量计算
    }
    pic_send_eoi(0);
}
```

#### 解决方案

中断处理函数应该快速执行：

```c
// 优化后
void fast_handler(interrupt_frame_t* frame) {
    // 仅设置标志，实际处理推迟到下半部
    g_pending_work = true;
    pic_send_eoi(0);
}
```

### 5.3 竞态条件

#### 问题

在中断处理和主代码之间访问共享数据：

```c
int g_counter = 0;

void main(void) {
    g_counter++;  // 可能被中断打断！
}

void timer_handler(interrupt_frame_t* frame) {
    g_counter++;  // 竞态！
}
```

#### 解决方案

使用中断禁用保护临界区：

```c
void main(void) {
    interrupt_disable();
    g_counter++;
    interrupt_enable();
}
```

## 6. 栈对齐问题专题

### 6.1 问题描述

在第一次启用中断后，系统立即触发 Divide Error (#DE) 异常：

```
[ERROR] === EXCEPTION OCCURRED ===
[ERROR] Vector: 0 - Divide Error (#DE)
[ERROR] RIP: 0x00000000000100a1
```

### 6.2 根本原因

**x86-64 System V ABI 要求调用 C 函数时栈必须 16 字节对齐。**

原始实现未满足这一要求，导致编译器生成的 SSE 指令访问错误内存。

### 6.3 栈偏移计算

进入 `interrupt_common` 时的栈内容：

| 推送者 | 内容 | 大小 |
|--------|------|------|
| ISR stub | error_code/dummy | 8 字节 |
| ISR stub | vector_number | 8 字节 |
| CPU | RIP, CS, RFLAGS | 24 字节 |
| **修复后** | alignment dummy | 8 字节 |
| **总计** | | 48 字节 (48 % 16 = 0) ✓ |

### 6.4 修复方案

在每个 ISR stub 中添加对齐 dummy：

```asm
%macro ISR_NOERRCODE 1
  global isr%1
  isr%1:
    push qword 0         ; dummy error code
    push qword %1        ; vector number
    push qword 0         ; ← 添加：对齐 dummy
    jmp interrupt_common
%endmacro
```

同时更新 `interrupt_common` 的栈偏移计算：

```asm
; 修复前
add rsp, 16

; 修复后
add rsp, 24
```

### 6.5 经验教训

1. **x86-64 ABI 的栈对齐是硬性要求**
2. **不对齐可能导致各种奇怪异常**（不一定是预期的异常类型）
3. **调试技巧**：
   - 检查 RIP 是否在循环中
   - 检查 RSP 对齐情况
   - 反汇编确认指令合法性

## 8. 经验总结

### 8.1 最大的收获

#### 中断是操作系统的核心

```
理解中断系统是掌握操作系统的关键：

- 中断 = 硬件事件的软件处理
- 异常 = CPU 同步事件
- 良好的中断设计是响应式系统的基础
```

#### 栈对齐的隐性要求

```
栈对齐问题往往表现得很隐蔽：
- 可能触发完全无关的异常
- 难以定位问题根源
- 必须从架构层面理解 ABI
```

### 8.2 如果重来

#### 会做得更好

1. **更完整的错误处理**
   ```c
   typedef enum {
       INT_OK,
       INT_INVALID_VECTOR,
       INT_HANDLER_NULL,
       INT_EOI_FAILED
   } int_result_t;
   ```

2. **更灵活的处理程序注册**
   ```c
   // 支持优先级、共享、过滤等
   int idt_register_handler_ex(uint8_t vector, interrupt_handler_fn handler,
                               uint8_t priority, bool shared);
   ```

3. **更详细的调试支持**
   - 中断计数器
   - 处理时间统计
   - 栈使用监控

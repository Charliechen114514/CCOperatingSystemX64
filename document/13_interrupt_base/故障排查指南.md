## 1. 中断未触发

### 1.1 定时器中断不工作

#### 症状

启用中断后，定时器滴答数始终为 0：

```
[TIMER] Tick #1 received
[TIMER] Tick #2 received
[... 之后再也没有输出 ...]
```

或完全没有定时器输出。

#### 原因分析

1. PIC 未正确初始化
2. IRQ 0 被屏蔽
3. 中断未启用 (sti)
4. 定时器处理程序未注册

#### 诊断步骤

```c
// 1. 检查 PIC 初始化
void debug_pic_status(void) {
    // 读取 PIC 屏蔽字
    uint8_t mask1 = inb(PIC1_DATA);
    uint8_t mask2 = inb(PIC2_DATA);

    klog_info("PIC1 mask: 0x%02x (IRQ 0-7)\n", mask1);
    klog_info("PIC2 mask: 0x%02x (IRQ 8-15)\n", mask2);

    // 位 0 = 0 表示 IRQ 0 启用
    if (mask1 & 0x01) {
        klog_error("IRQ 0 (timer) is MASKED!\n");
    }
}

// 2. 检查中断是否启用
bool check_interrupts_enabled(void) {
    uint64_t rflags;
    __asm__ volatile("pushfq; popq %0" : "=r"(rflags));
    return (rflags & 0x200) != 0;  // IF 位
}

// 3. 检查处理程序注册
if (custom_handlers[32] == NULL) {
    klog_error("No handler registered for IRQ 0\n");
}
```

#### 解决方案

确保按正确顺序初始化：

```c
void interrupt_init(void) {
    // 1. 先初始化 PIC
    pic_init(0x20, 0x28);

    // 2. 禁用所有 IRQ
    pic_disable_all();

    // 3. 初始化 IDT
    idt_init();

    // 4. 注册处理程序
    idt_register_handler(32, timer_handler);

    // 5. 启用需要的 IRQ
    pic_enable_irq(0);  // 启用定时器

    // 6. 最后启用中断
    interrupt_enable();
}
```

### 1.2 键盘中断无响应

#### 症状

按键没有任何反应。

#### 诊断步骤

```c
// 1. 检查 IRQ 1 是否启用
uint8_t mask1 = inb(PIC1_DATA);
if (mask1 & 0x02) {
    klog_error("IRQ 1 (keyboard) is MASKED\n");
}

// 2. 检查处理程序
if (custom_handlers[33] == NULL) {
    klog_error("No handler registered for IRQ 1\n");
}

// 3. 手动检查键盘数据端口
if (inb(0x64) & 0x01) {
    uint8_t data = inb(0x60);
    klog_info("Keyboard data available: 0x%02x\n", data);
}
```

#### 解决方案

```c
// 注册键盘处理程序
void keyboard_handler(interrupt_frame_t* frame, uint64_t error_code) {
    uint8_t scancode = inb(0x60);
    klog_info("Keyboard: 0x%02x\n", scancode);
    pic_send_eoi(1);
}

idt_register_handler(33, keyboard_handler);
pic_enable_irq(1);
```

## 2. 异常处理崩溃

### 2.1 Divide Error (#DE) 在启用中断后立即发生

#### 症状

```
[ERROR] === EXCEPTION OCCURRED ===
[ERROR] Vector: 0 - Divide Error (#DE)
[ERROR] RIP: 0x00000000000100a1
```

但 RIP 处的指令并不是除法指令！

#### 原因

**栈未按 x86-64 ABI 要求进行 16 字节对齐。**

详见 [栈对齐问题](#4-栈对齐问题)。

#### 解决方案

在每个 ISR stub 中添加对齐 dummy：

```asm
%macro ISR_NOERRCODE 1
  global isr%1
  isr%1:
    push qword 0         ; 虚拟错误码
    push qword %1        ; 向量号
    push qword 0         ; ← 添加: 对齐 dummy
    jmp interrupt_common
%endmacro
```

### 2.2 General Protection Fault (#GP)

#### 症状

```
[ERROR] === EXCEPTION OCCURRED ===
[ERROR] Vector: 13 - General Protection Fault (#GP)
[ERROR] Error Code: 0x0000000000000000
```

#### 原因分析

1. 段选择子错误
2. IDT 条目类型错误
3. 访问未对齐的内存
4. 特权级违规

#### 诊断步骤

```c
void debug_gpf_handler(interrupt_frame_t* frame, uint64_t error_code) {
    klog_error("=== GPF Debug ===\n");
    klog_error("RIP: 0x%016lx\n", frame->rip);
    klog_error("CS:  0x%016lx\n", frame->cs);
    klog_error("Error: 0x%016lx\n", error_code);

    // 检查 IDT 条目
    if (error_code & 0x01) {
        klog_error("External event\n");
    }
    if (error_code & 0x02) {
        klog_error("IDT access\n");
    }
    if (error_code & 0x04) {
        klog_error("TI bit set\n");
    }

    // 检查 RIP 是否在有效范围
    klog_error("Text section: 0x%lx - 0x%lx\n",
              _symbol_text_start, _symbol_text_end);
}
```

#### 解决方案

1. **检查段选择子**:

```c
// Bootloader GDT:
// - gdt_code64 在偏移 0x18 → 选择子 0x18
uint16_t kernel_cs = 0x18;
idt_set_entry(vector, handler, type, kernel_cs);
```

2. **检查 IDT 条目类型**:

```c
// 使用正确的类型
#define IDT_KERNEL_INTERRUPT_GATE  0x8E
```

### 2.3 Double Fault (#DF)

#### 症状

```
[ERROR] === EXCEPTION OCCURRED ===
[ERROR] Vector: 8 - Double Fault (#DF)
```

#### 原因

处理异常时又发生异常（通常是栈问题）。

#### 解决方案

```c
// 1. 确保栈足够大
// 2. 使用 IST (Interrupt Stack Table)
// 3. 检查处理程序中的内存访问

// 简单处理：打印信息后停止
void double_fault_handler(interrupt_frame_t* frame, uint64_t error_code) {
    klog_error("Double Fault! System halted.\n");
    klog_error("RSP: 0x%016lx\n", frame->rsp);
    __asm__ volatile("cli; .halt: hlt; jmp .halt");
}
```

## 3. 系统挂起问题

### 3.1 中断返回后系统挂起

#### 症状

中断处理程序执行后，系统不再响应。

#### 原因

1. 忘记发送 EOI
2. 寄存器未正确恢复
3. 栈不平衡导致 iretq 错误

#### 诊断步骤

```c
// 在中断处理程序中添加调试信息
void timer_handler(interrupt_frame_t* frame, uint64_t error_code) {
    klog_debug("Timer handler start\n");

    timer_ticks++;

    klog_debug("Sending EOI...\n");
    pic_send_eoi(0);

    klog_debug("Timer handler end\n");
}

// 检查汇编入口
// 添加调试信息到 interrupt_common
```

#### 解决方案

确保 `interrupt_common` 正确恢复所有寄存器：

```asm
interrupt_common:
    ; 保存所有寄存器
    push rax
    push rbx
    ; ...
    push r15

    ; 调用 C 处理程序
    call interrupt_handler

    ; 恢复所有寄存器
    pop r15
    ; ...
    pop rax

    ; 清理栈 (error_code, vector, align_dummy)
    add rsp, 24

    ; 中断返回
    iretq
```

### 3.2 中断风暴

#### 症状

系统疯狂打印中断信息，无法进行其他操作。

#### 原因

处理程序耗时过长，或中断频率过高。

#### 解决方案

```c
// 快速处理
void fast_handler(interrupt_frame_t* frame, uint64_t error_code) {
    // 仅设置标志
    g_pending_flag = true;
    pic_send_eoi(0);
}

// 主循环中处理
void kernel_main(void) {
    while (1) {
        if (g_pending_flag) {
            g_pending_flag = false;
            // 执行实际处理
            process_work();
        }
        __asm__ volatile("hlt");
    }
}
```

## 4. 栈对齐问题

### 4.1 症状

启用中断后立即触发奇怪的异常（通常是 #DE）。

### 4.2 诊断

```c
// 检查栈对齐
void check_stack_alignment(void) {
    uint64_t rsp;
    __asm__ volatile("mov %%rsp, %0" : "=r"(rsp));

    klog_info("RSP: 0x%016lx\n", rsp);
    klog_info("Aligned: %s\n", (rsp & 0xF) ? "No" : "Yes");
}

// 在 interrupt_common 开头检查

    and rax, 0xF
```

## 5. PIC 问题

### 5.1 IRQ 未重映射

#### 症状

IRQ 0 触发 Divide Error 而不是定时器处理程序。

#### 原因

PIC 未初始化，使用默认映射（IRQ 0-15 → 向量 0-15）。

#### 解决方案

```c
// 在初始化时必须调用 pic_init
pic_init(0x20, 0x28);  // 重映射到 32-47
```

### 5.2 假中断 (Spurious Interrupt)

#### 症状

```
Spurious interrupt: vector 39
```

#### 原因

PIC 7 或 IRQ 15 的假中断（硬件特性）。

#### 解决方案

```c
void interrupt_handler(uint64_t vector, uint64_t error_code,
                      interrupt_frame_t* frame) {
    if (vector >= 32 && vector < 48) {
        uint8_t irq = vector - 32;

        // 检查 ISR 寄存器
        outb(PIC1_CMD, PIC_READ_ISR);
        uint8_t isr1 = inb(PIC1_CMD);

        if (!(isr1 & (1 << irq))) {
            // 假中断，不需要 EOI
            klog_debug("Spurious IRQ %d\n", irq);
            return;
        }

        // 正常处理...
        pic_send_eoi(irq);
    }
}
```

```c
void dump_pic_status(void) {
    outb(PIC1_CMD, PIC_READ_ISR);
    uint8_t isr1 = inb(PIC1_CMD);
    outb(PIC1_CMD, PIC_READ_IRR);
    uint8_t irr1 = inb(PIC1_CMD);

// 打印 IDT 条目
void dump_idt_entry(uint8_t vector) {
    idt_entry_t* entry = &idt[vector];
    uint64_t handler = (uint64_t)(entry->offset_high << 32 |
                                  entry->offset_middle << 16 |
                                  entry->offset_low);

    klog_info("IDT[%d]: handler=0x%016lx type=0x%02x\n",
              vector, handler, entry->type_attr);
}
```

### 6.5 性能分析

```c
// 测量中断处理时间
static uint64_t intr_start_time[256];
static uint64_t intr_total_time[256];
static uint64_t intr_count[256];

void interrupt_handler(uint64_t vector, uint64_t error_code,
                      interrupt_frame_t* frame) {
    uint64_t start = rdtsc();

    // 处理中断...

    uint64_t end = rdtsc();
    intr_count[vector]++;
    intr_total_time[vector] += (end - start);

    if (intr_count[vector] % 1000 == 0) {
        klog_info("IRQ %d: avg %lu cycles\n", vector,
                  intr_total_time[vector] / intr_count[vector]);
    }
}
```

## 7. 常见错误代码

### 7.1 编译错误

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `undefined reference to isr_handler_table` | 汇编文件未链接 | 检查 CMakeLists.txt |

### 7.2 运行时异常

| 异常 | 常见原因 | 解决方案 |
|------|----------|----------|
| #DE | 栈对齐问题 | 添加对齐 dummy |
| #GP | 段选择子错误 | 检查 CS 值 |
| #DF | 栈损坏 | 检查栈大小 |
| #PF | 无效内存访问 | 检查指针 |

## 8. 最佳实践

### 8.1 初始化顺序

```c
// 正确的初始化顺序
void kernel_init(void) {
    // 1. 早期初始化 (无中断)
    early_init();

    // 2. 初始化中断子系统
    interrupt_init();

    // 3. 其他初始化 (有中断)
    other_init();

    // 4. 进入主循环
    kernel_main();
}
```

### 8.2 中断处理原则

```c
// 快速处理
void handler(interrupt_frame_t* frame, uint64_t error_code) {
    // 1. 快速: 只做必要操作
    critical_operation();

    // 2. EOI: 尽快发送
    pic_send_eoi(irq);

    // 3. 返回: 不要耗时
}
```

### 8.3 错误处理

```c
// 安全的中断处理
void safe_handler(interrupt_frame_t* frame, uint64_t error_code) {
    // 检查参数
    if (frame == NULL) {
        klog_error("NULL frame in handler\n");
        return;
    }

    // 使用 try-catch 风格
    __asm__ volatile("cli");  // 禁用嵌套
    // 处理逻辑
    __asm__ volatile("sti");  // 重新启用
}
```

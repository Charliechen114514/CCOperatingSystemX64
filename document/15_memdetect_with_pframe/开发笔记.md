# CCOS 内存检测与物理帧管理 - 开发笔记

本文档记录 Stage 15 - 内存检测与物理帧管理的设计思路、开发过程和经验总结。

---

## 1. 为什么需要内存检测与物理帧管理

### 1.1 问题的提出

在 Stage 14 之前，CCOS 内核对系统内存一无所知：
- 不知道系统有多少物理内存
- 不知道哪些内存区域可用
- 无法动态分配物理内存
- 所有内存布局都是硬编码假设

这种局限性使得我们无法实现：
- 虚拟内存管理
- 动态堆分配器 (kmalloc/kfree)
- 进程独立的地址空间
- 内存映射文件

### 1.2 解决方案概述

我们需要两套基础设施：

**1. 内存检测系统**
- 在 Bootloader 阶段查询 BIOS 获取内存地图
- 将内存信息传递给内核
- 提供查询接口判断内存区域可用性

**2. 物理帧分配器**
- 管理可用物理内存（以 4KB 页为单位）
- 提供分配/释放接口
- 跟踪内存使用状态

## 2. 设计决策

### 2.1 为什么选择 E820

x86 平台有三种 BIOS 内存检测方法：

| 方法 | 中断 | 优点 | 缺点 |
|------|------|------|------|
| **E820** | INT 15h, AX=E820h | 详细内存地图，支持多种类型 | 需要多次调用 |
| **E801** | INT 15h, AX=E801h | 简单快速 | 只区分 1MB 上下 |
| **88h** | INT 15h, AH=88h | 最简单 | 最大 64MB，无区域信息 |

**决策：三级回退策略**
```
E820 (首选) → E801 (回退1) → 88h (回退2)
```

这样可以：
- 在现代机器上获得最佳内存信息
- 兼容老旧硬件
- 确保至少能检测到 64MB 内存

### 2.2 为什么选择位图分配器

物理内存管理有三种常见方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **位图** | 简单、O(1) 分配、固定开销 | 连续分配慢、外部碎片 |
| 栈/链表 | 快速、低碎片 | 需要初始化遍历、复杂 |
| 伙伴系统 | 最小碎片、高效 | 实现复杂 |

**决策：位图方案**

理由：
1. **实现简单** - 适合教学项目
2. **性能可预测** - 分配释放都是 O(1)
3. **固定内存开销** - 每帧 1 bit
4. **易于调试** - 可直接打印位图查看状态

对于早期内核，简单可靠比极致性能更重要。

### 2.3 内存布局设计

固定地址传递内存地图：

```
地址         用途
---------    ------------------
0x0 - 0x7FFF     BIOS 数据区（避免）
0x7C00          MBR
0x7E00          Stage 2 Bootloader
0x9000          页表
0xC000          ★ 内存地图存储 ★
0x10000         内核
```

选择 0xC000 的原因：
1. 避开 BIOS 和 bootloader 区域
2. 在页表之前，不会被覆盖
3. 16KB 空间足够存储 128 个 E820 条目

## 4. 实现细节

### 4.1 E820 检测 (Bootloader 端)

E820 调用约定：
```
Input:  AX = E820h
        BX = 连续值 (首次为 0)
        ES:DI = 缓冲区地址
        CX = 缓冲区大小 (24 字节)
        EDX = 'SMAP' 签名
Output: CF = 0 成功, 1 失败
        AX = 'SMAP' 签名
        CX = 实际写入字节数
        BX = 下一次的连续值
```

关键实现点：
1. **签名验证** - 检查返回值是否为 'SMAP'
2. **连续值处理** - BX 用于多次调用获取全部条目
3. **缓冲区对齐** - ES:DI 必须指向有效内存
4. **条目限制** - 最多存储 128 个条目

### 4.2 E801 检测 (回退方案)

E801 返回两个内存区域：
```
Output: AX = 1MB 以下的内存大小 (KB)
        CX = 1MB 以上的内存大小 (KB)
        DX = 1MB 以上的内存大小 (64KB 单位，溢出)
```

转换为 E820 格式：
```
Entry 0: base=0x00000000, length=<AX>KB, type=1
Entry 1: base=0x00100000, length=<CX*KB or DX*64KB>, type=1
```

### 4.3 位图分配器算法

**数据结构：**
```c
#define BITS_PER_BYTE  8
#define BITS_PER_QWORD 64

typedef struct {
    uint64_t* bitmap;        // 位图数组
    uint64_t bitmap_qwords;  // 数组长度
    uint64_t total_frames;   // 总帧数
    uint64_t managed_start;  // 起始地址
    uint64_t managed_end;    // 结束地址
} pframe_allocator_t;
```

**分配算法：**
```c
// 查找第一个空闲位
for (uint64_t i = 0; i < bitmap_qwords; i++) {
    if (bitmap[i] != ~0ULL) {  // 有空闲位
        uint64_t bit = __builtin_ctzll(~bitmap[i]);  // 找到第一个 0
        uint64_t frame = i * BITS_PER_QWORD + bit;
        bitmap[i] |= (1ULL << bit);  // 标记为已用
        return managed_start + frame * PAGE_SIZE;
    }
}
return PFRAME_ERR_OOM;
```

**释放算法：**
```c
uint64_t frame = (addr - managed_start) / PAGE_SIZE;
uint64_t qword = frame / BITS_PER_QWORD;
uint64_t bit = frame % BITS_PER_QWORD;
bitmap[qword] &= ~(1ULL << bit);  // 清除位
```

### 4.4 CMake 配置生成

问题：Bootloader 和内核需要共享内存常量定义。

解决方案：CMake `configure_file` 生成两种格式：

```cmake

    ${CMAKE_CURRENT_SOURCE_DIR}/MemConfig.h.in
    ${CMAKE_BINARY_DIR}/include/mem_config.h

```

## 5. 常见陷阱与注意事项

### 5.1 实模式与保护模式切换

**问题：** Bootloader 运行在 16 位实模式，而内核是 64 位。

**解决：** 内存地图存储在固定物理地址，不依赖段地址。

```asm
; Bootloader (16-bit)
mov ax, 0x0000
mov ds, ax              ; DS = 0x0000
mov di, 0xC000          ; 物理地址 0x00C00

; Kernel (64-bit)
e820_entry_t* map = (e820_entry_t*)0xC000;  // 直接映射
```

### 5.2 E820 条目对齐

**问题：** BIOS 可能返回未对齐的条目。

**解决：** 确保缓冲区足够大且对齐。

```asm
%define E820_STORAGE_ADDR   0xC000
%define E820_ENTRY_SIZE     24
%define E820_MAX_ENTRIES    128
; 总大小: 128 * 24 = 3072 字节，在 16KB 范围内
```

### 5.3 位图大小计算

**问题：** 位图太小无法覆盖全部内存。

**解决：** 根据检测到的内存大小动态分配位图。

```c
// 每帧 1 bit，每字节 8 bit
uint64_t bitmap_bytes = (total_frames + 7) / 8;
uint64_t bitmap_qwords = (bitmap_bytes + 7) / 8;
```

### 5.4 保留内存区域

**问题：** 内核和 bootloader 所在内存不能被分配。

**解决：** 初始化时显式标记。

```c
// 标记内核所在区域
pframe_mark_region(KERNEL_PHYS_BASE, KERNEL_SIZE, PFRAME_RESERVED);

// 标记内存地图存储区域
pframe_mark_region(E820_STORAGE_ADDR, E820_STORAGE_SIZE, PFRAME_RESERVED);
```

### 5.5 QEMU 内存配置

**问题：** QEMU 默认内存太小导致测试失败。

**解决：** 在 QEMU 命令中指定足够内存。

```bash
qemu-system-x86_64 -m 128M  # 至少 128MB
```

## 7. 性能考虑

### 7.1 分配器复杂度

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| `pframe_alloc()` | O(n) | n = bitmap qwords |
| `pframe_alloc_n()` | O(n*m) | m = 帧数 |
| `pframe_free()` | O(1) | 直接位操作 |

优化方向：
- 使用空闲帧链表加速分配
- 缓存最后分配位置减少扫描
- 分离大小类（类似 slab）

### 7.2 内存开销

位图开销 = 总帧数 / 8 字节

| 内存大小 | 帧数 | 位图大小 |
|---------|------|----------|
| 128 MB | 32K | 4 KB |
| 1 GB | 256K | 32 KB |
| 4 GB | 1M | 128 KB |

# CCOS 内存检测与物理帧管理 - 调试工具指南

本文档介绍 Stage 15 开发过程中可用的调试工具和技巧。

## 1. QEMU 调试

### 1.1 QEMU Monitor 命令

#### 启用 Monitor

```bash
# 方法 1: 使用独立 telnet 端口
qemu-system-x86_64 -monitor telnet:127.0.0.1:4444,server,nowait ...

# 方法 2: 使用 stdio
qemu-system-x86_64 -monitor stdio ...
```

#### 连接 Monitor

```bash
telnet localhost 4444
```

#### 常用命令

| 命令 | 说明 |
|------|------|
| `info registers` | 显示所有寄存器 |
| `info cpustats` | 显示 CPU 统计 |
| `xp /16x 0xC000` | 查看物理内存 (16 个十六进制字) |
| `x /10i $rip` | 查看当前指令 |
| `info tlb` | 显示 TLB 内容 |
| `info mem` | 显示内存映射 |
| `quit` | 退出 QEMU |

#### 内存检查示例

```bash
# 查看 E820 内存地图
xp /128x 0xC000

# 查看页表
xp /16x 0x9000   # PML4
xp /16x 0x91000  # PDPT

# 查看 IDT
info idt
```

---

### 1.2 QEMU 内存配置

#### 指定内存大小

```bash
# 最小 128MB
qemu-system-x86_64 -m 128M ...

# 推荐 256MB 或更多
qemu-system-x86_64 -m 256M ...
```

#### 检测 BIOS 信息

```bash
# 启动时查看 BIOS 检测到的内存
qemu-system-x86_64 -d guest_errors ...
```

## 2. GDB 调试

### 2.1 启动调试会话

#### 启动 QEMU

```bash
qemu-system-x86_64 -s -S -drive format=raw,file=boot.img ...
```

参数说明：
- `-s` : 等待 GDB 连接（端口 1234）
- `-S` : 启动时暂停 CPU

#### 启动 GDB

```bash
gdb build/kernel.bin
```

### 2.2 GDB 命令

#### 连接和基本命令

```gdb
# 连接到 QEMU
target remote :1234

# 设置架构
set architecture i386:x86-64

# 继续执行
continue

# 单步执行
stepi      # 指令级单步
next       # 源码级单步

# 查看栈
bt         # 回溯
frame 0    # 切换帧

# 查看变量
print var_name
print *ptr@10    # 查看数组
```

#### 断点设置

```gdb
# 函数断点
break e820_init
break pframe_alloc

# 地址断点
break *0x10000

# 条件断点
break pframe_alloc if frame_count > 10

# 查看断点
info breakpoints

# 删除断点
delete 1
clear e820_init
```

---

### 2.3 调试内存相关代码

#### 查看结构体

```gdb
# 打印 E820 条目
print *entry

# 打印数组
print e820_map[0]
print e820_map[0]@10

# 打印位图
print *bitmap@16
```

#### 内存检查

```gdb
# 检查物理内存（转换为虚拟地址）
x /16x 0xffff80000000c000

# 搜索内存
find 0xC000, +0x4000, 0x534D4150  # 查找 'SMAP' 签名
```

### 5.2 自定义验证脚本

#### 检查内存地图

```python
#!/usr/bin/env python3

def check_e820_overlap(entries):
    """检查 E820 条目是否有重叠"""
    sorted_entries = sorted(entries, key=lambda e: e['base'])
    for i, a in enumerate(sorted_entries):
        for b in sorted_entries[i+1:]:
            a_end = a['base'] + a['length']
            b_start = b['base']
            if a_end > b_start:
                print(f"Warning: Overlap detected!")
                print(f"  {a['base']:x}-{a_end:x} ({a['type']})")
                print(f"  {b['base']:x}-{b['base']+b['length']:x} ({b['type']})")

# 示例使用
entries = [
    {'base': 0x0, 'length': 0x9FC00, 'type': 1},
    {'base': 0x100000, 'length': 0x7F00000, 'type': 1},
]
check_e820_overlap(entries)
```

## 6. 常见调试场景

### 6.1 内存检测失败

**步骤：**

1. 检查 QEMU 内存配置
```bash
# 确保 QEMU 启动时有足够内存
qemu-system-x86_64 -m 256M ...
```

2. 在 Bootloader 中添加调试输出
```asm
mov si, msg_detect_start
call serial_write_string

call detect_memory_e820
jc .try_e801

mov si, msg_e820_ok
call serial_write_string
```

3. 检查 INT 15h 返回值
```asm
int 0x15
jc .error_handler        ; CF=1 表示错误
cmp eax, 'SMAP'          ; 验证签名
jne .error_handler
```

---

### 6.2 物理帧分配失败

**步骤：**

1. 检查分配器状态
```c
pframe_stats_t stats;
pframe_get_stats(&stats);
klog_info("Free frames: %llu / %llu\n",
          stats.free_frames, stats.total_frames);
```

2. 检查位图状态
```c
// 打印位图前 64 位
for (int i = 0; i < 64; i++) {
    char c = (bitmap[0] & (1ULL << i)) ? 'X' : '.';
    klog_putc(c);
}
klog_putc('\n');
```

3. 使用 GDB 设置断点
```gdb
break pframe_alloc
commands
  silent
  print allocator->free_frames
  continue
end
```

---

### 6.3 内核启动崩溃

**步骤：**

1. 检查栈状态
```gdb
bt
info frame
```

2. 检查寄存器
```gdb
info registers
print $rip
print $rsp
```

3. 检查最近分配的内存
```gdb
# 查找最近分配的帧
print last_allocated_frame
```

4. 启用更详细的日志
```c
#define DEBUG_PFRAME 1
#ifdef DEBUG_PFRAME
#define PFRAME_LOG(fmt, ...) klog_info("[PFRAME] " fmt, ##__VA_ARGS__)
#else
#define PFRAME_LOG(fmt, ...) do {} while(0)
#endif
```

uint64_t start = timer_get_ticks();

for (int i = 0; i < 1000; i++) {

## 8. 调试技巧总结

### 最佳实践

1. **逐步验证** - 从 E820 检测开始，逐层验证
2. **串口为王** - 在早期启动阶段，串口是最可靠的输出
3. **断点策略** - 在关键函数入口设置断点
4. **状态转储** - 定期打印关键状态信息
5. **边界测试** - 测试极端情况（0 分配、大量分配）

### 快速诊断流程

```
问题
  │
  ├─ 启动失败？ ─→ 检查串口输出
  │                 查看 QEMU Monitor
  │
  ├─ 内存检测失败？ ─→ 检查 QEMU 内存配置
  │                     验证 BIOS 调用
  │
  ├─ 分配失败？ ─→ 检查 free_frames
  │                 查看 bitmap 状态
  │                 验证初始化顺序
  │
  └─ 崩溃？ ─→ GDB 回溯
               检查栈溢出
               验证内存访问
```

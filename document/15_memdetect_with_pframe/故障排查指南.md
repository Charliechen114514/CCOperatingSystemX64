# CCOS 内存检测与物理帧管理 - 故障排查指南

本文档提供 Stage 15 开发过程中常见问题的症状、原因和解决方案。

---

## 1. 内存检测失败

### 症状
- 串口输出显示 "Memory detection failed"
- `e820_get_detect_method()` 返回 `MEM_DETECT_UNKNOWN`
- E820 条目数为 0

### 可能原因

#### 原因 1: QEMU 内存配置不正确

**检查：**
```bash
# 检查 QEMU 命令行是否指定了内存
qemu-system-x86_64 -m 128M ...  # 应该至少 128M
```

**解决方案：**
确保 QEMU 启动时使用 `-m` 参数指定足够内存：
```bash
qemu-system-x86_64 -m 256M -drive format=raw,file=boot.img
```

#### 原因 2: BIOS 不支持 E820

**检查：**
查看串口输出中是否尝试了 E801 或 88h 回退。

**解决方案：**
E820 回退机制应该自动工作。如果全部失败：
1. 检查 Bootloader 的 INT 15h 调用是否正确
2. 验证寄存器值设置
3. 尝试在真实硬件上测试

#### 原因 3: 缓冲区地址无效

**检查：**
```asm
; Bootloader 中检查
mov di, E820_STORAGE_ADDR  ; 应该是 0xC000
```

**解决方案：**
确保 `E820_STORAGE_ADDR` 在可访问的内存范围内：
```asm
; 确保在实模式下可访问
mov ax, 0x0000
mov es, ax              ; ES = 0
mov di, 0xC000          ; 物理地址 0x00C00
```

#### 原因 4: 签名验证失败

**检查：**
```asm
cmp eax, 'SMAP'         ; 检查返回签名
jne .e820_failed
```

**解决方案：**
某些旧 BIOS 可能不返回 'SMAP' 签名。可以尝试放宽检查：
```asm
; 只检查 CF 标志，忽略签名
int 0x15
jc .e820_failed
; 继续，不检查签名
```

## 2. 物理帧分配失败

### 症状
- `pframe_alloc()` 返回 `PFRAME_ERR_OOM`
- `pframe_get_free_frames()` 返回 0
- 系统运行一段时间后无法分配内存

### 可能原因

#### 原因 1: 分配器未正确初始化

**检查：**
```c
// 在 kernel_init.c 中
e820_init();
pframe_init();  // 必须在 e820_init() 之后调用
```

**解决方案：**
确保初始化顺序正确：
1. `e820_init()` 必须先于 `pframe_init()`
2. 检查 `pframe_init()` 返回值
```c
if (pframe_init() != PFRAME_OK) {
    klog_error("Failed to initialize pframe allocator\n");
}
```

#### 原因 2: 内核区域未被标记为保留

**检查：**
```bash# 在串口输出中查看
pframe_dump();
# 检查内核所在区域是否被标记为已分配
```

**解决方案：**
确保在 `pframe_init()` 中标记内核区域：
```c
// 内核物理地址范围
#define KERNEL_PHYS_BASE  0x10000
#define KERNEL_PHYS_SIZE  0x10000  // 根据实际大小调整

pframe_mark_region(KERNEL_PHYS_BASE, KERNEL_PHYS_SIZE, PFRAME_RESERVED);
```

#### 原因 3: 内存碎片化

**检查：**
```c
pframe_stats_t stats;
pframe_get_stats(&stats);
klog_info("Free: %llu, Allocated: %llu\n",
          stats.free_frames, stats.allocated_frames);
```

**解决方案：**
1. 尽量分配大小相近的帧
2. 考虑实现帧合并功能
3. 使用 `pframe_alloc_n()` 分配连续帧

#### 原因 4: 位图太小

**检查：**
```bash
# 检查位图大小
pframe_dump();
# 查看 bitmap_size_bytes 值
```

**解决方案：**
位图大小应根据实际内存计算：
```c
uint64_t required_bytes = (total_frames + 7) / 8;
if (bitmap_qwords * 8 < required_bytes) {
    klog_error("Bitmap too small!\n");
}
```

## 3. 内存地图解析错误

### 症状
- `e820_dump_map()` 显示异常值
- 某些内存区域显示为类型 0 或未知类型
- 统计的总内存与预期不符

### 可能原因

#### 原因 1: 结构体对齐问题

**检查：**
```c
typedef struct PACKED e820_entry {
    uint64_t base;
    uint64_t length;
    uint32_t type;
    uint32_t acpi_attrs;
} e820_entry_t;  // 确保是 24 字节
```

**解决方案：**
使用 `PACKED` 宏确保结构体没有填充：
```c
#define PACKED __attribute__((packed))
```

#### 原因 2: 字节序问题

**检查：**
```bash
# 在串口输出中查看
# E820 条目的 base/length 值是否异常
```

**解决方案：**
x86 平台是小端序，确保正确解析：
```c
// 直接读取，不需要字节序转换
e820_entry_t* entry = (e820_entry_t*)E820_STORAGE_ADDR;
uint64_t base = entry->base;  // 直接读取
```

#### 原因 3: 检测方法混淆

**检查：**
```bash
# 查看检测方法
klog_info("Detection method: %s\n",
          e820_get_detect_method_name(e820_get_detect_method()));
```

**解决方案：**
不同检测方法的条目格式不同。确保转换正确：
```c
// E801 和 88h 需要手动构造 E820 条目
if (method == MEM_DETECT_E801) {
    // 转换 E801 数据为 E820 格式
    convert_e801_to_e820();
}
```

## 4. QEMU 运行问题

### 症状
- QEMU 启动后立即崩溃
- 串口输出停止在内存检测阶段
- VGA 显示异常

### 可能原因

#### 原因 1: 内存地址冲突

**检查：**
```bash
# 使用 QEMU Monitor 查看内存
info tlb
info mem
```

**解决方案：**
确保内存布局不冲突：
```
0x00000 - 0x7FFFF    : BIOS/conventional (640KB)
0x80000 - 0x9FFFF    : 扩展 BIOS
0xC000   - 0xFFFF    : ★ 内存地图存储 (避免冲突)
0x10000+             : 内核
```

#### 原因 2: 页表配置错误

**检查：**
```bash
# 在 QEMU Monitor 中
info registers  # 查看 CR3 寄存器
```

**解决方案：**
确保页表正确初始化：
```c
// Stage 2 中设置页表
mov edi, 0x9000      ; 页表物理地址
; ... 初始化页表 ...
mov cr3, edi
```

#### 原因 3: 保护模式切换问题

**检查：**
```asm
; 检查 CR0.PG 位
mov eax, cr0
or eax, 0x80000001   ; PE + PG
mov cr0, eax
```

**解决方案：**
确保在启用分页前：
1. 页表已正确设置
2. CR3 已加载
3. 段选择子正确

## 5. 编译和链接问题

### 症状
- CMake 配置失败
- 链接时出现 undefined reference
- 头文件找不到

### 可能原因

#### 原因 1: 配置文件未生成

**检查：**
```bash
ls build/include/mem_config.h
ls build/mem_detect_constants.inc
```

**解决方案：**
确保 CMake 配置正确：
```cmake
# 在 CMakeLists.txt 中
configure_file(
    ${CMAKE_CURRENT_SOURCE_DIR}/MemConfig.h.in
    ${CMAKE_BINARY_DIR}/include/mem_config.h
)
```

#### 原因 2: 包含路径错误

**检查：**
```c
#include "mm/memory_detect/e820.h"  // 确保路径正确
```

**解决方案：**
在 `kernel/CMakeLists.txt` 中添加包含目录：
```cmake
target_include_directories(kernel PRIVATE
    ${CMAKE_SOURCE_DIR}/kernel
    ${CMAKE_BINARY_DIR}/include  # 生成的头文件
)
```

#### 原因 3: 链接顺序错误

**检查：**
```bash
# 查看链接命令
nm build/kernel.bin | grep e820
```

**解决方案：**
确保正确的链接顺序：
```cmake
# 在 kernel/CMakeLists.txt 中
add_subdirectory(mm)  # 先添加子目录
target_link_libraries(kernel PRIVATE
    # ... 其他库
)
```

## 7. 常见错误信息

### "Memory detection failed: E820 not supported"

**含义：** BIOS 不支持 E820 扩展内存检测。

**解决：** 系统会自动尝试 E801 和 88h 回退。

### "pframe_alloc: Out of memory"

**含义：** 没有可用的物理帧。

**解决：**
1. 检查 `pframe_get_free_frames()` 的返回值
2. 确认是否有内存泄漏
3. 检查初始化是否正确

### "e820_is_range_usable: Invalid range"

**含义：** 检查的内存范围超出物理内存。

**解决：**
1. 检查 base + length 是否溢出
2. 确保 base 和 length 是有效的

### "pframe_init: Invalid E820 map"

**含义：** E820 内存地图格式不正确。

**解决：**
1. 检查 `e820_get_entry_count()` 返回值
2. 验证每个条目的 type 字段

## 8. 预防性检查清单

在提交代码前，确保：

- [ ] 内存检测在 QEMU 中正常工作
- [ ] E820 条目数合理（通常 5-20 条）
- [ ] 物理帧分配器初始化成功
- [ ] `pframe_alloc()` 和 `pframe_free()` 配对测试通过
- [ ] 连续帧分配测试通过
- [ ] 内存统计值正确
- [ ] 串口和 VGA 输出一致
- [ ] 在不同内存配置下测试（128MB, 256MB, 512MB）

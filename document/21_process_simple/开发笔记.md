## 为什么需要进程管理

### 1. 从单线程到多进程

Stage 20 实现了系统调用框架，但操作系统仍然是单线程执行的。这存在以下限制：

- **无法并发执行**：同时只能运行一个程序
- **没有隔离性**：所有代码共享同一地址空间
- **容错性差**：一个程序崩溃会导致整个系统崩溃
- **资源管理困难**：无法公平分配 CPU 时间

### 2. 进程管理的优势

进程管理解决了上述问题：

- **多任务能力**：多个程序可以"同时"运行
- **内存隔离**：每个进程有独立的地址空间
- **容错性强**：一个进程崩溃不影响其他进程
- **资源公平**：通过调度器公平分配 CPU

### 3. 为什么现在实现

在 Stage 20 系统调用完成后，我们已经具备了：

- 完善的系统调用机制
- 虚拟内存管理 (VMM)
- 中断处理框架
- 物理内存管理

这些是进程管理实现的必要前置条件。

### 4. 与标准进程管理的区别

```c
// 标准 Linux 进程 API
pid_t fork(void);
void exit(int status);
pid_t wait(int *status);
pid_t getpid(void);
pid_t getppid(void);
```

**主要区别**：
- 运行环境：我们运行在裸机内核
- 实现简化：当前 fork 不做写时复制
- 调度算法：简单轮转，非抢占式
- 线程安全：当前实现未考虑多核

## 进程管理设计基础

### 1. 进程与线程

| 特性 | 进程 | 线程 |
|------|------|------|
| 地址空间 | 独立 | 共享 |
| 资源 | 独立 | 共享 |
| 通信 | IPC | 直接访问 |
| 创建开销 | 大 | 小 |
| 隔离性 | 强 | 弱 |

**当前实现**：只实现了进程，线程是未来改进方向。

### 2. 进程状态

```
┌─────────┐
│  NEW    │  进程创建中
└────┬────┘
     │ fork()
     ▼
┌─────────┐    schedule()    ┌─────────┐
│  READY  │ ────────────────> │ RUNNING │
└─────────┘                   └────┬────┘
     ▲                              │
     │                              │ exit()
     │                              ▼
     │                        ┌─────────┐
     │                        │  ZOMBIE │
     │                        └────┬────┘
     │                              │
     │                              │ wait4()
     │                              ▼
     └────────────────────────  (reaped)
```

**状态说明**：
- **NEW**: 进程正在创建
- **READY**: 等待 CPU，在运行队列中
- **RUNNING**: 正在执行
- **BLOCKED**: 等待 I/O 或事件
- **ZOMBIE**: 已退出，等待父进程回收

### 3. 调度算法选择

常见的调度算法：

#### Round-Robin (轮转) ✅
- 每个进程分配固定时间片
- 公平性好
- 实现简单

#### Priority Scheduling (优先级调度)
- 按优先级选择进程
- 可能导致饥饿

#### Completely Fair Scheduler (CFS)
- Linux 使用的调度器
- 按运行时间排序
- 实现复杂

**我们的选择**：Round-Robin
- 适合教学目的
- 实现简单直观
- 公平性可接受
- 后续可扩展

## 设计决策

### 1. 简化的 fork 实现

#### 决策：fork 不做完整内存复制

```c
int32_t proc_fork(void) {
    // 当前简化实现：
    // 1. 创建空的地址空间
    // 2. TODO: 添加写时复制 (COW)
}
```

**理由**：
- 写时复制实现复杂
- 当前阶段重点是建立进程框架
- 演示程序不需要完整的 fork

**后续改进**：
- 添加 COW 页错误处理
- 复制用户空间内存

### 2. Bitmap PID 分配

#### 决策：使用 bitmap 管理 PID

```c
#define MAX_PID 256
static uint64_t pid_bitmap[MAX_PID / 64];  // 4 个 uint64_t
```

**理由**：
- O(1) 分配和释放
- 内存占用小（32 字节）
- 简单可靠

**替代方案**：
- 线性搜索：O(n) 时间
- 动态增长：复杂度高

### 3. 独立地址空间

#### 决策：每个进程独立的 PML4

```c
typedef struct memory_context {
    physical_addr_t pml4_phys;    // 独立页表
    virtual_addr_t brk;           // 堆结束
    virtual_addr_t stack_start;   // 栈起始
} memory_context_t;
```

**理由**：
- 完全的内存隔离
- 符合现代 OS 设计
- 便于实现保护

**代价**：
- 上下文切换需要切换 CR3
- 内核代码需要映射到每个空间

### 4. 内核栈分离

#### 决策：每个进程独立的内核栈

```c
typedef struct pcb {
    virtual_addr_t kernel_stack;      // 内核栈顶
    virtual_addr_t kernel_stack_base; // 内核栈底
    // ...
} pcb_t;
```

**理由**：
- 用户态进入内核时使用独立栈
- 防止栈溢出影响内核
- 符合 x86_64 ABI 要求

**实现**：
- TSS.rsp0 存储内核栈指针
- 特权级切换时自动加载

### 5. 汇编实现上下文切换

#### 决策：关键路径使用汇编

```assembly
switch_context:
    # 保存寄存器
    # 切换栈
    # 切换地址空间
    # 恢复寄存器
    # 返回
```

**理由**：
- 精确控制寄存器
- 避免编译器干扰
- 性能最优

**注意事项**：
- 必须保存 callee-saved 寄存器
- 正确处理返回地址

### 2. 进程控制块 (PCB)

```c
typedef struct pcb {
    // === 进程标识 ===
    int32_t pid;                    // 进程 ID
    int32_t ppid;                   // 父进程 ID
    char comm[16];                  // 命令名

    // === 进程状态 ===
    process_state_t state;          // 当前状态
    int32_t exit_code;              // 退出码

    // === 链表节点 ===
    list_head run_list;             // 运行队列
    list_head siblings;             // 兄弟进程
    list_head children;             // 子进程
    list_head zombie_children;      // 僵尸子进程

    // === 内存上下文 ===
    memory_context_t mm;            // 地址空间
    virtual_addr_t kernel_stack;    // 内核栈顶
    virtual_addr_t kernel_stack_base; // 内核栈底

    // === 执行上下文 ===
    cpu_context_t* cpu_ctx;         // 保存的 CPU 状态
    trap_frame_t* trap_frame;       // 用户陷阱帧

    // === 家族关系 ===
    struct pcb* parent;             // 父进程指针
    uint64_t start_time;            // 创建时间
} pcb_t;
```

## 实现细节

### 1. 初始化流程

```c
int proc_init(void) {
    // 1. 初始化 PID 分配器
    pid_alloc_init();

    // 2. 初始化调度器
    scheduler_init();

    // 3. 创建 init 进程 (PID 1)
    pcb_t* init = create_init_process();

    // 4. 设置当前进程
    set_current_process(init);

    // 5. 添加到运行队列
    schedule_add(init);

    return 0;
}
```

### 2. fork 流程

```c
int32_t proc_fork(void) {
    pcb_t* parent = proc_current();

    // 1. 分配新 PID
    int32_t pid = pid_alloc();
    if (pid < 0) return -1;  // PID 耗尽

    // 2. 分配新 PCB
    pcb_t* child = kmalloc(sizeof(pcb_t));
    if (!child) {
        pid_free(pid);
        return -1;
    }

    // 3. 初始化 PCB
    child->pid = pid;
    child->ppid = parent->pid;
    child->state = PROC_READY;

    // 4. 创建新地址空间
    if (vmm_create_user_space(&child->mm.pml4_phys) != VMM_OK) {
        kfree(child);
        pid_free(pid);
        return -1;
    }

    // 5. 分配内核栈
    child->kernel_stack = alloc_kernel_stack();
    child->kernel_stack_base = child->kernel_stack - KERNEL_STACK_SIZE;

    // 6. 设置执行上下文
    child->cpu_ctx = setup_cpu_context(child);
    child->trap_frame = copy_trap_frame(parent->trap_frame);

    // 7. 建立家族关系
    list_add(&child->siblings, &parent->children);
    child->parent = parent;

    // 8. 添加到运行队列
    schedule_add(child);

    return child->pid;  // 返回子进程 PID
}
```

### 3. 上下文切换

#### 汇编实现

```assembly
# switch_context(pcb_t** prev, pcb_t* next)
# rdi = &prev->cpu_ctx
# rsi = next
.global switch_context
switch_context:
    # === 保存当前进程状态 ===

    # 保存 callee-saved 寄存器
    mov %rax, (%rdi)       # [0]  rax
    mov %rbx, 8(%rdi)      # [8]  rbx
    mov %rbp, 16(%rdi)     # [16] rbp
    mov %r12, 24(%rdi)     # [24] r12
    mov %r13, 32(%rdi)     # [32] r13
    mov %r14, 40(%rdi)     # [40] r14
    mov %r15, 48(%rdi)     # [48] r15

    # 保存返回地址 (RIP)
    movq (%rsp), %rax
    mov %rax, 56(%rdi)     # [56] rip

    # 保存栈指针 (RSP)
    movq %rsp, 64(%rdi)    # [64] rsp

    # === 切换到下一个进程 ===

    # 更新 TSS 内核栈
    mov PCB_KERNEL_STACK_OFFSET(%rsi), %rdx
    mov %rdx, %gs:0        # 设置 TSS.rsp0

    # 切换地址空间 (CR3)
    mov PCB_PML4_OFFSET(%rsi), %rdx
    mov %rdx, %cr3

    # === 恢复下一个进程状态 ===

    # 恢复栈指针
    mov 64(%rsi), %rsp

    # 恢复返回地址
    mov 56(%rsi), %rax
    push %rax

    # 恢复 callee-saved 寄存器
    mov 8(%rsi), %rbx
    mov 16(%rsi), %rbp
    mov 24(%rsi), %r12
    mov 32(%rsi), %r13
    mov 40(%rsi), %r14
    mov 48(%rsi), %r15

    ret
```

#### C 调用

void schedule(void) {
    pcb_t* prev = current;
    pcb_t* next = pick_next_process();

    if (prev != next) {
        current = next;
        switch_context(&prev->cpu_ctx, next);
    }
}

### 4. exit 流程

```c
void proc_exit(int exit_code) {
    pcb_t* current = proc_current();

    // 1. 设置退出状态
    current->state = PROC_ZOMBIE;
    current->exit_code = exit_code;

    // 2. 从运行队列移除
    schedule_remove(current);

    // 3. 唤醒等待的父进程
    if (current->parent->state == PROC_BLOCKED) {
        current->parent->state = PROC_READY;
        schedule_add(current->parent);
    }

    // 4. 将子进程移交给 init
    reparent_children_to_init(current);

    // 5. 调度新进程
    schedule();
}
```

### 5. wait4 流程

```c
int32_t proc_wait4(int32_t pid, int* wstatus, int options) {
    pcb_t* current = proc_current();
    pcb_t* child;

    // 1. 查找子进程
    if (pid == -1) {
        child = find_any_zombie_child(current);
    } else {
        child = find_child_by_pid(current, pid);
    }

    // 2. 如果子进程未退出，阻塞当前进程
    if (!child || child->state != PROC_ZOMBIE) {
        if (options & WNOHANG) {
            return 0;  // 非阻塞
        }
        current->state = PROC_BLOCKED;
        schedule();  // 切换到其他进程
        // 唤醒后重新查找
        child = find_any_zombie_child(current);
    }

    // 3. 收集退出状态
    if (wstatus) {
        *wstatus = child->exit_code;
    }

    // 4. 回收僵尸进程
    int32_t ret_pid = child->pid;
    reap_zombie_child(current, child);

    return ret_pid;
}
```

### 6. 调度器

```c
void schedule(void) {
    // 1. 从运行队列选择下一个进程
    pcb_t* next = list_first_entry(&scheduler.run_queue, pcb_t, run_list);

    // 2. 如果没有就绪进程，运行 idle 进程
    if (!next) {
        next = scheduler.idle;
    }

    // 3. 切换进程
    if (scheduler.current != next) {
        pcb_t* prev = scheduler.current;
        scheduler.current = next;

        // 更新 TSS
        tss_set_kernel_stack_ctx(next->kernel_stack);

        // 切换地址空间
        vmm_load_pml4(next->mm.pml4_phys);

        // 上下文切换
        switch_context(&prev->cpu_ctx, next);
    }
}
```

## 常见陷阱与注意事项

### 1. 僵尸进程

**问题**：子进程退出后未被回收

```c
// 父进程忘记 wait
if (fork() == 0) {
    exit(0);
}
// 父进程继续运行，不调用 wait()
```

**现象**：
```
[PROC] Zombie process: PID 123
```

**解决方案**：
- 父进程必须调用 wait() 或 waitpid()
- init 进程 (PID 1) 自动回收孤儿进程

### 2. 内存泄漏

**问题**：退出进程时未释放资源

```c
void proc_exit(int exit_code) {
    // 忘记释放内核栈
    // 忘记销毁地址空间
    // 忘记释放 PCB
}
```

**预防**：
```c
void proc_exit(int exit_code) {
    // 1. 释放内核栈
    kfree((void*)current->kernel_stack_base);

    // 2. 销毁地址空间
    vmm_destroy_user_space(current->mm.pml4_phys);

    // 3. 最后才释放 PCB (由父进程 wait 时回收)
}
```

### 3. 竞态条件

**问题**：多核环境下的并发访问

```c
// 非线程安全的 PID 分配
int32_t pid_alloc(void) {
    int bit = find_free_bit();
    pid_bitmap[bit / 64] |= (1ULL << (bit % 64));  // 竞态!
    return bit;
}
```

**预防**（未来改进）：
- 添加自旋锁保护
- 使用原子操作

### 4. 栈溢出

**问题**：内核栈太小

```c
#define KERNEL_STACK_SIZE  0x1000  // 4KB 可能太小
```

**现象**：
```
[DOUBLE FAULT] Stack overflow
```

**解决方案**：
- 增大内核栈 (16KB)
- 启用栈溢出检测

### 5. 上下文切换错误

**问题**：汇编中寄存器保存不完整

```assembly
# 忘记保存 rbx
switch_context:
    mov %rax, (%rdi)
    # mov %rbx, 8(%rdi)  # 漏掉!
    mov %rbp, 16(%rdi)
    # ...
```

**后果**：
- 进程切换后返回错误地址
- 数据损坏
- 系统崩溃

**预防**：
- 严格按照 ABI 保存寄存器
- 使用编译器属性检查

### 6. 地址空间泄漏

**问题**：PML4 未释放

```c
vmm_result_t vmm_create_user_space(physical_addr_t* out_pml4) {
    // 分配 PML4
    *out_pml4 = pframe_alloc();
    // ...
}

// 忘记释放
void proc_exit(int exit_code) {
    // vmm_destroy_user_space(current->mm.pml4_phys);  // 漏掉!
}
```

**预防**：
- 实现引用计数
- 在 wait4 时释放

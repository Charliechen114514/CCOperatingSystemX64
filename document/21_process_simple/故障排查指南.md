## 初始化问题

### 问题 1：进程子系统初始化失败

**症状**：
```
[PROC] Failed to initialize process subsystem
```

**可能原因**：
1. VMM 未初始化
2. 内核栈分配失败
3. PID 分配器初始化失败

**诊断步骤**：
```c
// 检查初始化顺序
void kernel_init(void) {
    pframe_init();    // 1. 物理帧
    page_init();      // 2. 页表
    vmm_init();       // 3. 虚拟内存
    // 确保上面都成功后再调用 proc_init
    if (proc_init() != 0) {
        klog_error("proc_init failed\n");
        while(1) halt();
    }
}
```

**解决方案**：
1. 确保 `vmm_init()` 在 `proc_init()` 之前调用
2. 检查物理内存是否足够
3. 验证 PID bitmap 内存分配成功

### 问题 2：init 进程创建失败

**症状**：
```
[PROC] Failed to create init process
```

**可能原因**：
1. PCB 分配失败
2. 内核栈分配失败
3. 地址空间创建失败

**诊断步骤**：
```c
// 添加详细错误日志
int proc_init(void) {
    pcb_t* init = kmalloc(sizeof(pcb_t));
    if (!init) {
        klog_error("[PROC] PCB allocation failed\n");
        return -1;
    }

    init->kernel_stack = alloc_kernel_stack();
    if (!init->kernel_stack) {
        klog_error("[PROC] Kernel stack allocation failed\n");
        kfree(init);
        return -1;
    }

    // ...
}
```

**解决方案**：
1. 增加 `KERNEL_STACK_SIZE`
2. 检查堆分配器是否正常工作
3. 验证 VMM 用户空间创建函数

## 进程创建问题

### 问题 3：fork 返回错误

**症状**：
```c
int32_t pid = proc_fork();
if (pid < 0) {
    klog_error("fork failed: %d\n", pid);
}
// 输出: fork failed: -1
```

**可能原因**：
1. PID 耗尽 (MAX_PROCS 达到上限)
2. 内存不足 (PCB 或内核栈分配失败)
3. 地址空间创建失败

**诊断步骤**：
```c
// 检查当前进程数
void check_process_count(void) {
    int count = 0;
    pcb_t* proc = NULL;
    list_for_each_entry(proc, &scheduler.run_queue, run_list) {
        count++;
    }
    klog_info("Running processes: %d / %d\n", count, MAX_PROCS);
}
```

**解决方案**：
```c
// 增加 MAX_PROCS
#define MAX_PROCS  512  // 从 256 增加到 512

// 或实现进程回收
// 确保父进程正确调用 wait4
```

### 问题 4：子进程状态异常

**症状**：
```
[PROC] Child process state invalid: 0
```

**可能原因**：
1. PCB 未正确初始化
2. 状态字段未设置
3. 内存损坏

**诊断步骤**：
```c
// 添加 PCB 验证
bool validate_pcb(pcb_t* proc) {
    if (!proc) return false;
    if (proc->pid <= 0 || proc->pid >= MAX_PROCS) return false;
    if (proc->state < PROC_READY || proc->state > PROC_ZOMBIE) return false;
    return true;
}

// fork 后验证
int32_t pid = proc_fork();
if (pid > 0) {
    pcb_t* child = proc_find(pid);
    if (!validate_pcb(child)) {
        klog_error("[PROC] Invalid child PCB\n");
    }
}
```

**解决方案**：
1. 确保 fork 时正确设置 `state = PROC_READY`
2. 使用 `memzero()` 清零 PCB
3. 添加魔数检测

## 进程退出问题

### 问题 5：僵尸进程累积

**症状**：
```
[PROC] Zombie process detected: PID 123
[PROC] Zombie process detected: PID 124
[PROC] Zombie process detected: PID 125
```

**可能原因**：
1. 父进程未调用 wait()
2. 父进程先于子进程退出
3. wait4 逻辑错误

**诊断步骤**：
```c
// 检查僵尸进程
void check_zombie_processes(void) {
    pcb_t* current = proc_current();
    int zombie_count = 0;

    list_head* pos;
    list_for_each(pos, &current->zombie_children) {
        zombie_count++;
    }

    if (zombie_count > 0) {
        klog_warn("[PROC] %d zombie children\n", zombie_count);
    }
}
```

**解决方案**：
```c
// 正确的 fork/wait 模式
int32_t pid = proc_fork();
if (pid > 0) {
    // 父进程：等待子进程
    int status;
    proc_wait4(pid, &status, 0);
} else if (pid == 0) {
    // 子进程
    proc_exit(0);
}

// 或在父进程退出时回收
void proc_exit(int exit_code) {
    // 将子进程移交给 init
    reparent_children_to_init(current);
}
```

### 问题 6：孤儿进程

**症状**：
```
[PROC] Orphan process detected: PID 200
```

**可能原因**：
父进程先于子进程退出

**诊断步骤**：
```c
// 检查父进程是否存在
bool is_parent_alive(pcb_t* proc) {
    if (proc->ppid == 0) return false;  // 没有父进程
    pcb_t* parent = proc_find(proc->ppid);
    return (parent != NULL);
}
```

**解决方案**：
```c
// 在 proc_exit 中重新父化子进程
void reparent_children_to_init(pcb_t* proc) {
    pcb_t* init = proc_find(INIT_PID);
    if (!init) {
        klog_error("[PROC] init process not found\n");
        return;
    }

    list_head* pos, *next;
    list_for_each_safe(pos, next, &proc->children) {
        pcb_t* child = list_entry(pos, pcb_t, siblings);
        child->parent = init;
        list_move_tail(pos, &init->children);
    }
}
```

## 上下文切换问题

### 问题 7：上下文切换后崩溃

**症状**：
```
[DOUBLE FAULT] Context switch failed
[GENERAL PROTECTION FAULT]
```

**可能原因**：
1. 寄存器保存/恢复不完整
2. 栈指针错误
3. CR3 切换错误

**诊断步骤**：
```c
// 在 switch_context 前后添加日志
void schedule(void) {
    pcb_t* prev = scheduler.current;
    pcb_t* next = pick_next_process();

    klog_debug("[SCHED] Switching: %d -> %d\n", prev->pid, next->pid);
    klog_debug("[SCHED] prev->cpu_ctx = 0x%p\n", prev->cpu_ctx);
    klog_debug("[SCHED] prev->rsp = 0x%llx\n", prev->cpu_ctx->rsp);

    switch_context(&prev->cpu_ctx, next);

    klog_debug("[SCHED] Switched to %d\n", next->pid);
}
```

**解决方案**：
1. 检查汇编中的寄存器保存顺序
2. 确保 TSS 内核栈正确设置
3. 验证 CR3 值有效

```assembly
# 验证 CR3 加载
mov PCB_PML4(%rsi), %rdx
test %rdx, %rdx
jz invalid_cr3
mov %rdx, %cr3
```

### 问题 8：栈溢出

**症状**：
```
[DOUBLE FAULT] Stack overflow
[PAGE FAULT] at 0x...
```

**可能原因**：
1. 内核栈太小
2. 递归调用过深
3. 局部变量过大

**诊断步骤**：
```c
// 添加栈检查
void check_stack_usage(void) {
    virtual_addr_t current_stack;
    __asm__ volatile("mov %%rsp, %0" : "=r"(current_stack));

    pcb_t* proc = proc_current();
    uint64_t stack_used = proc->kernel_stack - current_stack;
    uint64_t stack_total = KERNEL_STACK_SIZE;

    klog_debug("[STACK] Used: %llu / %llu bytes\n",
               stack_used, stack_total);

    if (stack_used > stack_total * 0.9) {
        klog_warn("[STACK] Stack almost full!\n");
    }
}
```

**解决方案**：
```c
// 增大内核栈
#define KERNEL_STACK_SIZE  0x8000  // 32KB

// 使用循环代替递归
// 减少局部变量大小
```

## 内存管理问题

### 问题 9：地址空间切换失败

**症状**：
```
[PAGE FAULT] Invalid address: 0x...
```

**可能原因**：
1. PML4 物理地址错误
2. 页表未正确设置
3. CR3 切换时机错误

**诊断步骤**：
```c
// 验证 PML4 地址
void validate_pml4(physical_addr_t pml4_phys) {
    klog_debug("[VMM] PML4 phys: 0x%llx\n", pml4_phys);

    // 检查是否在有效范围内
    if (pml4_phys < 0x100000 || pml4_phys > 0x100000000) {
        klog_error("[VMM] Invalid PML4 address\n");
    }
}

// 在切换前验证
void vmm_load_pml4_safe(physical_addr_t pml4_phys) {
    validate_pml4(pml4_phys);
    __asm__ volatile("mov %0, %%cr3" : : "r"(pml4_phys) : "memory");
}
```

**解决方案**：
1. 确保 `vmm_create_user_space()` 正确初始化 PML4
2. 验证物理帧分配成功
3. 检查内核映射在所有用户空间中都存在

### 问题 10：内存泄漏

**症状**：
```
[HEAP] Out of memory
```

**可能原因**：
1. 退出进程时未释放 PCB
2. 内核栈未释放
3. 地址空间未销毁

**诊断步骤**：
```c
// 添加资源跟踪
static uint32_t pcb_count = 0;
static uint32_t kernel_stack_count = 0;

pcb_t* alloc_pcb(void) {
    pcb_t* pcb = kmalloc(sizeof(pcb_t));
    if (pcb) {
        pcb_count++;
        klog_debug("[ALLOC] PCB count: %u\n", pcb_count);
    }
    return pcb;
}

void free_pcb(pcb_t* pcb) {
    kfree(pcb);
    pcb_count--;
    klog_debug("[FREE] PCB count: %u\n", pcb_count);
}
```

**解决方案**：
```c
// 在 wait4 中完整清理
int32_t proc_wait4(int32_t pid, int* wstatus, int options) {
    pcb_t* zombie = find_zombie_child(current);

    // 释放内核栈
    kfree((void*)zombie->kernel_stack_base);
    kernel_stack_count--;

    // 销毁地址空间
    vmm_destroy_user_space(zombie->mm.pml4_phys);

    // 释放 CPU 上下文
    kfree(zombie->cpu_ctx);

    // 释放 trap_frame
    kfree(zombie->trap_frame);

    // 释放 PCB
    kfree(zombie);
}
```

### 技巧 2：打印进程树

```c
void print_process_tree(void) {
    klog_info("=== Process Tree ===\n");

    pcb_t* init = proc_find(INIT_PID);
    if (!init) {
        klog_error("init not found\n");
        return;
    }

    print_process_subtree(init, 0);
}

void print_process_subtree(pcb_t* proc, int depth) {
    // 打印缩进
    for (int i = 0; i < depth; i++) {
        klog_info("  ");
    }

    // 打印进程信息
    const char* state_str[] = {"READY", "RUNNING", "BLOCKED", "ZOMBIE"};
    klog_info("PID %d (%s) - %s\n",
             proc->pid,
             proc->comm,
             state_str[proc->state]);

    // 递归打印子进程
    pcb_t* child;
    list_for_each_entry(child, &proc->children, siblings) {
        print_process_subtree(child, depth + 1);
    }
}
```

## 检查清单

### 系统启动检查

- [ ] 运行队列不为空
- [ ] 当前进程指针有效

- [ ] PID 分配成功

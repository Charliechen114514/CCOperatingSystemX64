## 为什么需要用户态进程支持

### 1. 从内核态到用户态

Stage 22 实现了调度器分类，但所有进程仍然运行在内核态（Ring 0）。这存在以下限制：

- **安全性问题**：进程可以直接访问内核内存和硬件
- **稳定性问题**：错误的代码可能破坏整个系统
- **没有用户库**：所有代码必须链接到内核
- **无法独立运行程序**：不能加载和执行独立的用户程序

### 2. 用户态的优势

用户态进程支持解决了上述问题：

- **特权级隔离**：Ring 3 程序不能直接访问 Ring 0 资源
- **内存保护**：用户空间与内核空间分离
- **标准化接口**：通过系统调用访问内核服务
- **独立程序**：可以加载和执行 ELF 二进制文件

### 3. 为什么现在实现

在 Stage 22 调度器分类完成后，我们已经具备了：

- 完善的进程管理
- 虚拟内存管理 (VMM)
- 页错误处理
- 物理内存管理
- 系统调用框架

这些是实现用户态进程支持的必要前置条件。

### 4. 与标准 Linux 用户态的区别

```c
// 标准 Linux 用户程序
int main(int argc, char** argv) {
    printf("Hello, World!\n");
    return 0;
}

// 我们的实现 (简化)
void _start(void) {
    const char* msg = "Hello, World!\n";
    write(1, msg, 14);
    exit(0);
}
```

**主要区别**：
- 运行环境：我们运行在裸机操作系统上
- 实现简化：当前没有 ELF 加载器
- 库简化：用户库功能有限
- 程序嵌入：用户程序编译后嵌入内核镜像

## 用户态设计基础

### 1. x86_64 特权级

```
┌─────────────────────────────────────────────────────────┐
│                    Ring 0 (内核态)                      │
│  - 完全访问所有资源                                     │
│  - 可以执行所有指令                                     │
│  - 访问所有内存                                         │
└─────────────────────────────────────────────────────────┘
                         △
                         │ syscall / iretq
                         │
┌─────────────────────────────────────────────────────────┐
│                    Ring 3 (用户态)                      │
│  - 只能访问用户空间内存                                  │
│  - 不能执行特权指令                                     │
│  - 通过系统调用访问内核服务                             │
└─────────────────────────────────────────────────────────┘
```

### 2. 段选择器

| 段 | 选择器 | 描述 |
|---|--------|------|
| 内核代码 | 0x08 | GDT_KERNEL_CODE |
| 内核数据 | 0x10 | GDT_KERNEL_DATA |
| 用户代码 | 0x18 \| 3 = 0x1B | GDT_USER_CODE + RPL=3 |
| 用户数据 | 0x20 \| 3 = 0x23 | GDT_USER_DATA + RPL=3 |

### 3. 用户空间布局

```
┌─────────────────────────────────────────────────────────┐
│                    内核空间 (高地址)                     │
│  - 内核代码和数据                                       │
│  - 永久映射                                             │
└─────────────────────────────────────────────────────────┘
                    USER_END = 0xFFFF800000000000
                         │
┌─────────────────────────────────────────────────────────┐
│                    用户栈 (1MB)                         │
│  - 向下增长                                             │
│  - 保护页                                               │
├─────────────────────────────────────────────────────────┤
│                    用户堆 (brk)                         │
│  - 向上增长                                             │
│  - brk/mmap 管理                                        │
├─────────────────────────────────────────────────────────┤
│                    用户程序代码                         │
│  - 从 0x400000 开始                                     │
│  - 只读可执行                                           │
├─────────────────────────────────────────────────────────┤
│                    NULL 页保护                          │
│  - 最低 4MB 保护                                        │
└─────────────────────────────────────────────────────────┘
                    USER_BASE = 0x400000
```

### 4. 特权级切换方式

#### syscall (用户 → 内核)
```assembly
; 用户态执行
mov rax, SYS_WRITE      ; 系统调用号
mov rdi, 1              ; fd = stdout
mov rsi, buffer         ; buffer
mov rdx, length         ; length
syscall                 ; 切换到 Ring 0

; 内核态处理程序...
```

#### iretq (内核 → 用户)
```assembly
; 内核态设置
push USER_SS            ; SS
push user_rsp           ; RSP
push user_rflags        ; RFLAGS
push USER_CS            ; CS
push user_rip           ; RIP
iretq                   ; 切换到 Ring 3
```

## 设计决策

### 1. 用户程序嵌入内核

#### 决策：用户程序编译为二进制并嵌入内核

```cmake
# 转换为二进制
objcopy -O binary uname_test uname_test.bin

# 转换为对象文件
objcopy -I binary -O elf64-x86-64 -B i386 \
    --rename-section .data=.user_uname_test,alloc,load,readonly,data,contents \
    uname_test.bin uname_test.o
```

**理由**：
- 简化实现，不需要文件系统
- 避免复杂的 ELF 加载器
- 程序在编译时确定
- 适合早期开发和测试

**后续改进**：
- 实现 ELF 加载器
- 支持从文件系统加载
- 实现动态链接器

### 2. 用户栈大小和位置

#### 决策：1MB 用户栈，位于用户空间顶部

```c
#define USER_STACK_SIZE    (1 * 1024 * 1024)   // 1MB
#define USER_STACK_TOP     (USER_END - 8)

pcb->user_stack = (USER_END - USER_STACK_SIZE) & ~(PAGE_SIZE - 1);
```

**理由**：
- 1MB 足够大多数用户程序
- 位于高地址符合 Unix 传统
- 页对齐便于内存映射
- 可以方便扩展

**代价**：
- 每个进程消耗 1MB 物理内存
- 后续可考虑按需分配

### 3. 用户内存验证策略

#### 决策：基于范围验证，暂不完整实现页表遍历

```c
bool user_validate_pointer(const void* ptr, size_t size, bool write) {
    virtual_addr_t addr = (virtual_addr_t)ptr;

    // 检查用户空间范围
    if (!vmm_is_user_addr(addr)) return false;

    // 检查溢出
    if (addr + size < addr) return false;

    // 检查超出用户空间
    if (addr + size > USER_END) return false;

    return true;
}
```

**理由**：
- 快速简单
- 覆盖大多数情况
- 页表遍历复杂度高

**后续改进**：
- 添加实际页表检查
- 实现页错误修复
- 考虑延迟验证

### 4. 用户库独立编译

#### 决策：用户库与内核分别编译

```cmake
# 内核编译
add_library(userlib STATIC
    src/stdio.c
    src/stdlib.c
    src/unistd.c
    syscall/x86_64/syscall.c
)

# 用户程序编译
add_executable(uname_test programs/demo/uname_test.c)
```

**理由**：
- 用户程序不依赖内核符号
- 使用 freestanding 环境
- 符合标准 C 库设计

### 5. physical_addr_t 类型变更

#### 决策：从 uint32_t 改为 uint64_t

```c
// Stage 22
typedef uint32_t physical_addr_t;

// Stage 23
typedef uint64_t physical_addr_t;
```

**理由**：
- x86_64 支持最大 2^52 物理地址
- 32-bit 不足以表示高物理内存
- 与虚拟地址类型一致

### 1. 初始化流程

```c
int user_init(void) {

    klog_info("[USER] User stack size: %d MB\n",
              USER_STACK_SIZE / (1024 * 1024));
    klog_info("[USER] User space: 0x%llX - 0x%llX\n",
              USER_BASE, USER_END);
    return 0;
}
```

### 2. 用户进程创建

```c
int user_create_process(virtual_addr_t entry, pcb_t* pcb) {
    /* 分配用户栈 */
    size_t stack_pages = USER_STACK_SIZE / PAGE_SIZE;
    pcb->user_stack = (USER_END - USER_STACK_SIZE) & ~(PAGE_SIZE - 1);

    /* 映射用户栈页 */
    for (size_t i = 0; i < stack_pages; i++) {
        physical_addr_t paddr;
        pframe_alloc(&paddr);

        vmm_map_to_user(pcb->mm.pml4_phys,
                       pcb->user_stack + (i * PAGE_SIZE),
                       paddr, 1,
                       VMAP_FLAG_WRITE | VMAP_FLAG_USER);

        memset((void*)phys_to_virt_offset(paddr), 0, PAGE_SIZE);
    }

    pcb->is_user_mode = true;
    return 0;
}
```

### 3. Ring 3 切换

#### 汇编实现

```assembly
; user_switch_to_usermode(user_context_t* ctx)
global user_switch_to_usermode
user_switch_to_usermode:
    ; RDI = ctx

    ; 加载用户上下文
    mov rax, [rdi + user_context.entry]
    mov rbx, [rdi + user_context.stack_top]
    mov rcx, [rdi + user_context.cs]
    mov rdx, [rdi + user_context.ss]
    mov rsi, [rdi + user_context.rflags]

    ; 设置 iretq 栈帧
    push rdx        ; SS
    push rbx        ; RSP
    push rsi        ; RFLAGS
    push rcx        ; CS
    push rax        ; RIP

    ; 设置数据段
    mov ax, 0x23    ; USER_SS
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    iretq           ; 切换到 Ring 3
```

### 4. 用户内存管理

#### brk 实现

```c
virtual_addr_t user_brk(pcb_t* pcb, virtual_addr_t new_brk) {
    /* NULL 查询当前 break */
    if (new_brk == 0) {
        return pcb->mm.brk;
    }

    /* 页对齐 */
    new_brk = (new_brk + PAGE_SIZE - 1) & ~(PAGE_SIZE - 1);

    /* 验证范围 */
    if (new_brk < USER_BASE || new_brk >= (USER_END - USER_STACK_SIZE)) {
        return pcb->mm.brk;
    }

    /* 缩小：直接更新 */
    if (new_brk <= pcb->mm.brk) {
        pcb->mm.brk = new_brk;
        return new_brk;
    }

    /* 扩大：分配新页 */
    size_t old_brk = pcb->mm.brk ? pcb->mm.brk : (USER_BASE + 16*1024*1024);
    size_t additional_pages = (new_brk - old_brk) / PAGE_SIZE;

    for (size_t i = 0; i < additional_pages; i++) {
        physical_addr_t paddr;
        pframe_alloc(&paddr);

        vmm_map_to_user(pcb->mm.pml4_phys,
                       old_brk + (i * PAGE_SIZE),
                       paddr, 1,
                       VMAP_FLAG_WRITE | VMAP_FLAG_USER);
    }

    pcb->mm.brk = new_brk;
    return new_brk;
}
```

#### mmap 实现

```c
virtual_addr_t user_mmap(pcb_t* pcb, virtual_addr_t addr, size_t length,
                        int prot, int flags, int fd, size_t offset) {
    (void)fd;
    (void)offset;

    /* 页对齐 */
    length = (length + PAGE_SIZE - 1) & ~(PAGE_SIZE - 1);

    /* 转换保护标志 */
    uint64_t vmap_flags = VMAP_FLAG_USER;
    if (prot & PROT_WRITE) vmap_flags |= VMAP_FLAG_WRITE;
    if (!(prot & PROT_EXEC)) vmap_flags |= VMAP_FLAG_NO_EXEC;

    /* 查找空闲地址 */
    if (addr == 0) {
        addr = USER_BASE + (16 * 1024 * 1024);
        if (pcb->mm.brk > addr) addr = pcb->mm.brk;
        addr = (addr + PAGE_SIZE - 1) & ~(PAGE_SIZE - 1);
    }

    /* 分配和映射页 */
    for (size_t i = 0; i < length / PAGE_SIZE; i++) {
        physical_addr_t paddr;
        pframe_alloc(&paddr);

        vmm_map_to_user(pcb->mm.pml4_phys,
                       addr + (i * PAGE_SIZE),
                       paddr, 1, vmap_flags);
    }

    return addr;
}
```

### 6. 系统调用实现

#### uname 系统调用

```c
static int64_t sys_uname(syscall_frame_t* frame) {
    struct utsname* buf = (struct utsname*)frame->arg0;

    /* 验证用户指针 */
    if (!user_validate_pointer(buf, sizeof(struct utsname), true)) {
        return SYS_ERR_INVAL;
    }

    /* 填充系统信息 */
    struct utsname kernel_info = {
        .sysname = "CCOS",
        .nodename = "localhost",
        .release = CCOS_VERSION,
        .version = "CCOS x86_64 v" CCOS_VERSION,
        .machine = "x86_64",
        .domainname = "(none current)",
    };

    /* 复制到用户空间 */
    int64_t result = user_copy_to_user(buf, &kernel_info,
                                       sizeof(struct utsname));
    return (result < 0) ? SYS_ERR_IO : SYS_OK;
}
```

## 常见陷阱与注意事项

### 1. 用户指针验证错误

**问题**：未验证用户指针导致内核崩溃

```c
// 错误实现
static int64_t sys_uname(syscall_frame_t* frame) {
    struct utsname* buf = (struct utsname*)frame->arg0;
    memcpy(buf, &kernel_info, sizeof(struct utsname));  // 危险!
    return SYS_OK;
}
```

**解决方案**：
```c
// 正确实现
if (!user_validate_pointer(buf, sizeof(struct utsname), true)) {
    return SYS_ERR_INVAL;
}
int64_t result = user_copy_to_user(buf, &kernel_info,
                                   sizeof(struct utsname));
```

### 2. 符号冲突

**问题**：用户程序和内核符号冲突

```c
// 用户程序
void _start(void) {
    // ...
}

// 内核也可能有 _start
```

**解决方案**：
- 用户程序使用 `_start` 作为入口
- 使用 objcopy 重命名符号
- 使用独立编译

### 3. 页对齐问题

**问题**：用户程序未对齐导致映射失败

```cmake
# 错误：没有对齐
objcopy -I binary -O elf64-x86-64 uname_test.bin uname_test.o
```

**解决方案**：
```cmake
# 正确：4096 字节对齐
objcopy --set-section-alignment .user_uname_test=4096
```

### 4. 段寄存器设置

**问题**：忘记设置用户数据段选择器

```assembly
user_switch_to_usermode:
    ; 设置 iretq 栈帧
    push ...
    ; 忘记设置段寄存器!
    iretq
```

**后果**：
- 进入用户态后段寄存器仍然指向内核
- 可能导致异常

**解决方案**：
```assembly
    mov ax, 0x23    ; USER_SS
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
```

### 5. Red Zone 问题

**问题**：用户代码访问 Red Zone 区域

```c
// 用户代码使用 -O2 优化
// 编译器可能使用 red zone
```

**解决方案**：
```cmake
# 添加 -mno-red-zone
target_compile_options(uname_test PRIVATE
    -mno-red-zone
)
```

### 6. 物理地址类型

**问题**：32-bit 物理地址不足以表示高内存

```c
// Stage 22
typedef uint32_t physical_addr_t;  // 只能到 4GB
```

**后果**：
- 高物理内存无法访问
- 页表映射错误

**解决方案**：
```c
// Stage 23
typedef uint64_t physical_addr_t;  // 支持到 2^52
```

### 7. 用户栈溢出

**问题**：用户程序递归过深

```c
void recursive(int n) {
    char buffer[1024];
    if (n > 0) recursive(n - 1);
}
```

**预防**：
- 设置合理的栈大小 (1MB)
- 添加栈保护页
- 实现栈溢出检测

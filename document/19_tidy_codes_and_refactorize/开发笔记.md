## 1. 为什么需要进程管理

### 1.1 问题背景

在 Stage 18 完成写时复制和异常处理后，系统具备了基本的内存管理能力，但缺乏进程管理功能：

- **无进程隔离**：所有代码在内核态运行，没有用户态进程概念
- **无并发执行**：无法同时运行多个程序
- **无资源保护**：进程间可能相互干扰
- **系统调用不完整**：fork、exit、wait4 等核心系统调用未实现

### 1.2 进程管理解决方案

实现完整的进程管理子系统需要：

1. **进程抽象**：用 PCB (Process Control Block) 表示进程
2. **调度器**：决定哪个进程运行
3. **上下文切换**：保存/恢复进程状态
4. **进程创建与销毁**：fork、exit、wait4 系统调用
5. **地址空间隔离**：每个进程独立的虚拟地址空间

## 2. 设计决策

### 2.1 PCB 结构设计

进程控制块（PCB）是进程管理的核心数据结构，需要包含：

| 类别 | 字段 | 用途 |
|:-----|:-----|:-----|
| 进程标识 | `pid`, `ppid` | 进程 ID 和父进程 ID |
| 进程状态 | `state`, `exit_code` | 当前状态和退出码 |
| 调度信息 | `run_list`, `children` | 运行队列和子进程列表 |
| 内存上下文 | `mm` | 地址空间信息 |
| CPU 上下文 | `cpu_ctx`, `kernel_stack` | 寄存器状态和内核栈 |
| 统计信息 | `start_time`, `comm` | 创建时间和命令名 |

**设计原则**：
- 保持 PCB 结构紧凑，避免过大
- 分离 CPU 上下文（动态分配）与静态字段
- 使用内核链表 (`list_head`) 管理进程关系

### 2.2 PID 分配方案

| 方案 | 优点 | 缺点 | 选择 |
|:-----|:-----|:-----|:-----|
| 简单计数器 | 实现简单 | PID 耗尽后需重启 | ❌ |
| 位图 (bitmap) | O(1) 分配/释放，易于实现 | 限制最大进程数 | ✅ |
| 哈希表 | 灵活，无硬限制 | 复杂度高，内存开销大 | ❌ |
| 空闲栈 | 分配快速 | 需维护栈结构 | ❌ |

**最终选择**：基于位图的 PID 分配器

```c
#define PID_MAX 32768

static byte_t s_pid_bitmap_buffer[PID_BITMAP_SIZE];
static struct bitmap s_pid_bitmap;

// PID 0 保留，从 1 开始分配
```

**理由**：
- 32768 个进程对单机 OS 足够
- bitmap_find_first_zero() 是 O(1) 操作
- 实现简单，易于调试

### 2.3 上下文切换实现

#### 为什么需要汇编？

上下文切换必须精确控制 CPU 状态：

1. **寄存器保存与恢复**：C 语言无法精确控制所有寄存器
2. **栈指针操作**：需要手动管理 RSP
3. **特殊指令**：需要操作 CR3 (地址空间) 和 TSS

#### callee-saved 寄存器

根据 x86_64 System V ABI，只需保存 callee-saved 寄存器：

```
RBX, RBP, R12, R13, R14, R15
```

caller-saved 寄存器（RAX, RCX, RDX, RSI, RDI, R8-R11）由调用者保护。

#### TSS RSP0 的作用

```
用户态 → 内核态 (中断/系统调用)
    ↓
CPU 自动切换到 TSS.RSP0 指向的栈
```

每次切换进程时必须更新 `TSS.RSP0 = next->kernel_stack`。

### 2.4 调度器设计

采用简单的 Round-Robin 算法：

```c
typedef struct scheduler {
    list_head     run_queue;    // FIFO 运行队列
    pcb_t*        current;      // 当前进程
    pcb_t*        idle;         // 空闲进程
    uint32_t      nr_running;   // 运行进程数
} scheduler_t;
```

**调度流程**：
1. 从 `run_queue` 取出第一个进程
2. 切换到该进程
3. 当前进程放回队列末尾（如果不是阻塞状态）

**未实现**：
- 时间片（需要定时器中断）
- 优先级
- 多级反馈队列

## 4. 实现细节

### 4.1 PCB 分配与释放

```c
static pcb_t* proc_alloc_pcb(void) {
    // 1. 分配 PCB 结构
    pcb_t* pcb = kmalloc(sizeof(pcb_t));

    // 2. 分配 CPU 上下文
    pcb->cpu_ctx = kmalloc(sizeof(cpu_context_t));

    // 3. 分配内核栈 (16KB)
    pcb->kernel_stack_base = kmalloc(KERNEL_STACK_SIZE);
    pcb->kernel_stack = pcb->kernel_stack_base + KERNEL_STACK_SIZE;

    // 4. 初始化链表头
    INIT_LIST_HEAD(&pcb->run_list);
    INIT_LIST_HEAD(&pcb->children);
    INIT_LIST_HEAD(&pcb->zombie_children);

    return pcb;
}
```

**关键点**：
- 内核栈 16 字节对齐（x86_64 ABI 要求）
- 栈 grows down，所以 `kernel_stack` 是栈顶
- CPU 上下文分离存储，便于上下文切换

### 4.2 PID 分配器实现

```c
void pid_alloc_init(void) {
    bitmap_init(&s_pid_bitmap, s_pid_bitmap_buffer, PID_MAX);
    bitmap_set(&s_pid_bitmap, 0);  // 保留 PID 0
}

int32_t pid_alloc(void) {
    int pid = bitmap_find_first_zero(&s_pid_bitmap);
    if (pid < 0 || pid >= PID_MAX) {
        return -1;
    }
    bitmap_set(&s_pid_bitmap, pid);
    return pid;
}

void pid_free(int32_t pid) {
    if (pid > 0 && pid < PID_MAX) {
        bitmap_clear(&s_pid_bitmap, pid);
    }
}
```

**特点**：
- PID 0 保留（类似 Unix init 进程概念）
- 线性搜索，可优化为使用起始 hint
- 未实现 PID 回绕（达到 PID_MAX 后失败）

### 4.3 上下文切换流程

#### switch_context(prev, next)

```asm
switch_context:
    ; 1. 保存 callee-saved 寄存器
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15

    ; 2. 保存 RSP 到 prev->cpu_ctx
    mov rax, [rdi]           ; rax = *prev
    mov [rax + pcb.cpu_ctx + cpu_ctx.rsp], rsp

    ; 3. 保存 RIP (返回地址)
    mov r15, [rsp + 48]      ; 跳过 6 个 pushed 寄存器
    mov [rax + pcb.cpu_ctx + cpu_ctx.rip], r15

    ; 4. 更新 TSS.RSP0
    mov rdi, [rsi + pcb.kernel_stack]
    call tss_set_kernel_stack_ctx

    ; 5. 切换 CR3
    mov rdi, [rsi + pcb.mm_pml4]
    call vmm_load_pml4

    ; 6. 恢复 next 的寄存器
    mov rax, [rsi + pcb.cpu_ctx]
    mov rbx, [rax + cpu_ctx.rbx]
    mov rbp, [rax + cpu_ctx.rbp]
    ...  ; 恢复 r12-r15

    ; 7. 恢复 RSP
    mov rsp, [rax + cpu_ctx.rsp]

    ; 8. 恢复寄存器并返回
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbp
    pop rbx
    ret
```

#### switch_to_first(first)

```asm
switch_to_first:
    ; 从内核初始化切换到首个进程
    ; 没有 prev 需要保存

    ; 1. 更新 TSS.RSP0
    mov rsi, rdi                ; 保存 first 指针
    mov rdi, [rsi + pcb.kernel_stack]
    push rsi
    call tss_set_kernel_stack_ctx
    pop rsi

    ; 2. 切换 CR3
    mov rdi, [rsi + pcb.mm_pml4]
    push rsi
    call vmm_load_pml4
    pop rsi

    ; 3. 恢复寄存器
    mov rax, [rsi + pcb.cpu_ctx]
    ...  ; 恢复 rbx, rbp, r12-r15, rsp

    ; 4. 跳转到进程入口点
    mov rax, [rax + cpu_ctx.rip]
    jmp rax
```

### 4.4 fork 系统调用实现

```c
int32_t proc_fork(void) {
    pcb_t* parent = proc_current();

    // 1. 分配子进程 PCB
    pcb_t* child = proc_alloc_pcb();

    // 2. 分配 PID
    child->pid = pid_alloc();

    // 3. 设置父进程关系
    child->ppid = parent->pid;
    child->parent = parent;

    // 4. 复制命令名
    memcpy(child->comm, parent->comm, 16);

    // 5. 复制地址空间
    proc_copy_address_space(parent, child);

    // 6. 添加到父进程的子进程列表
    list_add_tail(&child->siblings, &parent->children);

    // 7. 添加到运行队列
    list_add_tail(&child->run_list, &scheduler.run_queue);
    scheduler.nr_running++;

    // 8. 返回：父进程返回子进程 PID，子进程返回 0
    if (proc_current() == child) {
        return 0;
    }
    return child->pid;
}
```

**未实现**：
- 完整的 COW fork（当前只创建空地址空间）
- 用户栈设置
- 文件描述符继承

### 4.5 进程退出与等待

```c
void proc_exit(int exit_code) {
    pcb_t* current = proc_current();

    // 1. 设置僵尸状态
    current->state = PROC_ZOMBIE;
    current->exit_code = exit_code;

    // 2. 从运行队列移除
    list_del(&current->run_list);

    // 3. 移动到父进程的僵尸列表
    if (current->parent) {
        list_add_tail(&current->zombie_children,
                      &current->parent->zombie_children);
    }

    // 4. 减少运行进程数
    scheduler.nr_running--;

    // 5. 调度下一个进程
    schedule();

    // 永不返回
    __builtin_unreachable();
}

int32_t proc_wait4(int32_t pid, int* wstatus, int options) {
    pcb_t* current = proc_current();

    // 1. 查找僵尸子进程
    pcb_t* child, *target = NULL;
    list_for_each_entry(child, &current->zombie_children, zombie_children) {
        if (pid == -1 || child->pid == pid) {
            target = child;
            break;
        }
    }

    if (target) {
        // 2. 返回退出状态
        if (wstatus) {
            *wstatus = target->exit_code;
        }
        int32_t result = target->pid;

        // 3. 释放 PCB
        list_del(&target->zombie_children);
        proc_free_pcb(target);

        return result;
    }

    // 4. 没有僵尸子进程，阻塞当前进程
    // TODO: 实现阻塞与唤醒
    current->state = PROC_BLOCKED;
    schedule();

    return -1;
}
```

## 5. 常见陷阱与注意事项

### 5.1 上下文切换相关

#### 陷阱 1：栈指针未正确保存

**问题**：如果 RSP 保存错误，进程恢复时会在错误的栈地址执行。

**解决**：
```c
// 保存时，RSP 指向最后 pushed 的寄存器
// 当前布局: [R15][R14][R13][R12][RBP][RBX][RSP]
//          ^-- RSP 指向这里
mov [rax + pcb.cpu_ctx + cpu_ctx.rsp], rsp
```

#### 陷阱 2：TSS RSP0 更新时机错误

**问题**：如果 TSS.RSP0 未在切换前更新，中断发生时可能使用错误的内核栈。

**解决**：
```asm
; 在切换 CR3 之前更新 TSS.RSP0
mov rdi, [rsi + pcb.kernel_stack]
call tss_set_kernel_stack_ctx
```

#### 陷阱 3：CR3 切换与 TLB

**问题**：切换 CR3 会刷新 TLB，可能影响性能。

**决策**：当前实现总是切换 CR3，简化了逻辑。

### 5.2 进程管理相关

#### 陷阱 1：PID 0 保留

**问题**：如果 PID 0 被分配，可能与系统约定冲突。

**解决**：
```c
void pid_alloc_init(void) {
    bitmap_init(&s_pid_bitmap, s_pid_bitmap_buffer, PID_MAX);
    bitmap_set(&s_pid_bitmap, 0);  // 显式保留 PID 0
}
```

#### 陷阱 2：僵尸进程泄漏

**问题**：父进程未调用 wait4()，僵尸进程不会被回收。

**解决**：
- 父进程必须调用 wait4() 回收子进程
- 未实现：init 进程回收孤儿进程

#### 陷阱 3：进程状态不一致

**问题**：进程在 run_queue 中但状态不是 READY。

**解决**：确保状态转换与队列操作原子化（当前单核无需锁）。

### 5.3 内存地址空间冲突修复

#### 问题背景

在 Stage 19 开发过程中，发现了一个严重的地址空间冲突问题：

**症状**：
```
[ERROR] [PAGE] Page already mapped at 0xFFFFFFFF81015000
[ERROR] [HEAP] Failed to allocate pages at 0xFFFFFFFF81015000 for expansion
[ERROR] [HEAP] Out of memory
```

**原因分析**：

1. **VMM Demo** 使用 `vmm_alloc_pages()` 分配内存，搜索范围从 `KERNEL_HEAP_BASE` 开始
2. **堆分配器** 使用 `vmm_alloc_pages_at()` 在固定地址 (`heap_brk`) 分配
3. 两者使用同一地址范围，导致冲突

**解决方案**：

将虚拟地址空间分离为两个独立区域：

```c
/* 原有设计 - 两者共享同一范围 */
#define KERNEL_HEAP_BASE    0xFFFFFFFF81000000ULL
/* vmm_alloc_pages() 也从这里开始搜索 ❌ */

/* 修复后 - 分离为两个区域 */
#define KERNEL_HEAP_BASE    0xFFFFFFFF81000000ULL  // 堆专用
#define KERNEL_HEAP_SIZE    (128 * 1024 * 1024)
#define KERNEL_HEAP_MAX     (KERNEL_HEAP_BASE + KERNEL_HEAP_SIZE)

#define KERNEL_GENERAL_BASE 0xFFFFFFFF88000000ULL  // 通用分配
#define KERNEL_GENERAL_SIZE  (128 * 1024 * 1024)
#define KERNEL_GENERAL_MAX  (KERNEL_GENERAL_BASE + KERNEL_GENERAL_SIZE)
```

**代码修改**：

1. 更新 VMM 初始 hint：
```c
static virtual_addr_t s_kernel_virt_hint = KERNEL_GENERAL_BASE;  // 改为 GENERAL_BASE
```

2. 注册堆区域为保留：
```c
void vmm_init(void) {
    // ...
    add_region(KERNEL_HEAP_BASE, KERNEL_HEAP_MAX, 0, VMAP_FLAG_NONE, "kernel_heap");
}
```

**效果**：
- 堆分配器独占 `0xFFFFFFFF81000000 - 0xFFFFFFFF81080000` (128MB)
- 通用分配使用 `0xFFFFFFFF88000000 - 0xFFFFFFFF88080000` (128MB)
- 两者不再冲突

## 7. 性能考虑

### 7.1 调度器性能

**当前复杂度**：
- `schedule()`: O(1) - 直接取队列首元素
- `proc_find()`: O(n) - 遍历运行队列

**改进方向**：
- 使用哈希表实现 O(1) 的 `proc_find()`
- 实现时间片以支持公平调度

### 7.2 上下文切换开销

**保存/恢复的寄存器数量**：
- 6 个 callee-saved 寄存器
- RSP 和 RIP
- 总共约 8 次内存访问

**优化方向**：
- 使用 `fs/gs` 段寄存器存储 per-CPU 数据
- 避免不必要的 CR3 切换（同一地址空间内）

4. 页错误时自动处理 COW 写入

## 9. 调试经验

### 9.1 打印进程树

```c
void print_process_tree(pcb_t* root, int depth) {
    for (int i = 0; i < depth; i++) klog_info("  ");
    klog_info("PID:%d State:%d\n", root->pid, root->state);

    pcb_t* child;
    list_for_each_entry(child, &root->children, siblings) {
        print_process_tree(child, depth + 1);
    }
}
```

### 9.2 检查运行队列

```c
void check_run_queue(void) {
    klog_info("Running processes: %u\n", scheduler.nr_running);

    pcb_t* proc;
    list_for_each_entry(proc, &scheduler.run_queue, run_list) {
        klog_info("  PID:%d State:%d\n", proc->pid, proc->state);
    }
}
```

### 9.3 验证 PID 位图

```c
extern struct bitmap s_pid_bitmap;

void dump_pid_bitmap(void) {
    int allocated = 0;
    for (int i = 0; i < PID_MAX; i++) {
        if (bitmap_test(&s_pid_bitmap, i)) {
            allocated++;
        }
    }
    klog_info("Allocated PIDs: %d / %d\n", allocated, PID_MAX);
}
```

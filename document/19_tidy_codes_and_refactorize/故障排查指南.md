## 1. 进程创建问题

### 1.1 fork 返回负数错误码

**症状**：
```c
int32_t pid = proc_fork();
// pid < 0，fork 失败
```

**可能原因**：

| 原因 | 检查方法 |
|:-----|:---------|
| PID 耗尽 | 检查是否达到 PID_MAX (32768) |
| PCB 分配失败 | 检查内核堆内存是否充足 |
| 地址空间创建失败 | 检查 VMM 状态 |

**解决方案**：

1. **检查 PID 位图**：
```c
extern struct bitmap s_pid_bitmap;

int allocated = 0;
for (int i = 0; i < PID_MAX; i++) {
    if (bitmap_test(&s_pid_bitmap, i)) allocated++;
}
klog_info("Allocated PIDs: %d / %d\n", allocated, PID_MAX);
```

2. **检查内核堆**：
```c
// 尝试分配测试 PCB
pcb_t* test = kmalloc(sizeof(pcb_t));
if (!test) {
    klog_error("Kernel heap exhausted!\n");
} else {
    kfree(test);
}
```

3. **检查 VMM 状态**：
```c
virtual_addr_t vaddr;
physical_addr_t paddr;
if (pframe_alloc(&paddr) == PFRAME_OK) {
    vaddr = vmm_map_physical(paddr, VMM_FLAG_WRITE);
    if (vaddr == 0) {
        klog_error("VMM mapping failed!\n");
    }
}
```

### 1.2 子进程未正确初始化

**症状**：fork 返回成功，但子进程行为异常

**可能原因**：
- CPU 上下文未正确初始化
- 内核栈未设置

**检查方法**：
```c
pcb_t* child = proc_alloc_pcb();
klog_info("Child PCB:\n");
klog_info("  cpu_ctx: %p\n", child->cpu_ctx);
klog_info("  kernel_stack: 0x%016llX\n", child->kernel_stack);
klog_info("  kernel_stack_base: 0x%016llX\n", child->kernel_stack_base);

// 检查栈对齐
if ((child->kernel_stack & 0xF) != 0) {
    klog_error("Stack misaligned!\n");
}
```

**解决方案**：确保 `proc_alloc_pcb()` 正确初始化所有字段。

## 2. 上下文切换问题

### 2.1 上下文切换后系统崩溃

**症状**：`switch_context()` 执行后系统挂起或三重故障

**可能原因**：

| 原因 | 说明 |
|:-----|:-----|
| 栈指针未正确保存 | RIP 可能恢复到错误的地址 |
| TSS RSP0 未更新 | 中断时使用错误的栈 |
| CR3 切换问题 | TLB 无效导致访问错误 |
| PCB 结构偏移错误 | 汇编与 C 结构体不匹配 |

**诊断步骤**：

1. **检查 PCB 布局**：
```c
// 验证汇编中的偏移与 C 结构体匹配
STATIC_ASSERT(offsetof(pcb_t, pid) == 0, "PID offset mismatch");
STATIC_ASSERT(offsetof(pcb_t, cpu_ctx) == 104, "cpu_ctx offset mismatch");
STATIC_ASSERT(offsetof(pcb_t, kernel_stack) == 120, "kernel_stack offset mismatch");
```

2. **在 switch_context 前后打印状态**：
```c
void schedule(void) {
    pcb_t* prev = scheduler.current;
    pcb_t* next = list_first_entry(&scheduler.run_queue, pcb_t, run_list);

    if (prev) {
        klog_info("Switching: PID %d -> PID %d\n", prev->pid, next->pid);
        klog_info("  prev->cpu_ctx: %p\n", prev->cpu_ctx);
        klog_info("  prev->kernel_stack: 0x%016llX\n", prev->kernel_stack);
    }

    klog_info("  next->cpu_ctx: %p\n", next->cpu_ctx);
    klog_info("  next->kernel_stack: 0x%016llX\n", next->kernel_stack);
    klog_info("  next->cpu_ctx->rip: 0x%016llX\n", next->cpu_ctx->rip);

    switch_context(&prev, next);
}
```

3. **验证 TSS 状态**：
```c
tss_dump();  // 打印 TSS 内容，检查 RSP0
```

**解决方案**：

- 确保 PCB 结构体与汇编中的偏移量一致
- 确保在切换前正确初始化 `next->cpu_ctx`
- 确保 `switch_context` 中 TSS.RSP0 在 CR3 切换前更新

---

### 2.2 进程无法恢复执行

**症状**：切换到进程后，进程不继续执行

**可能原因**：
- RIP 未正确保存
- 栈指针损坏

**检查方法**：
```c
// 在切换前检查 CPU 上下文
klog_info("cpu_ctx->rip: 0x%016llX\n", pcb->cpu_ctx->rip);
klog_info("cpu_ctx->rsp: 0x%016llX\n", pcb->cpu_ctx->rsp);

// 验证 RIP 在合理范围内
if (pcb->cpu_ctx->rip < KERNEL_BASE ||
    pcb->cpu_ctx->rip > KERNEL_BASE + 0x10000000) {
    klog_error("Invalid RIP!\n");
}
```

## 3. 调度器问题

### 3.1 运行队列为空但进程存在

**症状**：`scheduler.nr_running > 0` 但 `list_is_empty(&scheduler.run_queue)` 为真

**原因**：队列操作与计数器不一致

**检查方法**：
```c
klog_info("nr_running: %u\n", scheduler.nr_running);
klog_info("run_queue empty: %d\n", list_is_empty(&scheduler.run_queue));

// 手动统计运行队列
int count = 0;
pcb_t* proc;
list_for_each_entry(proc, &scheduler.run_queue, run_list) {
    count++;
}
klog_info("Actual run_queue count: %d\n", count);
```

**解决方案**：
- 确保所有添加/删除队列操作同时更新 `nr_running`
- 检查 `list_del` 和 `list_add` 的配对

---

### 3.2 进程卡在 BLOCKED 状态

**症状**：进程状态为 `PROC_BLOCKED` 且永不恢复

**原因**：唤醒逻辑未实现或错误

**当前状态**：Stage 19 中 `proc_wait4()` 的阻塞实现不完整

**解决方案**：
- 实现完整的阻塞与唤醒机制
- 确保子进程退出时唤醒父进程

## 4. 内存管理问题

### 4.1 内核栈溢出

**症状**：不可预测的行为、奇怪的崩溃、寄存器损坏

**原因**：
- 递归调用过深
- 大的栈上变量

**检查方法**：
```c
// 在栈底放置魔法值
#define KERNEL_STACK_CANARY 0xDEADBEEF12345678ULL

void proc_alloc_pcb(void) {
    pcb->kernel_stack_base = kmalloc(KERNEL_STACK_SIZE);
    uint64_t* canary = (uint64_t*)pcb->kernel_stack_base;
    *canary = KERNEL_STACK_CANARY;
}

void check_stack_canary(pcb_t* pcb) {
    uint64_t* canary = (uint64_t*)pcb->kernel_stack_base;
    if (*canary != KERNEL_STACK_CANARY) {
        klog_error("Stack overflow detected for PID %d!\n", pcb->pid);
    }
}
```

**解决方案**：
1. 增大 `KERNEL_STACK_SIZE`
2. 减少栈上分配，改用堆
3. 避免深递归

---

### 4.2 地址空间切换失败

**症状**：切换 CR3 后立即崩溃

**原因**：
- PML4 物理地址无效
- 页表损坏

**检查方法**：
```c
void vmm_load_pml4(physical_addr_t pml4_phys) {
    // 验证 PML4 地址对齐
    if (pml4_phys & 0xFFF) {
        klog_error("PML4 misaligned: 0x%016llX\n", pml4_phys);
        return;
    }

    // 验证 PML4 在可用内存范围内
    // ...

    uint64_t cr3 = pml4_phys & ~0xFFFULL;
    klog_info("Switching to CR3: 0x%016llX\n", cr3);
    page_set_cr3(cr3);
}
```

**解决方案**：
- 确保地址空间创建时正确初始化 PML4
- 使用 `vmm_create_user_space()` 创建有效的地址空间

### 4.3 堆/VMM 地址冲突

**症状**：
```
[ERROR] [PAGE] Page already mapped at 0xFFFFFFFF81015000
[ERROR] [HEAP] Failed to allocate pages at 0xFFFFFFFF81015000
[ERROR] [HEAP] Out of memory
```

**原因**：堆分配器和通用 VMM 分配使用同一地址范围

**解决方案**：已在 Stage 19 中修复

1. **配置独立的内存区域**：
```c
/* 堆区域 - 堆分配器专用 */
#define KERNEL_HEAP_BASE    0xFFFFFFFF81000000ULL
#define KERNEL_HEAP_SIZE    (128 * 1024 * 1024)
#define KERNEL_HEAP_MAX     (KERNEL_HEAP_BASE + KERNEL_HEAP_SIZE)

/* 通用分配区域 */
#define KERNEL_GENERAL_BASE 0xFFFFFFFF88000000ULL
#define KERNEL_GENERAL_SIZE (128 * 1024 * 1024)
#define KERNEL_GENERAL_MAX  (KERNEL_GENERAL_BASE + KERNEL_GENERAL_SIZE)
```

2. **更新 VMM 搜索范围**：
```c
static virtual_addr_t s_kernel_virt_hint = KERNEL_GENERAL_BASE;
```

3. **注册堆区域为保留**：
```c
void vmm_init(void) {
    // ...
    add_region(KERNEL_HEAP_BASE, KERNEL_HEAP_MAX, 0,
               VMAP_FLAG_NONE, "kernel_heap");
}
```

**验证**：
```c
// 运行 VMM demo 后运行 heap demo
// 两者应该在不同地址范围分配
```

## 5. PID 分配器问题

### 5.1 PID 分配冲突

**症状**：两个进程获得相同的 PID

**原因**：bitmap 操作非原子（多核时）

**检查方法**：
```c
int32_t pid1 = pid_alloc();
int32_t pid2 = pid_alloc();
if (pid1 == pid2) {
    klog_error("PID collision detected!\n");
}
```

**解决方案**：
- 当前单核实现无此问题
- 多核时需要加锁保护 bitmap 操作

---

### 5.2 PID 泄漏

**症状**：可用 PID 逐渐减少

**原因**：进程退出后 PID 未释放

**检查方法**：
```c
void check_pid_leak(void) {
    extern struct bitmap s_pid_bitmap;
    int allocated = 0;
    for (int i = 0; i < PID_MAX; i++) {
        if (bitmap_test(&s_pid_bitmap, i)) {
            allocated++;
        }
    }
    klog_info("Allocated PIDs: %d (should equal process count)\n", allocated);
}
```

**解决方案**：
- 确保 `proc_free_pcb()` 中调用 `pid_free()`
- 确保僵尸进程被回收

## 6. 僵尸进程问题

### 6.1 僵尸进程未回收

**症状**：
```c
list_for_each_entry(child, &current->zombie_children, zombie_children) {
    klog_info("Zombie child PID: %d\n", child->pid);
}
// 列表不为空，但父进程未调用 wait4
```

**原因**：父进程未调用 `wait4()` 或父进程已退出

**检查方法**：
```c
void dump_zombie_children(pcb_t* parent) {
    int count = 0;
    pcb_t* child;
    list_for_each_entry(child, &parent->zombie_children, zombie_children) {
        klog_info("  Zombie PID %d, exit_code %d\n",
                  child->pid, child->exit_code);
        count++;
    }
    if (count > 0) {
        klog_warn("Parent PID %d has %d unreaped zombies\n",
                  parent->pid, count);
    }
}
```

**解决方案**：

1. **父进程必须调用 wait4**：
```c
int32_t child_pid = proc_fork();
if (child_pid > 0) {
    // 父进程
    int status;
    proc_wait4(-1, &status, 0);  // 回收子进程
}
```

2. **实现 init 进程**（未来工作）：
   - 当父进程退出时，将其子进程重新挂到 init
   - init 定期回收孤儿进程

## 7. VMM/TSS 集成问题

### 7.1 TSS RSP0 未更新

**症状**：从中断返回时使用错误的栈

**检查方法**：
```c
void check_tss_rsp0(void) {
    extern tss_t s_tss;
    klog_info("TSS.RSP0: 0x%016llX\n", s_tss.rsp0);

    if (scheduler.current) {
        if (s_tss.rsp0 != scheduler.current->kernel_stack) {
            klog_error("TSS.RSP0 mismatch!\n");
            klog_error("  Expected: 0x%016llX\n", scheduler.current->kernel_stack);
        }
    }
}
```

**解决方案**：确保 `switch_context()` 中调用 `tss_set_kernel_stack_ctx()`。

---

### 7.2 CR3 切换问题

**症状**：切换地址空间后页面错误

**检查方法**：
```c
physical_addr_t current_cr3 = vmm_get_current_pml4();
klog_info("Current CR3: 0x%016llX\n", current_cr3);

if (scheduler.current) {
    if (current_cr3 != scheduler.current->mm.pml4_phys) {
        klog_error("CR3 mismatch with current process!\n");
        klog_error("  Process CR3: 0x%016llX\n",
                   scheduler.current->mm.pml4_phys);
    }
}
```

**解决方案**：
- 确保进程的 PML4 有效
- 检查 `vmm_create_user_space()` 是否成功

## 8. 调试技巧

### 8.1 打印进程状态

```c
void print_process_info(pcb_t* pcb) {
    if (!pcb) {
        klog_info("Process: NULL\n");
        return;
    }

    const char* state_str;
    switch (pcb->state) {
        case PROC_READY:   state_str = "READY";   break;
        case PROC_RUNNING: state_str = "RUNNING"; break;
        case PROC_BLOCKED: state_str = "BLOCKED"; break;
        case PROC_ZOMBIE:  state_str = "ZOMBIE";  break;
        default:           state_str = "UNKNOWN"; break;
    }

    klog_info("Process PID %d:\n", pcb->pid);
    klog_info("  PPID: %d\n", pcb->ppid);
    klog_info("  State: %s\n", state_str);
    klog_info("  Parent: %p\n", pcb->parent);
    klog_info("  PML4: 0x%016llX\n", pcb->mm.pml4_phys);
    klog_info("  Kernel Stack: 0x%016llX\n", pcb->kernel_stack);
}
```

---

### 8.2 打印进程树

```c
void print_process_tree_recursive(pcb_t* root, int depth) {
    for (int i = 0; i < depth; i++) klog_info("  ");

    const char* state_str;
    switch (root->state) {
        case PROC_READY:   state_str = "R"; break;
        case PROC_RUNNING: state_str = "P"; break;
        case PROC_BLOCKED: state_str = "S"; break;
        case PROC_ZOMBIE:  state_str = "Z"; break;
        default:           state_str = "?"; break;
    }

    klog_info("[%d] %s (%s)\n", root->pid, root->comm, state_str);

    pcb_t* child;
    list_for_each_entry(child, &root->children, siblings) {
        print_process_tree_recursive(child, depth + 1);
    }
}

void print_process_tree(void) {
    klog_info("\n=== Process Tree ===\n");
    // 假设 init 进程 PID 为 1
    pcb_t* init = proc_find(1);
    if (init) {
        print_process_tree_recursive(init, 0);
    }
    klog_info("===================\n\n");
}
```

### 8.3 检查运行队列

```c
void dump_run_queue(void) {
    klog_info("\n=== Run Queue ===\n");
    klog_info("nr_running: %u\n", scheduler.nr_running);

    if (scheduler.current) {
        klog_info("Current: PID %d\n", scheduler.current->pid);
    } else {
        klog_info("Current: NULL\n");
    }

    if (list_is_empty(&scheduler.run_queue)) {
        klog_info("Run queue: EMPTY\n");
    } else {
        pcb_t* proc;
        int idx = 0;
        list_for_each_entry(proc, &scheduler.run_queue, run_list) {
            klog_info("  [%d] PID %d, State %d\n",
                      idx++, proc->pid, proc->state);
        }
    }
    klog_info("=================\n\n");
}
```

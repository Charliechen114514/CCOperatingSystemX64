## 1. 阶段背景

### 1.1 前一阶段遗留问题

在 Stage 13 (中断基础) 中，我们实现了：
- 完整的 IDT 和中断处理框架
- 8259 PIC 驱动
- 基础定时器中断

但当时缺乏：
- **键盘输入支持** - 无法获取用户输入
- **实时时钟** - 无法获取准确时间
- **丰富的定时功能** - 只有固定频率滴答
- **中断驱动的串口** - 串口效率较低
- **交互界面** - 缺少 Shell 系统

### 1.2 本阶段目标

```
核心目标：建立完整的人机交互能力

1. 输入设备支持
   - PS/2 键盘驱动
   - 扫描码处理
   - 修饰键支持

2. 时钟与定时
   - RTC 读取/设置
   - 周期性中断
   - 可配置频率 PIT

3. 高效串口
   - 中断驱动模式
   - FIFO 支持
   - 异步 I/O

4. Shell 系统
   - 通用 Shell 框架
   - VGA/Serial 后端
   - 命令注册机制
```

## 2. 设计决策

### 2.1 键盘驱动：轮询 vs 中断

#### 问题

键盘输入可以采用两种方式：

| 方式 | 优点 | 缺点 |
|------|------|------|
| 轮询 | 简单、无中断开销 | CPU 浪费、响应延迟 |
| 中断 | 高效、实时响应 | 复杂、需要缓冲区 |

#### 选择：中断驱动模式

**理由**:
1. **CPU 效率** - 键盘输入频率低，轮询浪费大量 CPU
2. **实时响应** - 中断可以立即捕获按键
3. **可扩展性** - 为未来多任务做准备

#### 缓冲区设计

采用环形缓冲区（Ring Buffer）：

```c
#define KEYBOARD_BUFFER_SIZE 256

typedef struct {
    char buffer[256];
    volatile uint32_t head;
    volatile uint32_t tail;
} ring_buffer_t;
```

**256 字节大小的考虑**:
- 足够大：一般打字速度下不会溢出
- 足够小：静态分配，不浪费内存
- 2 的幂：取模运算优化（虽然我们用 `%`）

### 2.2 扫描码处理方案

#### 问题

PS/2 键盘发送的是扫描码，需要转换为 ASCII。

**扫描码集 1 的复杂性**:
- Make Code (按下) / Break Code (释放)
- 修饰键状态
- Caps Lock 影响

#### 解决方案：状态机

```c
// 状态变量
static volatile bool kb_shift_pressed = false;
static volatile bool kb_caps_lock = false;

// 转换逻辑
bool use_shift = kb_shift_pressed;
if (kb_caps_lock && is_letter_scancode(scancode)) {
    use_shift = !use_shift;  // Caps Lock 反转字母大小写
}
```

**关键设计**:
1. Break Code 检测：`scancode & 0x80`
2. 修饰键单独处理
3. Caps Lock 只影响字母

### 2.3 RTC：寄存器访问策略

#### 问题

CMOS RTC 访问需要特殊处理：
- 需要等待更新完成
- BCD 格式转换
- NMI 禁用

#### 解决方案

**1. 更新等待**:

```c
bool rtc_is_updating(void) {
    return (cmos_read(RTC_REG_A) & RTC_REG_A_UIP) != 0;
}

// 读取前等待
while (rtc_is_updating()) {
    __asm__ volatile("pause");
}
```

**2. BCD 自动转换**:

```c
static uint8_t rtc_read_register(uint8_t reg) {
    uint8_t value = cmos_read(reg);
    if (!rtc_binary_mode) {
        value = bcd_to_binary(value);  // 自动处理 BCD
    }
    return value;
}
```

**3. NMI 处理**:

```c
static inline uint8_t cmos_read(uint8_t reg) {
    outb(CMOS_ADDRESS_PORT, reg | CMOS_NMI_DISABLE);  // 禁用 NMI
    return inb(CMOS_DATA_PORT);
}
```

### 2.4 Shell：后端抽象设计

#### 问题

需要同时支持 VGA 和 Serial 两种 I/O 方式。

#### 方案：后端接口

```c
typedef struct shell_backend {
    const char* name;
    void (*puts)(const char* str);
    void (*putc)(char c);
    bool (*haschar)(void);
    char (*getchar)(void);
    void (*clear)(void);
} shell_backend_t;
```

**优点**:
- 核心逻辑与 I/O 解耦
- 易于添加新后端
- 代码复用

**实现**:
```c
// VGA 后端
shell_backend_t g_vga_backend = {
    .name = "VGA",
    .puts = vga_shell_puts,
    .getc = vga_shell_getc,
    // ...
};

// Serial 后端
shell_backend_t g_serial_backend = {
    .name = "Serial",
    .puts = serial_shell_puts,
    .getc = serial_shell_getc,
    // ...
};
```

#### 问题

硬件光标在模拟环境中不可靠或难以控制。

#### 方案：软件光标

```c
typedef struct vga_soft_cursor {
```

## 3. 架构设计

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    Shell 系统                           │
│  - shell_run()                                           │
│  - 命令解析与执行                                         │
└──────────────┬──────────────────────────────────────────┘
               │
     ┌─────────┴─────────┐
     │                   │
┌────▼────┐         ┌────▼────┐
│VGA 后端 │         │Serial   │
│         │         │后端     │
└────┬────┘         └────┬────┘
     │                   │
┌────▼────┐         ┌────▼────┐
│VGA 驱动 │         │UART 驱动│
│+软光标  │         │(中断)   │
└─────────┘         └────┬────┘
                         │
              ┌──────────┼──────────┐
              │          │          │
        ┌─────▼───┐ ┌───▼───┐ ┌───▼────┐
        │Keyboard │ │ RTC   │ │ Timer  │
        │(IRQ 1)  │ │(IRQ8) │ │(IRQ 0) │
        └─────────┘ └───────┘ └────────┘
              │          │          │
              └──────────┼──────────┘
                         │
                  ┌──────▼──────┐
                  │   中断系统   │
                  │   (Stage 13) │
                  └─────────────┘
```

### 3.2 中断流程

```
硬件事件 → IRQ → CPU → ISR Stub → interrupt_handler
                                            │
                                    ┌───────┴────────┐
                                    │                │
                            ┌───────▼─────┐  ┌─────▼─────┐
                            │ 设备处理程序  │  │默认处理器  │
                            │ (回调/缓冲)  │  │ (错误显示) │
                            └─────────────┘  └───────────┘
```

### 3.3 数据流

**键盘输入流**:
```
物理按键 → PS/2 端口 → IRQ 1
    → keyboard_irq_handler()
    → 扫描码转 ASCII
    → 写入环形缓冲区
    → keyboard_getchar() 读取
```

**串口输出流**:
```
async_serial_puts()
    → 写入 TX 缓冲区
    → 启用 TX 中断
    → IRQ 4 触发
    → uart_irq_handler()
    → 从缓冲区读取并发送
```

## 4. 实现细节

### 4.1 键盘扫描码处理

#### 扫描码格式

**Set 1 Make Code**: 单字节，如 `0x01` = Esc
**Set 1 Break Code**: Make Code | 0x80，如 `0x81` = Esc 释放

```c
uint8_t code = scancode & 0x7F;  // 移除 break 位
bool is_break = (scancode & 0x80) != 0;

switch (code) {
    case SCANCODE_LSHIFT:
    case SCANCODE_RSHIFT:
        kb_shift_pressed = !is_break;  // 按下置位，释放清除
        break;
    // ...
}
```

#### 大小写处理

```c
static inline bool is_letter_scancode(uint8_t scancode) {
    // QWERTY 行: 0x10-0x1C (Q-P)
    // ASDF 行: 0x1E-0x26 (A-L)
    return (scancode >= 0x10 && scancode <= 0x1C) ||
           (scancode >= 0x1E && scancode <= 0x26);
}

// 应用 Shift 和 Caps Lock
bool use_shift = kb_shift_pressed;
if (kb_caps_lock && is_letter_scancode(scancode)) {
    use_shift = !use_shift;
}
```

### 4.2 RTC 周期性中断

#### 频率设置

RTC 周期性中断频率由寄存器 A 的 RS 位决定：

```c
// 寄存器 A 的 RS 位值与频率关系
#define RTC_RATE_2Hz      0x0F   // 2 Hz
#define RTC_RATE_4Hz      0x0E   // 4 Hz
#define RTC_RATE_8Hz      0x0D   // 8 Hz
#define RTC_RATE_16Hz     0x0C   // 16 Hz
// ...
#define RTC_RATE_8192Hz   0x03   // 8192 Hz
```

#### 使能流程

```c
int rtc_enable_periodic(uint8_t rate_div, callback_fn cb, void* ctx) {
    // 1. 禁用 IRQ 8
    pic_disable_irq(8);

    // 2. 设置频率
    uint8_t reg_a = cmos_read(RTC_REG_A);
    reg_a = (reg_a & ~RTC_REG_A_RS_MASK) | rate_div;
    cmos_write(RTC_REG_A, reg_a);

    // 3. 启用周期中断
    uint8_t reg_b = cmos_read(RTC_REG_B);
    reg_b |= RTC_REG_B_PIE;
    cmos_write(RTC_REG_B, reg_b);

    // 4. 清除待处理中断
    cmos_read(RTC_REG_C);

    // 5. 启用 IRQ 8
    pic_enable_irq(8);

    return 0;
}
```

### 4.3 UART 中断驱动

#### FIFO 配置

16550 UART 支持 14 字节 FIFO：

```c
// 0xC7 = 使能 FIFO + 清空两个 FIFO + 14 字节阈值
outb(SERIAL_FIFO_CTRL_REG(base), 0xC7);
```

#### IER 配置

```c
#define SERIAL_IER_RX_READY  0x01  // 接收数据可用
#define SERIAL_IER_TX_EMPTY  0x02  // 发送保持寄存器空
#define SERIAL_IER_RX_STATUS 0x04  // 接收线状态

// 初始化：启用 RX 和线状态中断
outb(SERIAL_INT_ENABLE_REG(base),
     SERIAL_IER_RX_READY | SERIAL_IER_RX_STATUS);
```

#### TX 中断优化

TX 中断不需要一直启用：

```c
// 有数据时启用
if (!ring_tx_is_empty(&tx_buffer)) {
    outb(SERIAL_INT_ENABLE_REG(base),
         inb(SERIAL_INT_ENABLE_REG(base)) | SERIAL_IER_TX_EMPTY);
}

// 缓冲区空时禁用
if (ring_tx_is_empty(&tx_buffer)) {
    outb(SERIAL_INT_ENABLE_REG(base),
         inb(SERIAL_INT_ENABLE_REG(base)) & ~SERIAL_IER_TX_EMPTY);
}
```

### 4.4 Shell 命令解析

#### 命令格式

```
command arg1 arg2 ...
```

#### 解析实现

```c
static int parse_command(char* cmd_line, char* argv[]) {
    int argc = 0;
    char* p = cmd_line;

    // 跳过前导空白
    while (*p == ' ' || *p == '\t') p++;

    while (*p != '\0' && argc < SHELL_MAX_ARGS) {
        argv[argc++] = p;

        // 找到 token 结尾
        while (*p != '\0' && *p != ' ' && *p != '\t') p++;

        if (*p == '\0') break;

        // Null 终止 token
        *p++ = '\0';

        // 跳过空白
        while (*p == ' ' || *p == '\t') p++;
    }

    return argc;
}
```

## 5. 常见陷阱

### 5.1 键盘扫描码混淆

#### 问题

扫描码集 1、2、3 格式不同，容易混淆。

**集 1**: PC/AT 标准，单字节
**集 2**: PS/2 多数默认，双字节
**集 3**: 少数键盘

#### 解决

强制使用集 1，或在初始化时切换：

```c
// 发送 0xF0 获取当前扫描码集
// 发送 0x01 切换到集 1
```

### 5.2 RTC BCD 转换错误

#### 问题

忘记检查二进制模式标志。

```c
// 错误：总是进行 BCD 转换
uint8_t value = bcd_to_binary(cmos_read(reg));
```

#### 解决

```c
// 正确：检查 DM 位
uint8_t reg_b = cmos_read(RTC_REG_B);
bool binary_mode = (reg_b & RTC_REG_B_DM) != 0;

uint8_t value = cmos_read(reg);
if (!binary_mode) {
    value = bcd_to_binary(value);
}
```

### 5.3 UART 中断风暴

#### 问题

TX 空中断会持续触发，直到禁用。

```c
// 忘记禁用 TX 中断
case SERIAL_IIR_TX_EMPTY:
    // 发送数据...
    // 忘记禁用中断！
    break;
```

#### 解决

```c
case SERIAL_IIR_TX_EMPTY:
    if (!ring_tx_is_empty(&tx_buffer)) {
        // 发送数据
    } else {
        // 缓冲区空，禁用 TX 中断
        uint8_t ier = inb(SERIAL_INT_ENABLE_REG(base));
        outb(SERIAL_INT_ENABLE_REG(base), ier & ~SERIAL_IER_TX_EMPTY);
    }
    break;
```

### 5.4 Shell 缓冲区溢出

#### 问题

命令行缓冲区大小固定，超长输入会导致溢出。

```c
char cmd_buffer[128];
// 没有边界检查
cmd_buffer[cmd_pos++] = c;  // 危险！
```

#### 解决

```c
if (cmd_pos < SHELL_CMD_BUFFER_SIZE - 1) {
    cmd_buffer[cmd_pos++] = c;
}
// 超长部分静默丢弃
```

## 6. 经验总结

### 6.1 最大的收获

#### 中断驱动是高效 I/O 的基础

```
中断驱动的优势：
- CPU 不需要轮询
- 设备就绪立即响应
- 可以处理多个设备
- 为多任务打下基础
```

#### 抽象接口带来灵活性

```
Shell 后端抽象的价值：
- 同一核心代码支持多种设备
- 添加新后端不需要修改核心
- 便于测试和调试
```

#### 缓冲区大小需要权衡

```
256 字节环形缓冲区：
- 足够日常使用
- 不会溢出（正常打字）
- 静态分配简单
- 更适合嵌入式场景
```

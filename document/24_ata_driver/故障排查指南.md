## 1. 设备检测问题

### 1.1 设备未检测到

#### 症状

```
[ATA] Primary Master: Not Present
[ATA] Primary Slave: Not Present
[ATA] Secondary Master: Not Present
[ATA] Secondary Slave: Not Present
```

#### 原因分析

1. QEMU 未添加磁盘镜像
2. I/O 端口配置错误
3. 设备选择失败

#### 诊断步骤

```c
// 检查 I/O 端口响应
void debug_io_ports(void) {
    // 尝试读取 Primary Master 状态
    uint8_t status1 = inb(0x1F7);

    // 尝试读取 Secondary Master 状态
    uint8_t status2 = inb(0x177);

    klog_info("Primary status: 0x%02X\n", status1);
    klog_info("Secondary status: 0x%02X\n", status2);
}
```

#### 解决方案

**QEMU 启动参数**:
```bash
qemu-system-x86_64 \
    -drive file=disk.img,format=raw,index=0,media=disk \
    -drive file=disk2.img,format=raw,index=1,media=disk \
    ...
```

### 1.2 IDENTIFY 命令超时

#### 症状

```
[ATA ERROR] IDENTIFY timeout on Primary Master
```

#### 原因分析

1. 未等待 400ns 延迟
2. BSY 位未清除
3. 设备不是 ATA（可能是 ATAPI）

#### 解决方案

```c
// 确保添加延迟
ata_select_device(ctrl, device);
ata_delay();  // 必须！

outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_IDENTIFY);

// 立即检查状态
uint8_t status = inb(ctrl->io_base + ATA_REG_STATUS);
if (status == 0) {
    return false;  // 无设备
}
if (status & ATA_STATUS_ERR) {
    return false;  // 可能是 ATAPI
}
```

### 1.3 字符串乱码

#### 症状

```
Model: "EMQ HARDDISS  "   // 应该是 "QEMU HARDDISK"
```

#### 原因

IDENTIFY 数据中的字符串以大端序字存储。

#### 解决方案

使用正确的字符串转换函数：

```c
void ata_identify_string_to_c(const uint16_t* src, char* dest, int words) {
    for (int i = 0; i < words; i++) {
        uint16_t word = src[i];
        dest[i * 2] = (char)(word >> 8);     // 高字节在前
        dest[i * 2 + 1] = (char)(word & 0xFF);  // 低字节在后
    }
    dest[words * 2] = '\0';

    // 去除尾部空格
    int len = words * 2;
    while (len > 0 && dest[len - 1] == ' ') {
        dest[--len] = '\0';
    }
}
```

## 2. 读写操作问题

### 2.1 读取超时

#### 症状

```
[ATA ERROR] Read timeout: BSY not clearing
```

#### 原因分析

1. LBA 地址超出范围
2. 设备未准备好
3. 命令发送错误

#### 诊断步骤

```c
// 添加详细调试
ata_result_t ata_read_pio(...) {
    // ... 设置寄存器 ...

    klog_debug("Sending READ command for LBA %u\n", lba);
    outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_READ_SECTORS);

    // 等待 BSY 清除
    klog_debug("Waiting for BSY to clear...\n");
    ata_result_t result = ata_wait_bsy(ctrl->io_base);

    if (result != ATA_OK) {
        klog_error("BSY timeout! Status: 0x%02X\n",
                   inb(ctrl->io_base + ATA_REG_STATUS));
        return result;
    }

    // ...
}
```

#### 解决方案

1. **检查 LBA 范围**:
```c
uint64_t max_lba = ata_get_sector_count(device);
if (lba >= max_lba) {
    klog_error("LBA %llu exceeds max %llu\n", lba, max_lba);
    return ATA_ERR_INVALID_PARAM;
}
```

2. **增加超时时间**:
```c
#define ATA_TIMEOUT_LOOPS 1000000  // 增加超时
```

### 2.2 数据不完整

#### 症状

读取的数据与写入不一致，或后半部分为 0。

#### 原因

扇区数设置错误，特别是 256 扇区的边界情况。

#### 解决方案

```c
// 256 扇区编码为 0
uint8_t sec_count = (sectors == 256) ? 0 : sectors;

// 确保循环正确
for (uint16_t sec = 0; sec < sectors; sec++) {
    // ... 读取 256 字 ...
}
```

### 2.3 写入后数据丢失

#### 症状

写入成功，但读取返回旧数据。

#### 原因

未刷新磁盘缓存。

#### 解决方案

```c
// 写入完成后刷新缓存
outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_FLUSH_CACHE);
ata_wait_bsy(ctrl->io_base);
```

## 3. 中断驱动问题

### 3.1 中断未触发

#### 症状

异步操作永远不会完成。

#### 原因分析

1. IRQ 未启用
2. IRQ 处理程序未注册
3. nIEN 位被设置

#### 诊断步骤

```c
// 检查 IRQ 状态
void debug_irq_status(void) {
    // 检查 PIC 屏蔽
    uint8_t mask1 = inb(0x21);
    uint8_t mask2 = inb(0xA1);

    klog_info("PIC1 mask: 0x%02X\n", mask1);
    klog_info("PIC2 mask: 0x%02X\n", mask2);

    // IRQ 14/15 状态
    bool irq14_masked = mask1 & (1 << 6);  // Primary
    bool irq15_masked = mask2 & (1 << 7);  // Secondary

    klog_info("IRQ 14 (Primary ATA): %s\n",
              irq14_masked ? "MASKED" : "ENABLED");
    klog_info("IRQ 15 (Secondary ATA): %s\n",
              irq15_masked ? "MASKED" : "ENABLED");
}
```

#### 解决方案

```c
// 1. 启用 IRQ
pic_enable_irq(14);  // Primary
pic_enable_irq(15);  // Secondary

// 2. 注册处理程序
idt_register_handler(46, ata_primary_irq_handler);   // IRQ 14
idt_register_handler(47, ata_secondary_irq_handler); // IRQ 15

// 3. 清除 nIEN 位
ata_enable_interrupts(ctrl);
```

### 3.2 假中断 (Spurious Interrupt)

#### 症状

```
[ATA] Spurious interrupt on IRQ 14
```

#### 原因

ATA 控制器的硬件特性，可能产生假中断。

#### 解决方案

```c
void ata_irq_handler(interrupt_frame_t* frame, void* context) {
    ata_controller_t* ctrl = (ata_controller_t*)context;

    // 检查 ISR 寄存器
    uint8_t status = inb(ctrl->io_base + ATA_REG_STATUS);

    // 检查是否是真正的中断
    if (!(status & (ATA_STATUS_BSY | ATA_STATUS_DRQ))) {
        klog_debug("Spurious interrupt, ignoring\n");
        return;  // 不发送 EOI
    }

    // 正常处理...
    pic_send_eoi(ctrl->irq - 32);
}
```

## 4. QEMU 调试问题

### 4.1 磁盘镜像格式问题

#### 症状

QEMU 启动时找不到磁盘。

#### 解决方案

```bash
# 创建原始镜像
dd if=/dev/zero of=disk.img bs=1M count=128

# 创建 qcow2 镜像
qemu-img create -f qcow2 disk.qcow2 128M

# QEMU 启动参数
qemu-system-x86_64 \
    -drive file=disk.img,format=raw,index=0,media=disk \
    ...
```

### 4.2 磁盘大小不匹配

#### 症状

报告的扇区数与预期不符。

#### 原因

磁盘镜像创建时的参数。

#### 解决方案

```bash
# 检查镜像信息
qemu-img info disk.img

# 创建指定大小的镜像
# 128MB = 262144 扇区 (512 字节/扇区)
dd if=/dev/zero of=disk.img bs=512 count=262144
```

### 4.3 监控 ATA 操作

#### QEMU Monitor 命令

```qemu
# 查看驱动器信息
info block

# 查看块设备统计
info blockstats

# 追踪 ATA 命令
trace ata_cmd_read
trace ata_cmd_write
```

## 5. 性能问题

### 5.1 读取速度慢

#### 症状

读取速度远低于预期。

#### 原因分析

1. 每次只读 1 个扇区
2. PIO 模式固有限制
3. 轮询等待时间长

#### 优化方案

```c
// 批量读取
ata_result_t read_optimized(int device, uint64_t lba,
                            void* buffer, uint16_t sectors) {
    // 单次请求最多 256 扇区
    while (sectors > 0) {
        uint16_t chunk = (sectors > 256) ? 256 : sectors;

        ata_result_t result = ata_read(device, lba, buffer, chunk);
        if (result != ATA_OK) return result;

        buffer += chunk * ATA_SECTOR_SIZE;
        lba += chunk;
        sectors -= chunk;
    }

    return ATA_OK;
}
```

### 5.2 CPU 占用过高

#### 症状

磁盘 I/O 时 CPU 无法执行其他任务。

#### 原因

同步 PIO 模式占用 CPU 轮询。

#### 解决方案

使用异步 I/O：

```c
// 异步读取，CPU 可以做其他工作
ata_read_async(device, lba, buffer, sectors, callback, NULL);

// 在其他地方处理
while (!async_complete) {
    // 做其他工作
    do_other_tasks();
}
```

## 6. 调试技巧

### 6.1 端口监控

```c
// 打印所有寄存器状态
void dump_ata_registers(uint16_t io_base) {
    klog_info("=== ATA Registers @ 0x%04X ===\n", io_base);
    klog_info("Data:    0x%04X\n", inw(io_base + ATA_REG_DATA));
    klog_info("Error:   0x%02X\n", inb(io_base + ATA_REG_ERROR));
    klog_info("SecCnt:  0x%02X\n", inb(io_base + ATA_REG_SECCOUNT));
    klog_info("LBA Lo:  0x%02X\n", inb(io_base + ATA_REG_LBA_LO));
    klog_info("LBA Mid: 0x%02X\n", inb(io_base + ATA_REG_LBA_MID));
    klog_info("LBA Hi:  0x%02X\n", inb(io_base + ATA_REG_LBA_HI));
    klog_info("Device:  0x%02X\n", inb(io_base + ATA_REG_DEVICE));
    klog_info("Status:  0x%02X\n", inb(io_base + ATA_REG_STATUS));

    // 解析状态
    uint8_t status = inb(io_base + ATA_REG_STATUS);
    klog_info("  BSY: %d\n", !!(status & ATA_STATUS_BSY));
    klog_info("  DRDY: %d\n", !!(status & ATA_STATUS_DRDY));
    klog_info("  DRQ: %d\n", !!(status & ATA_STATUS_DRQ));
    klog_info("  ERR: %d\n", !!(status & ATA_STATUS_ERR));
}
```

### 6.2 数据验证

```c
// 写入测试模式
void test_pattern_write(void) {
    uint8_t buffer[512];

    // 创建可识别的模式
    for (int i = 0; i < 512; i++) {
        buffer[i] = i & 0xFF;
    }

    ata_write(ATA_PRIMARY_MASTER, 1, buffer, 1);
}

// 读取并验证
void test_pattern_verify(void) {
    uint8_t buffer[512];

    ata_read(ATA_PRIMARY_MASTER, 1, buffer, 1);

    // 验证模式
    bool ok = true;
    for (int i = 0; i < 512; i++) {
        if (buffer[i] != (i & 0xFF)) {
            klog_error("Mismatch at %d: got 0x%02X, expected 0x%02X\n",
                     i, buffer[i], i & 0xFF);
            ok = false;
        }
    }

    if (ok) {
        klog_info("Pattern verification PASSED\n");
    }
}
```

### 6.3 MBR 验证

```c
// 检查 MBR 签名
bool verify_mbr_signature(uint8_t* mbr) {
    uint16_t signature = *(uint16_t*)&mbr[510];

    klog_info("MBR Signature: 0x%04X\n", signature);

    if (signature == 0xAA55) {
        klog_info("MBR signature VALID\n");
        return true;
    } else {
        klog_error("MBR signature INVALID (expected 0xAA55)\n");
        return false;
    }
}
```

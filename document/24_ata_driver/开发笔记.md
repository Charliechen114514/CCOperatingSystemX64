## 1. 阶段背景

### 1.1 前一阶段遗留问题

在 Stage 23 (用户进程) 中，我们实现了：
- 进程管理基础
- 系统调用框架
- 用户态进程支持

但当时缺乏：
- **持久化存储** - 所有数据仅存在于内存中
- **文件系统基础** - 无法保存和加载文件
- **大容量存储** - 受限于物理内存大小
- **块设备 I/O** - 只有字符设备驱动

### 1.2 本阶段目标

```
核心目标：建立完整的磁盘 I/O 能力

1. 硬件驱动
   - ATA/IDE 控制器驱动
   - PIO 模式读写
   - 设备检测与识别

2. 寻址支持
   - LBA 寻址模式
   - LBA48 扩展支持

3. I/O 模式
   - 同步阻塞 I/O
   - 异步中断驱动 I/O

4. 多设备支持
   - Primary/Secondary 通道
   - Master/Slave 设备
```

## 2. 设计决策

### 2.1 PIO vs DMA

#### 问题

x86 ATA 支持两种数据传输模式：

| 模式 | 优点 | 缺点 |
|------|------|------|
| PIO | 简单、无需 DMA 控制器 | CPU 占用高、速度慢 |
| DMA | 高效、CPU 并行 | 复杂、需要 Bus Master |

#### 选择：使用 PIO

**理由**:
1. **实现简单** - 直接使用 CPU IN/OUT 指令
2. **学习友好** - 易于理解 I/O 端口操作
3. **足够使用** - 对于操作系统开发初期够用
4. **渐进式** - 后续可升级 DMA

#### 硬件时序

PIO 读写的严格时序要求：

```
写入命令 → 等待 400ns → 检查 BSY → 检查 DRQ → 传输数据
```

### 2.2 同步 vs 异步

#### 问题

I/O 操作可以采用两种模式：

| 模式 | 优点 | 缺点 |
|------|------|------|
| 同步 | 简单、易于理解 | 阻塞 CPU、效率低 |
| 异步 | 高效、CPU 并行 | 复杂、需要中断 |

#### 选择：两者都支持

**设计**:
```c
// 同步 API
ata_result_t ata_read(int device, uint64_t lba,
                      void* buffer, uint16_t sectors);

// 异步 API
ata_result_t ata_read_async(int device, uint64_t lba, void* buffer,
                            uint16_t sectors, ata_read_callback_fn cb,
                            void* context);
```

### 2.3 LBA vs CHS

#### 问题

磁盘寻址有两种方式：

| 方式 | 描述 | 容量限制 |
|------|------|----------|
| CHS | 柱面-磁头-扇区 | 8GB |
| LBA28 | 逻辑块地址 | 128GB |
| LBA48 | 扩展逻辑块地址 | 128PB |

#### 选择：LBA 优先，CHS 兼容

```c
// 优先使用 LBA
if (info->lba_supported) {
    return ata_read_lba(ctrl, device, lba, buffer, sectors);
} else {
    return ata_read_chs(ctrl, device, lba, buffer, sectors);
}
```

## 4. 实现细节

### 4.1 设备检测流程

```c
bool ata_device_present(ata_controller_t* ctrl, ata_device_t device) {
    // 1. 选择设备
    ata_select_device(ctrl, device);

    // 2. 发送 IDENTIFY 命令
    outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_IDENTIFY);

    // 3. 检查状态
    uint8_t status = inb(ctrl->io_base + ATA_REG_STATUS);

    // 4. status = 0 表示无设备
    if (status == 0) return false;

    // 5. 错误位表示 ATAPI（不支持）
    if (status & ATA_STATUS_ERR) return false;

    // 6. 等待 BSY 清除并检查 DRQ
    return ata_wait_bsy(ctrl->io_base) == ATA_OK;
}
```

### 4.2 IDENTIFY 数据解析

IDENTIFY 命令返回 256 字（512 字节）的设备信息：

```c
ata_result_t ata_identify_device(ata_controller_t* ctrl,
                                 ata_device_t device,
                                 ata_device_info_t* info) {
    // ... 读取 256 字 ...

    // 解析能力位
    uint16_t caps = identify_data[ATA_IDENT_CAPABILITIES];
    info->lba_supported = (caps & ATA_CAP_LBA) != 0;
    info->dma_supported = (caps & ATA_CAP_DMA) != 0;
    info->lba48_supported = (caps & ATA_CAP_LBA48) != 0;

    // 解析字符串（大端序字）
    ata_identify_string_to_c(&identify_data[ATA_IDENT_MODEL],
                              info->model, 20);

    // 解析扇区数
    info->lba_sectors = ((uint64_t)identify_data[61] << 16) |
                        identify_data[60];

    return ATA_OK;
}
```

### 4.3 400ns 延迟实现

ATA 规范要求某些操作后等待至少 400ns：

```c
static inline void ata_delay(void) {
    // 读取未使用的端口实现延迟
    for (int i = 0; i < 4; i++) {
        inb(0x80);  // 每次约 100ns
    }
}
```

### 4.4 BSY/DRQ 等待

```c
ata_result_t ata_wait_bsy(uint16_t io_base) {
    uint32_t timeout = 100000;

    while (timeout-- > 0) {
        uint8_t status = inb(io_base + ATA_REG_STATUS);
        if (!(status & ATA_STATUS_BSY)) {
            return ATA_OK;
        }
        __asm__ volatile("pause");
    }

    return ATA_ERR_TIMEOUT;
}

ata_result_t ata_wait_drq(uint16_t io_base) {
    uint32_t timeout = 100000;

    while (timeout-- > 0) {
        uint8_t status = inb(io_base + ATA_REG_STATUS);
        if ((status & ATA_STATUS_DRQ) && !(status & ATA_STATUS_BSY)) {
            return ATA_OK;
        }
        if (status & ATA_STATUS_ERR) {
            return ATA_ERR_IO_ERROR;
        }
        __asm__ volatile("pause");
    }

    return ATA_ERR_TIMEOUT;
}
```

### 4.5 PIO 读取实现

```c
ata_result_t ata_read_pio(ata_controller_t* ctrl, ata_device_t device,
                          uint32_t lba, void* buffer, uint16_t sectors) {
    // 1. 选择设备并等待
    ata_select_device(ctrl, device);
    ata_wait_bsy(ctrl->io_base);

    // 2. 设置 LBA 地址
    outb(ctrl->io_base + ATA_REG_SECCOUNT, sectors);
    outb(ctrl->io_base + ATA_REG_LBA_LO, lba & 0xFF);
    outb(ctrl->io_base + ATA_REG_LBA_MID, (lba >> 8) & 0xFF);
    outb(ctrl->io_base + ATA_REG_LBA_HI, (lba >> 16) & 0xFF);

    // 3. 设备寄存器（包含 LBA 最高位和设备选择）
    uint8_t dev_byte = ATA_DEV_LBA;
    if (device == ATA_DEVICE_SLAVE) dev_byte |= ATA_DEV_SLAVE;
    dev_byte |= (lba >> 24) & 0x0F;
    outb(ctrl->io_base + ATA_REG_DEVICE, dev_byte);

    // 4. 发送读命令
    outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_READ_SECTORS);

    // 5. 读取每个扇区
    uint16_t* buf16 = (uint16_t*)buffer;
    for (uint16_t sec = 0; sec < sectors; sec++) {
        ata_wait_drq(ctrl->io_base);

        // 读取 256 字（512 字节）
        for (int i = 0; i < 256; i++) {
            buf16[sec * 256 + i] = inw(ctrl->io_base + ATA_REG_DATA);
        }
    }

    return ATA_OK;
}
```

## 5. 常见陷阱

### 5.1 忘记 400ns 延迟

#### 问题

选择设备后立即发送命令，导致设备未准备好。

```c
// 错误示例
ata_select_device(ctrl, device);
outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_IDENTIFY);  // 太快！
```

#### 解决方案

```c
ata_select_device(ctrl, device);
ata_delay();  // 等待 400ns
outb(ctrl->io_base + ATA_REG_COMMAND, ATA_CMD_IDENTIFY);
```

### 5.2 字符串字节序错误

#### 问题

IDENTIFY 数据中的字符串以大端序字存储：

```
原始: "QEMU HARDDISK"
存储: 0x5145 0x5551 0x2048 0x5241 0x4444 0x4953 0x4B20
```

直接读取会得到乱码。

#### 解决方案

```c
void ata_identify_string_to_c(const uint16_t* src, char* dest, int words) {
    for (int i = 0; i < words; i++) {
        uint16_t word = src[i];
        dest[i * 2] = (char)(word >> 8);     // 高字节在前
        dest[i * 2 + 1] = (char)(word & 0xFF);  // 低字节在后
    }
    dest[words * 2] = '\0';

    // 去除尾部空格
    int len = words * 2;
    while (len > 0 && dest[len - 1] == ' ') {
        dest[--len] = '\0';
    }
}
```

### 5.3 256 扇区边界

#### 问题

ATA 命令中 256 扇区编码为 0：

```c
// 错误示例
uint8_t sec_count = sectors;  // 256 会变成 0！
```

#### 解决方案

```c
uint8_t sec_count = (sectors == 256) ? 0 : sectors;
```

### 5.4 LBA 地址截断

#### 问题

LBA48 命令使用不同的寄存器写入顺序：

```c
// LBA28
outb(io_base + ATA_REG_LBA_LO, lba & 0xFF);
outb(io_base + ATA_REG_LBA_MID, (lba >> 8) & 0xFF);
outb(io_base + ATA_REG_LBA_HI, (lba >> 16) & 0xFF);

// LBA48 - 需要写入两次！
outb(io_base + ATA_REG_LBA_LO, lba & 0xFF);
outb(io_base + ATA_REG_LBA_MID, (lba >> 8) & 0xFF);
outb(io_base + ATA_REG_LBA_HI, (lba >> 16) & 0xFF);
outb(io_base + ATA_REG_LBA_LO, (lba >> 24) & 0xFF);  // 再次写入
outb(io_base + ATA_REG_LBA_MID, (lba >> 32) & 0xFF);
outb(io_base + ATA_REG_LBA_HI, (lba >> 48) & 0xFF);
```

## 6. 性能优化

### 6.1 批量读写

```c
// 单扇区读取 - 慢
for (int i = 0; i < 256; i++) {
    ata_read(device, i, buffer + i * 512, 1);
}

// 批量读取 - 快
ata_read(device, 0, buffer, 256);
```

### 6.2 避免轮询

使用中断驱动的异步模式：

```c
// 同步模式 - CPU 阻塞
ata_read(device, lba, buffer, sectors);  // 等待完成

// 异步模式 - CPU 并行
ata_read_async(device, lba, buffer, sectors, callback, NULL);
// 可以做其他工作...
```

## 8. 经验总结

### 8.1 最大的收获

#### I/O 端口操作是基础

```
理解 I/O 端口操作是硬件驱动的关键：
- inb/outb 用于字节传输
- inw/outw 用于字传输（数据端口）
- 严格的时序要求必须遵守
```

#### 状态轮询是关键

```
ATA 设备状态轮询的正确顺序：
1. 等待 BSY 清除（设备就绪）
2. 检查 ERR 位（错误检测）
3. 等待 DRQ 置位（数据准备）
4. 传输数据
```

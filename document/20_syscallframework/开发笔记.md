## 为什么需要系统调用框架

### 1.1 用户态与内核态的隔离

在保护模式下，x86_64 处理器提供四个特权级（Ring 0-3），操作系统通常：

- **内核态 (Ring 0)**：完全访问硬件和系统资源
- **用户态 (Ring 3)**：受限访问，不能直接执行特权指令

用户程序需要请求内核服务时，必须通过**系统调用**来安全地切换到内核态。

### 1.2 传统中断方式的局限性

早期的系统调用使用软中断（如 int 0x80）：

```asm
; 传统 int 0x80 方式
int 0x80    ; 触发中断，切换到内核态
```

这种方式存在性能问题：

1. **保存/恢复开销大**：需要保存完整的中断帧（SS, RSP, RFLAGS, CS, RIP）
2. **中断处理复杂**：需要查 IDT 表，处理中断控制器
3. **无法优化**：通用中断机制，不能针对系统调用优化

### 1.3 syscall/sysret 的优势

x86_64 引入了专用的 syscall/sysret 指令：

```asm
; 现代方式
syscall     ; 快速切换到内核态
sysretq     ; 快速返回用户态
```

优势：

1. **更快**：专用指令，硬件优化
2. **开销更小**：只保存必要的寄存器（RCX, R11）
3. **不经过 IDT**：直接从 MSR 读取目标地址

## x86_64 系统调用机制详解

### 2.1 syscall 指令工作原理

当用户态程序执行 `syscall` 指令时，CPU 自动执行以下操作：

```
1. 保存用户模式状态：
   - RCX ← RIP (用户返回地址)
   - R11 ← RFLAGS (用户标志)

2. 加载内核模式状态：
   - RIP ← IA32_LSTAR (内核入口点)
   - CS ← IA32_STAR[47:32] (内核代码段)
   - SS ← IA32_STAR[47:32] + 8 (内核数据段)

3. 清除 RFLAGS 标志：
   - RFLAGS ← RFLAGS & ~IA32_FMASK

4. 提升特权级到 Ring 0

5. 开始执行内核代码
```

### 2.2 sysretq 指令工作原理

当内核执行 `sysretq` 指令返回时：

```
1. 恢复用户模式状态：
   - RIP ← RCX
   - RFLAGS ← R11

2. 加载用户模式段：
   - CS ← IA32_STAR[63:48] | 3 (用户代码段)
   - SS ← IA32_STAR[63:48] + 8 | 3 (用户数据段)

3. 降低特权级到 Ring 3

4. 开始执行用户代码
```

### 2.3 MSR 寄存器详解

#### IA32_LSTAR (0xC0000082) - Long Mode SYSCALL Target Address

```
保存 syscall 指令的目标 RIP 值（内核入口点地址）

例如：syscall_handler 函数的地址
```

#### IA32_STAR (0xC0000081) - SYSCALL Target Address Register

```
63:48 - SYSRET CS (用户模式代码段选择器)
       = GDT_USER_CODE | 3 = 0x18 | 3 = 0x1B

47:32 - syscall CS (内核模式代码段选择器)
       = GDT_KERNEL_CODE = 0x08

其他位 - 保留
```

#### IA32_FMASK (0xC0000084) - SYSCALL Flag Mask

```
指定 syscall 时需要清除的 RFLAGS 位

常用值：0x200 (清除 IF 位，禁用中断)

其他有用的位：
- 0x001: CF (进位标志)
- 0x040: TF (陷阱标志)
- 0x080: SF (符号标志)
```

### 2.4 System V AMD64 ABI 调用约定

系统调用遵循 System V AMD64 ABI：

| 寄存器 | 用途 |
|--------|------|
| RAX | 系统调用号（输入）/ 返回值（输出） |
| RDI | 第 1 个参数 |
| RSI | 第 2 个参数 |
| RDX | 第 3 个参数 |
| R10 | 第 4 个参数 |
| RCX | - (syscall 不使用，用于保存 RIP) |
| R8 | 第 5 个参数 |
| R9 | 第 6 个参数 |

**注意**：系统调用使用 R10 而非 RCX 作为第 4 个参数，这是因为 syscall 指令会覆盖 RCX。

## 设计决策

### 3.1 syscall vs int 0x80

#### 方案对比

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| syscall/sysret | 快速，专用指令 | 需要 MSR 配置 | ✅ 主要接口 |
| int 0x80 | 兼容性好，简单 | 慢，开销大 | ✅ 备用接口 |
| call gate | 历史遗留 | 不再使用 | ❌ |

**决策**：同时实现两种接口
- 默认使用 syscall/sysret
- 提供 int 0x80 作为兼容性备用

### 3.2 系统调用表设计

#### 方案对比

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 静态数组 | 简单，快速查找 | 固定大小，浪费空间 | ✅ |
| 哈希表 | 动态扩展 | 实现复杂，查找慢 | ❌ |
| 跳转表 | 编译时优化 | 不灵活 | ❌ |

**决策**：使用 256 项静态数组
- 系统调用号范围：0-255
- O(1) 查找
- 内存开销小（256 × 16 字节 = 4KB）

### 3.3 系统调用帧结构

```c
typedef struct PACKED {
    uint64_t syscall_number;    // RAX
    uint64_t arg0;              // RDI
    uint64_t arg1;              // RSI
    uint64_t arg2;              // RDX
    uint64_t arg3;              // R10
    uint64_t arg4;              // R8
    uint64_t arg5;              // R9
} syscall_frame_t;
```

**设计考虑**：
- 与 System V AMD64 ABI 一一对应
- 48 字节，栈上对齐友好
- 方便处理函数访问

### 3.4 错误处理策略

```c
typedef enum syscall_result {
    SYS_OK           = 0,   // 成功
    SYS_ERR_INVAL    = -1,  // 无效参数
    SYS_ERR_PERM     = -2,  // 权限拒绝
    SYS_ERR_NOMEM    = -3,  // 内存不足
    SYS_ERR_NFILE    = -4,  // 文件描述符溢出
    SYS_ERR_NOENT    = -5,  // 文件不存在
    SYS_ERR_IO       = -6,  // I/O 错误
    SYS_ERR_NOTIMPL  = -7,  // 未实现
} syscall_result_t;
```

**策略**：
- 使用负数返回值表示错误
- 0 或正数表示成功
- 未实现系统调用返回 SYS_ERR_NOTIMPL

### 4.2 数据流

#### 系统调用发起流程

```
用户程序: syscall
    │
    ├─> CPU 保存 RCX→RIP, R11→RFLAGS
    ├─> CPU 加载 RIP←IA32_LSTAR
    ├─> CPU 切换到 Ring 0
    │
    ▼
syscall_handler (汇编)
    │
    ├─> 保存所有通用寄存器
    ├─> 加载内核数据段
    ├─> 栈对齐
    ├─> 构建 syscall_frame_t
    │
    ▼
syscall_dispatch (C)
    │
    ├─> 读取系统调用号
    ├─> 边界检查
    ├─> 更新统计
    ├─> 查找处理函数
    │
    ▼
sys_xxx (系统调用处理函数)
    │
    ├─> 执行系统调用逻辑
    ├─> 返回结果
    │
    ▼
syscall_handler (汇编返回)
    │
    ├─> 清理栈
    ├─> 恢复用户 RIP/RFLAGS
    ├─> 恢复寄存器
    │
    ▼
sysretq (返回用户态)
```

## 实现细节

### 5.1 MSR 配置实现

```c
void syscall_init(void) {
    // 1. 检查 CPU 支持
    if (!syscall_is_available()) {
        klog_error("[SYSCALL] CPU does not support syscall/sysret\n");
        return;
    }

    // 2. 启用 CR4 的 SCE 位
    uint64_t cr4;
    __asm__ volatile("mov %%cr4, %0" : "=r"(cr4));
    cr4 |= (1 << 11);  // SCE bit
    __asm__ volatile("mov %0, %%cr4" : : "r"(cr4));

    // 3. 配置 IA32_LSTAR
    extern void syscall_handler(void);
    wrmsr(0xC0000082, (uint64_t)syscall_handler);

    // 4. 配置 IA32_STAR
    uint64_t star = ((uint64_t)(GDT_USER_CODE | 3) << 48) |
                    ((uint64_t)GDT_KERNEL_CODE << 32);
    wrmsr(0xC0000081, star);

    // 5. 配置 IA32_FMASK
    wrmsr(0xC0000084, SYSCALL_FMASK_DEFAULT);

    // 6. 注册 int 0x80 处理器
    extern void int0x80_handler(void);
    idt_set_gate(128, (uint64_t)int0x80_handler,
                 IDT_USER_INTERRUPT_GATE, GDT_KERNEL_CODE);
}
```

### 5.2 汇编入口实现

```asm
; syscall_handler - syscall 指令入口点
global syscall_handler
extern syscall_dispatch
syscall_handler:
    ; syscall 指令已保存：
    ;   RCX = 用户 RIP
    ;   R11 = 用户 RFLAGS

    ; 保存所有寄存器
    push rax
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15

    ; 单独保存 RCX 和 R11
    mov r15, rcx    ; 用户 RIP
    mov r14, r11    ; 用户 RFLAGS

    ; 加载内核数据段
    mov ax, 0x10    ; GDT_KERNEL_DATA
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    ; 栈对齐 (16 字节)
    push qword 0

    ; 构建 syscall_frame_t
    sub rsp, 48
    mov qword [rsp], rax      ; syscall_number
    mov qword [rsp+8], rdi    ; arg0
    mov qword [rsp+16], rsi   ; arg1
    mov qword [rsp+24], rdx   ; arg2
    mov qword [rsp+32], r10   ; arg3
    mov qword [rsp+40], r8    ; arg4

    ; 调用 C 分发器
    mov rdi, rsp    ; frame 指针
    mov rsi, r9     ; arg5
    call syscall_dispatch

    ; 清理并返回
    add rsp, 48
    add rsp, 8

    ; 恢复用户 RIP/RFLAGS
    mov rcx, r15
    mov r11, r14

    ; 恢复寄存器
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbp
    pop rbx
    pop rax

    ; 返回用户态
    sysretq
```

### 5.3 系统调用分发实现

```c
int64_t syscall_dispatch(syscall_frame_t* frame, uint64_t arg5) {
    // 更新统计
    s_stats.total_calls++;
    uint64_t number = frame->syscall_number;

    // 边界检查
    if (number >= SYS_MAX) {
        s_stats.errors++;
        return SYS_ERR_INVAL;
    }

    // 保存 arg5 到 frame
    frame->arg5 = arg5;

    // 更新每个系统调用的计数
    if (number < 256) {
        s_stats.syscall_calls[number]++;
    }

    // 获取处理函数
    syscall_entry_t* entry = &s_syscall_table[number];

    // 检查是否已注册
    if (!entry->registered || entry->handler == NULL) {
        return syscall_not_impl(frame);
    }

    // 调用处理函数
    return entry->handler(frame);
}
```

### 5.4 系统调用注册

```c
int syscall_register_handler(uint64_t number,
                             syscall_handler_fn handler,
                             const char* name) {
    // 边界检查
    if (number >= SYS_MAX) {
        return -1;
    }

    // 检查处理函数
    if (handler == NULL) {
        return -2;
    }

    // 注册
    syscall_entry_t* entry = &s_syscall_table[number];
    entry->handler = handler;
    entry->name = name;
    entry->registered = true;

    return 0;
}
```

## 常见陷阱与注意事项

### 6.1 栈对齐问题

**陷阱**：调用 C 函数前未对齐栈

System V AMD64 ABI 要求调用时栈 16 字节对齐。

```c
// 错误：未对齐
call syscall_dispatch  ; 栈可能未对齐

// 正确：确保对齐
push qword 0           ; 强制对齐
call syscall_dispatch
add rsp, 8
```

### 6.2 R10 vs RCX

**陷阱**：混淆 R10 和 RCX 作为第 4 个参数

系统调用使用 R10，普通函数调用使用 RCX。

```c
// 系统调用约定：
// arg0=rdi, arg1=rsi, arg2=rdx, arg3=r10, arg4=r8, arg5=r9

// 普通函数调用约定：
// arg0=rdi, arg1=rsi, arg2=rdx, arg3=rcx, arg4=r8, arg5=r9
```

### 6.3 MSR 写入时机

**陷阱**：在启用 SCE 位前写入 MSR

```c
// 错误顺序：
wrmsr(...);        // 写入 MSR
cr4 |= (1 << 11);  // 启用 SCE

// 正确顺序：
cr4 |= (1 << 11);  // 先启用 SCE
wrmsr(...);        // 再写入 MSR
```

### 6.4 int 0x80 参数顺序

**陷阱**：int 0x80 使用不同的寄存器约定

```c
// int 0x80 使用 i386 约定：
// arg0=ebx, arg1=ecx, arg2=edx, arg3=esi, arg4=edi, arg5=ebp

// 我们的 int 0x80 处理器转换为标准约定
```

### 6.5 返回值检查

**陷阱**：忽略负数返回值表示错误

```c
// 错误：
int64_t result = syscall_dispatch(&frame, arg5);
klog_info("Result: %lld\n", result);  // 可能是错误码

// 正确：
int64_t result = syscall_dispatch(&frame, arg5);
if (result < 0) {
    // 处理错误
    klog_error("Syscall failed: %lld\n", result);
} else {
    klog_info("Result: %lld\n", result);
}
```

### 6.6 GDT 段选择器

**陷阱**：STAR 寄存器配置错误

```c
// 错误：
uint64_t star = ((uint64_t)GDT_USER_CODE << 48) |  // 忘记 | 3
                ((uint64_t)GDT_KERNEL_CODE << 32);

// 正确：
uint64_t star = ((uint64_t)(GDT_USER_CODE | 3) << 48) |  // 用户态需要 RPL=3
                ((uint64_t)GDT_KERNEL_CODE << 32);
```

## 测试方法

### 7.1 MSR 配置测试

```c
static bool test_msr_config(void) {
    // 读取 IA32_LSTAR
    uint64_t lstar = rdmsr(0xC0000082);
    assert(lstar != 0);

    // 读取 IA32_STAR
    uint64_t star = rdmsr(0xC0000081);
    assert(star != 0);

    // 验证段选择器
    uint32_t user_cs = (star >> 48) & 0xFFFF;
    uint32_t kernel_cs = (star >> 32) & 0xFFFF;
    assert(kernel_cs == 0x08);
    assert(user_cs == 0x1B);

    return true;
}
```

### 7.2 系统调用分发测试

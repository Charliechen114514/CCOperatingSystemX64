## 1. 阶段背景

### 1.1 前一阶段遗留问题

在 Stage 09 (内存管理与串口驱动) 中，我们实现了：
- 基础的内存管理 (`kmalloc`, `kfree`)
- 串口驱动 (`sync_serial_puts`)

但当时缺乏：
- **格式化输出能力** - 只能输出固定字符串
- **字符串处理函数** - 没有数值转换工具
- **统一的日志接口** - 直接调用串口驱动，难以扩展
- **颜色输出支持** - 日志缺乏视觉区分

### 1.2 本阶段目标

```
核心目标：建立类似 Linux kernel 的 printk/kprintf 系统

1. 基础字符串库
   - 字符分类 (isspace, isdigit)
   - 字符串转数值 (strtol, strtoul, atoi)
   - 数值转字符串 (itoa, uitoa)

2. 格式化日志系统
   - printf 风格格式化 (%s, %d, %x, %p)
   - 分级日志 (TRACE, DEBUG, INFO, WARN, ERROR)
   - 可扩展后端架构

3. 串口彩色输出
   - ANSI 转义序列支持
   - 日志级别颜色映射

4. 欢迎界面重构
   - 将欢迎界面从 kernel_main.c 分离
   - 模块化的欢迎界面实现
```

## 2. 设计决策

### 2.1 为什么自己实现字符串库？

#### 问题
内核环境没有标准库支持，无法使用 `stdlib.h` 和 `stdio.h`。

#### 选择

**方案 A**: 简单实现
```c
// 只实现需要的功能
int my_atoi(const char* s) { ... }
void my_itoa(int val, char* buf) { ... }
```

**方案 B**: 完整实现
```c
// 兼容标准库接口
long strtol(const char* nptr, char** endptr, int base) { ... }
```

#### 决策：采用方案 B

**理由**:
1. **可维护性** - 标准接口便于理解和替换
2. **可扩展性** - 完整功能便于后续使用
3. **代码质量** - 处理边界情况更全面

### 2.2 为什么使用后端抽象？

#### 问题

直接调用串口驱动会导致：
```c
// 紧耦合
void log_info(const char* msg) {
    sync_serial_puts("[INFO] ");
    sync_serial_puts(msg);
    sync_serial_puts("\n");
}
```

#### 解决方案

抽象接口层：
```c
typedef struct {
    void (*process)(const char* str, int level);
    bool (*is_ready)(void);
} KLogBackendOps;

void klog_info(const char* format, ...) {
    const KLogBackendOps* ops = klog_get_backend_ops(KLOG_BACKEND_SERIAL);
    if (ops && ops->is_ready()) {
        // 格式化输出
        ops->process(buffer, KLOG_LEVEL_INFO);
    }
}
```

**好处**:
1. **解耦** - 日志系统不依赖具体输出设备
2. **可扩展** - 未来可轻松添加 VGA、文件、网络后端
3. **可测试** - 可以 mock 后端进行单元测试

### 2.3 为什么选择分级日志？

#### 常见分级

```
TRACE  - 最详细的跟踪信息
DEBUG  - 调试信息
INFO   - 一般信息
WARN   - 警告
ERROR  - 错误
FATAL  - 致命错误 (暂未实现)
```

#### 设计考虑

1. **编译时过滤** vs **运行时过滤**
   - 编译时：完全移除不需要的日志代码
   - 运行时：动态调整过滤级别

2. **决策：支持运行时过滤**
   ```c
   static klog_level_t g_log_level = KLOG_LEVEL_TRACE;

   void klog_log(klog_level_t level, const char* format, ...) {
       if (level < g_log_level) {
           return;  // 提前返回，不处理
       }
       // ...
   }
   ```

### 2.4 为什么支持 ANSI 颜色？

#### 动机

串口输出到终端时，纯文本难以区分：
```
[TRACE]Entering function foo
[DEBUG]Variable x = 42
[INFO]System started
[WARN]Low memory
[ERROR]Failed to open device
```

#### 方案

使用 ANSI 转义序列：
```
\033[30m - 黑色
\033[31m - 红色
\033[32m - 绿色
\033[33m - 黄色
...
\033[0m  - 重置
```

#### 颜色映射

```c
const char* serial_color_for_log_level(int level) {
    switch (level) {
        case 0: return "\033[90m";  // TRACE  → Gray
        case 1: return "\033[35m";  // DEBUG  → Magenta
        case 2: return "\033[32m";  // INFO   → Green
        case 3: return "\033[33m";  // WARN   → Yellow
        case 4: return "\033[31m";  // ERROR  → Red
        default: return "\033[0m";  // other  → Reset
    }
}
```

## 4. 实现细节

### 4.1 vsnprintf 简化实现

#### 挑战

内核中没有 `vsnprintf`，需要自实现。

#### 实现策略

```c
static int format_string(char* buffer, size_t size,
                         const char* format, va_list args) {
    size_t pos = 0;

    while (*p != '\0' && pos < size - 1) {
        if (*p != '%') {
            buffer[pos++] = *p++;
            continue;
        }

        p++; // Skip '%'

        switch (*p) {
            case 's':  // 字符串
                s = va_arg(args, const char*);
                // 复制到 buffer
                break;
            case 'd':  // 有符号整数
                val = va_arg(args, int);
                itoa(val, g_format_buffer, 10);
                // 复制到 buffer
                break;
            case 'x':  // 十六进制
                val = va_arg(args, unsigned int);
                uitoa(val, g_format_buffer, 16);
                break;
            // ...
        }
        p++;
    }

    buffer[pos] = '\0';
    return pos;
}
```

#### 支持的格式符

| 格式符 | 类型 | 示例 |
|--------|------|------|
| `%` | 字面量 `%` | `%%` → `%` |
| `c` | 字符 | `%c` → `A` |
| `s` | 字符串 | `%s` → `hello` |
| `d/i` | 有符号整数 | `%d` → `-42` |
| `u` | 无符号整数 | `%u` → `42` |
| `x` | 十六进制 (小写) | `%x` → `2a` |
| `p` | 指针 | `%p` → `0x7c00` |

### 4.2 strtol 实现

#### 边界情况处理

```c
long strtol(const char* nptr, char** endptr, int base) {
    const char* s = nptr;
    long result = 0;
    bool neg = false;

    // 1. 跳过空白字符
    while (isspace((unsigned char)*s))
        s++;

    // 2. 处理符号
    if (*s == '-') {
        neg = true;
        s++;
    } else if (*s == '+') {
        s++;
    }

    // 3. 自动检测基数
    if (base == 0) {
        if (*s == '0') {
            if (*(s + 1) == 'x' || *(s + 1) == 'X') {
                base = 16;
                s += 2;
            } else {
                base = 8;
                s++;
            }
        } else {
            base = 10;
        }
    }

    // 4. 转换数字
    const char* start = s;
    while (*s) {
        int digit;
        if (*s >= '0' && *s <= '9')
            digit = *s - '0';
        else if (*s >= 'a' && *s <= 'z')
            digit = *s - 'a' + 10;
        else if (*s >= 'A' && *s <= 'Z')
            digit = *s - 'A' + 10;
        else
            break;

        if (digit >= base)
            break;

        result = result * base + digit;
        s++;
    }

    // 5. 设置 endptr
    if (endptr)
        *endptr = (s != start) ? (char*)s : (char*)nptr;

    return neg ? -result : result;
}
```

### 4.3 itoa 实现

#### 算法选择

**方法**: 反向构造 + 反转字符串

```c
char* itoa(int value, char* str, int base) {
    int i = 0;
    bool neg = false;
    unsigned int uval;

    // 处理负数 (仅十进制)
    if (value < 0 && base == 10) {
        neg = true;
        uval = (unsigned int)(-value);
    } else {
        uval = (unsigned int)value;
    }

    // 反向生成数字
    do {
        int digit = uval % base;
        str[i++] = (digit < 10) ? ('0' + digit) : ('a' + digit - 10);
        uval /= base;
    } while (uval != 0);

    // 添加负号
    if (neg)
        str[i++] = '-';

    str[i] = '\0';

    // 反转字符串
    reverse_str(str, i);

    return str;
}
```

**示例**:
```
value = -1234, base = 10

1. uval = 1234
2. 反向生成: "4321-"
3. 反转: "-1234"
```

### 4.4 后端注册机制

```c
// 全局后端表
static const KLogBackendOps* g_backends[KPRINTF_MAX_BACKEND_N];
static klog_backend_t g_default_backend = KLOG_BACKEND_NONE;

// 注册后端
bool klog_register_backend(klog_backend_t backend_type,
                           const KLogBackendOps* ops) {
    if (backend_type >= KPRINTF_MAX_BACKEND_N) {
        return false;
    }
    g_backends[backend_type] = ops;
    return true;
}

// 获取后端
const KLogBackendOps* klog_get_backend_ops(klog_backend_t backend) {
    if (backend >= KPRINTF_MAX_BACKEND_N) {
        return NULL;
    }
    return g_backends[backend];
}
```

## 5. 常见陷阱

### 5.1 变长参数陷阱

#### 陷阱：忘记 va_end

```c
// 错误
void klog_info(const char* format, ...) {
    va_list args;
    va_start(args, format);
    // 使用 args
    // 忘记 va_end
}

// 正确
void klog_info(const char* format, ...) {
    va_list args;
    va_start(args, format);
    // 使用 args
    va_end(args);  // 必须调用！
}
```

#### 陷阱：va_list 的多次遍历

```c
// 错误：va_list 只能遍历一次
va_list args;
va_start(args, format);
klog_format1(args);
klog_format2(args);  // undefined behavior
va_end(args);

// 正确：使用 va_copy
va_list args, args2;
va_start(args, format);
va_copy(args2, args);
klog_format1(args);
klog_format2(args2);
va_end(args2);
va_end(args);
```

### 5.2 数组边界陷阱

#### 陷阱：缓冲区溢出

```c
// 错误：没有检查边界
void append(char* buf, const char* s) {
    while (*s) {
        *buf++ = *s++;  // 可能溢出
    }
}

// 正确
void append(char* buf, size_t size, const char* s) {
    size_t pos = 0;
    while (*s && pos < size - 1) {
        buf[pos++] = *s++;
    }
    buf[pos] = '\0';
}
```

### 5.3 ANSI 转义序列陷阱

#### 陷阱：转义序列被截断

```c
// 错误：分段输出导致序列分离
sync_serial_puts("\033[");
sync_serial_puts("31m");
sync_serial_puts("Error\n");
// 如果中间被中断，可能显示原始字符

// 正确：原子输出
sync_serial_puts("\033[31mError\033[0m\n");
```

### 5.4 字符串格式化陷阱

#### 陷阱：格式字符串和参数不匹配

```c
// 危险：类型不匹配
klog_info("Value: %s", 123);  // 将整数当作指针

// 危险：参数数量不匹配
klog_info("Values: %d %d %d", 1, 2);  // 缺少一个参数

// 正确：使用编译警告检查
// GCC/Clang: -Wformat
```

## 6. 性能优化

### 6.1 静态缓冲区

#### 设计

```c
// 使用静态缓冲区避免频繁分配
static char g_format_buffer[32];   // 用于数字转换
static char buffer[KPRINTF_BUFFER_SIZE];  // 用于格式化输出
```

**优点**:
- 避免动态内存分配
- 减少栈使用
- 提高缓存命中率

**缺点**:
- 不是线程安全的
- 缓冲区大小固定

### 6.2 提前返回优化

```c
void klog_log(klog_level_t level, const char* format, ...) {
    // 级别不够，提前返回
    if (level < g_log_level) {
        return;  // 避免格式化开销
    }

    // ... 格式化和输出
}
```

### 6.3 内联小函数

```c
// 小函数适合内联
static inline bool isdigit(char ch) {
    return '0' <= ch && ch <= '9';
}

static inline bool isspace(char ch) {
    return strchr(" \t\n\v\f\r", ch) != NULL;
}
```

```c
typedef enum {
    KLOG_LEVEL_TRACE = 0,
    KLOG_LEVEL_DEBUG = 1,
    KLOG_LEVEL_INFO  = 2,
    KLOG_LEVEL_WARN  = 3,
    KLOG_LEVEL_ERROR = 4,
    KLOG_LEVEL_FATAL = 5,  // 新增

// klog_fatal 会在输出后停止系统
void klog_fatal(const char* format, ...) {
    klog_log(KLOG_LEVEL_FATAL, format, ...);
    system_halt();
}
```

#### 3. VGA 后端实现

```c
// kernel/klogs/backends/vga_backends.c
#include "driver/vga/vga.h"

static void vga_backend_process(const char* str, int level) {
    vga_puts_color(str, vga_color_for_log_level(level));
}

static bool vga_backend_is_ready(void) {
    return vga_is_initialized();
}

const KLogBackendOps* klog_vga_backend_get_ops(void) {
    static const KLogBackendOps ops = {
        .process = vga_backend_process,
```

## 8. 经验总结

### 8.1 最大的收获

#### 抽象的价值

```
直接实现 vs 抽象设计

直接实现:
  快速完成，但难以扩展
  修改一处需要改全部

抽象设计:
  前期投入，但长期受益
  新增功能无需修改现有代码
```

#### 渐进式开发

```
1. 先实现核心功能
   - 简单的格式化输出
   - 基本的字符串转换

2. 再添加高级特性
   - 分级日志
   - 后端抽象

3. 最后优化完善
   - 性能优化
   - 错误处理
```

## 1. 开发流程

### 1.1 迭代开发策略

#### 原则
```
先让它工作，再让它优雅。
```

#### CCOS 开发迭代
```
1. 实模式启动
   ✓ MBR 加载
   ✓ 字符串打印
   ✓ Stage 2 加载

2. 保护模式切换
   ✓ GDT 设置
   ✓ Far jump
   ✓ 段寄存器加载

3. 长模式切换
   ✓ 页表设置
   ✓ PAE 启用
   ✓ EFER.LME 设置
   ✓ 分页启用
```

#### 避免一次性实现过多功能
**错误做法**:
```asm
; 同时实现保护模式 + 长模式 + VGA 打印
protected_mode:
    call setup_segments
    call print_message
    call setup_page_tables
    call enable_paging
    jmp long_mode
```

**正确做法**:
```asm
; 先只实现模式切换，验证成功后再添加其他功能
protected_mode:
    call setup_segments
    jmp hang           ; 先验证这里能到达
```

### 1.2 调试驱动开发

#### 逐步验证
```
每完成一个功能点，立即测试验证。

示例：
1. 实现 GDT 加载
   → 编译
```

## 2. 关键决策

### 2.1 为什么选择两阶段 Bootloader？

#### 单阶段问题
```
MBR 只有 512 字节，无法容纳：
  - 完整的 GDT（40 字节）
  - 页表设置代码（4KB × 3）
  - 错误处理代码
  - 字符串数据
```

#### 两阶段优势
```
Stage 1 (MBR, 512 bytes):
  - 只负责加载 Stage 2
  - 简单的 LBA/CHS 读取
  - 最小化错误处理

Stage 2 (0x7E00, 无限制):
  - 完整的系统初始化
  - 复杂的内存管理
  - 模式切换逻辑
```

### 2.2 为什么使用 Identity Mapping？

#### 问题
```
启用分页后，所有地址都经过页表翻译。
如果页表中没有映射当前代码地址，会立即 Page Fault。
```

#### 解决方案
```
PML4[0] → PDPT[0] → PD[0] → 0x00000000 (identity)
                              → 0x00200000 (2MB page)

这样，启用分页后：
  - 0x7E00 仍然映射到物理 0x7E00
  - 代码继续执行，不会 Page Fault
```

### 2.3 为什么需要 Higher-Half Mapping？

#### 内核地址空间分离
```
传统（无 higher-half）:
  - 内核代码在低 4GB
  - 用户空间也在低 4GB
  - 需要复杂的权限管理

现代（with higher-half）:
  - 内核代码在 0xFFFF800000000000+
  - 用户空间在低 128TB
  - 地址空间清晰分离
  - 权限检查更简单
```

## 3. 常见陷阱

### 3.1 位模式陷阱

#### 陷阱 1: `bits` 指令不影响标签值
```asm
bits 16
gdt_start:     ; 标签值是实际地址（如 0x7E03）
    dq 0

bits 32
mov eax, gdt_start  ; EAX = 0x00007E03 (32 位值)
```

#### 陷阱 2: `bits` 影响指令编码
```asm
bits 16
mov eax, 0x1234    ; 机器码: 66 B8 34 12 00 00

bits 32
mov eax, 0x1234    ; 机器码: B8 34 12 00 00 00 00
```

**教训**: 切换 bits 时，要明确知道指令编码变化。

### 3.2 内存布局陷阱

#### 陷阱 1: 段选择子 vs 描述符索引
```asm
; 错误理解
jmp 0x00:protected_mode    ; 这是 null 描述符！

; 正确理解
jmp 0x08:protected_mode    ; 索引 1 (第二个描述符)

; 计算公式
; 段选择子 = (索引 × 8) | TI | RPL
; 0x08 = (1 × 8) | 0 | 0 = 0x08
```

#### 陷阱 2: 物理地址 vs 线性地址
```
实模式：
  物理地址 = 段 × 16 + 偏移

保护模式（开启分页前）：
  线性地址 = 段基址 + 偏移
  物理地址 = 线性地址

保护模式（开启分页后）：
  线性地址 = 段基址 + 偏移
  物理地址 = 页表翻译(线性地址)
```

**教训**: 开启分页后，必须确保页表映射了所有使用的地址。

### 3.3 数据结构陷阱

#### 陷阱 1: 小端序混淆
```asm
; GDT 描述符在内存中的布局
Base = 0x00000000

字节序（小端）：
  00 00 00 00  ...

反汇编时看到的：
  dd 0x00000000  ; 这是正确值
```

#### 陷阱 2: 结构体对齐
```asm
; 错误：手动计算偏移
mov [edi + 0], 0x10
mov [edi + 1], 0x00
mov [edi + 2], 0x01    ; 可能不对齐！

; 正确：使用结构体
struc DAP
    .size:     resb 1
    .reserved:  resb 1
    .sectors:  resw 1
    .offset:   resw 1
    .segment:  resw 1
    .lba:      resd 1
    .lba_high: resd 1
endstruc

mov ax, [edi + DAP.sectors]
```

### 3.4 控制流陷阱

#### 陷阱 1: Far jump 目标
```asm
bits 16
    mov eax, cr0
    or eax, 1
    mov cr0, eax

    ; 错误： jmp 0x08:protected_mode
    ; NASM 在 bits 16 下生成 16 位偏移

    ; 正确：手动编码 32 位偏移
    db 0x66
    db 0xEA
    dd protected_mode
    dw 0x08

bits 32
protected_mode:
    ; 这里的代码
```

#### 陷阱 2: 未刷新指令队列
```
修改 CR0.PE 位后，CPU 仍使用预取的旧指令。

必须执行 far jump 来：
  1. 刷新指令队列
  2. 加载新的 CS 段选择子

如果只修改 CR0 不执行 far jump：
  → CPU 继续执行旧模式的指令
  → 未定义行为 / Triple Fault
```

## 4. 性能优化

### 4.1 代码大小优化

#### 当前状态
```
Stage 1 (boot.bin):
  - 大小: 512 字节（完全使用）
  - 必须留空间给 partition table (0x1BE-0x1FD)

Stage 2 (boot2.bin):
  - 大小: ~500 字节（远小于 1 个扇区）
  - 有大量优化空间
```

#### 优化方向
1. **复用代码**
   ```asm
   ; 当前：重复的打印函数
   print_bios: ...
   print_pm: ...
   print_lm: ...

   ; 优化：统一打印接口
   print_string: ...
   ```

2. **使用宏**
   ```asm
   %macro PRINT 1
       mov si, %1
       call print_string
   %endmacro

   PRINT msg_stage2
   PRINT msg_protected
   ```

3. **去除冗余数据**
   ```asm
   ; 当前：多个字符串
   msg_stage2: db "Stage 2 running...", 0
   msg_protected: db "Protected Mode OK", 0
   msg_longmode: db "=== LONG MODE ACTIVE ===", 0

   ; 优化：共享字符串数据
   ```

### 4.2 启动速度优化

#### LBA vs CHS
```
LBA 扩展读取：
  - 现代 BIOS 必须支持
  - 通常更快（直接寻址）
  - 优先使用

CHS 读取：
  - 兼容性回退
  - 需要转换计算
  - 较慢

CCOS 策略：先尝试 LBA，失败后回退 CHS
```

#### 减少磁盘读取
```
当前：
  - 读取 1 个扇区（512 字节）
  - boot2.bin 只有 500 字节

优化：
  - 可以读取更小的扇区数？
  - BIOS 可能不支持
  - 保持现状即可
```

## 5. 未来改进

### 5.1 短期改进 (1-2 周)

#### 1. ELF 内核加载
```
当前：直接跳转到固定地址

改进：解析 ELF 格式
  - 支持多个代码段
  - 支持数据段分离
  - 自动加载到正确地址
```

#### 2. 内存检测
```
使用 BIOS INT 15h, EAX=0xE820
  - 检测可用内存范围
  - 构建内存映射
  - 传递给内核
```

#### 3. VBE 图形模式
```
使用 VBE (VESA BIOS Extensions)
  - 设置高分辨率图形模式
  - 绘制像素
  - 为 GUI 准备
```

### 5.2 中期改进 (1-2 月)

#### 1. APM / ACPI 电源管理
```
APM (Advanced Power Management)
  - 旧标准，但简单

ACPI (Advanced Configuration and Power Interface)
  - 现代 PC 必须支持
  - 复杂但功能强大
```

#### 2. SMBios 系统信息
```
检测：
  - CPU 型号和速度
  - 内存大小
  - 硬件信息
  - 序列号等
```

#### 3. 多处理器支持
```
MP (Multiprocessing) 表
  - 检测 CPU 数量
  - 启动 AP (Application Processors)
  - 实现 SMP 内核
```

### 5.3 长期改进 (3-6 月)

#### 1. UEFI 支持
```
传统 BIOS (Legacy)
  - CCOS 当前实现
  - 兼容性好
  - 功能受限

UEFI (Unified Extensible Firmware Interface)
  - 现代 PC 必须支持
  - 图形界面
  - GPT 分区表
  - 需要重写 bootloader
```

#### 2. 网络启动
```
PXE (Preboot Execution Environment)
  - 从网络加载
  - 支持无盘工作站
  - 企业环境有用
```

#### 3. 安全启动
```
UEFI Secure Boot
  - 验证 bootloader 签名
  - 防止 bootkit
  - 需要 Microsoft 证书
```

## 6. 经验总结

### 6.1 调试心得

#### 痱苦但必要
```
汇编调试非常困难，但必须掌握。

工具：
  - ndisasm (反汇编）
  - xxd (十六进制查看）
  - GDB (单步调试）

技巧：
  - 小步前进
  - 频期结果
  - 验证假设
```

#### 相信工具，不凭直觉
```
错误思维："我觉得应该没问题"
正确思维："用工具验证"

反汇编能揭示：
  - 指令编码错误
  - 地址计算错误
  - 数据结构错误
```

### 6.2 代码组织

#### 模块化
```
即使汇编也要模块化：

good:
  - print.inc (打印函数）
  - disk.inc (磁盘操作）
  - gdt.inc (GDT 定义）
  - pm.inc (模式切换）

bad:
  - 所有代码在一个文件
  - 难以维护和理解
```

#### 注释的重要性
```
自解释代码是幻想：
  mov eax, cr0        ; 读取 CR0
  or eax, 1          ; 设置 PE 位
  mov cr0, eax        ; 写入 CR0

好的注释说明"为什么"，而非"是什么"：
  ; 必须使用 far jump 刷新指令队列
  jmp 0x08:protected_mode
```

### 6.3 测试策略

#### 持续集成
```
每次修改后：
  1. make clean && make
  2. 检查文件大小
  3. 反汇编验证
  4. 运行测试
  5. 失败则调试

自动化：
  - 编写测试脚本
  - 自动化检查清单
  - 持续监控
```

#### 边界条件
```
测试极限情况：
  - 最小内存配置
  - 最大磁盘容量
  - 多种 BIOS 版本
  - 虚拟机 + 真实硬件
```

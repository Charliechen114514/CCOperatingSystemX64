# CCOS Bootloader 故障排查指南

本文档记录了 bootloader 开发过程中遇到的实际问题及解决方案。

---

## 1. 磁盘读取错误（错误代码 0C）

### 症状
```
DISK ERROR! Cannot read Stage 2
0C
```

### 根本原因
**问题**: BIOS INT 13h 读取失败，错误代码 AH=0C

**分析过程**:
1. 检查 boot2.bin 大小：仅 500 字节（<1 个扇区）
2. 检查 boot.asm：尝试读取 16 个扇区（`mov al, 0x10`）
3. 检查 boot.img 总大小：1012 字节（只有 2 个扇区）

**结论**: 尝试读取超出磁盘镜像大小的扇区导致错误。

### 解决方案

#### 修复 1: 减少 LBA 读取扇区数
```asm
; 修复前
mov word [edi + 2], 0x10    ; 读取 16 个扇区

; 修复后
mov word [edi + 2], 0x01    ; 读取 1 个扇区
```

#### 修复 2: 减少 CHS 读取扇区数
```asm
; 修复前
mov al, 0x10            ; 读取 16 个扇区

; 修复后
mov al, 0x01            ; 读取 1 个扇区
```

### 关键要点
- **总是验证读取的数据大小不超过磁盘容量**
- **boot2.bin 大小 = 500 字节，只需 1 个扇区**
- **错误代码 0C** = "Invalid media" 通常表示读取超出范围

## 2. DAP 结构错误（LBA 扩展读取）

### 症状
即使减少扇区数，LBA 读取仍然失败。

### 根本原因
**问题**: Disk Address Packet (DAP) 结构中 offset 和 segment 位置颠倒

**DAP 正确格式**:
```
Offset  Size    Description
0       1 byte   Packet size (0x10)
1       1 byte   Reserved
2       2 bytes  Number of sectors to transfer
4       2 bytes  Buffer offset (NOT segment!)
6       2 bytes  Buffer segment
8       4 bytes  Starting LBA (low 32 bits)
12      4 bytes  Starting LBA (high 32 bits)
```

**错误代码**:
```asm
mov word [edi + 4], 0x7E0   ; 错误！这是 offset 位置
mov word [edi + 6], 0x0000  ; 错误！这是 segment 位置
```

**正确代码**:
```asm
mov word [edi + 4], 0x0000  ; Buffer offset = 0x0000
mov word [edi + 6], 0x7E0   ; Buffer segment = 0x7E0
```

### 解决方案
```asm
; Extended read supported, use LBA
pusha
mov edi, 0x5000        ; DAP address

mov byte [edi + 0], 0x10    ; packet size = 16
mov byte [edi + 1], 0x00    ; reserved
mov word [edi + 2], 0x01    ; read 1 sector
mov word [edi + 4], 0x0000  ; buffer offset
mov word [edi + 6], 0x7E0   ; buffer segment → 0x7E00
mov dword [edi + 8], 0x00000001  ; LBA = 1
mov dword [edi + 12], 0x00000000

mov si, di
mov ah, 0x42            ; extended read
int 0x13

popa
```

### 关键要点
- **DAP 偏移 4** = buffer **offset**，不是 segment
- **DAP 偏移 6** = buffer **segment**
- **组合地址**: segment × 16 + offset = 物理地址
  - 0x7E0 × 16 + 0x0000 = 0x7E00 ✅

## 3. 保护模式 Triple Fault（系统重启）

### 症状
```
Stage 2 running...
[1] GDT loaded, PM enabled...
[系统无限重启]
```

### 根本原因
**问题 1**: GDT base 地址在 `bits 16` 下计算错误
**问题 2**: Far jump 指令编码错误（16 位 vs 32 位偏移）

### 分析过程

#### 步骤 1: 使用 GDB 调试
```bash
# 启动 QEMU with GDB server
qemu-system-x86_64 -drive format=raw,file=boot.img,if=floppy -nographic -s -S

# 连接 GDB
gdb
(gdb) target remote localhost:1234
(gdb) set architecture i8086
(gdb) si 100  # 单步执行 100 条指令
```

#### 步骤 2: 反汇编检查
```bash
# 反汇编 boot2.bin
ndisasm -b 16 boot2.bin | head -80

# 查找 far jump 指令
xxd boot2.bin | grep "66 ea"
```

发现的问题：
```
00000067  66EA7A7E0800    jmp word 0x8:word 0x7e7a
```

这是 **16 位** far jump（`jmp word`），但我们需要 **32 位** 偏移！

### 解决方案

#### 修复 1: GDT base 地址

**错误代码**:
```asm
gdt_ptr:
    dw gdt_end - gdt_start - 1
    dd 0x7E00 + gdt_start  ; 在 bits 16 下计算错误！
```

**正确代码**:
```asm
gdt_ptr:
    dw 5 * 8 - 1        ; 5 descriptors × 8 bytes = 40, limit = 39
    dd 0x00007E03      ; 直接硬编码 GDT base 地址
```

**验证**:
```bash
xxd boot2.bin | grep "27 00"
00000020: 9aaf 00ff ff00 0000 92cf 0027 0003 fc00
#                                            27 00 03 00
#                                            limit  base
```

#### 修复 2: Far jump 指令编码

**错误尝试 1**: 使用 `jmp dword`
```asm
jmp dword 0x08:protected_mode
```
问题: 在 `bits 16` 下仍生成 16 位偏移。

**错误尝试 2**: 使用 `dw` 手动编码
```asm
db 0xEA             ; jmp far opcode
dw pm_entry         ; 只生成 2 字节！
dw 0x08
```
结果: `66 EA 7B 7E 08 00 60 AC` - CPU 读取了额外字节。

**正确方案**: 使用 `dd` 生成 32 位偏移
```asm
db 0x66             ; operand-size prefix (32-bit offset)
db 0xEA             ; jmp far opcode
dd pm_entry         ; 32-bit offset
dw 0x08             ; 16-bit segment selector
```

**验证**:
```bash
xxd boot2.bin | grep "66 ea"
00000060: 6683 c801 0f22 c066 ea7d 7e00 0008 0060
#                                 66 ea 7d 7e 00 00 08 00
#                                 prefix op  offset(32-bit) segment
```

### 关键要点
- **`bits 16` 下**: `jmp far` 默认是 `ptr16:16`（16 位偏移）
- **使用 `0x66` 前缀**: 强制 CPU 使用 32 位偏移（`ptr16:32`）
- **GDT base 必须正确**: LGDT 使用这个值，错误会导致 Triple Fault
- **使用 `dd` 而非 `dw`**: 确保生成 32 位偏移量

## 4. 调试技巧总结

### 工具使用

#### 1. 反汇编
```bash
# 反汇编 MBR (512 bytes)
ndisasm -b 16 boot.bin

# 反汇编 Stage 2
ndisasm -b 16 boot2.bin | head -100

# 查找特定指令
ndisasm -b 16 boot2.bin | grep "EA"
```

#### 2. 十六进制查看
```bash
# 查看文件内容
xxd boot2.bin | head -20

# 查找特定字节
xxd boot2.bin | grep "66 ea"

# 查看特定偏移
xxd boot2.bin | sed -n '3,5p'
```

#### 3. 检查文件大小
```bash
ls -lh boot.bin boot2.bin boot.img

# 计算扇区数
wc -c boot2.bin  # 字节数
# 除以 512 得到扇区数
```

#### 4. GDB 调试
```bash
# 启动 QEMU with GDB server
qemu-system-x86_64 -drive format=raw,file=boot.img,if=floppy -nographic -s -S

# 在另一个终端连接 GDB
gdb
(gdb) target remote localhost:1234
(gdb) set architecture i8086  # 实模式
(gdb) x/10i $pc             # 查看指令
(gdb) si                      # 单步执行
(gdb) info registers          # 查看寄存器
```

#### 5. QEMU 运行
```bash
# 文本模式（无 VGA）
qemu-system-x86_64 -drive format=raw,file=boot.img,if=floppy -nographic

# 图形模式（VNC）
qemu-system-x86_64 -drive format=raw,file=boot.img,if=floppy
# VNC server on ::1:5900

# 使用 timeout 防止无限运行
timeout 5 qemu-system-x86_64 -drive format=raw,file=boot.img,if=floppy -nographic
```

### 调试流程

#### 遇到 Triple Fault（系统重启）
1. **检查 GDT**: 使用 `xxd` 查看 GDT base 和 limit
2. **反汇编**: 使用 `ndisasm` 检查 far jump 指令编码
3. **简化代码**: 移除所有额外代码，只保留模式切换
4. **单步调试**: 使用 GDB 单步执行到出错的指令

#### 遇到磁盘读取错误
1. **检查文件大小**: `ls -lh boot2.bin`
2. **检查读取扇区数**: 搜索 `mov al,` 查看读取数量
3. **检查 DAP 结构**: 验证 offset/segment 位置
4. **验证 LBA 值**: 确保从扇区 1 开始（0-based LBA = 1）

## 5. 常见错误代码

### BIOS INT 13h 错误代码
```
AH = 0Ch  Invalid media / General failure
AH = 01h  Invalid command
AH = 04h  Sector not found
AH = 09h  Data boundary error
```

### 保护模式异常
```
Triple Fault  → GDT 错误 / far jump 错误 / 页表错误
General Protection Fault → 段选择子错误 / 内存访问错误
Page Fault    → 页表缺失 / 权限错误
```

## 6. 检查清单

### Bootloader 开发检查清单
- [ ] MBR 签名 0xAA55 在文件末尾
- [ ] Stage 1 正确加载 Stage 2 到 0x7E00
- [ ] 读取扇区数与 boot2.bin 大小匹配
- [ ] DAP 结构 offset/segment 位置正确
- [ ] GDT limit = (描述符数量 × 8) - 1
- [ ] GDT base 地址正确（使用 `xxd` 验证）
- [ ] Far jump 使用 32 位偏移（带 0x66 前缀）
- [ ] 页表设置正确（PML4/PDPT/PD）
- [ ] CR4.PAE = 1, CR0.PG = 1, EFER.LME = 1

### 调试前检查
- [ ] 使用 `make clean && make` 重新编译
- [ ] 检查 boot.img 大小合理
- [ ] 使用 `ndisasm` 反汇编验证指令
- [ ] 使用 `xxd` 检查关键数据结构

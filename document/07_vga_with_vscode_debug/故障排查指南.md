# VGA 图形界面与 VSCode 调试 - 故障排查指南

本文档提供常见问题的诊断和解决方案。

---

## 1. VGA 显示问题

### 1.1 屏幕完全黑屏

**症状**: QEMU 启动后 VGA 窗口全黑

**可能原因**:

| 原因 | 检查方法 | 解决方案 |
|------|----------|----------|
| VGA 未初始化 | 检查是否调用了 `system_vga_init()` | 在 `kernel_init()` 开头添加初始化调用 |
| 缓冲区地址错误 | `print vga_instance()->base_addr` | 确保为 `0xB8000` |
| 未使用 VNC | 检查 QEMU 命令行 | 添加 `-display vnc=:0` 并用 vncviewer 连接 |
| 内核未执行 | 检查是否有断点触发 | 在 `kernel_start` 设置断点 |

**调试步骤**:
```gdb
# 1. 检查 VGA 是否初始化
(gdb) break system_vga_init
(gdb) continue
# 如果未触发，检查调用链

# 2. 检查缓冲区地址
(gdb) print/x vga_instance()->base_addr
# 应该是 0xb8000

# 3. 尝试直接写内存
(gdb) set *(uint16_t*)0xb8000 = 0x1f41
# 应该显示白字蓝底的 'A'
```

### 1.2 显示字符颜色错误

**症状**: 字符显示但颜色不正确

**可能原因**:
1. 颜色参数顺序错误（前景/背景颠倒）
2. 颜色编码计算错误
3. 颜色值超出范围

**检查方法**:
```c
// 确保正确的编码格式
// VGA: 背景 << 4 | 前景
uint8_t attr = (bg << 4) | font;
uint16_t entry = c | (attr << 8);  // 字节顺序正确

// 常见错误
uint8_t attr = (font << 4) | bg;  // 错误！
```

**调试代码**:
```c
// 测试颜色
vga_put_char_at(vga, 0, 0, 'A', VGA_COLOR_WHITE, VGA_COLOR_BLACK);   // 白字黑底
vga_put_char_at(vga, 1, 0, 'B', VGA_COLOR_BLACK, VGA_COLOR_WHITE);   // 黑字白底
vga_put_char_at(vga, 2, 0, 'C', VGA_COLOR_RED, VGA_COLOR_BLACK);     // 红字黑底
vga_put_char_at(vga, 3, 0, 'D', VGA_COLOR_BRIGHT_GREEN, VGA_COLOR_BLACK); // 亮绿字黑底
```

### 1.3 文本位置错误

**症状**: 字符显示在错误的位置

**可能原因**:
1. 坐标计算错误
2. 宽度/高度参数错误
3. 边界检查不正确

**调试方法**:
```c
// 绘制测试边框
for (int i = 0; i < 80; i++) {
    vga_put_char_at(vga, i, 0, '0' + (i % 10), VGA_COLOR_WHITE, VGA_COLOR_BLACK);
}
// 第一行应该显示 01234567890123456789...

for (int i = 0; i < 25; i++) {
    vga_put_char_at(vga, 0, i, 'A' + (i % 26), VGA_COLOR_WHITE, VGA_COLOR_BLACK);
}
// 第一列应该显示 ABCDEFGHIJKLMNOPQRSTUVWXYZ
```

### 1.4 动画无效果

**症状**: 动画代码执行但屏幕不变化

**可能原因**:
1. 延迟时间太短
2. VNC 刷新延迟
3. 绘制在同一位置

**解决方法**:
```c
// 1. 增加延迟时间
vga_delay(10000000);  // 从 1M 增加到 10M

// 2. 强制刷新（VGA 自动刷新，但 VNC 可能有延迟）
// 多次绘制同一位置
for (int i = 0; i < 3; i++) {
    vga_put_char_at(vga, x, y, c, color, bg);
    vga_delay(1000000);
}

// 3. 确保位置变化
static vga_sz_t offset = 0;
vga_put_char_at(vga, 10 + offset, 10, 'X', 15, 0);
offset = (offset + 1) % 20;
```

## 2. VSCode 调试连接问题

### 2.1 "Connection refused" 错误

**症状**: VSCode 显示无法连接到 localhost:1234

**诊断流程**:

```bash
# 1. 检查 QEMU 是否运行
./scripts/launch_qemu_for_vscode_debug.sh --status

# 2. 检查端口 1234
lsof -i:1234
# 或
netstat -tuln | grep 1234

# 3. 检查防火墙
sudo ufw status
```

**解决方案**:

| 情况 | 解决方法 |
|------|----------|
| QEMU 未运行 | 运行启动脚本 |
| 端口被其他程序占用 | 杀死占用进程或更改端口 |
| 防火墙阻止 | 允许本地端口连接 |

### 2.2 GDB 连接后立即断开

**症状**: 连接建立但立即断开

**可能原因**:
1. 符号文件不匹配
2. QEMU 崩溃
3. 脚本误判连接状态

**调试步骤**:

```bash
# 1. 检查 QEMU 日志
# 修改启动脚本，移除 > /dev/null 2>&1
qemu-system-x86_64 ... 2>&1 | tee qemu.log

# 2. 检查符号文件
file build/kernel.elf
# 应该显示 "ELF 64-bit LSB executable"

# 3. 手动测试 GDB
gdb build/kernel.elf
(gdb) target remote :1234
(gdb) break kernel_main
(gdb) continue
```

### 2.3 断点不触发

**症状**: 设置断点后程序不停止

**可能原因**:
1. 断点位置错误
2. 代码被优化掉
3. 符号信息不完整

**解决方法**:

```gdb
# 1. 确认符号加载
(gdb) info breakpoints
(gdb) info files

# 2. 使用函数名而非行号
(gdb) break kernel_main
(gdb) break kernel_init

# 3. 检查优化选项
# 确保使用 -O0 或 -Og
cmake -DCMAKE_BUILD_TYPE=Debug -B build
```

### 2.4 单步执行跳过代码

**症状**: step 命令跳过整个函数

**说明**: 这是 `step` 的正常行为，使用 `stepi` 或 `next` 代替

```gdb
# step: 执行下一行（跳过函数调用）
(gdb) step

# stepi: 执行一条指令
(gdb) stepi

# next: 执行下一行（不进入函数）
(gdb) next

# 进入函数
(gdb) step
# 或
(gdb) return  # 跳出当前函数
```

## 3. 构建问题

### 3.1 符号文件未生成

**症状**: `build/kernel.elf` 不存在或无符号信息

**检查方法**:

```bash
# 检查文件是否存在
ls -la build/kernel.elf

# 检查符号信息
file build/kernel.elf
nm build/kernel.elf | head -20

# 检查 CMake 配置
grep CMAKE_BUILD_TYPE build/CMakeCache.txt
```

**解决方案**:

```bash
# 确保 Debug 构建
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build

# 检查 kernel.elf 是否被 objcopy 删除
# 确保 CMakeLists.txt 中保留 ELF 文件
```

### 3.2 链接错误

**症状**: undefined reference 错误

**常见错误**:

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `undefined reference to vga_put_char_at` | 未链接 vga_helpers.c | 检查 CMakeLists.txt |
| `undefined reference to kernel_init` | 声明但未定义 | 添加 kernel_init.c |
| `multiple definition` | 重复定义 | 检查头文件保护 |

**调试步骤**:

```bash
# 查看链接命令
cmake --build build --verbose | grep kernel.elf

# 检查目标文件
nm build/kernel/kernel_main.o
nm build/kernel/driver/vga/vga_helpers.o

# 检查符号冲突
nm build/kernel.elf | grep vga_put_char_at
```

## 4. 进程管理问题

### 4.1 QEMU 进程泄漏

**症状**: 多个 QEMU 进程在运行

**诊断**:

```bash
# 查找所有 QEMU 进程
ps aux | grep qemu-system

# 查找监听 1234 端口的进程
lsof -i:1234
```

**解决方法**:

```bash
# 使用脚本清理
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 手动杀死
killall qemu-system-x86_64

# 强制杀死
killall -9 qemu-system-x86_64
```

### 4.2 PID 文件残留

**症状**: 启动脚本报告 QEMU 已运行但实际未运行

**解决方法**:

```bash
# 删除 PID 文件
rm -f scripts/.qemu_debug.pid

# 重新启动
./scripts/launch_qemu_for_vscode_debug.sh
```

## 5. 性能问题

### 5.1 启动时间过长

**症状**: 启动界面显示时间过长

**可能原因**:
1. 延迟循环计数过大
2. 动画循环次数过多
3. VNC 刷新延迟

**优化方法**:

```c
// 减少延迟
// vga_delay(50000000);  // 太长
vga_delay(5000000);      // 减少 10 倍

// 减少动画循环
// for (int cycle = 0; cycle < 10; cycle++)  // 太多
for (int cycle = 0; cycle < 3; cycle++)    // 适中

// 跳过动画（可选）
#ifdef SKIP_ANIMATION
    // 直接显示最终状态
#else
    // 显示动画
#endif
```

### 5.2 VNC 刷新慢

**症状**: 动画卡顿

**解决方法**:

1. 使用 SDL 后端代替 VNC:
```bash
qemu-system-x86_64 -vga std -display sdl
```

2. 减少 VNC 编码复杂度:
```bash
vncviewer -Encodings "raw" localhost:5900
```

## 6. 开发环境问题

### 6.1 VSCode 不识别断点

**症状**: 在编辑器中设置断点显示为灰色/未验证

**可能原因**:
1. `launch.json` 配置错误
2. `program` 路径错误
3. 未生成 `compile_commands.json`

**解决方法**:

```json
// 确保 program 路径正确
"program": "${workspaceFolder}/build/kernel.elf"

// 确保 CMake 导出 compile_commands.json
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -B build
```

### 6.2 IntelliSense 不工作

**症状**: 代码无补全，显示"无法包含文件"

**解决方法**:

1. 确保 `compile_commands.json` 存在:
```bash
ls -la build/compile_commands.json
```

2. 配置 `.vscode/c_cpp_properties.json`:
```json
{
    "configurations": [
        {
            "name": "CCOS",
            "includePath": [
                "${workspaceFolder}/**",
                "${workspaceFolder}/kernel/include"
            ],
            "compilerPath": "/usr/bin/gcc",
            "compileCommands": "${workspaceFolder}/build/compile_commands.json"
        }
    ]
}
```

## 7. 问题诊断清单

遇到问题时，按顺序检查：

- [ ] QEMU 是否在运行？
- [ ] 端口 1234 是否被监听？
- [ ] `kernel.elf` 是否存在且有符号？
- [ ] `launch.json` 配置是否正确？
- [ ] VGA 是否已初始化？
- [ ] 是否有断点触发？
- [ ] 控制台是否有错误信息？

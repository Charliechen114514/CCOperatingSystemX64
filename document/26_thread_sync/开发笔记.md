## 为什么需要同步原语

### 1.1 并发带来的问题

Stage 25 实现了文件系统，但操作系统仍然缺乏基本的并发控制机制。当多个进程/线程同时访问共享资源时，会出现以下问题：

#### 竞态条件 (Race Condition)

```c
// 全局计数器
int counter = 0;

// 两个进程同时执行
void increment(void) {
    int temp = counter;    // 读
    temp = temp + 1;       // 改
    counter = temp;        // 写  // 可能丢失更新!
}
```

#### 数据不一致

```c
// 链表插入
void insert(node* new_node) {
    new_node->next = head->next;  // A
    head->next = new_node;        // B
    // 如果在 A 和 B 之间发生切换，链表会损坏
}
```

### 1.2 同步原语的作用

同步原语解决上述问题：

| 问题 | 解决方案 | 原语 |
|------|---------|------|
| 竞态条件 | 互斥访问 | spinlock, mutex |
| 资源计数 | 信号量机制 | semaphore |
| 条件等待 | 条件通知 | condvar |
| 读多写少 | 读写分离 | rwlock |
| 简单计数 | 无锁操作 | atomic |

### 1.3 为什么需要多种原语

不同场景需要不同的同步机制：

- **短临界区**：spinlock（忙等待快）
- **长临界区**：mutex（可睡眠，不浪费 CPU）
- **资源管理**：semaphore（天生支持计数）
- **事件通知**：condvar（标准条件变量模式）
- **数据结构**：rwlock（读者并发）
- **计数器**：atomic（无锁，最快）

### 1.4 从进程到线程

Stage 21 实现了进程管理，但真正的线程支持需要：

1. **共享地址空间**：线程共享同一内存
2. **独立的执行流**：每个线程有自己的栈和寄存器
3. **同步机制**：线程间通信需要同步原语
4. **轻量级创建**：线程创建比进程快

## 同步设计基础

### 2.1 基本概念

#### 临界区

访问共享资源的代码段，必须互斥执行：

```c
// 临界区
lock(&mutex);
// 访问共享资源
shared_resource++;
unlock(&mutex);
```

#### 互斥

同一时刻只有一个线程执行：

```c
mutex_t m;
mutex_init(&m);

// 线程 1
mutex_lock(&m);
// 临界区
mutex_unlock(&m);

// 线程 2 必须等待
```

#### 死锁

两个或多个线程互相等待：

```
线程 1: 持有 A，等待 B
线程 2: 持有 B，等待 A
→ 死锁！
```

### 2.2 同步原语分类

#### 忙等待 vs 可睡眠

| 特性 | 忙等待 (spinlock) | 可睡眠 (mutex) |
|------|-------------------|----------------|
| 等待方式 | 循环检测 | 阻塞调度 |
| CPU 使用 | 高 | 低 |
| 适用场景 | 短临界区 | 长临界区 |
| 中断处理 | 可以 | 不可以 |

#### 互斥 vs 同步

| 原语 | 主要用途 | 示例 |
|------|---------|------|
| mutex | 互斥访问 | 保护链表 |
| semaphore | 资源计数 | 连接池 |
| condvar | 条件等待 | 生产者-消费者 |

### 2.3 经典同步问题

#### 生产者-消费者

```c
semaphore_t empty;  // 空槽位
semaphore_t full;   // 满槽位
mutex_t mutex;

// 生产者
sem_wait(&empty);
mutex_lock(&mutex);
queue.push(item);
mutex_unlock(&mutex);
sem_post(&full);

// 消费者
sem_wait(&full);
mutex_lock(&mutex);
item = queue.pop();
mutex_unlock(&mutex);
sem_post(&empty);
```

#### 读者-写者

```c
rwlock_t rwlock;

// 读者
rwlock_read_lock(&rwlock);
read_data();
rwlock_read_unlock(&rwlock);

// 写者
rwlock_write_lock(&rwlock);
write_data();
rwlock_write_unlock(&rwlock);
```

## 设计决策

### 3.1 自旋锁实现

#### 决策：使用 GCC 内置原子操作

```c
static inline void spin_lock(spinlock_t* lock) {
    while (__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE)) {
        __asm__ volatile("pause");  // 减少 CPU 消耗
    }
}
```

**理由**：
- **正确性**：编译器保证原子性
- **可移植性**：标准 C，不依赖汇编
- **性能**：现代 CPU 优化良好

**替代方案**：
- **汇编实现**：更直接，但不可移植
- **库函数**：依赖外部库

#### 决策：提供中断安全版本

```c
unsigned long flags;
spin_lock_irqsave(&lock, &flags);
critical_section();
spin_unlock_irqrestore(&lock, &flags);
```

**理由**：
- **中断处理**：中断处理程序可能也需要锁
- **防止死锁**：保存中断状态，避免死锁

### 3.2 互斥锁设计

#### 决策：支持递归锁

```c
void mutex_lock(mutex_t* mutex) {
    if (mutex->owner == current) {
        mutex->count++;  // 递归
        return;
    }
    // ...
}
```

**理由**：
- **灵活性**：允许同一个线程多次获取锁
- **安全性**：防止同一线程死锁

**代价**：
- 额外的 owner 检查
- 轻微性能开销

#### 决策：快速路径优化

```c
void mutex_lock(mutex_t* mutex) {
    // 快速路径：无竞争
    if (atomic_compare_and_exchange(&mutex->locked, 0, 1) == 0) {
        mutex->owner = current;
        return;
    }
    // 慢速路径：可能有竞争
    mutex_lock_slow(mutex);
}
```

**理由**：
- **性能**：无竞争时只需一条原子指令
- **可扩展性**：复杂逻辑在慢速路径

### 3.3 信号量设计

#### 决策：使用计数信号量

```c
typedef struct {
    atomic_t count;
    spinlock_t lock;
    list_head wait_list;
} semaphore_t;
```

**理由**：
- **通用性**：二值信号量只是计数=1 的特例
- **资源管理**：天然支持多资源

### 3.4 条件变量设计

#### 决策：必须与 mutex 配合

```c
void condvar_wait(condvar_t* cond, mutex_t* mutex) {
    // 1. 释放 mutex
    // 2. 阻塞当前线程
    // 3. 被唤醒后重新获取 mutex
}
```

**理由**：
- **标准语义**：POSIX 标准规定
- **正确性**：防止信号丢失

### 3.5 读写锁设计

#### 决策：读者优先

```c
void rwlock_read_lock(rwlock_t* lock) {
    // 只要有读者，写者就等待
    atomic_inc(&lock->readers);
}

void rwlock_write_lock(rwlock_t* lock) {
    // 等待所有读者完成
    while (atomic_read(&lock->readers) > 0) {
        schedule();
    }
}
```

**理由**：
- **简单性**：实现直观
- **读多场景**：适合大多数应用

**缺点**：
- **写者饥饿**：读者持续到达时，写者可能饿死

**替代方案**：
- **写者优先**：公平性好，但复杂
- **公平读写锁**：使用队列，但开销大

### 3.6 原子操作

#### 决策：使用 GCC 内置函数

```c
atomic_inc(&v);           // ++v
atomic_add(&v, 10);       // v += 10
atomic_compare_and_exchange(&v, &old, new);  // CAS
```

**理由**：
- **无锁**：不使用锁，避免死锁
- **性能**：单条指令，极快
- **可组合**：可构建复杂无锁结构

## 实现细节

### 5.1 自旋锁实现

```c
// 初始化
static inline void spin_init(spinlock_t* lock) {
    lock->locked = 0;
}

// 获取锁
static inline void spin_lock(spinlock_t* lock) {
    while (__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE)) {
        // pause 指令减少 CPU 功耗
        __asm__ volatile("pause");
    }
}

// 尝试获取锁
static inline bool spin_trylock(spinlock_t* lock) {
    return !__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE);
}

// 释放锁
static inline void spin_unlock(spinlock_t* lock) {
    __atomic_clear(&lock->locked, __ATOMIC_RELEASE);
}

// 中断安全版本
static inline void spin_lock_irqsave(spinlock_t* lock,
                                      unsigned long* flags) {
    *flags = irq_save();
    spin_lock(lock);
}

static inline void spin_unlock_irqrestore(spinlock_t* lock,
                                          unsigned long flags) {
    spin_unlock(lock);
    irq_restore(flags);
}
```

### 5.2 互斥锁实现

```c
void mutex_lock(mutex_t* mutex) {
    pcb_t* current = proc_current();

    // 快速路径：无竞争
    if (atomic_compare_and_exchange(&mutex->locked, 0, 1) == 0) {
        mutex->owner = current;
        mutex->count = 1;
        return;
    }

    // 慢速路径
    spin_lock(&mutex->wait_lock);

    // 检查递归
    if (mutex->owner == current) {
        mutex->count++;
        spin_unlock(&mutex->wait_lock);
        return;
    }

    // 添加到等待队列
    list_add_tail(&current->wait_list, &mutex->wait_list);

    // 阻塞当前进程
    current->state = PROC_BLOCKED;
    spin_unlock(&mutex->wait_lock);
    schedule();

    // 被唤醒后重新获取锁
}

void mutex_unlock(mutex_t* mutex) {
    pcb_t* current = proc_current();

    // 递归释放
    if (mutex->owner == current && mutex->count > 1) {
        mutex->count--;
        return;
    }

    spin_lock(&mutex->wait_lock);

    // 清除所有者
    mutex->owner = NULL;
    mutex->count = 0;

    // 唤醒一个等待者
    if (!list_empty(&mutex->wait_list)) {
        pcb_t* waiter = list_first_entry(&mutex->wait_list,
                                          pcb_t, wait_list);
        list_del(&waiter->wait_list);
        waiter->state = PROC_READY;
        schedule_add(waiter);
    } else {
        atomic_set(&mutex->locked, 0);
    }

    spin_unlock(&mutex->wait_lock);
}
```

### 5.3 信号量实现

```c
void sem_wait(semaphore_t* sem) {
    // 快速路径：有资源
    if (atomic_sub_if_positive(&sem->count, 1) >= 0) {
        return;
    }

    // 慢速路径：等待
    spin_lock(&sem->lock);

    // 双重检查
    while (atomic_read(&sem->count) <= 0) {
        pcb_t* current = proc_current();
        list_add_tail(&current->wait_list, &sem->wait_list);
        current->state = PROC_BLOCKED;
        spin_unlock(&sem->lock);
        schedule();
        spin_lock(&sem->lock);
    }

    atomic_dec(&sem->count);
    spin_unlock(&sem->lock);
}

void sem_post(semaphore_t* sem) {
    spin_lock(&sem->lock);

    atomic_inc(&sem->count);

    // 唤醒一个等待者
    if (!list_empty(&sem->wait_list)) {
        pcb_t* waiter = list_first_entry(&sem->wait_list,
                                          pcb_t, wait_list);
        list_del(&waiter->wait_list);
        waiter->state = PROC_READY;
        schedule_add(waiter);
    }

    spin_unlock(&sem->lock);
}
```

### 5.4 条件变量实现

```c
void condvar_wait(condvar_t* cond, mutex_t* mutex) {
    spin_lock(&cond->lock);

    // 添加到等待列表
    wait_queue_entry_t entry;
    entry.task = proc_current();
    entry.exclusive = false;
    list_add_tail(&entry.list, &cond->waiters);

    // 释放 mutex（原子操作）
    mutex_unlock(mutex);

    // 阻塞
    entry.task->state = PROC_BLOCKED;
    spin_unlock(&cond->lock);
    schedule();

    // 被唤醒后重新获取 mutex
    mutex_lock(mutex);
}

void condvar_signal(condvar_t* cond) {
    spin_lock(&cond->lock);

    // 唤醒一个等待者
    if (!list_empty(&cond->waiters)) {
        wait_queue_entry_t* entry = list_first_entry(
            &cond->waiters, wait_queue_entry_t, list);
        list_del(&entry->list);
        entry->task->state = PROC_READY;
        schedule_add(entry->task);
    }

    spin_unlock(&cond->lock);
}

void condvar_broadcast(condvar_t* cond) {
    spin_lock(&cond->lock);

    // 唤醒所有等待者
    wait_queue_entry_t* entry, *tmp;
    list_for_each_entry_safe(entry, tmp, &cond->waiters, list) {
        list_del(&entry->list);
        entry->task->state = PROC_READY;
        schedule_add(entry->task);
    }

    spin_unlock(&cond->lock);
}
```

### 5.5 线程创建

#### 内核线程

```c
pcb_t* proc_create_kernel_thread(thread_entry_t entry, void* arg) {
    // 1. 分配 PCB
    pcb_t* thread = kmalloc(sizeof(pcb_t));

    // 2. 设置线程标识
    thread->tgid = proc_current()->tgid;  // 继承线程组
    thread->is_thread = true;

    // 3. 分配内核栈（不创建用户栈）
    thread->kernel_stack = alloc_kernel_stack();

    // 4. 设置入口点
    thread->thread_entry = entry;
    thread->thread_arg = arg;

    // 5. 共享地址空间
    thread->mm = proc_current()->mm;

    // 6. 添加到线程组
    list_add(&thread->thread_group, &proc_current()->thread_group);

    // 7. 添加到运行队列
    schedule_add(thread);

    return thread;
}
```

#### 用户线程

```c
pcb_t* proc_create_user_thread(virtual_addr_t entry,
                                 virtual_addr_t stack,
                                 void* arg) {
    pcb_t* parent = proc_current();
    pcb_t* thread = kmalloc(sizeof(pcb_t));

    // 线程标识
    thread->tgid = parent->tgid;
    thread->is_thread = true;

    // 共享地址空间
    thread->mm = parent->mm;

    // 设置用户栈
    if (stack == 0) {
        thread->user_stack = alloc_user_stack(DEFAULT_STACK_SIZE);
        thread->user_stack_size = DEFAULT_STACK_SIZE;
    } else {
        thread->user_stack = stack;
        thread->user_stack_size = 0;
    }

    // 设置入口点
    thread->thread_entry = (thread_entry_t)entry;
    thread->thread_arg = arg;

    // 设置 trap_frame
    thread->trap_frame = setup_thread_trap_frame(entry, stack, arg);

    return thread;
}
```

### 5.6 线程 Join

```c
int proc_thread_join(int32_t pid, void** retval) {
    pcb_t* current = proc_current();
    pcb_t* thread = find_thread_by_pid(current->tgid, pid);

    // 检查是否为同一线程组
    if (thread->tgid != current->tgid) {
        return -EINVAL;
    }

    // 检查是否为分离线程
    if (thread->detached) {
        return -EINVAL;
    }

    // 等待线程退出
    spin_lock(&thread->state_lock);
    while (thread->state != PROC_ZOMBIE) {
        // 添加到 join 等待列表
        list_add(&current->join_list, &thread->join_waiters);
        current->state = PROC_BLOCKED;
        spin_unlock(&thread->state_lock);
        schedule();
        spin_lock(&thread->state_lock);
    }

    // 收集返回值
    if (retval) {
        *retval = thread->return_value;
    }

    // 清理线程
    reap_thread(thread);

    spin_unlock(&thread->state_lock);
    return 0;
}
```

## 常见陷阱与注意事项

### 6.1 死锁

#### 问题：循环等待

```c
// 线程 1
mutex_lock(&a);
mutex_lock(&b);

// 线程 2
mutex_lock(&b);
mutex_lock(&a);  // 死锁!
```

**预防**：
- **固定顺序**：总是按相同顺序获取锁
- **尝试锁**：使用 trylock，失败时释放已持有的锁
- **超时**：使用带超时的锁

```c
// 正确：固定顺序
mutex_lock(&a);
mutex_lock(&b);
// ...
mutex_unlock(&b);
mutex_unlock(&a);
```

### 6.2 优先级反转

**问题**：高优先级线程等待低优先级线程持有的锁

```
高优先级线程 → 等待锁 → 低优先级线程持有锁
                         ↑
                    被中优先级线程抢占
```

**解决方案**：
- **优先级继承**：锁持有者继承等待者的优先级
- **优先级天花板**：立即提升锁持有者的优先级

### 6.3 忘记释放锁

```c
void function(void) {
    mutex_lock(&lock);
    if (error_condition) {
        return;  // 忘记解锁!
    }
    mutex_unlock(&lock);
}
```

**预防**：
- **RAII**：使用自动释放机制
- **代码审查**：仔细检查所有路径
- **工具**：使用静态分析工具

### 6.4 锁的粒度

**太大**：性能差，并发度低

```c
mutex_lock(&big_lock);
// 整个链表操作都被锁住
list_operation();
mutex_unlock(&big_lock);
```

**太小**：复杂度高，容易出错

```c
mutex_lock(&node1_lock);
node1->value++;
mutex_unlock(&node1_lock);
mutex_lock(&node2_lock);
node2->value++;
mutex_unlock(&node2_lock);
// 可能不一致!
```

**平衡**：根据实际情况选择

### 6.5 信号丢失（条件变量）

```c
// 线程 1
mutex_lock(&mutex);
while (!condition) {
    condvar_wait(&cond, &mutex);
}

// 线程 2（在 wait 之前执行）
mutex_lock(&mutex);
condition = true;
condvar_signal(&cond);
mutex_unlock(&mutex);
// 信号丢失!
```

**预防**：总是使用 while 循环检查条件

```c
while (!condition) {  // 正确
    condvar_wait(&cond, &mutex);
}
```

### 6.6 ABA 问题

**问题**：原子 CAS 中的 ABA 问题

```c
// 线程 1 读到 A
// 线程 2 改为 B
// 线程 2 改回 A
// 线程 1 的 CAS 成功，但状态已变
```

**解决方案**：
- **版本号**：使用双字 CAS（值 + 版本）
- ** Hazard Pointer**：安全内存回收

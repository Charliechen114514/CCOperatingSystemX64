## 为什么需要文件系统

### 1.1 从块设备到文件系统

Stage 24 实现了 ATA 驱动，可以直接读写硬盘扇区。但这存在以下问题：

- **数据组织困难**：必须手动跟踪每个数据的位置
- **空间管理复杂**：需要自己管理哪些块是空闲的
- **目录结构缺失**：无法按名称组织文件
- **元数据管理缺失**：没有文件大小、创建时间等信息
- **扩展性差**：难以支持不同类型的存储设备

### 1.2 文件系统的优势

文件系统解决了上述问题：

- **抽象命名空间**：通过路径名访问文件
- **结构化存储**：目录层次结构
- **元数据管理**：inode 存储文件信息
- **空间管理**：块位图、inode 位图
- **统一接口**：不同文件系统提供相同的 API

### 1.3 为什么选择 EXT2

EXT2 (Second Extended Filesystem) 是 Linux 历史上最重要的文件系统之一：

| 特性 | 优势 |
|------|------|
| 成熟稳定 | Linux 标准配置多年 |
| 设计清晰 | 结构简单，易于理解和实现 |
| 文档丰富 | 大量参考资料和示例代码 |
| 广泛支持 | � 几乎所有工具都支持 |
| 教学价值 | 是学习文件系统的最佳选择 |

**其他候选方案**：
- **FAT32**：结构简单，但功能有限（无权限、无硬链接）
- **EXT3/4**：增加了日志功能，但实现更复杂
- **Btrfs**：现代特性丰富，但过于复杂

### 1.4 为什么需要 VFS

VFS (Virtual Filesystem Switch) 是内核的文件系统抽象层：

- **统一接口**：应用程序无需关心底层文件系统类型
- **多文件系统支持**：同时挂载多种文件系统
- **缓存优化**：统一的 inode 和 dentry 缓存
- **扩展性强**：添加新文件系统只需实现操作接口

```
没有 VFS:
应用程序 → 直接调用 EXT2 函数 → 硬编码文件系统依赖

有 VFS:
应用程序 → VFS 接口 → 动态分发到具体文件系统 → 可扩展
```

### 2.1 EXT2 磁盘布局

```
┌────────────────────────────────────────────────────────────┐
│                      引导块 (1024 字节)                     │
├────────────────────────────────────────────────────────────┤
│                      超级块 (1024 字节)                     │
│                    - 文件系统整体信息                        │
│                    - 块组描述符表                           │
├────────────────────────────────────────────────────────────┤
│  块组 0                        │  块组 1        │  ...      │
│  ├─ 块位图                      │  (重复结构)      │           │
│  ├─ inode 位图                  │                 │           │
│  ├─ inode 表                    │                 │           │
│  └─ 数据块                      │                 │           │
└────────────────────────────────────────────────────────────┘
```

### 2.2 EXT2 核心概念

#### 超级块 (Superblock)

文件系统的全局信息，每个块组都有副本：

```c
struct ext2_superblock {
    uint32_t s_inodes_count;       // inode 总数
    uint32_t s_blocks_count;       // 块总数
    uint32_t s_free_blocks_count;  // 空闲块数
    uint32_t s_free_inodes_count;  // 空闲 inode 数
    uint32_t s_first_data_block;   // 第一个数据块
    uint32_t s_log_block_size;     // 块大小 (0=1KB, 1=2KB...)
    uint32_t s_blocks_per_group;   // 每组块数
    uint32_t s_inodes_per_group;   // 每组 inode 数
    uint32_t s_magic;              // 魔数 0xEF53
    // ...
};
```

#### Inode

存储文件/目录的元数据：

```c
struct ext2_inode {
    uint16_t i_mode;               // 文件类型和权限
    uint16_t i_uid;                // 所有者 UID
    uint32_t i_size;               // 文件大小
    uint32_t i_atime;              // 访问时间
    uint32_t i_ctime;              // 创建时间
    uint32_t i_mtime;              // 修改时间
    uint32_t i_dtime;              // 删除时间
    uint16_t i_gid;                // 组 ID
    uint16_t i_links_count;        // 硬链接数
    uint32_t i_blocks;             // 512字节块数
    uint32_t i_flags;              // 文件标志
    uint32_t i_block[15];          // 块指针数组
    // ...
};
```

#### 块指针布局

EXT2 inode 使用 15 个块指针支持大文件：

```
i_block[0]    → 直接数据块
i_block[1]    → 直接数据块
...
i_block[11]   → 直接数据块 (12个直接块 = 48KB)

i_block[12]   → 单间接块 → 1024个块指针 → 4MB 数据
i_block[13]   → 双间接块 → 1024个单间接块 → 4GB 数据
i_block[14]   → 三间接块 → 1024个双间接块 → 4TB 数据
```

#### 目录项

目录是特殊的文件，存储目录项列表：

```c
struct ext2_dir_entry {
    uint32_t inode;                // inode 号
    uint16_t rec_len;              // 记录长度
    uint8_t  name_len;             // 文件名长度
    uint8_t  file_type;            // 文件类型
    char     name[];               // 文件名
};
```

### 2.3 VFS 抽象层次

VFS 定义了统一的抽象概念：

| VFS 概念 | EXT2 对应 | FAT32 对应 |
|----------|-----------|------------|
| superblock | ext2_superblock | FAT Boot Sector |
| inode | ext2_inode | 无 (FAT 无独立 inode) |
| dentry | ext2_dir_entry | FAT 长文件名目录项 |
| file | 打开的文件上下文 | 打开的文件上下文 |

## 设计决策

### 3.1 VFS 分层架构

#### 决策：三层架构

```
┌────────────────────────────────────────┐
│         VFS 抽象层                      │
│  - 统一 API                             │
│  - 路径解析                             │
│  - 权限检查                             │
│  - 缓存管理                             │
├────────────────────────────────────────┤
│       具体文件系统层                     │
│  - EXT2 实现                            │
│  - (未来) FAT32                         │
│  - (未来) ext4                          │
├────────────────────────────────────────┤
│         块设备层                         │
│  - 块 I/O 抽象                          │
│  - 缓冲管理 (未来)                       │
└────────────────────────────────────────┘
```

**理由**：
- **关注点分离**：每层专注于特定职责
- **可扩展性**：添加新文件系统不需要修改 VFS 层
- **可测试性**：每层可独立测试

### 3.2 函数指针表设计

#### 决策：使用 C 函数指针实现多态

```c
struct super_operations {
    int (*read_inode)(struct vfs_inode*);
    int (*write_inode)(struct vfs_inode*);
    int (*put_super)(struct vfs_superblock*);
};

struct file_operations {
    ssize_t (*read)(struct file*, char*, size_t);
    ssize_t (*write)(struct file*, const char*, size_t);
};
```

**理由**：
- **OOP 风格**：在 C 中模拟面向对象
- **动态分发**：运行时选择正确的实现
- **内存效率**：每个类型一份函数表

**替代方案**：
- **switch-case**：性能好，但扩展性差
- **C++ 虚函数**：更优雅，但内核用 C

### 3.3 缓存策略

#### 决策：Inode 和 Dentry 缓存，块设备同步 I/O

**Inode 缓存**：
```c
#define INODE_HASH_SIZE  256
static struct hlist_head inode_cache_hash[INODE_HASH_SIZE];
```

**Dentry 缓存**：
```c
#define DENTRY_HASH_SIZE  256
static struct list_head dentry_hash[DENTRY_HASH_SIZE];
```

**块设备**：当前使用同步 I/O，无缓存

**理由**：
- **Inode/Dentry**：频繁访问，缓存收益大
- **块设备**：实现复杂，推迟到后续阶段

### 3.4 错误处理

#### 决策：统一负数错误码

```c
#define VFS_OK      0
#define VFS_INVAL  -1   // 无效参数
#define VFS_IO     -2   // I/O 错误
#define VFS_NOMEM  -3   // 内存不足
#define VFS_NOENT  -5   // 文件不存在
```

**理由**：
- **C 惯例**：负数表示错误，0/正数表示成功
- **简单直观**：易于检查和传播
- **兼容性**：与 Linux 风格一致

## 实现细节

### 5.1 挂载流程

```c
struct vfs_superblock* vfs_mount(const char* dev,
                                  const char* mount_point,
                                  const char* type,
                                  int flags,
                                  const char* opts) {
    // 1. 解析设备名
    int dev_id = parse_device_name(dev);  // "hda" → 0

    // 2. 查找文件系统类型
    file_system_type_t* fs_type = fs_type_get(type);

    // 3. 调用具体文件系统的挂载方法
    struct vfs_superblock* sb = fs_type->mount(dev, opts);

    // 4. 设置根目录
    struct vfs_inode* root_inode = sb->s_root;

    // 5. 创建挂载点 dentry
    struct vfs_dentry* mount_dentry = dentry_alloc(root_inode, mount_point);

    // 6. 添加到挂载点树
    mount_add(mount_point, sb);

    return sb;
}
```

### 5.2 文件打开流程

```c
file_t* vfs_open(const char* path, int flags) {
    // 1. 路径解析
    struct path path_parsed;
    if (path_parse(path, &path_parsed) != 0) {
        return NULL;
    }

    // 2. 逐级查找 dentry
    struct vfs_dentry* dentry = path_lookup(&path_parsed);
    if (!dentry) {
        if (flags & O_CREAT) {
            // 创建新文件
            dentry = vfs_create(path, flags);
        } else {
            return NULL;
        }
    }

    // 3. 检查权限
    if (!permission_check(dentry->d_inode, flags)) {
        return NULL;
    }

    // 4. 分配 file 结构
    file_t* file = kmalloc(sizeof(file_t));
    file->f_dentry = dentry;
    file->f_inode = dentry->d_inode;
    file->f_pos = 0;
    file->f_flags = flags;
    file->f_op = dentry->d_inode->i_fop;

    // 5. 调用文件系统的 open 方法
    if (file->f_op->open) {
        file->f_op->open(file);
    }

    return file;
}
```

### 5.3 EXT2 块映射

```c
// 获取文件偏移对应的物理块号
static uint32_t ext2_get_block(struct vfs_inode* inode,
                                uint32_t lblock) {
    struct ext2_inode_info* ei = inode->i_private;

    // 直接块 (0-11)
    if (lblock < 12) {
        return ei->i_data[lblock];
    }

    // 单间接块
    lblock -= 12;
    if (lblock < 256) {  // 假设 4KB 块，每块 1024 个指针
        uint32_t* indirect = read_indirect_block(ei->i_data[12]);
        return indirect[lblock];
    }

    // 双间接块
    lblock -= 256;
    if (lblock < 256 * 256) {
        uint32_t* doubly_indirect = read_indirect_block(ei->i_data[13]);
        uint32_t indirect_block = doubly_indirect[lblock / 256];
        uint32_t* indirect = read_indirect_block(indirect_block);
        return indirect[lblock % 256];
    }

    // 三间接块...
    return 0;
}
```

### 5.4 目录查找

```c
// 在目录中查找名称
struct vfs_dentry* ext2_lookup(struct vfs_inode* dir,
                                const char* name) {
    // 1. 读取目录数据
    char* dir_data = kmalloc(dir->i_size);
    ext2_read_inode_data(dir, dir_data, 0, dir->i_size);

    // 2. 遍历目录项
    uint32_t offset = 0;
    while (offset < dir->i_size) {
        struct ext2_dir_entry* entry =
            (struct ext2_dir_entry*)(dir_data + offset);

        // 3. 比较文件名
        if (strncmp(entry->name, name, entry->name_len) == 0) {
            // 找到！
            struct vfs_inode* inode = vfs_iget(dir->i_sb, entry->inode);
            struct vfs_dentry* dentry = dentry_alloc(inode, name);
            kfree(dir_data);
            return dentry;
        }

        // 4. 移动到下一个目录项
        offset += entry->rec_len;
    }

    kfree(dir_data);
    return NULL;  // 未找到
}
```

### 5.5 Inode 缓存

```c
// 获取 inode（优先从缓存）
struct vfs_inode* vfs_iget(struct vfs_superblock* sb,
                            uint64_t ino) {
    // 1. 计算哈希
    uint32_t hash = inode_hash(sb, ino);

    // 2. 查找缓存
    struct vfs_inode* inode;
    struct hlist_node* p;
    hlist_for_each_entry(inode, p, &inode_cache_hash[hash], i_hash) {
        if (inode->i_ino == ino && inode->i_sb == sb) {
            // 命中！增加引用计数
            inode_ref_get(inode);
            return inode;
        }
    }

    // 3. 未命中，从磁盘读取
    inode = kmalloc(sizeof(struct vfs_inode));
    inode->i_ino = ino;
    inode->i_sb = sb;

    // 调用文件系统的 read_inode 方法
    sb->s_op->read_inode(inode);

    // 4. 加入缓存
    hlist_add_head(&inode->i_hash, &inode_cache_hash[hash]);

    return inode;
}
```

## 常见陷阱与注意事项

### 6.1 块大小不一致

**问题**：EXT2 支持多种块大小，但假设固定大小

```c
// 错误：假设 1024 字节块
#define BLOCK_SIZE  1024
uint32_t block_num = offset / BLOCK_SIZE;

// 正确：从超级块读取
uint32_t block_size = sb->s_blocksize;
uint32_t block_num = offset / block_size;
```

### 6.2 Endian 问题

**问题**：磁盘数据可能使用不同的字节序

```c
// EXT2 使用小端序
#define le32_to_cpu(x)  (x)

// 从磁盘读取时转换
uint32_t s_magic = le32_to_cpu(raw_sb->s_magic);
```

### 6.3 缓存一致性

**问题**：修改文件后缓存未更新

```c
// 写入文件后
vfs_write(file, data, size);

// 错误：忘记标记 inode 为脏
// inode->i_state &= ~I_DIRTY;

// 正确：标记为脏，需要写回
inode->i_state |= I_DIRTY;
```

### 6.4 路径遍历死循环

**问题**：符号链接可能导致无限循环

```c
// 当前实现：不支持符号链接，无此问题
```

## 未来改进方向

### 7.1 缓冲区缓存

```c
// 当前：每次都读取磁盘
block_read(dev, block, buffer, 1);

// 改进：添加块缓存
struct buffer_head* bh = bh_get(dev, block);
if (!bh) {
    bh = bh_alloc(dev, block);
    block_read(dev, block, bh->b_data, 1);
}
// 使用 bh->b_data
bh_put(bh);
```

### 7.2 异步 I/O

```c
// 当前：同步 I/O
int result = vfs_read(file, buffer, size);

// 改进：异步 I/O
struct aio_request req;
vfs_read_async(file, buffer, size, &req);
// ... 做其他事情 ...
vfs_wait(&req);
```

### 7.3 文件锁

```c
// 当前：无文件锁

// 改进：添加文件锁
vfs_flock(file1, LOCK_EX);
```

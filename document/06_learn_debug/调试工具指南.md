# CCOS 调试基础设施 - 调试工具指南

## 1. GDB 调试器

### 1.1 GDB 基础

GDB (GNU Debugger) 是 Linux 下最常用的调试工具。

#### 安装

```bash
# Debian/Ubuntu
sudo apt install gdb

# Fedora/RHEL
sudo dnf install gdb

# Arch Linux
sudo pacman -S gdb
```

#### 基本用法

```bash
# 启动 GDB
gdb [程序文件]

# 带参数启动
gdb -x 初始化文件 [程序文件]

# 附加到运行中的进程
gdb -p <PID>

# 查看版本
gdb --version
```

### 1.2 远程调试

#### 连接到 QEMU

```gdb
# 连接到远程 GDB 服务器
target remote <主机>:<端口>
target remote :1234
target remote localhost:1234
target remote 192.168.1.100:1234

# 扩展远程模式（支持多进程）
target extended-remote :1234
```

#### 断开连接

```gdb
# 断开连接（保持 QEMU 运行）
disconnect

# 退出 GDB（会自动清理）
quit
```

### 1.3 断点管理

#### 设置断点

```gdb
# 在地址处设置断点
break *0x10000
b *0x10000

# 在函数处设置断点
break kernel_main
b kernel_main

# 在文件:行号处设置断点
break kernel_main.c:42

# 条件断点
break kernel_main if x == 42

# 临时断点（命中后删除）
tbreak *0x10000
```

#### 管理断点

```gdb
# 查看所有断点
info breakpoints
info b

# 禁用断点
disable 2          # 禁用断点 2
disable 1-5        # 禁用断点 1-5
disable            # 禁用所有断点

# 启用断点
enable 2
enable 1-5
enable

# 删除断点
delete 2
delete 1-5
delete             # 删除所有断点

# 清除断点（指定位置）
clear *0x10000
clear kernel_main
```

### 1.4 程序控制

```gdb
# 继续执行
continue
c

# 单步执行（进入函数）
step
s

# 单步执行（不进入函数）
next
n

# 单步执行指令
stepi
si

# 执行下一条指令
nexti
ni

# 跳出当前函数
finish

# 跳到指定位置
jump *0x10000
jump kernel_main

# 发送信号
signal SIGINT

# 杀死程序
kill
```

### 1.5 查看信息

#### 查看寄存器

```gdb
# 查看所有寄存器
info registers
info r

# 查看特定寄存器
info registers rax
info r rax

# 查看浮点寄存器
info all-registers

# 修改寄存器
set $rax = 42
set $rsp += 8
```

#### 查看内存

```gdb
# 查看内存（十六进制）
x/10x 0xB8000

# 查看内存（十进制）
x/10d 0xB8000

# 查看内存（指令）
x/10i 0x10000
x/10i $pc

# 查看内存（字符串）
x/s 0xB8000

# 查看内存（字符）
x/10c 0xB8000

# 查看内存（多种格式）
x/10gx 0xB8000    # 8 字节十六进制
x/10wx 0xB8000    # 4 字节十六进制
x/10hx 0xB8000    # 2 字节十六进制
x/10bx 0xB8000    # 1 字节十六进制

# 格式说明
# x - 十六进制
# d - 十进制有符号
# u - 十进制无符号
# o - 八进制
# t - 二进制
# a - 地址
# i - 指令
# c - 字符
# s - 字符串
```

#### 查看变量

```gdb
# 打印变量
print x
p x

# 打印表达式
print x + y
p $rax + 8

# 打印数组
print arr[0]
print *arr@10

# 打印结构体
print my_struct
print my_struct.field

# 按格式打印
print/x x         # 十六进制
print/d x         # 十进制
print/t x         # 二进制
print/c x         # 字符

# 查看类型
whatis x
ptype x
```

#### 查看调用栈

```gdb
# 查看调用栈
backtrace
bt

# 查看 N 帧栈
backtrace 10
bt 10

# 查看完整栈
full backtrace

# 切换栈帧
frame 0
f 0

# 向上/向下移动栈帧
up
down

# 查看栈帧信息
info frame
info f
```

### 1.6 反汇编

```gdb
# 反汇编当前函数
disassemble
disas

# 反汇编指定范围
disassemble 0x10000 0x10100
disassemble kernel_main

# 反汇编周围代码
disassemble $pc-10 $pc+10

# 设置反汇编语法
set disassembly-flavor intel    # Intel 语法
set disassembly-flavor att      # AT&T 语法
```

### 1.7 常用配置

```gdb
# 设置架构
set architecture i386:x86-64
set arch i386:x86-64

# 关闭分页
set pagination off

# 设置输出格式
set output-radix 16    # 十六进制
set output-radix 10    # 十进制
set output-radix 8     # 八进制

# 显示源代码
list
l
list 1
list kernel_main

# 设置提示符
set prompt (gdb)

# 历史记录
show commands
```

### 1.8 宏和脚本

```gdb
# 定义宏
define print_regs
    info registers
end

# 条件执行
define print_if_eq
    if $argc == 2
        if $arg0 == $arg1
            printf "Equal: %d == %d\n", $arg0, $arg1
        end
    end
end
```

## 2. VSCode 调试配置

### 2.1 安装扩展

```bash
# 推荐扩展
code --install-extension ms-vscode.cpptools
code --install-extension llvm-vs-code-extensions.vscode-clangd
```

### 2.2 launch.json 配置

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Attach QEMU GDB",
            "type": "cppdbg",
            "request": "launch",
            "program": "${workspaceFolder}/build/kernel.elf",
            "cwd": "${workspaceFolder}",
            "MIMode": "gdb",
            "miDebuggerPath": "/usr/bin/gdb",
            "miDebuggerServerAddress": "localhost:1234",
            "setupCommands": [
                {
                    "text": "-gdb-set architecture i386:x86-64"
                },
                {
                    "text": "-gdb-set disassembly-flavor intel"
                },
                {
                    "text": "-gdb-set pagination off"
                }
            ],
            "logging": {
                "engineLogging": false,
                "trace": false,
                "traceResponse": false
            }
        }
    ]
}
```

### 2.3 调试操作

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 开始调试 | `F5` | 启动调试 |
| 继续执行 | `F5` | 继续执行程序 |
| 单步跳过 | `F10` | 下一行（不进入函数） |
| 单步进入 | `F11` | 单步（进入函数） |
| 单步跳出 | `Shift+F11` | 跳出当前函数 |
| 重启调试 | `Ctrl+Shift+F5` | 重启调试 |
| 停止调试 | `Shift+F5` | 停止调试 |
| 切换断点 | `F9` | 设置/取消断点 |

### 2.4 断点类型

#### 普通断点
点击行号左侧设置断点

#### 条件断点
右键行号 → 添加条件断点

```
// 条件表达式
x == 42
arr[i] > 100
ptr != NULL
```

#### 日志点
右键行号 → 添加日志点

```
// 输出消息
"x = {x}"
"array[0] = {arr[0]}"
```

#### 函数断点
在调试控制台输入：

```
-exec break kernel_main
```

### 2.5 变量监视

#### 变量面板
自动显示当前作用域的所有变量

#### 监视面板
添加自定义表达式：

```
x
arr[0]
ptr->field
$rax
```

### 2.6 调试控制台

#### 执行 GDB 命令

```
-exec info registers
-exec x/10x 0xB8000
-exec disassemble
```

#### 评估表达式

```
x + y
*ptr
arr[0]
```

## 4. launch_qemu_for_vscode_debug.sh 脚本

### 4.1 脚本功能

```bash
#!/bin/bash
# CCOS QEMU Launch Script for VSCode Debug

# 功能：
# 1. 检查并自动构建
# 2. 启动 QEMU 调试服务器
# 3. 监控 GDB 连接状态
# 4. GDB 断开时自动停止 QEMU
```

### 4.2 使用方法

```bash
# 启动 QEMU（自动监控）
./scripts/launch_qemu_for_vscode_debug.sh

# 停止 QEMU
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 查看状态
./scripts/launch_qemu_for_vscode_debug.sh --status

# 显示帮助
./scripts/launch_qemu_for_vscode_debug.sh --help
```

### 4.3 监控功能

脚本会持续监控 GDB 连接状态：

```

[监控] 检测到 GDB 已断开连接
[监控] 正在自动停止 QEMU...

```

## 6. QEMU 调试参数

### 6.1 基础参数

```bash
# GDB 服务器
-s                          # 在 :1234 启动 GDB 服务器
-gdb tcp::1234             # 同上，指定端口

# 启动控制
-S                          # 启动时暂停 CPU
```

### 6.2 完整启动命令

```bash
# 基础调试模式
qemu-system-x86_64 \
    -drive format=raw,file=boot.img,if=ide \
    -nographic \
    -s \
    -S

# 带串口输出
qemu-system-x86_64 \
    -drive format=raw,file=boot.img,if=ide \
    -nographic \
    -serial mon:stdio \
    -s \
    -S

# 带串口重定向
qemu-system-x86_64 \
    -drive format=raw,file=boot.img,if=ide \
    -nographic \
    -serial file:serial.log \
    -s \
    -S

# 多核调试
qemu-system-x86_64 \
    -drive format=raw,file=boot.img,if=ide \
    -nographic \
    -smp 2 \
    -s \
    -S
```

### 6.3 GDB 线程支持

```bash
# 多核调试时选择线程
(gdb) info threads
(gdb) thread 2

# 查看所有线程的栈
(gdb) thread apply all bt
```

## 8. Clang-Format 使用

### 8.1 命令行使用

```bash
# 格式化文件
clang-format -i file.c

# 查看改动（不写入）
clang-format --diff file.c

# 使用特定配置
clang-format -style=file:.clang-format -i file.c

find . -name "*.c" -o -name "*.h" | xargs clang-format -i
```

## 9. 工具组合使用

### 9.1 完整调试流程

```bash
# 1. 构建
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build

# 2. 启动调试（两种方式）

# 方式 A: 命令行
./scripts/debug.sh

# 方式 B: VSCode
./scripts/launch_qemu_for_vscode_debug.sh
# 然后在 VSCode 中按 F5

# 3. 调试完成后自动清理
```

### 9.2 快速验证

```gdb
# 快速验证调试环境
target remote :1234
b *0x10000
c
x/10i $pc
```

### 9.3 常用调试模式

| 场景 | 工具 | 命令 |
|------|------|------|
| 快速调试 | GDB | `./scripts/debug.sh` |
| 图形化调试 | VSCode | `./scripts/launch_qemu_for_vscode_debug.sh` + F5 |
| 分析问题 | GDB | `bt`, `info r`, `x/...` |
| 性能分析 | QEMU | `-d in_asm,cpu,exec` |

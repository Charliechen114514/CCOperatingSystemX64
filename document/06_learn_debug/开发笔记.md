### 2.2 开发步骤

#### 步骤 1: CMake Debug 配置

首先修改 CMakeLists.txt 支持 Debug 模式：

```cmake
# 设置构建类型
set(CMAKE_BUILD_TYPE Debug)

# 添加调试符号
add_compile_options(-g)

# kernel.elf 用于 GDB 调试
add_custom_command(OUTPUT kernel.elf
    COMMAND ${CMAKE_OBJCOPY} ... -O elf64-x86-64 ...)
```

**关键点**:
- `-g` 选项生成调试符号
- `kernel.elf` 保留完整符号信息
- `kernel.bin` 是纯二进制用于启动

#### 步骤 2: debug.sh 脚本

创建基础调试脚本：

```bash
#!/bin/bash
# 启动 QEMU 调试模式
qemu-system-x86_64 \
    -drive format=raw,file=boot.img,if=ide \
    -nographic \
    -s \          # GDB server on :1234
    -S &          # 暂停启动，等待 GDB

# 启动 GDB
gdb -x .gdbinit kernel.elf

# 清理
kill %1  # 停止 QEMU
```

**关键点**:
- `-s` 等价于 `-gdb tcp::1234`
- `-S` 启动时暂停 CPU
- GDB 退出时自动清理 QEMU

#### 步骤 3: .gdbinit 配置

创建 GDB 初始化配置：

```
# 设置架构
set architecture i386:x86-64

# 设置汇编语法
set disassembly-flavor intel

# 关闭分页
set pagination off

# 连接到 QEMU
target remote :1234

# 常用断点
# b *0x7C00    # Boot1 入口
# b *0x10000   # 内核入口
```

#### 步骤 4: VSCode 配置

创建 `.vscode/launch.json`：

```json
{
    "name": "Attach QEMU GDB",
    "type": "cppdbg",
    "request": "launch",
    "program": "${workspaceFolder}/build/kernel.elf",
    "MIMode": "gdb",
    "miDebuggerPath": "/usr/bin/gdb",
    "miDebuggerServerAddress": "localhost:1234",
    "setupCommands": [
        {"text": "-gdb-set architecture i386:x86-64"},
        {"text": "-gdb-set disassembly-flavor intel"}
    ]
}
```

#### 步骤 5: VGA 驱动实现

创建 VGA 文本模式驱动：

```c
// vga.h
typedef struct CCOS_VGA {
    volatile char* base_addr;
    vga_sz_t width;
    vga_sz_t height;
    vga_cursor_t native_cursor_pos;
    vga_color_t font_color;
    vga_color_t background_color;
} CCOS_VGA;

void vga_print_string(CCOS_VGA* vga, const char* string);
void vga_clear(CCOS_VGA* vga, vga_color_t background);
```

**关键设计**:
- 文本模式分辨率: 80x25
- 显存基地址: 0xB8000
- 每个字符 2 字节 (字符 + 属性)
- 支持 16 色

#### 步骤 6: 类型定义统一

创建统一的类型定义头文件：

```c
// types.h
typedef unsigned char      uint8_t;
typedef unsigned short     uint16_t;
typedef unsigned int       uint32_t;
typedef unsigned long long uint64_t;

// 类型限制
#define UINT8_MAX   ((uint8_t)0xFF)
#define UINT16_MAX  ((uint16_t)0xFFFF)
// ...

// 实用宏
#define NULL ((void*)0)
#define PACKED __attribute__((packed))
```

#### 步骤 7: clangd 配置

配置语言服务器：

```yaml

  Add:
    - -m64
    - -march=x86-64
    - -Wall
    - -Wextra

  UnusedIncludes: Strict

    Add:
      - bugprone-*
      - clang-analyzer-*
```

#### 步骤 8: launch_qemu_for_vscode_debug.sh

创建 VSCode 专用调试脚本，支持自动停止：

```bash
# 监控 GDB 连接状态
monitor_gdb_connection() {
    while true; do
        # 检查是否有 ESTABLISHED 连接
        if ! lsof -ti:1234 -sTCP:ESTABLISHED 2>/dev/null | grep -q .; then
            echo "GDB 已断开，自动停止 QEMU"
            kill $QEMU_PID
            break
        fi
        sleep 0.5
    done
}
```

**创新点**: 监控 GDB 连接状态，当 VSCode 断开调试时自动停止 QEMU

## 3. 关键决策

### 3.1 为什么使用 GDB 远程调试？

**决策**: 使用 GDB 远程调试而非本地调试

**原因**:
1. 内核运行在虚拟机中，无法直接调试
2. QEMU 内置 GDB server 支持
3. GDB 是成熟、标准的调试工具
4. 支持源代码级调试

**权衡**:
- 优点: 功能强大、生态成熟
- 缺点: 学习曲线较陡

### 3.2 为什么同时提供 debug.sh 和 VSCode 支持？

**决策**: 同时支持命令行和图形化调试

**原因**:
1. **命令行** (debug.sh): 轻量、快速、适合熟悉 GDB 的开发者
2. **VSCode**: 图形化界面、直观、适合初学者

### 3.3 为什么自己实现 VGA 驱动？

**决策**: 实现独立的 VGA 文本模式驱动

**原因**:
1. 不依赖任何外部库
2. 提供结构化的 API
3. 支持颜色、光标控制
4. 便于后续扩展

**设计考虑**:
- 使用面向对象风格 (CCOS_VGA 结构)
- 封装所有 VGA 操作
- 提供清晰的 API

### 3.4 为什么使用 .elf 而非 .bin 进行调试？

**决策**: 使用 kernel.elf 作为调试符号文件

**原因**:
| 格式 | 符号信息 | 用途 |
|------|----------|------|
| .bin | 无 | 启动 |
| .elf | 完整 | 调试 |

.elf 文件包含:
- 符号表 (函数、变量名)
- 调试信息 (行号、类型)
- 重定位信息

### 3.5 为什么需要 clangd 配置？

**决策**: 配置 clangd 而非使用默认设置

**原因**:
1. Freestanding 环境需要特殊标志
2. 禁用标准库相关检查
3. 启用有用的 ClangTidy 检查
4. 配置合适的警告级别

## 4. 常见陷阱

### 4.1 GDB 连接超时

**问题**: GDB 无法连接到 QEMU

**原因**:
1. QEMU 未启动
2. 端口被占用
3. 防火墙阻止

**解决方案**:
```bash
# 检查端口
lsof -ti:1234

# 停止占用进程
kill -9 $(lsof -ti:1234)

# 重新启动 QEMU
qemu-system-x86_64 -s -S ...
```

### 4.2 符号文件不匹配

**问题**: 设置断点失败，显示符号找不到

**原因**: kernel.elf 与运行的内核版本不一致

**解决方案**:
```bash
# 清理构建
rm -rf build
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build
```

### 4.3 VGA 显示乱码

**问题**: VGA 输出显示乱码或无输出

**原因**:
1. 显存地址错误
2. 字符编码问题
3. 光标位置错误

**解决方案**:
```c
// 确保显存地址正确
volatile uint16_t* video = (volatile uint16_t*)0xB8000;

// 正确构造 VGA 条目
uint16_t entry = (uint16_t)c | ((uint16_t)color << 8);
video[y * 80 + x] = entry;
```

### 4.4 QEMU 进程残留

**问题**: 调试结束后 QEMU 进程仍在运行

**原因**: 脚本异常退出，未清理进程

**解决方案**:
```bash
# 使用脚本停止
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 或手动停止
killall qemu-system-x86_64
```

### 4.5 clangd 报告不存在头文件

**问题**: clangd 报告找不到自定义头文件

**原因**: 编译数据库缺少 include 路径

**解决方案**:
```cmake
# 确保 CMakeLists.txt 正确设置
target_include_directories(kernel PRIVATE
    ${CMAKE_SOURCE_DIR}/kernel/defines
    ${CMAKE_SOURCE_DIR}/kernel/assert
)
```

### 5.2 VGA 驱动核心实现

#### VGA 条目构造

```c
static inline uint16_t vga_entry(char c, vga_color_t font, vga_color_t background) {
    // VGA 条目格式:
    // [15:8] - 属性字节
    //   [7:4] - 背景色
    //   [3:0] - 前景色
    // [7:0]  - ASCII 字符
    return (uint16_t)c | ((uint16_t)(background << 4 | font) << 8);
}
```

#### 光标位置编码

```c
// 光标位置编码: X 在高字节，Y 在低字节
vga->native_cursor_pos = ((uint16_t)x << 8) | (uint16_t)y;

// 解码
vga_sz_t x = (vga_sz_t)((vga->native_cursor_pos & 0xFF00) >> 8);
vga_sz_t y = (vga_sz_t)(vga->native_cursor_pos & 0x00FF);
```

## 6. 调试技巧

### 6.1 高效调试流程

1. **修改代码** → 清理构建 → 运行 debug.sh
2. **快速验证**: 在 kernel_main 入口处设置断点
3. **使用条件断点**: 避免频繁中断
4. **利用 VGA 输出**: 关键点输出调试信息

### 6.2 常用 GDB 命令

| 命令 | 缩写 | 说明 |
|------|------|------|
| `target remote` | - | 连接到远程 GDB server |
| `break` | `b` | 设置断点 |
| `continue` | `c` | 继续执行 |
| `stepi` | `si` | 单步执行指令 |
| `nexti` | `ni` | 执行下一条指令 (不进入函数) |
| `info registers` | - | 显示寄存器 |
| `x/10x $pc` | - | 查看当前指令的内存 |
| `disassemble` | - | 反汇编当前函数 |
| `backtrace` | `bt` | 显示调用栈 |

### 6.3 VSCode 调试技巧

1. **条件断点**: 右键行号 → "添加条件断点"
2. **日志点**: 不中断，只输出消息
3. **监视表达式**: 实时查看变量值
4. **即时窗口**: 在调试控制台执行表达式

## 7. 性能考虑

### 7.1 Debug vs Release 构建

| 构建类型 | 优化 | 符号 | 大小 | 调试 |
|----------|------|------|------|------|
| Debug | -O0 -g | 完整 | 大 | 完整支持 |
| Release | -O2/-O3 | 无/有限 | 小 | 有限支持 |

**建议**:
- 开发阶段使用 Debug
- 发布版本使用 Release

### 7.2 调试开销

1. **QEMU 虚拟化**: 比原生慢 10-100 倍
2. **GDB 单步**: 每步需要通信
3. **VGA 输出**: 直接写显存，开销小

# CCOS 调试基础设施 - 技术参考

## 1. VGA 文本模式

### 1.1 硬件基础

VGA (Video Graphics Array) 文本模式是 IBM PC 兼容机的标准显示模式。

#### 内存映射

```
显存地址: 0xB8000 (彩色文本模式)
          0xB0000 (单色文本模式)

分辨率: 80 字符 × 25 行
每个字符: 2 字节 (1 字符 + 1 属性)
总大小: 80 × 25 × 2 = 4000 字节
```

#### VGA 条目格式

```
位 15-8: 属性字节
  位 7-4: 背景色 (0-15)
  位 3-0: 前景色 (0-15)

位 7-0: ASCII 字符
```

### 1.2 颜色代码

| 值 | 颜色 | 显示效果 |
|----|------|----------|
| 0 | 黑色 | Black |
| 1 | 蓝色 | Blue |
| 2 | 绿色 | Green |
| 3 | 青色 | Cyan |
| 4 | 红色 | Red |
| 5 | 品红 | Magenta |
| 6 | 棕色 | Brown |
| 7 | 浅灰 | Light Grey |
| 8 | 深灰 | Dark Grey |
| 9 | 亮蓝 | Bright Blue |
| 10 | 亮绿 | Bright Green |
| 11 | 亮青 | Bright Cyan |
| 12 | 亮红 | Bright Red |
| 13 | 亮品红 | Bright Magenta |
| 14 | 黄色 | Yellow |
| 15 | 白色 | White |

#### 属性字节位操作

```c
// 基本颜色属性
uint8_t vga_entry_color(vga_color_t fg, vga_color_t bg) {
    return fg | (bg << 4);
}

// 完整 VGA 条目
uint16_t vga_entry(unsigned char uc, uint8_t color) {
    return (uint16_t) uc | (uint16_t) color << 8;
}
```

### 1.3 光标控制

VGA 光标位置通过 CRT 控制器 (CRT Controller) 端口控制：

```c
// 端口地址
#define VGA_CTRL_REGISTER 0x3D4
#define VGA_DATA_REGISTER  0x3D5

// 光标位置高字节
#define VGA_CURSOR_HIGH   0xE
// 光标位置低字节
#define VGA_CURSOR_LOW    0xF

// 设置光标位置
void vga_set_cursor_position(uint16_t position) {
    outb(VGA_CTRL_REGISTER, VGA_CURSOR_HIGH);
    outb(VGA_DATA_REGISTER, (position >> 8) & 0xFF);
    outb(VGA_CTRL_REGISTER, VGA_CURSOR_LOW);
    outb(VGA_DATA_REGISTER, position & 0xFF);
}

// 获取光标位置
uint16_t vga_get_cursor_position(void) {
    uint16_t position = 0;
    outb(VGA_CTRL_REGISTER, VGA_CURSOR_HIGH);
    position |= inb(VGA_DATA_REGISTER) << 8;
    outb(VGA_CTRL_REGISTER, VGA_CURSOR_LOW);
    position |= inb(VGA_DATA_REGISTER);
    return position;
}
```

### 1.4 滚屏实现

```
滚屏原理:
1. 将显存内容向上移动一行
2. 清空最后一行
3. 更新光标位置

实现方式:
- 内存复制: 使用 memcpy/memmove
- 直接写显存: 逐行复制
```

## 2. GDB 远程调试协议

### 2.1 协议概述

GDB 远程调试协议 (RSP) 是一个基于文本的协议，用于 GDB 与调试存根 (stub) 通信。

#### 通信流程

```
┌─────────┐                    ┌─────────┐
│   GDB   │                    │  QEMU   │
├─────────┤                    ├─────────┤
│         │ ─── 数据包 ───────► │         │
│  客户端  │                    │  服务器  │
│         │ ◄─── 数据包 ────── │         │
└─────────┘                    └─────────┘

数据包格式:
$<数据>#<校验和>

响应:
+   - 接收到数据包
-   - 校验和错误，请求重发
```

### 2.2 常用数据包

| 数据包 | 说明 |
|--------|------|
| `g` | 读取所有寄存器 |
| `G` | 写入所有寄存器 |
| `p n` | 读取寄存器 n |
| `P n=r` | 写入寄存器 n = r |
| `m addr,len` | 读取内存 |
| `M addr,len:...` | 写入内存 |
| `c` | 继续执行 |
| `s` | 单步执行 |
| `?` | 最后信号 |

### 2.3 QEMU GDB 服务器

#### 启动参数

```
-s            # 在 localhost:1234 启动 GDB 服务器
# 等价于 -gdb tcp::1234

-S            # 启动时暂停 CPU，等待 GDB 连接
```

#### 连接示例

```gdb
# 方式 1: 默认端口
target remote :1234

# 方式 2: 指定主机和端口
target remote localhost:1234

# 方式 3: 使用 TCP
target remote tcp:localhost:1234
```

### 2.4 架构设置

```gdb
# x86-64 架构
set architecture i386:x86-64

# 汇编语法风格
set disassembly-flavor intel    # Intel 语法 (mov eax, 1)
set disassembly-flavor att      # AT&T 语法   (movl $1, %eax)
```

## 3. VSCode 调试适配器协议

### 3.1 DAP 概述

调试适配器协议 (Debug Adapter Protocol) 是 VSCode 用于调试的标准化协议。

```
┌──────────┐     DAP      ┌──────────────┐     GDB MI     ┌─────────┐
│ VSCode   │ ◄──────────► │  C/C++ dap   │ ◄────────────► │   GDB   │
│  UI      │  JSON-RPC    │   (adapter)  │   MI Protocol  │         │
└──────────┘              └──────────────┘                └─────────┘
```

### 3.2 launch.json 配置

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            // 配置名称（显示在调试面板）
            "name": "Attach QEMU GDB",

            // 调试类型
            "type": "cppdbg",

            // 请求类型
            // "launch" - 启动新程序
            // "attach" - 附加到运行中的程序
            "request": "launch",

            // 要调试的程序（符号文件）
            "program": "${workspaceFolder}/build/kernel.elf",

            // 工作目录
            "cwd": "${workspaceFolder}",

            // 调试模式
            "MIMode": "gdb",

            // GDB 路径
            "miDebuggerPath": "/usr/bin/gdb",

            // GDB 服务器地址
            "miDebuggerServerAddress": "localhost:1234",

            // 初始化命令
            "setupCommands": [
                {
                    "text": "-gdb-set architecture i386:x86-64",
                    "description": "设置 x86-64 架构"
                },
                {
                    "text": "-gdb-set disassembly-flavor intel",
                    "description": "使用 Intel 汇编语法"
                },
                {
                    "text": "-gdb-set pagination off",
                    "description": "关闭分页"
                }
            ]
        }
    ]
}
```

### 3.3 MI 命令参考

GDB/MI (Machine Interface) 是 GDB 的机器接口命令。

| MI 命令 | 说明 | 输出 |
|---------|------|------|
| `-gdb-set` | 设置 GDB 参数 | `^done` |
| `-break-insert` | 插入断点 | `^done,bkpt={...}` |
| `-exec-continue` | 继续执行 | `^running` |
| `-exec-next` | 下一行 | `^running` |
| `-exec-step` | 单步进入 | `^running` |
| `-exec-interrupt` | 中断执行 | `^done` |
| `-stack-list-frames` | 获取调用栈 | `^done,stack=[...]` |
| `-var-create` | 创建变量对象 | `^done,name="..."` |
| `-var-evaluate` | 计算变量值 | `^done,value="..."` |

## 4. ELF 符号文件

### 4.1 ELF 格式概述

ELF (Executable and Linkable Format) 是 Unix 系统的可执行文件格式。

```
ELF 文件结构:
┌─────────────────────────────────────────┐
│          ELF Header (ehdr)              │
├─────────────────────────────────────────┤
│          Program Header Table           │
│         (可选，用于加载器)               │
├─────────────────────────────────────────┤
│          Section 1                      │
│          .text (代码段)                  │
├─────────────────────────────────────────┤
│          Section 2                      │
│          .data (数据段)                  │
├─────────────────────────────────────────┤
│          Section 3                      │
│          .bss (未初始化数据)             │
├─────────────────────────────────────────┤
│          Section 4                      │
│          .symtab (符号表)                │
├─────────────────────────────────────────┤
│          Section 5                      │
│          .strtab (字符串表)              │
├─────────────────────────────────────────┤
│          Section N                      │
│          .debug_* (调试信息)             │
├─────────────────────────────────────────┤
│          Section Header Table           │
├─────────────────────────────────────────┤
│          Section N...                   │
└─────────────────────────────────────────┘
```

### 4.2 符号表

符号表 (`.symtab`) 包含程序中定义和引用的所有符号。

```c
typedef struct {
    uint32_t st_name;     // 符号名称在 .strtab 中的偏移
    uint32_t st_value;    // 符号的值（地址）
    uint32_t st_size;     // 符号的大小
    uint8_t  st_info;     // 符号类型和绑定
    uint8_t  st_other;    // 符号可见性
    uint16_t st_shndx;    // 相关的节区索引
} Elf32_Sym;
```

#### 符号类型

| 值 | 类型 | 说明 |
|----|------|------|
| 0 | NOTYPE | 未指定类型 |
| 1 | OBJECT | 数据对象（变量） |
| 2 | FUNC | 代码对象（函数） |
| 3 | SECTION | 节区 |
| 4 | FILE | 源文件名 |

### 4.3 调试信息

DWARF 是 ELF 使用的调试信息格式。

```
.debug_info    # 主要调试信息
.debug_line    # 行号信息
.debug_abbrev  # 缩写代码
.debug_aranges # 地址范围
.debug_str     # 调试字符串
.debug_ranges  # 范围信息
```

### 4.4 objcopy 操作

```bash
# 创建纯二进制文件
objcopy -O binary kernel.elf kernel.bin

# 只提取特定段
objcopy -O binary -j .text kernel.elf kernel.text.bin

# 保留调试符号
objcopy --only-keep-debug kernel.elf kernel.debug

# 剥离调试信息
objcopy --strip-debug kernel.elf kernel.stripped.elf

# 添加调试链接
objcopy --add-gnu-debuglink=kernel.debug kernel.stripped.elf
```

## 5. CMake Debug 配置

### 5.1 构建类型

```cmake
# 设置构建类型
set(CMAKE_BUILD_TYPE Debug)

# 或者使用命令行
cmake -DCMAKE_BUILD_TYPE=Debug -B build
```

#### 构建类型对比

| 类型 | C 标志 | C++ 标志 | 调试符号 | 优化 |
|------|--------|----------|----------|------|
| Debug | `-g` | `-g` | 完整 | `-O0` |
| Release | `-O3` | `-O3` | 无/有限 | 最大优化 |
| RelWithDebInfo | `-O2 -g` | `-O2 -g` | 完整 | 中等优化 |
| MinSizeRel | `-Os` | `-Os` | 无 | 最小体积 |

### 5.2 符号文件生成

```cmake
# 生成 kernel.elf (带符号)
add_custom_command(
    OUTPUT kernel.elf
    DEPENDS ${CMAKE_OBJCOPY}
    COMMAND ${CMAKE_OBJCOPY}
        -O elf64-x86-64
        --keep-global-symbol kernel_main
        $<TARGET_FILE:kernel>
        kernel.elf
    VERBATIM
)

add_custom_target(kernel_elf ALL DEPENDS kernel.elf)
```

### 5.3 调试选项

```cmake
# 添加调试符号
add_compile_options(-g)

# 禁用优化 (Debug 模式默认)
add_compile_options(-O0)

# 添加调试宏
add_definitions(-DDEBUG=1)

# 保留帧指针 (便于栈回溯)
add_compile_options(-fno-omit-frame-pointer)

# 添加额外调试信息
add_compile_options(-fno-optimize-sibling-calls)
```

## 8. 静态断言

### 8.1 C11 静态断言

```c
#include <assert.h>

// C11 静态断言
static_assert(sizeof(int) == 4, "int must be 4 bytes");

// 带消息的静态断言
static_assert(CHAR_BIT == 8, "CHAR_BIT must be 8");
```

### 8.2 编译期检查

```c
// 类型大小检查
static_assert(sizeof(uint8_t) == 1, "uint8_t size error");
static_assert(sizeof(uint16_t) == 2, "uint16_t size error");
static_assert(sizeof(uint32_t) == 4, "uint32_t size error");
static_assert(sizeof(uint64_t) == 8, "uint64_t size error");

// 指针大小检查
static_assert(sizeof(void*) == 8, "must be 64-bit");

// 结构体对齐检查
static_assert(alignof(max_align_t) >= 8, "alignment error");
```

### 8.3 自定义静态断言（C 兼容）

```c
// 编译期断言宏
#define STATIC_ASSERT(cond, msg) \
    typedef char static_assert_##msg[(cond) ? 1 : -1]

// 使用
STATIC_ASSERT(sizeof(int) == 4, int_must_be_4_bytes);
```

### 8.4 常用编译期检查

```c
// 检查常量值
static_assert(UINT8_MAX == 0xFF, "UINT8_MAX error");
static_assert(UINT16_MAX == 0xFFFF, "UINT16_MAX error");
static_assert(UINT32_MAX == 0xFFFFFFFF, "UINT32_MAX error");

// 检查宏定义
#ifndef PAGE_SIZE
#define PAGE_SIZE 4096
#endif
static_assert(PAGE_SIZE == 4096, "PAGE_SIZE must be 4096");

// 检查枚举值
enum {
    COLOR_BLACK = 0,
    COLOR_WHITE = 15
};
static_assert(COLOR_WHITE == 15, "color enum error");
```

## 9. 端口和中断

### 9.1 VGA 相关端口

| 端口 | 名称 | 读/写 | 说明 |
|------|------|-------|------|
| 0x3C4 | VGA Sequencer Index | W | 序列器索引 |
| 0x3C5 | VGA Sequencer Data | R/W | 序列器数据 |
| 0x3B4/0x3D4 | CRT Controller Index | W | CRT 控制器索引 |
| 0x3B5/0x3D5 | CRT Controller Data | R/W | CRT 控制器数据 |
| 0x3CE | Graphics Controller Index | W | 图形控制器索引 |
| 0x3CF | Graphics Controller Data | R/W | 图形控制器数据 |
| 0x3DA | Input Status 1 | R | 输入状态寄存器 1 |

### 9.2 端口 I/O 函数

```c
// 输出字节到端口
static inline void outb(uint16_t port, uint8_t value) {
    __asm__ volatile ("outb %0, %1" : : "a"(value), "Nd"(port));
}

// 从端口读取字节
static inline uint8_t inb(uint16_t port) {
    uint8_t value;
    __asm__ volatile ("inb %1, %0" : "=a"(value) : "Nd"(port));
    return value;
}

// 输出字到端口
static inline void outw(uint16_t port, uint16_t value) {
    __asm__ volatile ("outw %0, %1" : : "a"(value), "Nd"(port));
}

// 从端口读取字
static inline uint16_t inw(uint16_t port) {
    uint16_t value;
    __asm__ volatile ("inw %1, %0" : "=a"(value) : "Nd"(port));
    return value;
}
```

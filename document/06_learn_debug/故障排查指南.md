# CCOS 调试基础设施 - 故障排查指南

## 1. GDB 无法连接到 QEMU

### 1.1 问题现象

```
(gdb) target remote :1234
Remote communication error.  Target disconnected.: Connection refused
```

### 1.2 诊断步骤

```bash
# 1. 检查 QEMU 是否运行
ps aux | grep qemu-system

# 2. 检查端口是否监听
lsof -ti:1234
ss -tlnp | grep 1234
netstat -tlnp | grep 1234

# 3. 检查防火墙
sudo ufw status
sudo iptables -L -n | grep 1234
```

### 1.3 常见原因和解决方案

#### 原因 1: QEMU 未启动

**诊断**: `ps aux | grep qemu` 无输出

**解决方案**:
```bash
# 启动 QEMU
./scripts/debug.sh
# 或
qemu-system-x86_64 -drive format=raw,file=build/boot.img,if=ide -nographic -s -S
```

#### 原因 2: 端口被占用

**诊断**: `lsof -ti:1234` 显示其他 PID

**解决方案**:
```bash
# 查看占用进程
lsof -ti:1234
ps -p $(lsof -ti:1234)

# 停止占用进程
kill $(lsof -ti:1234)

# 或使用其他端口
qemu-system-x86_64 ... -gdb tcp::2345
gdb> target remote :2345
```

#### 原因 3: QEMU 崩溃退出

**诊断**: QEMU 启动后立即退出

**解决方案**:
```bash
# 查看错误信息
qemu-system-x86_64 ... 2>&1 | tee qemu.log

# 检查磁盘镜像
ls -la build/boot.img
file build/boot.img

# 验证镜像内容
hexdump -C build/boot.img | head -20
```

#### 原因 4: 防火墙阻止

**诊断**: 本地连接被拒绝

**解决方案**:
```bash
# Ubuntu/Debian
sudo ufw allow 1234/tcp

# Fedora/RHEL
sudo firewall-cmd --add-port=1234/tcp --permanent
sudo firewall-cmd --reload

# 或使用 localhost 连接（通常不受防火墙影响）
gdb> target remote localhost:1234
```

## 2. 符号文件加载失败

### 2.1 问题现象

```
Reading symbols from build/kernel.elf...
"(no debugging symbols found)"...
(gdb) b kernel_main
No symbol table is loaded.  Use the "file" command.
```

### 2.2 诊断步骤

```bash
# 1. 检查文件是否存在
ls -la build/kernel.elf

# 2. 检查符号信息
file build/kernel.elf
readelf -h build/kernel.elf
nm build/kernel.elf

# 3. 检查调试信息
readelf -S build/kernel.elf | grep debug
objdump -h build/kernel.elf

# 4. 检查构建类型
grep CMAKE_BUILD_TYPE build/CMakeCache.txt
```

### 2.3 常见原因和解决方案

#### 原因 1: 未使用 Debug 构建

**诊断**: `CMAKE_BUILD_TYPE` 不是 Debug

**解决方案**:
```bash
# 清理并重新构建
rm -rf build
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build

# 验证
file build/kernel.elf
# 应显示: with debug_info
```

#### 原因 2: kernel.elf 文件过时

**诊断**: 符号与运行代码不匹配

**解决方案**:
```bash
# 清理并重新构建
rm -rf build
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build --clean-first
```

#### 原因 3: GDB 未正确加载符号

**诊断**: GDB 已连接但找不到符号

**解决方案**:
```gdb
# 显式加载符号文件
file build/kernel.elf

# 验证符号加载
info symbols kernel_main
info functions
```

#### 原因 4: Strip 导致符号丢失

**诊断**: 文件显示 `stripped`

**解决方案**:
```bash
# 检查 CMakeLists.txt
# 确保没有 strip 操作
# 或保留未 strip 的副本

# 重新生成符号
objcopy --only-keep-debug build/kernel.elf build/kernel.debug
```

## 3. VSCode 调试配置问题

### 3.1 问题现象

```
错误: 无法启动调试
启动失败: 无法连接到 localhost:1234
```

### 3.2 诊断步骤

```bash
# 1. 检查 launch.json
cat .vscode/launch.json

# 2. 验证 QEMU 运行
./scripts/launch_qemu_for_vscode_debug.sh --status

# 3. 检查 GDB 路径
which gdb
ls -la /usr/bin/gdb
```

### 3.3 常见原因和解决方案

#### 原因 1: launch.json 配置错误

**诊断**: JSON 格式错误或路径错误

**解决方案**:
```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Attach QEMU GDB",
            "type": "cppdbg",
            "request": "launch",
            "program": "${workspaceFolder}/build/kernel.elf",
            "cwd": "${workspaceFolder}",
            "MIMode": "gdb",
            "miDebuggerPath": "/usr/bin/gdb",
            "miDebuggerServerAddress": "localhost:1234",
            "setupCommands": [
                {
                    "text": "-gdb-set architecture i386:x86-64",
                    "description": "设置 x86-64 架构"
                },
                {
                    "text": "-gdb-set disassembly-flavor intel",
                    "description": "使用 Intel 汇编语法"
                }
            ]
        }
    ]
}
```

#### 原因 2: QEMU 未启动

**诊断**: VSCode 无法连接

**解决方案**:
```bash
# 先启动 QEMU
./scripts/launch_qemu_for_vscode_debug.sh

# 等待 "QEMU GDB Server 已就绪" 消息
# 然后在 VSCode 中按 F5
```

#### 原因 3: cpptools 扩展冲突

**诊断**: clangd 和 cpptools 冲突

**解决方案**:
```json
// settings.json
{
    "C_Cpp.intelliSenseEngine": "disabled",
    "C_Cpp.autocomplete": "disabled"
}
```

#### 原因 4: GDB 版本问题

**诊断**: GDB 版本过旧

**解决方案**:
```bash
# 检查版本
gdb --version

# 安装最新版本
sudo apt install gdb
# 或
sudo dnf install gdb
```

## 4. VGA 输出异常

### 4.1 问题现象

```
1. VGA 显示乱码
2. VGA 无输出
3. 光标位置错误
4. 颜色显示错误
```

### 4.2 诊断步骤

```bash
# 1. 检查显存地址
gdb> x/10x 0xB8000

# 2. 检查 VGA 初始化
gdb> b system_vga_init
gdb> c
gdb> s
gdb> info registers

# 3. 检查 VGA 结构
gdb> p internal_vga_instance
gdb> p internal_vga_instance.base_addr
gdb> p internal_vga_instance.width
gdb> p internal_vga_instance.height
```

### 4.3 常见原因和解决方案

#### 原因 1: 显存地址错误

**诊断**: `base_addr` 不是 0xB8000

**解决方案**:
```c
// 确保 VGA_BASE_ADDR 定义正确
#define VGA_BASE_ADDR 0xB8000

// 检查类型转换
internal_vga_instance.base_addr =
    (char*)(uintptr_t)VGA_BASE_ADDR;  // 正确
    // (char*)VGA_BASE_ADDR;          // 可能警告
```

#### 原因 2: VGA 条目格式错误

**诊断**: 内存中的条目格式不对

**解决方案**:
```c
// 正确的 VGA 条目格式
static inline uint16_t vga_entry(char c, vga_color_t font, vga_color_t background) {
    // 低 8 位: ASCII 字符
    // 高 8 位: 属性 (背景色 << 4 | 前景色)
    return (uint16_t)c | ((uint16_t)(background << 4 | font) << 8);
}

// 错误示例
return (uint16_t)c | (uint16_t)background << 12 | (uint16_t)font << 8;  // 错误的优先级
```

#### 原因 3: 光标位置计算错误

**诊断**: 字符显示位置不对

**解决方案**:
```c
// 正确的光标位置计算
vga_sz_t x = (vga_sz_t)((cursor_pos & 0xFF00) >> 8);  // 高字节
vga_sz_t y = (vga_sz_t)(cursor_pos & 0x00FF);          // 低字节

// 数组索引
video[y * width + x] = entry;

// 错误示例
video[x * width + y] = entry;  // X 和 Y 搞反了
```

#### 原因 4: 未调用初始化

**诊断**: VGA 未初始化

**解决方案**:
```c
// 在 kernel_main 开始时调用
void kernel_main(void) {
    system_vga_init();

    CCOS_VGA* vga = (CCOS_VGA*)vga_instance();
    vga_clear(vga, VGA_COLOR_BLACK);
    vga_print_string(vga, "Hello, VGA!");
}
```

## 5. 单步执行异常

### 5.1 问题现象

```
1. 单步执行跳到错误位置
2. step/next 不工作
3. 断点不起作用
4. 无法进入 C 代码
```

### 5.2 诊断步骤

```gdb
# 1. 检查当前位置
info frame
x/10i $pc

# 2. 检查符号
info symbol $pc
info functions

# 3. 检查行信息
info line *0x10000

# 4. 验证断点
info breakpoints
```

### 5.3 常见原因和解决方案

#### 原因 1: 汇编和 C 混合调试

**诊断**: 在汇编代码中使用 `next`

**解决方案**:
```gdb
# 在汇编代码中使用 stepi
si    # 单步指令
ni    # 下一指令（不进入调用）

# 跳到 C 函数入口
b kernel_main
c
```

#### 原因 2: 优化导致代码重排

**诊断**: 源码行与指令不对应

**解决方案**:
```bash
# 使用 Debug 构建
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build

# 验证优化级别
gcc -Q --help=optimizers | grep -E "[-]O[0-3]"
```

#### 原因 3: 断点位置错误

**诊断**: 断点设置在无效地址

**解决方案**:
```gdb
# 使用函数名而非地址
b kernel_main

# 或使用入口地址
b *0x10000

# 检查代码是否被优化掉
objdump -d build/kernel.elf | grep -A20 kernel_main
```

#### 原因 4: 长模式跳转问题

**诊断**: 从 32 位跳到 64 位时丢失调试信息

**解决方案**:
```gdb
# 在长模式入口设置断点
b *0x10000

# 继续后再设置 C 断点
c
b kernel_main
```

## 6. QEMU 进程残留

### 6.1 问题现象

```bash
# 调试结束后 QEMU 仍在运行
ps aux | grep qemu-system
```

### 6.2 诊断步骤

```bash
# 1. 查找所有 QEMU 进程
ps aux | grep qemu-system
pgrep -a qemu-system

# 2. 查看端口占用
lsof -ti:1234
ss -tlnp | grep 1234

# 3. 查看进程树
pstree -p | grep qemu
```

### 6.3 常见原因和解决方案

#### 原因 1: 脚本异常退出

**诊断**: 脚本被强制终止

**解决方案**:
```bash
# 使用脚本停止
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 或手动停止
killall qemu-system-x86_64

# 强制停止
killall -9 qemu-system-x86_64
```

#### 原因 2: GDB 断开但 QEMU 未检测到

**诊断**: 监控脚本失效

**解决方案**:
```bash
# 停止所有相关进程
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 重新启动
./scripts/launch_qemu_for_vscode_debug.sh
```

#### 原因 3: VNC 连接占用

**诊断**: VNC 端口也被占用

**解决方案**:
```bash
# 查找并停止所有 QEMU
killall qemu-system-x86_64

# 等待几秒后验证
sleep 2
ps aux | grep qemu-system
```

## 8. Clangd 警告和错误

### 8.1 问题现象

```
1. clangd 报告找不到头文件
2. 类型推断错误
3. 未定义类型警告
4. 静态分析警告
```

### 8.2 诊断步骤

```bash
# 1. 检查 clangd 日志
# VSCode: 输出 → Clangd

# 2. 检查配置文件
cat .clangd

# 3. 验证编译数据库
cat build/compile_commands.json | jq .

# 4. 手动运行 clangd
clangd --log=verbose --check=<文件>
```

### 8.3 常见原因和解决方案

#### 原因 1: 编译数据库缺失

**诊断**: `compile_commands.json` 不存在

**解决方案**:
```cmake
# CMakeLists.txt
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
```

#### 原因 2: Include 路径未配置

**诊断**: 找不到自定义头文件

**解决方案**:
```yaml
# .clangd
CompileFlags:
  Add:
    - I${workspaceFolder}/kernel/defines
    - I${workspaceFolder}/kernel/assert
    - I${workspaceFolder}/build/include
```

#### 原因 3: Freestanding 警告

**诊断**: 标准库相关警告

**解决方案**:
```yaml
# .clangd
CompileFlags:
  Add:
    - -ffreestanding
    - -nostdlib

Diagnostics:
  ClangTidy:
    Remove:
      - cert-env-*-*
      - -llvm-*
```

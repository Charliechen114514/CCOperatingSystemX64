# 开发笔记 - Stage 18 写时复制与异常处理

本文档记录 CCOS Stage 18 - 写时复制(COW)与异常处理机制的开发思路、设计决策和实现细节。

---

## 1. 为什么需要写时复制？

### 1.1 问题背景

在操作系统中，进程创建（如 `fork()`）是一个核心操作。传统的 `fork()` 实现将父进程的整个地址空间复制到子进程，这存在以下问题：

1. **内存浪费**：大多数 `fork()` 后紧接着 `exec()`，复制的内容立即被丢弃
2. **性能开销**：复制大量内存需要时间和 CPU 资源
3. **延迟增加**：用户感知到明显的创建延迟

### 1.2 写时复制解决方案

COW 机制的核心思想：

- **共享物理页**：父子进程最初共享相同的物理内存页
- **延迟复制**：只有当某个进程尝试写入时才真正复制
- **透明处理**：通过页错误机制自动处理，用户无感知

```c
// COW 流程示例
fork()  → 创建子进程，共享所有物理页
    ↓
标记所有共享页为只读 + COW 标志
    ↓
任一进程写入 → 触发页错误
    ↓
检查 COW 标志 → 分配新页 + 复制内容
    ↓
恢复执行（写入者获得新页，其他进程仍共享原页）
```

## 2. 设计决策

### 2.1 COW 页跟踪方案

#### 方案对比

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| 链表 | 简单 | 查找 O(n) | ❌ |
| 红黑树 | O(log n) 查找 | 实现复杂 | ❌ |
| 哈希表 | O(1) 查找 | 需要处理冲突 | ✅ |

**决策**：使用哈希表
- 物理地址作为键
- 指针哈希函数
- 链式法解决冲突

### 2.2 COW 标志存储

#### 页表保留位利用

x86_64 页表项中有多个可用位（Available bits），我们使用第 9 位：

```c
#define COW_FLAG_MASK    (1ULL << 9)
```

**为什么不使用软件结构？**
- 软件查找慢：需要遍历所有 COW 页
- 硬件检查快：页错误时 CPU 提供页表项
- 语义清晰：页表项直接反映页面状态

### 2.3 引用计数管理

```c
typedef struct cow_block {
    physical_addr_t    orig_phys;     // 原始物理页
    uint16_t           refcount;      // 引用计数 (1-COW_MAX_REFCOUNT)
} cow_block_t;
```

**引用计数规则**：
- 初始值：2（父子进程各一）
- 写入时：减 1
- 减到 1 时：直接设置写权限，无需复制
- 减到 0 时：从 COW 跟踪中移除

### 2.4 异常处理优先级

x86_64 异常有不同的优先级，必须正确配置：

```
Double Fault (#DF) → 最高优先级，需要独立 IST 栈
Stack Fault (#SS)  → 高优先级，需要独立 IST 栈
Page Fault (#PF)   → 正常优先级，使用当前栈
GPF (#GP)          → 正常优先级，使用当前栈
```

**IST 栈配置**：
- IST1: Double Fault 栈（16KB）
- IST4: Stack Fault 栈（16KB）

## 4. 实现细节

### 4.1 哈希表实现

**泛型设计**：

```c
typedef size_t (*hash_fn_t)(const void* key);
typedef bool (*hash_eq_fn_t)(const void* a, const void* b);

typedef struct {
    hash_entry_t** buckets;
    size_t num_buckets;
    size_t size;
    hash_fn_t hash_func;
    hash_eq_fn_t eq_func;
} hashmap_t;
```

**关键点**：
- 使用 `void*` 支持任意键类型
- 2 的幂次桶数量，使用位运算取模
- 链式冲突解决

### 4.2 COW 页错误处理

```c
cow_result_t cow_handle_fault(physical_addr_t pml4, virtual_addr_t fault_addr) {
    // 1. 查询当前映射
    page_query_result_t query;
    if (page_query(pml4, fault_addr, &query) != PAGE_OK) {
        return COW_ERR_INVALID;
    }

    // 2. 检查 COW 标志
    if (!cow_is_cow_page(query.flags)) {
        return COW_ERR_NOT_COW;
    }

    // 3. 查找 COW 块
    cow_block_t* block = cow_lookup_block(query.phys_addr);
    if (!block) {
        return COW_ERR_INVALID;
    }

    // 4. 根据引用计数处理
    if (block->refcount == 1) {
        // 直接设置写权限
        return cow_make_writable(pml4, fault_addr, query.phys_addr);
    } else {
        // 分配新页并复制
        return cow_copy_on_write(pml4, fault_addr, query.phys_addr, block);
    }
}
```

### 4.3 异常处理实现

**Double Fault 处理**：

```c
void double_fault_handler(interrupt_frame_t* frame, uint64_t error_code) {
    exception_stats.df_count++;

    // Double Fault 是严重错误，记录后停机
    klog_error("[Exception] Double Fault! Error code: 0x%llX\n", error_code);

    // 打印状态信息
    dump_interrupt_frame(frame);
    dump_cr_registers();

    // 停机
    halt();
}
```

**GPF 处理**：

```c
void gp_fault_handler(interrupt_frame_t* frame, uint64_t error_code) {
    exception_stats.gp_count++;

    if (frame->cs & 0x3) {
        exception_stats.gp_user_count++;
        // 用户态 GPF → 终止进程（未来）
    } else {
        exception_stats.gp_kernel_count++;
        // 内核态 GPF → 内核恐慌
        kernel_panic("Kernel GPF");
    }
}
```

## 5. 常见陷阱与注意事项

### 5.1 COW 相关

1. **页表同步问题**
   - 问题：多个虚拟地址映射同一物理页，只修改一个页表项
   - 解决：COW 只处理故障的虚拟地址

2. **引用计数泄漏**
   - 问题：进程退出时未减少引用计数
   - 解决：使用 `cow_unregister_region()` 自动处理

3. **递归页错误**
   - 问题：COW 处理过程中再次页错误
   - 解决：预分配内存，避免处理过程中分配

### 5.2 异常处理相关

1. **IST 栈溢出**
   - 问题：异常处理太深，IST 栈不够
   - 解决：增大 IST 栈到 16KB，限制处理深度

2. **嵌套异常**
   - 问题：处理异常时再次触发异常
   - 解决：使用 IST 栈隔离，避免栈破坏

3. **GDT 加载时序**
   - 问题：在 GDT 加载前使用段选择器
   - 解决：先初始化 GDT，再初始化其他模块

void test_cow_basic(void) {

## 7. 性能考虑

### 7.1 COW 性能

1. **哈希表大小**
   - 使用 64 桶，平衡内存和冲突率
   - 未来可动态扩展

2. **缓存友好**
   - COW 块紧凑存储
   - 热页优先处理

### 7.2 异常处理性能

1. **快速路径**
   - 常见异常快速判断
   - 避免不必要的处理

2. **延迟日志**
   - 非关键异常延迟记录
   - 批量输出

## 8. 未来改进方向

### 8.1 COW 增强

1. **COW 页合并**
   - 检测相同内容的页，合并为 COW
   - 节省物理内存

2. **写时合并**
   - 多个写入者合并修改
   - 减少复制次数

3. **延迟分配**
   - 只分配被访问的页
   - 配合按需分页

### 8.2 异常处理增强

1. **进程隔离**
   - 用户态异常只终止进程
   - 内核态异常才恐慌

2. **异常恢复**
   - 某些异常可恢复
   - 如修复后重新执行

3. **异常日志**
   - 持久化异常信息
   - 事后分析

# 故障排查指南 - Stage 18 写时复制与异常处理

本文档提供 CCOS Stage 18 写时复制与异常处理机制的常见问题排查方法。

---

## 1. COW 页错误处理失败

### 症状
- 写入共享内存时系统崩溃
- 页错误处理陷入死循环
- 进程意外终止

### 可能原因
1. COW 标志未正确设置
2. 哈希表查找失败
3. 引用计数管理错误
4. 内存分配失败

### 排查步骤

#### 1.1 检查 COW 标志

```c
// 在 cow_mark_page_readonly() 后验证
page_query_result_t query;
if (page_query(pml4, vaddr, &query) == PAGE_OK) {
    if (!cow_is_cow_page(query.flags)) {
        klog_error("COW flag not set!\n");
    }
}
```

#### 1.2 检查哈希表状态

```c
// 获取 COW 统计
cow_stats_t stats;
cow_get_stats(&stats);
klog_info("COW blocks: %llu\n", stats.cow_current_blocks);

// 检查特定页面
cow_block_t* block = cow_lookup_block(phys);
if (!block) {
    klog_error("Page not in COW tracking: 0x%llx\n", phys);
} else {
    klog_info("Refcount: %u\n", block->refcount);
}
```

#### 1.3 验证引用计数

```c
// 确保引用计数正确
uint16_t refcount;
cow_get_refcount(phys, &refcount);
if (refcount == 0 || refcount > COW_MAX_REFCOUNT) {
    klog_error("Invalid refcount: %u\n", refcount);
}
```

### 解决方案
- 确保 COW 注册在映射完成后进行
- 检查 `cow_inc_refcount()` 调用次数
- 验证物理页地址有效性

## 2. 异常处理器崩溃

### 症状
- Double Fault 后系统停机
- 异常处理时再次触发异常
- 栈损坏或溢出

### 可能原因
1. IST 栈配置错误
2. 异常处理器中有 bug
3. 栈大小不足
4. GDT/TSS 初始化问题

### 排查步骤

#### 2.1 检查 IST 栈配置

```c
// 验证 IST 栈已设置
tss_t* tss = tss_get();
if (tss->ist1 == 0) {
    klog_error("IST1 not configured!\n");
}
if (tss->ist4 == 0) {
    klog_error("IST4 not configured!\n");
}
```

#### 2.2 检查 TSS 加载

```c
// 确认 TSS 已加载
uint16_t tr;
__asm__ volatile("str %0" : "=r"(tr));
if (tr != GDT_TSS) {
    klog_error("TSS not loaded: TR=0x%x\n", tr);
}
```

#### 2.3 验证 GDT 选择子

```c
// 打印 GDT 条目
gdt_dump();
// 检查 TSS 描述符是否存在且有效
```

### 解决方案
- 确保 `tss_init()` 在 `gdt_load()` 之前调用
- 增大 IST 栈大小到 16KB 或更大
- 在异常处理器中避免复杂操作
- 使用汇编检查点验证栈状态

## 3. GDT/TSS 初始化问题

### 症状
- 系统启动后立即崩溃
- 段错误频繁发生
- 特权级切换失败

### 可能原因
1. GDT 条目配置错误
2. TSS 对齐问题
3. 选择子值不匹配
4. lgdt/ltr 指令执行失败

### 排查步骤

#### 3.1 检查 GDT 基址和限制

```c
const gdt_ptr_t* gdt_ptr = gdt_get_ptr();
klog_info("GDT base: 0x%llx, limit: %u\n",
          gdt_ptr->base, gdt_ptr->limit);

// 验证限制正确 (应该是 GDT 大小 - 1)
if (gdt_ptr->limit != 6 * 8 - 1) {  // 6 个条目，每个 8 字节
    klog_error("GDT limit incorrect!\n");
}
```

#### 3.2 验证 TSS 对齐

```c
// TSS 必须 16 字节对齐
if ((uintptr_t)tss_get() & 0xF) {
    klog_error("TSS not 16-byte aligned!\n");
}
```

#### 3.3 检查选择子

```c
// 验证当前 CS/DS
uint16_t cs, ds;
__asm__ volatile("mov %%cs, %0" : "=r"(cs));
__asm__ volatile("mov %%ds, %0" : "=r"(ds));
klog_info("CS=0x%x, DS=0x%x\n", cs, ds);
```

### 解决方案
- 确保 GDT 条目正确初始化
- 检查 TSS 描述符类型 (0x9 for 64-bit available TSS)
- 验证 lgdt 和 ltr 指令正确执行
- 使用 GDB 单步调试初始化代码

## 4. IST 栈溢出

### 症状
- 异常处理时 Triple Fault
- QEMU 突然退出
- 栈变量损坏

### 可能原因
1. IST 栈太小
2. 异常处理深度过大
3. 递归调用
4. 大栈帧函数

### 排查步骤

#### 4.1 检查 IST 栈使用

```c
// 在异常处理器中检查栈
void check_ist_stack(void) {
    uint64_t rsp;
    __asm__ volatile("mov %%rsp, %0" : "=r"(rsp));

    uint64_t ist_base = tss->ist1;  // 假设 IST1
    uint64_t stack_used = ist_base - rsp;

    klog_info("Stack used: %llu / %d bytes\n",
              stack_used, IST_STACK_SIZE);
}
```

#### 4.2 检测递归

```c
// 使用静态变量检测递归
static int depth = 0;

void double_fault_handler(...) {
    depth++;
    if (depth > 1) {
        klog_error("Recursive Double Fault! depth=%d\n", depth);
        halt();
    }
    // ... 处理 ...
    depth--;
}
```

### 解决方案
- 增大 IST 栈大小 (修改 `IST_STACK_SIZE`)
- 减少异常处理器中的栈使用
- 避免在异常处理器中调用大栈帧函数
- 添加栈保护机制

```c
    }

    klog_info("Collision rate: %f%%\n",
              (float)collisions / TESTS * 100);
}
```

#### 5.2 检查键比较

```c
// 验证比较函数
if (!eq_uint64(&key1, &key2)) {
    // key1 != key2
}
```

#### 5.3 检查内存状态

```c
// 检查哈希表分配
if (cow_state.page_map == NULL) {
    klog_error("COW hashmap not allocated!\n");
}
```

### 解决方案
- 使用更好的哈希函数
- 增加桶数量
- 修复键比较函数
- 检查内存分配器状态

## 6. 引用计数泄漏

### 症状
- COW 块数量持续增长
- 内存不足
- 页无法正确释放

### 可能原因
1. `cow_inc_refcount()` 未配对 `cow_dec_refcount()`
2. 进程退出时未清理
3. COW 区域未注销
4. 异常路径未处理

### 排查步骤

#### 6.1 检查引用计数平衡

```c
// 在关键点检查
cow_stats_t stats1, stats2;
cow_get_stats(&stats1);
// ... 操作 ...
cow_get_stats(&stats2);

if (stats2.cow_current_blocks > stats1.cow_current_blocks) {
    klog_warn("COW blocks increased: %llu → %llu\n",
              stats1.cow_current_blocks,
              stats2.cow_current_blocks);
}
```

#### 6.2 验证区域清理

```c
// 确保所有 COW 区域都被注销
if (cow_region_list != NULL) {
    klog_warn("Leaking COW regions!\n");
}
```

#### 6.3 跟踪引用计数

```c
// 调试版本添加跟踪
#ifdef COW_DEBUG
klog_info("inc_refcount(0x%llx): %u → %u\n",
          phys, block->refcount, block->refcount + 1);
#endif
```

### 解决方案
- 使用 `cow_unregister_region()` 自动清理
- 在进程退出时显式减少引用计数
- 添加引用计数跟踪
- 使用工具检测内存泄漏

## 7. 通用调试技巧

### 7.1 启用详细日志

```c
// 在相关头文件中定义
#define COW_DEBUG 1
#define EXCEPTION_DEBUG 1
```

### 7.2 使用 QEMU Monitor

```bash
# 查看页表
(qemu) info pg

# 查看寄存器
(qemu) info registers

# 查看虚拟内存
(qemu) xp /100xg 0xffffffff81000000

# 设置断点

```

### 7.3 使用 GDB

```bash
# 捕获异常
(gdb) catch signal

# 查看栈
(gdb) bt

# 查看变量
(gdb) print cow_state

# 检查内存
(gdb) x/10gx 0xffff800000001000
```

### 7.4 添加诊断代码

```c
// 打印异常帧
void dump_interrupt_frame(interrupt_frame_t* frame) {
    klog_error("RIP: 0x%llx, RSP: 0x%llx\n", frame->rip, frame->rsp);
    klog_error("RAX: 0x%llx, RBX: 0x%llx\n", frame->rax, frame->rbx);
    // ... 其他寄存器
}

// 打印 CR 寄存器
void dump_cr_registers(void) {
    uint64_t cr0, cr2, cr3, cr4;
    __asm__ volatile("mov %%cr0, %0" : "=r"(cr0));
    __asm__ volatile("mov %%cr2, %0" : "=r"(cr2));
    __asm__ volatile("mov %%cr3, %0" : "=r"(cr3));
    __asm__ volatile("mov %%cr4, %0" : "=r"(cr4));

    klog_error("CR0: 0x%llx, CR2: 0x%llx\n", cr0, cr2);
    klog_error("CR3: 0x%llx, CR4: 0x%llx\n", cr3, cr4);
}
```

## 8. 性能问题

### 症状
- COW 处理慢
- 高延迟
- CPU 使用率高

### 排查步骤

#### 8.1 检查哈希表性能

```c
// 统计查找时间
uint64_t start = rdtsc();
cow_block_t* block = cow_lookup_block(phys);
uint64_t cycles = rdtsc() - start;

if (cycles > 1000) {
    klog_warn("Slow COW lookup: %llu cycles\n", cycles);
}
```

#### 8.2 检查冲突率

```c
// 统计每个桶的条目数
for (size_t i = 0; i < num_buckets; i++) {
    int count = count_bucket_entries(i);
    if (count > 5) {
        klog_warn("Bucket %zu has %d entries\n", i, count);
    }
}
```

### 解决方案
- 增加哈希表大小
- 优化哈希函数
- 使用更高效的数据结构
- 添加缓存

## 1. 设计演进

### 1.1 从硬编码到动态配置

#### 阶段 04: 硬编码配置

```asm
; boot2.asm 中的硬编码
mov ax, 0x1000
mov es, ax
mov bx, 0x0000
mov ah, 0x02
mov al, 0x01          ; 硬编码：只读 1 个扇区
mov ch, 0x00
mov cl, 0x03          ; 硬编码：扇区 3
mov dh, 0x00
```

**问题**:
- 内核大小变化时需要手动修改
- 没有验证机制
- 磁盘布局不清晰

#### 阶段 05: 动态配置系统

```asm
; 引用配置文件
%include "boot_config.inc"

; 使用动态配置
call load_kernel_chs    ; 使用 boot_config.inc 中的参数
```

**优势**:
- 配置与代码分离
- 自动计算内核大小
- 构建时验证

### 1.3 验证系统的引入

#### 动机

```
开发过程中遇到的问题：
1. 内核变大后覆盖了 bootloader
2. 内存地址计算错误导致崩溃
3. 磁盘布局不连续
```

#### 解决方案

```python
# verify_disk_layout.py
def calculate_memory_layout(bootloader_sectors, kernel_sectors):
    stage2_end = 0x7E00 + (bootloader_sectors * 512)
    kernel_start = 0x10000

    if stage2_end > kernel_start:
        return "ERROR: Memory overlap"

    gap = kernel_start - stage2_end
    if gap < 512:
        return f"WARNING: Small gap ({gap} bytes)"

    return "OK"
```

## 2. 构建系统集成

### 2.1 CMake 目标依赖

#### 依赖链设计

```cmake
# bootloader 目标
add_custom_target(bootloader DEPENDS
    ${CMAKE_BINARY_DIR}/bootloader.bin    # 输出
    ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc  # 配置依赖
)

# boot_img 目标（依赖 bootloader 和 kernel）
add_custom_target(boot_img ALL DEPENDS
    bootloader
    kernel
)

# 构建后验证
add_custom_command(TARGET boot_img POST_BUILD
    COMMAND ${PYTHON} ${CMAKE_SOURCE_DIR}/scripts/verify_disk_layout.py
        ${CMAKE_BINARY_DIR}/bootloader.bin
        ${CMAKE_BINARY_DIR}/kernel.bin
)
```

#### 构建顺序

```
1. 生成 boot_config.inc (Mock)
2. 编译 bootloader.asm → bootloader.bin
3. 编译 kernel.asm → kernel.bin
4. 生成 boot.img (拼接)
5. 验证磁盘布局
```

## 3. 关键技术决策

### 3.1 为什么选择 CHS 而非 LBA？

#### 当前实现: CHS 模式

```asm
load_kernel_chs:
    mov ah, 0x02        ; CHS 读取
    mov al, KERNEL_SECTOR_COUNT
    mov ch, KERNEL_CHS_CYLINDER
    mov cl, KERNEL_CHS_SECTOR
    mov dh, KERNEL_CHS_HEAD
    mov dl, 0x80
    int 0x13
```

#### 原因

1. **兼容性**: CHS 在所有 BIOS 上都可用
2. **简单性**: 不需要构造 DAP 结构
3. **调试友好**: 参数直观

#### 未来计划: LBA 优先 + CHS 回退

```asm
; 计划中的实现
load_kernel:
    ; 尝试 LBA 扩展读取
    call load_kernel_lba
    jc .try_chs         ; LBA 失败，尝试 CHS
    ret

.try_chs:
    call load_kernel_chs
    ret
```

### 3.2 为什么使用 Mock 配置？

#### 问题

```
构建循环依赖：
  - bootloader 编译需要 boot_config.inc
  - boot_config.inc 生成需要 kernel.bin 大小
  - kernel.bin 编译不需要 bootloader

理论上可以两阶段构建，但复杂度高
```

#### 解决方案: Mock 配置

```
首次构建：
  boot_config.inc (Mock) → bootloader → kernel

后续构建：
  kernel.bin → GenerateKernelSize.cmake → boot_config.inc (真实值) → bootloader
```

#### Mock 配置内容

```asm
; 保守的默认值
%define KERNEL_SECTOR_COUNT       1       ; 假设最小内核
%define KERNEL_CHS_CYLINDER       0
%define KERNEL_CHS_HEAD           0
%define KERNEL_CHS_SECTOR         5
```

### 3.3 为什么内存加载地址选择 0x10000？

#### 候选地址分析

| 地址 | 优点 | 缺点 |
|------|------|------|
| 0x8000 | 紧凑 | 覆盖 IVT/BDA 区域 |
| 0x9000 | 较安全 | 可能与页表冲突 |
| 0x10000 | 安全隔离 | 需要大内核支持 |

#### 选择 0x10000 的原因

1. **安全**: 60KB 隔离间隙
2. **对齐**: 64KB 边界对齐
3. **扩展**: 支持最大 64MB 内核

```
Stage 2 结束: 0x8400
内核开始:    0x10000
间隙:        0x7C00 = 30,720 字节
```

## 4. 常见陷阱

### 4.1 CHS 扇区号陷阱

#### 陷阱: 0-based vs 1-based

```asm
; LBA 是 0-based
LBA 3 = 扇区 4

; CHS 扇区号是 1-based！
Sector = 4 (不是 3)

; 错误计算
mov cl, 4    ; ✗ 这会读取扇区 4，而非 LBA 3

; 正确计算
; LBA 3 → CHS (0, 0, 5)
mov cl, 5    ; ✓ 正确
```

#### 公式

```
CHS_Sector = (LBA % SectorsPerTrack) + 1    # 注意 +1

LBA 3:
  (3 % 63) + 1 = 3 + 1 = 4? 错误！

等等，让我重新计算：
  LBA 0 = 扇区 1 → CHS_Sector = (0 % 63) + 1 = 1 ✓
  LBA 1 = 扇区 2 → CHS_Sector = (1 % 63) + 1 = 2 ✓
  LTA 3 = 扇区 4 → CHS_Sector = (3 % 63) + 1 = 4 ✓

哦，boot_config.inc 中的注释有误？
%define KERNEL_CHS_SECTOR         5       ; 这个值对应 LBA 4

让我验证：
  LBA 4 = (4 % 63) + 1 = 5 ✓
```

### 4.2 BIOS INT 13h 限制

#### 陷阱: 单次读取最多 127 扇区

```asm
; 错误：假设可以读取任意数量
mov al, 200     ; ✗ BIOS 可能只读取部分

; 正确：检查并分批读取
mov ax, KERNEL_SECTOR_COUNT
cmp ax, 127
ja .needs_batch
mov al, ax      ; ✓ 直接读取
.int 0x13

.needs_batch:
    ; TODO: 实现循环读取
```

#### 当前限制

```
最大内核大小 = 127 × 512 = 65,024 字节 ≈ 63.5 KB

要支持更大内核，需要：
1. 实现循环读取
2. 更新 ES:BX 缓冲区指针
3. 累加实际读取的扇区数
```

### 4.3 段:偏移计算陷阱

#### 陷阱: 忘记 ×16

```asm
; 错误思维
mov ax, 0x1000
mov es, ax
; 认为 ES = 0x10000 ✗

; 正确理解
; ES = 0x1000
; 物理地址 = ES × 16 + BX
;           = 0x1000 × 16 + 0x0000
;           = 0x10000
```

#### 记忆技巧

```
实模式地址翻译：
  物理地址 = 段 × 16 + 偏移

为什么 ×16？
  - 8086 地址线 20 位
  - 段寄存器 16 位
  - 位移 4 位 = ×16
```

## 5. 未来改进

### 5.1 短期改进 (1-2 周)

#### 1. LBA 优先加载策略

```asm
load_kernel_auto:
    pusha

    ; 尝试检测扩展读取支持
    mov ah, 0x41
    mov bx, 0x55AA
    mov dl, 0x80
    int 0x13
    jc .use_chs         ; 不支持，使用 CHS
    cmp bx, 0xAA55
    jne .use_chs

    ; 使用 LBA 扩展读取
    call load_kernel_lba
    ret

.use_chs:
    call load_kernel_chs
    popa
    ret
```

#### 2. 多批读取支持

```asm
load_kernel_large:
    pusha

    mov cx, KERNEL_SECTOR_COUNT    ; 总扇区数
    mov di, 0                      ; 当前批次数

.loop:
    ; 计算本次读取扇区数
    mov ax, cx
    cmp ax, 127
    jbe .read_now
    mov ax, 127                    ; 最多 127

.read_now:
    ; 读取一批
    call read_sectors

    ; 更新缓冲区指针
    add bx, ax * 512

    ; 更新剩余扇区数
    sub cx, ax

    ; 检查是否完成
    cmp cx, 0
    jg .loop

    popa
    ret
```

#### 3. 集成自动配置生成

```cmake
# 在 kernel 构建后自动重新生成配置
add_custom_command(
    OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc.real
    COMMAND ${CMAKE_COMMAND}
        -DKERNEL_BIN=${CMAKE_BINARY_DIR}/kernel.bin
        -DOUTPUT_FILE=${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc.real
        -DBOOTLOADER_SECTORS=${BOOTLOADER_SECTORS}
        -P ${CMAKE_SOURCE_DIR}/cmake/GenerateKernelSize.cmake
    DEPENDS
        ${CMAKE_BINARY_DIR}/kernel.bin
        ${CMAKE_SOURCE_DIR}/cmake/GenerateKernelSize.cmake
    COMMENT "Generating real boot configuration from kernel size"
)

# 替换并重新编译 bootloader
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/bootloader.bin.real
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc.real
        ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc
    COMMAND ${NASM} -f bin
        -I${CMAKE_CURRENT_BINARY_DIR}/
        ${CMAKE_CURRENT_SOURCE_DIR}/bootloader.asm
        -o ${CMAKE_BINARY_DIR}/bootloader.bin
    DEPENDS
        ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc.real
        ${CMAKE_CURRENT_SOURCE_DIR}/bootloader.asm
    COMMENT "Rebuilding bootloader with real kernel size"
)
```

## 6. 经验总结

### 6.1 构建系统设计

#### 渐进式复杂度

```
从简单开始：
  1. 手动编译和链接
  2. Makefile 自动化
  3. CMake 跨平台支持
  4. 动态配置生成
  5. 自动验证系统

每一步都建立在前一步基础上
```

#### 依赖管理

```
明确依赖关系：
  - 显式声明 DEPENDS
  - 使用 POST_BUILD 钩子
  - 避免循环依赖

清晰的依赖链让构建可靠
```

### 6.2 调试技巧

#### 验证优先

```
每修改一个功能：
  1. 写验证脚本
  2. 运行验证
  3. 检查输出
  4. 修复问题

verify_disk_layout.py 是很好的例子
```

#### 分步调试

```
遇到问题时：
  1. 简化到最小可复现
  2. 添加调试输出
  3. 使用工具验证（xxd, ndisasm）
  4. 逐项检查假设

不要凭直觉，要用工具验证
```

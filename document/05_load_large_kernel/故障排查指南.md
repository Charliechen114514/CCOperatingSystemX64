## 1. 内核加载失败

### 1.1 症状：内核过大错误

```
[E3] Kernel too large for single CHS read
系统挂起
```

### 根本原因

**问题**: BIOS INT 13h AH=02h 单次读取限制为 127 扇区

**分析**:
```asm
; bootloader.asm
mov ax, KERNEL_SECTOR_COUNT
cmp ax, 127
ja .kernel_too_large       ; 超过 127 扇区触发错误
```

### 解决方案

#### 方案 1: 减小内核大小（临时）

```bash
# 检查当前内核大小
ls -lh kernel.bin

# 如果小于 63.5 KB，检查配置
# 127 扇区 × 512 字节 = 65,024 字节
```

#### 方案 2: 实现多批读取（推荐）

```asm
load_kernel_multi:
    pusha

    mov cx, KERNEL_SECTOR_COUNT    ; 总扇区数
    mov ax, KERNEL_LOAD_SEGMENT
    mov es, ax
    mov bx, KERNEL_LOAD_OFFSET     ; 缓冲区指针

.read_loop:
    ; 计算本次读取扇区数
    mov ax, cx
    cmp ax, 127
    jbe .do_read
    mov ax, 127                    ; 最多 127

.do_read:
    push cx                        ; 保存剩余扇区数
    push bx                        ; 保存缓冲区指针

    ; 设置 CHS 参数
    mov ah, 0x02
    mov al, al                      ; 本次读取扇区数
    ; ... CHS 参数设置

    int 0x13
    jc .error

    pop bx
    pop cx

    ; 更新指针
    push ax
    mov ax, [read_count]
    add bx, ax * 512                ; 移动缓冲区指针
    sub cx, ax                      ; 减少剩余扇区数
    pop ax

    cmp cx, 0
    jg .read_loop                   ; 继续读取

    popa
    clc
    ret

.error:
    popa
    stc
    ret
```

#### 方案 3: 使用 LBA 扩展读取

```asm
load_kernel_lba:
    pusha

    ; 设置 DAP
    mov edi, 0x5000
    mov byte [edi + 0], 0x10       ; Packet size
    mov byte [edi + 1], 0x00       ; Reserved
    mov word [edi + 2], 127        ; 最多 127 扇区
    mov word [edi + 4], 0x0000     ; Offset
    mov word [edi + 6], 0x1000     ; Segment (0x10000)
    mov dword [edi + 8], 3         ; LBA = 3
    mov dword [edi + 12], 0

    ; 执行扩展读取
    mov si, di
    mov ah, 0x42
    int 0x13

    popa
    ret
```

### 关键要点

- **BIOS INT 13h AH=02h 限制**: 最大 127 扇区/次
- **INT 13h AH=42h 限制**: 无此限制（推荐使用）
- **当前实现**: 只支持 ≤127 扇区的内核
- **验证方法**: `wc -c kernel.bin` 检查大小

## 2. 内存重叠问题

### 2.1 症状：系统无响应或 Triple Fault

```
Stage 2 running...
[系统重启或无响应]
```

### 根本原因

**问题**: 内存布局计算错误，导致 Bootloader 和内核重叠

**分析**:
```python
# 验证脚本输出
ERROR: Memory overlap: Stage 2 ends at 0x9500, kernel starts at 0x10000
```

### 诊断步骤

#### 1. 运行验证脚本

```bash
python3 scripts/verify_disk_layout.py \
    build/bootloader.bin \
    build/kernel.bin
```

#### 2. 检查内存布局

```asm
; bootloader.asm
; 检查 KERNEL_LOAD_SEGMENT 和 KERNEL_LOAD_OFFSET
%define KERNEL_LOAD_SEGMENT       0x1000      ; ES:BX = 0x1000:0x0000
%define KERNEL_LOAD_OFFSET        0x0000

; 物理地址 = 0x1000 × 16 + 0x0000 = 0x10000
```

#### 3. 计算 Stage 2 结束地址

```python
bootloader_sectors = 3
stage2_start = 0x7E00
stage2_end = stage2_start + (bootloader_sectors * 512)
            = 0x7E00 + 1536
            = 0x8400

kernel_start = 0x10000

if stage2_end > kernel_start:
    print("ERROR: Memory overlap!")
```

### 解决方案

#### 方案 1: 增加 Kernel 加载地址

```asm
; 修改前
%define KERNEL_LOAD_SEGMENT       0x1000

; 修改后（确保足够隔离）
%define KERNEL_LOAD_SEGMENT       0x2000      ; 0x20000
```

#### 方案 2: 减小 Bootloader 大小

```asm
; 优化 Stage 2 代码，减少占用扇区
; 或将部分功能移到内核
```

#### 方案 3: 使用验证脚本

```bash
# 每次构建后自动验证
add_custom_command(TARGET boot_img POST_BUILD
    COMMAND ${PYTHON} ${CMAKE_SOURCE_DIR}/scripts/verify_disk_layout.py
        ${CMAKE_BINARY_DIR}/bootloader.bin
        ${CMAKE_BINARY_DIR}/kernel.bin
    # 失败会中断构建
)
```

### 关键要点

- **Stage 2 结束地址**: 0x7E00 + (BOOTLOADER_SECTORS × 512)
- **内核起始地址**: KERNEL_LOAD_SEGMENT × 16 + KERNEL_LOAD_OFFSET
- **最小间隙**: 建议 ≥ 512 字节
- **验证工具**: `verify_disk_layout.py`

## 3. 配置生成错误

### 3.1 症状：boot_config.inc 不存在

```
fatal error: boot_config.inc: No such file or directory
```

### 根本原因

**问题**: CMake 构建顺序错误，配置未先生成

**分析**:
```cmake
# 错误：bootloader 不依赖配置
add_custom_target(bootloader DEPENDS
    ${CMAKE_BINARY_DIR}/bootloader.bin
)
```

### 解决方案

#### 方案 1: 确保依赖关系

```cmake
# boot/CMakeLists.txt
add_custom_command(
    OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        ${CMAKE_CURRENT_SOURCE_DIR}/boot_config.inc
        ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc
    COMMENT "Generating boot configuration"
)

add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/bootloader.bin
    COMMAND ${NASM} -f bin
        -I${CMAKE_CURRENT_BINARY_DIR}/    # 添加包含路径
        ${CMAKE_CURRENT_SOURCE_DIR}/bootloader.asm
        -o ${CMAKE_BINARY_DIR}/bootloader.bin
    DEPENDS
        ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc  # 依赖配置
    COMMENT "Building bootloader"
)
```

#### 方案 2: 清理重建

```bash
rm -rf build/boot/*
cmake --build . --target bootloader
```

#### 方案 3: 检查包含路径

```asm
; bootloader.asm
; 确保使用正确的路径
%include "boot_config.inc"     ; CMAKE_CURRENT_BINARY_DIR 在 -I 中
```

### 关键要点

- **依赖声明**: DEPENDS 必须包含 boot_config.inc
- **包含路径**: `-I${CMAKE_CURRENT_BINARY_DIR}/`
- **清理重建**: 出现问题时先清理再构建

## 4. CHS 参数计算错误

### 4.1 症状：磁盘读取错误

```
DISK ERROR! Cannot read kernel
04  (扇区未找到)
```

### 根本原因

**问题**: CHS 参数计算错误，导致读取错误的扇区

### 诊断步骤

#### 1. 验证 CHS 计算

```python
# LBA 到 CHS 转换
def lba_to_chs(lba, spt=63, heads=16):
    cylinder = lba // (spt * heads)
    head = (lba // spt) % heads
    sector = (lba % spt) + 1    # 注意 +1
    return cylinder, head, sector

# 测试
print(lba_to_chs(3))  # 应该输出 (0, 0, 4)
```

#### 2. 检查 boot_config.inc

```bash
grep "CHS" build/boot/boot_config.inc

# 输出应该类似：
# %define KERNEL_CHS_CYLINDER       0
# %define KERNEL_CHS_HEAD           0
# %define KERNEL_CHS_SECTOR         5
```

#### 3. 反汇编验证

```bash
ndisasm -b 16 build/bootloader.bin | grep -E "mov ch,|mov cl,|mov dh," | head -3
```

### 解决方案

#### 方案 1: 修正 CHS 计算

```cmake
# GenerateKernelSize.cmake
# 确保 LBA 是 0-based
math(EXPR KERNEL_LBA_ZERO "${KERNEL_LBA_START} - 1")

# CHS 计算
math(EXPR CHS_CYLINDER "${KERNEL_LBA_ZERO} / (${SECTORS_PER_TRACK} * ${HEADS})")
math(EXPR CHS_HEAD "(${KERNEL_LBA_ZERO} / ${SECTORS_PER_TRACK}) % ${HEADS}")
math(EXPR CHS_SECTOR "(${KERNEL_LBA_ZERO} % ${SECTORS_PER_TRACK}) + 1")
```

#### 方案 2: 验证 LBA 起始

```asm
; boot_config.inc
; 确保 KERNEL_LBA_START 正确
; bootloader = 3 sectors
; kernel starts at LBA 3 (0-based) = sector 4 (1-based)
%define KERNEL_LBA_START          4       ; 1-based
```

### 关键要点

- **LBA 起始**: bootloader 扇区数（当前 = 3）
- **CHS 扇区号**: 是 1-based，需要 +1
- **验证工具**: `verify_disk_layout.py` 会报告 CHS 参数

## 5. 构建系统问题

### 5.1 症状：验证脚本未运行

```
构建完成但没有验证输出
```

### 根本原因

**问题**: POST_BUILD 命令未正确配置

### 解决方案

#### 方案 1: 检查 CMakeLists.txt

```cmake
# 根 CMakeLists.txt
add_custom_command(TARGET boot_img POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E echo ""
    COMMAND ${CMAKE_COMMAND} -E echo "Verifying disk layout..."
    COMMAND ${PYTHON} ${CMAKE_SOURCE_DIR}/scripts/verify_disk_layout.py
        ${CMAKE_BINARY_DIR}/bootloader.bin
        ${CMAKE_BINARY_DIR}/kernel.bin
    COMMENT "Verifying disk layout"
)
```

#### 方案 2: 确保找到 Python

```cmake
# 在根 CMakeLists.txt 中
find_program(PYTHON python3 REQUIRED)

if(NOT PYTHON)
    message(FATAL_ERROR "Python 3 not found")
endif()

message(STATUS "Found Python: ${PYTHON}")
```

#### 方案 3: 手动运行验证

```bash
# 如果自动验证失败，手动运行
cd build
python3 ../scripts/verify_disk_layout.py \
    bootloader.bin \
    kernel.bin
```

### 5.2 症状：Bootloader 大小不正确

```
Stage 1 size: 0 bytes
ERROR: Invalid MBR signature
```

### 根本原因

**问题**: Bootloader 编译失败或大小异常

### 解决方案

#### 方案 1: 检查编译输出

```bash
# 详细编译输出
cmake --build . --verbose

# 检查文件大小
ls -la build/bootloader.bin
```

#### 方案 2: 验证 MBR 签名

```bash
# 检查最后两字节
xxd -s 510 -l 2 build/bootloader.bin

# 应该输出：
# 000001fe: 55aa
```

#### 方案 3: 检查源码

```asm
; bootloader.asm
; 确保末尾有：
times 510-($-$$) db 0
dw 0xAA55
```

## 6. 调试技巧总结

### 6.1 快速诊断流程

```
遇到问题时：
1. 运行 verify_disk_layout.py
2. 检查 boot_config.inc 内容
3. 反汇编 bootloader.bin 查找关键指令
4. 使用 QEMU -d int 追踪 BIOS 调用
5. 使用 GDB 单步调试
```

### 6.2 常用调试命令

```bash
# 1. 验证布局
python3 scripts/verify_disk_layout.py build/bootloader.bin build/kernel.bin

# 2. 检查配置
cat build/boot/boot_config.inc

# 3. 反汇编
ndisasm -b 16 build/bootloader.bin | grep -A 10 "load_kernel"

# 4. 十六进制查看
xxd build/boot.img | head -40

# 5. QEMU 调试
qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic -d int
```

### 6.3 错误代码参考

| 错误 | 含义 | 解决方案 |
|------|------|----------|
| AH=01 | 无效命令 | 检查 INT 13h 参数 |
| AH=02 | 地址标记未找到 | 检查 CHS/LBA 地址 |
| AH=04 | 扇区未找到 | 检查 CHS 参数 |
| AH=0C | 无效介质 | 检查磁盘大小 |
| AH=0D | 扇区数无效 | 检查 AL 值 (≤127) |

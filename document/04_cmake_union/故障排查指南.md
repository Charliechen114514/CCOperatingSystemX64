# CCOS CMake 构建系统与 C 内核 - 故障排查指南

本文档记录在使用 CMake 构建系统和开发 C 内核时遇到的问题及其解决方案。

---

## 1. CMake 配置问题

### 1.1 工具未找到

**症状**：
```
CMake Error at CMakeLists.txt:20 (find_program):
  Could not find NASM
```

**原因**：系统未安装 NASM 或 CMake 找不到

**解决方案**：
```bash
# Ubuntu/Debian
sudo apt-get install nasm

# 验证安装
which nasm
nasm -v

# 重新配置
cmake -B build
```

**替代方案** - 指定工具路径：
```bash
cmake -B build -DNASM=/custom/path/to/nasm
```

### 1.2 CMake 版本过低

**症状**：
```
CMake Error at CMakeLists.txt:1 (cmake_minimum_required):
  CMake 3.20 or higher is required.
```

**解决方案**：
```bash
# Ubuntu/Debian
sudo apt-get install cmake

# 或从官网安装最新版本
# https://cmake.org/download/
```

### 1.3 构建类型未生效

**症状**：设置了 `CMAKE_BUILD_TYPE=Debug`，但代码仍然优化

**原因**：CMake 缓存了之前的设置

**解决方案**：
```bash
# 清除缓存
rm -rf build/CMakeCache.txt
rm -rf build/CMakeFiles/

# 重新配置
cmake -B build -DCMAKE_BUILD_TYPE=Debug
```

## 2. 编译问题

### 2.1 freestanding 环境错误

**症状**：
```
error: 'memcpy' undeclared
```

**原因**：使用了标准库函数，但处于 freestanding 环境

**解决方案**：

1. 使用编译器 builtin：
```c
// GCC 会自动优化为合适实现
void *dest = __builtin_memcpy(src, size);
```

2. 自己实现：
```c
void *memcpy(void *dest, const void *src, size_t n) {
    uint8_t *d = (uint8_t *)dest;
    const uint8_t *s = (const uint8_t *)src;
    while (n--) *d++ = *s++;
    return dest;
}
```

3. 添加编译选项允许 builtin：
```cmake
add_compile_options(-fno-builtin)  # 移除此选项
```

### 2.2 64 位指针截断

**症状**：
```
warning: cast from pointer to integer of different size
```

**原因**：使用了 `int` 代替 `long` 存储指针

**解决方案**：
```c
// 错误
int addr = (int)ptr;

// 正确
long addr = (long)ptr;
// 或
uint64_t addr = (uint64_t)ptr;
```

### 2.3 代码模型错误

**症状**：
```
error: symbol 'xxx' is too large for the medium code model
```

**原因**：代码或数据超过 medium 模型限制

**解决方案**：确保使用 large 代码模型
```cmake
add_compile_options(-mcmodel=large)
```

## 3. 链接问题

### 3.1 未定义引用

**症状**：
```
ld: kernel_entry.o: in function `kernel_start':
undefined reference to `kernel_main'
```

**原因**：
1. 符号拼写错误
2. 没有链接包含该符号的文件
3. C++ 名字修饰（如果误用 C++ 编译）

**解决方案**：

1. 检查拼写：
```c
// kernel_entry.asm
extern kernel_main    ; 确保与 C 函数名一致
```

```c
// kernel_main.c
void kernel_main(void) { ... }  // 确保与汇编声明一致
```

2. 确保链接所有文件：
```bash
# 检查链接命令包含所有 .o 文件
ld -m elf_x86_64 -T linker.ld \
   kernel_entry.o \
   kernel_main.o \
   -o kernel.elf
```

3. 使用 C 链接（避免 C++ 名字修饰）：
```c
#ifdef __cplusplus
extern "C" {
#endif

void kernel_main(void);

#ifdef __cplusplus
}
#endif
```

### 3.2 BSS 符号未定义

**症状**：
```
undefined reference to `__bss_start'
```

**原因**：链接脚本没有导出这些符号

**解决方案**：确保链接脚本包含：
```ld
.bss : {
    __bss_start = .;
    *(.bss)
    *(.bss.*)
    *(COMMON)
    __bss_end = .;
}
```

### 3.3 入口点未定义

**症状**：
```
ld: warning: cannot find entry symbol _start
```

**原因**：链接器默认查找 `_start`，但我们的入口是 `kernel_start`

**解决方案**：在链接脚本中明确指定：
```ld
ENTRY(kernel_start)
```

或在命令行指定：
```bash
ld -e kernel_start ...
```

## 4. 运行时问题

### 4.1 三重故障 (Triple Fault)

**症状**：QEMU 直接退出，无任何输出

**原因**：通常是栈指针或 GDT 问题

**调试步骤**：

1. 在汇编入口添加调试输出：
```assembly
kernel_start:
    ; 先输出一些内容证明到了这里
    mov rdi, 0xB8000
    mov word [rdi], 0x1F4B  ; 'K' for Kernel entry

    ; 然后设置栈
    mov rsp, 0x80000
```

2. 检查栈地址是否有效：
```assembly
; 确保栈地址在可用范围内
mov rsp, 0x80000      ; 好的
mov rsp, 0x0          ; 不好 - 会三重故障
mov rsp, 0xB8000      ; 不好 - VGA 地址
```

3. 使用 QEMU 调试模式：
```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -d int,cpu_reset
```

### 4.2 C 代码未执行

**症状**：只看到汇编输出的 'X'，没看到 C 代码输出的 'C'

**原因**：
1. 跳转地址错误
2. C 函数调用约定错误
3. 栈未正确设置

**调试步骤**：

1. 检查 `extern` 声明：
```assembly
; 必须声明外部函数
extern kernel_main
```

2. 检查调用：
```assembly
; 使用 call 而不是 jmp
call kernel_main
```

3. 使用 GDB 单步：
```gdb
(gdb) break *kernel_start
(gdb) continue
(gdb) stepi   # 单步到 call 指令
(gdb) stepi   # 应该进入 kernel_main
(gdb) list    # 如果成功，应该看到 C 源码
```

### 4.3 BSS 未清零导致的问题

**症状**：未初始化变量包含随机值

**验证**：
```c
static int uninitialized;

void kernel_main(void) {
    // 应该是 0，如果不是则 BSS 未清零
    if (uninitialized != 0) {
        // 显示错误标记
        volatile uint16_t *vga = (uint16_t *)0xB8000;
        vga[0] = 0x1F45;  // 'E' for Error
    }
}
```

**解决方案**：确保汇编代码清零 BSS：
```assembly
extern __bss_start
extern __bss_end

cld
mov rdi, __bss_start
mov rcx, __bss_end
sub rcx, rdi
shr rcx, 3          ; 转换为 qwords
xor eax, eax
rep stosq
```

## 5. 内存布局问题

### 5.1 内核未加载到正确地址

**症状**：调试器显示代码在错误的地址

**原因**：链接脚本地址与 bootloader 不一致

**解决方案**：确保一致：

链接脚本：
```ld
. = 0x10000;
```

bootloader：
```assembly
; 加载到 0x10000
mov ax, 0x1000 >> 4
mov es, ax
mov bx, 0           ; 偏移 0
```

验证：
```bash
# 检查 ELF 中的地址
readelf -h build/kernel.elf | grep "Entry point"

# 检查符号地址
nm build/kernel.elf | grep kernel_start
```

### 5.2 栈溢出

**症状**：随机崩溃或三重故障

**原因**：栈太小或递归太深

**诊断**：
```assembly
; 在栈底放一个魔法值
mov rdi, 0x80000 - 8
mov qword [rdi], 0xDEADBEEFDEADBEEF

; 在代码中检查
mov rax, [0x80000 - 8]
cmp rax, 0xDEADBEEFDEADBEEF
jne stack_corrupted
```

**解决方案**：
1. 增大栈空间
2. 使用链接脚本专门分配栈段
3. 实现栈溢出检测

## 6. 构建产物问题

### 6.1 boot.img 大小不正确

**症状**：镜像文件大小不对

**诊断**：
```bash
ls -lh build/boot.img
# bootloader (2 sectors) + kernel
```

**计算正确大小**：
```bash
# 检查各组件大小
ls -lh build/bootloader.bin
ls -lh build/kernel.bin

# 预期：
# bootloader.bin <= 1024 字节 (2 sectors)
# kernel.bin 可变
```

**解决方案**：检查 dd 命令
```bash
# 确保 dd 正确执行
dd if=bootloader.bin of=boot.img bs=512 count=2 conv=notrunc
dd if=kernel.bin of=boot.img bs=512 seek=2 conv=notrunc
```

### 6.2 kernel.bin 过大

**症状**：内核二进制比预期大很多

**原因**：
1. 未优化构建
2. 包含了调试信息
3. 链接进了不需要的段

**诊断**：
```bash
# 比较 ELF 和 BIN 大小
ls -lh build/kernel.elf
ls -lh build/kernel.bin

# 如果 BIN 比 ELF 大很多，说明有问题
```

**解决方案**：
1. 检查丢弃段是否生效：
```bash
readelf -S build/kernel.elf | grep DISCARD
```

2. 使用 Release 构建：
```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
```

## 7. 调试验证清单

### 7.1 验证构建步骤

```bash
# 1. 确认工具存在
which nasm gcc ld qemu-system-x86_64

# 2. 清理并重新构建
rm -rf build
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --verbose

# 3. 验证输出文件
ls -lh build/bootloader.bin
ls -lh build/kernel.bin
ls -lh build/kernel.elf
ls -lh build/boot.img

# 4. 验证 ELF 结构
readelf -h build/kernel.elf
readelf -S build/kernel.elf
nm build/kernel.elf
```

### 7.2 验证内存布局

```bash
# 检查符号地址
nm build/kernel.elf | grep -E "kernel_start|kernel_main|__bss"

# 检查段地址
objdump -h build/kernel.elf

# 应该看到：
# .text 从 0x10000 开始
# BSS 有 __bss_start 和 __bss_end 符号
```

### 7.3 验证运行时

```bash
# 1. 启动 QEMU
qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic

# 预期输出：
# (如果一切正常) 系统暂停或显示标记字符

# 2. 启动调试
qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S

# 3. 在另一个终端
gdb build/kernel.elf
(gdb) target remote :1234
(gdb) break kernel_main
(gdb) continue
```

## 8. 常见错误速查

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `Could not find NASM` | 工具未安装 | `sudo apt-get install nasm` |
| `undefined reference to 'kernel_main'` | 链接问题 | 确保链接所有 .o 文件 |
| `symbol is too large` | 代码模型错误 | 使用 `-mcmodel=large` |
| `Triple fault` | 栈或 GDT 问题 | 检查栈指针和 GDT 设置 |
| `__bss_start undefined` | 链接脚本错误 | 添加 BSS 符号定义 |
| `'memcpy' undeclared` | 标准库问题 | 使用 builtin 或自己实现 |
| `cannot find entry symbol` | 入口点未定义 | 在链接脚本中 `ENTRY()` |

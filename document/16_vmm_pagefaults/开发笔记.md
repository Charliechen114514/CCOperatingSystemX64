## 为什么需要虚拟内存管理

### 1. 从物理内存管理到虚拟内存管理

Stage 15 实现了物理帧管理器（pframe），能够分配和释放 4KB 的物理内存帧。但这存在以下限制：

- **地址空间限制**：只能直接访问物理内存
- **内存碎片**：物理内存可能不连续
- **缺乏保护**：所有代码对内存有相同访问权限
- **无法支持多进程**：没有地址空间隔离

### 2. 虚拟内存的优势

虚拟内存管理解决了上述问题：

- **统一地址空间**：每个进程看到独立的虚拟地址空间
- **内存保护**：通过页表项标志实现读写权限控制
- **按需分页**：只在需要时分配物理内存
- **内存映射**：灵活映射物理内存到虚拟地址

### 3. 为什么现在实现

在 Stage 15 物理帧管理完成后，我们已经具备了：
- 可靠的物理内存分配器
- 内存检测信息
- 中断处理基础设施

这些是 VMM 实现的必要前置条件。

## x86_64 分页机制基础

### 1. 四级页表结构

x86_64 使用四级页表结构：

```
虚拟地址格式 (64位):
┌────────┬────────┬────────┬────────┬────────┬─────┐
│  PML4  │  PDPT  │   PD   │   PT   │ Offset│     │
│  9 bit │  9 bit │  9 bit │  9 bit │ 12 bit│     │
│[63:48] │ [47:39]│ [38:30]│ [29:21]│ [20:12]│[11:0]│
└────────┴────────┴────────┴────────┴────────┴─────┘
```

每级页表有 512 个项（2^9），每个项 8 字节，页表大小 4KB。

### 2. 页表项格式

```c
typedef union {
    struct {
        uint64_t present      : 1;   // Bit 0: 页是否在内存中
        uint64_t writable     : 1;   // Bit 1: 是否可写
        uint64_t user         : 1;   // Bit 2: 用户/内核模式
        uint64_t pwt          : 1;   // Bit 3: Write-Through
        uint64_t pcd          : 1;   // Bit 4: Cache Disable
        uint64_t accessed     : 1;   // Bit 5: 是否被访问
        uint64_t dirty        : 1;   // Bit 6: 是否被修改
        uint64_t pat          : 1;   // Bit 7: PAT/PS
        uint64_t global       : 1;   // Bit 8: 全局页
        uint64_t available    : 3;   // Bit 9-11: OS 可用
        uint64_t frame        : 40;  // Bit 12-51: 物理帧号
        uint64_t available2   : 11;  // Bit 52-62: OS 可用
        uint64_t nx           : 1;   // Bit 63: 禁止执行
    } bits;
    uint64_t value;
} page_table_entry_t;
```

### 3. 地址转换过程

```
1. 从 CR3 寄存器获取 PML4 物理地址
2. 使用 PML4 索引获取 PDPT 地址
3. 使用 PDPT 索引获取 PD 地址
4. 使用 PD 索引获取 PT 地址
5. 使用 PT 索引获取物理页地址
6. 加上偏移量得到最终物理地址
```

## 设计决策

### 1. 地址空间布局

#### 决策：采用高半内核映射

```c
// 直接物理映射区域
#define KERNEL_VIRT_BASE   0xFFFF800000000000ULL
#define KERNEL_VIRT_END    0xFFFF800001000000ULL

// 内核代码/数据区域
#define KERNEL_TEXT_BASE   0xFFFFFFFF80000000ULL
#define KERNEL_DATA_BASE   0xFFFFFFFF80200000ULL

// 内核堆区域
#define KERNEL_HEAP_BASE   0xFFFFFFFF81000000ULL
#define KERNEL_HEAP_MAX    0xFFFFFFFF89000000ULL

// 用户空间
#define USER_BASE          0x0000000000400000ULL
#define USER_END           0x00007FFFFFFFFFFFULL
```

**理由**：
- 符合 x86_64 规范的规范地址要求
- 用户空间和内核空间清晰分离
- 便于实现共享内核映射

### 2. 直接物理映射大小

#### 决策：初始映射 512MB

```c
static page_result_t establish_direct_map(void) {
    // 映射前 512MB 物理内存
    for (int i = 0; i < 256; i++) {
        physical_addr_t paddr = i * 0x200000;  // 2MB 对齐
        pd->entries[i].value = (paddr & PTE_ADDR_MASK) |
                               PAGE_PRESENT | PAGE_WRITE | PAGE_HUGE_PD;
    }
}
```

**理由**：
- 2MB 巨大页减少页表开销
- 512MB 对当前系统足够
- 可按需扩展

### 3. 模块分离

#### 决策：VMM 分为三个模块

```
page.c/h  - 页表底层操作
vmm.c/h   - 高层虚拟内存管理
fault.c/h - 页错误处理
```

**理由**：
- 职责清晰
- 便于测试
- 支持未来扩展

### 4. 巨大页支持

#### 决策：支持 2MB 和 1GB 巨大页

```c
typedef enum {
    VMAP_FLAG_HUGE_2MB = (1 << 5),
    VMAP_FLAG_HUGE_1GB = (1 << 6),
} vmap_flags_t;
```

**理由**：
- 减少 TLB 压力
- 提高内存访问效率
- 符合 x86_64 硬件能力

## 实现细节

### 1. 直接物理映射建立

Bootloader 只映射了低 2MB 内存。内核需要扩展直接映射：

```c
static page_result_t establish_direct_map(void) {
    physical_addr_t pml4_phys = s_kernel_pml4;

    // 使用身份映射访问 PML4
    volatile pml4_t* pml4 = (volatile pml4_t*)TEMP_IDENTITY_VIRT(pml4_phys);

    // 检查 PML4[256] (直接映射区域)
    if (!pml4->entries[256].bits.present) {
        // 获取 bootloader 的 PD (在低 2MB 范围内)
        volatile pd_t* pd = (volatile pd_t*)TEMP_IDENTITY_VIRT(0xB000);

        // 扩展 PD 以映射 512MB
        for (int i = 0; i < 256; i++) {
            if (!pd->entries[i].bits.present) {
                physical_addr_t paddr = i * 0x200000;
                pd->entries[i].value = (paddr & PTE_ADDR_MASK) |
                                       PAGE_PRESENT | PAGE_WRITE | PAGE_HUGE_PD;
            }
        }

        // 设置 PML4[256]
        pml4->entries[256].value = (0xA000 & PTE_ADDR_MASK) |
                                   PAGE_PRESENT | PAGE_WRITE;
    }

    // 刷新 TLB
    __asm__ volatile("mov %0, %%cr3" : : "r"((uint64_t)pml4_phys) : "memory");

    s_direct_map_established = true;
    return PAGE_OK;
}
```

### 3. 虚拟地址分配

内核空间虚拟地址分配使用简单线性搜索：

```c
static vmm_result_t find_free_virt_range(uint64_t size, virtual_addr_t* out_vaddr) {
    virtual_addr_t hint = s_kernel_virt_hint;
    virtual_addr_t end = KERNEL_HEAP_MAX;

    // 大小决定对齐
    uint64_t alignment = (size >= PAGE_SIZE_2MB) ? PAGE_SIZE_2MB : PAGE_SIZE;
    hint = (hint + alignment - 1) & ~(alignment - 1);

    // 线性搜索空闲区域
    while (hint + size <= end) {
        if (!check_region_collision(hint, hint + size)) {
            *out_vaddr = hint;
            s_kernel_virt_hint = hint + size;
            return VMM_OK;
        }
        hint += alignment;
    }

    return VMM_ERR_OOM;
}
```

## 页错误处理策略

### 1. 错误码解析

```c
void pf_parse_error_code(uint64_t error_code, page_fault_info_t* info) {
    info->error_code = error_code;
    info->present = (error_code & PF_ERR_PRESENT) != 0;
    info->write = (error_code & PF_ERR_WRITE) != 0;
    info->user = (error_code & PF_ERR_USER) != 0;
    info->reserved_bit = (error_code & PF_ERR_RESERVED) != 0;
    info->instruction_fetch = (error_code & PF_ERR_INSTR) != 0;
}
```

### 2. 处理策略

#### 内核态页错误

当前策略：**终止系统**

**理由**：内核态页错误表示内核 bug，不应继续运行。

## 常见陷阱与注意事项

### 1. 直接映射时机

**陷阱**：在直接映射建立前使用 `phys_to_virt()`

**解决方案**：
```c
// 错误：在 establish_direct_map() 前使用
void* virt = phys_to_virt(paddr);  // 虚拟地址无效！

// 正确：使用身份映射（仅在低 2MB 有效）
void* virt = TEMP_IDENTITY_VIRT(low_2mb_paddr);
```

### 2. TLB 一致性

**陷阱**：修改页表后未刷新 TLB

**解决方案**：
```c
// 修改页表后总是刷新 TLB
page_invalidate_tlb(vaddr);
// 或
__asm__ volatile("mov %0, %%cr3" : : "r"(cr3_value) : "memory");
```

### 3. 巨大页对齐

**陷阱**：地址未正确对齐

**解决方案**：
```c
// 验证对齐
if ((vaddr & (page_size - 1)) != 0) {
    return PAGE_ERR_ALIGNMENT;
}
if ((paddr & (page_size - 1)) != 0) {
    return PAGE_ERR_ALIGNMENT;
}
```

### 4. 页表项检查

**陷阱**：假设页表已存在

**解决方案**：
```c
// 总是检查 Present 位
if (!pml4e->bits.present) {
    return PAGE_ERR_NOT_PRESENT;
}
```

### 5. 用户空间映射

**陷阱**：忘记设置 USER 标志

**解决方案**：
```c
// 用户映射必须设置 USER 标志
if (vmm_is_user_addr(vaddr)) {
    flags |= VMAP_FLAG_USER;
}
```

### 6. CR2 寄存器读取

**陷阱**：在页错误处理外读取 CR2

**注意**：CR2 只在页错误时有效，其他时间读取值无意义。

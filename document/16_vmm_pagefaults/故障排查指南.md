## 初始化问题

### 问题 1.1: page_init() 返回 PAGE_ERR_OOM

**症状**:
```
[PAGE] Failed to establish direct mapping!
```

**原因**:
- 物理帧分配器未初始化
- 可用物理内存不足
- 物理帧分配失败

**解决方案**:
1. 确保 `pframe_init()` 在 `page_init()` 之前调用
2. 检查物理内存统计：
```c
pframe_stats_t stats;
pframe_get_stats(&stats);
klog_trace("Free frames: %llu / %llu\n", stats.free_frames, stats.total_frames);
```
3. 确保内存检测正确完成

### 问题 1.2: s_direct_map_established 为 false

**症状**:
访问物理地址转换时系统崩溃

**原因**:
- `establish_direct_map()` 未执行或失败
- PML4[256] 未正确设置

**解决方案**:
1. 检查 PML4 状态：
```c
physical_addr_t pml4 = page_get_pml4();
klog_trace("Kernel PML4: 0x%X\n", pml4);
page_dump_pml4(pml4);
```
2. 验证 bootloader PD 存在：
```bash
# 在 QEMU Monitor 中
xp/512x 0xB000  # 检查 PD 内容
```

### 问题 1.3: vmm_init() 后统计信息为 0

**症状**:
```c
vmm_stats_t stats;
vmm_get_stats(&stats);
// stats.total_pages == 0
```

**原因**:
- VMM 初始化顺序错误
- 内核 PML4 未正确获取

**解决方案**:
1. 确保正确的初始化顺序：
```c
pframe_init();
page_init();
vmm_init();
pf_init();
```

## 页映射问题

### 问题 2.1: page_map_page() 返回 PAGE_ERR_ALIGNMENT

**症状**:
```
[PAGE] Virtual address not aligned to 2097152 bytes
```

**原因**:
- 使用巨大页时地址未正确对齐

**解决方案**:
1. 2MB 页需要 2MB 对齐：
```c
// 错误
virtual_addr_t vaddr = 0x1000;  // 未对齐
vmm_alloc_pages(1, VMAP_FLAG_HUGE_2MB);

// 正确：让 VMM 自动选择对齐地址
virtual_addr_t vaddr = vmm_alloc_pages(1, VMAP_FLAG_HUGE_2MB);
```

### 问题 2.2: page_map_page() 返回 PAGE_ERR_ALREADY_MAPPED

**症状**:
```
[PAGE] Page already mapped at 0x...
```

**原因**:
- 地址已被映射
- 尝试重复映射

**解决方案**:
1. 检查现有映射：
```c
page_query_result_t result;
if (page_query(pml4, vaddr, &result) == PAGE_OK && result.present) {
    // 已映射，先取消映射
    page_unmap_page(pml4, vaddr, false);
}
```

### 问题 2.3: 映射成功但访问时崩溃

**症状**:
映射完成但访问虚拟地址时系统挂起

**原因**:
- TLB 未刷新
- 页表标志错误
- 映射到错误的物理地址

**解决方案**:
1. 检查映射是否正确建立：
```c
page_query_result_t result;
page_query(pml4, vaddr, &result);
klog_trace("Mapped: 0x%llX -> 0x%X (flags: 0x%llX)\n",
          vaddr, result.phys_addr, result.flags);
```

2. 确认 TLB 刷新：
```c
// page_map_page 应该自动刷新
// 如果手动修改页表，需要：
__asm__ volatile("invlpg (%0)" : : "r"(vaddr) : "memory");
```

3. 验证物理地址可访问：
```c
// 使用直接映射访问
physical_addr_t paddr = ...;
void* direct_vaddr = phys_to_virt(paddr);
volatile uint64_t* ptr = (volatile uint64_t*)direct_vaddr;
ptr[0] = 0x12345678;  // 测试写入
```

### 问题 2.4: page_query 返回 PAGE_ERR_NOT_PRESENT

**症状**:
查询已映射地址返回不存在

**原因**:
- 查询错误的 PML4
- 地址未实际映射
- TLB 缓存了旧状态

**解决方案**:
1. 确认使用正确的 PML4：
```c
physical_addr_t pml4 = page_get_pml4();  // 内核 PML4
// 或用户 PML4
```

2. 转储完整页表路径：
```c
page_dump_mapping(vaddr, 4);  // 完整转储
```

## 页错误处理问题

### 问题 3.1: 页错误未触发处理函数

**症状**:
访问无效地址时系统直接重启

**原因**:
- 页错误处理器未注册
- IDT 条目配置错误

**解决方案**:
1. 确认页错误处理器已注册：
```c
// 在 kernel_init() 中
pf_init();  // 注册 IDT[14]
```

2. 检查 IDT 配置：
```c
// IDT[14] 应指向 pf_handler
extern void pf_handler(interrupt_frame_t*, uint64_t);
```

### 问题 3.2: 页错误时 CR2 值异常

**症状**:
CR2 显示不是预期的故障地址

**原因**:
- 级联页错误
- 栈损坏导致 RIP 错误

**解决方案**:
1. 打印完整中断帧：
```c
void pf_handler(interrupt_frame_t* frame, uint64_t error_code) {
    klog_error("RIP: 0x%llX, RSP: 0x%llX\n", frame->rip, frame->rsp);
    klog_error("RBP: 0x%llX, RAX: 0x%llX\n", frame->rbp, frame->rax);
    // ...
}
```

### 问题 3.3: 用户态页错误被误判为内核态

**症状**:
用户代码访问错误时显示内核页错误

**原因**:
- 错误码 U 位解析错误
- CPL 检查不正确

**解决方案**:
1. 验证错误码解析：
```c
page_fault_info_t info;
pf_parse_error_code(error_code, &info);
klog_error("User mode: %s (error_code: 0x%llX)\n",
          info.user ? "yes" : "no", error_code);
```

### 问题 3.4: 页错误死循环

**症状**:
页错误处理器不断被触发

**原因**:
- 处理器本身触发页错误
- 未能正确解决页错误

**解决方案**:
1. 在页错误处理器入口设置断点
2. 检查页错误地址是否每次相同
3. 验证处理器代码不访问用户内存

## 直接映射问题

### 问题 4.1: 直接映射地址访问失败

**症状**:
```c
void* v = phys_to_virt(0x100000);
volatile uint32_t* ptr = (volatile uint32_t*)v;
*ptr = 0x12345678;  // 崩溃
```

**原因**:
- 物理地址超出直接映射范围
- 直接映射未正确建立

**解决方案**:
1. 检查物理地址是否在映射范围内：
```c
#define DIRECT_MAP_MAX  (512 * 1024 * 1024)  // 512MB

if (phys >= DIRECT_MAP_MAX) {
    // 需要使用 vmm_map_physical
}
```

2. 验证直接映射状态：
```c
page_query_result_t result;
virtual_addr_t vaddr = KERNEL_VIRT_BASE;
if (page_query(page_get_pml4(), vaddr, &result) == PAGE_OK) {
    klog_trace("Direct map OK: 0x%llX -> 0x%X\n",
              vaddr, result.phys_addr);
}
```

### 问题 4.2: 高物理内存无法访问

**症状**:
超过 512MB 的物理内存无法访问

**原因**:
- 默认直接映射只有 512MB
- 需要扩展或使用临时映射

**解决方案**:
1. 使用 `vmm_map_physical` 映射高内存：
```c
physical_addr_t high_mem = 0x40000000;  // 1GB
virtual_addr_t vaddr = vmm_map_physical(high_mem, VMAP_FLAG_WRITE);
if (vaddr != 0) {
    // 通过 vaddr 访问
    // ...
    vmm_unmap_physical(vaddr);
}
```

## 巨大页问题

### 问题 5.1: 巨大页分配失败

**症状**:
```c
virtual_addr_t vaddr = vmm_alloc_pages(1, VMAP_FLAG_HUGE_2MB);
// vaddr == 0
```

**原因**:
- 没有足够的连续物理内存
- 对齐要求无法满足

**解决方案**:
1. 检查可用物理内存：
```c
pframe_stats_t stats;
pframe_get_stats(&stats);
klog_trace("Free: %llu frames (%llu MB)\n",
          stats.free_frames,
          (stats.free_frames * PAGE_SIZE) / (1024 * 1024));
```

2. 回退到 4KB 页：
```c
virtual_addr_t vaddr = vmm_alloc_pages(512, VMAP_FLAG_WRITE);
// 512 * 4KB = 2MB
```

### 问题 5.2: 巨大页映射后访问异常

**症状**:
映射成功但访问时只部分可访问

**原因**:
- PD 项 PS 位未设置
- 使用了错误的页级别

**解决方案**:
1. 查询映射类型：
```c
page_query_result_t result;
page_query(pml4, vaddr, &result);
if (result.is_huge) {
    klog_trace("Huge page mapping confirmed\n");
} else {
    klog_error("Expected huge page, got 4KB page!\n");
}
```

## 用户空间问题

### 问题 6.1: 用户映射无法从内核访问

**症状**:
```c
vmm_map_to_user(user_pml4, 0x400000, paddr, 1, VMAP_FLAG_USER);
// 从内核访问 0x400000 失败
```

**原因**:
- 用户地址空间与内核地址空间分离
- 需要切换 CR3

**解决方案**:
1. 从内核访问用户内存需要临时映射：
```c
virtual_addr_t kernel_vaddr = vmm_map_physical(paddr, VMAP_FLAG_WRITE);
// 使用 kernel_vaddr 访问
// ...
vmm_unmap_physical(kernel_vaddr);
```

### 问题 6.2: 创建用户地址空间后无法切换

**症状**:
```
vmm_create_user_space(&user_pml4);
// 如何切换到用户地址空间？
```

**原因**:
- 尚未实现进程切换
- 需要修改 CR3

**解决方案**:
1. 加载用户 PML4（需要保存内核状态）：
```c
// 注意：这仅用于演示，实际进程切换更复杂
physical_addr_t old_pml4 = page_get_cr3() & ~0xFFFULL;
page_set_cr3(user_pml4);
// ... 执行用户代码 ...
page_set_cr3(old_pml4);
```

## 系统稳定性问题

### 问题 7.1: 随机崩溃

**症状**:
系统运行一段时间后随机崩溃

**原因**:
- 页表损坏
- 内存越界
- 栈溢出

**解决方案**:
1. 启用栈保护：
```bash
# 在 CMakeLists.txt 中
target_compile_options(kernel PRIVATE -fstack-protector-all)
```

2. 检查页表完整性：
```c
// 定期检查关键页表
page_dump_mapping(KERNEL_TEXT_BASE, 4);
page_dump_mapping(KERNEL_DATA_BASE, 4);
```

### 问题 7.2: 内存泄漏

**症状**:
可用内存持续减少

**原因**:
- 虚拟页未释放
- 物理页未释放

**解决方案**:
1. 检查 VMM 统计：
```c
vmm_stats_t vmm_stats;
vmm_get_stats(&vmm_stats);

pframe_stats_t pframe_stats;
pframe_get_stats(&pframe_stats);

klog_trace("VMM pages: %llu, PFrame free: %llu\n",
          vmm_stats.mapped_pages, pframe_stats.free_frames);
```

2. 确保成对调用：
```c
vaddr = vmm_alloc_pages(count, flags);
// ... 使用 ...
vmm_free_pages(vaddr, count);  // 必须调用
```

## 调试技巧

### 技巧 1: 使用 QEMU Monitor 检查页表

```bash
# 在 QEMU Monitor 中
info mem                  # 查看内存映射
xp/512x 0xFFFF800000000000  # 查看直接映射内容
info registers            # 查看 CR3, CR2
```

### 技巧 2: GDB 页表检查

```gdb
# 查看页表项
x/16gx 0xFFFF800000009000  # PML4

# 设置断点
b pf_handler
b page_map_page

# 检查变量
print s_kernel_pml4
print s_direct_map_established
```

### 技巧 3: 串口日志

```c
// 在关键点添加日志
klog_trace("[DEBUG] Entering page_map_page\n");
klog_trace("[DEBUG] vaddr=0x%llX, paddr=0x%X\n", vaddr, paddr);
```

### 技巧 4: 转储页表层次

```c
// 完整转储一个地址的页表路径
page_dump_mapping(0xFFFFFFFF80000000, 4);
// 输出 PML4 -> PDPT -> PD -> PT 完整路径
```

### 技巧 5: 统计信息

```c
// 定期输出统计信息
vmm_dump();           // VMM 统计
page_dump_pml4(pml4); // PML4 摘要
```

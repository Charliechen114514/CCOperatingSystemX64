# 内存操作与串口驱动 - 故障排查指南

本文档提供内存操作和串口驱动阶段常见问题的诊断和解决方案。

---

## 1. 内存函数问题

### 1.1 memset 填充不正确

**症状**: 内存未按预期填充

**可能原因**:

| 原因 | 检查方法 | 解决方案 |
|------|----------|----------|
| 字节截断 | 检查填充值 | memset 只填充低字节 |
| 指针错误 | 验证指针有效性 | 确保指针正确 |
| 大小计算错误 | 检查 size 参数 | 使用 sizeof 而非魔法数字 |

**调试步骤**:
```c
// 常见错误：期望填充 0x1234 但实际填充 0x34
memset(buffer, 0x1234, 100);  // 错误！
// 实际填充为 0x34

// 正确做法：使用期望的字节值
memset(buffer, 0x34, 100);    // 填充 0x34

// 填充模式需要循环
for (int i = 0; i < 100; i++) {
    buffer[i] = pattern;
}
```

**GDB 调试**:
```gdb
# 查看内存内容
(gdb) x/20bx buffer
(gdb) print buffer[0]
(gdb) print buffer[1]
```

### 1.2 memcpy 导致数据损坏

**症状**: 拷贝后数据不正确

**可能原因**:
1. 内存重叠导致覆盖
2. 源/目标指针错误
3. 大小参数不正确

**解决方案**:
```c
// 检查内存重叠
if (dest < src && dest + n > src) {
    // 需要使用 memmove
    memmove(dest, src, n);
} else {
    memcpy(dest, src, n);
}

// 调试时使用 memmove 替代 memcpy
// memmove 总是安全的，虽然稍慢
```

**检测方法**:
```bash
# 使用 Valgrind 检测内存重叠
valgrind --memcheck:overlap=Yes ./build/test/test_memory
```

### 1.3 memmove 性能问题

**症状**: memmove 比预期慢很多

**可能原因**:
1. 总是检测重叠（即使在无重叠情况下）
2. 编译器未优化
3. 频繁的小拷贝

**优化方案**:
```c
// 如果确定无重叠，使用 memcpy
memcpy(dest, src, n);  // 更快

// 合并小拷贝为大拷贝
// 慢
for (int i = 0; i < 1000; i++) {
    memcpy(buffer + i * 10, src, 10);
}

// 快
memcpy(buffer, src, 10000);
```

### 1.4 memcmp 返回意外值

**症状**: 比较结果与预期不符

**可能原因**:
1. 使用有符号字符比较
2. 大小计算错误
3. 未初始化内存

**调试方法**:
```c
// 逐字节显示差异
void debug_memcmp(const void* s1, const void* s2, size_t n) {
    const unsigned char* p1 = s1;
    const unsigned char* p2 = s2;

    for (size_t i = 0; i < n; i++) {
        if (p1[i] != p2[i]) {
            printf("First difference at %zu: 0x%02x vs 0x%02x\n",
                   i, p1[i], p2[i]);
            return;
        }
    }
    printf("No difference found\n");
}

// 使用
debug_memcmp(s1, s2, n);
```

## 2. 串口驱动问题

### 2.1 串口无输出

**症状**: 串口没有输出任何字符

**诊断流程**:

```
┌─────────────────────────────────────────────────────────┐
│  1. 检查 QEMU 配置                                       │
│     - 是否使用 -serial mon:stdio                         │
│     - 是否使用 -nographic                                │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  2. 检查串口初始化                                       │
│     - 是否调用 serial_init()                             │
│     - 初始化是否成功                                     │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  3. 检查硬件状态                                         │
│     - LSR 寄存器值                                       │
│     - THR 是否就绪                                       │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  4. 检查发送逻辑                                         │
│     - 字符是否正确写入                                   │
│     - 是否等待就绪                                       │
└─────────────────────────────────────────────────────────┘
```

**解决方案**:

```bash
# 1. 确认 QEMU 配置
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -nographic -serial mon:stdio

# 2. 检查串口初始化
# 在 kernel_init.c 中确认
bool init_ok = serial_init();
CCOS_ASSERT(init_ok);

# 3. 使用 GDB 检查寄存器
(gdb) print/x inb(0x3FD)  # LSR 寄存器
(gdb) print/x inb(0x3F8)  # 数据寄存器
```

### 2.2 串口输出乱码

**症状**: 输出字符显示为乱码

**可能原因**:

| 原因 | 检查方法 | 解决方案 |
|------|----------|----------|
| 波特率不匹配 | 检查除数设置 | 确保 DLL=1, DLM=0 |
| 数据格式错误 | 检查 LCR 配置 | 确保 8N1 (LCR=0x03) |
| 终端编码 | 检查终端设置 | 使用 UTF-8 |

**解决方案**:
```c
// 检查 LCR 配置
outb(SERIAL_LINE_CTRL_REG(base), 0x03);  // 8N1

// 验证波特率除数
outb(SERIAL_LINE_CTRL_REG(base), 0x80);  // 启用 DLAB
outb(SERIAL_DATA_REG(base), 1);           // DLL = 1
outb(SERIAL_INT_ENABLE_REG(base), 0);     // DLM = 0
outb(SERIAL_LINE_CTRL_REG(base), 0x03);  // 禁用 DLAB, 8N1
```

### 2.3 串口输出卡死

**症状**: 系统在串口输出时挂起

**可能原因**:
1. LSR 检测死循环
2. 端口地址错误
3. 硬件未响应

**调试方法**:
```c
// 添加超时机制
bool serial_putc_safe(char c) {
    const uint16_t base = SERIAL_COM1_BASE;
    int timeout = 1000000;

    while (timeout-- > 0) {
        if (inb(SERIAL_LINE_STATUS_REG(base)) & SERIAL_LSR_READY_TO_SEND) {
            outb(SERIAL_DATA_REG(base), c);
            return true;
        }
    }
    return false;  // 超时
}
```

**GDB 调试**:
```gdb
# 在循环中中断
(gdb) break serial_putc
(gdb) continue
(gdb) print $rdi  # 字符参数
(gdb) print/x inb(0x3FD)  # LSR 值
(gdb) info registers  # 查看所有寄存器
```

### 2.4 ANSI 颜色不显示

**症状**: 颜色转义序列显示为文字而非颜色

**可能原因**:
1. 终端不支持 ANSI
2. 转义序列格式错误
3. QEMU 终端类型不正确

**解决方案**:
```c
// 确保转义序列格式正确
// ESC[0;32m = 绿色
sync_serial_puts("\033[0;32mGreen text\033[0m\n");

// 检查转义字符
// \033 = 八进制转义
// \x1b = 十六进制转义
// \e = 一些编译器支持
```

## 3. 端口 I/O 问题

### 3.1 inb/outb 不工作

**症状**: 端口读写无效果

**可能原因**:
1. 内联汇编约束错误
2. 编译器优化掉指令
3. 权限问题

**检查方法**:
```c
// 检查汇编输出
// 使用 objdump 查看生成的代码

// 添加 volatile 确保不优化
__asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
//         ^^^^^^^^ 重要！
```

**GDB 调试**:
```gdb
# 单步执行汇编
(gdb) display/i $pc
(gdb) stepi

# 检查端口值
(gdb) call inb(0x3F8)
```

### 3.2 端口地址冲突

**症状**: 访问端口导致异常

**可能原因**:
1. 端口地址错误
2. 硬件不存在
3. 权限不足

**解决方案**:
```bash
# 验证端口地址
# COM1 = 0x3F8
# COM2 = 0x2F8
# COM3 = 0x3E8
# COM4 = 0x2E8

# 在 GDB 中检查端口
(gdb) call inb(0x3F8)
(gdb) call inb(0x3FD)  # LSR
```

## 4. Bootloader 串口问题

### 4.1 实模式串口不工作

**症状**: Bootloader 早期没有串口输出

**可能原因**:
1. 串口未初始化
2. 16 位代码错误
3. 段地址问题

**检查方法**:
```asm
; 确保在实模式初始化串口
bits 16
call serial_init
call serial_write_string

; 检查串口初始化返回值
; （如果有的话）
```

**调试技巧**:
```asm
; 使用 Bochs 调试器
; 安装: sudo apt install bochs
; 运行: bochs -q

; 在 Bochs 中调试
break 0x7c00
continue
info sreg  ; 查看段寄存器
x /10i $pc  ; 查看指令
```

### 4.2 模式切换后串口失效

**症状**: 进入保护模式/长模式后串口无输出

**可能原因**:
1. 需要重新初始化
2. 64 位代码错误
3. 栈问题

**解决方案**:
```asm
; 在长模式重新初始化串口
bits 64
call serial_init_64

; 确保使用正确的调用约定
; 64 位使用寄存器传递参数
```

## 5. 测试问题

### 5.1 主机测试链接失败

**症状**: `test_memory` 编译错误

**常见错误**:

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `undefined reference to memset` | 未链接 kernel_base | 检查 CMakeLists.txt |
| `undefined reference to inb` | I/O 函数无主机实现 | 添加桩函数 |
| `multiple definition` | 重复定义 | 检查头文件 |

**解决方案**:
```cmake
# test/CMakeLists.txt
add_executable(test_memory test_memory.c)

# 链接 kernel_base（包含 memory.c）
target_link_libraries(test_memory PRIVATE kernel_base)

# 或直接编译 memory.c
target_sources(test_memory PRIVATE ../kernel/base/memory.c)
```

### 5.2 主机端 I/O 桩函数

**问题**: 主机上无法执行 inb/outb

**解决方案**:
```c
// test/test_memory.c 中添加桩函数

#ifdef HOST_TEST
uint8_t inb(uint16_t port) {
    (void)port;
    fprintf(stderr, "Warning: inb called on host (port=%u)\n", port);
    return 0xFF;
}

void outb(uint16_t port, uint8_t data) {
    (void)port;
    (void)data;
    fprintf(stderr, "Warning: outb called on host (port=%u, data=0x%02x)\n",
            port, data);
}
#endif
```

## 6. QEMU 配置问题

### 6.1 串口重定向不工作

**症状**: QEMU 运行但无串口输出

**解决方案**:

```bash
# 方法 1: 重定向到 stdio（推荐）
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -nographic -serial mon:stdio

# 方法 2: 重定向到文件
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -serial file:serial.log

# 方法 3: 使用虚拟控制台
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -nographic -serial vc

# 方法 4: 重定向到伪终端
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -serial pty
```

### 6.2 VGA 和串口同时使用

**症状**: 需要同时看到 VGA 和串口输出

**解决方案**:
```bash
# VGA + 串口
qemu-system-x86_64 -drive format=raw,file=build/boot.img \
    -vga std -display vnc=:0 \
    -nographic -serial mon:stdio

# 终端 1: 查看串口
# （QEMU 主窗口）

# 终端 2: 查看 VGA
vncviewer localhost:5900
```

## 8. 常用调试命令

### GDB 命令

```gdb
# 调用 I/O 函数
(gdb) call inb(0x3F8)
(gdb) call outb(0x3F8, 0x41)

# 检查内存
(gdb) x/20bx buffer
(gdb) x/10s string_ptr

# 查看汇编
(gdb) disassemble
(gdb) display/i $pc
```

### QEMU 监控命令

```
# 在 QEMU monitor 中（按 Ctrl+A, C）
info serial      # 显示串口状态
info cpustate    # 显示 CPU 状态
xp /20bx 0x3F8   # 查看端口内存
```

### Shell 命令

```bash
# 检查串口设备
ls -l /dev/ttyS*

# 使用 screen 连接串口
screen /dev/ttyS0 115200

# 使用 minicom
minicom -D /dev/ttyS0 -b 115200
```

## 1. 功能概述

### 1.1 目标

实现从 bootloader 加载并跳转到独立内核的功能。

**需求**：
- Bootloader 能够将内核从磁盘加载到内存
- 成功切换到 64 位长模式
- 跳转到内核入口点执行
- 内核能够正常运行并输出验证

### 1.2 实现结果

```
启动流程：
BIOS → Stage 1 → Stage 2 → Kernel

内存布局：
┌─────────────┐ 0x7C00  Stage 1 (boot.bin)
│   Stage 1  │
├─────────────┤ 0x7E00  Stage 2 (boot2.bin)
│   Stage 2  │          ~824 字节，占用 2 个扇区
├─────────────┤ 0x9000  Page Tables
│ Page Tables │          PML4 + PDPT + PD = 12KB
├─────────────┤ 0x10000 Kernel
│   Kernel   │          kernel.bin 加载地址
└─────────────┘

磁盘布局：
┌─────────────┤ Sector 1  (512B)
│   Boot1     │
├─────────────┤ Sector 2-3 (1024B)
│   Boot2     │
├─────────────┤ Sector 4+  (512B)
│   Kernel    │
└─────────────┘
```

### 1.3 VGA 调试输出

内核加载成功后在 VGA 显示的字符序列：

```
位置 0  内容: S (Stage 2 消息)
位置 1  内容: t
...
位置 12 内容: G (Long mode 第一个字符)
位置 13 内容: H
位置 14 内容: I
位置 15 内容: J
位置 16 内容: K (跳转内核前)
位置 17 内容: Z (内核返回后的标记，实际不会到达)
位置 80 内容: X (内核输出，行 5 位置 0)
```

**验证方法**：QEMU 启动后使用 `info registers` 检查 VGA 内存。

## 2. 开发流程

### 2.1 迭代步骤

```
第 1 步：修改 Stage 1 磁盘读取
  ✓ 从 1 扇区增加到 2 扇区
  ✓ Boot2 现在更大 (~824 字节)
  ✓ 更新 LBA 和 CHS 读取参数

第 2 步：在 Stage 2 添加内核加载函数
  ✓ 实模式调用 load_kernel()
  ✓ 使用 CHS 读取内核到 0x10000
  ✓ 添加成功/失败消息

第 3 步：构建系统更新
  ✓ Makefile 添加 kernel.asm
  ✓ 生成 kernel.bin
  ✓ 合并到 boot.img (sector 4)

第 4 步：内核入口实现
  ✓ 简单的 64 位代码
  ✓ 写 'X' 到 VGA 行 5
  ✓ 停机循环
```

### 2.2 调试策略

**逐步验证原则**：

```
每个步骤都独立验证：

1. Boot2 能否加载 2 扇区？
   → 编译后检查文件大小
   → 确认 <= 1024 字节

2. 内核能否读取到内存？
   → 在实模式打印消息
   → 检查磁盘返回值

3. 长模式能否正常进入？
   → VGA 逐步写入字符
   → 确认每个阶段到达

4. 内核能否执行？
   → 在独立位置写标记
   → 确认与 Boot2 输出不同
```

## 3. 关键决策

### 3.1 为什么在实模式加载内核？

#### 问题分析

```
保护模式/长模式磁盘读取问题：
  - BIOS INT 13h 只在实模式可用
  - 保护模式需要自己驱动磁盘
  - 长模式更是完全不能使用 BIOS

如果不在实模式加载：
  1. 需要实现 ATA/AHCI 驱动
  2. 代码量大增
  3. 兼容性问题多
```

#### 解决方案

```
在 Stage 2 实模式阶段加载内核：
  ✗ 切换到保护模式之前
  ✗ 使用 BIOS INT 13h
  ✗ 简单可靠
  ✗ 兼容所有 BIOS

顺序：
  main() → load_kernel() → lgdt → protected mode → ...
```

**代码位置**: [boot2.asm:42-43](../../boot/boot2.asm#L42-L43)

### 3.2 为什么选择 0x10000 作为内核地址？

#### 地址空间分析

```
低内存区域 (< 1MB):
  0x00000 - 0x003FF  IVT (中断向量表)
  0x00400 - 0x004FF  BDA (BIOS 数据区)
  0x07C00 - 0x07DFF  Boot1 (MBR)
  0x07E00 - 0x083FF  Boot2 (我们的代码)
  0x09000 - 0x0BFFF  Page Tables (我们使用)
  0x0A0000 - 0x0BFFFF  VGA 显存

1MB 之后:
  0x10000          第一个安全的"高"地址
  4KB 对齐
  不与 BIOS 区域冲突
```

#### 为什么不用更高地址？

```
可选地址：
  0x10000  → 选择：简单明确
  0x100000 → 1MB 标准内核地址
  0x200000 → 更高位，需要更多页表映射

选择 0x10000 的原因：
  1. 足够远，不会覆盖 bootloader
  2. 不需要复杂的页表设置
  3. Identity mapping 直接可用
  4. 早期内核足够使用
```

### 3.3 为什么使用 CHS 而不是 LBA？

#### 对比分析

```
LBA Extended Read:
  优点：现代、支持大磁盘
  缺点：DAP 结构复杂、容易出错

CHS Read:
  优点：简单、参数少
  缺点：传统方式

内核加载特点：
  - 只读 1 个扇区
  - 位置固定 (sector 4)
  - 在小磁盘上也工作
```

#### 代码实现

```asm
; boot2.asm:82-88
mov ah, 0x02            ; read function
mov al, 0x01            ; read 1 sector
mov ch, 0x00            ; cylinder 0
mov cl, 0x04            ; sector 4
mov dh, 0x00            ; head 0
mov dl, 0x80            ; first hard drive
int 0x13
```

**简洁性**：8 行代码完成读取，无需复杂的 DAP 结构。

### 3.4 为什么在长模式跳转而不是保护模式？

#### 执行流程分析

```
保护模式跳转问题：
  - 内核是 64 位代码
  - 保护模式只能执行 32 位代码
  - 需要额外的模式切换代码

长模式跳转优势：
  - 直接调用 64 位代码
  - 使用 call 指令可以返回
  - 内核可以使用完整 64 位功能
```

#### 跳转实现

```asm
; boot2.asm:332-334
; Jump to kernel entry point at 0x10000
mov rdi, 0x10000
call rdi
```

**注意**：使用 `call` 而非 `jmp`，理论上内核可以返回（虽然当前内核会 halt）。

## 4. 常见陷阱

### 4.1 磁盘读取扇区计算

#### 陷阱：混淆 0-based 和 1-based

```
LBA (0-based):
  Sector 0 = MBR
  Sector 1 = 第一个数据扇区

CHS (1-based):
  Sector 1 = MBR
  Sector 2 = 第一个数据扇区

BIOS INT 13h (CHS):
  cl 寄存器是 1-based
  cl = 1 → 第一个扇区
  cl = 4 → 第四个扇区 (我们的内核)
```

**验证方法**：
```bash
# 检查内核在磁盘的偏移
dd if=build/boot.img bs=512 skip=3 count=1 | xxd
# 应该看到 kernel.bin 的内容
```

### 4.2 内核大小限制

#### 陷阱：假设内核无限大

```
当前实现：
  - 只读取 1 个扇区 (512 字节)
  - 内核必须 <= 512 字节

内核变大后：
  1. 修改 `mov al, 0x01` 为需要的扇区数
  2. 或者实现 FAT/EXT 文件系统
  3. 或者支持多扇区连续读取
```

#### 当前内核大小

```bash
$ ls -lh build/kernel.bin
-rw-r--r-- 1 user user 18 Feb 14 12:00 build/kernel.bin
# 只有 18 字节，远小于 512 字节限制
```

### 4.3 长模式调用约定

#### 陷阱：假设 C 调用约定

```
System V AMD64 ABI:
  - 参数: RDI, RSI, RDX, RCX, R8, R9
  - 返回值: RAX
  - 栈: 16 字节对齐

我们的跳转：
  mov rdi, 0x10000  ; 地址放在 RDI
  call rdi          ; 这是函数指针调用

内核入口:
  - 不需要参数，RDI 可以直接忽略
  - 使用 syscall/ret 是未来的事
```

### 4.4 VGA 调试位置冲突

#### 陷阱：覆盖已有的调试输出

```
当前 VGA 使用情况：
  位置 0-11:  S (Boot2 字符串)
  位置 12-15: GHIJ (Long mode 测试)
  位置 16:    K (跳转前)
  位置 17:    Z (返回后)

内核选择位置 80 (行 5):
  - 不与 Boot2 输出冲突
  - 清楚表明是内核输出
  - 便于调试验证
```

**代码**: [kernel.asm:12](../../kernel/kernel.asm#L12)

## 5. 代码详解

### 5.1 Stage 1 改动

#### boot.asm 变更

```diff
- mov word [edi + 2], 0x01    ; read 1 sector
+ mov word [edi + 2], 0x02    ; read 2 sectors

- cmp al, 0x01                ; check if sector was read
+ cmp al, 0x02                ; check if 2 sectors were read

- mov al, 0x01                ; read 1 sector
+ mov al, 0x02                ; read 2 sectors

- cmp al, 0x01                ; verify sector was read
+ cmp al, 0x02                ; verify 2 sectors were read
```

**原因**: Boot2 从 ~500 字节增长到 ~824 字节，需要 2 个扇区。

**文件**: [boot.asm](../../boot/boot.asm)

### 5.2 Stage 2 内核加载

#### load_kernel 函数

```asm
; boot2.asm:69-120
load_kernel:
    pusha

    ; 打印消息
    mov si, msg_loading_kernel
    call print_bios

    ; 设置目标地址: 0x1000:0x0000 = 0x10000
    mov ax, 0x1000
    mov es, ax
    xor bx, bx

    ; BIOS 磁盘读取 (CHS)
    mov ah, 0x02            ; 读取功能
    mov al, 0x01            ; 1 个扇区
    mov ch, 0x00            ; 柱面 0
    mov cl, 0x04            ; 扇区 4 (我们的内核位置)
    mov dh, 0x00            ; 磁头 0
    mov dl, 0x80            ; 第一个硬盘
    int 0x13

    jc .read_error          ; 错误处理

    ; 成功消息
    mov si, msg_kernel_loaded
    call print_bios

    popa
    ret
```

**关键点**：
1. 必须在实模式调用（保护模式前）
2. 使用 ES:BX = 0x10000 作为目标地址
3. 硬编码位置 (sector 4) 简化实现

#### 调用时机

```asm
; boot2.asm:42-43
main:
    cli
    ; ... 初始化 ...
    call load_kernel    ; ← 在切换模式前加载
    lgdt [gdt_ptr]     ; ← 之后才加载 GDT
```

**文件**: [boot2.asm](../../boot/boot2.asm)

### 5.3 Makefile 更新

#### 构建规则

```makefile
# 源文件
KERNEL_ASM = $(KERNEL_DIR)/kernel.asm
KERNEL_BIN = $(BUILD_DIR)/kernel.bin

# 构建内核
$(KERNEL_BIN): $(KERNEL_ASM) | prepare
	@echo "Building Kernel..."
	$(AS) $(ASFLAGS) $< -o $@
	@echo "Kernel size:"
	@ls -lh $@

# 合并所有镜像
$(BOOT_IMG): $(BOOT_BIN) $(BOOT2_BIN) $(KERNEL_BIN)
	@echo "Combining stages into boot image..."
	dd if=$(BOOT_BIN) of=$@ bs=512 count=1 conv=notrunc
	dd if=$(BOOT2_BIN) of=$@ bs=512 seek=1 conv=notrunc
	dd if=$(KERNEL_BIN) of=$@ bs=512 seek=3 conv=notrunc
```

**磁盘布局**：
```
Sector 0 (seek=0):   boot1.bin
Sector 1-2 (seek=1): boot2.bin (2 扇区)
Sector 3 (seek=3):   kernel.bin (1 扇区)
```

**文件**: [Makefile](../../Makefile)

### 5.4 内核实现

#### 最小 64 位内核

```asm
; kernel.asm:1-18
section .text
    org 0x10000
    bits 64

kernel_start:
    ; 写 'X' 到 VGA 行 5 证明到达
    mov rdi, 0xB8000 + 160 * 5  ; 行 5
    mov word [rdi], 0x1F58      ; 'X' 白字蓝底

    ; 停机
    cli
    hlt
    jmp kernel_start
```

**验证点**：
1. `org 0x10000` - 加载地址
2. `bits 64` - 64 位模式
3. 行 5 输出 - 不与 Boot2 冲突

**文件**: [kernel.asm](../../kernel/kernel.asm)

## 6. 未来改进

### 6.1 短期改进 (1-2 周)

#### 1. ELF 内核支持

```
当前: 直接加载二进制

改进: 解析 ELF 格式
  - 支持多个程序段 (.text, .data, .bss)
  - 自动重定位
  - 符号表支持
  - 更灵活的内存布局
```

**参考**: [ELF Specification](https://refspecs.linuxfoundation.org/elf/elf.pdf)

#### 2. 多扇区内核

```asm
; 当前固定 1 扇区
mov al, 0x01

; 改进：动态计算
; 1. 读取 ELF header
; 2. 解析程序段数量
; 3. 按需读取所有扇区
```

#### 3. 内核命令行

```
传递参数给内核：
  - 内存布局信息
  - ACPI 表位置
  - 可用内存范围
  - 命令行参数
```

### 6.2 中期改进 (1-2 月)

#### 1. 文件系统支持

```
FAT32:
  - 最常见的文件系统
  - 简单可靠
  - U 盘兼容

实现：
  1. 读取 VBR (Volume Boot Record)
  2. 解析 FAT 表
  3. 加载 KERNEL.BIN 文件
```

#### 2. 内核解压缩

```
压缩内核：
  - 使用 LZMA 或 DEFLATE
  - 减少启动时间
  - 节省磁盘空间

流程：
  1. 加载压缩内核
  2. 解压到目标地址
  3. 跳转到解压后的内核
```

#### 3. 签名验证

```
安全启动准备：
  - 验证内核 SHA256
  - 检查 Ed25519 签名
  - 防止恶意内核加载
```

### 6.3 长期改进 (3-6 月)

#### 1. 多内核支持

```
选择不同内核：
  - 正常模式内核
  - 安全模式内核
  - 调试模式内核
  - 恢复模式内核
```

#### 2. 热加载内核

```
运行时切换内核：
  - 保存当前状态
  - 加载新内核
  - 恢复执行
```

#### 3. 网络启动

```
PXE/TFTP 支持：
  - 从网络加载内核
  - 无盘工作站
  - 集中管理
```

## 7. 经验总结

### 7.1 调试心得

#### VGA 是最好的朋友

```
没有串口输出时：
  - VGA 直接写入最可靠
  - 不同位置写不同字符
  - 可以精确定位崩溃点

示例：
  A → Protected mode 到达
  B → Page tables 完成
  C → PAE 启用
  ...
  K → 准备跳转内核
  X → 内核执行
```

#### 从简单开始

```
第一个内核只做一件事：
  ✗ 完整的 C 运行时
  ✗ 复杂的初始化
  ✓ 只写一个字符到 VGA

逐步增加功能：
  1. 验证能到达
  2. 添加更多功能
  3. 保持每步可验证
```

### 7.2 代码组织

#### 模块化思考

```
虽然目前是单文件：
  - load_kernel() 可以独立
  - 页表设置可以独立
  - 长模式跳转可以独立

未来拆分：
  load/
    load_disk.asm    - 磁盘加载
    load_elf.asm     - ELF 解析
  mode/
    pm.asm           - 保护模式
    lm.asm           - 长模式
```

#### 注释清晰

```asm
; 好的注释说明为什么
; Load kernel NOW while still in real mode
; (BIOS disk functions only work here)
call load_kernel

; 而不是
; Load kernel from disk
call load_kernel
```

## 1. 调试方法论

### 1.1 分层验证

```
启动流程的每一层都应该独立验证：

层 1: Stage 1 加载 Stage 2
  验证: 看到屏幕输出

层 2: Stage 2 加载内核
  验证: 看到内核加载消息

层 3: 长模式切换
  验证: VGA 逐步字符输出

层 4: 内核执行
  验证: 独立位置输出
```

### 1.2 VGA 调试输出

```
关键调试点输出位置:

Boot2:
  位置 0-11:   "Stage 2 running..."
  位置 12:     'G' (进入长模式)
  位置 13:     'H'
  位置 14:     'I'
  位置 15:     'J'
  位置 16:     'K' (跳转前)

Kernel:
  位置 80:     'X' (行 5, 验证内核执行)
```

### 1.3 使用 QEMU/GDB 调试

```bash
# 启动调试
make debug

# 连接 GDB (另一个终端)
gdb build/kernel.bin
target remote :1234

# 关键断点
b *0x7E00        # Stage 2 入口
b *0x10000      # 内核入口

# 单步执行
si               # step instruction
ni               # next instruction

# 查看内存
x/10i $pc       # 反汇编
x/10x 0xB8000   # VGA 内存
```

## 2. 内核未加载问题

### 2.1 症状

```
预期: 看到 "[LOAD] Loading kernel..." 消息
实际: 系统停机或重启
```

### 2.2 诊断步骤

```bash
# 1. 检查内核文件是否存在
ls -lh build/kernel.bin

# 2. 检查内核是否正确合并到 boot.img
dd if=build/boot.img bs=512 skip=3 count=1 | xxd
# 应该看到 0xB8... (内核开头的 mov 指令)

# 3. 检查 boot2.asm 是否调用了 load_kernel
grep -n "call load_kernel" boot/boot2.asm
```

### 2.3 解决方案

#### 问题 1: load_kernel 调用位置错误

```asm
; 错误: 在保护模式后调用
main:
    lgdt [gdt_ptr]
    mov eax, cr0
    or eax, 1
    mov cr0, eax
    call load_kernel    ; 太晚了！

; 正确: 在实模式调用
main:
    call load_kernel    ; 在切换模式前
    lgdt [gdt_ptr]
    ...
```

#### 问题 2: 磁盘地址错误

```asm
; 检查: 内核应该在 sector 4 (1-based)
; CHS: cl = 4
; LBA: lba = 3 (0-based)

; boot2.asm:85
mov cl, 0x04        ; 正确
```

#### 问题 3: 目标地址错误

```asm
; 检查: ES:BX = 0x10000
mov ax, 0x1000     ; ES = 0x1000
mov es, ax
xor bx, bx         ; BX = 0x0000
; ES:BX = 0x10000 ✓
```

## 3. 长模式切换失败

### 3.1 症状

```
预期: 看到 VGA 位置 12-15 的字符
实际: 系统重启 (Triple Fault) 或停在 'C'/'D'
```

### 3.2 逐步诊断

```
A: 进入保护模式 (0xB8000+0)
B: 页表设置完成 (0xB8000+2)
C: PAE 启用 (0xB8000+4)
D: CR3 加载 (0xB8000+6)
E: LME 设置 (0xB8000+8)
F: 分页启用 (0xB8000+10)
G: 进入长模式 (0xB8000+12)
```

### 3.3 故障点分析

#### 停在 'C' - PAE 启用失败

```
原因: CPU 不支持 PAE
检查: CPUID 检测

解决方案:
  检查 CPU 是否支持 PAE
  大多数现代 CPU 都支持
  QEMU 默认启用
```

#### 停在 'D' - CR3 加载问题

```
原因: 页表地址未对齐或无效
检查: 0x9000 是否 4KB 对齐?

验证:
  (gdb) x/10x 0x9000
  应该看到页表项

解决方案:
  确保页表清零完成
  确保页表项设置正确
```

#### 停在 'E' - LME 设置问题

```
原因: MSR 读写错误
检查: EFER MSR 是否存在?

验证:
  CPUID.80000001H.EDX[29] = LM support

解决方案:
  使用 rdmsr/wrmsr 前检查 CPUID
```

#### 停在 'F' - 分页启用失败

```
原因: 页表映射不完整
检查: Identity mapping 是否正确?

验证:
  当前执行地址 (0x7E00) 是否映射?
  页表必须映射 0x0-0x100000 区域

解决方案:
  确保 PML4[0] → PDPT[0] → PD[0] → 0x0
```

#### 停在 'G' - 长模式跳转失败

```
原因: Far jump 失败
检查: 段选择子 0x18 是否正确?

验证:
  0x18 = (3 × 8) | 0 = gdt_code64

解决方案:
  确保 GDT[3] 是 64 位代码段描述符
  确保 L 位 (bit 21) = 1
```

## 4. 内核跳转失败

### 4.1 症状

```
预期: 看到位置 80 的 'X'
实际: 只看到位置 16 的 'K'，然后重启/停机
```

### 4.2 诊断步骤

```bash
# 1. 检查内核是否被正确加载
(gdb) x/10i 0x10000
# 应该看到:
# 0x10000:  mov rdi, 0xB8000+160*5
# 0x10007:  mov word [rdi], 0x1F58
# 0x1000d:  cli
# ...

# 2. 检查跳转地址是否正确
(gdb) print/x $rdi
# 应该是 0x10000

# 3. 检查是否真的在长模式
(gdb) info registers
# 查看 CS 的值
# 应该是 0x0033 (long mode selector)
```

### 4.3 解决方案

#### 问题 1: 内核不是 64 位代码

```asm
; kernel.asm 检查
section .text
    org 0x10000
    bits 64           ; 必须是 64!

kernel_start:
    ; ...
```

验证方法:
```bash
ndisasm -b 64 build/kernel.bin | head
# 应该看到:
# 00000000  48BF0005B8B8  mov rdi,0xb8000
```

#### 问题 2: 内核地址错误

```asm
; boot2.asm 跳转
mov rdi, 0x10000   ; 正确
call rdi

; kernel.asm 入口
section .text
    org 0x10000    ; 必须匹配!
```

#### 问题 3: 长模式未正确设置

```
检查清单:
  [ ] CR4.PAE = 1
  [ ] CR3 已加载
  [ ] EFER.LME = 1
  [ ] CR0.PG = 1
  [ ] CS 已更新为 64 位段
```

### 4.4 系统崩溃处理

```
如果内核导致 Triple Fault:

1. 最小化内核
kernel_start:
    hlt
    jmp kernel_start

2. 逐步添加功能
    - 先只停机
    - 添加 VGA 写入
    - 添加其他功能

3. 使用 QEMU 日志
qemu-system-x86_64 -d int,cpu_reset
```

## 5. 常见错误代码

### 5.1 BIOS 磁盘错误

```
INT 13h 错误码 (AH):

01h - 无效命令
  原因: BIOS 不支持该功能
  解决: 检查 BIOS 版本

02h - 找不到地址标记
  原因: 磁盘损坏或地址错误
  解决: 检查 CHS/LBA 参数

04h - 扇区未找到
  原因: 扇区号超出磁盘范围
  解决: 检查磁盘大小

08h - DMA 过溢出
  原因: 缓冲区跨越 64K 边界
  解决: 确保缓冲区对齐

80h - 超时
  原因: 磁盘未响应
  解决: 检查磁盘连接
```

### 5.2 QEMU 错误

```
Triple Fault
  原因: 异常处理失败
  解决: 检查 GDT、IDT 设置

General Protection Fault (#GP)
  原因: 访问违规
  解决: 检查段选择子、内存访问

Page Fault (#PF)
  原因: 页表未映射
  解决: 检查页表设置

Invalid Opcode (#UD)
  原因: CPU 不支持指令
  解决: 检查 CPUID 功能位
```

## 6. 调试技巧

### 6.1 QEMU 监控命令

```bash
# 在 QEMU 窗口按 Ctrl+Alt+2 进入监控

# 信息查询
info registers    # 查看寄存器
info cpustats    # CPU 统计
info mem         # 内存映射
info tlb         # TLB 内容

# 内存操作
xp /10x 0xB8000  # 物理内存查看
x /10i 0x7E00    # 虚拟内存反汇编

# 执行控制
c                # 继续
s                # 单步
stepi            # 指令单步

# 断点
pb 0x7E00        # 物理地址断点
break 0x10000    # 虚拟地址断点
```

### 6.2 GDB 调试会话

```gdb
# 连接到 QEMU
target remote :1234

# 加载符号
file build/kernel.bin

# 设置断点
b *0x7E00      # Stage 2 入口
b *0x10000     # 内核入口

# 运行到断点
c

# 单步执行
si             # 指令单步
ni             # 步过函数调用

# 查看上下文
info registers         # 寄存器
info all-registers    # 所有寄存器
disassemble 0x7E00 10 # 反汇编

# 内存查看
x/10i $pc            # 反汇编当前 PC
x/10x 0xB8000       # 查看内存
x/2x 0x9000         # 查看页表
```

### 6.3 日志和跟踪

```
# QEMU 跟踪选项
qemu-system-x86_64 \
  -d in_asm          # 反汇编指令
  -d int             # 中断
  -d cpu_reset       # CPU 复位
  -d exec            # 执行
  -d guest_errors    # 客户端错误
  -d trace:crs       # 控制寄存器
  -d trace:mmu       # MMU 操作

# 输出到文件
qemu-system-x86_64 -D debug.log ...

# 组合使用
qemu-system-x86_64 -d int,cpu_reset,mmu -D boot.log
```

### 6.4 十六进制查看

```bash
# xxd 基础用法
xxd build/boot.img          # 查看全部
xxd -s 0x7C00 boot.img     # 从偏移开始
xxd -l 512 boot.img        # 限制长度
xxd -g 4 boot.img         # 4 字节一组

# 搜索特定字节
xxd build/boot.img | grep "55aa"

# 对比两个文件
xxd boot1.bin > boot1.hex
xxd boot2.bin > boot2.hex
diff boot1.hex boot2.hex
```

### 6.5 反汇编技巧

```bash
# ndisasm 反汇编
ndisasm -b 16 build/boot.bin    # 16 位
ndisasm -b 32 build/boot2.bin   # 32 位
ndisasm -b 64 build/kernel.bin  # 64 位

# 指定起始地址
ndisasm -o 0x7C00 -b 16 boot.bin

# 输出更详细的格式
ndisasm -b 64 -o 0x10000 kernel.bin | head

# objdump (如果使用 ELF 格式)
objdump -d -M intel,i386 kernel.elf
objdump -d -M intel,x86-64 kernel.elf
```

## 7. 典型调试案例

### 7.1 案例: 内核不执行

**问题描述**:
- Boot2 执行正常，看到 'K'
- 但没有看到内核的 'X'
- QEMU 显示 Triple Fault

**调试过程**:

```bash
# 1. 检查内核是否加载
(gdb) x/10i 0x10000
0x10000:  mov rdi, 0xB8000+160*5
0x10007:  mov word [rdi], 0x1F58
0x1000d:  cli
...
# 内核代码正确

# 2. 检查跳转前的状态
(gdb) b *0x7E00+325  # boot2 跳转指令
(gdb) c
(gdb) info registers
rax = 0x0000000000000000
rcx = 0x0000000000000000
rdx = 0x0000000000000000
...
cs  = 0x0033  # 长模式选择子 ✓
...
rdi = 0x0000000000010000  # 正确地址 ✓

# 3. 检查是否真的在长模式
(gdb) x/10i $pc
-> 指令能正确反汇编

# 4. 单步执行跳转
(gdb) si
(gdb) x/10i $pc
# PC 应该在 0x10000
```

**根本原因**:
- 内核的 `bits 64` 指令缺失
- 编译为 32 位代码
- 在长模式下执行 32 位代码导致异常

**解决方案**:
```asm
; 添加 bits 64
section .text
    org 0x10000
    bits 64  # ← 关键!

kernel_start:
    ; ...
```

### 7.2 案例: VGA 无输出

**问题描述**:
- 系统启动但屏幕空白
- QEMU 继续运行

**调试过程**:

```bash
# 1. 检查 VGA 内存
(gdb) x/10x 0xB8000
0xb8000: 0x1f53 0x1f74 0x1f61 0x1f67 ...
# 有数据， VGA 正常

# 2. 检查输出位置
(gdb) x/160x 0xB8000
# 发现输出在 0xB8000 (位置 0)
# 而不是预期位置

# 3. 检查代码偏移
(gdb) x/10i 0x10000
0x10000:  mov rdi, 0xB8000+160*5
# 计算: 0xB8000+160*5 = 0xB8000+0x320 = 0xB8320

(gdb) x/10x 0xB8320
# 确实有 0x1F58 ('X')
```

**根本原因**:
- VGA 输出正确，只是在不同行
- 真实硬件可能显示在正确位置
- QEMU 可能显示问题

**解决方案**:
- 不是真正的问题，验证即可
- 使用 QEMU graphic 模式查看
- 检查物理机器

### 7.3 案例: 磁盘读取失败

**问题描述**:
- 看到 "[LOAD] Loading kernel..."
- 然后看到 "[ERROR] Disk read failed: 0C"

**调试过程**:

```bash
# 1. 查找错误代码
# 0Ch = "未定义错误" 或 "介质类型错误"

# 2. 检查磁盘布局
dd if=build/boot.img bs=512 count=1 | wc -c
# 应该是 512

dd if=build/boot.img bs=512 skip=3 count=1 | wc -c
# 应该是 512 (有内核)

# 3. 检查 CHS 参数
mov cl, 0x04    # Sector 4
# QEMU 默认磁盘足够大
# Sector 4 应该存在

# 4. 尝试 LBA 读取
# 当前使用 CHS，可能问题在 CHS 参数
```

**根本原因**:
- CHS 参数在某些 BIOS 下不准确
- 扇区数计算可能有误

**解决方案**:
```asm
; 使用更保守的扇区数
mov al, 0x01    ; 只读 1 扇区

; 或者使用 LBA (如果支持)
; 检查扩展支持后使用 LBA 读取
```

## 8. 预防性编程

### 8.1 错误处理模式

```asm
; 总是检查返回值
mov ah, 0x02
int 0x13
jc .error_handler    ; 检查 CF
cmp al, 0x01        ; 检查返回值
jne .error_handler

; 提供详细错误信息
.error_handler:
    mov si, error_msg
    call print_string
    ; 打印错误代码
    mov al, ah
    call print_hex
    jmp hang
```

### 8.2 验证点模式

```asm
; 每个关键步骤都有验证点
step1:
    mov byte [0xB8000], '1'
    ; 做步骤 1

step2:
    mov byte [0xB8000+2], '2'
    ; 做步骤 2

step3:
    mov byte [0xB8000+4], '3'
    ; 做步骤 3

; 如果看到 '12' 但没看到 '3'，
; 问题在步骤 3
```

### 8.3 渐进式开发

```asm
; 先实现最小功能
kernel_start:
    mov word [0xB8000], 0x1F58
    hlt
    jmp kernel_start

; 验证成功后再添加更多
kernel_start:
    mov word [0xB8000], 0x1F58
    mov word [0xB8000+2], 0x1F59
    hlt
    jmp kernel_start

; 逐步构建复杂功能
```

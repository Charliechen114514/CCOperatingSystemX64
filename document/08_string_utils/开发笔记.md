## 2. 开发流程

### 2.1 第一阶段：字符串函数实现

**目标**: 实现 C 标准库的字符串函数

**实现顺序**:
1. 基础操作 - `strlen`, `strcpy`
2. 比较函数 - `strcmp`, `strncmp`
3. 搜索函数 - `strchr`, `strstr`
4. 高级功能 - `strtok`, `strtok_r`

**设计考虑**:
- 所有函数都接受 `const char*` 参数，明确不修改输入
- 返回值遵循 POSIX 规范
- 使用断言验证非空指针

### 2.2 第二阶段：断言系统实现

**目标**: 提供内核级别的错误检测机制

**实现内容**:
```c
// 断言宏
#define CCOS_ASSERT(EXPECTED_EXPR) \
    ccos_assert_impl(EXPECTED_EXPR, #EXPECTED_EXPR, __FILE__, __LINE__, __func__)

// 实现
void ccos_assert_impl(bool condition, const char* expr_str,
                      const char* file, int line, const char* func) {
    if (condition) return;
    assert_backend_to_vga(file, line, func, expr_str);
    assert_failed_action();
}
```

**关键设计**:
1. 使用字符串化操作符 `#` 获取表达式文本
2. 使用预定义宏 `__FILE__`, `__LINE__`, `__func__` 获取位置
3. 分离后端实现，便于替换输出方式

### 2.3 第三阶段：VGA 报告后端

**目标**: 在 VGA 上显示友好的错误信息

**实现内容**:
```c
void assert_backend_to_vga(const char* file, int line,
                           const char* func, const char* expr_str) {
    // 保存当前光标和颜色
    vga_cursor_t saved_cursor = vga_get_cursor(vga);
    vga_color_t saved_font = vga->font_color;
    vga_color_t saved_bg = vga->background_color;

    // 设置错误样式（白字红底）
    vga->font_color = VGA_COLOR_WHITE;
    vga->background_color = VGA_COLOR_RED;

    // 显示错误信息
    vga_print_string(vga, "*** ASSERTION FAILED ***\n\n");
    // ... 显示文件、行号、函数、表达式

    // 恢复原始状态
    vga->font_color = saved_font;
    vga->background_color = saved_bg;
}
```

**UI 考虑**:
1. 不清屏，保留上下文
2. 在新行开始输出
3. 使用醒目的颜色
4. 输出后恢复原始状态

### 2.4 第四阶段：测试框架

**目标**: 验证所有字符串函数的正确性

**实现策略**:
1. **主机环境优先** - 在主机上编译和运行测试
2. **前向声明** - 避免包含内核头文件
3. **测试宏** - 提供统一的断言接口

**测试宏实现**:
```c
#define TEST_ASSERT_EQ(actual, expected, msg) \
    do { \
        if ((actual) != (expected)) { \
            printf("[FAIL] %s: %lld != %lld\n", msg, (long long)(actual), (long long)(expected)); \
            g_test_failed++; \
        } else { \
            g_test_passed++; \
        } \
    } while (0)

#define TEST_ASSERT_STR_EQ(actual, expected, msg) \
    do { \
        if (strcmp(actual, expected) != 0) { \
            printf("[FAIL] %s: '%s' != '%s'\n", msg, actual, expected); \
            g_test_failed++; \
        } else { \
            g_test_passed++; \
        } \
    } while (0)
```

## 3. 关键决策

### 3.1 为什么自实现字符串函数？

**问题**: Freestanding 环境没有标准库支持

**解决方案**: 实现自己的字符串函数库

**好处**:
1. 完全控制实现，适合内核环境
2. 可以添加断言验证
3. 便于调试和优化
4. 学习底层实现细节

### 3.2 为什么分离断言后端？

**问题**: 不同的输出目标需要不同的处理

**解决方案**: 创建可插拔的后端接口

**好处**:
1. 可以切换输出方式（VGA、串口、日志）
2. 便于测试
3. 代码组织清晰

### 3.3 为什么在主机环境测试？

**问题**: 内核测试需要启动 QEMU，周期长

**解决方案**: 创建独立的主机测试程序

**好处**:
1. 快速反馈（几秒 vs 几十秒）
2. 易于调试（可以使用 GDB、Valgrind）
3. 持续集成友好

### 3.4 为什么需要两个断言宏？

**问题**: 有些检查需要始终启用，有些只需调试时启用

**解决方案**: `CCOS_ASSERT` 和 `CCOS_DEBUG_ASSERT`

**好处**:
1. `CCOS_ASSERT` 用于关键检查（如非空指针）
2. `CCOS_DEBUG_ASSERT` 用于调试辅助（如不变式验证）
3. Release 构建可以禁用调试断言

## 4. 常见陷阱

### 4.1 strtok 的状态管理

**陷阱**: `strtok` 使用静态状态，不是线程安全的

**解决方案**: 提供 `strtok_r` 可重入版本

```c
// 非线程安全版本
char* strtok(char* str, const char* delim) {
    static char* saveptr = NULL;
    return strtok_r(str, delim, &saveptr);
}

// 线程安全版本
char* strtok_r(char* str, const char* delim, char** saveptr) {
    // 使用调用者提供的状态
}
```

### 4.2 strncpy 的空终止问题

**陷阱**: `strncpy` 可能不会空终止结果字符串

**说明**: 如果 `src` 长度 ≥ `n`，`strncpy` 不会写入空字符

**解决方案**: 显式处理
```c
strncpy(buffer, src, sizeof(buffer) - 1);
buffer[sizeof(buffer) - 1] = '\0';  // 确保终止
```

### 4.3 大小写转换的本地化

**陷阱**: 简单的 `c | 0x20` 不适用于所有字符

**解决方案**: 使用查找表或标准算法

```c
char tolower(char c) {
    if (c >= 'A' && c <= 'Z') {
        return c + ('a' - 'A');
    }
    return c;
}
```

### 4.4 测试中的内存管理

**陷阱**: 测试字符串函数需要足够的缓冲区

**解决方案**: 使用固定大小的栈缓冲区

```c
static void test_strcpy(void) {
    char buffer[100];  // 足够大
    strcpy(buffer, "hello");
    // ...
}
```

## 5. 代码详解

### 5.1 strlen 实现

```c
size_t strlen(const char* s) {
    CCOS_DEBUG_ASSERT(s);  // 断言非空

    const char* p = s;
    while (*p) {
        p++;
    }
    return (size_t)(p - s);
}
```

**优化**:
- 指针运算比计数器更快
- 单次循环，简单高效

### 5.2 strstr 实现

```c
char* strstr(const char* haystack, const char* needle) {
    CCOS_DEBUG_ASSERT(haystack && needle);

    if (*needle == '\0')
        return (char*)haystack;

    for (; *haystack; ++haystack) {
        const char* h = haystack;
        const char* n = needle;

        while (*h && *n && (*h == *n)) {
            ++h;
            ++n;
        }

        if (*n == '\0')
            return (char*)haystack;
    }

    return NULL;
}
```

**算法**: 简单的字符串匹配（类似暴力法）

**复杂度**: O(n×m)，其中 n 是 haystack 长度，m 是 needle 长度

### 5.3 strtok_r 实现

```c
char* strtok_r(char* str, const char* delim, char** saveptr) {
    CCOS_DEBUG_ASSERT(delim && saveptr);

    if (str) {
        *saveptr = str;
    }

    char* token = *saveptr;
    if (token == NULL) {
        return NULL;
    }

    // 跳过前导分隔符
    while (*token && strchr(delim, *token)) {
        token++;
    }

    if (*token == '\0') {
        *saveptr = NULL;
        return NULL;
    }

    char* end = token;
    while (*end && !strchr(delim, *end)) {
        end++;
    }

    if (*end) {
        *end = '\0';
        *saveptr = end + 1;
    } else {
        *saveptr = NULL;
    }

    return token;
}
```

**状态机**:
```
1. 首次调用：保存输入字符串
2. 跳过前导分隔符
3. 扫描到下一个分隔符
4. 替换分隔符为 '\0'
5. 保存下一个位置
6. 返回当前 token
```

## 7. 经验总结

### 7.1 设计原则
1. **标准兼容** - 尽量遵循 C 标准规范
2. **防御编程** - 使用断言验证输入
3. **简洁实现** - 避免过度优化，保持可读性
4. **充分测试** - 覆盖各种边界情况

### 7.2 调试技巧
1. **先主机后内核** - 在主机上快速验证
2. **使用 Valgrind** - 检测内存问题
3. **添加调试输出** - 在关键点打印状态
4. **简化问题** - 从最小示例开始

### 7.3 代码风格
1. **一致的命名** - 遵循 C 标准库命名
2. **清晰的注释** - 说明参数和返回值
3. **适当的抽象** - 避免不必要的复杂性

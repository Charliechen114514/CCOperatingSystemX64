# 字符串工具库与断言系统 - 调试工具指南

本文档详细说明字符串工具库和断言系统阶段的调试工具和最佳实践。

## 1. 开发环境配置

### 1.1 主机端测试环境

主机端测试允许在开发机上快速验证字符串函数的正确性。

#### 构建和运行

```bash
# 配置构建
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 构建测试
cmake --build build --target test_string

# 运行测试
./build/test/test_string

# 输出示例
# [INFO] Testing strlen...
# [PASS] strlen: all tests passed
# [INFO] Testing strcpy...
# [PASS] strcpy: all tests passed
# ...
# ==========================================
# Test Summary: 100 passed, 0 failed
# ==========================================
```

#### 使用 Valgrind 检测内存问题

```bash
# 内存泄漏检测
valgrind --leak-check=full ./build/test/test_string

# 详细报告
valgrind --leak-check=full --show-leak-kinds=all ./build/test/test_string

# 检测未初始化内存
valgrind --track-origins=yes ./build/test/test_string
```

#### 使用 GDB 调试测试

```bash
# 启动 GDB
gdb ./build/test/test_string

# 常用命令
(gdb) break test_strlen
(gdb) run
(gdb) print buffer
(gdb) next
(gdb) continue
```

## 2. 字符串函数调试技巧

### 2.1 使用 GDB 检查字符串

#### 查看字符串内容

```gdb
# 以字符串形式显示
(gdb) print/s str_variable

# 查看指定长度
(gdb) print/s (char*)0xaddress
(gdb) print/s (char*)$rsp

# 查看内存字节
(gdb) x/50bx 0xaddress
(gdb) x/20s str_variable
```

#### 搜索内存中的字符串

```gdb
# 查找包含特定内容的内存
(gdb) find 0x7c00, +0x10000, "hello"

# 查找特定字节
(gdb) find 0x7c00, +0x10000, 0x00
```

### 2.2 监控字符串操作

#### 在函数入口设置断点

```gdb
# 在字符串函数入口断点
(gdb) break strlen
(gdb) break strcpy
(gdb) break strcmp

# 带条件的断点
(gdb) break strcmp if strcmp(s1, s2) != 0
```

#### 查看调用栈

```gdb
# 在断点触发后
(gdb) backtrace
# #0  strlen (s=0x10000 "hello") at string.c:42
# #1  0x100023 in process_string at main.c:15
# #2  0x100050 in kernel_main at kernel_main.c:10

# 切换帧
(gdb) frame 1
(gdb) print local_variable
```

### 2.3 测试字符串函数

#### 在 GDB 中调用函数

```gdb
# 直接调用字符串函数测试
(gdb) call strlen("test")
$1 = 4

(gdb) call strcpy(buffer, "hello")
$2 = 0x7fffffffe000

(gdb) call strcmp("abc", "def")
$3 = -3
```

#### 检查返回值

```gdb
# 查看最后一次函数返回的值
(gdb) print $rax  # x86-64

# 检查特定函数返回
(gdb) finish  # 执行到当前函数返回
(gdb) print $rax
```

## 3. 断言系统调试

### 3.1 断言触发时的调试

#### 在断言实现中设置断点

```gdb
# 在断言函数入口停止
(gdb) break ccos_assert_impl

# 当触发时查看上下文
(gdb) print condition
(gdb) print expr_str
(gdb) print file
(gdb) print line
```

#### 查看失败的断言

```gdb
# 断言触发后
(gdb) backtrace  # 查看调用栈

# 查看失败的表达式值
(gdb) print x
(gdb) print y
(gdb) print x > y

# 切换到调用者
(gdb) up
(gdb) print local_var
```

### 3.2 VGA 断言输出调试

#### 检查 VGA 状态

```gdb
# 查看 VGA 实例
(gdb) print *vga_instance()

# 查看当前颜色设置
(gdb) print vga_instance()->font_color
(gdb) print vga_instance()->background_color

# 查看光标位置
(gdb) print vga_instance()->native_cursor_pos
```

#### 手动触发断言

```c
// 测试断言系统
void test_assert(void) {
    CCOS_ASSERT(1 == 1);   // 通过
    CCOS_ASSERT(1 == 0);   // 失败，显示错误
}

// 测试 VGA 输出
void test_vga_assert(void) {
    assert_backend_to_vga(__FILE__, __LINE__, __func__, "test != NULL");
}
```

### 3.3 断言级别选择

#### CCOS_ASSERT vs CCOS_DEBUG_ASSERT

| 断言类型 | Debug | Release | 用途 |
|---------|-------|---------|------|
| `CCOS_ASSERT` | 启用 | 启用 | 关键检查 |
| `CCOS_DEBUG_ASSERT` | 启用 | 禁用 | 调试检查 |

#### 使用示例

```c
// 始终检查 - 关键不变式
void* memcpy(void* dest, const void* src, size_t n) {
    CCOS_ASSERT(dest != NULL);
    CCOS_ASSERT(src != NULL);
    // ...
}

// 仅调试检查 - 性能相关
void sort(int* array, size_t n) {
    // 排序算法...
    CCOS_DEBUG_ASSERT(is_sorted(array, n));  // 仅 Debug
}
```

## 4. 测试框架使用

### 4.1 测试宏详解

#### 相等断言

```c
// 整数比较
TEST_ASSERT_EQ(strlen(""), 0, "strlen: empty string");
TEST_ASSERT_EQ(strlen("hello"), 5, "strlen: normal string");

// 指针比较
TEST_ASSERT_EQ(ptr, NULL, "ptr should be NULL");
TEST_ASSERT_EQ(result, expected_ptr, "pointer mismatch");
```

#### 字符串断言

```c
// 字符串相等
TEST_ASSERT_STR_EQ(buffer, "hello", "strcpy: basic copy");
TEST_ASSERT_STR_EQ(strcat(buf, " world"), "hello world", "strcat");

// 手动比较
if (strcmp(actual, expected) != 0) {
    printf("FAIL: strings don't match\n");
    printf("  Expected: [%s]\n", expected);
    printf("  Actual:   [%s]\n", actual);
}
```

### 4.2 编写测试

#### 基本测试模板

```c
static void test_function(void) {
    TEST_INFO("Testing function_name");

    // 测试正常情况
    TEST_ASSERT_EQ(func(normal_input), expected, "normal case");

    // 测试边界条件
    TEST_ASSERT_EQ(func(0), special_result, "zero input");
    TEST_ASSERT_EQ(func(MAX), max_result, "max input");

    // 测试错误情况
    TEST_ASSERT_EQ(func(invalid), error_code, "invalid input");
}
```

#### 字符串函数测试模板

```c
static void test_strlen(void) {
    TEST_INFO("Testing strlen");

    // 空字符串
    TEST_ASSERT_EQ(strlen(""), 0, "empty string");

    // 单字符
    TEST_ASSERT_EQ(strlen("a"), 1, "single char");

    // 普通字符串
    TEST_ASSERT_EQ(strlen("hello"), 5, "normal string");

    // 长字符串
    TEST_ASSERT_EQ(strlen(long_string), known_length, "long string");
}
```

### 4.3 运行特定测试

```bash
# 只编译测试（不运行）
cmake --build build --target test_string

# 运行并过滤输出
./build/test/test_string | grep strlen

# 统计测试结果
./build/test/test_string | tail -5
```

## 5. 常见调试场景

### 5.1 字符串截断问题

**症状**: 字符串被意外截断

```gdb
# 检查字符串长度
(gdb) print strlen(str)
(gdb) print str

# 查看内存
(gdb) x/20s str

# 查找终止符
(gdb) find 0xaddress, +0x100, 0
```

### 5.2 内存损坏追踪

```bash
# 使用 Valgrind
valgrind --track-origins=yes ./build/test/test_string

# 使用 AddressSanitizer (如果支持)
cmake -DCMAKE_C_FLAGS="-fsanitize=address -g" -B build
cmake --build build --target test_string
./build/test/test_string
```

### 5.3 断言过度触发

**问题**: 断言在正常代码中触发

```c
// 添加详细日志
#define DEBUG_LOG(expr) \
    printf("[%s:%d] Checking: %s\n", __FILE__, __LINE__, #expr)

// 在断言前使用
DEBUG_LOG(ptr != NULL);
CCOS_ASSERT(ptr != NULL);
```

## 7. 调试最佳实践

### 7.1 渐进式测试

1. **先主机后内核** - 在主机验证后再集成到内核
2. **先简单后复杂** - 从基本功能开始
3. **小步提交** - 每个小功能都提交检查点

### 7.2 使用版本控制

```bash
# 创建工作检查点
git checkpoint "string-tests-passing"

# 实验性修改
git checkout -b experiment/fast-strlen

# 失败后回退
git checkout main
```

### 7.3 调试日志

```c
// 条件编译的调试输出
#ifdef STRING_DEBUG
    #define STR_DBG(fmt, ...) \
        vga_print_string(vga, "[STR DBG] " fmt "\n")
#else
    #define STR_DBG(fmt, ...) ((void)0)
#endif

// 使用
STR_DBG("strlen called on %p", str);
```

## 8. 快速参考

### GDB 常用命令

| 命令 | 功能 |
|------|------|
| `break func` | 在函数入口设置断点 |
| `print/s var` | 以字符串形式显示变量 |
| `x/20bx addr` | 查看内存字节 |
| `backtrace` | 显示调用栈 |
| `finish` | 执行到函数返回 |
| `next` | 下一行（不进入函数） |
| `step` | 下一行（进入函数） |

### Valgrind 常用选项

| 选项 | 功能 |
|------|------|
| `--leak-check=full` | 详细内存泄漏检查 |
| `--show-leak-kinds=all` | 显示所有泄漏类型 |
| `--track-origins=yes` | 追踪未初始化内存 |

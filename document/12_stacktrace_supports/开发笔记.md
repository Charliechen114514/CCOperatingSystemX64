## 2. 设计决策

### 2.1 栈回溯方法选择

#### 问题

x86_64 架构下有多种栈回溯方法：

| 方法 | 优点 | 缺点 |
|------|------|------|
| 帧指针 (RBP) | 简单可靠 | 需要编译时保留帧指针 |
| DWARF CFI | 精确支持优化 | 复杂，需要解析库 |
| ORC (Oops Rewind) | 高性能 | Linux 特有，格式不公开 |

#### 选择：使用帧指针 (RBP)

**理由**:
1. **实现简单** - 每个栈帧结构固定
2. **无需额外数据** - 不需要调试信息
3. **编译器支持好** - GCC/Clang 都支持 `-fno-omit-frame-pointer`

#### 编译选项

```cmake
# 确保保留帧指针
target_compile_options(kernel PRIVATE -fno-omit-frame-pointer)
```

### 2.2 符号表设计

#### 问题

如何将地址转换为可读的函数名？

#### 方案 A：运行时解析 ELF

```c
// 链接时加载符号表
void load_symbols_from_elf(const char* elf_path);
```

**缺点**:
- 需要 ELF 解析库
- 内核文件系统支持
- 增加启动时间

#### 方案 B：编译时生成符号表

```python
# 构建时执行
python scripts/extract_symbols.py kernel.elf > symbols.c
```

**优点**:
- 无运行时开销
- 不依赖文件系统
- 符号表紧凑

**选择**：采用方案 B

### 2.3 符号查找算法

#### 问题

如何快速找到地址对应的符号？

#### 方案 A：线性查找

```c
for (int i = 0; i < count; i++) {
    if (addr >= symbols[i].addr && addr < symbols[i+1].addr)
        return &symbols[i];
}
```

**复杂度**: O(n)

#### 方案 B：二分查找

```c
while (left <= right) {
    int mid = (left + right) / 2;
    if (addr >= symbols[mid].addr && addr < symbols[mid+1].addr)
        return &symbols[mid];
    // ...
}
```

**复杂度**: O(log n)

**选择**：采用方案 B（符号表按地址排序）

## 3. 架构设计

### 3.1 x86_64 栈帧结构

#### System V AMD64 ABI 调用约定

```
高地址
    +------------------+  <- 上一个栈帧的 RBP
    |  保存的 RBP      |
    +------------------+  <- 当前 RBP 指向这里
    |  返回地址 (RIP)  |  (RBP + 8)
    +------------------+
    |  局部变量 1      |  (RBP - 8)
    +------------------+
    |  局部变量 2      |  (RBP - 16)
    +------------------+
    |     ...          |
    +------------------+  <- 当前 RSP
低地址
```

#### 栈遍历过程

```c
uintptr_t rbp = get_rbp();  // 获取当前帧指针

while (rbp != 0) {
    // 读取保存的 RBP 和返回地址
    uintptr_t saved_rbp = *(uintptr_t*)rbp;
    uintptr_t ret_addr = *(uintptr_t*)(rbp + 8);

    // 处理返回地址...

    // 移动到上一个栈帧
    rbp = saved_rbp;
}
```

## 4. 实现细节

### 4.1 读取寄存器

#### 内联汇编实现

```c
static inline uintptr_t get_rsp(void) {
    uintptr_t rsp;
    __asm__ volatile("mov %%rsp, %0" : "=r"(rsp));
    return rsp;
}

static inline uintptr_t get_rbp(void) {
    uintptr_t rbp;
    __asm__ volatile("mov %%rbp, %0" : "=r"(rbp));
    return rbp;
}
```

**说明**:
- `volatile` - 防止编译器优化掉
- `"=r"(rsp)` - 使用任意寄存器输出

### 4.2 栈帧验证

#### 验证规则

```c
static bool is_valid_frame(uintptr_t ptr) {
    // 1. 检查对齐 (x86_64 栈 8 字节对齐)
    if (ptr & 0x7)
        return false;

    // 2. 检查栈边界
    if (ptr > STACK_BASE)              // 栈向下增长
        return false;

    if (ptr < (STACK_BASE - STACK_SIZE))  // 不超出栈底
        return false;

    return true;
}
```

#### 栈边界定义

```c
// 栈的起始地址 (从 linker script 或 entry point 获取)
#define STACK_BASE    0x80000UL

// 栈大小 (64KB)
#define STACK_SIZE    0x10000UL
```

### 4.3 符号表二分查找

#### 算法实现

```c
bool find_symbol(uintptr_t addr, const char** out_name, uintptr_t* out_offset) {
    int left = 0;
    int right = table->count - 1;

    while (left <= right) {
        int mid = (left + right) / 2;
        const symbol_entry_t* entry = &table->entries[mid];

        uintptr_t entry_addr = entry->address;
        uintptr_t next_addr = (mid < table->count - 1)
                              ? table->entries[mid + 1].address
                              : UINTPTR_MAX;

        // 检查地址是否在这个符号的范围内
        if (addr >= entry_addr && addr < next_addr) {
            *out_name = entry->name;
            *out_offset = addr - entry_addr;
            return true;
        } else if (addr < entry_addr) {
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }

    return false;
}
```

## 5. 常见陷阱

### 5.1 帧指针被优化

#### 问题

编译器优化可能省略帧指针：

```c
// 开启 -O2 优化时
void foo() {
    // 可能没有 push rbp / mov rbp, rsp
}
```

#### 解决方案

确保编译时保留帧指针：

```cmake
# CMakeLists.txt
target_compile_options(kernel PRIVATE
    -fno-omit-frame-pointer
    -fno-optimize-sibling-calls
)
```

### 5.2 内联函数导致的栈帧缺失

#### 问题

内联函数不会生成新的栈帧：

```c
static inline void helper() {
    // 被内联，没有栈帧
}

void caller() {
    helper();  // 直接展开
}
```

栈回溯会跳过 `helper`。

#### 解决方案

对于需要追踪的函数，避免使用 `inline`：

```c
// 不要 inline
static void helper() {
    // 会生成栈帧
}
```

### 5.3 尾调用优化

#### 问题

尾调用可能重用栈帧：

```c
int factorial(int n, int acc) {
    if (n == 0) return acc;
    return factorial(n - 1, acc * n);  // 尾调用
}
```

栈回溯可能显示异常的调用链。

#### 解决方案

禁用尾调用优化：

```cmake
target_compile_options(kernel PRIVATE
    -fno-optimize-sibling-calls
)
```

### 5.4 符号表不完整

#### 问题

某些函数符号未被提取：

```c
// static 函数可能被优化掉
static void internal_func() {
    // ...
}
```

#### 解决方案

确保符号提取脚本包含所有符号：

```python
# 包含静态和局部符号
for symbol in symtab.iter_symbols():
    if symbol.entry.st_value != 0:  # 有地址的符号
        symbols.append(symbol)
```

## 8. 经验总结

### 8.1 最大的收获

#### 调用约定的理解

```
理解 System V AMD64 ABI 是实现栈回溯的基础：

- RBP: 帧指针，指向当前栈帧
- RIP: 返回地址保存在 RBP + 8
- 栈向下增长: RSP < RBP
- 8 字节对齐: 栈地址必须是 8 的倍数
```

#### 自动化的重要性

```
手工维护符号表 → 容易出错、难以同步

自动化方案：
- Python 脚本提取符号
- CMake 集成构建流程
- 每次构建自动更新
```

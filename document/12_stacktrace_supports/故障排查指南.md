## 1. 编译问题

### 1.1 帧指针被优化

#### 症状

栈回溯输出为空或帧数很少：

```
╔═══════════════════════════════════════════════════════════════╗
║                      Stack Trace                             ║
╠═══════════════════════════════════════════════════════════════╣
║  #  Address           Function                           ║
╠═══════════════════════════════════════════════════════════════╣
║  0   0x000000000001001a  kernel_main                    ║
╚═══════════════════════════════════════════════════════════════╝
```

#### 原因

编译器优化省略了帧指针：

```bash
# 反汇编检查
objdump -d kernel.elf | grep -A5 "kernel_main"
```

如果看到没有 `push rbp; mov rbp, rsp`，说明帧指针被优化。

#### 解决方案

确保编译选项包含：

```cmake
# CMakeLists.txt
target_compile_options(stacktrace PUBLIC
    -fno-omit-frame-pointer
    -fno-optimize-sibling-calls
)
```

### 1.2 符号表未生成

#### 症状

```
undefined reference to `_symbol_table_start'
undefined reference to `_symbol_string_table'
```

#### 原因

符号表生成脚本未执行或执行失败。

#### 解决方案

1. 检查 Python 依赖：

```bash
pip install pyelftools
```

2. 手动执行脚本：

```bash
python scripts/extract_symbols.py build/kernel/kernel.elf
```

3. 检查 CMake 配置：

```cmake
# 确保符号表生成规则正确
add_custom_command(
    OUTPUT symbols.c
    COMMAND python3 ...
)
```

### 1.3 内联函数缺失栈帧

#### 症状

某些函数不出现在栈回溯中。

#### 原因

函数被内联展开：

```c
static inline void helper() {
    // 被内联，没有栈帧
}
```

#### 解决方案

对于需要追踪的函数，移除 `inline`：

```c
// 不要 inline
static void helper() {
    // 会生成栈帧
}
```

## 2. 符号表问题

### 2.1 符号显示为 ???

#### 症状

```
║  0   0x000000000001001a  ???                           ║
║  1   0x0000000000007c00  ???                           ║
```

#### 原因

1. 符号表为空
2. 地址不在 .text 段
3. 符号表未初始化

#### 诊断步骤

```c
// 检查符号表
const symbol_table_t* table = get_symbol_table();
klog_info("Symbol count: %d\n", table->count);
klog_info("Text range: 0x%lx - 0x%lx\n",
          table->text_start, table->text_end);
```

#### 解决方案

1. 重新生成符号表：

```bash
rm kernel/stacktrace/symbols.c
make clean && make
```

2. 检查 ELF 文件：

```bash
# 查看符号表
readelf -s kernel.elf | grep FUNC
```

### 2.2 符号偏移量错误

#### 症状

```
║  0   0x000000000001001a  kernel_main+0x1234           ║
```

偏移量过大或不合理。

#### 原因

1. 符号地址错误
2. 二分查找逻辑问题
3. 返回地址计算错误

#### 诊断步骤

```c
// 验证符号查找结果
const char* name;
uintptr_t offset;

if (find_symbol(rip, &name, &offset)) {
    klog_info("Found: %s + 0x%lx\n", name, offset);

    // 手动验证
    uintptr_t sym_addr = get_symbol_address(name);
    klog_info("Symbol addr: 0x%lx, RIP: 0x%lx\n", sym_addr, rip);
}
```

#### 解决方案

确保符号表按地址排序：

```python
# extract_symbols.py
symbols = sorted(symbols, key=lambda x: x['address'])
```

### 2.3 符号表覆盖不全

#### 症状

部分函数符号缺失。

#### 原因

符号提取脚本过滤条件过严。

#### 解决方案

调整提取逻辑：

```python
# 包含更多符号类型
for symbol in symtab.iter_symbols():
    # 包含所有有地址的符号
    if symbol.entry.st_value != 0:
        symbols.append(symbol)
```

## 3. 栈回溯异常

### 3.1 无限循环

#### 症状

栈回溯持续输出相同帧。

#### 原因

栈帧链形成环（栈损坏）。

#### 解决方案

循环检测机制已内置：

```c
// 检查 RBP 是否回到起点
if (rbp == get_rbp()) {
    kprintf(KLOG_BACKEND_SERIAL, "║  <frame loop detected>                                     ║\n");
    break;
}
```

### 3.2 无效帧指针

#### 症状

```
║  2  <invalid frame: 0x0000000000001234>                 ║
```

#### 原因

1. 帧指针未对齐
2. 帧指针超出栈边界
3. 栈损坏

#### 诊断步骤

```c
// 检查帧指针有效性
uintptr_t rbp = get_rbp();
klog_info("RBP: 0x%lx\n", rbp);
klog_info("Aligned: %s\n", (rbp & 0x7) ? "No" : "Yes");
klog_info("In range: %s\n",
          (rbp > STACK_BASE - STACK_SIZE && rbp < STACK_BASE) ? "Yes" : "No");
```

#### 解决方案

1. 确保编译时保留帧指针
2. 检查栈溢出
3. 验证栈边界设置

### 3.3 栈帧截断

#### 症状

栈回溯突然停止，未到达栈底。

#### 原因

1. 帧指针链断裂
2. 某个函数未使用标准序言

#### 解决方案

对于汇编代码，确保使用标准序言：

```asm
; 正确
push rbp
mov rbp, rsp

; 函数体

pop rbp
ret
```

## 4. 符号解析问题

### 4.1 二分查找失败

#### 症状

已知地址有符号，但查找失败。

#### 原因

1. 符号表未排序
2. 地址比较逻辑错误

#### 诊断步骤

```c
// 线性查找验证
bool find_symbol_linear(uintptr_t addr, const char** name, uintptr_t* offset) {
    for (int i = 0; i < table->count - 1; i++) {
        if (addr >= table->entries[i].address &&
            addr < table->entries[i + 1].address) {
            *name = table->entries[i].name;
            *offset = addr - table->entries[i].address;
            return true;
        }
    }
    return false;
}

// 比较结果
bool found_linear = find_symbol_linear(addr, &name1, &off1);
bool found_binary = find_symbol(addr, &name2, &off2);
```

#### 解决方案

确保符号表生成时排序：

```python
symbols = sorted(symbols, key=lambda x: x['address'])
```

### 4.2 符号名乱码

#### 症状

```
║  0   0x000000000001001a  ??$$##@@                      ║
```

#### 原因

字符串表指针错误。

#### 解决方案

验证字符串表结构：

```python
# 确保字符串以 null 分隔
string_table = "\0".join(sym['name'] for sym in symbols) + "\0"

# 计算正确偏移
offset = 0
for i, sym in enumerate(symbols):
    sym['string_offset'] = offset
    offset += len(sym['name']) + 1
```

## 7. 最佳实践

### 7.1 开发时配置

```cmake
# 开发时启用所有调试
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
    target_compile_options(kernel PRIVATE
        -fno-omit-frame-pointer
        -fno-optimize-sibling-calls
        -g
        -O0
    )
endif()
```

### 7.2 符号表验证

```c
// 启动时验证符号表
void verify_symbol_table(void) {
    const symbol_table_t* table = get_symbol_table();

    if (table->count == 0) {
        klog_warn("No symbols available!\n");
        return;
    }

    // 验证排序
    for (int i = 0; i < table->count - 1; i++) {
        if (table->entries[i].address >= table->entries[i + 1].address) {
            klog_error("Symbol table not sorted at index %d\n", i);
        }
    }
}
```

### 7.3 错误处理

```c
// 安全的栈回溯
void safe_dump_stack(void) {

    int count = 0;

    while (rbp != 0 && count < DUMP_STACK_MAX_FRAMES) {
        if (!is_valid_frame(rbp)) {
            klog_warn("Invalid frame at 0x%lx\n", rbp);
            break;
        }

        // 处理帧...
        rbp = *(uintptr_t*)rbp;
        count++;
    }
}
```

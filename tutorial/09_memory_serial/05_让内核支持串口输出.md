# 05 - 让内核支持串口输出

串口驱动已经实现了，现在要把它集成到内核里。

---

## 我们现在要做什么

我们需要修改内核代码，让串口驱动真正工作起来。这个过程看起来简单，但有几个细节需要注意：

1. 在内核初始化时初始化串口
2. 在主函数中使用串口输出
3. 更新 CMakeLists.txt 链接串口驱动
4. 处理初始化失败的情况

---

## 第一步 —— 理解内核初始化流程

在内核启动时，我们需要按特定顺序初始化各个组件。顺序很重要，因为有些组件依赖于其他组件。

我们的初始化顺序是：
1. VGA 驱动（用于早期调试输出）
2. 串口驱动（用于日志输出）

为什么先初始化 VGA？因为 VGA 更简单，如果出问题我们能看到错误信息。串口初始化可能失败（比如在虚拟机中串口被禁用），如果先初始化串口失败了，我们连错误信息都看不到。

这是一个基本的调试原则：**在可能出错的操作之前，先确保有可用的调试输出**。

---

## 第二步 —— 修改内核初始化

打开 `kernel/kernel_init.c`，我们需要在系统初始化时初始化串口。

我们先来看一个基础版本，然后逐步完善：

```c
#include "defines/types.h"
#include "driver/serial/serial.h"
#include "driver/vga/vga.h"
#include "assert/assert.h"

void kernel_init(void) {
    // 先初始化 VGA
    system_vga_init();
    system_vga_print_welcome();

    // 初始化串口
    bool serial_ok = serial_init();

    // 通过串口输出欢迎信息
    if (serial_ok) {
        sync_serial_puts("=== CCOS Kernel ===\n");
        sync_serial_puts("Serial port initialized at 115200 8N1\n");
    }
}
```

这个版本能工作，但有几个改进空间。

### 使用 ANSI 颜色

串口支持 ANSI 转义序列，我们可以用颜色来区分不同级别的消息：

```c
// ANSI 颜色代码
#define ANSI_COLOR_GREEN   "\033[0;32m"
#define ANSI_COLOR_YELLOW  "\033[0;33m"
#define ANSI_COLOR_RED     "\033[0;31m"
#define ANSI_COLOR_RESET   "\033[0m"

// 在串口输出中使用
sync_serial_puts(ANSI_COLOR_GREEN);
sync_serial_puts("=== CCOS Kernel ===\n");
sync_serial_puts(ANSI_COLOR_RESET);
```

ANSI 转义序列以 ESC（\033 或 \x1B）开头，后面跟 [ 和参数。例如：
- `\033[0;32m` 设置颜色为绿色
- `\033[0m` 重置为默认颜色
- `\033[1m` 设置粗体

这些序列在支持 ANSI 的终端中都能正确显示，包括 Linux 终端、macOS Terminal、Windows Terminal 等。

### 完整的初始化代码

```c
#include "defines/types.h"
#include "driver/serial/serial.h"
#include "driver/vga/vga.h"
#include "assert/assert.h"

void kernel_init(void) {
    // 先初始化 VGA（用于早期错误输出）
    system_vga_init();
    system_vga_print_welcome();

    // 初始化串口
    bool serial_ok = serial_init();

    // 如果串口初始化失败，这通常不是致命错误
    // 我们可以继续运行，只是没有串口输出
    if (!serial_ok) {
        // VGA 上已经显示欢迎信息，这里不做额外处理
        return;
    }

    // 通过串口输出欢迎信息（带颜色）
    sync_serial_puts("\033[0;32m");  // 绿色
    sync_serial_puts("=== CCOS Kernel ===\n");
    sync_serial_puts("Serial port initialized at 115200 8N1\n");
    sync_serial_puts("\033[0m");  // 重置颜色
}
```

注意到我们没有使用 `CCOS_ASSERT(serial_ok)`。这是因为串口不可用并不致命——内核可以继续运行，只是没有串口输出而已。

在某些环境中（如某些虚拟机配置），串口可能被完全禁用。如果在这种情况下 ASSERT 失败，内核就无法启动了，这不是我们想要的。

## 第三步 —— 修改内核主函数

打开 `kernel/kernel_main.c`，让主函数也使用串口输出：

```c
#include "defines/types.h"
#include "driver/vga/vga.h"
#include "driver/serial/serial.h"

extern kernel_vga_t* vga;

void kernel_main(void) {
    // VGA 输出
    vga_print_string(vga, "Hello from CCOS kernel!\n");
    vga_print_string(vga, "Kernel is running in 64-bit long mode.\n");

    // 串口输出（带颜色标记不同级别）
    sync_serial_puts("\033[0;36m[KERNEL]\033[0m Hello from CCOS kernel!\n");
    sync_serial_puts("\033[0;36m[KERNEL]\033[0m Kernel is running in 64-bit long mode.\n");
    sync_serial_puts("\033[0;36m[KERNEL]\033[0m VGA + Serial dual output is working!\n");

    // 不同级别的日志示例
    sync_serial_puts("\033[0;32m[INFO]\033[0m System initialized successfully\n");
    sync_serial_puts("\033[1;33m[WARN]\033[0m This is a warning message\n");
    sync_serial_puts("\033[0;31m[ERROR]\033[0m This is an error message\n");

    // 死循环，防止内核退出
    while (1) {
        __asm__ volatile("hlt");
    }
}
```

注意到我们使用了 `\033[0;36m[KERNEL]\033[0m` 的模式。这会在每行消息前显示蓝色的 `[KERNEL]` 前缀，方便在日志中过滤。

### 日志级别设计

在调试时，不同级别的消息用不同颜色很有帮助：

| 级别 | 颜色 | 用途 | ANSI 码 |
|------|------|------|--------|
| INFO | 绿色 | 正常信息 | `\033[0;32m` |
| WARN | 黄色 | 警告信息 | `\033[1;33m` |
| ERROR | 红色 | 错误信息 | `\033[0;31m` |
| DEBUG | 青色 | 调试信息 | `\033[0;36m` |

随着内核的发展，你可以实现一个更完善的日志系统，支持日志级别过滤、时间戳等功能。

## 第四步 —— 更新 CMakeLists.txt

我们需要确保串口驱动被正确链接。

检查 `kernel/CMakeLists.txt`，确保依赖关系正确：

```cmake
# 内核可执行文件
add_executable(kernel.elf
    # ... 现有文件 ...
    kernel_init.c
    kernel_main.c
)

# 链接串口驱动
target_link_libraries(kernel.elf PRIVATE
    kernel_base      # 内存函数
    driver_serial    # 串口驱动
    driver_vga       # VGA 驱动
    # ... 其他依赖 ...
)
```

注意到 `driver_serial` 会自动链接 `driver_io`（因为我们在 serial 的 CMakeLists.txt 中声明了依赖）。所以这里不需要显式链接 `driver_io`。

但如果链接顺序错误，可能会遇到 `undefined reference` 错误。如果遇到这种情况，确保 `driver_io` 在 `driver_serial` 之前链接。

## 第五步 —— 编译验证

```bash
# 清理旧的构建
rm -rf build

# 重新配置
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 构建
cmake --build build
```

**预期输出**：

```
[ 10%] Building C object kernel/CMakeFiles/kernel_base.dir/base/memory.c.o
[ 20%] Building C object kernel/CMakeFiles/driver_io.dir/io/io.c.o
[ 30%] Building C object kernel/CMakeFiles/driver_serial.dir/serial/serial.c.o
[ 40%] Building C object kernel/CMakeFiles/kernel.elf.dir/kernel_init.c.o
[ 50%] Building C object kernel/CMakeFiles/kernel.elf.dir/kernel_main.c.o
[ 60%] Linking C executable kernel.elf
[100%] Built target kernel.elf
```

### 常见编译错误

如果遇到 `undefined reference to 'inb'`：

```cmake
# 确保链接顺序正确
target_link_libraries(kernel.elf PRIVATE
    driver_serial    # 会自动链接 driver_io
    driver_io        # 或者显式链接在这里
)
```

如果遇到 `undefined reference to 'serial_init'`：

```cmake
# 确保 driver_serial 被链接
target_link_libraries(kernel.elf PRIVATE
    driver_serial
)
```

## 第六步 —— 验证链接输出

让我们看看内核 ELF 文件是否包含了我们的新代码：

```bash
# 查看符号表
nm build/kernel/kernel.elf | grep -E "(serial|memory|inb|outb)"
```

**预期输出**：

```
0000000000001234 T serial_init
0000000000001280 T sync_serial_putc
00000000000012a0 T sync_serial_puts
0000000000001300 T memset
0000000000001320 T memcpy
0000000000001340 T memmove
0000000000001360 T memcmp
0000000000001380 T inb
0000000000001390 T outb
```

如果能看到这些符号，说明链接成功了。

`T` 表示符号在代码段（Text segment），是可执行函数。如果你看到 `U`（Undefined），说明链接有问题。

## 第七步 —— 快速串口测试

在完整测试之前，我们先快速验证串口输出是否工作。

创建一个简单的测试脚本 `test_serial.sh`：

```bash
#!/bin/bash

# 启动 QEMU，串口重定向到 stdio
qemu-system-x86_64 \
    -drive format=raw,file=build/boot.img \
    -nographic \
    -serial mon:stdio
```

运行脚本：

```bash
chmod +x test_serial.sh
./test_serial.sh
```

**预期输出**：

```
QEMU 7.0.0 monitor - type 'help' for commands
(qemu) === CCOS Bootloader v1.0 ===
[Serial] Bootloader initialized
[Serial] Entering protected mode...
[Serial] Loading kernel...
=== CCOS Kernel ===
Serial port initialized at 115200 8N1
[KERNEL] Hello from CCOS kernel!
[KERNEL] Kernel is running in 64-bit long mode.
[KERNEL] VGA + Serial dual output is working!
[INFO] System initialized successfully
[WARN] This is a warning message
[ERROR] This is an error message
```

如果你看到这些输出，恭喜！串口驱动已经成功集成了。

注意 `qemu-system-x86_64` 的 `QEMU 7.0.0 monitor` 输出是 QEMU 自身的，不是内核的输出。内核的输出从 `=== CCOS Bootloader ===` 开始。

### 如果没有串口输出

如果看不到串口输出，按 `Ctrl+A, X` 退出 QEMU，然后检查以下几点：

1. **QEMU 参数是否正确**：确保加了 `-serial mon:stdio`
2. **serial_init 是否被调用**：用 GDB 检查
3. **端口地址是否正确**：COM1 应该是 0x3F8
4. **Bootloader 串口是否工作**：如果 Bootloader 没有输出，说明问题在更早阶段

## 第八步 —— 调试技巧

如果串口不工作，可以用以下方法调试。

### 使用 GDB 检查

```bash
# 在一个终端启动 QEMU（带 GDB）
qemu-system-x86_64 \
    -drive format=raw,file=build/boot.img \
    -nographic \
    -serial mon:stdio \
    -s -S

# 在另一个终端启动 GDB
gdb build/kernel/kernel.elf
(gdb) target remote :1234
(gdb) break serial_init
(gdb) continue
(gdb) print *(uint8_t*)0x3F8  # 查看串口端口
```

### 检查端口值

在 GDB 中，你可以直接读取 I/O 端口：

```gdb
# 读取 LSR 寄存器
(gdb) call inb(0x3FD)
# 如果返回 0x60 (0x20 = THRE, 0x40 = TEMT)，说明串口可用

# 读取 LCR 寄存器
(gdb) call inb(0x3FB)
# 应该返回 0x03 (8N1 格式)
```

### 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 完全没有输出 | QEMU 参数错误 | 检查 `-serial` 参数 |
| 只有 Bootloader 输出 | 内核串口未初始化 | 检查 `serial_init` 是否被调用 |
| 输出乱码 | 波特率不匹配 | 检查 DLL/DLM 值 |
| 输出中断 | 某个字符触发特殊序列 | 避免输出 `\0` 等特殊字符 |

## 第九步 —— VGA 与串口双输出

现在内核能同时输出到 VGA 和串口。这是一个很好的调试配置：

- **VGA**：用于查看当前状态、图形界面
- **串口**：用于完整日志、长期记录

在 QEMU 中，你可以同时使用两者：

```bash
qemu-system-x86_64 \
    -drive format=raw,file=build/boot.img \
    -vga std -display gtk \
    -nographic \
    -serial mon:stdio
```

这会打开一个 GTK 窗口显示 VGA，同时串口输出到终端。

### 为什么先 VGA 后串口

你可能会问：为什么我们不先初始化串口？

这是一个基本的调试原则：**在可能出错的操作之前，先确保有可用的调试输出**。

如果先初始化串口，而串口初始化失败（比如硬件不支持），我们就没有任何调试输出了。这时即使 VGA 也没初始化成功，我们也不知道问题出在哪里。

但如果我们先初始化 VGA，即使串口失败，我们还能在 VGA 上看到错误信息。

这是很多操作系统的做法：先初始化最简单、最可靠的输出设备，再初始化其他设备。

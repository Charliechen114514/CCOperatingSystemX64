# 04 - UART 16550 串口驱动实现

串口是裸机开发中最有用的调试工具，没有之一。

---

## 我们现在要做什么

我们需要实现一个完整的 UART 16550 串口驱动，包括串口初始化、字符输出、字符串输出。

最终我们能在串口上看到内核的调试输出，这比盯着 VGA 屏幕舒服太多了。

但在这之前，我们需要理解 UART 16550 的工作原理。这是一款有四十多年历史的芯片，但至今仍在广泛使用。

---

## 第一步 —— UART 16550 的历史

UART 16550 的历史可以追溯到 1980 年代。当时的 National Semiconductor（后来被 Intel 收购）推出了这款芯片，作为 PC 串口控制器的标准。

在 16550 之前，有 8250（用于最初的 IBM PC）、16450（改进版本）。但这些芯片没有 FIFO 缓冲，每次只能发送/接收一个字节。在高波特率下，CPU 需要频繁响应中断，否则会丢失数据。

16550 的重大改进是添加了 16 字节的 FIFO 缓冲。这意味着 CPU 可以一次处理更多数据，中断频率大大降低，系统效率显著提升。

有趣的是，早期的 16550 有一个 bug：FIFO 不工作。这些芯片被标记为 16550AF。后来修复的版本叫 16550A，是我们今天使用的版本。

到了 1990 年代，出现了 16550D，添加了更多功能。但基本寄存器接口保持不变，这就是为什么 40 年前的代码今天仍然能工作。

在 PC 上，COM1 串口的基地址是 0x3F8，这几乎成了行业标准。从 IBM PC 到现代服务器，你都能找到这个地址。

---

## 第二步 —— 寄存器映射与 DLAB 机制

UART 16550 有一组寄存器，通过端口 I/O 访问。但这里有个特殊的设计：**有些寄存器共享同一个端口地址**。

让我们看看实际的寄存器定义（来自我们的 `serial_config.h`）：

```c
// COM1 base I/O port (standard for x86)
#define SERIAL_COM1_BASE 0x3F8

// UART 16550 register offsets
#define SERIAL_DATA_REG(base)        ((base) + 0)  // Data register
#define SERIAL_INT_ENABLE_REG(base)  ((base) + 1)  // Interrupt enable
#define SERIAL_FIFO_CTRL_REG(base)   ((base) + 2)  // FIFO control
#define SERIAL_LINE_CTRL_REG(base)   ((base) + 3)  // Line control
#define SERIAL_MODEM_CTRL_REG(base)  ((base) + 4)  // Modem control
#define SERIAL_LINE_STATUS_REG(base) ((base) + 5)  // Line status

// Line status register bits
#define SERIAL_LSR_READY_TO_SEND 0x20  // Transmit hold register empty
```

注意到偏移 +0 和 +1 的寄存器有两个用途！这就是 DLAB（Divisor Latch Access Bit）机制。

### DLAB 机制详解

DLAB 是线路控制寄存器（LCR）的第 7 位。当 DLAB=1 时，偏移 +0 和 +1 访问波特率除数寄存器；当 DLAB=0 时，它们访问正常的数据/中断寄存器。

```
DLAB = 0 时：
偏移 +0: THR/RBR (发送保持/接收缓冲)
偏移 +1: IER (中断使能)

DLAB = 1 时：
偏移 +0: DLL (除数低字节)
偏移 +1: DLM (除数高字节)
```

为什么这样设计？因为 I/O 端口地址是宝贵的资源。PC 的 I/O 空间只有 64KB，每个设备只能分配少数几个端口。通过复用寄存器，16550 只需要 8 个端口就能实现所有功能。

这在今天看来有点奇怪，但在 1980 年代，这是非常聪明的设计。

### 完整寄存器表

| 偏移 | DLAB=0 读 | DLAB=0 写 | DLAB=1 读 | DLAB=1 写 | 说明 |
|------|----------|----------|----------|----------|------|
| +0 | RBR | THR | DLL | DLL | 接收/发送/除数低 |
| +1 | IER | - | DLM | DLM | 中断使能/除数高 |
| +2 | IIR | FCR | - | - | 中断识别/FIFO 控制 |
| +3 | LCR | LCR | - | - | 线路控制 |
| +4 | MCR | MCR | - | - | 调制解调器控制 |
| +5 | LSR | - | - | - | 线路状态 |
| +6 | MSR | - | - | - | 调制解调器状态 |
| +7 | SCR | SCR | - | - | 暂存寄存器 |

现在我们只需要几个寄存器：
- **THR (Transmit Holding Register)**：写入要发送的数据
- **LSR (Line Status Register)**：检查发送缓冲区是否为空
- **LCR (Line Control Register)**：配置数据格式和 DLAB
- **DLL/DLM**：设置波特率
- **FCR (FIFO Control Register)**：启用和配置 FIFO
- **MCR (Modem Control Register)**：控制调制解调器信号

### LSR 寄存器详解

LSR 寄存器告诉我们串口的当前状态。我们只关心其中一位：

| 位 | 名称 | 说明 |
|----|------|------|
| 5 | THRE | 发送保持寄存器为空 (Transmitter Holding Register Empty) |

当 THRE=1 时，表示 THR 为空，可以写入新数据。我们在发送字符之前要检查这个位。

## 第四步 —— 波特率计算

串口的波特率由一个内部除数控制。UART 的基准时钟是 1.8432 MHz。

```
波特率 = 时钟频率 / (16 × 除数)
除数 = 时钟频率 / (16 × 波特率)
```

对于 115200 波特率：

```
除数 = 1843200 / (16 × 115200) = 1843200 / 1843200 = 1
```

所以 DLL=1，DLM=0。

### 为什么是 1.8432 MHz？

你可能好奇，为什么 UART 时钟是这么奇怪的频率？

这个频率的选择是为了能整除常见的波特率。早期串口常用的波特率是 300、1200、2400、9600 等。1.8432 MHz 能精确产生这些波特率：

| 波特率 | 除数 | DLL | DLM |
|--------|------|-----|-----|
| 115200 | 1 | 0x01 | 0x00 |
| 57600 | 2 | 0x02 | 0x00 |
| 38400 | 3 | 0x03 | 0x00 |
| 19200 | 6 | 0x06 | 0x00 |
| 9600 | 12 | 0x0C | 0x00 |

这个频率来自 PC 的时钟历史。最早的 IBM PC 使用 14.31818 MHz 的晶振，这个频率能同时产生 NTSC 彩色电视信号（4.572 × 3.579545 MHz）和串口时钟。1.8432 MHz 是 14.31818 MHz 的 1/8。

### 常用波特率表

在我们的实现中，我们使用 115200 波特率，这是现代系统的标准配置。但了解一下其他波特率也有好处：

| 波特率 | 除数值 | 常见用途 |
|--------|--------|----------|
| 300 | 384 | 极慢速设备（早期的调制解调器） |
| 1200 | 96 | 慢速设备 |
| 9600 | 12 | 传统默认值 |
| 115200 | 1 | 现代高速串口 |

如果你要连接旧设备，可能需要使用较低的波特率。

## 第五步 —— 实现串口初始化

现在我们开始实现串口驱动。创建 `kernel/driver/serial/serial.h`：

```c
/**
 * @file serial.h
 * @brief Serial port driver for kernel debug output (UART 16550)
 */
#pragma once

#include "defines/types.h"
#include "serial_config.h"

/**
 * @brief Initialize the serial port (COM1) for communication.
 *        Configured to 115200 baud, 8 data bits, no parity, 1 stop bit (8N1).
 *
 * @return true  - if serial port was successfully initialized
 * @return false - if serial port is not available or initialization failed
 */
bool serial_init(void);

/**
 * @brief Send a null-terminated string through the serial port (blocking).
 *
 * @param str - string to send
 */
void sync_serial_puts(const char* str);
```

创建 `kernel/driver/serial/serial.c`：

```c
#include "serial.h"
#include "io/io.h"

// 波特率除数（115200 = 除数 1）
#define BAUD_DIVISOR_LOW  1
#define BAUD_DIVISOR_HIGH 0

/**
 * @brief Send single character (blocking)
 */
static void sync_serial_putc(char c) {
    const uint16_t base = SERIAL_COM1_BASE;

    // 等待发送保持寄存器为空
    while ((inb(SERIAL_LINE_STATUS_REG(base)) & SERIAL_LSR_READY_TO_SEND) == 0) {
        // 忙等待 - CPU spins until ready
    }

    // 发送字符
    outb(SERIAL_DATA_REG(base), (uint8_t)c);
}

bool serial_init(void) {
    const uint16_t base = SERIAL_COM1_BASE;

    // Step 1: 禁用中断
    outb(SERIAL_INT_ENABLE_REG(base), 0x00);

    // Step 2: 启用 DLAB（设置波特率需要）
    outb(SERIAL_LINE_CTRL_REG(base), 0x80);

    // Step 3: 设置波特率除数
    outb(SERIAL_DATA_REG(base), BAUD_DIVISOR_LOW);   // DLL
    outb(SERIAL_INT_ENABLE_REG(base), BAUD_DIVISOR_HIGH);  // DLM

    // Step 4: 配置 8N1 格式
    outb(SERIAL_LINE_CTRL_REG(base), 0x03);

    // Step 5: 启用 FIFO，清空缓冲，设置 14 字节阈值
    outb(SERIAL_FIFO_CTRL_REG(base), 0xC7);

    // Step 6: 设置调制解调器控制（启用 RTS/DSR）
    outb(SERIAL_MODEM_CTRL_REG(base), 0x0B);

    return true;
}

void sync_serial_puts(const char* str) {
    if (str == NULL) {
        return;
    }

    while (*str != '\0') {
        sync_serial_putc(*str);
        str++;
    }
}
```

### 初始化流程详解

让我们逐个步骤理解串口初始化：

**Step 1: 禁用中断**

```c
outb(SERIAL_INT_ENABLE_REG(base), 0x00);
```

我们使用轮询模式，不需要中断。把 IER（Interrupt Enable Register）设为 0，禁用所有中断。

**Step 2: 启用 DLAB**

```c
outb(SERIAL_LINE_CTRL_REG(base), 0x80);
```

0x80 的二进制是 10000000，第 7 位是 DLAB 位。把它设为 1，就可以访问波特率除数寄存器。

**Step 3: 设置波特率除数**

```c
outb(SERIAL_DATA_REG(base), BAUD_DIVISOR_LOW);   // DLL = 1
outb(SERIAL_INT_ENABLE_REG(base), BAUD_DIVISOR_HIGH);  // DLM = 0
```

因为 DLAB=1，所以偏移 +0 是 DLL，偏移 +1 是 DLM。我们写入除数 1（DLL=1, DLM=0），对应 115200 波特率。

**Step 4: 配置 8N1 格式**

```c
outb(SERIAL_LINE_CTRL_REG(base), 0x03);
```

0x03 的二进制是 00000011：
- 位 1-0: 11 = 8 数据位
- 位 2: 0 = 1 停止位
- 位 3: 0 = 无校验
- 位 7: 0 = 禁用 DLAB（恢复正常寄存器访问）

**Step 5: 启用 FIFO**

```c
outb(SERIAL_FIFO_CTRL_REG(base), 0xC7);
```

0xC7 的二进制是 11000111：
- 位 0: 1 = 启用 FIFO
- 位 1: 1 = 清空接收 FIFO
- 位 2: 1 = 清空发送 FIFO
- 位 6-7: 11 = 14 字节触发阈值

### FIFO 阈值为什么是 14 字节？

这是个好问题。16550 的 FIFO 是 16 字节。当接收 FIFO 中的数据达到阈值时，UART 会触发中断通知 CPU 读取数据。

为什么是 14 而不是 16？这是为了给 CPU 留出时间响应中断。如果阈值是 16，那么 FIFO 满了才触发中断。如果这时又来了新数据，就会因为 FIFO 满而丢失。

把阈值设为 14，意味着还有 2 个字节的空间时就会触发中断。这给了 CPU 一定的"时间裕度"，减少了数据丢失的风险。

当然，这是中断驱动的设计考虑。对于我们的轮询模式来说，阈值不太重要，因为我们每次都检查 FIFO 状态。

**Step 6: 设置调制解调器控制**

```c
outb(SERIAL_MODEM_CTRL_REG(base), 0x0B);
```

0x0B 的二进制是 00001011：
- 位 0: 1 = DTR (Data Terminal Ready) 有效
- 位 1: 1 = RTS (Request to Send) 有效
- 位 3: 1 = 辅助输出 2（用于中断）

这些信号用于硬件流控。在实际连接设备时，对方设备会检测这些信号，确认我们准备好通信。

如果不需要硬件流控，可以把 MCR 设为 0x03（只设置 DTR 和 RTS）或 0x00（全部禁用）。

## 第六步 —— 发送字符流程

`sync_serial_putc` 的流程很简单，但值得理解一下硬件机制：

```c
while ((inb(SERIAL_LINE_STATUS_REG(base)) & SERIAL_LSR_READY_TO_SEND) == 0) {
    // 忙等待 - CPU spins until ready
}

outb(SERIAL_DATA_REG(base), (uint8_t)c);
```

### UART 发送机制

UART 的发送部分有几个关键组件：

1. **THR (Transmit Holding Register)**：我们写入数据的地方
2. **发送移位寄存器**：硬件自动把 THR 的数据转移到这里，然后逐位移出
3. **LSR.THR**：指示 THR 是否为空

流程是这样的：

```
我们写入 THR → 数据移到发送移位寄存器 → 逐位发送到线路
     ↓              ↓                    ↓
   THR 满      移位寄存器忙          正在发送
```

当 THR 为空（LSR.THR=1）时，表示我们可以写入新数据。即使移位寄存器还在发送之前的数据，新数据也会被缓存到 THR 中。

这就是为什么叫"保持寄存器"（Holding Register）——它保持数据，等待移位寄存器空闲。

### 忙等待 vs 中断

我们的实现使用忙等待（busy waiting）。这意味着 CPU 会一直循环检查 LSR，直到 THR 为空。

这对于低速操作（如初始化、调试输出）是完全可以接受的。但如果要高速发送大量数据，CPU 会浪费很多时间在等待上。

更高效的方式是使用中断驱动：当 THR 为空时，UART 触发中断，CPU 在中断处理程序中写入下一个数据。这样 CPU 在等待时可以做其他事情。

但中断驱动需要完整的中断系统支持，比轮询复杂得多。对于我们的内核调试输出，轮询方式足够了。

## 第七步 —— 硬件流控

你可能注意到了 MCR 中的 RTS（Request to Send）信号。这是硬件流控的一部分。

硬件流控用两根信号线：
- **RTS (Request to Send)**：我们告诉对方"我准备好接收数据了"
- **CTS (Clear to Send)**：对方告诉我们"我准备好接收你的数据了"

当 CTS=0 时，我们暂停发送，等待对方准备好。这防止了数据发送过快导致对方丢失数据。

我们的实现启用了 RTS（MCR 位 1），但没有实现 CTS 检查。对于调试输出来说这不是问题，因为对方（通常是 PC 的串口终端）不会丢失数据。

如果你要连接实际设备，可能需要实现完整的硬件流控。这需要检查 MSR（Modem Status Register）的 CTS 位，只在 CTS=1 时发送数据。

## 第八步 —— 更新 CMakeLists.txt

在 `kernel/driver/CMakeLists.txt` 中添加：

```cmake
# 串口驱动
add_library(driver_serial INTERFACE
    serial/serial.c
    serial/serial.h
    serial/serial_config.h
)

target_include_directories(driver_serial INTERFACE
    ${CMAKE_CURRENT_SOURCE_DIR}
)

# 串口依赖端口 I/O
target_link_libraries(driver_serial INTERFACE driver_io)
```

注意到我们声明了串口驱动对 I/O 驱动的依赖。这样在链接时会自动包含 `inb` 和 `outb` 函数。

## 第九步 —— 兼容性说明

UART 16550 的一个优点是它的向后兼容性。

如果你的代码在 16550 上工作，它也能在以下芯片上工作：
- 16750：增加了 64 字节 FIFO
- 16850：增加了自动流控
- 16950：增加了完全软件控制的硬件流控

这些芯片都保持了与 16550 兼容的寄存器接口（至少在基本功能上）。

同样，我们的代码也能在 8250/16450 上工作（没有 FIFO）。FCR 寄存器的写入会被忽略，芯片会以兼容模式运行。

这就是为什么 40 年前的串口代码今天仍然能工作——硬件保持了向后兼容。

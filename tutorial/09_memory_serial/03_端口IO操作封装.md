# 03 - 端口 I/O 操作封装

在 x86 架构上，访问硬件设备有两种方式：内存映射 I/O 和端口 I/O。串口使用的是端口 I/O，所以我们需要先封装好端口操作。

---

## 我们现在要做什么

我们需要实现两个核心函数：

```c
uint8_t inb(uint16_t port);   // 从端口读取一个字节
void outb(uint16_t port, uint8_t data);  // 向端口写入一个字节
```

这两个函数会直接使用 x86 的 `in` 和 `out` 指令，是串口驱动的基础。

---

## 第一步 —— 理解端口 I/O

在 x86 架构中，CPU 有独立的地址空间：

| 地址空间 | 用途 | 访问方式 |
|---------|------|----------|
| 内存地址空间 | RAM、内存映射设备 | `mov` 指令 |
| I/O 端口空间 | 硬件设备寄存器 | `in`/`out` 指令 |

串口设备位于 I/O 端口空间，地址是 `0x3F8`（COM1）。

**为什么要有两种方式？**

这是历史遗留设计。早期 PC 的 I/O 总线（ISA）与内存地址线是分离的。现在虽然大多设备使用内存映射 I/O，但串口等传统设备仍然保留端口 I/O 方式。

---

## 第二步 —— 创建驱动目录

```bash
mkdir -p kernel/driver/io
```

## 第三步 —— 实现端口 I/O 函数

创建头文件 `kernel/driver/io/io.h`：

```c
/**
 * @file io.h
 * @brief x86 Port I/O operations
 */
#pragma once

#include "defines/types.h"

/**
 * @brief Read one byte from the specified port
 * @param port Port number (0-65535)
 * @return Byte read from port
 */
uint8_t inb(uint16_t port);

/**
 * @brief Write one byte to the specified port
 * @param port Port number (0-65535)
 * @param data Byte to write
 */
void outb(uint16_t port, uint8_t data);
```

创建实现文件 `kernel/driver/io/io.c`：

```c
#include "io.h"

uint8_t inb(uint16_t port) {
    uint8_t result;
    __asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
    return result;
}

void outb(uint16_t port, uint8_t data) {
    __asm__ volatile("outb %0, %1" : : "a"(data), "Nd"(port));
}
```

---

## 第四步 —— 理解内联汇编

这里我们使用 GCC 内联汇编，让我逐行解释：

### inb 函数分解

```c
__asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
//      ^        ^            ^           ^
//      |        |            |           |
//    volatile  汇编模板    输出操作数   输入操作数
```

| 部分 | 含义 |
|------|------|
| `volatile` | 告诉编译器不要优化掉这条指令 |
| `"inb %1, %0"` | 汇编模板，`%0`=`result`，`%1`=`port` |
| `"=a"(result)` | 输出到 AL/EAX/RAX 寄存器 |
| `"Nd"(port)` | 输入可以是立即数或 DX 寄存器 |

**约束说明**：

- `"a"` — 使用 AL/A/EAX/RAX 寄存器（自动选择大小）
- `"Nd"` — 允许 0-255 的立即数，或者 DX 寄存器

### outb 函数分解

```c
__asm__ volatile("outb %0, %1" : : "a"(data), "Nd"(port));
//                     ^           ^
//                     |           |
//               没有输出      两个输入
```

`outb` 指令的格式是 `outb 立即数/寄存器, 端口`，所以：
- `%0` = `data`（在 AL 寄存器中）
- `%1` = `port`（立即数或 DX 寄存器）

---

## 第五步 —— 为什么需要 volatile

这是一个非常重要的坑点。

**没有 volatile 会发生什么？**

```c
// 没有 volatile 的版本
uint8_t inb_bad(uint16_t port) {
    uint8_t result;
    __asm__("inb %1, %0" : "=a"(result) : "Nd"(port));
    return result;
}

// 编译器可能优化成这样：
uint8_t inb_optimized(uint16_t port) {
    (void)port;  // 未使用警告
    return 0;    // ??? 完全错了！
}
```

**问题原因**：

编译器的优化器看到：
1. 没有明显的副作用
2. 结果没有被使用（在某种优化级别下）
3. 既然没有副作用，直接删除好了

**volatile 的作用**：

```c
// 有 volatile 的版本
__asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
```

`volatile` 告诉编译器：**这条指令有副作用，绝对不能删除或重排**。

对于 I/O 操作，副作用就是"读写硬件设备"，这在 C 代码中是看不见的。

在 `kernel/driver/CMakeLists.txt` 中添加：

```cmake
# I/O 端口操作
add_library(driver_io INTERFACE

    io/io.h
)

target_include_directories(driver_io INTERFACE
    ${CMAKE_CURRENT_SOURCE_DIR}
)
```

## 第八步 —— 常见陷阱

### 陷阱 1：忘记 volatile

```c
// ❌ 错误：可能被编译器优化掉
__asm__("inb %1, %0" : "=a"(result) : "Nd"(port));

// ✅ 正确：保证指令执行
__asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
```

### 陷阱 2：错误的寄存器约束

```c
// ❌ 错误：端口必须在 DX 或立即数
__asm__ volatile("inb %1, %0" : "=a"(result) : "b"(port));

// ✅ 正确：使用 "Nd" 约束
__asm__ volatile("inb %1, %0" : "=a"(result) : "Nd"(port));
```

### 陷阱 3：端口地址范围

I/O 端口是 16 位的，范围是 0-65535。

```c
// COM1 串口基地址
#define SERIAL_COM1 0x3F8  // ✅ 正确
#define SERIAL_COM1 0x3F800  // ❌ 错误：超过 16 位
```

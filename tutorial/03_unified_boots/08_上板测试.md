# 上板测试

代码写完了，构建系统也好了，现在让我们验证一下。

---

## 编译验证

首先确保代码能编译通过：

```bash
cd /path/to/CCOperatingSystemX64
make clean
make
```

你应该看到类似这样的输出：

```
==> Building bootloader...
==> Bootloader size: 1999 bytes
==> Building kernel...
==> Kernel size: 15680 bytes
==> Generating boot image...
Bootloader: 4 sectors
==> Boot image generated: build/boot.img
```

**检查点**：
1. bootloader 大小应该在 2KB 左右（不超过 4KB）
2. kernel 大小根据你的代码而定
3. boot.img 应该成功生成

### 检查二进制文件

```bash
# 查看文件大小
ls -lh build/bootloader.bin
ls -lh build/kernel.bin
ls -lh build/boot.img

# 查看 bootloader 前几字节
hexdump -C build/bootloader.bin | head -10

# 查看 MBR 签名（应该在偏移 0x1FE 处）
xxd -s 0x1FE -l 2 build/bootloader.bin
```

你应该能看到 MBR 签名 `55 AA`。

---

## 反汇编验证

让我们验证生成的二进制文件是否正确：

```bash
# 反汇编 Stage 1 (从 0x7C00 开始)
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | head -30

# 检查 MBR 签名
xxd -s 0x1FE -l 2 build/bootloader.bin
```

你应该能看到：
- 代码从 `00007C00` 开始
- 偏移 `0x01FE` 处是 `55 AA`

### 检查 Stage 2

```bash
# Stage 2 从文件偏移 0x200 开始
ndisasm -b 16 -o 0x7E00 -e 0x200 build/bootloader.bin | head -30
```

`-e 0x200` 告诉 ndisasm 从文件偏移 0x200 开始反汇编。

## QEMU 运行测试

### 基本运行

```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -serial stdio
```

你应该能看到 VGA 和串口都有输出：

```
=== BootLoader Stage Start ===
READY TO BOOT CCOS
[1] Stage 1: Loading second stage...
[2] Stage 2: Loading kernel...
[MODE] Using LBA extended read
[LOAD] LBA: loading 31 sectors
READY TO BOOT KERNEL
=== BootLoader Stage End ===
```

### 检查各个阶段

如果系统卡住，检查是哪个阶段出了问题：

1. **Stage 1 输出正常吗？** - 看到 `[1] Stage 1: ...` 说明 Stage 1 工作正常
2. **Stage 2 输出正常吗？** - 看到 `[2] Stage 2: ...` 说明 Stage 1→Stage 2 跳转成功
3. **磁盘读取正常吗？** - 看到模式选择和扇区数说明磁盘读取成功
4. **长模式切换成功吗？** - 看到 `READY TO BOOT KERNEL` 说明切换成功

## GDB 调试

如果系统卡住，我们需要用 GDB 来定位问题。

### 启动 QEMU GDB 服务器

在一个终端运行：

```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S
```

`-s` 参数启动 GDB 服务器（监听 1234 端口）
`-S` 参数让 CPU 在启动时暂停

### 连接 GDB

在另一个终端运行：

```bash
gdb build/bootloader.bin
```

然后在 GDB 中：

```
(gdb) target remote :1234
(gdb) break *0x7C00
(gdb) continue
```

### 常用断点位置

```
# Stage 1 入口
(gdb) break *0x7C00

# Stage 2 入口
(gdb) break *0x7E00

# 保护模式入口
(gdb) break *0x7E00 + 0x100  # 根据实际代码调整

# 长模式入口
(gdb) break *0x10000  # 内核入口
```

### 单步执行

```
(gdb) si       # 单步执行（汇编指令）
(gdb) ni       # 下一行（跳过函数调用）
(gdb) continue # 继续执行
```

### 检查寄存器和内存

```
(gdb) info registers   # 查看所有寄存器
(gdb) print $eax       # 查看特定寄存器
(gdb) x/10x 0x7C00     # 查看内存（16 进制）
(gdb) x/10i 0x7C00     # 查看内存（反汇编）
(gdb) x/10s 0x7E00     # 查看内存（字符串）
```

## 常见问题和解决方法

### 问题 1：系统启动后直接卡死

**可能原因**：
- Stage 1 代码有问题
- MBR 签名不正确
- 串口初始化有问题

**解决方法**：
1. 检查 MBR 签名：`xxd -s 0x1FE -l 2 build/bootloader.bin`
2. 用 GDB 单步执行 Stage 1
3. 先去掉串口初始化，看是否是串口的问题

### 问题 2：看不到 Stage 2 输出

**可能原因**：
- Stage 2 磁盘读取失败
- Stage 1→Stage 2 跳转地址不对
- vstart 设置错误

**解决方法**：
1. 检查 Stage 1 的磁盘读取代码
2. 用 GDB 断点在 `0x7E00`，看是否能到达
3. 检查 `vstart=0x7E00` 是否正确设置

### 问题 3：看到 Stage 2 输出但卡在磁盘读取

**可能原因**：
- LBA 检测失败
- 磁盘读取参数错误
- 内核扇区数不正确

**解决方法**：
1. 检查 `boot_config.inc` 中的配置
2. 用 GDB 检查磁盘读取后的内存内容
3. 尝试强制使用 CHS 模式

### 问题 4：长模式切换失败

**可能原因**：
- GDT 设置错误
- 页表设置错误
- CR0/CR4/EFER 设置错误

**解决方法**：
1. 用 GDB 检查 CR0、CR4、CR3 寄存器
2. 检查页表内容（0x9000-0xBFFF）
3. 确认 EFER.LME 位已设置

### 问题 5：内核无法执行

**可能原因**：
- 内核没有正确加载
- 内核入口地址错误
- 内核代码有问题

**解决方法**：
1. 检查 `boot_config.inc` 中的 `KERNEL_LOAD_SEGMENT`
2. 用 GDB 检查 0x10000 处的内存内容
3. 单独测试内核

## 性能验证

虽然 bootloader 不会运行很长时间，但我们也可以看看性能：

```bash
# 测量启动时间
time qemu-system-x86_64 -drive format=raw,file=build/boot.img -serial stdio -nographic
```

你应该能看到类似这样的输出：

```
=== BootLoader Stage Start ===
...
=== BootLoader Stage End ===

real    0m0.123s
user    0m0.045s
sys     0m0.012s
```

启动时间应该在 100-200ms 左右。

# 第一步 - 合并两个文件

好，现在我们开始动手。

---

## 我们的起点

首先看一下我们现在有什么。如果你跟着之前的教程做下来，你的 boot 目录应该是这样的：boot.asm 和 boot2.asm 两个文件，还有一个 lib 目录存放一些公用的函数。我们的目标是创建一个新的 bootloader.asm，把这两个文件的内容合并进去，使用 section 指令分离两个阶段，然后删除旧文件。

---

## 第一步：创建新文件

先别急着复制代码，我们先把文件创建出来。cd 到你的 boot 目录，用 touch 命令创建一个空的 bootloader.asm。现在打开你最喜欢的编辑器，准备开始写代码。

---

## 第二步：写入 Stage 1 代码

我们从 Stage 1 开始。这部分代码基本来自原来的 boot.asm，但我们会做一些调整。首先在文件开头加一个注释块，说明这个文件的用途和结构，然后定义 .mbr 段。

MBR 段的开头是这样的：我们先声明这是一个 section，名字叫 .mbr，然后 org 0x7c00 告诉 NASM 这段代码会被加载到 0x7C00，bits 16 说明这是 16 位实模式代码。接下来是 start 标签，这是我们代码的入口点。

在 start 里，我们首先要做一些标准的初始化工作。cli 关闭中断，然后把段寄存器都清零，设置栈指针指向 0x7C00，最后再 sti 打开中断。这些是 bootloader 启动的标准流程，不做这些的话后续代码可能会出各种奇怪的问题。

初始化完成后，我们调用 BIOS 的清屏功能，int 0x10 的 AH=0x00 AL=0x03 可以清屏并设置文本模式。然后我们打印一些欢迎信息，让用户知道系统正在启动。这些信息会同时输出到 VGA 屏幕和串口，这样无论是在图形界面还是终端里都能看到输出。

接下来是关键的一步：从磁盘读取 Stage 2。我们用 BIOS 的 int 0x13 AH=0x02 功能，参数设置成读取两个扇区到 0x7E00 这个地址。这里要注意的是，我们读取的是扇区 2 和扇区 3，因为扇区 1 是 MBR 本身。如果读取失败，CF 标志位会被设置，我们跳转到错误处理代码；如果成功，AL 会返回实际读取的扇区数，我们需要验证它是否等于我们请求的数量。

读取成功后，我们用 jmp 0x7E00 跳转到 Stage 2。这个跳转会把 CS:IP 设置成 0x0000:0x7E00，正好是 Stage 2 的入口地址。

错误处理代码很简单，就是打印一条错误信息然后进入死循环。hlt 让 CPU 停机，jmp .hang 无限循环，这样系统就不会继续执行下去。

打印函数 print_string 也很直接，用 lodsb 逐个读取字符串字符，遇到零就结束，否则就用 int 0x10 AH=0x0E 打印到屏幕上。

最后是数据段，我们定义了几个字符串常量。header_msg 是启动标题，welcome_msg 是第一阶段的消息，load_error_msg 是加载失败时的错误信息。

MBR 段的最后是填充和签名。times 510-($-$$) db 0 会用零填充到 510 字节，确保我们的代码加上填充正好是 510 字节。然后 dw 0xaa55 是 MBR 签名，这个是必须的，否则 BIOS 不会认为这是一个有效的启动扇区。

---

## 第三步：添加 Stage 2 代码

现在我们在同一个文件里添加 Stage 2。这里有个坑，我们用 vstart 而不是 org。vstart=0x7E00 告诉 NASM 这个 section 里的所有标签值都要加上 0x7E00 的偏移，这样标签的值就是正确的运行时地址了。如果用 org 或者干脆不写，gdt_ptr 里的地址会错得一塌糊涂，系统会在 lgdt 那里崩溃。

Stage 2 的入口是 stage2_entry，我们先跳过一段空隙到 stage2_main，这段空隙是用来放 GDT 的。GDT 即全局描述符表，定义了代码段和数据段的描述符。我们有五个 GDT 项：第一个是空描述符，第二个是 32 位代码段，第三个是 32 位数据段，第四个是 64 位代码段，第五个是 64 位数据段。gdt_ptr 结构包含 GDT 的限制和基址，基址是 0x7E03，正好是 gdt_start 的运行时地址。

在 stage2_main 里，我们先做一些初始化，然后打印一条消息，告诉用户 Stage 2 正在加载内核。接下来我们会调用 load_kernel_auto 函数，这个函数会先用 LBA 方式读取内核，如果失败就回退到 CHS 方式。如果内核加载成功，我们打印一条成功消息，然后加载 GDT，设置 CR0 的 PE 位进入保护模式。

保护模式的切换是通过一个 far jump 实现的。我们需要跳转到 32 位代码段，但 NASM 在 16 位模式下不能直接生成 32 位的 far jump，所以我们用 db 指令手动编码跳转指令。db 0x66 是操作数大小前缀，db 0xEA 是 jump far 的操作码，dd pm_entry 是目标地址，dw 0x08 是段选择子。

print_bios 函数和 Stage 1 的 print_string 几乎一模一样，也是用 int 0x10 AH=0x0E 打印字符串。消息定义了 Stage 2 的提示信息、内核加载成功的消息，以及加载失败的错误信息。

---

## 第四步：添加保护模式代码

继续添加保护模式部分。这里我们用 bits 32 告诉 NASM 接下来生成 32 位指令。

保护模式入口 pm_entry 首先设置各个段寄存器，然后把栈指针设置好。接着调用 setup_page_tables 设置页表，这是进入长模式必须的步骤。页表设置涉及到 4 级页表结构：PML4、PDPT、PD 和 PT。我们这里用的是 2MB 大页，所以不需要 PT。

页表设置完成后，我们启用 PAE，这通过设置 CR4 的第 5 位实现。然后把 PML4 的地址加载到 CR3，这是页目录的基址。接下来我们需要设置 EFER.LME 位来启用长模式，EFER 是模型特定寄存器，地址是 0xC0000080，我们用 rdmsr 和 wrmsr 来读写它。

最后我们设置 CR0 的 PG 位启用分页，然后用 far jump 跳转到 64 位代码段。jmp 0x18:long_mode 会跳转到长模式入口，0x18 是 64 位代码段的选择子。

setup_page_tables 函数首先清空 PML4、PDPT 和 PD 的内存区域，然后设置相应的页表项。PML4 的第一个项指向 PDPT，PDPT 的第一个项指向 PD，PD 的第一个项是一个 2MB 大页。我们还在高地址映射了同样的 2MB 页面，这样内核可以访问高地址内存。

---

## 第五步：添加长模式代码

最后是 64 位长模式部分，这里用 bits 64 告诉 NASM 接下来生成 64 位指令。

长模式入口 long_mode 首先设置各个段寄存器，然后初始化串口。接着清空 VGA 文本模式的显存，这通过向 0xB8000 开始的内存写入空格字符实现。每两个字节代表一个字符，第一个字节是 ASCII 码，第二个字节是颜色属性。

清屏后，我们打印 "READY TO BOOT KERNEL" 消息，同时输出到 VGA 和串口。然后跳转到内核入口 0x10000，用 call rdi 而不是 jmp，这样如果内核返回我们可以捕获到。内核返回后进入死循环，hlt 让 CPU 停机，jmp kernel_halt 无限循环。

---

## 第六步：编译验证

现在我们来验证一下代码是否正确。用 nasm -f bin bootloader.asm -o bootloader.bin 编译，然后用 ls -lh 查看生成的文件大小。如果编译成功，文件大小应该在 2KB 左右，不超过 4KB。如果编译失败，检查一下是不是漏掉了 bits 声明，或者 vstart 写错了，或者段结束的填充是否正确。

---

## 第七步：反汇编验证

这一步很重要，我们要确认生成的二进制文件是正确的。用 ndisasm -b 16 -o 0x7C00 bootloader.bin | head -30 反汇编，你应该能看到 Stage 1 的代码从 0x7C00 开始。然后检查偏移 0x200 处，应该是 Stage 2 的开始，用 ndisasm -b 16 -o 0x7E00 -e 0x200 bootloader.bin | head -30 查看。或者直接用 hexdump -C bootloader.bin | head -20 查看二进制内容，你应该能看到偏移 0x0000 是 Stage 1 代码，偏移 0x0200 是 Stage 2 代码，偏移 0x01FE 是 MBR 签名 55 AA。

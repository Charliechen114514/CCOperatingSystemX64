# 更新构建系统

代码写完了，现在让我们把构建系统也整理一下。

---

## 之前的构建系统

重构之前，我们需要分别编译两个文件。boot.asm 编译成 boot.bin，boot2.asm 编译成 boot2.bin，然后用 dd 命令把 boot.bin 写入第一个扇区，boot2.bin 写入第二和第三个扇区，内核从第四个扇区开始。这很繁琐，而且容易出错，每次修改都要重复这些步骤。

---

## 重构后的构建系统

现在我们只有一个 bootloader.asm 文件，编译起来简单多了。nasm -f bin bootloader.asm -o bootloader.bin 一次编译搞定，生成的 bootloader.bin 包含了两个阶段的所有代码。

但这里有个重要的变化，扇区布局变了。重构之前，bootloader 占两个扇区，内核从第三个扇区开始。重构之后，bootloader 占四个扇区，内核从第五个扇区开始。这是因为 .mbr 段是 512 字节正好一扇区，.stage2 段大约 1500 字节大约三扇区，总共需要四扇区。所以内核起始 LBA 从 4 变成了 5，这个变化要在构建系统里反映出来。

---

## 自动生成配置文件

为了避免硬编码魔法数字，我们引入了 CMake 自动生成的 boot_config.inc。这个文件定义了内核的起始 LBA、扇区数、加载地址等配置。内核扇区数是内核大小除以 512 向上取整，bootloader 扇区数是 bootloader 大小除以 512 向上取整，这些计算都是自动的。

CMake 配置里，我们用 execute_process 命令获取文件大小并计算扇区数。对于内核，我们用 wc -c 获取字节数，然后计算 (字节数 + 511) / 512 得到扇区数。对于 bootloader，也是同样的计算。然后我们用 configure_file 生成 boot_config.inc，把计算出来的值填入模板。

boot_config.inc.in 模板定义了所有的配置项。KERNEL_LBA_START 是内核起始 LBA，等于 BOOTLOADER_SECTORS。KERNEL_SECTOR_COUNT 是内核扇区数，自动计算。KERNEL_LOAD_SEGMENT 和 KERNEL_LOAD_OFFSET 是内核加载地址，0x1000:0x0000。BOOTLOADER_SECTORS 是 bootloader 占用的扇区数，自动计算。SECTORS_PER_TRACK 和 HEADS 是 CHS 转换用的参数，63 和 16 是标准值。

---

## 完整的 Makefile

这里有一个完整的 Makefile 示例。AS 是 nasm，ASFLAGS 是 -f bin。BUILD_DIR 是 build，BOOT_DIR 是 boot，KERNEL_DIR 是 kernel。BOOTLOADER_ASM 是 bootloader.asm，BOOTLOADER_BIN 是 bootloader.bin。KERNEL_ASM 是 kernel.asm，KERNEL_BIN 是 kernel.bin。BOOT_IMG 是 boot.img。

all 目标依赖 BOOT_IMG，也就是最终的可启动镜像。BOOTLOADER_BIN 目标编译 bootloader，KERNEL_BIN 目标编译内核。BOOT_IMG 目标生成最终镜像，它首先计算 bootloader 占用的扇区数，然后用 dd 写入 bootloader，再用 dd 在那个扇区之后写入内核。

clean 目标删除 build 目录，run 目标用 QEMU 运行 boot.img，-serial stdio 把串口输出到终端。debug 目标启动 QEMU GDB 服务器，-s 启用 GDB，-S 让 CPU 在启动时暂停。gdb 目标启动 GDB 连接到 localhost:1234。

## 验证构建系统

编译的时候，你应该能看到类似这样的输出。首先编译 bootloader，显示它的大小字节数。然后编译内核，显示它的大小字节数。最后生成镜像，显示 bootloader 占用的扇区数，然后镜像生成成功。如果 bootloader 大小是 1999 字节，那就是 4 个扇区，内核从第 5 个扇区开始。

检查一下 boot.img 的大小是否正确，用 hexdump 查看前几个字节，应该能看到 MBR 签名在偏移 0x1FE 处。运行 QEMU，你应该能看到完整的启动输出，包括串口输出。

## 常见问题

内核加载失败，可能是 boot_config.inc 中的 KERNEL_LBA_START 不对。检查一下这个值是否等于 BOOTLOADER_SECTORS，Makefile 中 dd 命令的 seek 参数是否正确，内核实际扇区数是否和配置一致。

bootloader 大小超过预期，可能是有不必要的代码或数据。检查一下是否有多余的函数或变量，times 510-($-$$) db 0 填充是否在正确的 section，用 ls -lh 查看实际大小。

CMake 配置不生效，可能是 boot_config.inc 没有正确生成，或者 CMake 没有正确设置变量。检查一下 boot_config.inc 是否存在，@BOOTLOADER_SECTORS@ 是否被替换成实际值。

# CMake 集成与自动化

说实话，我受够了手动编译。

---

## 前言 - 每次都要 nasm 一遍太烦了

之前每次改完代码，我都要手动敲这些命令：

```bash
nasm -f bin boot/bootloader.asm -o build/bootloader.bin
nasm -f bin kernel/kernel.asm -o build/kernel.bin
dd if=build/bootloader.bin of=build/boot.img bs=512 count=1
dd if=build/bootloader.bin of=build/boot.img bs=512 seek=1 skip=1
dd if=build/kernel.bin of=build/boot.img bs=512 seek=4
```

而且，最烦的是：**每次内核大小变了，我还要手动计算扇区数，然后改 `boot_config.inc`**。

这也太原始了。今年都 2026 年了，我们怎么还在用这种构建方式？

今天我们要做的，是把这一切自动化。

---

## 环境说明

在我们开始之前，确认一下你的环境：

**开发平台**：WSL2 (Ubuntu 22.04) + QEMU 7.0+
**工具链**：NASM 2.16.01，CMake 3.28.1，Python 3.10+
**目标**：一个命令完成所有构建步骤

如果你的环境有些不一样，也不用担心。CMake 的语法在不同版本之间变化不大，只要不要太老（3.10 以前），应该都能正常工作。

---

## 目标：一个命令搞定所有

我们想要的是：

```bash
cmake --build build
```

就这么一个命令，自动完成：计算 bootloader 的大小，计算内核的大小，生成 `boot_config.inc`（包含正确的扇区数），编译 bootloader（使用新的配置），编译内核，拼接成 `boot.img`。

---

## 从0开始：创建 CMake 配置生成脚本

首先，我们创建一个 CMake 脚本来生成配置文件：

```cmake
# =============================================================================
# GenerateKernelSize.cmake
# =============================================================================
# 这个脚本根据编译后的 bootloader.bin 和 kernel.bin 的大小，
# 自动生成 boot_config.inc 配置文件
#
# 用法：
#   cmake -DKERNEL_BIN=build/kernel.bin
#         -DBOOTLOADER_BIN=build/bootloader.bin
#         -DOUTPUT_FILE=build/boot_config.inc
#         -P cmake/GenerateKernelSize.cmake
# =============================================================================

# -----------------------------------------------------------------------------
# 第一步：读取文件大小
# -----------------------------------------------------------------------------

# 获取 kernel.bin 的大小（单位：字节）
if(NOT EXISTS ${KERNEL_BIN})
    message(FATAL_ERROR "Kernel binary not found: ${KERNEL_BIN}")
endif()

file(SIZE ${KERNEL_BIN} KERNEL_SIZE_BYTES)
# KERNEL_SIZE_BYTES 现在存储的是 kernel.bin 的字节数

# 同样获取 bootloader.bin 的大小
if(NOT EXISTS ${BOOTLOADER_BIN})
    message(FATAL_ERROR "Bootloader binary not found: ${BOOTLOADER_BIN}")
endif()

file(SIZE ${BOOTLOADER_BIN} BOOTLOADER_SIZE_BYTES)

# -----------------------------------------------------------------------------
# 第二步：计算扇区数
# -----------------------------------------------------------------------------
# 每个扇区 512 字节，向上取整

# KERNEL_SIZE_SECTORS = (KERNEL_SIZE_BYTES + 511) / 512
math(EXPR KERNEL_SIZE_SECTORS "(${KERNEL_SIZE_BYTES} + 511) / 512")

# 同样计算 bootloader 的扇区数
math(EXPR BOOTLOADER_SECTORS "(${BOOTLOADER_SIZE_BYTES} + 511) / 512")

# 内核的起始 LBA = bootloader 占用的扇区数
# 注意：LBA 是 0-based，所以如果 bootloader 占 4 扇区（扇区 1-4），
# 内核从 LBA 4 开始（扇区 5）
math(EXPR KERNEL_LBA_START "${BOOTLOADER_SECTORS}")

# -----------------------------------------------------------------------------
# 第三步：计算 CHS 参数
# -----------------------------------------------------------------------------
# 假设标准几何参数：63 扇区/磁道，16 磁头

set(SECTORS_PER_TRACK 63)
set(HEADS 16)

# 柱面 = LBA / (每磁道扇区数 × 磁头数)
math(EXPR CHS_CYLINDER "${KERNEL_LBA_START} / (${SECTORS_PER_TRACK} * ${HEADS})")

# 磁头 = (LBA / 每磁道扇区数) % 磁头数
math(EXPR TEMP "${KERNEL_LBA_START} / ${SECTORS_PER_TRACK}")
math(EXPR CHS_HEAD "${TEMP} % ${HEADS}")

# 扇区 = (LBA % 每磁道扇区数) + 1  ← 注意 +1！
math(EXPR TEMP "${KERNEL_LBA_START} % ${SECTORS_PER_TRACK}")
math(EXPR CHS_SECTOR "${TEMP} + 1")

# -----------------------------------------------------------------------------
# 第四步：生成配置文件
# -----------------------------------------------------------------------------

# 打开输出文件，准备写入
file(WRITE ${OUTPUT_FILE} "; ==============================================================================\n")
file(APPEND ${OUTPUT_FILE} "; CCOS Bootloader Configuration\n")
file(APPEND ${OUTPUT_FILE} "; ==============================================================================\n")
file(APPEND ${OUTPUT_FILE} "; This file is AUTO-GENERATED by CMake during build\n")
file(APPEND ${OUTPUT_FILE} "; Generated from: ${KERNEL_BIN} (${KERNEL_SIZE_BYTES} bytes)\n")
file(APPEND ${OUTPUT_FILE} ";              : ${BOOTLOADER_BIN} (${BOOTLOADER_SIZE_BYTES} bytes)\n")
file(APPEND ${OUTPUT_FILE} "; DO NOT EDIT MANUALLY - Changes will be overwritten\n")
file(APPEND ${OUTPUT_FILE} "; ==============================================================================\n")
file(APPEND ${OUTPUT_FILE} "\n")

# 写入内核磁盘位置配置
file(APPEND ${OUTPUT_FILE} "; Kernel disk location (LBA/CHS)\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_LBA_START          ${KERNEL_LBA_START}\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_SECTOR_COUNT       ${KERNEL_SIZE_SECTORS}\n")
file(APPEND ${OUTPUT_FILE} ";\n")

# 写入内存布局配置
file(APPEND ${OUTPUT_FILE} "; Memory layout\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_LOAD_SEGMENT       0x1000\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_LOAD_OFFSET        0x0000\n")
file(APPEND ${OUTPUT_FILE} ";\n")

# 写入 bootloader 大小信息
file(APPEND ${OUTPUT_FILE} "; Bootloader size info\n")
file(APPEND ${OUTPUT_FILE} "%define BOOTLOADER_SECTORS        ${BOOTLOADER_SECTORS}\n")
file(APPEND ${OUTPUT_FILE} ";\n")

# 写入 CHS 几何参数
file(APPEND ${OUTPUT_FILE} "; CHS Geometry (for CHS fallback)\n")
file(APPEND ${OUTPUT_FILE} "%define SECTORS_PER_TRACK         ${SECTORS_PER_TRACK}\n")
file(APPEND ${OUTPUT_FILE} "%define HEADS                     ${HEADS}\n")
file(APPEND ${OUTPUT_FILE} ";\n")

# 写入内核 CHS 起始地址
file(APPEND ${OUTPUT_FILE} "; Kernel CHS start (LBA=${KERNEL_LBA_START})\n")
file(APPEND ${OUTPUT_FILE} "; Cylinder = ${CHS_CYLINDER}\n")
file(APPEND ${OUTPUT_FILE} "; Head     = ${CHS_HEAD}\n")
file(APPEND ${OUTPUT_FILE} "; Sector   = ${CHS_SECTOR}\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_CHS_CYLINDER       ${CHS_CYLINDER}\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_CHS_HEAD           ${CHS_HEAD}\n")
file(APPEND ${OUTPUT_FILE} "%define KERNEL_CHS_SECTOR         ${CHS_SECTOR}\n")

# -----------------------------------------------------------------------------
# 第五步：打印调试信息
# -----------------------------------------------------------------------------

message(STATUS "Generated boot configuration:")
message(STATUS "  Kernel: ${KERNEL_SIZE_BYTES} bytes = ${KERNEL_SIZE_SECTORS} sectors")
message(STATUS "  Bootloader: ${BOOTLOADER_SIZE_BYTES} bytes = ${BOOTLOADER_SECTORS} sectors")
message(STATUS "  Kernel LBA start: ${KERNEL_LBA_START}")
message(STATUS "  Kernel CHS: (${CHS_CYLINDER}, ${CHS_HEAD}, ${CHS_SECTOR})")
```

我来解释一下这个脚本做了什么。首先用 file(SIZE ...) 命令获取文件大小，这个比读取文件内容要快。然后用 math(EXPR ...) 命令进行算术运算，注意 CMake 的表达式需要用引号括起来。计算扇区数时用 (字节数 + 511) / 512 来向上取整，这是一个常用的技巧。CHS 参数的计算公式我们在上一篇讲过了，这里不再赘述。最后用 file(WRITE ...) 和 file(APPEND ...) 写入配置文件。

## 爆改 CMakeLists.txt：集成配置生成

现在，我们需要把这个脚本集成到主 CMake 构建系统中：

```cmake
# =============================================================================
# CMakeLists.txt - CCOS 构建配置
# =============================================================================

cmake_minimum_required(VERSION 3.10)
project(CCOS C ASM)

# -----------------------------------------------------------------------------
# 工具链检测
# -----------------------------------------------------------------------------

find_program(NASM nasm REQUIRED)
find_program(QEMU qemu-system-x86_64 REQUIRED)
find_program(PYTHON python3 REQUIRED)

message(STATUS "Found NASM: ${NASM}")
message(STATUS "Found QEMU: ${QEMU}")
message(STATUS "Found Python: ${PYTHON}")

# -----------------------------------------------------------------------------
# 设置编译选项
# -----------------------------------------------------------------------------

set(CMAKE_ASM_NASM_OBJECT_FORMAT bin)  # 生成原始二进制文件

# -----------------------------------------------------------------------------
# Bootloader 配置生成
# -----------------------------------------------------------------------------

# 第一步：创建一个 Mock 配置用于首次构建
# 这解决了鸡生蛋问题：bootloader 编译需要 boot_config.inc，
# 但 boot_config.inc 生成需要 kernel.bin，而 kernel.bin 还没编译

set(BOOT_CONFIG_MOCK ${CMAKE_CURRENT_SOURCE_DIR}/boot/boot_config.inc.mock)
set(BOOT_CONFIG_REAL ${CMAKE_CURRENT_BINARY_DIR}/boot_config.inc)

# 如果 Mock 配置不存在，创建一个默认的
if(NOT EXISTS ${BOOT_CONFIG_MOCK})
    file(WRITE ${BOOT_CONFIG_MOCK} "%define KERNEL_SECTOR_COUNT       1\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_LBA_START          4\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_LOAD_SEGMENT       0x1000\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_LOAD_OFFSET        0x0000\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define BOOTLOADER_SECTORS        4\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_CHS_CYLINDER       0\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_CHS_HEAD           0\n")
    file(APPEND ${BOOT_CONFIG_MOCK} "%define KERNEL_CHS_SECTOR         5\n")
endif()

# 复制 Mock 配置到构建目录（作为首次构建的配置）
add_custom_command(
    OUTPUT ${BOOT_CONFIG_REAL}
    COMMAND ${CMAKE_COMMAND} -E copy_if_different
        ${BOOT_CONFIG_MOCK}
        ${BOOT_CONFIG_REAL}
    DEPENDS ${BOOT_CONFIG_MOCK}
    COMMENT "Copying mock boot configuration"
)

# ... 其他配置 ...
```

这个 CMakeLists.txt 做了几件事：首先检测必要的工具（NASM、QEMU、Python），然后创建 Mock 配置用于首次构建。add_custom_command 定义了一个自定义构建步骤，在构建时复制 Mock 配置。

## 构建流程

现在，整个构建流程是这样的：

首次构建时，先创建 Mock boot_config.inc，然后使用 Mock 配置编译 bootloader，编译 kernel，生成 boot.img，验证磁盘布局。后续构建时，使用已有的 boot_config.inc，编译 bootloader，编译 kernel，生成真实的 boot_config.inc.real，生成 boot.img，验证磁盘布局。

## 可能遇到的坑

如果你的 CMake 版本低于 3.10，某些命令可能不支持。解决方法是升级 CMake，或者降低 cmake_minimum_required 版本号。

如果 NASM 路径有问题，你会看到 "nasm: command not found" 的错误。解决方法是安装 NASM，或在 CMakeLists.txt 中指定完整路径。

dd 命令在 Windows 上默认不存在。解决方法是在 WSL 中运行（推荐），或使用 Git Bash 的 dd，或编写 CMake 脚本使用 file() 命令替代 dd。

⚠️ **注意**
千万别在 Windows CMD 中直接运行这些构建命令。dd 命令在 Windows 上不是原生的，如果你看到 "dd is not recognized" 的错误，说明你在错误的环境中运行。要么用 WSL，要么用 Git Bash。

# CHS 寻址的那些坑

说真的，我在这上面踩过坑。

---

## 前言 - 算出来是对的，一跑就炸

之前我按照 CHS 转换公式，把 LBA 地址转换成 CHS 地址，然后写进代码里。结果呢？一运行，读出来的数据完全不对。

我反复检查公式，没错啊。LBA 到 CHS 的转换公式我也查了多份资料，都是这么写的。

最后才发现问题出在一个不起眼的地方：**CHS 的扇区号是从 1 开始的，而不是从 0**。

这一点真的坑了我半天。我当时查了很多资料，每个都在讲公式怎么算，但没一个人明确提醒我这个 +1 的问题。结果我算出来的 CHS 参数看起来完全正确，一跑就是错的。那种感觉，真的血压拉满。

---

## 环境说明

在我们深入 CHS 之前，先了解一下我们正在和什么打交道：

**目标平台**：BIOS 磁盘 I/O (INT 13h AH=02h)
**寻址模式**：CHS (Cylinder-Head-Sector)
**磁盘几何**：标准 63 扇区/磁道，16 磁头
**约束条件**：扇区号是 1-based，柱面和磁头是 0-based

这些约束是从 PC 诞生以来就存在的"历史包袱"，我们没法改，只能适应。

---

## 什么是 CHS？

CHS 是 Cylinder-Head-Sector（柱面-磁头-扇区）的缩写，这是早期磁盘寻址的一种方式。在 CHS 模式下，磁盘的每个扇区用一个三元组来定位。

这三个数的计数方式不一样：柱面号从 0 开始，磁头号也从 0 开始，但扇区号是从 1 开始！这就是最容易踩坑的地方，很多开发者都因为忽略了这一点导致磁盘读取失败。

对应到 BIOS INT 13h 的调用，我们需要设置这些寄存器：

```asm
mov ah, 0x02        ; 功能号：读磁盘
mov al, 扇区数      ; 要读多少个扇区
mov ch, 柱面号      ; Cylinder，0-based
mov cl, 扇区号      ; Sector，1-based ← 注意！
mov dh, 磁头号      ; Head，0-based
mov dl, 驱动器号    ; Drive，0x80 = 第一个硬盘
int 0x13            ; 调用 BIOS
```

⚠️ **注意**
千万别忘了 cl 寄存器中的扇区号是从 1 开始的！如果你写成 0，BIOS 会直接忽略你的请求，返回错误代码。很多教程都漏掉了这个细节，导致你的代码看起来没错就是跑不起来。

---

## LBA vs CHS

现代磁盘通常使用 LBA（Logical Block Addressing，逻辑块寻址），这种方式更简单：LBA 从 0 开始编号，LBA 0 = 扇区 1，LBA 1 = 扇区 2，LBA N = 扇区 N+1。但在 CHS 模式下，扇区号从 1 开始，CHS (0, 0, 1) = 扇区 1 = LBA 0，CHS (0, 0, 2) = 扇区 2 = LBA 1，CHS (0, 0, N) = 扇区 N = LBA N-1。

这就是问题的根源！

---

## 我们来算一下

给定一个 LBA 地址，转换成 CHS 的公式是这样的：假设标准几何参数是每磁道 63 扇区（SPT = 63），每柱面 16 磁头（HPC = 16），那么柱面 = LBA / (SPT × HPC)，磁头 = (LBA / SPT) % HPC，扇区 = (LBA % SPT) + 1。

为什么要 +1？因为 CHS 扇区号是 1-based 的，而 LBA 是 0-based 的。

让我举个例子：LBA = 0（第一个扇区）。柱面 = 0 / (63 × 16) = 0，磁头 = (0 / 63) % 16 = 0，扇区 = (0 % 63) + 1 = 0 + 1 = 1。所以 LBA 0 对应 CHS (0, 0, **1**)，正确！

再举个例子：LBA = 4（第五个扇区）。柱面 = 4 / (63 × 16) = 0，磁头 = (4 / 63) % 16 = 0，扇区 = (4 % 63) + 1 = 4 + 1 = 5。所以 LBA 4 对应 CHS (0, 0, **5**)。

我们可以用反向公式验证一下：从 CHS 转回 LBA 的公式是 LBA = (柱面 × HPC + 磁头) × SPT + (扇区 - 1)。代入 CHS (0, 0, 5)：LBA = (0 × 16 + 0) × 63 + (5 - 1) = 0 + 4 = 4。正确！

---

## 那个经典的陷阱

现在，让我展示一下我之前踩过的坑。

**错误代码：**

```asm
; 我想读取 LBA 4（第 5 个扇区）
; 直接把 LBA 当成 CHS 扇区号

mov ch, 0        ; 柱面 = 0
mov cl, 4        ; 扇区 = 4   ← 错误！这会读取 LBA 3
mov dh, 0        ; 磁头 = 0
mov dl, 0x80     ; 驱动器 = 第一个硬盘
```

这段代码实际上读取的是 **LBA 3**（第 4 个扇区），而不是 LBA 4！

因为 CHS (0, 0, 4) 对应 LBA 3，LBA = (0 × 16 + 0) × 63 + (4 - 1) = 3。

**正确代码：**

```asm
; 我想读取 LBA 4（第 5 个扇区）
; 按照公式计算正确的 CHS 值

mov ch, 0        ; 柱面 = 0
mov cl, 5        ; 扇区 = 5   ← 正确！
mov dh, 0        ; 磁头 = 0
mov dl, 0x80     ; 驱动器 = 第一个硬盘
```

## 图示一下

让我用一个更直观的方式来展示这个关系。磁盘扇区编号从 LBA 视角看是 LBA 0、LBA 1、LBA 2、LBA 3、LBA 4... 但对应的 CHS 扇区号是 1、2、3、4、5... 差值始终为 1。LBA 0 → CHS 扇区 1，LBA 1 → CHS 扇区 2，LBA 4 → CHS 扇区 5，LBA N → CHS 扇区 N+1（当 N < 63 时）。

⚠️ **千万别**
直接把 LBA 当成 CHS 扇区号用！这是我踩过的坑，希望你不要重蹈覆辙。每次转换都要记得加 1，或者在脑子里明确意识到这两种编号系统的差异。

## INT 13h 的另一个限制：127 扇区

除了那个 +1 的陷阱，BIOS INT 13h AH=02h 还有一个限制：**单次最多读取 127 个扇区**。

如果你试图一次读取 200 个扇区，BIOS 可能只读取部分数据，或者直接失败。如果内核超过 127 个扇区（约 63.5KB），我们需要分批读取。

分批读取的逻辑是这样的：首先设置总扇区数到 CX，然后初始化已读扇区数为 0。进入循环后，先计算本次读取的扇区数，如果剩余扇区数大于 127，只读 127 个，否则读全部剩余。然后调用 BIOS 读取，更新缓冲区指针，减少剩余扇区数，如果还有剩余就继续循环。

不过，这个循环读取的实现有点复杂，我们先用简单的方式：假设内核不超过 127 个扇区。

---

## 为什么还要用 CHS？

你可能会问："既然 LBA 更简单，为什么还要用 CHS？"

原因有几个：首先是兼容性，CHS 在所有 BIOS 上都可用，而 LBA 扩展读取需要 BIOS 支持。其次是简单性，CHS 不需要构造复杂的 DAP（Disk Address Packet）结构。最后是调试友好，CHS 参数直观，容易理解和调试。

一个常见的策略是：**LBA 优先，CHS 回退**。先尝试 LBA 扩展读取，如果失败了再尝试 CHS 模式。不过，LBA 扩展读取的实现比较复杂，我们先用 CHS 模式，等系统稳定后再加 LBA 支持。

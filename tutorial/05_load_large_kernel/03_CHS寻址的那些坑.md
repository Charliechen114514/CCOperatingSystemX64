# CHS 寻址的那些坑

说真的，我在这上面踩过坑。

---

## 前言 - 算出来是对的，一跑就炸

之前我按照 CHS 转换公式，把 LBA 地址转换成 CHS 地址，然后写进代码里。结果呢？

一运行，读出来的数据完全不对。

我反复检查公式，没错啊。LBA 到 CHS 的转换公式我也查了多份资料，都是这么写的。

最后才发现问题出在一个不起眼的地方：**CHS 的扇区号是从 1 开始的，而不是从 0**。

---

## 什么是 CHS？

CHS 是 **Cylinder-Head-Sector**（柱面-磁头-扇区）的缩写，这是早期磁盘寻址的一种方式。

在 CHS 模式下，磁盘的每个扇区用一个三元组来定位：

| 组件 | 含义 | 取值范围 |
|------|------|----------|
| C (Cylinder) | 柱面号 | 从 0 开始 |
| H (Head) | 磁头号 | 从 0 开始 |
| S (Sector) | 扇区号 | **从 1 开始** ← 注意！ |

对应到 BIOS INT 13h 的调用：

```asm
mov ah, 0x02        ; 功能号：读磁盘
mov al, 扇区数      ; 要读多少个扇区
mov ch, 柱面号      ; Cylinder，0-based
mov cl, 扇区号      ; Sector，1-based ← 注意！
mov dh, 磁头号      ; Head，0-based
mov dl, 驱动器号    ; Drive，0x80 = 第一个硬盘
int 0x13            ; 调用 BIOS
```

---

## LBA vs CHS

现代磁盘通常使用 **LBA（Logical Block Addressing，逻辑块寻址）**，这种方式更简单：

- LBA 从 0 开始编号
- LBA 0 = 扇区 1
- LBA 1 = 扇区 2
- LBA N = 扇区 N+1

但在 CHS 模式下，扇区号从 **1** 开始：

- CHS (0, 0, 1) = 扇区 1 = LBA 0
- CHS (0, 0, 2) = 扇区 2 = LBA 1
- CHS (0, 0, N) = 扇区 N = LBA N-1

这就是问题的根源！

---

## LBA 到 CHS 的转换公式

给定一个 LBA 地址，转换成 CHS 的公式是：

```
假设：
  SPT = 每磁道扇区数（Sectors Per Track），通常是 63
  HPC = 检面磁头数（Heads Per Cylinder），通常是 16

计算：
  柱面 = LBA / (SPT × HPC)
  磁头 = (LBA / SPT) % HPC
  扇区 = (LBA % SPT) + 1    ← 注意这里的 +1！
```

**为什么要 +1？**

因为 CHS 扇区号是 1-based 的，而 LBA 是 0-based 的。

让我举个例子：

**例子：LBA = 0（第一个扇区）**

```
柱面 = 0 / (63 × 16) = 0
磁头 = (0 / 63) % 16 = 0
扇区 = (0 % 63) + 1 = 0 + 1 = 1
```

所以 LBA 0 对应 CHS (0, 0, **1**)，正确！

**例子：LBA = 4（第五个扇区）**

```
柱面 = 4 / (63 × 16) = 0
磁头 = (4 / 63) % 16 = 0
扇区 = (4 % 63) + 1 = 4 + 1 = 5
```

所以 LBA 4 对应 CHS (0, 0, **5**)。

**验证：用反向公式验证**

从 CHS 转回 LBA 的公式是：

```
LBA = (柱面 × HPC + 磁头) × SPT + (扇区 - 1)   ← 注意这里的 -1
```

代入 CHS (0, 0, 5)：

```
LBA = (0 × 16 + 0) × 63 + (5 - 1)
    = 0 + 4
    = 4
```

正确！

## 那个经典的陷阱

现在，让我展示一下我之前踩过的坑。

**错误代码：**

```asm
; 我想读取 LBA 4（第 5 个扇区）
; 直接把 LBA 当成 CHS 扇区号

mov ch, 0        ; 柱面 = 0
mov cl, 4        ; 扇区 = 4   ← 错误！这会读取 LBA 3
mov dh, 0        ; 磁头 = 0
mov dl, 0x80     ; 驱动器 = 第一个硬盘
```

这段代码实际上读取的是 **LBA 3**（第 4 个扇区），而不是 LBA 4！

因为：

```
CHS (0, 0, 4) 对应 LBA 3
  LBA = (0 × 16 + 0) × 63 + (4 - 1) = 3
```

**正确代码：**

```asm
; 我想读取 LBA 4（第 5 个扇区）
; 按照公式计算正确的 CHS 值

mov ch, 0        ; 柱面 = 0
mov cl, 5        ; 扇区 = 5   ← 正确！
mov dh, 0        ; 磁头 = 0
mov dl, 0x80     ; 驱动器 = 第一个硬盘
```

## INT 13h 的另一个限制：127 扇区

除了那个 +1 的陷阱，BIOS INT 13h AH=02h 还有一个限制：**单次最多读取 127 个扇区**。

```asm
mov al, 200     ; ← 错误！试图一次读取 200 个扇区
int 0x13
; BIOS 可能只读取部分数据，或者直接失败
```

如果内核超过 127 个扇区（约 63.5KB），我们需要分批读取。

分批读取的逻辑是这样的：

```asm
load_kernel_large:
    mov cx, KERNEL_SECTOR_COUNT    ; cx = 总扇区数
    mov di, 0                      ; di = 当前已读扇区数

.read_loop:
    ; 计算本次读取的扇区数
    mov ax, cx                     ; ax = 剩余扇区数
    cmp ax, 127                    ; 和 127 比较
    jbe .read_now                  ; 如果 <= 127，直接读
    mov ax, 127                    ; 否则，只读 127 个

.read_now:
    ; 读取一批扇区
    mov ah, 0x02
    mov al, al                     ; al = 本次读取的扇区数
    ; ... 设置 CHS 参数 ...
    int 0x13
    jc .error                      ; 出错则跳转

    ; 更新缓冲区指针
    add bx, ax * 512               ; bx += 本次读取的字节数

    ; 更新剩余扇区数
    sub cx, ax                     ; cx -= 本次读取的扇区数

    ; 检查是否完成
    cmp cx, 0
    jg .read_loop                  ; 如果还有剩余，继续循环

    jmp .done

.error:
    ; 错误处理
    jmp $

.done:
    ; 完成
    ret
```

**逐行解释这段代码：**

1. `mov cx, KERNEL_SECTOR_COUNT` - 把总扇区数放到 CX
2. `mov di, 0` - DI 清零，用于计数
3. `mov ax, cx` - 把剩余扇区数复制到 AX
4. `cmp ax, 127` - 和 127 比较
5. `jbe .read_now` - 如果小于等于，跳转到读取
6. `mov ax, 127` - 否则，限制为 127
7. `mov ah, 0x02` - BIOS 读盘功能号
8. `mov al, al` - 设置本次读取的扇区数
9. `int 0x13` - 调用 BIOS
10. `jc .error` - 出错检查
11. `add bx, ax * 512` - 更新缓冲区指针（每次读完后向后移动）
12. `sub cx, ax` - 减少剩余扇区数
13. `cmp cx, 0` - 检查是否读完
14. `jg .read_loop` - 如果还有剩余，继续循环

不过，这个循环读取的实现有点复杂，我们先用简单的方式：假设内核不超过 127 个扇区。

## 为什么还要用 CHS？

你可能会问："既然 LBA 更简单，为什么还要用 CHS？"

原因有几个：

1. **兼容性**：CHS 在所有 BIOS 上都可用，而 LBA 扩展读取需要 BIOS 支持
2. **简单性**：CHS 不需要构造复杂的 DAP（Disk Address Packet）结构
3. **调试友好**：CHS 参数直观，容易理解和调试

一个常见的策略是：**LBA 优先，CHS 回退**。

```asm
load_kernel_auto:
    ; 先尝试 LBA 扩展读取
    call load_kernel_lba
    jc .try_chs          ; LBA 失败，尝试 CHS
    ret                  ; LBA 成功，返回

.try_chs:
    call load_kernel_chs  ; 使用 CHS 模式
    ret
```

不过，LBA 扩展读取的实现比较复杂，我们先用 CHS 模式，等系统稳定后再加 LBA 支持。

## 可能遇到的坑

### 坑 1：忘记 +1

```asm
; 错误：忘记 +1
mov cl, 4        ; 想读取 LBA 4，但实际读取的是 LBA 3
```

**解决方法**：记住公式 `扇区 = (LBA % SPT) + 1`

### 坑 2：CL 寄存器的位复用

在 CHS 模式下，CL 寄存器不仅存储扇区号（低 6 位），还存储柱面号的高 2 位（位 6-7）：

```
CL 寄存器布局：
  bit 7-6: 柱面号的高 2 位
  bit 5-0: 扇区号（1-63）
```

对于小容量磁盘（柱面号 < 256），这个位复用通常不影响我们。

### 坑 3：INT 13h 返回后 CF 未清零

BIOS 调用后，**即使成功，CF 也可能未被清零**。正确的做法是：

```asm
mov ah, 0x02
; ... 设置参数 ...
int 0x13
jc .error          ; 检查 CF 位
cmp al, 0          ; 还要检查实际读取的扇区数
jne .error         ; 如果 AL != 期望值，也说明出错
```

# 上板测试

代码写完了，构建也通过了，现在让我们验证一下。

---

## 前言 - 紧张时刻

每次改完代码，我最紧张的就是第一次运行。

**编译通过不代表能运行。** 你可能遇到各种问题：
- 磁盘读取失败
- 内存布局冲突
- CHS 参数错误
- 或者某个地方少写了一条指令

所以，测试是非常重要的。

---

## 第一步：编译验证

首先，确保代码能编译通过：

```bash
cd /path/to/CCOperatingSystemX64
cmake --build build --clean-first
```

`--clean-first` 会在构建前清理旧的构建产物，确保从头开始编译。

你应该看到类似这样的输出：

```
-- Copying mock boot configuration
[0/4] Building bootloader
[1/4] Building kernel
[2/4] Generating boot image
[3/4] Verifying disk layout
CCOS Disk Layout Verification
============================================================
Analyzing bootloader...
  Size: 1999 bytes (4 sectors)
  Valid MBR signature
Analyzing kernel...
  Size: 15680 bytes (31 sectors, 0.01 MB)
============================================================
DISK LAYOUT (LBA)
============================================================
Bootloader:  Sector 1-4 (LBA 0-3)
Kernel:      Sector 5-35 (LBA 4-34)
============================================================
MEMORY LAYOUT
============================================================
Stage 1:     0x7C00 - 0x7E00
Stage 2:     0x7E00 - 0x3400
```

**检查点：**
1. bootloader 大小应该在 2KB 左右（不超过 4KB）
2. kernel 大小根据你的代码而定
3. boot.img 应该成功生成
4. 验证脚本应该通过

## 第二步：检查二进制文件

在运行之前，让我们先检查生成的二进制文件是否正确：

```bash
# 查看文件大小
ls -lh build/bootloader.bin build/kernel.bin build/boot.img
```

输出示例：

```
-rwxr-xr-x 1 user user 2.0K Feb 15 16:45 build/bootloader.bin
-rwxr-xr-x 1 user user 16K  Feb 15 16:45 build/kernel.bin
-rwxr-xr-x 1 user user 1.5M Feb 15 16:45 build/boot.img
```

### 检查 MBR 签名

```bash
# 查看 bootloader 前几字节
hexdump -C build/bootloader.bin | head -20
```

输出示例：

```
00000000  fa b8 00 7c 8e d8 8e c0  |....|....|
00000008  8e d0 bc 00 7c fb 00 7c  |.....|..||
00000010  b8 01 00 cd 13 72 0b 81  |......r..|
...
```

最重要的是检查 MBR 签名（在偏移 0x1FE 处）：

```bash
xxd -s 0x1FE -l 2 build/bootloader.bin
```

你应该能看到：

```
000001fe: 55 aa
```

这是 MBR 签名，必须是 `55 AA`（注意字节序，小端序）。如果不是这个值，BIOS 不会识别这是一个可启动的磁盘。

---

## 第三步：反汇编验证

让我们验证生成的二进制文件是否正确：

```bash
# 反汇编 Stage 1（从 0x7C00 开始）
ndisasm -b 16 -o 0x7C00 build/bootloader.bin | head -30
```

输出示例：

```
00007C00  FA                cli
00007C01  B8007C            mov ax,0x7C00
00007C04  8ED8              mov ds,ax
00007C06  8EC0              mov es,ax
00007C07  8ED0              mov ss,ax
...
```

### 检查 Stage 2

```bash
# Stage 2 从文件偏移 0x200 开始（第 2 扇区）
ndisasm -b 16 -o 0x7E00 -e 0x200 build/bootloader.bin | head -30
```

`-e 0x200` 告诉 ndisasm 从文件偏移 0x200（512 字节）开始反汇编。

输出示例：

```
00007E00  FA                cli
00007E01  B80000            mov ax,0x0000
00007E04  8ED8              mov ds,ax
...
```

## 第四步：QEMU 运行测试

### 基本运行

```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -serial stdio
```

参数说明：
- `-drive format=raw,file=build/boot.img`：指定磁盘镜像文件
- `-serial stdio`：把串口输出重定向到标准输出（终端）

你应该能看到 VGA 和串口都有输出：

```
=== BootLoader Stage Start ===
READY TO BOOT CCOS
[1] Stage 1: Loading second stage...
[2] Stage 2: Loading kernel...
[MODE] Using CHS mode
[LOAD] CHS: loading 31 sectors from (0,0,5)
READY TO BOOT KERNEL
=== BootLoader Stage End ===
```

### 检查各个阶段

如果系统卡住，检查是哪个阶段出了问题：

| 现象 | 可能的问题 |
|------|------------|
| 看不到任何输出 | BIOS 没识别到磁盘，MBR 签名错误 |
| 看到 `[1]` 但卡住 | Stage 1 磁盘读取失败 |
| 看到 `[2]` 但卡住 | Stage 2 磁盘读取失败 |
| 看到 `[MODE]` 但卡住 | CHS 参数错误 |
| 看到 `[LOAD]` 但卡住 | 内核读取失败 |
| 看到 `READY TO BOOT KERNEL` | bootloader 成功！问题可能在内核 |

### 带调试输出运行

如果需要更详细的调试信息，可以加上 `-d` 参数：

```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -serial stdio -d int,cpu_reset
```

参数说明：
- `-d int`：显示所有中断
- `-d cpu_reset`：显示 CPU 重置信息

## 第五步：GDB 调试

如果系统卡住，我们需要用 GDB 来定位问题。

### 启动 QEMU GDB 服务器

在一个终端运行：

```bash
qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S
```

参数说明：
- `-s`：启动 GDB 服务器（监听 1234 端口）
- `-S`：让 CPU 在启动时暂停，等待 GDB 连接

### 连接 GDB

在另一个终端运行：

```bash
gdb build/bootloader.bin
```

然后在 GDB 中：

```
(gdb) target remote :1234
(gdb) break *0x7C00
(gdb) continue
```

### 常用断点位置

```
# Stage 1 入口
(gdb) break *0x7C00

# Stage 2 入口
(gdb) break *0x7E00

# 内核入口
(gdb) break *0x10000
```

### 单步执行

```
(gdb) si       # 单步执行（汇编指令）
(gdb) ni       # 下一行（跳过函数调用）
(gdb) continue # 继续执行
```

### 检查寄存器和内存

```
(gdb) info registers   # 查看所有寄存器
(gdb) print $eax       # 查看特定寄存器
(gdb) x/10x 0x7C00     # 查看内存（16 进制）
(gdb) x/10i 0x7C00     # 查看内存（反汇编）
(gdb) x/10s 0x7E00     # 查看内存（字符串）
```

## 第六步：常见问题排查

### 问题 1：系统启动后直接卡死

**可能原因：**
- Stage 1 代码有问题
- MBR 签名不正确
- 串口初始化有问题

**解决方法：**

1. 检查 MBR 签名：

```bash
xxd -s 0x1FE -l 2 build/bootloader.bin
```

应该是 `55 AA`。

2. 用 GDB 单步执行 Stage 1，定位问题

### 问题 2：看不到 Stage 2 输出

**可能原因：**
- Stage 2 磁盘读取失败
- Stage 1 → Stage 2 跳转地址不对
- vstart 设置错误

**解决方法：**

1. 检查 Stage 1 的磁盘读取代码
2. 用 GDB 断点在 `0x7E00`，看是否能到达
3. 检查 `boot_config.inc` 中的 `KERNEL_LBA_START` 值

### 问题 3：看到 Stage 2 输出但卡在磁盘读取

**可能原因：**
- CHS 参数计算错误
- 内核扇区数不正确
- BIOS 不支持 CHS 模式

**解决方法：**

1. 检查 `boot_config.inc` 中的 CHS 配置
2. 用 GDB 检查磁盘读取后的内存内容：

```
(gdb) x/10x 0x10000
```

3. 尝试强制使用 LBA 模式（如果支持）

### 问题 4：内核无法执行

**可能原因：**
- 内核没有正确加载
- 内核入口地址错误
- 内核代码有问题

**解决方法：**

1. 检查 `boot_config.inc` 中的 `KERNEL_LOAD_SEGMENT` 和 `KERNEL_LOAD_OFFSET`
2. 用 GDB 检查 0x10000 处的内存内容
3. 单独测试内核

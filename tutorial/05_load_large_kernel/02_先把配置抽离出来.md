## 前言 - 看看那一堆魔法数字

打开我们现在的 `bootloader.asm`，找到内核加载的代码，你会看到一堆数字：

```asm
; bootloader.asm 中的内核加载代码（阶段 04）
load_kernel:
    ; 设置内存地址
    mov ax, 0x1000          ; ← 这是什么？
    mov es, ax
    mov bx, 0x0000          ; ← 这又是什么？
    ; ES:BX = 0x10000，内核要加载到的内存地址

    ; 设置磁盘读取参数
    mov ah, 0x02            ; ← BIOS 功能号，这个还好说
    mov al, 0x01            ; ← 只读 1 个扇区？？
    mov ch, 0x00            ; ← 柱面号
    mov cl, 0x03            ; ← 扇区号（从第 3 扇区开始）
    mov dh, 0x00            ; ← 磁头号
    mov dl, 0x80            ; ← 驱动器号

    int 0x13                ; 调用 BIOS
    jc disk_error
```

这些数字，我们称之为"魔法数字"（Magic Numbers）。

**为什么叫"魔法"？因为你看到它们的时候，完全不知道它们是什么意思，除非你有魔法一样的能力。**

而且，这些数字散落在代码各处，想改某个配置的时候，你要在整个文件里搜索替换，很容易出错。我之前就遇到过一次，改了内核加载地址但忘记改扇区号，结果内核加载到了错误的内存位置，系统启动后直接 Triple Fault。那种感觉，真的想给自己一巴掌。

## 从0开始编写配置文件

我们的第一步，是创建一个配置文件 `boot_config.inc`，把所有这些数字都放进去。

在 `boot/` 目录下新建一个文件 `boot_config.inc`：

```asm
; ==============================================================================
; CCOS Bootloader Configuration
; ==============================================================================
; 这个文件由 CMake 在构建时自动生成
; 请勿手动编辑 - 你的修改会被覆盖
; ==============================================================================

; -----------------------------------------------------------------------------
; 磁盘上的内核位置（LBA 和 CHS 格式）
; -----------------------------------------------------------------------------

; 内核的起始 LBA 扇区号
; LBA = Logical Block Address，逻辑块地址，从 0 开始计数
; 例如：4 表示从磁盘第 5 个扇区开始（LBA 0 = 扇区 1）
%define KERNEL_LBA_START          4

; 内核占用的扇区数量
; 这个值应该根据编译后的 kernel.bin 实际大小自动计算
; 例如：31 表示内核占 31 个扇区 = 15936 字节 ≈ 15.5KB
%define KERNEL_SECTOR_COUNT       1

; -----------------------------------------------------------------------------
; 内存布局配置
; -----------------------------------------------------------------------------

; 内核要加载到的内存地址（段:偏移 格式）
; 物理地址 = 段 × 16 + 偏移
; 例如：0x1000:0x0000 = 0x10000 = 65536
%define KERNEL_LOAD_SEGMENT       0x1000
%define KERNEL_LOAD_OFFSET        0x0000

; -----------------------------------------------------------------------------
; Bootloader 大小信息
; -----------------------------------------------------------------------------

; bootloader 占用的扇区数（包括 Stage 1 和 Stage 2）
; 这个值决定了内核从磁盘哪个扇区开始
%define BOOTLOADER_SECTORS        4

; -----------------------------------------------------------------------------
; CHS 几何参数（用于 CHS 回退模式）
; -----------------------------------------------------------------------------

; 每个磁道的扇区数（标准值是 63）
%define SECTORS_PER_TRACK         63

; 磁头数（标准值是 16）
%define HEADS                     16

; 内核的 CHS 起始地址（柱面、磁头、扇区）
; 这些值是根据 KERNEL_LBA_START 计算出来的
; 计算公式：
;   柱面 = LBA / (每磁道扇区数 × 磁头数)
;   磁头 = (LBA / 每磁道扇区数) % 磁头数
;   扇区 = (LBA % 每磁道扇区数) + 1  ← 注意 +1，CHS 扇区号从 1 开始
;
; 对于 LBA = 4：
;   柱面 = 4 / (63 × 16) = 0
;   磁头 = (4 / 63) % 16 = 0
;   扇区 = (4 % 63) + 1 = 5
%define KERNEL_CHS_CYLINDER       0
%define KERNEL_CHS_HEAD           0
%define KERNEL_CHS_SECTOR         5

; -----------------------------------------------------------------------------
; 最大内核大小限制
; -----------------------------------------------------------------------------

; 最大支持的内核扇区数（64MB）
; 64MB = 64 × 1024 × 1024 ÷ 512 = 131072 扇区
%define KERNEL_MAX_SECTORS        131072
```

这个配置文件看起来有点长，但每个部分都有它的用途。我来解释一下这些配置的含义：

KERNEL_LBA_START 是内核在磁盘上的起始位置（LBA 格式）。LBA 是 Logical Block Address 的缩写，从 0 开始计数，所以 LBA 4 实际上是第 5 个扇区。KERNEL_SECTOR_COUNT 是内核占用的扇区数，这个值会被 CMake 自动计算并替换。KERNEL_LOAD_SEGMENT 和 KERNEL_LOAD_OFFSET 共同决定了内核加载到内存的哪个位置，物理地址 = 段 × 16 + 偏移，所以 0x1000:0x0000 = 0x10000。

BOOTLOADER_SECTORS 告诉我们 bootloader 占了多少扇区，这个值很重要，因为内核必须紧跟在 bootloader 后面。SECTORS_PER_TRACK 和 HEADS 是磁盘的几何参数，用于 CHS 寻址模式。KERNEL_CHS_* 三个值是内核起始位置的 CHS 格式表示，是根据 KERNEL_LBA_START 计算出来的。

## 在 bootloader 中使用配置

现在，我们修改 `bootloader.asm`，引入这个配置文件：

```asm
; ==============================================================================
; CCOS Unified Bootloader
; ==============================================================================

; 引入配置文件
; 这一行必须放在文件开头，这样后面的代码才能使用配置中定义的常量
%include "boot_config.inc"

; ... 其他代码 ...

; =============================================================================
; 加载内核
; =============================================================================
; 输入：无（使用 boot_config.inc 中的配置）
; 输出：内核被加载到 KERNEL_LOAD_SEGMENT:KERNEL_LOAD_OFFSET
; =============================================================================

load_kernel:
    pusha                           ; 保存所有通用寄存器
                                    ; pusha 会把 AX, CX, DX, BX, SP, BP, SI, DI 依次压栈

    ; -----------------------------------------------------------------
    ; 第一步：设置目标内存地址
    ; -----------------------------------------------------------------

    mov ax, KERNEL_LOAD_SEGMENT     ; 从配置中读取段地址
                                    ; ax = 0x1000
    mov es, ax                      ; es = 0x1000
                                    ; ES 是"目标段寄存器"，BIOS 会把数据读到 ES:BX 指向的内存

    mov bx, KERNEL_LOAD_OFFSET      ; 从配置中读取偏移地址
                                    ; bx = 0x0000
                                    ; 现在 ES:BX = 0x1000:0x0000
                                    ; 物理地址 = 0x1000 × 16 + 0x0000 = 0x10000

    ; -----------------------------------------------------------------
    ; 第二步：调用通用的内核加载函数
    ; -----------------------------------------------------------------

    call load_kernel_chs            ; 调用 CHS 模式加载函数
                                    ; 这个函数会使用 boot_config.inc 中的配置

    ; -----------------------------------------------------------------
    ; 第三步：检查是否成功
    ; -----------------------------------------------------------------

    jc .error                       ; jc = jump if carry，如果进位标志位被设置，说明出错了
                                    ; BIOS INT 13h 在失败时会设置 CF 位

    ; -----------------------------------------------------------------
    ; 第四步：成功！显示消息并返回
    ; -----------------------------------------------------------------

    mov si, msg_kernel_loaded       ; si 指向成功消息字符串
    call print_string               ; 调用打印函数

    popa                            ; 恢复所有通用寄存器
                                    ; popa 会按相反顺序从栈中弹出 DI, SI, BP, SP, BX, DX, CX, AX
    ret                             ; 返回到调用者

    ; -----------------------------------------------------------------
    ; 错误处理
    ; -----------------------------------------------------------------

.error:
    mov si, msg_kernel_error        ; si 指向错误消息字符串
    call print_string               ; 打印错误消息

    jmp $                           ; jmp $ 是一个无限循环
                                    ; $ 表示当前指令的地址
                                    ; 所以 jmp $ 会一直跳到自己，程序卡死在这里
```

我来逐行解释一下这段代码做了什么：

首先我们用 pusha 保存所有通用寄存器到栈上，这样我们修改寄存器后可以恢复。然后从配置文件读取段地址到 AX，再存到 ES，ES 是 BIOS 用来知道把数据读到哪里的"目标段寄存器"。接着从配置文件读取偏移地址到 BX。现在 ES:BX = 0x1000:0x0000，物理地址是 0x10000。

然后我们调用 load_kernel_chs 函数（我们下一篇会实现这个函数），它会使用配置文件中的参数来加载内核。调用返回后，我们检查 CF 位是否被设置，如果被设置说明出错了。如果成功，显示成功消息，恢复寄存器，然后返回。如果失败，显示错误消息，然后进入死循环。

⚠️ **注意**
千万别忘了在汇编文件开头用 %include 引入配置文件，否则 NASM 会报错说找不到那些符号常量。而且这个 include 必须放在使用这些常量之前，否则编译器会抱怨"undefined symbol"。

## 鸡生蛋问题：首次构建怎么办？

你可能已经注意到一个问题：**首次构建时，内核还没编译，怎么知道 `KERNEL_SECTOR_COUNT` 应该是多少？**

这是一个经典的"鸡生蛋"问题：bootloader 编译需要 boot_config.inc，boot_config.inc 生成需要 kernel.bin 大小，kernel.bin 编译不需要 bootloader（可以独立编译）。

解决方案是：**使用 Mock 配置进行首次构建**。

在首次构建时，我们使用一个保守的估计值：

```asm
; boot_config.inc (Mock 版本，用于首次构建)
%define KERNEL_SECTOR_COUNT       1       ; 假设内核只有 1 个扇区
%define KERNEL_LBA_START          4       ; 假设 bootloader 占 4 扇区
%define KERNEL_LOAD_SEGMENT       0x1000
%define KERNEL_LOAD_OFFSET        0x0000
%define BOOTLOADER_SECTORS        4
%define KERNEL_CHS_CYLINDER       0
%define KERNEL_CHS_HEAD           0
%define KERNEL_CHS_SECTOR         5
```

这样首次构建可以成功。后续构建时，内核已经编译好了，CMake 脚本可以读取 kernel.bin 的实际大小，计算出真实的扇区数，重新生成 boot_config.inc，然后重新编译 bootloader 使用真实配置。

这个两阶段构建的流程，我们会在后面的"CMake 集成"那篇详细讲。

## 配置文件的注释很重要

你可能会注意到，我在配置文件里写了大量的注释。

**这是有意的。**

配置文件里的每一个数字都有它的含义，如果不写注释，过几个月你再回来看，绝对会忘记这些数字是什么意思。而且，注释还能帮助理解计算公式。比如 CHS 扇区号的计算公式有个 +1，这是一个经典的坑点，如果不写注释，很容易忘记。

我之前就吃过这个亏。当时写配置文件时嫌麻烦没写注释，结果三个月后回来改代码，完全记不起来这些数字是怎么算出来的，只能从头推导一遍，浪费了半天时间。

⚠️ **千万别**
为了"省事"就不写注释。配置文件中的每个数字都有它的来源和计算公式，不写注释的话，过段时间你自己都看不懂。我见过太多项目因为缺少注释，维护起来非常痛苦，最后只能推倒重来。

## 可能遇到的坑

如果你在编译时遇到 "unable to open include file" 错误，检查一下 boot_config.inc 的路径。当用 `%include "boot_config.inc"` 时，NASM 会在当前工作目录和源文件所在目录中查找这个文件。如果你的 `boot_config.inc` 和 `bootloader.asm` 不在同一个目录，你需要指定正确的路径，或者用 `-I` 参数指定 include 路径。

另一个常见问题是修改了配置文件但编译没有生效。这是编译缓存的问题，记得要重新编译 bootloader。可以删除旧的 .bin 文件然后重新编译，或者用 `make clean && make`。

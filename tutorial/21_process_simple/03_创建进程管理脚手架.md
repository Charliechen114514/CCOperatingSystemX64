# 创建进程管理脚手架

## 前言

在之前的文章中，我们已经建立了理论基础。现在终于要动手写代码了，说实话这可能是最让人兴奋的部分。但别着急，我们需要先搭建好"脚手架"——创建目录结构、配置构建系统、定义数据结构和常量。

这些基础工作虽然看起来不那么"硬核"，但它们决定了后续代码的组织方式和可维护性。如果你之前跟着这个系列做过其他阶段，应该已经熟悉我们的代码组织方式了。我们会在 `kernel/process/` 目录下创建所有进程管理相关的代码。

## 环境说明

开始之前，确保你的项目已经完成了 Stage 20 的系统调用框架。你应该有一个干净的内核代码库，CMake 构建系统正常工作。

```
工作目录: /home/charliechen/CCOperatingSystemX64
构建工具: CMake 3.25+
编译器:   x86_64-elf-gcc
汇编器:   NASM 2.15+
```

## 第一步：创建目录结构

首先在 `kernel/` 目录下创建 `process/` 子目录：

```bash
cd /home/charliechen/CCOperatingSystemX64/kernel
mkdir process
cd process
```

这个目录将包含所有进程管理相关的代码。让我们先规划一下每个文件的用途：

```
kernel/process/
├── CMakeLists.txt         # 构建配置
├── process.h              # 公共接口定义
├── process.c              # 进程管理实现
├── process_defines.h      # 类型定义和常量
├── switch.s               # 上下文切换汇编
├── sched.h                # 调度类框架
├── sched.c                # 调度器实现
├── sched_rr.h             # Round-Robin 调度类
├── sched_rr.c             # RR 调度类实现
├── sched_prio.h           # 优先级调度类（可选）
└── sched_prio.c           # 优先级调度类实现（可选）
```

现在创建这些空文件：

```bash
touch CMakeLists.txt process.h process.c process_defines.h switch.s
touch sched.h sched.c sched_rr.h sched_rr.c
touch sched_prio.h sched_prio.c
```

## 第二步：定义常量和类型

先从简单的开始。打开 `process_defines.h`，写入基本类型定义和常量：

```c
/* ==============================================================================
 * CCOS - Process Type Definitions
 * ============================================================================ */

#pragma once

#include "defines/types.h"

/* ============================================================================
 * Process Types
 * ============================================================================ */

typedef int32_t pid_t;
```

这里定义了 `pid_t` 类型，用于表示进程 ID。我们使用有符号 32 位整数，这样可以返回负数错误码。

接下来添加信号号定义：

```c
/* ============================================================================
 * Signal Numbers
 * ============================================================================ */

#define SIGEXIT 0    /* Exit */
#define SIGHUP  1    /* Hangup */
#define SIGINT  2    /* Interrupt */
#define SIGQUIT 3    /* Quit */
#define SIGILL  4    /* Illegal instruction */
#define SIGTRAP 5    /* Trace trap */
#define SIGABRT 6    /* Abort */
#define SIGBUS  7    /* BUS error */
#define SIGFPE  8    /* Floating-point exception */
#define SIGKILL 9    /* Kill (cannot be caught/ignored) */
#define SIGSEGV 11   /* Segmentation violation */
```

这些信号号定义兼容 POSIX 标准。虽然我们在这个阶段不会实现完整的信号机制，但先定义好这些常量可以让代码更加规范。

## 第三步：编写 process.h 头文件

`process.h` 是进程管理模块的公共接口，包含了所有数据结构定义和函数声明。这是最重要的头文件，我们需要仔细设计。

先包含必要的头文件和定义常量：

```c
/* ==============================================================================
 * CCOS - Process Management
 * ============================================================================ */

#pragma once

#include "process_defines.h"
#include "defines/types.h"
#include "list/list.h"
#include "mm/vmm/vmm_config.h"
#include "mm/page_config.h"
#include "process/sched.h"
#include "sync/atomic.h"
```

然后定义进程常量：

```c
/* ============================================================================
 * Process Constants
 * ============================================================================ */

#define PID_MAX           32768
#define KERNEL_STACK_SIZE (16 * 1024)  /* 16KB */
#define USER_STACK        (USER_END - PAGE_SIZE)

/* ============================================================================
 * Thread Constants
 * ============================================================================ */

#define THREAD_STACK_BASE    (USER_END - 64 * 1024 * 1024)
#define THREAD_STACK_SIZE    (256 * 1024)
```

`PID_MAX` 定义了最大进程数，这是 bitmap 分配器的大小。`KERNEL_STACK_SIZE` 是每个进程的内核栈大小，16KB 足够内核使用，又不会浪费太多内存。

接下来定义进程状态枚举：

```c
/* ============================================================================
 * Process State Enumeration
 * ============================================================================ */

typedef enum process_state {
    PROC_READY    = 0,
    PROC_RUNNING  = 1,
    PROC_BLOCKED  = 2,
    PROC_ZOMBIE   = 3,
} process_state_t;
```

然后定义 CPU 上下文结构：

```c
/* ============================================================================
 * CPU Context Structure
 * ============================================================================ */

typedef struct PACKED cpu_context {
    uint64_t rbx;
    uint64_t rbp;
    uint64_t r12;
    uint64_t r13;
    uint64_t r14;
    uint64_t r15;
    uint64_t rsp;
    uint64_t rip;
} cpu_context_t;
```

注意这个结构只包含 callee-saved 寄存器。caller-saved 寄存器（RAX、RCX、RDX、RSI、RDI、R8-R11）由编译器自动处理，我们不需要保存。

陷阱帧结构：

```c
/* ============================================================================
 * Trap Frame Structure
 * ============================================================================ */

typedef struct PACKED trap_frame {
    uint64_t rax;
    uint64_t rbx;
    uint64_t rcx;
    uint64_t rdx;
    uint64_t rsi;
    uint64_t rdi;
    uint64_t rbp;
    uint64_t r8;
    uint64_t r9;
    uint64_t r10;
    uint64_t r11;
    uint64_t r12;
    uint64_t r13;
    uint64_t r14;
    uint64_t r15;
    uint64_t vector;
    uint64_t error_code;
    uint64_t rip;
    uint64_t cs;
    uint64_t rflags;
    uint64_t rsp;
    uint64_t ss;
} trap_frame_t;
```

这个结构必须和硬件自动保存的格式完全匹配，否则 iretq 指令会出错。

内存上下文结构：

```c
/* ============================================================================
 * Memory Context Structure
 * ============================================================================ */

typedef struct memory_context {
    physical_addr_t pml4_phys;
    virtual_addr_t  brk;
    virtual_addr_t  stack_start;
} memory_context_t;
```

这是进程的内存管理信息。`pml4_phys` 是页表的物理地址，`brk` 是堆结束位置，`stack_start` 是栈起始地址。

进程控制块（PCB）结构：

```c
/* ============================================================================
 * Process Control Block (PCB)
 * ============================================================================ */

typedef struct pcb {
    /* Process Identification */
    int32_t            pid;
    int32_t            ppid;

    /* Process State */
    process_state_t    state;
    int32_t            exit_code;

    /* Scheduling */
    list_head          run_list;
    list_head          siblings;
    list_head          children;
    list_head          zombie_children;

    /* Scheduler Entity */
    sched_entity_t     sched_entity;

    /* Memory Context */
    memory_context_t   mm;

    /* CPU Context */
    cpu_context_t*     cpu_ctx;
    trap_frame_t*      trap_frame;
    virtual_addr_t     kernel_stack;
    virtual_addr_t     kernel_stack_base;

    /* User Mode Specific */
    bool               is_user_mode;
    virtual_addr_t     user_stack;
    size_t             user_stack_size;

    /* Parent/Child Relations */
    struct pcb*        parent;

    /* Statistics */
    uint64_t           start_time;
    char               comm[16];

    /* Thread Identification */
    int32_t            tgid;
    bool               is_thread;
    list_head          thread_list;
    list_head          thread_group;
    atomic_t           mm_refcount;

    /* Thread Join Support */
    void*              join_waiters;
    bool               detached;
    void*              return_value;

    /* Thread Entry Point */
    virtual_addr_t     thread_entry;
    virtual_addr_t     thread_arg;

} pcb_t;
```

这个结构包含了进程的所有信息。有些字段（如线程相关）暂时用不到，但先定义好可以避免后续大规模修改。

调度器结构：

```c
/* ============================================================================
 * Scheduler Structure
 * ============================================================================ */

typedef struct scheduler {
    list_head          run_queue;
    pcb_t*             current;
    pcb_t*             idle;
    uint32_t           nr_running;
    bool               need_resched;
    sched_rq_t*        rq;
    sched_class_t**    classes;
} scheduler_t;
```

最后是函数声明：

```c
/* ============================================================================
 * Process Management API
 * ============================================================================ */

int proc_init(void);
int32_t proc_fork(void);
void proc_exit(int exit_code) __attribute__((noreturn));
int32_t proc_wait4(int32_t pid, int* wstatus, int options);
pcb_t* proc_alloc_pcb(void);
void proc_free_pcb(pcb_t* pcb);
pcb_t* proc_current(void);
pcb_t* proc_find(int32_t pid);
void schedule(void);

/* ============================================================================
 * PID Allocator API
 * ============================================================================ */

void pid_alloc_init(void);
int32_t pid_alloc(void);
void pid_free(int32_t pid);

/* ============================================================================
 * Thread Management API
 * ============================================================================ */

typedef void (*thread_fn_t)(void* arg);

pcb_t* proc_create_kernel_thread(thread_fn_t fn, void* arg, const char* name);
int32_t proc_create_user_thread(pcb_t* parent, virtual_addr_t entry,
                                virtual_addr_t arg,
                                virtual_addr_t stack_addr,
                                size_t stack_size);
void proc_thread_exit(void* retval) __attribute__((noreturn));
int32_t proc_thread_join(int32_t tid, void** retval);
int32_t proc_thread_detach(int32_t tid);
pcb_t* proc_find_by_tid(int32_t tid);
```

`proc_current()` 函数声明为 `static inline`，因为它只是简单地返回 `scheduler.current`，不需要函数调用的开销。

## 第四步：编写 sched.h 调度类框架头文件

调度类框架允许我们灵活地实现多种调度算法。打开 `sched.h`，写入以下内容：

```c
/* ==============================================================================
 * CCOS - Scheduling Class Framework
 * ============================================================================ */

#pragma once

#include "defines/types.h"
#include "list/list.h"
#include "sync/spinlock.h"

/* ============================================================================
 * Forward Declarations
 * ============================================================================ */

struct pcb;
struct sched_class;
struct sched_rq;

/* ============================================================================
 * Scheduling Policy Enumeration
 * ============================================================================ */

typedef enum sched_policy {
    SCHED_NORMAL   = 0,
    SCHED_PRIORITY = 1,
    SCHED_MAX      = 2,
} sched_policy_t;
```

然后定义调度类结构：

```c
/* ============================================================================
 * Scheduling Class Structure
 * ============================================================================ */

typedef struct sched_class {
    const char* name;
    sched_policy_t policy;

    void (*enqueue_task)(struct sched_rq* rq, struct pcb* pcb, bool head);
    void (*dequeue_task)(struct sched_rq* rq, struct pcb* pcb);
    struct pcb* (*pick_next_task)(struct sched_rq* rq, struct pcb* prev);
    bool (*should_preempt)(struct pcb* p, struct pcb* curr);
    void (*task_tick)(struct sched_rq* rq, struct pcb* pcb);
    void (*task_fork)(struct pcb* pcb, int nice);
    uint32_t (*get_time_slice)(const struct pcb* pcb);

} sched_class_t;
```

每个调度类需要实现这些方法。我们会在后面的文章中详细解释每个方法的作用。

运行队列结构：

```c
/* ============================================================================
 * Per-Class Run Queue Structure
 * ============================================================================ */

typedef struct sched_rq {
    sched_class_t* sched_class;
    list_head        queue;
    uint32_t         nr_running;
    void*            class_data;
} sched_rq_t;
```

每个调度类都有自己的运行队列，存储在该类上等待执行的进程。

调度实体结构：

```c
/* ============================================================================
 * Per-Task Scheduling Entity
 * ============================================================================ */

typedef struct sched_entity {
    sched_policy_t    policy;
    sched_class_t*    sched_class;
    uint32_t          time_slice;
    uint32_t          time_slice_total;
    int               priority;
    int               nice;
    uint64_t          last_ran;
    list_head         run_list;

} sched_entity_t;
```

每个 PCB 都包含一个 `sched_entity`，存储调度相关信息。

时间片常量：

```c
/* ============================================================================
 * Time Slice Constants
 * ============================================================================ */

#define DEF_TIMESLICE_MS     10
#define MIN_TIMESLICE_MS     2
#define MAX_TIMESLICE_MS     100
```

最后是函数声明：

```c
/* ============================================================================
 * Scheduling Class API
 * ============================================================================ */

int sched_class_init(void);
int sched_class_register(sched_class_t* class, sched_policy_t policy);
void sched_enqueue_task(struct pcb* pcb, bool head);
void sched_dequeue_task(struct pcb* pcb);
struct pcb* sched_pick_next_task(void);
void sched_tick(void);
bool sched_needs_reschedule(void);
void sched_set_resched(void);
void sched_clear_resched(void);

/* ============================================================================
 * Time Slice Management
 * ============================================================================ */

void sched_init_time_slice(struct pcb* pcb);
void sched_reset_time_slice(struct pcb* pcb);

/* ============================================================================
 * Policy Selection Helpers
 * ============================================================================ */

int sched_set_policy(struct pcb* pcb, sched_policy_t policy, int priority);
sched_policy_t sched_get_policy(const struct pcb* pcb);

/* ============================================================================
 * Global Scheduler Lock
 * ============================================================================ */

extern spinlock_t g_scheduler_lock;
```

## 第五步：编写 CMakeLists.txt

现在配置构建系统。打开 `kernel/process/CMakeLists.txt`，写入以下内容：

```cmake
# ============================================================================
# CCOS Process Management
# ============================================================================

set(PROCESS_ASM_SRC
    ${CMAKE_CURRENT_LIST_DIR}/switch.s
)

set(PROCESS_C_SRC
    ${CMAKE_CURRENT_LIST_DIR}/process.c
    ${CMAKE_CURRENT_LIST_DIR}/sched.c
    ${CMAKE_CURRENT_LIST_DIR}/sched_rr.c
    ${CMAKE_CURRENT_LIST_DIR}/sched_prio.c
)

set(PROCESS_INCLUDE_DIR
    ${CMAKE_CURRENT_LIST_DIR}
)

add_library(process_lib STATIC ${PROCESS_ASM_SRC} ${PROCESS_C_SRC})

target_include_directories(process_lib PUBLIC
    ${PROCESS_INCLUDE_DIR}
    ${KERNEL_INCLUDE_DIRS}
)

target_compile_options(process_lib PUBLIC
    -ffreestanding
    -mcmodel=large
    -mno-red-zone
    -mno-mmx
    -mno-sse
    -mno-sse2
)

target_link_libraries(kernel PUBLIC process_lib)
```

这个 CMakeLists.txt 做了几件事：定义汇编和 C 源文件，创建静态库 `process_lib`，设置编译选项，最后链接到内核主目标。

## 第六步：初始化 process.c

创建 `process.c` 的初始版本，包含全局变量和基本函数：

```c
/* ==============================================================================
 * CCOS - Process Management Implementation
 * ============================================================================ */

#include "process/process.h"
#include "klogs/kprintf.h"

/* ============================================================================
 * Global Scheduler State
 * ============================================================================ */

scheduler_t scheduler = {
    .current = NULL,
    .idle = NULL,
    .nr_running = 0,
    .need_resched = false,
};

/* ============================================================================
 * Process Initialization
 * ============================================================================ */

int proc_init(void) {
    klog_info("[PROC] Initializing process subsystem...\n");

    /* Initialize scheduler class framework */
    int ret = sched_class_init();
    if (ret != 0) {
        klog_error("[PROC] Failed to initialize scheduler classes\n");
        return ret;
    }

    /* Initialize Round-Robin scheduling class */
    ret = sched_rr_init();
    if (ret != 0) {
        klog_error("[PROC] Failed to initialize RR scheduler class\n");
        return ret;
    }

    /* Initialize scheduler */
    INIT_LIST_HEAD(&scheduler.run_queue);
    scheduler.current = NULL;
    scheduler.idle = NULL;
    scheduler.nr_running = 0;
    scheduler.need_resched = false;

    klog_info("[PROC] Process subsystem initialized\n");
    return 0;
}
```

这里需要包含 `sched_rr.h` 来调用 `sched_rr_init()`。完整的初始化会在后面的文章中逐步完善。

## 第七步：更新主 CMakeLists.txt

打开 `kernel/CMakeLists.txt`，在适当的位置添加：

```cmake

```

确保在其他子目录（如 syscall）之后添加，这样进程管理可以依赖系统调用框架。

## 常见问题排查

如果你在编译时遇到问题，这里有一些常见的坑：

**问题1：找不到头文件**

错误信息类似 `fatal error: process/sched.h: No such file or directory`

解决方法：确保 `PROCESS_INCLUDE_DIR` 包含了 `${CMAKE_CURRENT_LIST_DIR}`，这样其他文件可以用 `#include "process/sched.h"` 的方式引用。

**问题2：未定义的引用**

错误信息类似 `undefined reference to 'sched_class_init'`

解决方法：确保 `sched.c` 已经添加到 `PROCESS_C_SRC` 中，并且 `sched_init()` 函数已经实现。

**问题3：汇编编译错误**

错误信息类似 `error: operation size not specified`

解决方法：确保在 `switch.s` 中正确使用了 `qword`、`dword` 等操作数大小指示符。我们会在后面的文章中完整实现这个文件。

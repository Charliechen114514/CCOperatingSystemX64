# 实现进程控制块管理

## 前言

进程控制块（PCB）是进程存在的物理载体。内核通过 PCB 来跟踪进程的所有信息：PID、状态、内存上下文、CPU 上下文等等。每个进程在内核中都有一个对应的 PCB，PCB 被释放意味着进程彻底消失。

PCB 管理看起来像是简单的内存分配和释放，但实际实现时有不少细节需要注意。比如，PCB 包含一个 CPU 上下文结构，这个结构本身需要动态分配。每个进程还需要自己的内核栈，栈的大小和位置也有讲究。如果这些细节处理不好，上下文切换时会出各种奇怪的问题。

## PCB 结构回顾

让我们回顾一下 PCB 的主要字段：

```c
typedef struct pcb {
    /* Process Identification */
    int32_t            pid;
    int32_t            ppid;

    /* Process State */
    process_state_t    state;
    int32_t            exit_code;

    /* Scheduling */
    list_head          run_list;
    list_head          siblings;
    list_head          children;
    list_head          zombie_children;
    sched_entity_t     sched_entity;

    /* Memory Context */
    memory_context_t   mm;

    /* CPU Context */
    cpu_context_t*     cpu_ctx;
    trap_frame_t*      trap_frame;
    virtual_addr_t     kernel_stack;
    virtual_addr_t     kernel_stack_base;

    /* ... more fields ... */
} pcb_t;
```

这些字段可以分成几类：标识信息（pid、ppid）、状态信息（state、exit_code）、调度信息（各种链表）、内存信息（mm、kernel_stack）、执行上下文（cpu_ctx、trap_frame）。

## 分配 PCB

`proc_alloc_pcb()` 分配一个新的 PCB 并初始化所有字段：

```c
pcb_t* proc_alloc_pcb(void) {
    pcb_t* pcb = (pcb_t*)kmalloc(sizeof(pcb_t));
    if (!pcb) {
        return NULL;
    }

    /* Initialize to zero */
    memset(pcb, 0, sizeof(pcb_t));
```

首先分配 PCB 本身，如果失败返回 NULL。然后用 `memset()` 清零，确保所有字段都被初始化为 0。这很重要，因为我们不会设置每个字段的值，未初始化的值会导致不可预测的行为。

接下来分配 CPU 上下文：

```c
    /* Allocate CPU context */
    pcb->cpu_ctx = (cpu_context_t*)kmalloc(sizeof(cpu_context_t));
    if (!pcb->cpu_ctx) {
        kfree(pcb);
        return NULL;
    }
    memset(pcb->cpu_ctx, 0, sizeof(cpu_context_t));
```

CPU 上下文是单独分配的，因为它需要在上下文切换时被汇编代码访问。把它嵌入 PCB 中会使得偏移计算变得复杂。

然后分配内核栈：

```c
    /* Allocate kernel stack */
    pcb->kernel_stack_base = (virtual_addr_t)kmalloc(KERNEL_STACK_SIZE);
    if (!pcb->kernel_stack_base) {
        kfree(pcb->cpu_ctx);
        kfree(pcb);
        return NULL;
    }
    /* Stack grows down, so top is base + size */
    pcb->kernel_stack = pcb->kernel_stack_base + KERNEL_STACK_SIZE;
```

内核栈的大小是 16KB，这对于大多数内核操作来说足够了。栈在 x86_64 上向下增长，所以栈顶是 `base + size`。

接下来初始化链表：

```c
    /* Initialize lists */
    INIT_LIST_HEAD(&pcb->run_list);
    INIT_LIST_HEAD(&pcb->siblings);
    INIT_LIST_HEAD(&pcb->children);
    INIT_LIST_HEAD(&pcb->zombie_children);
    INIT_LIST_HEAD(&pcb->sched_entity.run_list);
```

这些链表用于把 PCB 连接到各种数据结构：运行队列、父进程的子进程链表、调度器的就绪队列等。

初始化调度实体：

```c
    /* Initialize sched_entity with default values */
    pcb->sched_entity.policy = SCHED_NORMAL;
    pcb->sched_entity.sched_class = NULL;
    pcb->sched_entity.time_slice = DEF_TIMESLICE_MS;
    pcb->sched_entity.time_slice_total = DEF_TIMESLICE_MS;
    pcb->sched_entity.priority = PRIO_DEFAULT;
    pcb->sched_entity.nice = 0;
    pcb->sched_entity.last_ran = 0;
```

这些是调度相关的字段。默认使用 Round-Robin 调度（SCHED_NORMAL），时间片是 10ms，优先级是默认值。

初始化其他字段：

```c
    /* Initialize user mode fields */
    pcb->is_user_mode = false;
    pcb->user_stack = 0;
    pcb->user_stack_size = 0;

    /* Initialize thread fields */
    pcb->tgid = 0;
    pcb->is_thread = false;
    INIT_LIST_HEAD(&pcb->thread_list);
    INIT_LIST_HEAD(&pcb->thread_group);
    atomic_write(&pcb->mm_refcount, 1);
    pcb->join_waiters = NULL;
    pcb->detached = false;
    pcb->return_value = NULL;
    pcb->thread_entry = 0;
    pcb->thread_arg = 0;

    return pcb;
}
```

最后返回分配好的 PCB。注意我们没有设置 `pid`、`ppid`、`parent` 等字段，这些由调用者在创建进程时设置。

## 释放 PCB

`proc_free_pcb()` 释放一个 PCB 及其关联的资源：

```c
void proc_free_pcb(pcb_t* pcb) {
    if (!pcb) {
        return;
    }

    /* Free CPU context */
    if (pcb->cpu_ctx) {
        kfree(pcb->cpu_ctx);
    }

    /* Free kernel stack */
    if (pcb->kernel_stack_base) {
        kfree((void*)pcb->kernel_stack_base);
    }

    /* Free trap frame if exists */
    if (pcb->trap_frame) {
        kfree(pcb->trap_frame);
    }
```

首先检查 PCB 是否为 NULL，然后释放 CPU 上下文、内核栈和陷阱帧。这些都是用 `kmalloc()` 分配的，必须用 `kfree()` 释放。

处理用户栈：

```c
    /* Free user stack if this is a user process */
    if (pcb->is_user_mode && pcb->user_stack != 0 && pcb->user_stack_size > 0) {
        /* Unmap and free user stack pages */
        size_t stack_pages = pcb->user_stack_size / PAGE_SIZE;
        for (size_t i = 0; i < stack_pages; i++) {
            virtual_addr_t vaddr = pcb->user_stack + (i * PAGE_SIZE);
            physical_addr_t paddr;
            if (page_virt_to_phys(pcb->mm.pml4_phys, vaddr, &paddr) == PAGE_OK) {
                pframe_free(paddr);
            }
            page_unmap_page(pcb->mm.pml4_phys, vaddr, false);
        }
    }
```

如果这是一个用户进程，需要释放用户栈。用户栈是在用户地址空间中的，需要先解除页表映射，然后释放物理页帧。

处理地址空间：

```c
    /* Destroy address space using reference counting */
    if (pcb->mm.pml4_phys != 0) {
        if (atomic_dec_and_test(&pcb->mm_refcount)) {
            vmm_destroy_user_space(pcb->mm.pml4_phys);
        }
    }
```

这里使用引用计数来处理地址空间共享（线程场景）。只有当引用计数归零时才真正销毁地址空间。

释放其他资源：

```c
    /* Free join waiters if allocated */
    if (pcb->join_waiters) {
        kfree(pcb->join_waiters);
    }

    kfree(pcb);
}
```

最后释放 PCB 本身。

## 查找进程

`proc_find()` 根据 PID 查找进程：

```c
pcb_t* proc_find(int32_t pid) {
    /* For now, we only search the run queue */
    /* TODO: Implement a process table for O(1) lookup */

    if (scheduler.current && scheduler.current->pid == pid) {
        return scheduler.current;
    }

    pcb_t* proc;
    list_for_each_entry(proc, &scheduler.run_queue, run_list) {
        if (proc->pid == pid) {
            return proc;
        }
    }

    return NULL;
}
```

这是一个简单的线性查找实现，时间复杂度是 O(n)。先检查当前进程，然后遍历运行队列。如果找不到返回 NULL。

这个实现的问题是只能找到在运行队列中的进程。僵尸进程或阻塞进程不在运行队列中，无法通过这个函数找到。更完善的实现应该维护一个全局的进程哈希表，实现 O(1) 查找。我们把这个优化留到后续版本。

## 获取当前进程

`proc_current()` 返回当前正在运行的进程：

```c
static inline pcb_t* proc_current(void) {
    extern scheduler_t scheduler;
    return scheduler.current;
}
```

这是一个简单的内联函数，直接返回 `scheduler.current`。在单核环境下，这个函数总是返回正确的值。在多核环境下，每个 CPU 应该有自己的 `current` 指针，需要通过 CPU ID 来选择。

## 测试 PCB 管理

让我们写一个测试来验证 PCB 管理的正确性：

```c
bool test_pcb_allocation(void) {
    klog_info("[PROC_DEMO] Test: PCB Allocation...\n");

    /* Allocate a PCB */
    pcb_t* pcb = proc_alloc_pcb();
    if (!pcb) {
        klog_error("[PROC_DEMO] PCB allocation failed\n");
        return false;
    }

    /* Initialize basic fields */
    pcb->pid = 100;
    pcb->ppid = 1;
    pcb->state = PROC_READY;

    /* Verify fields */
    if (pcb->pid != 100 || pcb->state != PROC_READY) {
        klog_error("[PROC_DEMO] PCB fields not set correctly\n");
        proc_free_pcb(pcb);
        return false;
    }

    /* Verify kernel stack alignment */
    if ((pcb->kernel_stack & 0xF) != 0) {
        klog_error("[PROC_DEMO] Kernel stack not 16-byte aligned\n");
        proc_free_pcb(pcb);
        return false;
    }

    /* Free PCB */
    proc_free_pcb(pcb);

    klog_info("[PROC_DEMO] PCB Allocation test PASSED\n");
    return true;
}
```

这个测试验证了 PCB 分配、字段设置、栈对齐和释放是否正常工作。

## 常见陷阱

在实现 PCB 管理时，有几个常见的坑需要注意。

**栈对齐问题** - x86_64 ABI 要求栈在函数调用时必须 16 字节对齐。我们的内核栈是用 `kmalloc()` 分配的，返回的地址可能不是 16 字节对齐的。在使用栈之前，需要确保对齐。我们在 `proc_alloc_pcb()` 中已经处理了这个问题，栈顶是 `base + size`，而 `KERNEL_STACK_SIZE` 是 16KB，保证了对齐。

**内存泄漏** - PCB 包含多个动态分配的子对象（cpu_ctx、kernel_stack、trap_frame）。在释放 PCB 时，必须先释放这些子对象，再释放 PCB 本身。如果顺序错了，会导致内存泄漏或双重释放。

**双重释放** - 如果调用者多次调用 `proc_free_pcb()` 释放同一个 PCB，会发生双重释放。更完善的实现应该在 PCB 中添加一个"魔数"或标志，在释放时检查。如果魔数不匹配，说明 PCB 已经被释放或被破坏。

**竞态条件** - 在多核环境下，一个 CPU 可能在释放 PCB 的同时，另一个 CPU 在查找进程。如果 PCB 已经被释放但还在某个数据结构中，查找函数会访问无效内存。我们的实现没有处理这个问题，更完善的实现需要使用引用计数或 RCU（Read-Copy-Update）机制。

## 接下来

PCB 管理完成后，我们有了进程的"容器"。接下来需要实现调度器，决定哪个进程应该运行。调度器是进程管理的"大脑"，它维护运行队列，选择下一个进程，触发上下文切换。

调度器的设计需要考虑公平性、响应时间、吞吐量等多个目标。我们会实现一个可扩展的调度类框架，支持多种调度算法。默认实现 Round-Robin，这是最简单也最经典的算法。

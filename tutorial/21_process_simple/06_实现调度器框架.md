# 实现调度器框架

## 前言

调度器是进程管理的心脏。每次需要切换进程时，调度器决定下一个运行谁。这个决定看似简单，但实际实现时需要考虑很多因素：公平性、响应时间、吞吐量、优先级等等。

在设计调度器时，我们面临一个选择：是实现一个固定的调度算法，还是设计一个可扩展的框架？Linux 选择了后者，它的调度器架构支持多种调度算法共存，每种算法有自己的运行队列和选择策略。

我们借鉴 Linux 的设计，实现一个调度类框架。这样既可以用 Round-Robin 作为默认算法，又可以在未来添加更复杂的算法。这种设计让代码更加模块化，也更容易理解和扩展。

## 调度类框架设计

调度类框架的核心思想是把"选择下一个进程"的策略从调度器核心逻辑中分离出来。调度器负责管理全局状态（当前进程、运行队列、调度标志），而具体的选择策略由调度类实现。

每个调度类需要实现以下操作：

- `enqueue_task` - 把进程加入到运行队列
- `dequeue_task` - 从运行队列移除进程
- `pick_next_task` - 选择下一个运行的进程
- `should_preempt` - 判断是否应该抢占当前进程
- `task_tick` - 时钟中断时调用，更新进程状态
- `task_fork` - 进程创建时调用，初始化调度信息
- `get_time_slice` - 获取进程的时间片

调度器通过函数指针调用这些操作，不需要关心具体实现。这样添加新的调度算法只需要实现这些函数，然后注册到框架中。

## Round-Robin 调度类

Round-Robin（RR）是最简单的调度算法。每个进程被分配一个固定的时间片，时间片用完后被放到运行队列的末尾，调度器选择下一个进程运行。

RR 调度类的运行队列就是一个简单的链表。`enqueue_task` 把进程加到链表尾部（如果 `head` 为 true 则加到头部），`dequeue_task` 从链表中移除进程，`pick_next_task` 返回链表头部的进程。

这种算法的优点是实现简单、公平性好。每个进程都能得到平等的 CPU 时间，不会饿死。缺点是无法区分进程的优先级，重要的进程得不到更多资源。但对于教学项目来说，简单清晰的实现比复杂高效的实现更有价值。

## 调度类框架实现

首先定义全局调度器锁和运行队列数组：

```c
spinlock_t g_scheduler_lock;

static sched_rq_t g_run_queues[SCHED_MAX];
static sched_class_t* g_sched_classes[SCHED_MAX];
```

`g_scheduler_lock` 保护所有调度相关的数据结构。`g_run_queues` 是每个调度策略的运行队列数组，`g_sched_classes` 是已注册的调度类数组。

初始化函数：

```c
int sched_class_init(void) {
    spinlock_init(&g_scheduler_lock);

    /* Initialize run queues */
    for (int i = 0; i < SCHED_MAX; i++) {
        INIT_LIST_HEAD(&g_run_queues[i].queue);
        g_run_queues[i].sched_class = NULL;
        g_run_queues[i].nr_running = 0;
        g_run_queues[i].class_data = NULL;
        g_sched_classes[i] = NULL;
    }

    return 0;
}
```

注册调度类：

```c
int sched_class_register(sched_class_t* class, sched_policy_t policy) {
    if (policy >= SCHED_MAX) {
        return -1;
    }

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    g_sched_classes[policy] = class;
    g_run_queues[policy].sched_class = class;

    spin_unlock_irqrestore(&g_scheduler_lock, flags);

    klog_info("[SCHED] Registered scheduler class: %s (policy %d)\n",
              class->name, policy);
    return 0;
}
```

这个函数把调度类注册到指定的策略位置。之后创建进程时，可以通过设置 `sched_entity.policy` 来选择使用哪个调度类。

入队操作：

```c
void sched_enqueue_task(struct pcb* pcb, bool head) {
    sched_enqueue_task_locked(pcb, head);
}

void sched_enqueue_task_locked(struct pcb* pcb, bool head) {
    sched_policy_t policy = pcb->sched_entity.policy;
    sched_class_t* class = g_sched_classes[policy];

    if (class && class->enqueue_task) {
        class->enqueue_task(&g_run_queues[policy], pcb, head);
    }
}
```

这里有两个版本：`sched_enqueue_task()` 会获取锁，`sched_enqueue_task_locked()` 假设调用者已经持有锁。这种设计避免了在某些情况下重复获取锁。

出队操作类似：

```c
void sched_dequeue_task(struct pcb* pcb) {
    sched_dequeue_task_locked(pcb);
}

void sched_dequeue_task_locked(struct pcb* pcb) {
    sched_policy_t policy = pcb->sched_entity.policy;
    sched_class_t* class = g_sched_classes[policy];

    if (class && class->dequeue_task) {
        class->dequeue_task(&g_run_queues[policy], pcb);
    }
}
```

选择下一个进程：

```c
struct pcb* sched_pick_next_task(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    struct pcb* next = NULL;

    /* Try each policy in order */
    for (int i = 0; i < SCHED_MAX; i++) {
        sched_class_t* class = g_sched_classes[i];
        if (!class || !class->pick_next_task) {
            continue;
        }

        next = class->pick_next_task(&g_run_queues[i], scheduler.current);
        if (next) {
            break;
        }
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
    return next;
}
```

这个函数遍历所有调度策略，从每个策略的运行队列中选择下一个进程。策略的顺序决定了优先级：SCHED_NORMAL 优先于 SCHED_PRIORITY。如果所有队列都为空，返回 NULL。

## Round-Robin 调度类实现

首先定义 RR 调度类结构：

```c
static sched_class_t sched_rr_class = {
    .name = "RR",
    .policy = SCHED_NORMAL,

    .enqueue_task = rr_enqueue_task,
    .dequeue_task = rr_dequeue_task,
    .pick_next_task = rr_pick_next_task,
    .should_preempt = rr_should_preempt,
    .task_tick = rr_task_tick,
    .task_fork = rr_task_fork,
    .get_time_slice = rr_get_time_slice,
};
```

入队操作：

```c
static void rr_enqueue_task(sched_rq_t* rq, struct pcb* pcb, bool head) {
    if (head) {
        list_add(&pcb->sched_entity.run_list, &rq->queue);
    } else {
        list_add_tail(&pcb->sched_entity.run_list, &rq->queue);
    }
    rq->nr_running++;
}
```

如果 `head` 为 true，加到队列头部；否则加到尾部。然后增加运行计数。

出队操作：

```c
static void rr_dequeue_task(sched_rq_t* rq, struct pcb* pcb) {
    list_del(&pcb->sched_entity.run_list);
    rq->nr_running--;
}
```

从队列中移除进程，减少运行计数。

选择下一个进程：

```c
static struct pcb* rr_pick_next_task(sched_rq_t* rq, struct pcb* prev) {
    if (list_is_empty(&rq->queue)) {
        return NULL;
    }

    return list_first_entry(&rq->queue, struct pcb, sched_entity.run_list);
}
```

如果队列为空返回 NULL，否则返回队列头部的进程。这是 RR 算法的核心：FIFO（先进先出）。

抢占判断：

```c
static bool rr_should_preempt(struct pcb* p, struct pcb* curr) {
    /* RR doesn't preempt based on priority */
    return false;
}
```

RR 算法不支持优先级抢占，所以总是返回 false。进程只有在时间片用完或主动让出 CPU 时才会被切换。

时钟中断处理：

```c
static void rr_task_tick(sched_rq_t* rq, struct pcb* pcb) {
    if (pcb->sched_entity.time_slice > 0) {
        pcb->sched_entity.time_slice--;
    }

    if (pcb->sched_entity.time_slice == 0) {
        sched_set_resched_locked();
    }
}
```

每次时钟中断时递减时间片，如果时间片归零，设置重新调度标志。调度器会在下次合适的时候切换进程。

进程创建时的初始化：

```c
static void rr_task_fork(struct pcb* pcb, int nice) {
    pcb->sched_entity.time_slice = DEF_TIMESLICE_MS;
    pcb->sched_entity.time_slice_total = DEF_TIMESLICE_MS;
    pcb->sched_entity.priority = PRIO_DEFAULT;
    pcb->sched_entity.nice = nice;
}
```

初始化时间片为默认值（10ms），优先级为默认值。

获取时间片：

```c
static uint32_t rr_get_time_slice(const struct pcb* pcb) {
    return pcb->sched_entity.time_slice;
}
```

直接返回进程的剩余时间片。

## 初始化 RR 调度类

```c
int sched_rr_init(void) {
    return sched_class_register(&sched_rr_class, SCHED_NORMAL);
}
```

把 RR 调度类注册到 SCHED_NORMAL 策略位置。

## 设置进程调度策略

```c
int sched_set_policy(struct pcb* pcb, sched_policy_t policy, int priority) {
    if (policy >= SCHED_MAX) {
        return -1;
    }

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    /* Remove from old queue if on run queue */
    if (pcb->state == PROC_READY) {
        sched_dequeue_task_locked(pcb);
    }

    /* Set new policy */
    pcb->sched_entity.policy = policy;
    pcb->sched_entity.sched_class = g_sched_classes[policy];

    /* Call class's task_fork if available */
    sched_class_t* class = g_sched_classes[policy];
    if (class && class->task_fork) {
        class->task_fork(pcb, pcb->sched_entity.nice);
    }

    /* Set priority for priority scheduler */
    if (policy == SCHED_PRIORITY && priority >= 0) {
        pcb->sched_entity.priority = priority;
    }

    /* Add back to run queue if was on it */
    if (pcb->state == PROC_READY) {
        sched_enqueue_task_locked(pcb, false);
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
    return 0;
}
```

这个函数可以动态改变进程的调度策略。如果进程在运行队列上，需要先移除，改变策略后再加回去。

## 测试调度器

让我们写一个简单的测试来验证调度器框架：

```c
bool test_scheduler_init(void) {
    klog_info("[PROC_DEMO] Test: Scheduler Initialization...\n");

    /* Initialize process subsystem */
    int result = proc_init();
    if (result != 0) {
        klog_error("[PROC_DEMO] Process initialization failed\n");
        return false;
    }

    /* Verify scheduler is initialized */
    if (scheduler.current != NULL) {
        klog_error("[PROC_DEMO] Current process should be NULL after init\n");
        return false;
    }

    if (!list_is_empty(&scheduler.run_queue)) {
        klog_error("[PROC_DEMO] Run queue should be empty after init\n");
        return false;
    }

    if (scheduler.nr_running != 0) {
        klog_error("[PROC_DEMO] Running count should be 0 after init\n");
        return false;
    }

    klog_info("[PROC_DEMO] Scheduler Initialization test PASSED\n");
    return true;
}
```

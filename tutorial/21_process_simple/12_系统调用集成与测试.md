# 系统调用集成与测试

## 前言

之前的文章中，我们实现了进程管理的核心功能：fork、exit、wait4、getpid、getppid、线程管理。但这些功能都是内核内部的，用户程序还无法使用。

现在我们需要把这些功能注册为系统调用，让用户程序可以通过 syscall 指令调用它们。系统调用是用户态和内核态的桥梁，也是操作系统最核心的接口之一。

这篇文章会完成系统调用集成，然后编写一个用户态测试程序，验证从用户态创建进程、等待子进程、获取进程 ID 等功能的完整流程。

## 系统调用号定义

首先在 `syscall_numbers.h` 中定义新的系统调用号：

```c
typedef enum syscall_number {
    /* ... existing syscalls ... */

    /* Process management */
    SYS_EXIT       = 60,
    SYS_FORK       = 61,
    SYS_WAIT4      = 62,
    SYS_GETPID     = 63,
    SYS_GETPPID    = 64,

    /* ... other syscalls ... */
} syscall_number_t;
```

这些系统调用号选择在 60-64 范围内，避免与现有的系统调用冲突。

## 系统调用处理函数

在 `syscall_table.c` 中添加系统调用处理函数：

```c
/* ============================================================================
 * Process Management System Calls
 * ============================================================================ */

int64_t sys_exit(syscall_frame_t* frame) {
    int exit_code = (int)frame->arg0;
    proc_exit(exit_code);
    __builtin_unreachable();
    return 0; /* Never reached */
}

int64_t sys_fork(syscall_frame_t* frame) {
    (void)frame;
    return proc_fork();
}

int64_t sys_wait4(syscall_frame_t* frame) {
    int32_t pid = (int32_t)frame->arg0;
    int* wstatus = (int*)frame->arg1;
    int options = (int)frame->arg2;
    return proc_wait4(pid, wstatus, options);
}

int64_t sys_getpid(syscall_frame_t* frame) {
    (void)frame;
    pcb_t* current = proc_current();
    return current ? current->pid : -1;
}

int64_t sys_getppid(syscall_frame_t* frame) {
    (void)frame;
    pcb_t* current = proc_current();
    return current ? current->ppid : -1;
}
```

注意 `sys_exit` 是 noreturn 函数，它调用 `proc_exit` 后永远不会返回。

## 注册系统调用

在系统调用表中注册这些函数：

```c
void syscall_register_process_calls(void) {
    syscall_register_handler(SYS_EXIT, sys_exit, "exit");
    syscall_register_handler(SYS_FORK, sys_fork, "fork");
    syscall_register_handler(SYS_WAIT4, sys_wait4, "wait4");
    syscall_register_handler(SYS_GETPID, sys_getpid, "getpid");
    syscall_register_handler(SYS_GETPPID, sys_getppid, "getppid");
}
```

在内核初始化时调用这个函数：

```c
void kernel_init(void) {
    /* ... other initialization ... */

    /* Initialize process subsystem */
    proc_init();

    /* Register process syscalls */
    syscall_register_process_calls();

    /* ... other initialization ... */
}
```

## 用户态包装函数

用户程序通过系统调用号和寄存器传递参数。为了方便使用，我们可以定义包装函数：

```c
/* User-space wrapper functions */
static inline long sys_exit(int status) {
    long ret;
    __asm__ volatile(
        "syscall"
        : "=a"(ret)
        : "a"(SYS_EXIT), "D"(status)
        : "rcx", "r11", "memory"
    );
    return ret;
}

static inline long sys_fork(void) {
    long ret;
    __asm__ volatile(
        "syscall"
        : "=a"(ret)
        : "a"(SYS_FORK)
        : "rcx", "r11", "memory"
    );
    return ret;
}

static inline long sys_wait4(int pid, int* wstatus, int options) {
    long ret;
    __asm__ volatile(
        "syscall"
        : "=a"(ret)
        : "a"(SYS_WAIT4), "D"(pid), "S"(wstatus), "d"(options)
        : "rcx", "r11", "memory"
    );
    return ret;
}

static inline long sys_getpid(void) {
    long ret;
    __asm__ volatile(
        "syscall"
        : "=a"(ret)
        : "a"(SYS_GETPID)
        : "rcx", "r11", "memory"
    );
    return ret;
}

static inline long sys_getppid(void) {
    long ret;
    __asm__ volatile(
        "syscall"
        : "=a"(ret)
        : "a"(SYS_GETPPID)
        : "rcx", "r11", "memory"
    );
    return ret;
}
```

这些包装函数使用内联汇编直接调用 syscall 指令。参数按照 System V AMD64 ABI 的约定传递：RAX 存放系统调用号，RDI、RSI、RDX 传递前三个参数。

## 编写用户态测试程序

现在我们可以编写一个用户态测试程序来验证系统调用：

```c
/* user_test.c - User-space process management test */

#include "syscall_wrappers.h"

void print_int(int n) {
    sys_write(1, "[USER] ", 7);
    /* ... print n ... */
    sys_write(1, "\n", 1);
}

int main(void) {
    sys_write(1, "[USER] Process test starting\n", 30);

    /* Test getpid */
    int pid = sys_getpid();
    print_int(pid);

    /* Test getppid */
    int ppid = sys_getppid();
    print_int(ppid);

    /* Test fork */
    int child_pid = sys_fork();

    if (child_pid == 0) {
        /* Child process */
        sys_write(1, "[USER] Child process\n", 21);
        sys_exit(42);
    } else if (child_pid > 0) {
        /* Parent process */
        sys_write(1, "[USER] Parent process, child PID=", 33);
        print_int(child_pid);

        /* Test wait4 */
        int wstatus;
        int waited = sys_wait4(child_pid, &wstatus, 0);
        sys_write(1, "[USER] Child exited, status=", 28);
        print_int(wstatus);
    } else {
        /* Fork failed */
        sys_write(1, "[USER] Fork failed\n", 20);
        sys_exit(1);
    }

    sys_exit(0);
    return 0;
}
```

这个测试程序做了几件事：
1. 获取并打印当前进程的 PID 和 PPID
2. 调用 fork 创建子进程
3. 子进程打印消息并退出
4. 父进程等待子进程并打印退出状态

## 加载用户程序

内核需要能够加载用户程序到内存并执行。这通常通过 ELF 文件加载器实现，但对于简单的测试，我们可以硬编码用户程序的机器码。

更完善的实现应该：
1. 读取 ELF 文件
2. 解析程序头
3. 加载代码段和数据段到内存
4. 设置用户栈
5. 创建 PCB 并设置执行上下文
6. 跳转到用户程序入口

这些内容超出本教程范围，我们假设内核已经有了一个简单的用户程序加载器。

## 测试流程

完整的测试流程如下：

1. 内核启动，初始化进程管理子系统
2. 注册进程相关系统调用
3. 加载用户测试程序
4. 创建第一个用户进程
5. 用户程序调用 getpid、getppid 验证
6. 用户程序调用 fork 创建子进程
7. 子进程执行并退出
8. 父进程 wait4 等待并回收子进程
9. 打印测试结果

## 调试技巧

如果测试失败，这里有一些调试技巧：

**检查系统调用号** - 确保用户程序和内核使用相同的系统调用号。如果号不匹配，会调用错误的系统调用或返回 `ENOSYS`。

**验证参数传递** - 在系统调用处理函数中打印参数，确认用户程序传递的值正确到达内核。

**检查返回值** - 系统调用的返回值通过 RAX 传递。确保处理函数正确设置返回值。

**使用 strace 风格的日志** - 记录每个系统调用的参数和返回值，像 strace 那样。这可以快速定位问题。

**GDB 调试** - 在系统调用入口处设置断点，单步执行，观察寄存器和内存的变化。

## 常见问题

**fork 返回错误** - 检查 PID 是否耗尽、PCB 分配是否成功、地址空间创建是否成功。

**wait4 阻塞** - 如果子进程没有正确退出（没有变成 ZOMBIE），父进程会一直等待。检查 exit 是否正确设置状态。

**getpid 返回 -1** - 检查 `scheduler.current` 是否为 NULL。可能进程没有被正确设置或调度。

**系统调用未找到** - 检查系统调用表是否正确注册，系统调用号是否在有效范围内。

## 性能考虑

系统调用的开销应该尽可能小。每次系统调用需要：
1. 保存用户态寄存器
2. 切换到内核栈
3. 查找系统调用表
4. 执行处理函数
5. 恢复用户态寄存器
6. 返回用户态

这个过程大约需要几百个 CPU 周期。对于频繁调用的系统调用（如 getpid），可以考虑使用 vDSO（虚拟动态共享对象）来避免进入内核。

## 安全考虑

系统调用是用户态进入内核态的受控通道，必须严格验证参数：

**指针验证** - 确保用户传入的指针指向用户地址空间，而不是内核地址空间。使用 `copy_from_user` 和 `copy_to_user` 安全地访问用户内存。

**权限检查** - 某些操作需要特权。比如进程不能发送信号给属于其他用户的进程（除非有 CAP_KILL 权限）。

**资源限制** - 防止用户程序耗尽系统资源。比如每个用户的进程数限制、文件描述符限制等。

## 总结

到这里，我们已经完成了 Stage 21 简单进程管理的所有核心功能：

- 进程控制块（PCB）管理
- PID 分配器
- 调度器框架（Round-Robin）
- 上下文切换（汇编实现）
- fork 系统调用
- exit 和 wait4 系统调用
- 线程管理
- 系统调用集成

这是一个功能完整的进程管理系统，虽然简化了不少细节（如写时复制、抢占式调度、信号等），但已经具备了进程管理的核心能力。

## 下一步

进程管理是一个永无止境的主题。我们的实现还有很多可以改进的地方：

**写时复制** - fork 时不复制内存，而是在写入时才复制。这可以大幅提高 fork 性能。

**抢占式调度** - 时钟中断时触发调度，而不是等待进程主动让出 CPU。

**信号机制** - 实现信号的发送、接收、处理。信号是进程间异步通信的重要机制。

**优先级调度** - 实现基于优先级的调度算法，让重要进程得到更多 CPU 时间。

**完全公平调度器（CFS）** - 实现类似 Linux 的 CFS 调度器，使用红黑树维护虚拟运行时间。

**进程间通信（IPC）** - 实现管道、消息队列、共享内存、信号量等 IPC 机制。

这些改进可以作为后续项目的方向。当前实现为我们打下了坚实的基础，理解了进程管理的核心原理，后续的改进会容易很多。

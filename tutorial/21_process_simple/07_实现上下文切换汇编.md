# 实现上下文切换汇编

## 前言

之前我们已经实现了调度器框架，可以选择下一个运行的进程了。但选择是选择，真正把 CPU 切换到目标进程，还需要实现上下文切换。

上下文切换是进程管理中最复杂的部分之一，也是最关键的。它需要在最少的指令序列中完成大量操作：保存寄存器、切换栈、切换页表、恢复寄存器、跳转到新进程。任何一个细节出错都会导致系统崩溃，而且这种 bug 通常非常难调试。

更糟糕的是，上下文切换的代码非常底层，涉及到很多硬件细节。你需要理解 x86_64 的调用约定、TSS 结构、CR3 寄存器、中断返回机制等。这些内容在常规编程中很少遇到，但在操作系统开发中是必修课。

## 什么是上下文切换

上下文切换的本质是"保存现场，恢复现场"。当一个进程被切换出去时，我们需要保存它的 CPU 状态，这样下次切换回来时可以从离开的地方继续执行。这些状态包括所有通用寄存器、栈指针、指令指针等。

保存完当前进程的状态后，我们需要恢复下一个进程的状态，然后跳转到它的指令指针继续执行。从进程的角度看，它不知道自己被切换出去了，只是发现一段时间过去了而已。

上下文切换通常由汇编语言实现，因为需要精确控制每一条指令的效果。C 语言编译器会在函数调用前后自动保存/恢复一些寄存器，这和我们想要的精确控制冲突。

## CPU 上下文结构

首先回顾一下 CPU 上下文结构：

```c
typedef struct {
    uint64_t rbx;
    uint64_t rbp;
    uint64_t r12;
    uint64_t r13;
    uint64_t r14;
    uint64_t r15;
    uint64_t rsp;
    uint64_t rip;
} cpu_context_t;
```

注意这个结构只包含 callee-saved 寄存器。按照 System V AMD64 ABI，这些寄存器由被调用者负责保护。caller-saved 寄存器（RAX、RCX、RDX、RSI、RDI、R8-R11）由编译器自动处理，我们不需要保存。

## switch_context 函数

`switch_context(pcb_t** prev, pcb_t* next)` 是上下文切换的核心函数。它保存当前进程的状态到 `prev->cpu_ctx`，然后从 `next->cpu_ctx` 恢复状态并跳转到 `next` 进程。

这个函数用汇编实现，在 `switch.s` 中：

```assembly
global switch_context
switch_context:
    ; ================================================================
    ; Save current process state
    ; ================================================================
    ; RDI = &prev (pointer to pcb_t*)
    ; RSI = next (pcb_t*)

    ; Save callee-saved registers (System V AMD64 ABI)
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15
```

首先保存 callee-saved 寄存器到栈上。注意顺序不重要，只要保存和恢复时顺序一致即可。

获取 PCB 指针和 cpu_ctx 指针：

```assembly
    ; Get the actual prev PCB pointer
    mov rax, [rdi]           ; rax = *prev (pcb_t*)

    ; Get the cpu_ctx pointer (cpu_ctx is a POINTER, not embedded!)
    mov rcx, [rax + pcb.cpu_ctx]    ; rcx = prev->cpu_ctx (pointer!)
```

注意 `cpu_ctx` 是一个指针，不是嵌入在 PCB 中的结构。我们需要先获取这个指针，然后通过它来访问实际的 `cpu_context_t` 结构。

保存 RSP 和寄存器：

```assembly
    ; Save RSP to prev->cpu_ctx->rsp
    ; Current RSP points to the saved R15 on stack
    mov [rcx + cpu_ctx.rsp], rsp

    ; Save registers to prev->cpu_ctx
    mov [rcx + cpu_ctx.rbx], rbx
    mov [rcx + cpu_ctx.rbp], rbp
    mov [rcx + cpu_ctx.r12], r12
    mov [rcx + cpu_ctx.r13], r13
    mov [rcx + cpu_ctx.r14], r14
    mov [rcx + cpu_ctx.r15], r15
```

`rsp` 在我们 push 了 6 个寄存器后，指向栈上的 `r15`。这正是我们想要的，因为恢复时会从 `rsp` 开始 pop 这些寄存器。

保存 RIP：

```assembly
    ; Save RIP (the return address pushed by the call)
    ; It's at [rsp + 6*8] = rsp + 48 (after we pushed 6 registers)
    mov r15, [rsp + 48]
    mov [rcx + cpu_ctx.rip], r15
```

RIP 是调用 `switch_context` 时压入栈的返回地址，位于当前 `rsp + 48` 的位置（6 个寄存器 × 8 字节）。

## 加载下一个进程状态

现在开始加载下一个进程的状态：

```assembly
    ; ================================================================
    ; Load next process state
    ; ================================================================

    ; Save RSI (next pointer) since function calls will clobber it
    push rsi

    ; Update scheduler.current
    lea rax, [rel scheduler + 16]
    mov [rax], rsi             ; scheduler.current = next
```

`lea rax, [rel scheduler + 16]` 获取 `scheduler.current` 字段的地址（+16 是因为 `scheduler` 结构的前几个字段占 16 字节）。然后把 `next` 写入这个位置。

更新 TSS 内核栈：

```assembly
    ; Update TSS.rsp0 with next->kernel_stack
    mov rdi, [rsi + pcb.kernel_stack]
    call tss_set_kernel_stack_ctx
```

TSS 的 `rsp0` 字段存储了从用户态进入内核时使用的内核栈。我们需要把它更新为下一个进程的内核栈，这样中断发生时使用正确的栈。

切换地址空间：

```assembly
    ; Save RSI again before second function call
    push rsi

    ; Always switch CR3 to next->mm.pml4_phys
    mov rdi, [rsi + pcb.mm_pml4]
    call vmm_load_pml4

    ; Restore RSI (next pointer)
    pop rsi
```

加载下一个进程的页表到 CR3 寄存器。这会切换到下一个进程的地址空间。

恢复寄存器：

```assembly
    ; Restore registers from next->cpu_ctx
    mov rax, [rsi + pcb.cpu_ctx]    ; rax = next->cpu_ctx
    mov rbx, [rax + cpu_ctx.rbx]
    mov rbp, [rax + cpu_ctx.rbp]
    mov r12, [rax + cpu_ctx.r12]
    mov r13, [rax + cpu_ctx.r13]
    mov r14, [rax + cpu_ctx.r14]
    mov r15, [rax + cpu_ctx.r15]

    ; Restore RSP
    mov rsp, [rax + cpu_ctx.rsp]

    ; Restore callee-saved registers
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbp
    pop rbx
```

从 `next->cpu_ctx` 恢复寄存器，然后从栈上 pop 我们之前保存的寄存器。

检查是否需要返回用户态：

```assembly
    ; ================================================================
    ; Check if we need to restore trap frame and return to user mode
    ; ================================================================
    ; Get current PCB
    mov rdi, [rel scheduler + 16]
    test rdi, rdi
    jz .normal_return

    cmp byte [rdi + pcb.has_saved_trap_frame], 1
    jne .normal_return

    ; Need to restore trap_frame and iretq to user mode
    call trap_frame_restore_and_iret
    ; Never returns

.normal_return:
    ret
```

如果下一个进程有保存的陷阱帧（说明它是从用户态被切换出来的），我们需要恢复陷阱帧并通过 `iretq` 返回用户态。否则直接 `ret` 返回，继续在内核态执行。

## switch_to_first 函数

`switch_to_first(pcb_t* first)` 是一个特殊的上下文切换函数，用于从内核初始化代码切换到第一个进程。它不需要保存当前状态（因为之前没有进程），只需要加载第一个进程的状态并跳转。

```assembly
global switch_to_first
switch_to_first:
    ; RDI = first (pcb_t*)

    ; ================================================================
    ; Extract all values we need BEFORE modifying any state
    ; ================================================================
    mov rsi, rdi                ; RSI = first pointer

    mov rax, [rsi + pcb.cpu_ctx]

    ; Extract callee-saved registers
    mov rbx, [rax + cpu_ctx.rbx]
    mov rbp, [rax + cpu_ctx.rbp]
    mov r12, [rax + cpu_ctx.r12]
    mov r13, [rax + cpu_ctx.r13]
    mov r14, [rax + cpu_ctx.r14]
    mov r15, [rax + cpu_ctx.r15]

    ; Extract RIP and other values
    mov rcx, [rax + cpu_ctx.rip]     ; RCX = entry point
    mov r8,  [rsi + pcb.kernel_stack] ; R8 = kernel_stack (for TSS)
    mov r9, [rsi + pcb.mm_pml4]      ; R9 = pml4_phys
```

首先从 PCB 中提取所有需要用到的值。在修改任何状态之前完成这一步很重要，因为我们可能会覆盖包含 PCB 指针的寄存器。

更新系统状态：

```assembly
    ; ================================================================
    ; Update system state
    ; ================================================================

    ; Update TSS.rsp0 with first->kernel_stack
    mov rdi, r8
    call tss_set_kernel_stack_ctx

    ; Mark the task as having run
    mov byte [rsi + pcb.has_run], 1

    ; Switch CR3 to first->mm_pml4_phys
    mov rdi, r9
    call vmm_load_pml4
```

构建 `iretq` 帧：

```assembly
    ; ================================================================
    ; Build iretq frame on the NEW process's stack
    ; ================================================================

    ; Get new RSP
    mov rax, [rsi + pcb.cpu_ctx]
    mov rdx, [rax + cpu_ctx.rsp]     ; RDX = new stack pointer

    ; Switch to new process's stack
    mov rsp, rdx

    ; Push RFLAGS with interrupts enabled
    pushfq
    pop qword rax
    or rax, 0x200               ; Set interrupt flag (bit 9)
    push rax

    ; Push CS (kernel code segment)
    push qword 0x08

    ; Push RIP (entry point)
    push rcx

    ; ================================================================
    ; Execute iretq - all registers are already restored
    ; ================================================================
    iretq
```

对于第一次切换，我们需要在目标进程的栈上构建一个 `iretq` 帧，然后通过 `iretq` 跳转到目标进程。这个帧包含 RFLAGS、CS 和 RIP。RFLAGS 的中断标志位被设置，这样进程可以在运行时接收中断。

## PCB 结构偏移量

汇编代码中用到的 PCB 偏移量必须和 C 结构体定义完全匹配。我们在 `switch.s` 中定义了这些偏移量：

```assembly
struc pcb
    .pid                resd 1    ; offset   0
    .ppid               resd 1    ; offset   4
    .state              resd 1    ; offset   8
    .exit_code          resd 1    ; offset  12
    .run_list           resq 2    ; offset  16
    .siblings           resq 2    ; offset  32
    .children           resq 2    ; offset  48
    .zombie_children    resq 2    ; offset  64
    .sched_entity       resb 56   ; offset  80
    .mm_pml4            resq 1    ; offset 136
    .mm_brk             resq 1    ; offset 144
    .mm_stack_start     resq 1    ; offset 152
    .cpu_ctx            resq 1    ; offset 160
    ; ... more fields ...
endstruc
```

如果 C 结构体定义改变了，这些偏移量也必须更新，否则汇编代码会访问错误的字段。为了避免这种问题，可以用编译器的 `offsetof` 功能自动生成这些常量，但那样需要更复杂的构建系统。

## 调试上下文切换

上下文切换的 bug 通常非常难调试。这里有一些技巧：

**在 QEMU 中使用 GDB** - 可以在 `switch_context` 处设置断点，单步执行，观察寄存器和内存的变化。如果某个寄存器被意外修改，很容易发现。

**打印调试信息** - 在切换前后打印当前进程的 PID、RSP、RIP 等信息。如果某个进程的 RIP 变成了奇怪的值，可能是 PCB 被破坏了。

**魔数检查** - 在 PCB 中添加一个魔数字段，每次切换时验证。如果魔数不匹配，说明 PCB 被破坏或内存已损坏。

**栈溢出检测** - 在内核栈的底部放置一个特殊的值，切换时检查。如果这个值被覆盖，说明栈溢出了。

## 常见陷阱

**忘记保存寄存器** - 如果某个 callee-saved 寄存器没有被保存，切换回来后它的值会丢失。这通常会导致程序崩溃或产生不可预测的行为。

**栈不平衡** - push 和 pop 的数量必须匹配，否则函数返回时会跳转到错误的地址。如果 `ret` 从栈中弹出的不是返回地址，程序会崩溃。

**CR3 切换时机错误** - 如果在保存完当前进程状态之前切换 CR3，那么访问 `prev->cpu_ctx` 时可能会使用新的页表，导致访问错误的内存。

**中断未禁用** - 上下文切换期间必须禁用中断，否则中断处理程序可能会破坏正在切换的状态。我们使用 `spin_lock_irqsave` 来自动处理这个问题。

## 接下来

上下文切换完成后，我们有了保存和恢复进程状态的能力。现在可以创建真正的进程了：通过 fork 复制父进程、通过 exit 退出进程、通过 wait4 等待子进程。这些系统调用是进程管理的核心接口，也是用户程序与内核交互的主要方式。

在下一篇文章中，我们会实现 fork 系统调用，学习如何创建新进程、复制地址空间、建立父子关系。fork 是 UNIX 系统的传奇系统调用，它简单而强大，是理解进程管理的关键。

## 前言

写到这一篇的时候，我必须承认一个事实：我从来不是一个数学爱好者。大学的时候微积分差点挂科，线性代数全靠死记硬背。但内核开发有一个很有意思的特点：你不需要成为数学家，但你需要对数字在计算机中的表示方式有深刻的理解。尤其是位操作，这在内核开发中简直就是家常便饭。

为什么这么说呢？因为内核经常需要做一些非常底层的事情：检测一个数字是不是 2 的幂次、把一个地址对齐到页边界、计算需要多少个内存页、设置和清除特定的标志位。这些操作如果用普通的算术运算来做，既低效又容易出错。但用位操作的话，一条指令就能搞定，既快又精确。

说实话，我第一次看到 `n & (n - 1)` 这个技巧的时候，整个人都被震撼了。这行代码能检测一个数是不是 2 的幂次，而且只需要一次位运算和一次比较。相比之下，用循环或者对数运算来做这件事简直就是在浪费 CPU 周期。从那以后我就开始认真收集各种位操作技巧，现在终于有机会整理成一个完整的库了。

所以这一篇我们会一起实现一套完整的位操作数学库。从最基本的 2 的幂次检测开始，逐步构建出内存对齐、整数除法舍入等实用函数。每个函数我都会解释清楚它背后的位操作原理，确保你不仅知道怎么用，还知道为什么这样设计。准备好了吗？我们继续。

## 第二步：理解 2 的幂次检测技巧

在开始写代码之前，我们先理解一下 2 的幂次检测的原理。这是位操作中最经典也最实用的技巧之一。

2 的幂次有一个非常独特的性质：它的二进制表示中只有一个 1。让我举个例子：

```
十进制    二进制
1        0001
2        0010
4        0100
8        1000
16       10000
```

你看，每个 2 的幂次的二进制表示都只有一个 1。那么如果我们把这个数减 1 会发生什么？减法会让最低位的 1 变成 0，而它后面的所有 0 都变成 1。

```
n = 8    (1000)
n - 1 = 7 (0111)

8 & 7 = 0000 = 0
```

如果一个数不是 2 的幂次，它的二进制表示会有多个 1，减 1 之后最高位的 1 不会被消除。

```
n = 10    (1010)
n - 1 = 9 (1001)

10 & 9 = 1000 = 8 != 0
```

所以 `n & (n - 1) == 0` 这个表达式可以检测一个数是否是 2 的幂次。唯一的特殊情况是 n = 0，因为 `0 & -1 = 0`，但我们不希望 0 被认为是 2 的幂次，所以需要额外检查 `n != 0`。

理解了这个原理，我们就可以开始实现了。

## 第三步：实现 2 的幂次检测和计算函数

现在我们来创建 `kernel/math/bits.h` 文件，实现 2 的幂次相关的函数。

```c
/**
 * @file bits.h
 * @brief 位操作和内存对齐工具函数
 * @date 2026-02-17
 */
#pragma once

#include "defines/types.h"

/**
 * @brief 检查一个数是否是 2 的幂次
 *
 * 使用经典的位技巧：2 的幂次的二进制表示只有一个 1
 * 所以 n & (n-1) 必须为 0
 *
 * @param n 要检测的值
 * @return true 如果 n 是 2 的幂次，false 否则
 * @note 对于 n = 0 返回 false
 */
static inline bool is_power_of_2(unsigned long n) {
    return n != 0 && (n & (n - 1)) == 0;
}
```

接下来实现向上取整到 2 的幂次。这个函数在分配哈希表大小、内存池大小的时候非常有用，因为你通常希望这些大小是 2 的幂次。

```c
/**
 * @brief 向上取整到 2 的幂次
 *
 * 计算大于等于 n 的最小 2 的幂次
 * 使用位操作：将最高位 1 之后的所有位都置为 1，然后加 1
 *
 * @param n 要取整的值
 * @return 大于等于 n 的最小 2 的幂次（对于 n <= 1 返回 1）
 *
 * @note 对于 n = 0 返回 1（数学上不正确但对分配器有用）
 * @note 常用于哈希表、内存池的大小计算
 */
static inline unsigned long round_up_to_power_of_2(unsigned long n) {
    if (n <= 1)
        return 1;
    n--;
    n |= n >> 1;
    n |= n >> 2;
    n |= n >> 4;
    n |= n >> 8;
    n |= n >> 16;
    n |= n >> 32;
    return n + 1;
}
```

这个函数的原理很有意思。假设 n = 13（二进制 1101）：

```
n--          : 1100
n |= n >> 1  : 1110
n |= n >> 2  : 1111
n |= n >> 4  : 1111
...          : 1111
n++          : 10000 = 16
```

通过不断右移并或运算，我们最终把最高位 1 后面的所有位都变成了 1，然后加 1 就得到了下一个 2 的幂次。

还需要一个向下取整到 2 的幂次的函数：

```c
/**
 * @brief 向下取整到 2 的幂次
 *
 * 计算小于等于 n 的最大 2 的幂次
 * 从最高位开始扫描，找到第一个为 1 的位
 *
 * @param n 要取整的值
 * @return 小于等于 n 的最大 2 的幂次（对于 n = 0 返回 0）
 *
 * @note 如果 n 已经是 2 的幂次，返回 n 本身
 */
static inline unsigned long round_down_to_power_of_2(unsigned long n) {
    if (n == 0)
        return 0;
    unsigned long p = 1UL;
    for (int i = 63; i >= 0; i--) {
        if (n & (1UL << i)) {
            p = 1UL << i;
            break;
        }
    }
    return p;
}
```

这个函数比较简单粗暴，就是从最高位开始找第一个为 1 的位，然后返回 `2^i`。虽然不是最快的实现，但代码清晰易懂，对于大多数场景已经够用了。

## 第四步：实现内存对齐函数

内存对齐在内核开发中太重要了。CPU 访问对齐的内存比访问未对齐的内存要快得多，某些架构上访问未对齐的内存甚至会触发异常。所以我们需要一套可靠的内存对齐函数。

在 `bits.h` 中添加：

```c
/**
 * @brief 向上对齐到指定的边界
 *
 * 将给定的值向上取整到 alignment 的倍数
 * alignment 必须是 2 的幂次
 *
 * @param value 要对齐的值
 * @param alignment 对齐边界（必须是 2 的幂次）
 * @return 对齐后的值（大于等于 value 的最小 alignment 倍数）
 *
 * @note 如果 alignment 不是 2 的幂次，结果是未定义的
 * @note 常用于内存分配和页对齐
 */
static inline unsigned long align_up(unsigned long value, unsigned long alignment) {
    return (value + alignment - 1) & ~(alignment - 1);
}

/**
 * @brief 向下对齐到指定的边界
 *
 * 将给定的值向下取整到 alignment 的倍数
 * alignment 必须是 2 的幂次
 *
 * @param value 要对齐的值
 * @param alignment 对齐边界（必须是 2 的幂次）
 * @return 对齐后的值（小于等于 value 的最大 alignment 倍数）
 *
 * @note 如果 alignment 不是 2 的幂次，结果是未定义的
 * @note 常用于页边界计算
 */
static inline unsigned long align_down(unsigned long value, unsigned long alignment) {
    return value & ~(alignment - 1);
}

/**
 * @brief 检查值是否对齐到指定边界
 *
 * 检查给定的值是否是 alignment 的倍数
 * alignment 必须是 2 的幂次
 *
 * @param value 要检查的值
 * @param alignment 对齐边界（必须是 2 的幂次）
 * @return true 如果值是对齐的，false 否则
 *
 * @note 如果 alignment 不是 2 的幂次，结果是未定义的
 */
static inline bool is_aligned(unsigned long value, unsigned long alignment) {
    return (value & (alignment - 1)) == 0;
}
```

这三个函数的原理都是利用了 2 的幂次的性质。如果 alignment 是 2 的幂次，那么 `alignment - 1` 的二进制表示就是低位全 1。例如 alignment = 16（10000），`alignment - 1 = 15`（01111）。

`~(alignment - 1)` 就把低位全部变成 0，高位保持不变。例如 `~15 = ...11110000`。

所以 `value & ~(alignment - 1)` 就把 value 的低位清零，相当于向下对齐。而 `(value + alignment - 1) & ~(alignment - 1)` 先把 value 向上加一点，然后再向下对齐，就相当于向上对齐。

举个例子，假设我们要把 37 对齐到 16：

```
向下对齐：37 & ~15 = 37 & ...11110000 = 32
向上对齐：(37 + 15) & ~15 = 52 & ...11110000 = 48
```

## 第五步：实现除法舍入函数

在内核开发中，我们经常需要计算"需要多少个页面才能容纳这么多字节"。比如你有 10000 字节数据，每页 4096 字节，你需要多少页？答案是 `ceil(10000 / 4096) = 3` 页。但 C 语言的整数除法是向下取整的，`10000 / 4096 = 2`，这不对。

所以我们需要一个向上取整的除法函数。

在 `bits.h` 中添加：

```c
/**
 * @brief 向上取整除法
 *
 * 计算 n/d 向上取整的结果，返回大于等于 n/d 的最小整数
 * 相当于 ceil((double)n / (double)d) 但使用整数运算
 *
 * @param n 被除数
 * @param d 除数（必须非零）
 * @return 向上取整的商
 *
 * @note 如果 d = 0，行为未定义
 * @note 常用于计算需要的页数/块数
 */
static inline unsigned long div_round_up(unsigned long n, unsigned long d) {
    return (n + d - 1) / d;
}

/**
 * @brief 向下取整除法
 *
 * 计算 n/d 向下取整的结果，等同于标准整数除法
 * 为了 API 完整性和代码清晰性而提供
 *
 * @param n 被除数
 * @param d 除数（必须非零）
 * @return 向下取整的商
 *
 * @note 如果 d = 0，行为未定义
 * @note 等同于标准的 / 运算符
 */
static inline unsigned long div_round_down(unsigned long n, unsigned long d) {
    return n / d;
}

/**
 * @brief 四舍五入除法
 *
 * 计算 n/d 四舍五入的结果（精确的一半向下取整）
 * 使用"加一半除数"的技巧实现四舍五入
 *
 * @param n 被除数
 * @param d 除数（必须非零）
 * @return 四舍五入的商
 *
 * @note 如果 d = 0，行为未定义
 * @note 对于精确的一半（如 5/2），向正无穷方向取整
 */
static inline unsigned long div_round_nearest(unsigned long n, unsigned long d) {
    return (n + d / 2) / d;
}
```

`div_round_up` 的原理是：如果 n 能被 d 整除，`(n + d - 1) / d` 和 `n / d` 的结果一样。如果 n 不能被 d 整除，那么 `n % d` 肯定在 1 到 `d - 1` 之间，加上 `d - 1` 之后就会进位，实现向上取整。

举个例子：

```
div_round_up(10, 3) = (10 + 2) / 3 = 12 / 3 = 4
div_round_up(9, 3) = (9 + 2) / 3 = 11 / 3 = 3
```

## 第六步：实现数学工具函数

除了位操作，我们还需要一些常用的数学工具函数：`min`、`max`、`abs`、`clamp`。这些函数太简单了，用宏实现最合适。

创建 `kernel/math/math.h`：

```c
/**
 * @file math.h
 * @brief 数学工具函数
 * @date 2026-02-17
 */
#pragma once

/**
 * @brief 返回两个值中的较小者
 */
#ifndef min
#    define min(a, b) ((a) < (b) ? (a) : (b))
#endif

/**
 * @brief 返回两个值中的较大者
 */
#ifndef max
#    define max(a, b) ((a) < (b) ? (b) : (a))
#endif

/**
 * @brief 返回绝对值
 */
#ifndef abs
#    define abs(x) ((x) > 0 ? (x) : -(x))
#endif

/**
 * @brief 将值限制在指定范围内
 *
 * 如果 val < min_val 返回 min_val
 * 如果 val > max_val 返回 max_val
 * 否则返回 val
 *
 * @param val 要限制的值
 * @param min_val 最小值
 * @param max_val 最大值
 * @return 限制后的值
 */
int clamp(int val, int min_val, int max_val);
```

注意这里用了 `#ifndef` 包裹宏定义，这是为了防止和其他库的宏冲突。如果标准库或者其他库已经定义了 `min`、`max`、`abs`，我们就用它们的定义。

`clamp` 函数需要在 `.c` 文件中实现，因为它不太适合用宏实现（多次求值问题）。

创建 `kernel/math/math.c`：

```c
/**
 * @file math.c
 * @brief 数学工具函数实现
 * @date 2026-02-17
 */
#include "math/math.h"

int clamp(int val, int min_val, int max_val) {
    if (val < min_val)
        return min_val;
    if (val > max_val)
        return max_val;
    return val;
}
```

## 到这里我们完成了什么

让我们回顾一下这篇文章的内容。我们实现了一套完整的位操作数学库，包括：

- `is_power_of_2` — 检测一个数是否是 2 的幂次
- `round_up_to_power_of_2` — 向上取整到 2 的幂次
- `round_down_to_power_of_2` — 向下取整到 2 的幂次
- `align_up` / `align_down` — 内存对齐操作
- `is_aligned` — 检查对齐状态
- `div_round_up` / `div_round_down` / `div_round_nearest` — 除法舍入
- `min` / `max` / `abs` / `clamp` — 数学工具函数

这些函数在内核开发中使用频率极高，而且实现上都使用了高效的位操作技巧。说实话，第一次看到 `n & (n - 1)` 这个技巧的时候我整个人都被震撼了，这么简单的一行代码就能检测 2 的幂次，比循环或者对数运算快了不知多少倍。

还有一个好处是这些函数都是内联函数或者宏，编译器会把它们完全展开，没有任何函数调用开销。这对于内核这种对性能要求极高的代码来说非常重要。

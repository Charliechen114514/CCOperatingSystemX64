## Exception vs Interrupt

在 x86 架构中，Interrupt（中断）和 Exception（异常）是两个相关但不同的概念。

### 中断 (Interrupt)

中断是**外部**事件，与当前执行的指令无关：

- **硬件中断**：设备发送信号（如键盘、定时器、网卡）
- **软件中断**：程序执行 `int` 指令（如系统调用）

关键点：中断是**异步**的，可能在任何指令之间发生。

### 异常 (Exception)

异常是**内部**事件，由当前执行的指令直接触发：

- **Fault（故障）**：可以恢复，修复后重新执行指令（如页错误）
- **Trap（陷阱）**：报告执行状态，执行后继续（如调试断点）
- **Abort（中止）**：严重错误，通常无法恢复（如机器检查）

关键点：异常是**同步**的，总是与特定指令相关联。

### 一个简单的类比

```
中断 = 你在做饭时电话响了（外部事件）
异常 = 你在做饭时发现盐用完了（内部问题）
```

## x86_64 异常分类

x86_64 定义了多种异常，每个异常有一个向量号（0-31）。

### 关键异常列表

| 向量 | 助记符 | 名称 | 类型 | 错误码 |
|------|--------|------|------|--------|
| 0 | #DE | 除法错误 | Fault | 无 |
| 1 | #DB | 调试异常 | Fault/Trap | 无 |
| 2 | --- | NMI 中断 | 中断 | 无 |
| 3 | #BP | 断点 | Trap | 无 |
| 6 | #UD | 无效操作码 | Fault | 无 |
| 8 | #DF | Double Fault | Abort | 有 |
| 10 | #TS | 无效 TSS | Fault | 有 |
| 11 | #NP | 段不存在 | Fault | 有 |
| 12 | #SS | Stack Fault | Fault | 有 |
| 13 | #GP | General Protection Fault | Fault | 有 |
| 14 | #PF | Page Fault | Fault | 有 |
| 16 | #MF | 浮点错误 | Fault | 无 |
| 19 | #XF | SIMD 浮点错误 | Fault | 无 |

### 我们要实现的异常

本阶段我们专注于三个关键异常：

**Double Fault (#DF, 向量 8)**
- 当处理异常时又发生异常时触发
- 通常意味着栈已损坏或处理器状态异常
- 需要独立的 IST 栈避免 Triple Fault

**Stack Fault (#SS, 向量 12)**
- 栈相关错误（栈溢出、无效栈段引用）
- 可能是 Double Fault 的前兆
- 也需要独立的 IST 栈

**General Protection Fault (#GP, 向量 13)**
- 各种保护违规（特权指令、段错误、I/O 权限等）
- 是最常见的异常之一
- 错误码包含详细的诊断信息

## 异常错误码格式

很多异常会携带错误码，帮助我们诊断问题原因。错误码在异常发生时被压入栈中。

### 错误码格式（通用）

```
┌──────┬───────┬────────────────┐
│ 位 0 │ 位 1  │ 位 2          │
├──────┼───────┼────────────────┤
│ EXT  │ IDT   │ TI/Table      │
└──────┴───────┴────────────────┘
```

- **EXT (位 0)**：外部事件（1）或不是（0）
- **IDT (位 1)**：IDT 描述符违规（1）或表违规（0）
- **TI (位 2)**：LDT（1）或 GDT（0），仅在表违规时有效

### GPF 错误码详解

GPF 的错误码格式最复杂：

```
┌─────┬─────────────────────────────────────┐
│ 位  │ 含义                                │
├─────┼─────────────────────────────────────┤
│ 0   │ 外部事件（中断）                    │
│ 1   │ IDT 描述符违规                      │
│ 2   │ GDT/LDT 表违规                      │
│ 3   │ TI：0=GDT, 1=LDT                   │
│ 14:4│ 选择器索引（如果表违规）             │
└─────┴─────────────────────────────────────┘
```

### Page Fault 错误码

页错误的错误码格式已经在 Stage 16 讲过：

```
┌─────┬─────────────────────────────────────┐
│ 位  │ 含义                                │
├─────┼─────────────────────────────────────┤
│ 0   │ P：页面不存在（0）或权限违规（1）   │
│ 1   │ W：写入（1）或读取（0）             │
│ 2   │ U：用户态（1）或内核态（0）         │
│ 3   │ R：保留位违规                       │
│ 4   │ I：指令取（1）或数据访问（0）       │
└─────┴─────────────────────────────────────┘
```

## 异常发生时发生了什么

当异常发生时，硬件会自动执行一系列操作：

### 1. 硬件自动操作

```
异常发生
    ↓
检查当前指令是否允许中断
    ↓
在栈上保存以下信息：
    - SS, RSP（如果切换栈）
    - RFLAGS
    - CS, RIP
    - 错误码（如果有）
    ↓
从 IDT 中读取异常处理程序地址
    ↓
跳转到异常处理程序
```

### 2. 栈帧格式

异常处理程序接收一个 `interrupt_frame_t` 结构：

```c
typedef struct {
    uint64_t rdi, rsi, rbp, rbx, rdx, rcx, rax;
    uint64_t r8, r9, r10, r11, r12, r13, r14, r15;
    uint64_t interrupt_number;
    uint64_t error_code;
    uint64_t rip, cs, rflags;
    uint64_t rsp, ss;
} interrupt_frame_t;
```

⚠️ 注意：实际的栈帧格式取决于异常类型和特权级切换。上面的结构是简化版。

## Double Fault 详解

Double Fault 是一种特殊的异常，值得单独讨论。

### Double Fault 的触发条件

Double Fault 在以下情况下触发：

1. 处理一个异常时又发生了另一个异常
2. 第二个异常无法被正确处理（比如栈损坏）

### 为什么需要 IST 栈

想象这个场景：

```
1. 用户进程触发 #PF（页错误）
    ↓
2. CPU 切换到内核栈，准备调用 #PF 处理器
    ↓
3. 内核栈已损坏（bug 或攻击）
    ↓
4. 触发 #SS（Stack Fault）
    ↓
5. CPU 试图使用损坏的内核栈处理 #SS
    ↓
6. 又触发一个异常
    ↓
7. #DF (Double Fault)
```

如果 #DF 也使用损坏的内核栈，就会进入无限循环，最终触发 Triple Fault（系统重启）。

解决方案：为 #DF 配置独立的 IST（Interrupt Stack Table）栈。

```
正常中断 → 使用当前栈（可能是损坏的）
#DF → 使用独立的 IST 栈（保证完好）
```

### IST 栈配置

IST 是 x86_64 引入的机制，允许为特定中断向量配置独立的栈：

```
TSS 中有 7 个 IST 槽位（IST1-IST7）
    ↓
每个 IST 槽位存储一个栈指针
    ↓
IDT 项中的 IST 索引指定使用哪个 IST
    ↓
异常发生时，CPU 切换到指定的 IST 栈
```

我们使用：
- **IST1**：Double Fault 栈
- **IST4**：Stack Fault 栈

## 异常处理的三层模型

在 CCOS 中，我们把异常处理分为三个层次：

### 第一层：快速路径

对于可恢复的错误（如 COW 页错误），快速处理并恢复执行。

```c
if (is_cow_page_fault(fault_addr)) {
    cow_handle_fault(...);
    return;  // 恢复执行
}
```

### 第二层：进程终止

对于用户态无法恢复的错误（如段错误），终止当前进程。

```c
if (user_mode) {
    terminate_current_process(SIGSEGV);
    return;
}
```

### 第三层：内核恐慌

对于内核态无法恢复的错误，停止系统。

```c
kernel_panic("Unrecoverable kernel exception");
```

## 异常统计

为了调试和性能分析，我们维护异常统计信息：

```c
typedef struct {
    uint64_t df_count;        /* Double Fault count */
    uint64_t ss_count;        /* Stack Fault count */
    uint64_t gp_count;        /* GPF count */
    uint64_t gp_user_count;   /* User-mode GPF count */
    uint64_t gp_kernel_count; /* Kernel-mode GPF count */
} exception_stats_t;
```

这些统计信息可以帮助我们：
- 检测异常风暴
- 分析系统稳定性
- 定位频繁错误

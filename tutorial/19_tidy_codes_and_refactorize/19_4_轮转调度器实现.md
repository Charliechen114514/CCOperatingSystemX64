# 19-4 轮转调度器实现

## 前言

有了 PCB、PID 分配器和上下文切换，我们离真正的多任务系统只差最后一步了 —— 调度器。调度器决定哪个进程什么时候运行，运行多长时间。这一章我们实现一个简单的 Round-Robin（轮转）调度器，它把所有就绪进程排成一个队列，轮流给每个进程分配 CPU 时间。

Round-Robin 调度器虽然简单，但它公平、容易实现，而且对于教学目的来说足够了。后续如果要实现优先级调度、多级反馈队列等高级算法，基础也是类似的。

## 环境说明

本章需要修改 kernel/process/process.c，添加调度器相关函数。需要依赖之前实现的：
- PCB 结构和链表操作
- PID 分配器
- 上下文切换汇编函数

## Round-Robin 调度器原理

Round-Robin 调度器的核心思想很简单：所有就绪进程排成一个 FIFO 队列，调度器每次从队列头部取出一个进程执行。当进程用完时间片或者主动让出 CPU 时，把它放回队列尾部，然后取出下一个进程。

这个算法的优点是实现简单，每个进程获得公平的 CPU 时间。缺点是无法区分优先级，所有进程一视同仁。但对于我们的基础 OS 来说，这已经足够了。

## 调度器数据结构

我们定义一个全局调度器结构：

```c
/* kernel/process/process.h */

typedef struct scheduler {
    list_head     run_queue;      /* 运行队列 */
    pcb_t*        current;        /* 当前运行的进程 */
    pcb_t*        idle;           /* 空闲进程 */
    uint32_t      nr_running;     /* 运行进程数 */
    bool          need_resched;   /* 需要重新调度标志 */
} scheduler_t;

/* 全局调度器实例 */
extern scheduler_t scheduler;
```

run_queue 是运行队列，所有 READY 状态的进程都在这个队列里。current 指向当前正在运行的进程。idle 是空闲进程，当没有其他进程可运行时执行。nr_running 是计数器，记录当前有多少进程在运行。need_resched 是标志位，用于标记需要重新调度。

## 调度器初始化

在 process.c 中定义并初始化调度器：

```c
/* kernel/process/process.c */

scheduler_t scheduler = {
    .current = NULL,
    .idle = NULL,
    .nr_running = 0,
    .need_resched = false,
};

int proc_init(void) {
    klog_info("[PROC] Initializing process subsystem...\n");

    /* 初始化运行队列 */
    INIT_LIST_HEAD(&scheduler.run_queue);
    scheduler.current = NULL;
    scheduler.idle = NULL;
    scheduler.nr_running = 0;
    scheduler.need_resched = false;

    /* 初始化 PID 分配器 */
    pid_alloc_init();

    klog_info("[PROC] Process subsystem initialized\n");
    return 0;
}
```

初始化很简单，就是把所有字段设为初始值。运行队列需要用 INIT_LIST_HEAD 初始化链表头。

## 核心调度函数

schedule() 函数是调度器的核心，它选择下一个进程并执行切换：

```c
/**
 * @brief 调度下一个进程
 */
void schedule(void) {
    pcb_t* prev = scheduler.current;
    pcb_t* next = NULL;

    /* 清除重新调度标志 */
    scheduler.need_resched = false;

    /* 从运行队列选择下一个进程 */
    if (!list_is_empty(&scheduler.run_queue)) {
        /* 取出队列头部 */
        list_head* node = scheduler.run_queue.next;
        next = list_entry(node, pcb_t, run_list);
    }

    /* 如果没有可运行进程，使用空闲进程 */
    if (!next) {
        if (scheduler.idle) {
            next = scheduler.idle;
        } else {
            /* 没有空闲进程，无法调度 */
            klog_warn("[PROC] No process to run!\n");
            return;
        }
    }

    /* 如果下一个进程就是当前进程，不需要切换 */
    if (next == prev) {
        return;
    }

    /* 处理前一个进程 */
    if (prev && prev != scheduler.idle) {
        if (prev->state == PROC_RUNNING) {
            /* 将 RUNNING 改为 READY */
            prev->state = PROC_READY;
        }
        /* 如果是 READY 状态，重新入队 */
        if (prev->state == PROC_READY) {
            list_add_tail(&prev->run_list, &scheduler.run_queue);
        }
    }

    /* 从运行队列移除下一个进程 */
    if (next != scheduler.idle) {
        list_del(&next->run_list);
    }

    /* 更新状态 */
    next->state = PROC_RUNNING;
    scheduler.current = next;

    /* 执行上下文切换 */
    if (prev == NULL) {
        /* 第一次从内核切换 */
        switch_to_first(next);
    } else {
        switch_context(&prev, next);
    }
}
```

这个函数的逻辑比较清晰，我们来分解一下：

首先获取当前进程 prev，然后从运行队列头部取出 next。如果运行队列为空，使用空闲进程。如果 next 和 prev 是同一个进程，直接返回，不需要切换。

然后处理 prev 进程。如果它是 RUNNING 状态，改为 READY。如果是 READY 状态，放回运行队列尾部。这个设计实现了轮转效果：进程用完 CPU 后回到队列尾部排队。

接着更新 next 进程的状态为 RUNNING，设置为当前进程。

最后执行上下文切换。如果是第一次切换（prev 为 NULL），调用 switch_to_first()；否则调用 switch_context()。

## 进程入队操作

为了把新创建的进程加入调度，我们需要入队函数：

```c
/**
 * @brief 将进程加入运行队列
 * @param pcb 要加入的进程
 */
void sched_enqueue(pcb_t* pcb) {
    if (pcb->state == PROC_READY) {
        list_add_tail(&pcb->run_list, &scheduler.run_queue);
        scheduler.nr_running++;
    }
}

/**
 * @brief 从运行队列移除进程
 * @param pcb 要移除的进程
 */
void sched_dequeue(pcb_t* pcb) {
    if (!list_is_empty(&pcb->run_list)) {
        list_del(&pcb->run_list);
        scheduler.nr_running--;
    }
}
```

入队时只接受 READY 状态的进程，避免错误状态下的进程被调度。nr_running 计数器帮助我们快速判断是否有进程可运行。

## 主动让出 CPU

进程可以主动让出 CPU，调用 sched_yield() 函数：

```c
/**
 * @brief 当前进程主动让出 CPU
 */
void sched_yield(void) {
    schedule();
}
```

这个函数很简单，就是直接调用 schedule()。当前进程会被放回运行队列尾部，CPU 分配给下一个进程。

## 时钟中断集成

为了实现时间片轮转，我们需要在时钟中断中检查是否需要重新调度：

```c
/* 在时钟中断处理函数中 */
void timer_interrupt_handler(void) {
    /* 更新系统时间 */

    /* 检查是否需要重新调度 */
    if (scheduler.need_resched) {
        schedule();
    }
}
```

need_resched 标志由其他地方设置，比如进程睡眠、信号处理等。对于简单的时间片轮转，可以在时钟中断中维护一个计数器，每达到一定次数就设置 need_resched。

## 调度器的使用场景

调度器在几个关键场景下被调用：

第一，新进程创建后。fork 系统调用创建子进程后，子进程需要被加入运行队列，父进程可能需要让出 CPU 给子进程运行。

第二，进程主动让出 CPU。调用 sched_yield() 或者某些阻塞操作（如等待 I/O）时。

第三，时钟中断。时间片用完后，调度器切换到下一个进程。

第四，进程退出。exit 系统调用会调用 schedule() 切换到其他进程。

## 空闲进程

当没有其他进程可运行时，调度器会执行空闲进程。空闲进程通常是一个无限循环，执行 hlt 指令降低功耗：

```c
/**
 * @brief 空闲进程的主循环
 */
void idle_main(void) {
    while (1) {
        __asm__ volatile("hlt");  /* 等待中断 */
        schedule();               /* 检查是否有新进程 */
    }
}
```

hlt 指令让 CPU 进入低功耗状态，直到中断发生。中断返回后，schedule() 检查是否有新进程可运行。

## 踩坑预警

第一个坑是自调度问题。如果 schedule() 函数在持有锁的情况下被调用，可能导致死锁。一定要确保调用 schedule() 前释放所有自旋锁。

第二个坑是空队列处理。当运行队列为空且没有空闲进程时，schedule() 会无路可走。确保在系统初始化时至少创建一个空闲进程。

第三个坑是状态不一致。进程在 run_queue 中但状态不是 READY，会导致调度混乱。确保状态转换和队列操作的原子性（单核系统可以通过禁用中断保证）。

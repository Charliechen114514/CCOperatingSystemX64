## fork 系统调用

fork 是最复杂的系统调用之一。它创建一个几乎与父进程完全相同的子进程，包括代码、数据、堆栈等。在写时复制（COW）实现之前，我们先做一个简化版本：创建一个新的 PCB，复制基本信息，但地址空间暂时留空。

```c
/**
 * @brief 复制父进程地址空间到子进程
 * @param parent 父进程 PCB
 * @param child 子进程 PCB
 * @return 0 成功，-1 失败
 */
static int proc_copy_address_space(pcb_t* parent, pcb_t* child) {
    /* 创建新的用户地址空间 */
    vmm_result_t result = vmm_create_user_space(&child->mm.pml4_phys);
    if (result != VMM_OK) {
        klog_error("[PROC] Failed to create user address space for child\n");
        return -1;
    }

    /* TODO: 实现完整的 COW fork
     * 1. 复制父进程的页表项到子进程
     * 2. 将页面注册为 COW
     * 3. 标记页面为只读 + COW
     * 当前版本：创建空地址空间
     */

    /* 复制内存上下文设置 */
    child->mm.brk = parent->mm.brk;
    child->mm.stack_start = parent->mm.stack_start;

    return 0;
}

/**
 * @brief fork - 创建新进程
 * @return 父进程返回子进程 PID，子进程返回 0，错误返回负数
 */
int32_t proc_fork(void) {
    pcb_t* parent = proc_current();
    if (!parent) {
        klog_error("[PROC] No current process to fork from\n");
        return -1;
    }

    /* 分配子进程 PCB */
    pcb_t* child = proc_alloc_pcb();
    if (!child) {
        klog_error("[PROC] Failed to allocate child PCB\n");
        return -1;
    }

    /* 分配 PID */
    child->pid = pid_alloc();
    if (child->pid < 0) {
        klog_error("[PROC] Failed to allocate PID\n");
        proc_free_pcb(child);
        return -1;
    }

    /* 设置基本关系 */
    child->ppid = parent->pid;
    child->parent = parent;
    child->state = PROC_READY;
    child->start_time = 0;  /* TODO: 获取实际时间 */

    /* 新进程是自己的线程组领导者 */
    child->tgid = child->pid;
    child->is_thread = false;

    /* 重置 mm 引用计数 */
    atomic_write(&child->mm_refcount, 1);

    /* 复制命令名 */
    for (int i = 0; i < 16; i++) {
        child->comm[i] = parent->comm[i];
    }

    /* 复制地址空间 */
    if (proc_copy_address_space(parent, child) != 0) {
        pid_free(child->pid);
        proc_free_pcb(child);
        return -1;
    }

    /* 添加到父进程的子进程列表 */
    list_add_tail(&child->siblings, &parent->children);

    /* 加入运行队列 */
    list_add_tail(&child->run_list, &scheduler.run_queue);
    scheduler.nr_running++;

    klog_info("[PROC] Forked: parent PID=%d, child PID=%d\n",
              parent->pid, child->pid);

    /* 如果是子进程，返回 0 */
    /* 注意：这里有个技巧，实际实现中需要在上下文恢复后判断 */
    return child->pid;
}
```

fork 的逻辑比较复杂，我们分解一下：

首先分配子进程的 PCB，如果分配失败，直接返回错误。

然后分配 PID，PID 分配失败要释放之前分配的 PCB。

接着设置父子和线程组关系。新进程是自己的线程组领导者，tgid = pid。

复制命令名，这在调试时很有用。

复制地址空间。当前版本是简化实现，只创建空地址空间。完整的 COW fork 需要复制页表项并设置 COW 标记，这是后续优化方向。

最后把子进程加入父进程的 children 列表和全局运行队列。

注意返回值的处理：父进程返回子进程的 PID，子进程返回 0。但这个判断实际上需要在上下文切换完成后才能做，因为 fork 返回后，代码已经在不同进程的上下文中执行了。

## exit 系统调用

exit 让当前进程退出：

```c
/**
 * @brief 退出当前进程
 * @param exit_code 退出码
 */
void proc_exit(int exit_code) {
    pcb_t* current = proc_current();
    if (!current) {
        klog_error("[PROC] No current process to exit\n");
        while (1) {
            __asm__ volatile("hlt");
        }
    }

    klog_info("[PROC] Process %d exiting with code %d\n",
              current->pid, exit_code);

    /* 设置僵尸状态 */
    current->state = PROC_ZOMBIE;
    current->exit_code = exit_code;

    /* 从运行队列移除 */
    list_del(&current->run_list);

    /* 移动到父进程的僵尸列表 */
    if (current->parent) {
        list_add_tail(&current->zombie_children,
                      &current->parent->zombie_children);
    }

    scheduler.nr_running--;

    /* 调度下一个进程 */
    schedule();

    /* 永不返回 */
    __builtin_unreachable();
}
```

exit 把进程设为 ZOMBIE 状态，从运行队列移除，然后放到父进程的 zombie_children 列表。注意进程的 PCB 还没有释放，需要父进程调用 wait4 来回收。

最后调用 schedule() 切换到其他进程。__builtin_unreachable() 告诉编译器这里永远不会返回，避免编译器产生警告或错误代码。

## wait4 系统调用

wait4 等待子进程退出，并回收其资源：

```c
/**
 * @brief 等待子进程退出
 * @param pid 要等待的进程 ID（-1 表示任意）
 * @param wstatus 存储退出状态
 * @param options 选项（WNOHANG 等）
 * @return 退出的子进程 PID，或负数表示错误
 */
int32_t proc_wait4(int32_t pid, int* wstatus, int options) {
    (void)options;  /* TODO: 实现选项 */

    pcb_t* current = proc_current();
    if (!current) {
        return -1;
    }

    /* 检查是否有僵尸子进程 */
    pcb_t* child;
    pcb_t* target = NULL;
    list_for_each_entry(child, &current->zombie_children, zombie_children) {
        if (pid == -1 || child->pid == pid) {
            target = child;
            break;
        }
    }

    if (target) {
        /* 找到僵尸子进程 */
        if (wstatus) {
            *wstatus = target->exit_code;
        }
        int32_t result = target->pid;

        /* 从僵尸列表移除并释放 PCB */
        list_del(&target->zombie_children);
        proc_free_pcb(target);

        return result;
    }

    /* 没有僵尸子进程，阻塞当前进程 */
    /* TODO: 实现阻塞与唤醒机制 */
    current->state = PROC_BLOCKED;
    schedule();

    return -1;  /* 会在子进程退出时被唤醒 */
}
```

wait4 首先查找僵尸子进程。如果找到，返回退出码并释放 PCB。如果没有找到，当前进程进入 BLOCKED 状态，调用 schedule() 让出 CPU。

注意当前版本的阻塞是简化实现。完整的实现需要在子进程退出时唤醒父进程，这需要等待队列机制。

## getpid 和 getppid

这两个系统调用很简单：

```c
/**
 * @brief 获取当前进程 ID
 */
int32_t sys_getpid(void) {
    pcb_t* current = proc_current();
    return current ? current->pid : -1;
}

/**
 * @brief 获取父进程 ID
 */
int32_t sys_getppid(void) {
    pcb_t* current = proc_current();
    return current ? current->ppid : -1;
}
```

## 注册系统调用

现在把这些函数注册到系统调用表：

```c
/* kernel/syscall/syscall_table.c */

#include "process/process.h"

/* 系统调用 39 - getpid */
int64_t sys_getpid(void) {
    pcb_t* current = proc_current();
    return current ? current->pid : -1;
}

/* 系统调用 57 - fork */
int64_t sys_fork(void) {
    return proc_fork();
}

/* 系统调用 60 - exit */
int64_t sys_exit(int error_code) {
    proc_exit(error_code);
    return 0;  /* 永不返回 */
}

/* 系统调用 61 - wait4 */
int64_t sys_wait4(int32_t pid, int* wstatus, int options) {
    return proc_wait4(pid, wstatus, options);
}

/* 系统调用 110 - getppid */
int64_t sys_getppid(void) {
    pcb_t* current = proc_current();
    return current ? current->ppid : -1;
}

/* 在系统调用表中注册 */
void syscall_init(void) {
    /* ... 其他系统调用 ... */

    /* 进程相关 */
    register_syscall(39, sys_getpid);
    register_syscall(57, sys_fork);
    register_syscall(60, sys_exit);
    register_syscall(61, sys_wait4);
    register_syscall(110, sys_getppid);
}
```

## 编写测试程序

为了验证进程管理是否正常工作，我们编写一个简单的演示程序。这个程序会创建几个子进程，然后等待它们退出。

```c
/* kernel/demo/process_simple/process_demo.c */

int process_run_demo(void) {
    klog_info("\n");
    klog_info("╔════════════════════════════════════════╗\n");
    klog_info("║   Process Management Demo               ║\n");
    klog_info("╚════════════════════════════════════════╝\n");

    /* 测试 1: PID 分配 */
    klog_info("[PROC_DEMO] Test: PID Allocation...\n");
    pid_alloc_init();
    int32_t pid1 = pid_alloc();
    int32_t pid2 = pid_alloc();
    klog_info("[PROC_DEMO] Allocated PIDs: %d, %d\n", pid1, pid2);
    pid_free(pid1);
    int32_t pid3 = pid_alloc();
    klog_info("[PROC_DEMO] After free, allocated: %d (should be %d)\n", pid3, pid1);
    klog_info("[PROC_DEMO] PASSED\n");

    /* 测试 2: PCB 分配 */
    klog_info("[PROC_DEMO] Test: PCB Allocation...\n");
    pcb_t* pcb = proc_alloc_pcb();
    if (pcb) {
        klog_info("[PROC_DEMO] PCB allocated, kernel_stack = 0x%llx\n", pcb->kernel_stack);
        proc_free_pcb(pcb);
        klog_info("[PROC_DEMO] PASSED\n");
    }

    /* 测试 3: 进程状态转换 */
    klog_info("[PROC_DEMO] Test: Process States...\n");
    pcb = proc_alloc_pcb();
    pcb->state = PROC_READY;
    klog_info("[PROC_DEMO] State: READY\n");
    pcb->state = PROC_RUNNING;
    klog_info("[PROC_DEMO] State: RUNNING\n");
    pcb->state = PROC_ZOMBIE;
    klog_info("[PROC_DEMO] State: ZOMBIE\n");
    proc_free_pcb(pcb);
    klog_info("[PROC_DEMO] PASSED\n");

    klog_info("\n");
    klog_info("╔════════════════════════════════════════╗\n");
    klog_info("║   Process Demo Summary                 ║\n");
    klog_info("╚════════════════════════════════════════╝\n");
    klog_info("[PROC_DEMO] ✓ All tests PASSED\n");

    return 0;
}
```

## 踩坑预警

第一个坑是僵尸进程泄漏。如果父进程忘记调用 wait4()，僵尸进程永远不会被回收，最终会耗尽 PID 和内存。确保每个 fork 都有对应的 wait4。

第二个坑是父子进程同步。子进程创建后，父进程和子进程并发执行。如果需要同步，需要使用等待队列或信号量机制。

第三个坑是地址空间复制不完整。当前版本的 fork 没有真正复制地址空间，子进程无法访问父进程的数据。完整的实现需要 COW 机制。

# 19-3 上下文切换的汇编实现

## 前言

这一章可能是整个进程管理中最底层的部分了。上下文切换必须用汇编实现，因为 C 语言无法精确控制所有寄存器的操作。说实话，第一次写这段代码的时候我真的是小心翼翼，每一条指令都反复确认，生怕哪里弄错了导致莫名其妙的崩溃。

但你会发现，一旦理解了背后的原理，这段代码其实逻辑很清晰。我们按照功能分段讲解，一步步把 switch_context() 和 switch_to_first() 两个函数搞清楚。

## 环境说明

本章需要创建 switch.s 文件，实现两个汇编函数：
- switch_context() - 进程间切换
- switch_to_first() - 从内核切换到首个进程

你需要对 x86_64 汇编有基本了解，知道寄存器命名、指令格式、调用约定等内容。

## x86_64 调用约定回顾

在深入代码之前，我们先回顾一下 x86_64 System V AMD64 ABI 的调用约定。

函数调用时，寄存器分为两类：caller-saved 和 callee-saved。

Caller-saved 寄存器由调用者负责保护：RAX, RCX, RDX, RSI, RDI, R8-R11。函数可以随意修改这些寄存器，调用者如果需要保留这些值，要在调用前自己保存。

Callee-saved 寄存器由被调用者负责保护：RBX, RBP, R12-R15。函数如果修改这些寄存器，必须在返回前恢复原始值。

上下文切换时，我们只需要保存 callee-saved 寄存器。为什么？因为上下文切换本质上是一个函数调用，caller-saved 寄存器已经由调用者（或者说编译器生成的代码）处理了。

栈指针 RSP 和返回地址 RIP 比较特殊。它们由 call/ret 指令自动管理，但上下文切换时需要手动处理。

## 为什么上下文切换必须用汇编

这个问题值得好好解释一下。理论上，C 代码可以通过 setjmp/longjmp 或者内联汇编实现上下文切换，但实际操作有几个问题：

第一，编译器生成的代码会"偷偷"使用寄存器。你可能在 C 代码中只用了几个变量，但编译器可能把它们都放在寄存器里，你的"保存"操作可能漏掉某些寄存器。

第二，RSP 和 RIP 必须精确操作。C 语言无法直接获取当前 RSP 的值，也无法精确控制函数返回后的执行位置。

第三，CR3 寄存器（页表基址）和 TSS（任务状态段）的操作需要特殊指令，这些在 C 语言中不方便实现。

因此，上下文切换必须用汇编实现，确保每一条指令都精确执行。

## TSS RSP0 的作用

TSS（Task State Segment）是 x86 架构的一个遗留结构，在现代操作系统里主要用于一个目的：指定中断发生时的内核栈。

当中断或系统调用从用户态进入内核态时，CPU 会自动切换到 TSS.RSP0 指向的栈。这意味着每个进程需要一个独立的内核栈，否则多个用户进程共享同一个内核栈会互相干扰。

每次切换进程时，我们必须更新 TSS.RSP0 = next->kernel_stack。这个操作必须在切换 CR3 之前完成，原因我们后面会解释。

## CR3 切换与 TLB 刷新

CR3 寄存器保存页表的物理地址。切换 CR3 就意味着切换地址空间。

切换 CR3 有个副作用：它会刷新 TLB（Translation Lookaside Buffer）。TLB 是虚拟地址到物理地址的缓存，刷新后所有地址映射都需要重新查找，这会影响性能。

但在我们的设计中，每个进程都有独立的地址空间，所以切换进程时必须切换 CR3。后续优化可以考虑判断当前进程和新进程是否共享地址空间（比如同一进程的线程），如果共享则跳过 CR3 切换。

## switch.s 文件结构

我们先定义 PCB 结构的汇编偏移量。这些偏移量必须与 process.h 中的定义完全一致：

```asm
; ============================================================================
; PCB 结构偏移量
; ============================================================================
; 这些偏移量必须与 process.h 中的 pcb_t 结构完全匹配！

struc pcb
    .pid                resd 1    ; offset   0
    .ppid               resd 1    ; offset   4
    .state              resd 1    ; offset   8
    .exit_code          resd 1    ; offset  12
    .run_list           resq 2    ; offset  16
    .siblings           resq 2    ; offset  32
    .children           resq 2    ; offset  48
    .zombie_children    resq 2    ; offset  64
    .sched_entity       resb 56   ; offset  80
    .mm_pml4            resq 1    ; offset 136
    .mm_brk             resq 1    ; offset 144
    .mm_stack_start     resq 1    ; offset 152
    .cpu_ctx            resq 1    ; offset 160
    .trap_frame         resb 176  ; offset 168
    .kernel_stack       resq 1    ; offset 344
    .kernel_stack_base  resq 1    ; offset 352
    .is_user_mode       resb 1    ; offset 360
    .user_stack         resq 1    ; offset 364
    .user_stack_size    resq 1    ; offset 372
    .parent             resq 1    ; offset 380
    .start_time         resq 1    ; offset 388
    .comm               resb 16   ; offset 396
    .pad_comm           resb 4    ; offset 412
    .tgid               resd 1    ; offset 416
    .is_thread          resb 1    ; offset 420
    .pad_thread         resb 3    ; offset 421
    .thread_list        resq 2    ; offset  424
    .thread_group       resq 2    ; offset  440
    .mm_refcount        resd 1    ; offset 456
    .pad_refcount       resb 4    ; offset 460
    .join_waiters       resq 1    ; offset 464
    .detached           resb 1    ; offset 472
    .pad_detached       resb 7    ; offset 473
    .return_value       resq 1    ; offset 480
    .thread_entry       resq 1    ; offset 488
    .thread_arg         resq 1    ; offset 496
endstruc

; cpu_context_t 结构偏移量
struc cpu_ctx
    .rbx    resq 1
    .rbp    resq 1
    .r12    resq 1
    .r13    resq 1
    .r14    resq 1
    .r15    resq 1
    .rsp    resq 1
    .rip    resq 1
endstruc
```

注意这些偏移量是手动计算的，如果修改了 process.h 中的结构，必须同步更新这里。这个不匹配是一个非常隐蔽且难以调试的 bug。

## switch_context() 函数

switch_context() 函数用于进程间切换。它的 C 签名是：

```c
void switch_context(pcb_t** prev, pcb_t* next);
```

按照 System V ABI，参数通过寄存器传递：RDI = &prev, RSI = next。

### 第一段：保存当前进程状态

```asm
global switch_context
switch_context:
    ; RDI = &prev (指针的指针)
    ; RSI = next (pcb_t*)

    ; 保存 callee-saved 寄存器
    push rbx
    push rbp
    push r12
    push r13
    push r14
    push r15

    ; 获取 prev PCB 指针
    mov rax, [rdi]           ; rax = *prev

    ; 获取 cpu_ctx 指针（cpu_ctx 是指针，不是内嵌结构！）
    mov rcx, [rax + pcb.cpu_ctx]    ; rcx = prev->cpu_ctx

    ; 保存 RSP（此时 RSP 指向最后 push 的 r15）
    mov [rcx + cpu_ctx.rsp], rsp

    ; 保存寄存器
    mov [rcx + cpu_ctx.rbx], rbx
    mov [rcx + cpu_ctx.rbp], rbp
    mov [rcx + cpu_ctx.r12], r12
    mov [rcx + cpu_ctx.r13], r13
    mov [rcx + cpu_ctx.r14], r14
    mov [rcx + cpu_ctx.r15], r15

    ; 保存 RIP（返回地址在 [rsp + 6*8] = rsp + 48）
    mov r15, [rsp + 48]
    mov [rcx + cpu_ctx.rip], r15
```

这里有几个关键点。首先，我们 push 了 6 个寄存器，每个 8 字节，共 48 字节。返回地址（call 指令自动 push 的）在这 48 字节之上，所以偏移量是 48。

其次，cpu_ctx 是一个指针，不是内嵌结构。所以我们要先加载这个指针的值，然后再访问 cpu_context_t 结构的字段。

### 第二段：切换系统状态

```asm
    ; 保存 RSI（next 指针），因为函数调用会破坏它
    push rsi

    ; 更新 TSS.RSP0
    mov rdi, [rsi + pcb.kernel_stack]
    call tss_set_kernel_stack_ctx

    ; 恢复 RSI
    pop rsi

    ; 保存 RSI（第二次函数调用前）
    push rsi

    ; 切换 CR3
    mov rdi, [rsi + pcb.mm_pml4]
    call vmm_load_pml4

    ; 恢复 RSI
    pop rsi
```

为什么 TSS.RSP0 的更新要在 CR3 切换之前？因为更新 TSS.RSP0 是一个内核操作，需要访问当前地址空间的数据。如果先切换 CR3，可能访问到错误的地址。

这里用了 push/pop 来保护 RSI 寄存器，因为函数调用可能会修改它。虽然按照调用约定，RDI 是第一个参数寄存器，调用后可以修改，但我们还是小心一点。

### 第三段：恢复下一个进程的状态

```asm
    ; 从 next->cpu_ctx 恢复寄存器
    mov rax, [rsi + pcb.cpu_ctx]    ; rax = next->cpu_ctx
    mov rbx, [rax + cpu_ctx.rbx]
    mov rbp, [rax + cpu_ctx.rbp]
    mov r12, [rax + cpu_ctx.r12]
    mov r13, [rax + cpu_ctx.r13]
    mov r14, [rax + cpu_ctx.r14]
    mov r15, [rax + cpu_ctx.r15]

    ; 恢复 RSP
    mov rsp, [rax + cpu_ctx.rsp]

    ; 恢复 callee-saved 寄存器
    pop r15
    pop r14
    pop r13
    pop r12
    pop rbp
    pop rbx

    ; 返回
    ret
```

注意恢复的顺序：先恢复通用寄存器到寄存器中，然后恢复 RSP，最后 pop 寄存器并返回。pop 的顺序与 push 相反，这是栈的基本规则。

ret 指令会弹出之前保存的返回地址，跳转到下一个进程的执行点。这正是上下文切换的魔力所在。

## switch_to_first() 函数

switch_to_first() 用于从内核初始化切换到第一个进程。这时没有"前一个进程"需要保存。

```asm
global switch_to_first
switch_to_first:
    ; RDI = first (pcb_t*)

    ; 提取所有需要的值（在修改任何状态之前）
    mov rsi, rdi                ; RSI = first 指针

    mov rax, [rsi + pcb.cpu_ctx]

    ; 提取 callee-saved 寄存器
    mov rbx, [rax + cpu_ctx.rbx]
    mov rbp, [rax + cpu_ctx.rbp]
    mov r12, [rax + cpu_ctx.r12]
    mov r13, [rax + cpu_ctx.r13]
    mov r14, [rax + cpu_ctx.r14]
    mov r15, [rax + cpu_ctx.r15]

    ; 提取 RIP 和其他值
    mov rcx, [rax + cpu_ctx.rip]     ; RCX = 入口点
    mov r8,  [rsi + pcb.kernel_stack] ; R8 = 内核栈（用于 TSS）
    mov r9, [rsi + pcb.mm_pml4]      ; R9 = 页表物理地址

    ; 更新 TSS.RSP0
    mov rdi, r8
    call tss_set_kernel_stack_ctx

    ; 切换 CR3
    mov rdi, r9
    call vmm_load_pml4

    ; 获取新 RSP
    mov rax, [rsi + pcb.cpu_ctx]
    mov rdx, [rax + cpu_ctx.rsp]     ; RDX = 新栈指针

    ; 切换到新进程的栈
    mov rsp, rdx

    ; 构建 iretq 帧
    pushfq
    pop qword rax
    or rax, 0x200               ; 设置中断标志
    push rax

    push qword 0x08             ; 内核代码段

    push rcx                    ; RIP（入口点）

    ; 执行 iretq
    iretq
```

switch_to_first() 和 switch_context() 的主要区别在于：前者不需要保存任何状态，而且需要用 iretq 而不是 ret 来跳转。

iretq（中断返回）指令会从栈中弹出 RIP、CS、RFLAGS，恢复执行状态。这里我们构建了一个假的"中断帧"，让 CPU 以为是从中断返回，这样可以确保中断标志正确设置。

## 调试技巧

编写汇编代码时，调试是个大问题。这里有几个技巧：

第一，用 GDB 的 si（单步指令）命令逐步执行，观察每个寄存器的值变化。在关键位置设置断点，比如 switch_context 的入口和出口。

第二，在代码中添加一些容易识别的模式，比如在切换前后给某个寄存器设置特定值，这样在崩溃时可以通过寄存器值判断是在哪个阶段出的问题。

第三，使用 QEMU 的 monitor 命令 info registers 查看寄存器状态，info mem 查看内存映射。

## 踩坑预警

第一，栈对齐问题。x86_64 ABI 要求函数调用时栈指针 16 字节对齐。如果栈未对齐，某些库函数（特别是使用 SSE/AVX 指令的函数）会崩溃。确保 PCB 分配时内核栈是 16 字节对齐的。

第二，TSS.RSP0 更新顺序。必须在切换 CR3 之前更新 TSS.RSP0，否则如果期间发生中断，CPU 会使用错误的内核栈。

第三，PCB 偏移量同步。process.h 和 switch.s 中的偏移量必须完全一致，任何不匹配都会导致读写错误的字段。

# 实现读写锁 —— 读多写少场景优化

## 前言

读写锁（read-write lock）是一种专门为"读多写少"场景优化的同步原语。它允许多个读者同时访问，但写者必须独占访问。这对于配置表、路由表、缓存等数据结构非常有用。

这篇文章会实现一个读者优先的读写锁，并讨论写者饥饿问题。

## 第一步——定义 rwlock_t 结构

```c
/**
 * @file rwlock.h
 * @brief 读写锁
 * @date 2026-02-18
 */
#pragma once

#include "defines/types.h"
#include "sync/atomic.h"
#include "sync/spinlock.h"

/* ==============================================================================
 * 读写锁类型
 * ==============================================================================
 */

typedef struct {
    atomic_t readers;  /* 活跃读者数（负数表示有写者） */
    atomic_t writers;  /* 等待或活跃的写者数 */
    spinlock_t lock;   /* 内部锁 */
} rwlock_t;

/* ==============================================================================
 * 函数声明
 * ==============================================================================
 */

void rwlock_init(rwlock_t* lock);
void rwlock_read_lock(rwlock_t* lock);
void rwlock_read_unlock(rwlock_t* lock);
void rwlock_write_lock(rwlock_t* lock);
void rwlock_write_unlock(rwlock_t* lock);
void rwlock_write_downgrade(rwlock_t* lock);  /* 写锁降级为读锁 */
```

## 第二步——实现初始化

```c
/**
 * @file rwlock.c
 * @brief 读写锁实现
 */

#include "sync/rwlock.h"
#include "process/sched.h"

void rwlock_init(rwlock_t* lock) {
    atomic_set(&lock->readers, 0);
    atomic_set(&lock->writers, 0);
    spin_lock_init(&lock->lock);
}
```

## 第三步——实现读锁

读者优先策略：只要有读者在读，新的读者可以直接进入。

```c
void rwlock_read_lock(rwlock_t* lock) {
    spin_lock(&lock->lock);

    // 等待没有写者
    while (atomic_read(&lock->writers) > 0) {
        spin_unlock(&lock->lock);
        schedule();  /* 让出 CPU */
        spin_lock(&lock->lock);
    }

    // 增加读者计数
    atomic_inc(&lock->readers);

    spin_unlock(&lock->lock);
}

void rwlock_read_unlock(rwlock_t* lock) {
    // 减少读者计数
    atomic_dec(&lock->readers);
}
```

## 第四步——实现写锁

写者必须等待所有读者完成：

```c
void rwlock_write_lock(rwlock_t* lock) {
    spin_lock(&lock->lock);

    // 标记有写者在等待/活跃
    atomic_inc(&lock->writers);

    // 等待所有读者完成
    while (atomic_read(&lock->readers) != 0) {
        spin_unlock(&lock->lock);
        schedule();
        spin_lock(&lock->lock);
    }

    spin_unlock(&lock->lock);
}

void rwlock_write_unlock(rwlock_t* lock) {
    // 减少写者计数
    atomic_dec(&lock->writers);
}
```

## 第五步——实现写锁降级

写锁降级是指把写锁变成读锁，不释放锁的情况下允许其他读者进入：

```c
void rwlock_write_downgrade(rwlock_t* lock) {
    spin_lock(&lock->lock);

    // 写者变成读者
    atomic_inc(&lock->readers);
    atomic_dec(&lock->writers);

    spin_unlock(&lock->lock);
}
```

## 使用示例

```c
static rwlock_t config_lock;

// 初始化
rwlock_init(&config_lock);

// 读者
void read_config(void) {
    rwlock_read_lock(&config_lock);

    // 可以多个读者同时读取
    read_config_data();

    rwlock_read_unlock(&config_lock);
}

// 写者
void write_config(void) {
    rwlock_write_lock(&config_lock);

    // 同一时刻只能有一个写者
    update_config_data();

    rwlock_write_unlock(&config_lock);
}
```

## 写者饥饿问题

读者优先策略的问题是：如果读者源源不断，写者可能永远等不到。这就是写者饥饿。

解决方案：

1. **写者优先**：一旦有写者在等待，新读者必须排队
2. **公平调度**：使用队列保证公平性
3. **限时等待**：写者等待超时后强制获取锁

我们的基础实现采用读者优先，简单但可能有饥饿问题。如果需要避免饥饿，可以改进算法。

## 与互斥锁的性能对比

在读写比例高的情况下（比如 10:1），读写锁的性能明显优于互斥锁，因为多个读者可以并发执行。

如果读写比例接近（比如 1:1），读写锁的优势不明显，因为读者和写者会互相阻塞。

# 实现条件变量 —— 事件同步

## 前言

条件变量（condition variable）是一种用于等待某个条件成立的同步原语。与信号量不同，条件变量必须与互斥锁配合使用，这样可以避免"信号丢失"问题。

条件变量的典型使用场景是：线程 A 等待某个条件成立，线程 B 在使条件成立后通知线程 A。

## 第一步——定义 condvar_t 结构

```c
/**
 * @file condvar.h
 * @brief 条件变量
 * @date 2026-02-18
 */
#pragma once

#include "sync/spinlock.h"
#include "sync/mutex.h"
#include "list/list.h"

/* ==============================================================================
 * 条件变量类型
 * ==============================================================================
 */

typedef struct {
    spinlock_t lock;    /* 保护 waiters */
    list_head waiters;  /* 等待进程链表 */
} condvar_t;

/* ==============================================================================
 * 函数声明
 * ==============================================================================
 */

void condvar_init(condvar_t* cv);
void condvar_wait(condvar_t* cv, mutex_t* mutex);
void condvar_signal(condvar_t* cv);
void condvar_broadcast(condvar_t* cv);
```

## 第二步——实现初始化

```c
/**
 * @file condvar.c
 * @brief 条件变量实现
 */

#include "sync/condvar.h"
#include "process/process.h"
#include "process/sched.h"

void condvar_init(condvar_t* cv) {
    spin_lock_init(&cv->lock);
    INIT_LIST_HEAD(&cv->waiters);
}
```

## 第三步——实现 wait 操作

`condvar_wait` 的关键在于：原子地释放互斥锁并进入睡眠，被唤醒后重新获取互斥锁。

```c
typedef struct {
    list_head list;
    pcb_t* task;
    mutex_t* mutex;  /* 关联的互斥锁 */
} condvar_waiter_t;

void condvar_wait(condvar_t* cv, mutex_t* mutex) {
    pcb_t* current = proc_current();

    spin_lock(&cv->lock);

    // 创建等待条目
    condvar_waiter_t wait;
    wait.task = current;
    wait.mutex = mutex;
    list_add_tail(&wait.list, &cv->waiters);

    // 释放互斥锁（原子操作的一部分）
    spin_unlock(&cv->lock);
    mutex_unlock(mutex);

    // 阻塞当前进程
    current->state = PROC_BLOCKED;
    schedule();

    // 被唤醒后，重新获取互斥锁
    mutex_lock(mutex);
}
```

## 第四步——实现 signal 操作

```c
void condvar_signal(condvar_t* cv) {
    spin_lock(&cv->lock);

    if (!list_empty(&cv->waiters)) {
        condvar_waiter_t* waiter = list_first_entry(
            &cv->waiters, condvar_waiter_t, list);
        list_del(&waiter->list);

        // 唤醒等待者
        waiter->task->state = PROC_READY;
        schedule_add(waiter->task);
    }

    spin_unlock(&cv->lock);
}
```

## 第五步——实现 broadcast 操作

```c
void condvar_broadcast(condvar_t* cv) {
    spin_lock(&cv->lock);

    condvar_waiter_t* waiter, *tmp;
    list_for_each_entry_safe(waiter, tmp, &cv->waiters, list) {
        list_del(&waiter->list);
        waiter->task->state = PROC_READY;
        schedule_add(waiter->task);
    }

    spin_unlock(&cv->lock);
}
```

## 为什么必须用 while 检查条件

这是条件变量最重要的使用规则。看下面的代码：

```c
// 错误示例
mutex_lock(&mutex);
if (!condition) {           // 错误！应该用 while
    condvar_wait(&cond, &mutex);
}
// 使用资源
mutex_unlock(&mutex);
```

为什么必须用 `while`？因为存在"虚假唤醒"（spurious wakeup）和"信号丢失"问题。

**虚假唤醒**：在某些实现中，线程可能在没有收到 signal 的情况下被唤醒。如果用 `if`，线程会在条件不满足的情况下继续执行，导致错误。

**信号丢失**：如果线程 B 在线程 A 调用 `wait` 之前就调用了 `signal`，信号会丢失。线程 A 会永远等待。

正确的用法：

```c
mutex_lock(&mutex);
while (!condition) {           // 正确！用 while 循环
    condvar_wait(&cond, &mutex);
}
// 使用资源
mutex_unlock(&mutex);
```

## 使用示例

生产者-消费者模式：

```c
static mutex_t mutex;
static condvar_t not_empty;
static condvar_t not_full;
static int buffer[10];
static int count = 0;

// 生产者
void producer(int item) {
    mutex_lock(&mutex);

    // 等待缓冲区未满
    while (count >= 10) {
        condvar_wait(&not_full, &mutex);
    }

    buffer[count++] = item;

    // 通知消费者
    condvar_signal(&not_empty);

    mutex_unlock(&mutex);
}

// 消费者
int consumer(void) {
    mutex_lock(&mutex);

    // 等待缓冲区非空
    while (count == 0) {
        condvar_wait(&not_empty, &mutex);
    }

    int item = buffer[--count];

    // 通知生产者
    condvar_signal(&not_full);

    mutex_unlock(&mutex);
    return item;
}
```

## signal vs broadcast

- `signal`：唤醒一个等待者
- `broadcast`：唤醒所有等待者

在多个等待者的情况下，选择哪个取决于场景：

- 如果资源只够一个消费者使用，用 `signal`
- 如果资源足够所有消费者使用，用 `broadcast`

# 实现自旋锁与中断保护 —— 最简单的锁

## 前言

有了原子操作作为基础，我们终于可以开始实现真正的锁了。第一个要实现的是自旋锁（spinlock），这是最简单的同步原语，也是所有其他锁的基础。

自旋锁的原理非常简单：获取不到锁的时候就一直循环检测，直到获取到为止。这听起来很浪费 CPU，但在某些场景下却是最优选择。特别是临界区非常短的时候（比如只是修改一个变量或几个变量），自旋锁比需要睡眠的互斥锁快得多，因为没有调度切换的开销。

这篇文章会实现一个完整的自旋锁，包括基本的 lock/unlock 操作、trylock 尝试操作，以及中断安全版本（irqsave/irqrestore）。中断安全版本很重要，因为中断处理程序也可能需要获取锁，如果处理不当会导致死锁。

## 第一步——定义 spinlock_t 类型

自旋锁的核心是一个状态标志：0 表示未锁定，1 表示已锁定。我们用原子操作来修改这个标志。

```c
/**
 * @file spinlock.h
 * @brief 自旋锁
 * @date 2026-02-18
 */
#pragma once

#include "defines/types.h"
#include "stdbool.h"

/* ==============================================================================
 * 自旋锁类型
 * ==============================================================================
 */

/**
 * @brief 自旋锁结构
 *
 * locked: 0 = 未锁定, 1 = 已锁定
 */
typedef struct {
    volatile int locked;
} spinlock_t;

/**
 * @brief 保存中断状态的类型
 */
typedef uint64_t spinlock_flags_t;

/* ==============================================================================
 * 初始化宏
 * ==============================================================================
 */

#define SPIN_LOCK_INIT {.locked = 0}
#define SPIN_LOCK_INITIALIZER ((spinlock_t)SPIN_LOCK_INIT)
```

## 第二步——实现基础自旋锁操作

自旋锁的核心操作是 lock 和 unlock。lock 会一直尝试获取锁，unlock 会释放锁。

我们使用 `__atomic_test_and_set` 来实现 lock。这个函数原子地执行：读取当前值，设置为 1，返回旧值。如果旧值是 0，说明我们成功获取了锁；如果是 1，说明锁已被占用，需要继续等待。

```c
/* ==============================================================================
 * 基础操作
 * ==============================================================================
 */

/**
 * @brief 初始化自旋锁
 */
static inline void spin_lock_init(spinlock_t* lock) {
    lock->locked = 0;
}

/**
 * @brief 获取自旋锁
 *
 * 如果锁已被占用，会忙等待直到获取到锁
 */
static inline void spin_lock(spinlock_t* lock) {
    // __atomic_test_and_set 返回旧值
    // 如果旧值是 1（已锁定），继续循环
    while (__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE)) {
        // 等待
        __asm__ volatile("pause" ::: "memory");
    }
}

/**
 * @brief 释放自旋锁
 */
static inline void spin_unlock(spinlock_t* lock) {
    __atomic_clear(&lock->locked, __ATOMIC_RELEASE);
}

/**
 * @brief 尝试获取自旋锁
 * @return 如果成功获取锁返回 true，否则返回 false
 */
static inline bool spin_trylock(spinlock_t* lock) {
    return !__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE);
}
```

这里有个重要的细节：`pause` 指令。在 x86_64 上，这个指令告诉 CPU 我们正在自旋等待，CPU 可以优化执行（比如降低功耗、避免内存顺序违规）。没有 `pause` 指令，自旋锁在 Intel CPU 上可能会严重影响性能。

`__ATOMIC_ACQUIRE` 和 `__ATOMIC_RELEASE` 是内存顺序参数。acquire 保证获取锁之后的操作不会重排到锁获取之前，release 保证释放锁之前的操作不会重排到锁释放之后。这对于正确的同步至关重要。

## 第三步——实现递归锁检测

自旋锁通常不支持递归获取（同一个线程多次获取同一个锁）。如果递归获取，线程会死锁在自已持有的锁上。

我们可以添加一个检测机制，在开发时发现问题：

```c
/* ==============================================================================
 * 辅助操作
 * ==============================================================================
 */

/**
 * @brief 检查自旋锁是否已被锁定
 */
static inline bool spin_is_locked(const spinlock_t* lock) {
    return lock->locked != 0;
}
```

这个函数可以用来检查锁状态。如果要实现递归锁检测，需要知道当前线程是谁，这需要和进程管理系统配合。我们会在实现互斥锁时加入这个功能。

## 第四步——实现中断安全版本

现在进入更复杂的内容：中断安全版本的自旋锁。

想象一下这个场景：线程 A 获取了自旋锁，在临界区内执行时发生了中断，中断处理程序也要获取同一个自旋锁。结果就是死锁：中断处理程序等待线程 A 释放锁，但线程 A 无法继续执行因为中断没处理完。

解决方法是在获取锁之前禁用中断，释放锁后恢复中断状态。

```c
/* ==============================================================================
 * 中断安全版本
 * ==============================================================================
 */

/**
 * @brief 禁用中断并获取自旋锁
 */
static inline void spin_lock_irq(spinlock_t* lock) {
    interrupt_disable();
    spin_lock(lock);
}

/**
 * @brief 释放自旋锁并启用中断
 */
static inline void spin_unlock_irq(spinlock_t* lock) {
    spin_unlock(lock);
    interrupt_enable();
}

/**
 * @brief 保存中断状态并获取自旋锁
 *
 * 这是更安全的版本：它会保存当前的中断状态，
 * 释放锁时恢复原来的状态，而不是无条件启用中断
 */
static inline void spin_lock_irqsave(spinlock_t* lock, spinlock_flags_t* flags) {
    uint64_t rflags;
    // 读取 RFLAGS 寄存器
    __asm__ volatile("pushfq; popq %0" : "=r"(rflags));
    *flags = rflags;

    interrupt_disable();
    spin_lock(lock);
}

/**
 * @brief 释放自旋锁并恢复中断状态
 */
static inline void spin_unlock_irqrestore(spinlock_t* lock, spinlock_flags_t flags) {
    spin_unlock(lock);

    // 检查 IF 标志（bit 9）
    if (flags & 0x200) {
        interrupt_enable();
    }
}
```

`pushfq; popq` 指令把 RFLAGS 寄存器的值读取到变量中。RFLAGS 的 bit 9 是 IF（Interrupt Flag）标志，表示中断是否启用。我们在 `unlock_irqrestore` 中检查这个标志，只有原来中断是启用的情况下才重新启用。

注意 `interrupt_disable()` 和 `interrupt_enable()` 的实现。在我们的内核中，它们应该是：

```c
// 在 interrupt/idt.h 或类似位置
static inline void interrupt_disable(void) {
    __asm__ volatile("cli" ::: "memory");
}

static inline void interrupt_enable(void) {
    __asm__ volatile("sti" ::: "memory");
}
```

`cli` 清除 IF 标志，禁用中断；`sti` 设置 IF 标志，启用中断。

## 第五步——实现 "Raw" 版本

有些场景我们需要"原始"的自旋锁操作，不修改抢占计数（preempt_count）。这是高级用法，只在特定场景下需要：比如中断处理程序中使用锁，或者日志系统在调度器初始化之前需要锁。

```c
/* ==============================================================================
 * Raw 版本（不修改 preempt_count）
 * ==============================================================================
 *
 * 这些是"原始"自旋锁，不会修改 preempt_count。
 * 只应该在以下场景使用：
 * 1. 中断上下文中，没有当前进程
 * 2. 调度器初始化之前的日志/调试系统
 * 3. 你绝对知道自己在做什么！
 */

static inline void spin_lock_raw(spinlock_t* lock) {
    while (__atomic_test_and_set(&lock->locked, __ATOMIC_ACQUIRE)) {
        __asm__ volatile("pause" ::: "memory");
    }
}

static inline void spin_unlock_raw(spinlock_t* lock) {
    __atomic_clear(&lock->locked, __ATOMIC_RELEASE);
}

static inline void spin_lock_irqsave_raw(spinlock_t* lock, spinlock_flags_t* flags) {
    __asm__ volatile("pushfq; popq %0" : "=r"(*flags));
    __asm__ volatile("cli" ::: "memory");
    spin_lock_raw(lock);
}

static inline void spin_unlock_irqrestore_raw(spinlock_t* lock, spinlock_flags_t flags) {
    spin_unlock_raw(lock);
    if (flags & 0x200) {
        __asm__ volatile("sti" ::: "memory");
    }
}
```

这些 raw 版本不会修改 `preempt_count`，这意味着它们不会影响内核抢占行为。通常你应该使用普通版本，只有在明确知道需要 raw 版本时才使用。

```c
/**

#include "sync/spinlock.h"

```

实际上，因为我们所有函数都是 `static inline`，这个 `.c` 文件主要是为了保持项目结构一致。

## 使用示例

让我们看看如何使用自旋锁：

```c
// 全局锁
static spinlock_t g_lock = SPIN_LOCK_INIT;

// 全局计数器
static int g_counter = 0;

// 线程安全的增加计数器
void safe_increment(void) {
    spin_lock(&g_lock);
    g_counter++;
    spin_unlock(&g_lock);
}

// 中断处理程序中使用
void interrupt_handler(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_lock, &flags);

    // 临界区：处理中断，访问共享数据
    handle_shared_data();

    spin_unlock_irqrestore(&g_lock, flags);
}
```

## 性能考虑

自旋锁的性能取决于几个因素：

**临界区长度**。临界区越短，自旋锁越高效。如果临界区长到需要调度切换，应该考虑使用互斥锁。

**CPU 核心数**。单核系统上，自旋锁的等待完全是浪费 CPU，因为没有其他核心能释放锁。多核系统上，自旋锁更有意义。

**竞争程度**。如果锁竞争很少，大部分时候一次 `trylock` 就成功，自旋锁非常快。如果锁竞争激烈，很多 CPU 核心在自旋等待，浪费资源。

作为经验法则：
- 临界区执行时间 < 一次调度开销（约几微秒）：用自旋锁
- 临界区执行时间 > 一次调度开销：用互斥锁
- 中断处理程序中：必须用自旋锁（因为不能睡眠）

## 常见陷阱

使用自旋锁时有一些常见的错误：

**在持有自旋锁时睡眠**。这是绝对的错误，会导致死锁。自旋锁等待者不会睡眠，如果持有锁的线程睡眠了，没人能释放锁。

```c
// 错误示例
spin_lock(&lock);
schedule();  // 错误！持有锁时不能睡眠
spin_unlock(&lock);
```

**忘记释放锁**。这在任何锁类型上都是错误，但自旋锁尤其严重，因为等待者会一直占用 CPU。

```c
// 错误示例
spin_lock(&lock);
if (error) {
    return;  // 错误！忘记释放锁
}
spin_unlock(&lock);
```

正确做法是确保所有路径都释放锁：

```c
spin_lock(&lock);
if (error) {
    spin_unlock(&lock);
    return;
}
spin_unlock(&lock);
```

**递归获取锁**。普通自旋锁不支持递归获取，会导致死锁。

```c
// 错误示例
spin_lock(&lock);
spin_lock(&lock);  // 死锁！
spin_unlock(&lock);
spin_unlock(&lock);
```

如果需要递归锁，应该使用互斥锁（我们会实现递归互斥锁），或者修改代码结构避免递归获取。

## 验证

自旋锁的验证比较困难，因为竞态条件不是每次都能触发。我们可以写一个简单的测试：

```c
#include "sync/spinlock.h"

static spinlock_t test_lock = SPIN_LOCK_INIT;
static int test_counter = 0;

// 创建多个线程同时增加计数器
void test_thread(void* arg) {
    for (int i = 0; i < 10000; i++) {
        spin_lock(&test_lock);
        test_counter++;
        spin_unlock(&test_lock);
    }
}

// 主线程创建多个测试线程，最后检查 test_counter 是否正确
// 如果自旋锁工作正常，test_counter 应该 = 线程数 * 10000
```

这个测试虽然简单，但如果运行多次没有出现错误，可以说明自旋锁基本正常工作。更完整的测试需要专门的并发测试框架。

## 到这里我们完成了什么

让我们回顾一下这篇文章的内容。我们实现了完整的自旋锁，包括：

- `spinlock_t` 类型定义
- 基础操作：`spin_lock_init`、`spin_lock`、`spin_unlock`、`spin_trylock`
- 中断安全版本：`spin_lock_irq`、`spin_unlock_irq`、`spin_lock_irqsave`、`spin_unlock_irqrestore`
- Raw 版本：不修改 preempt_count 的原始操作
- 辅助函数：`spin_is_locked`

自旋锁是最简单的同步原语，也是所有其他锁的基础。接下来我们会用自旋锁来实现更复杂的同步原语，比如等待队列和互斥锁。

说实话，自旋锁虽然看起来简单，但正确实现并不容易。中断安全版本的 `irqsave/irqrestore` 尤其容易出错，需要仔细处理中断状态。而且自旋锁的正确使用也有很多陷阱，需要在实践中积累经验。

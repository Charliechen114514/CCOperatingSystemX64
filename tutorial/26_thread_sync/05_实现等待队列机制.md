# 实现等待队列机制 —— 进程阻塞与唤醒

## 前言

在上一篇文章中，我们实现了自旋锁。自旋锁的问题是在等待时占用 CPU，这在短临界区没问题，但在长临界区或需要等待事件的情况下就太浪费了。更好的方式是让等待的进程进入睡眠，让出 CPU 给其他进程，等事件发生时再被唤醒。

等待队列（Wait Queue）就是实现这种机制的基础设施。它维护一个等待某个条件的进程链表，提供 `sleep_on`（睡眠）和 `wake_up`（唤醒）操作。所有可睡眠的同步原语（互斥锁、信号量、条件变量）都会用到等待队列。

这篇文章会实现一个完整的等待队列，包括独占等待和非独占等待，以及中断唤醒支持。

## 第一步——定义等待队列结构

等待队列的核心是一个进程链表，每个节点代表一个正在等待的进程。

```c
/**
 * @file waitqueue.h
 * @brief 等待队列
 * @date 2026-02-18
 */
#pragma once

#include "defines/types.h"
#include "list/list.h"
#include "process/process.h"
#include "sync/spinlock.h"

/* ==============================================================================
 * 等待队列条目
 * ==============================================================================
 */

/**
 * @brief 等待队列条目
 *
 * 每个条目代表一个正在等待的进程
 */
typedef struct wait_queue_entry {
    list_head list;           /* 链表节点 */
    pcb_t* task;             /* 等待的进程 */
    process_state_t old_state;  /* 原始状态（用于恢复） */
    bool exclusive;          /* 是否为独占等待 */
} wait_queue_entry_t;

/**
 * @brief 等待队列头
 *
 * 管理所有等待该队列的进程
 */
typedef struct {
    list_head task_list;     /* 等待进程链表 */
    spinlock_t lock;         /* 保护链表的自旋锁 */
} wait_queue_head_t;

/* ==============================================================================
 * 初始化宏
 * ==============================================================================
 */

#define WAIT_QUEUE_HEAD_INIT(name) { \
    .task_list = LIST_HEAD_INIT(task_list), \
    .lock = SPIN_LOCK_INIT \
}

#define DECLARE_WAIT_QUEUE_HEAD(name) \
    wait_queue_head_t name = WAIT_QUEUE_HEAD_INIT(name)

/* ==============================================================================
 * 初始化函数
 * ==============================================================================
 */

/**
 * @brief 初始化等待队列头
 */
static inline void init_waitqueue_head(wait_queue_head_t* q) {
    INIT_LIST_HEAD(&q->task_list);
    spin_lock_init(&q->lock);
}
```

## 第二步——实现睡眠操作

睡眠操作的基本流程是：把当前进程加入等待队列，设置进程状态为阻塞，调用调度器让出 CPU。

```c
/* ==============================================================================
 * 睡眠操作
 * ==============================================================================
 */

/**
 * @brief 在等待队列上睡眠
 * @param q 等待队列头
 *
 * 当前进程会被加入等待队列并进入睡眠状态，
 * 直到被 wake_up 唤醒
 */
void sleep_on(wait_queue_head_t* q) {
    // 创建等待条目
    wait_queue_entry_t wait;
    wait.task = proc_current();
    wait.exclusive = false;

    // 获取队列锁
    spinlock_flags_t flags;
    spin_lock_irqsave(&q->lock, &flags);

    // 保存原始状态
    wait.old_state = wait.task->state;

    // 加入等待队列
    list_add_tail(&wait.list, &q->task_list);

    // 设置为阻塞状态
    wait.task->state = PROC_BLOCKED;

    // 释放队列锁
    spin_unlock_irqrestore(&q->lock, flags);

    // 调度出去
    schedule();

    // 被唤醒后从这里继续执行
}

/**
 * @brief 可中断的睡眠
 * @param q 等待队列头
 * @return 如果被信号中断返回 true，否则返回 false
 *
 * 与 sleep_on 类似，但可以被信号中断
 */
int sleep_on_interruptible(wait_queue_head_t* q) {
    wait_queue_entry_t wait;
    wait.task = proc_current();
    wait.exclusive = false;

    spinlock_flags_t flags;
    spin_lock_irqsave(&q->lock, &flags);

    wait.old_state = wait.task->state;
    list_add_tail(&wait.list, &q->task_list);
    wait.task->state = PROC_BLOCKED;

    spin_unlock_irqrestore(&q->lock, flags);

    schedule();

    // 检查是否被信号中断
    // （这个实现需要信号系统支持）
    return 0;
}
```

## 第三步——实现唤醒操作

唤醒操作的流程是：遍历等待队列，把等待的进程设置为就绪状态，加入调度器的运行队列。

```c
/* ==============================================================================
 * 唤醒操作
 * ==============================================================================
 */

/**
 * @brief 唤醒等待队列上的一个进程
 * @param q 等待队列头
 * @return 被唤醒的进程数
 */
int wake_up(wait_queue_head_t* q) {
    int woken = 0;

    spinlock_flags_t flags;
    spin_lock_irqsave(&q->lock, &flags);

    // 遍历等待队列
    wait_queue_entry_t* wait, *tmp;
    list_for_each_entry_safe(wait, tmp, &q->task_list, list) {
        // 从队列中移除
        list_del(&wait->list);

        // 设置为就绪状态
        wait->task->state = PROC_READY;

        // 加入调度器运行队列
        schedule_add(wait->task);

        woken++;

        // 只唤醒一个（非独占等待）
        if (!wait->exclusive) {
            break;
        }
    }

    spin_unlock_irqrestore(&q->lock, flags);

    return woken;
}

/**
 * @brief 唤醒等待队列上的所有进程
 * @param q 等待队列头
 * @return 被唤醒的进程数
 */
int wake_up_all(wait_queue_head_t* q) {
    int woken = 0;

    spinlock_flags_t flags;
    spin_lock_irqsave(&q->lock, &flags);

    wait_queue_entry_t* wait, *tmp;
    list_for_each_entry_safe(wait, tmp, &q->task_list, list) {
        list_del(&wait->list);
        wait->task->state = PROC_READY;
        schedule_add(wait->task);
        woken++;
    }

    spin_unlock_irqrestore(&q->lock, flags);

    return woken;
}
```

## 第四步——实现独占等待

独占等待是一种优化：当有多个进程在等待时，唤醒操作只唤醒一个独占等待者，而不是唤醒所有非独占等待者。这在资源有限的情况下很有用，比如只有一个资源可用时，只唤醒一个等待者就够了。

```c
/* ==============================================================================
 * 独占等待
 * ==============================================================================
 */

/**
 * @brief 独占睡眠
 * @param q 等待队列头
 *
 * 与 sleep_on 类似，但标记为独占等待
 */
void sleep_on_exclusive(wait_queue_head_t* q) {
    wait_queue_entry_t wait;
    wait.task = proc_current();
    wait.exclusive = true;  // 独占标记

    spinlock_flags_t flags;
    spin_lock_irqsave(&q->lock, &flags);

    wait.old_state = wait.task->state;
    list_add_tail(&wait.list, &q->task_list);
    wait.task->state = PROC_BLOCKED;

    spin_unlock_irqrestore(&q->lock, flags);

    schedule();
}
```

在 `wake_up` 中，我们检查 `exclusive` 标志。如果遇到独占等待者，唤醒它之后就停止，不再继续唤醒非独占等待者。这样可以避免"惊群效应"（thundering herd），即唤醒太多进程导致资源竞争。

## 使用示例

等待队列通常不直接使用，而是通过更高级的同步原语（如互斥锁、信号量）来间接使用。但这里给一个简单示例：

```c
static wait_queue_head_t wq;

// 初始化
init_waitqueue_head(&wq);

// 生产者：生产数据后唤醒等待者
void producer(void) {
    produce_data();
    wake_up(&wq);  // 唤醒一个等待者
}

// 消费者：等待数据
void consumer(void) {
    while (no_data_available()) {
        sleep_on(&wq);  // 等待数据
    }
    consume_data();
}
```

## 与调度器的交互

等待队列需要和调度器紧密配合。具体来说：

- `schedule()` 函数：选择下一个进程运行
- `schedule_add(pcb_t*)` 函数：把进程加入运行队列
- `proc_current()` 函数：获取当前进程

这些函数应该在进程管理系统中已经实现。如果没有，需要先实现它们。

## 常见陷阱

使用等待队列时有一些需要注意的地方：

**忘记加锁**。修改等待队列时必须加锁，否则多个进程同时修改会破坏链表结构。

**在持有自旋锁时睡眠**。这是死锁的经典场景。持有自旋锁时调用可能睡眠的函数（如 `sleep_on`）会导致死锁，因为等待者永远不会被调度去释放锁。

**唤醒丢失**。如果在 `sleep_on` 加入队列之前就调用了 `wake_up`，唤醒信号会丢失，进程可能永远等不到。解决方法是在加锁状态下检查条件。

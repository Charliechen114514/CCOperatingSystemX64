# 从 0 实现原子操作 —— 所有同步原语的基础

## 前言

在开始实现各种锁和信号量之前，我们需要先解决一个更基础的问题：如何保证一个操作是原子的？如果连这个都做不到，后面所有的同步原语都是空中楼阁。

说实话，原子操作这个概念看起来简单，实际实现起来有很多坑。我第一次实现的时候，天真地以为用 `volatile` 关键字就够了，结果在多核系统上测试时发现了各种诡异的 bug。后来才知道，`volatile` 只是禁止编译器优化，根本不能保证 CPU 级别的原子性。

这篇文章会从零开始实现一个完整的原子操作库。我们会定义 `atomic_t` 类型，实现各种算术操作，实现 CAS（Compare-And-Swap）操作，还会实现内存屏障。这些函数是所有后续同步原语的基础，必须精确无误。

## 第一步——定义 atomic_t 类型

我们的目标是定义一个原子整数类型。最简单的定义就是：

```c
typedef struct {
    volatile int counter;
} atomic_t;
```

这里用 `volatile` 是告诉编译器这个变量可能被意外修改，不要对其进行某些优化。但注意，`volatile` 不能保证原子性，只是让编译器每次都从内存读取值。

我们用结构体而不是直接的 `volatile int`，是为了防止意外的赋值操作。如果写成 `volatile int a`，你可能不小心写成 `a = 5`，这不会是原子操作。但 `atomic_t a; a.counter = 5` 看起来就很可疑，容易发现问题。

创建头文件 `kernel/sync/atomic.h`：

```c
/**
 * @file atomic.h
 * @brief 原子操作
 * @date 2026-02-18
 */
#pragma once

#include "defines/types.h"
#include "stdbool.h"

/* ==============================================================================
 * 原子类型定义
 * ==============================================================================
 */

/**
 * @brief 原子整数类型
 *
 * 使用 volatile 确保编译器不会优化掉访问，
 * 但真正的原子性由下面的原子操作函数保证。
 */
typedef struct {
    volatile int counter;
} atomic_t;

/* ==============================================================================
 * 初始化宏
 * ==============================================================================
 */

/**
 * @brief 静态初始化器
 */
#define ATOMIC_INIT(i) {.counter = (i)}

/**
 * @brief 运行时初始化器
 */
#define ATOMIC_INITIALIZER(i) ((atomic_t)ATOMIC_INIT(i))
```

## 第二步——实现基础读写操作

最简单的原子操作是读和写。在 x86_64 上，对齐的 int 类型读写本身是原子的（硬件保证），但我们还是需要确保内存可见性。

```c
/* ==============================================================================
 * 基础读写操作
 * ==============================================================================
 */

/**
 * @brief 原子读取
 */
static inline int atomic_read(const atomic_t* a) {
    return a->counter;
}

/**
 * @brief 原子写入
 */
static inline void atomic_write(atomic_t* a, int i) {
    a->counter = i;
}
```

你可能问：这不就是普通读写吗？为什么叫"原子"读写？在 x86_64 上，对齐的 int 读写确实是原子的。但我们需要这些函数作为接口，保持代码一致性。而且，如果未来需要加入内存屏障，只需要修改这两个函数即可。

## 第三步——实现算术操作

真正有趣的是算术操作：加、减、增一、减一。这些操作在汇编层面是"读-改-写"三步，不是原子的。我们必须用特殊的指令来保证原子性。

GCC 提供了内置的原子操作函数，我们直接使用它们：

```c
/* ==============================================================================
 * 算术操作
 * ==============================================================================
 */

/**
 * @brief 原子增一
 */
static inline void atomic_inc(atomic_t* a) {
    (void)__atomic_add_fetch(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减一
 */
static inline void atomic_dec(atomic_t* a) {
    (void)__atomic_sub_fetch(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子加
 */
static inline void atomic_add(atomic_t* a, int i) {
    (void)__atomic_add_fetch(&a->counter, i, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减
 */
static inline void atomic_sub(atomic_t* a, int i) {
    (void)__atomic_sub_fetch(&a->counter, i, __ATOMIC_SEQ_CST);
}
```

这里的关键是 `__atomic_add_fetch` 和 `__atomic_sub_fetch`。这是 GCC 的内置函数，会生成带 `lock` 前缀的 x86_64 指令，保证原子性。

`__ATOMIC_SEQ_CST` 是内存顺序参数，表示"顺序一致性"（Sequentially Consistent），是最强的内存顺序保证。对于我们的用途，这个是最安全的选择。

你可能会注意到我们忽略（cast to void）了返回值。`__atomic_add_fetch` 返回操作后的新值，但我们不需要。GCC 提供了另一个函数 `__atomic_fetch_add`，它返回操作前的旧值。你可以根据需要选择。

## 第四步——实现带返回值的算术操作

有时候我们需要知道操作后的值或操作前的值：

```c
/* ==============================================================================
 * 带返回值的算术操作
 * ==============================================================================
 */

/**
 * @brief 原子增一并返回新值
 */
static inline int atomic_inc_return(atomic_t* a) {
    return __atomic_add_fetch(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减一并返回新值
 */
static inline int atomic_dec_return(atomic_t* a) {
    return __atomic_sub_fetch(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子加并返回新值
 */
static inline int atomic_add_return(atomic_t* a, int i) {
    return __atomic_add_fetch(&a->counter, i, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减并返回新值
 */
static inline int atomic_sub_return(atomic_t* a, int i) {
    return __atomic_sub_fetch(&a->counter, i, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子增一并返回旧值
 */
static inline int atomic_fetch_inc(atomic_t* a) {
    return __atomic_fetch_add(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减一并返回旧值
 */
static inline int atomic_fetch_dec(atomic_t* a) {
    return __atomic_fetch_sub(&a->counter, 1, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子加并返回旧值
 */
static inline int atomic_fetch_add(atomic_t* a, int i) {
    return __atomic_fetch_add(&a->counter, i, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子减并返回旧值
 */
static inline int atomic_fetch_sub(atomic_t* a, int i) {
    return __atomic_fetch_sub(&a->counter, i, __ATOMIC_SEQ_CST);
}
```

`_fetch` 版本返回操作前的旧值，`_return` 版本返回操作后的新值。选择哪一个取决于你的需求。

## 第五步——实现条件操作

有些场景需要检查操作结果。比如原子减一后检查是否为零：

```c
/* ==============================================================================
 * 条件操作
 * ==============================================================================
 */

/**
 * @brief 原子减一并测试是否为零
 * @return 如果新值为零返回 true，否则返回 false
 */
static inline bool atomic_dec_and_test(atomic_t* a) {
    return __atomic_sub_fetch(&a->counter, 1, __ATOMIC_SEQ_CST) == 0;
}

/**
 * @brief 原子增一并测试是否为零
 * @return 如果新值为零返回 true，否则返回 false
 */
static inline bool atomic_inc_and_test(atomic_t* a) {
    return __atomic_add_fetch(&a->counter, 1, __ATOMIC_SEQ_CST) == 0;
}

/**
 * @brief 原子减并测试是否为零
 * @return 如果新值为零返回 true，否则返回 false
 */
static inline bool atomic_sub_and_test(atomic_t* a, int i) {
    return __atomic_sub_fetch(&a->counter, i, __ATOMIC_SEQ_CST) == 0;
}
```

这些函数在实现引用计数时非常有用。比如你想在最后一个引用释放时清理资源：

```c
// 释放引用
void put_ref(ref_counted_t* obj) {
    if (atomic_dec_and_test(&obj->refcount)) {
        // 没有引用了，可以释放
        free(obj);
    }
}
```

## 第六步——实现 CAS 操作

CAS（Compare-And-Swap，对比并交换）是最强大的原子操作，可以说是无锁编程的基础。它的语义是：如果当前值等于期望值，就把新值写进去，返回成功；否则返回失败。

```c
/* ==============================================================================
 * CAS 操作
 * ==============================================================================
 */

/**
 * @brief 原子对比并交换
 * @param a 原子变量
 * @param old_val 期望的当前值（指针，会被更新为实际值）
 * @param new_val 要设置的新值
 * @return 如果交换成功返回 true，否则返回 false
 *
 * 注意：如果交换失败，old_val 会被更新为实际的当前值
 */
static inline bool atomic_compare_exchange(atomic_t* a, int* old_val, int new_val) {
    return __atomic_compare_exchange_n(
        &a->counter,
        old_val,
        new_val,
        false,  // weak: false 表示需要强 CAS
        __ATOMIC_SEQ_CST,
        __ATOMIC_SEQ_CST
    );
}

/**
 * @brief 原子交换（简单版本）
 * @param a 原子变量
 * @param old_val 期望的当前值
 * @param new_val 要设置的新值
 * @return 如果交换成功返回 true，否则返回 false
 */
static inline bool atomic_compare_and_swap(atomic_t* a, int old_val, int new_val) {
    return __atomic_compare_exchange_n(
        &a->counter,
        &old_val,
        new_val,
        false,
        __ATOMIC_SEQ_CST,
        __ATOMIC_SEQ_CST
    );
}
```

CAS 操作是实现无锁数据结构的关键。你可以用它来实现无锁队列、无锁栈等。但要注意 ABA 问题，这个我们后面会讨论。

## 第七步——实现交换操作

交换操作是：把新值写入，返回旧值。它和 CAS 类似，但不比较，直接交换：

```c
/* ==============================================================================
 * 交换操作
 * ==============================================================================
 */

/**
 * @brief 原子交换
 * @param a 原子变量
 * @param new_val 要交换的新值
 * @return 交换前的旧值
 */
static inline int atomic_xchg(atomic_t* a, int new_val) {
    int old_val = __atomic_exchange_n(&a->counter, new_val, __ATOMIC_SEQ_CST);
    return old_val;
}
```

## 第八步——实现位操作

原子位操作在实现标志位、位图等场景很有用：

```c
/* ==============================================================================
 * 位操作
 * ==============================================================================
 */

/**
 * @brief 原子或操作
 */
static inline void atomic_or(atomic_t* a, int mask) {
    (void)__atomic_or_fetch(&a->counter, mask, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子与操作
 */
static inline void atomic_and(atomic_t* a, int mask) {
    (void)__atomic_and_fetch(&a->counter, mask, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子异或操作
 */
static inline void atomic_xor(atomic_t* a, int mask) {
    (void)__atomic_xor_fetch(&a->counter, mask, __ATOMIC_SEQ_CST);
}

/**
 * @brief 原子设置位
 */
static inline void atomic_set_bit(atomic_t* a, int nr) {
    atomic_or(a, 1 << nr);
}

/**
 * @brief 原子清除位
 */
static inline void atomic_clear_bit(atomic_t* a, int nr) {
    atomic_and(a, ~(1 << nr));
}

/**
 * @brief 原子测试并设置位
 * @return 如果位之前为 0 返回 true，否则返回 false
 */
static inline bool atomic_test_and_set_bit(atomic_t* a, int nr) {
    int mask = 1 << nr;
    int old = __atomic_fetch_or(&a->counter, mask, __ATOMIC_SEQ_CST);
    return (old & mask) == 0;
}

/**
 * @brief 原子测试并清除位
 * @return 如果位之前为 1 返回 true，否则返回 false
 */
static inline bool atomic_test_and_clear_bit(atomic_t* a, int nr) {
    int mask = 1 << nr;
    int old = __atomic_fetch_and(&a->counter, ~mask, __ATOMIC_SEQ_CST);
    return (old & mask) != 0;
}
```

## 第九步——实现内存屏障

内存屏障（Memory Barrier）是一个非常容易被忽视但又非常重要的概念。现代 CPU 和编译器会进行各种优化：指令重排序、缓存延迟写入等。这些优化在单线程环境下是安全的，但在多线程环境下可能导致问题。

```c
/* ==============================================================================
 * 内存屏障
 * ==============================================================================
 */

/**
 * @brief 编译器屏障
 *
 * 防止编译器重排序指令，但不影响 CPU 级别的重排序
 */
#define barrier() __asm__ __volatile__("" ::: "memory")

/**
 * @brief 完整内存屏障
 *
 * 确保所有内存操作在屏障之前完成
 */
static inline void mb(void) {
    __asm__ __volatile__("mfence" ::: "memory");
}

/**
 * @brief 读内存屏障
 *
 * 确保所有读操作在屏障之前完成
 */
static inline void rmb(void) {
    __asm__ __volatile__("lfence" ::: "memory");
}

/**
 * @brief 写内存屏障
 *
 * 确保所有写操作在屏障之前完成
 */
static inline void wmb(void) {
    __asm__ __volatile__("sfence" ::: "memory");
}

/**
 * @brief SMP 内存屏障（SMP = Symmetric Multi-Processing）
 *
 * 在多处理器系统上，确保所有 CPU 看到一致的内存视图
 */
#define smp_mb() mb()
#define smp_rmb() rmb()
#define smp_wmb() wmb()
```

这些屏障指令的作用：

- `mfence`（Memory Fence）：完整的内存屏障，确保所有读写操作在屏障之前完成，且对其他 CPU 可见
- `lfence`（Load Fence）：读屏障，确保所有读操作完成
- `sfence`（Store Fence）：写屏障，确保所有写操作完成

说实话，内存屏障是个非常深入的话题，涉及 CPU 缓存一致性协议、MESI 协议等。对于我们的实现，使用 `__ATOMIC_SEQ_CST` 内存顺序已经足够，GCC 会自动插入必要的屏障。但在某些特殊场景，你可能需要手动插入屏障，这时候可以用这些函数。

## 第十步——创建源文件

为了让编译器能正确处理这些内联函数，我们需要创建一个 `.c` 文件（即使大部分代码在头文件里）：

```c
/**
 * @file atomic.c
 * @brief 原子操作实现
 * @date 2026-02-18
 */

#include "sync/atomic.h"

// 大部分函数都是内联的，在头文件中定义

```

实际上，因为我们所有函数都是 `static inline`，这个 `.c` 文件几乎是空的。但创建它可以保持项目结构一致。

## ABA 问题简述

在结束这篇文章之前，我想简单提一下 ABA 问题。这是一个使用 CAS 操作时常见的陷阱。

假设你有一个链表，头指针是 A。线程 1 读取了头指针 A，准备用 CAS 把它改成 B。但在线程 1 执行 CAS 之前，线程 2 把头指针从 A 改成 C，又改回 A。当线程 1 执行 CAS 时，它会发现头指针还是 A，于是 CAS 成功。但实际上链表已经变了，线程 1 的操作可能基于一个过时的状态。

这就是 ABA 问题：值从 A 变成 B 又变回 A，CAS 无法检测到这个变化。

解决方法有几个：
- 使用版本号：不仅比较值，还比较版本号
- 使用 Hazard Pointer：安全地回收内存
- 使用 RCU（Read-Copy-Update）：延迟释放

这些方法都比较复杂，在我们的基础实现中不会涉及。但如果你要实现无锁数据结构，一定要考虑 ABA 问题。

## 验证

现在我们可以测试一下原子操作是否正常工作。但说实话，测试原子操作比较困难，因为竞态条件不是每次都能触发。最可靠的方法是使用专门的测试工具或压力测试。

在后续的同步原语实现中，我们会用到这些原子操作。如果原子操作有 bug，会在使用时暴露出来。所以现在我们暂时相信 GCC 的内置函数是正确的。

## 到这里我们完成了什么

让我们回顾一下这篇文章的内容。我们实现了完整的原子操作库，包括：

- `atomic_t` 类型定义
- 基础读写操作（`atomic_read`、`atomic_write`）
- 算术操作（`atomic_inc`、`atomic_dec`、`atomic_add`、`atomic_sub`）
- 带返回值的算术操作（`_return` 和 `_fetch` 版本）
- 条件操作（`atomic_dec_and_test` 等）
- CAS 操作（`atomic_compare_exchange`）
- 交换操作（`atomic_xchg`）
- 位操作（`atomic_or`、`atomic_and`、`atomic_set_bit` 等）
- 内存屏障（`mb`、`rmb`、`wmb`）

这些函数构成了所有同步原语的基础。接下来我们会用它们来实现自旋锁、互斥锁、信号量等高级同步原语。

说实话，原子操作这部分虽然代码量不大，但涉及的概念很多。内存屏障、缓存一致性、指令重排序...每一个都可以写一篇文章。如果你觉得有些地方没完全理解，不用担心，随着我们实现更多的同步原语，你会对它们有更深的认识。

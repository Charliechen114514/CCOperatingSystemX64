# 系统调用集成与调试 —— 用户态接口与常见问题

## 前言

在之前的文章中，我们实现了完整的线程同步系统。但到目前为止，所有功能只能在内核中使用。为了让用户程序也能创建和管理线程，我们需要添加系统调用。

这篇文章会注册线程相关的系统调用，编写用户态测试程序，并讨论常见问题和调优建议。

## 第一步——注册系统调用

在 `kernel/syscall/syscall_numbers.h` 中添加：

```c
#define SYS_THREAD_CREATE    6
#define SYS_THREAD_EXIT      7
#define SYS_THREAD_JOIN      8
#define SYS_THREAD_DETACH    9
```

## 第二步——实现系统调用处理

在 `kernel/syscall/syscall_table.c` 中添加：

```c
// 线程创建
int64_t sys_thread_create(uint64_t entry, uint64_t stack, uint64_t arg) {
    pcb_t* current = proc_current();

    pcb_t* thread = proc_create_user_thread(entry, stack, (void*)arg);
    if (!thread) {
        return -1;
    }

    return thread->pid;
}

// 线程退出
int64_t sys_thread_exit(uint64_t retval) {
    proc_thread_exit((void*)retval);
    return 0;  // 永不返回
}

// 线程 join
int64_t sys_thread_join(int32_t pid, uint64_t retval_ptr) {
    void* retval;
    int result = proc_thread_join(pid, &retval);

    if (result == 0 && retval_ptr != 0) {
        // 把返回值写到用户空间
        copy_to_user((void*)retval_ptr, &retval, sizeof(void*));
    }

    return result;
}

// 线程 detach
int64_t sys_thread_detach(int32_t pid) {
    pcb_t* thread = find_thread_by_pid(proc_current()->tgid, pid);
    if (!thread) {
        return -EINVAL;
    }
    return proc_thread_detach(thread);
}
```

## 第三步——用户态测试程序

```c
// user/thread_test.c

#include <stdio.h>
#include <sys/syscall.h>

// 线程函数
void thread_func(int arg) {
    printf("Thread running with arg: %d\n", arg);
    syscall(SYS_THREAD_EXIT, arg * 2);
}

int main(void) {
    printf("User thread test\n");

    // 创建线程
    int tid = syscall(SYS_THREAD_CREATE, (uint64_t)thread_func, 0, 42);
    if (tid < 0) {
        printf("Failed to create thread\n");
        return 1;
    }

    printf("Thread created with TID: %d\n", tid);

    // 等待线程结束
    uint64_t retval;
    int result = syscall(SYS_THREAD_JOIN, tid, (uint64_t)&retval);

    if (result == 0) {
        printf("Thread exited with retval: %ld\n", retval);
    } else {
        printf("Failed to join thread\n");
    }

    return 0;
}
```

## 常见问题排查

### 死锁

**症状**：系统卡住不动，多个线程互相等待。

**排查方法**：
1. 检查是否所有锁路径都有 unlock
2. 检查锁的获取顺序是否一致
3. 使用调试输出跟踪锁的获取/释放

**预防**：
- 总是按固定顺序获取多个锁
- 使用 trylock 避免循环等待
- 设置超时机制

### 优先级反转

**症状**：高优先级线程响应慢，被低优先级线程阻塞。

**解决**：
- 实现优先级继承：锁持有者继承等待者的优先级
- 使用优先级天花板：获取锁时立即提升优先级

### 忘记释放锁

**症状**：系统逐渐卡住，性能下降。

**排查**：
- 在 lock/unlock 处加日志
- 检查所有 return 路径

**预防**：
```c
// 确保所有路径都释放锁
mutex_lock(&lock);
if (error1) {
    mutex_unlock(&lock);  // 别忘了！
    return;
}
if (error2) {
    mutex_unlock(&lock);  // 别忘了！
    return;
}
mutex_unlock(&lock);
```

## 性能调优

### 锁的粒度

太粗：多个不相关的操作被同一个锁保护，并发度低。

太细：管理多个锁的开销大，容易死锁。

**建议**：根据实际访问模式选择，开始时用粗粒度，发现瓶颈后再细化。

### 自旋锁 vs 互斥锁

| 临界区长度 | 推荐锁 |
|-----------|--------|
| < 1 微秒 | 自旋锁 |
| 1-10 微秒 | 视情况而定 |
| > 10 微秒 | 互斥锁 |

### 快速路径优化

无竞争时应该尽可能快：

```c
void mutex_lock(mutex_t* m) {
    // 快速路径：无竞争
    if (atomic_compare_and_swap(&m->locked, 0, 1) == 0) {
        m->owner = current;
        return;  // 无竞争，直接返回
    }

    // 慢速路径：有竞争
    mutex_lock_slow(m);
}
```

# x86 中断机制详解 —— Stage 13 中断基础实战指南

## 前言

上一篇文章我们讲了为什么要实现中断系统，以及 8259 PIC 的基本原理。现在到了真正深入理解 x86 中断机制的时候了。

说实话，中断机制这块儿的内容比较抽象，很多初学者看到一堆寄存器、栈帧、描述符就头大。我当年也是这样，对着 Intel 手册看了半天，脑子里还是一团浆糊。但别担心，我们会把这些概念拆解开来，一步一步搞清楚。

理解 x86 中断机制是实现中断系统的基础。如果你不知道 CPU 在中断发生时做了什么，不知道栈帧是怎么布局的，那写出来的代码大概率会出问题。所以这篇文章虽然不涉及写代码，但非常重要。

## x86 中断处理流程

让我们先从宏观上理解一下，当中断发生时，整个系统是怎么运作的。

### 完整流程图

```
┌─────────────┐
│  硬件事件    │  (定时器到期、按键按下、CPU 异常...)
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   PIC       │  (仅硬件中断) 优先级仲裁、发送信号给 CPU
└──────┬──────┘
       │ INTR
       ▼
┌─────────────┐
│   CPU       │  检查中断标志(IF)、读取中断向量
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   IDT       │  根据向量号查找处理函数地址
└──────┬──────┘
       │
       ▼
┌─────────────────────┐
│  保存 CPU 状态        │  自动推送栈帧(SS, RSP, RFLAGS, CS, RIP)
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  跳转到处理函数       │  执行中断处理程序
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  恢复 CPU 状态        │  iretq 指令弹出栈帧
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│  返回被打断的代码     │
└─────────────────────┘
```

### 每一步详解

#### 1. 硬件事件发生

- **硬件中断**：外部设备（定时器、键盘等）通过 IRQ 线向 PIC 发送信号
- **异常**：CPU 执行指令时检测到错误条件（除零、缺页等）

#### 2. PIC 处理（仅硬件中断）

PIC 接收到中断请求后：
- 判断该 IRQ 是否被屏蔽
- 如果没有被屏蔽，向 CPU 的 INTR 引脚发送信号
- 将中断向量号放到数据总线上

#### 3. CPU 响应

CPU 在执行完当前指令后：
- 检查 IF（中断标志）是否为 1
- 如果是，则响应中断
- 从数据总线读取中断向量号

#### 4. 查找 IDT

CPU 使用中断向量号作为索引，在 IDT 中查找对应的门描述符。

#### 5. 保存 CPU 状态

CPU 自动将以下信息推送到栈上：
- **SS**（如果特权级改变）
- **RSP**（如果特权级改变）
- **RFLAGS**
- **CS**
- **RIP**
- **Error Code**（仅部分异常）

#### 6. 跳转到处理函数

CPU 从 IDT 条目中读取处理函数地址，跳转执行。

#### 7. 返回

处理函数执行完毕后，使用 `iretq` 指令恢复 CPU 状态并返回。

## IDT 条目结构

IDT 条目（门描述符）是整个中断机制的核心。x86_64 模式下，每个 IDT 条目是 16 字节。

### 结构布局

```
┌─────────────────────────────────────────────────────────────────┐
│ IDT Entry (16 bytes)                                            │
├─────────────────────────────────────────────────────────────────┤
│ Bytes 0-1   │ Offset Low  (handler address bits 0-15)          │
│ Bytes 2-3   │ Segment Selector (code segment)                   │
│ Byte 4      │ IST (bits 0-2) | Zero (bits 3-7)                 │
│ Byte 5      │ Type Attributes                                  │
│ Bytes 6-7   │ Offset Middle (handler address bits 16-31)       │
│ Bytes 8-11  │ Offset High (handler address bits 32-63)         │
│ Bytes 12-15 │ Reserved (must be 0)                             │
└─────────────────────────────────────────────────────────────────┘
```

### C 语言结构体表示

```c
typedef struct PACKED {
    uint16_t offset_low;       // Handler 地址 bits 0-15
    uint16_t segment_selector; // 代码段选择子
    uint8_t  ist;              // IST 偏移
    uint8_t  type_attr;        // 类型属性
    uint16_t offset_middle;    // Handler 地址 bits 16-31
    uint32_t offset_high;      // Handler 地址 bits 32-63
    uint32_t reserved;         // 保留（必须为 0）
} idt_entry_t;
```

### 字段详解

#### offset_low/middle/high

这三个字段组合起来形成处理函数的 64 位地址：

```
handler_address = (offset_high << 32) | (offset_middle << 16) | offset_low
```

#### segment_selector

代码段选择子，指向 GDT 中的代码段描述符。对于我们的内核，这个值通常是 0x08（第一个代码段）。

#### ist

中断栈表（IST）偏移，用于特殊栈切换。在我们的实现中设置为 0。

#### type_attr

类型属性字节，包含：

| 位 | 字段 | 说明 |
|----|------|------|
| 7 | Present | 描述符是否有效（1 = 有效） |
| 6-5 | DPL | 描述符特权级（0 = 内核，3 = 用户） |
| 4 | Storage Segment | 必须为 0 |
| 3-0 | Type | 门类型（0xE = 中断门，0xF = 陷阱门） |

### 常用属性组合

```c
// 内核中断门（最常用）
#define IDT_KERNEL_INTERRUPT_GATE 0x8E

// 用户中断门（用于系统调用）
#define IDT_USER_INTERRUPT_GATE 0xEE

// 内核陷阱门
#define IDT_KERNEL_TRAP_GATE 0x8F
```

## 中断栈帧

当中断发生时，CPU 会自动推送一个栈帧到栈上。理解这个结构非常重要，因为我们的中断处理函数需要读取这些信息。

### 栈帧结构

```c
typedef struct PACKED {
    uint64_t error_code;      // 错误码（仅部分异常）
    uint64_t rip;             // 返回地址
    uint64_t cs;              // 代码段选择子
    uint64_t rflags;          // RFLAGS 寄存器
    uint64_t rsp;             // 栈指针
    uint64_t ss;              // 栈段选择子（仅特权级改变时）
} interrupt_frame_t;
```

### 栈布局图示

```
高地址
    +------------------+
    |   SS (可选)      │  ← 仅当特权级改变时推送
    +------------------+
    |   RSP (可选)     │
    +------------------+
    |   RFLAGS         │
    +------------------+
    |   CS             │
    +------------------+
    |   RIP            │  ← 被打断的代码会从这里继续执行
    +------------------+
    |   Error Code     │  ← 仅部分异常推送（如 #PF, #GP）
    +------------------+
低地址
```

### Error Code 字段

不是所有异常都会推送错误码。有错误码的异常包括：

| 向量 | 异常 | 错误码含义 |
|------|------|-----------|
| 8 | Double Fault (#DF) | 始终为 0 |
| 10 | Invalid TSS (#TS) | TSS 选择子等 |
| 11 | Segment Not Present (#NP) | 段选择子 |
| 12 | Stack-Segment Fault (#SS) | 错误码标识 |
| 13 | General Protection (#GP) | 段选择子或 0 |
| 14 | Page Fault (#PF) | 页错误原因 |
| 17 | Alignment Check (#AC) | 地址 |
| 20 | Control Protection (#CP) | 错误码 |

对于没有错误码的异常（以及所有 IRQ），我们的汇编 stub 会推送一个 dummy 值（0），保证栈布局一致。

## CPU 异常向量表

x86 CPU 定义了 32 个异常向量（0-31），这些是保留给 CPU 使用的。

### 完整列表

| 向量 | 名称 | 缩写 | 是否有错误码 | 说明 |
|------|------|------|-------------|------|
| 0 | Divide Error | #DE | 无 | 除法错误 |
| 1 | Debug | #DB | 有 | 调试异常 |
| 2 | Non-Maskable Interrupt | NMI | 无 | 不可屏蔽中断 |
| 3 | Breakpoint | #BP | 无 | 断点（INT3 指令） |
| 4 | Overflow | #OF | 无 | 溢出（INTO 指令） |
| 5 | BOUND Range Exceeded | #BR | 无 | BOUND 指令越界 |
| 6 | Invalid Opcode | #UD | 无 | 无效操作码 |
| 7 | Device Not Available | #NM | 无 | 设备不可用（FPU/MMX） |
| 8 | Double Fault | #DF | 有（始终为0） | 双重故障 |
| 9 | Coprocessor Segment Overrun | #CSO | 无 | 协处理器段越界（废弃） |
| 10 | Invalid TSS | #TS | 有 | 无效 TSS |
| 11 | Segment Not Present | #NP | 有 | 段不存在 |
| 12 | Stack-Segment Fault | #SS | 有 | 栈段错误 |
| 13 | General Protection Fault | #GP | 有 | 通用保护错误 |
| 14 | Page Fault | #PF | 有 | 页错误 |
| 15 | x87 FPU Error | #MF | 无 | x87 FPU 错误 |
| 16 | Alignment Check | #AC | 有 | 对齐检查 |
| 17 | Machine Check | #MC | 无 | 机器检查 |
| 18 | SIMD FP Exception | #XM | 无 | SIMD 浮点异常 |
| 19 | Virtualization Exception | #VE | 无 | 虚拟化异常 |
| 20 | Control Protection | #CP | 有 | 控制保护异常 |
| 21-31 | Reserved | - | - | 保留 |

### 常见异常详解

#### Divide Error (#DE)

```c
int a = 10;
int b = 0;
int c = a / b;  // 触发 #DE
```

#### Page Fault (#PF）

当访问无效内存地址时触发：

```
[ERROR] Vector: 14 - Page Fault (#PF)
[ERROR] Error Code: 0x... (包含错误原因)
[ERROR] CR2: 0x... (触发异常的地址)
```

错误码格式：
- Bit 0: 0 = 页不存在, 1 = 访问违规
- Bit 1: 0 = 读操作, 1 = 写操作
- Bit 2: 0 = 内核模式, 1 = 用户模式

#### General Protection Fault (#GP)

最常见的异常，可能由以下原因触发：
- 段限违规
- 特权级违规
- 访问 I/O 端口时权限不足
- 加载无效的段选择子

## 中断门 vs 陷阱门

IDT 有两种主要的门类型：中断门和陷阱门。

### 中断门（Interrupt Gate, Type = 0xE）

- 进入时自动禁用中断（IF = 0）
- 处理函数执行期间中断被屏蔽
- 适用于大多数中断处理

### 陷阱门（Trap Gate, Type = 0xF）

- 保持中断状态不变
- 处理函数执行期间中断仍然可以触发
- 适用于需要嵌套中断的场景

### 我们的选择

对于内核异常处理，我们使用**中断门**，因为：
1. 异常处理通常需要快速完成
2. 避免复杂的嵌套情况
3. 简化实现

对于系统调用（未来），我们会使用**陷阱门**，因为系统调用处理程序可能会执行较长时间。

## 数据结构定义

现在我们可以开始定义我们的数据结构了。这些定义会放在 `idt_constants.h` 和 `idt.h` 中。

### 中断帧结构体

```c
typedef struct PACKED {
    uint64_t error_code;      // 错误码
    uint64_t rip;             // 指令指针
    uint64_t cs;              // 代码段
    uint64_t rflags;          // RFLAGS 寄存器
    uint64_t rsp;             // 栈指针
    uint64_t ss;              // 栈段
} interrupt_frame_t;
```

### IDT 条目结构体

```c
typedef struct PACKED {
    uint16_t offset_low;       // Handler 地址 bits 0-15
    uint16_t segment_selector; // 代码段选择子
    uint8_t  ist;              // IST 偏移
    uint8_t  type_attr;        // 类型属性
    uint16_t offset_middle;    // Handler 地址 bits 16-31
    uint32_t offset_high;      // Handler 地址 bits 32-63
    uint32_t reserved;         // 保留（必须为 0）
} idt_entry_t;
```

### IDT 指针结构体

```c
typedef struct PACKED {
    uint16_t limit;    // IDT 大小（字节数 - 1）
    uint64_t base;     // IDT 基地址
} __attribute__((packed)) idt_ptr_t;
```

这个结构体用于 `lidt` 指令，告诉 CPU IDT 在哪里以及有多大。

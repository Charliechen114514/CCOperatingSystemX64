# int 0x80 向后兼容 —— Stage 20 系统调用框架实战指南（六）

## 前言

在之前的几篇文章里，我们专注于实现现代的 syscall/sysret 机制。但如果你看过 Linux 的历史，就知道在很长一段时间里，系统调用是通过 int 0x80 软中断实现的。很多老程序、测试工具、甚至教学材料仍然使用这种方式。

这篇文章我们要实现 int 0x80 的向后兼容支持。说实话，这部分代码比 syscall 入口要复杂一些，因为 int 0x80 使用 i386 的调用约定，而我们需要转换为 AMD64 的约定。但别担心，我们会一步步搞定。

---

## 为什么要支持 int 0x80

你可能疑惑：既然有了更快的 syscall 指令，为什么还要支持旧的 int 0x80？有几个原因：

**兼容性**。很多现有的代码、测试工具、教学材料使用 int 0x80。如果我们不支持，这些东西就不能在我们的内核上运行。

**调试方便**。int 0x80 的调用约定更简单，更容易在调试器中手动构造。对于早期开发和调试，int 0x80 有时更方便。

**学习价值**。理解 int 0x80 的工作原理，有助于深入理解中断机制和系统调用历史。

当然，int 0x80 会比 syscall 慢一些（需要完整的中断处理流程），但对于大多数用途来说，这个差异可以忽略。

---

## int 0x80 与 syscall 的区别

首先让我们对比一下 int 0x80 和 syscall 的区别：

**触发方式**：
- syscall：专用指令，CPU 识别后执行特殊操作
- int 0x80：软中断，触发中断向量 0x80 的处理函数

**寄存器保存**：
- syscall：只保存 RCX 和 R11
- int 0x80：保存完整的中断帧（SS, RSP, RFLAGS, CS, RIP）

**调用约定**：
- syscall：使用 AMD64 约定（RDI, RSI, RDX, R10, R8, R9）
- int 0x80：使用 i386 约定（EBX, ECX, EDX, ESI, EDI, EBP）

**返回方式**：
- syscall：sysretq 指令
- int 0x80：iretq 指令

---

## i386 系统调用约定

int 0x80 使用 i386 的系统调用约定，这在 32 位时代是标准的：

| 寄存器 | 用途 |
|--------|------|
| EAX | 系统调用号 |
| EBX | 第 1 个参数 |
| ECX | 第 2 个参数 |
| EDX | 第 3 个参数 |
| ESI | 第 4 个参数 |
| EDI | 第 5 个参数 |
| EBP | 第 6 个参数 |

注意在 64 位模式下，这些寄存器的低 32 位仍然有效（EAX 是 RAX 的低 32 位，等等）。所以我们可以直接访问这些 32 位寄存器。

---

## int0x80_handler 的实现

现在让我们实现 `int0x80_handler`。打开 `syscall.asm`，在文件末尾添加以下代码：

```asm
; ============================================================================
; int 0x80 Entry Point (Legacy Interface)
; ============================================================================

global int0x80_handler
extern syscall_dispatch_int80

int0x80_handler:
    ; At this point, CPU has pushed an interrupt frame:
    ; [RSP]    = SS (ignored in long mode)
    ; [RSP+8]  = old RSP
    ; [RSP+16] = old RFLAGS
    ; [RSP+24] = old CS
    ; [RSP+32] = old RIP
    ; Total: 40 bytes

    ; -------------------------------------------------------------------------
    ; Step 1: Save all general-purpose registers
    ; -------------------------------------------------------------------------
    push rax                ; Save syscall number (EAX)
    push rbx                ; Save arg1 (EBX)
    push rcx                ; Save arg2 (ECX)
    push rdx                ; Save arg3 (EDX)
    push rsi                ; Save arg4 (ESI)
    push rdi                ; Save arg5 (EDI)
    push rbp                ; Save arg6 (EBP)
    push r8
    push r9
    push r10
    push r11
    push r12
    push r13
    push r14
    push r15

    ; -------------------------------------------------------------------------
    ; Step 2: Load kernel data segments
    ; -------------------------------------------------------------------------
    mov ax, 0x10            ; GDT_KERNEL_DATA
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    ; -------------------------------------------------------------------------
    ; Step 3: Align stack to 16 bytes
    ; -------------------------------------------------------------------------
    ; We pushed 15 registers = 120 bytes (120 mod 16 = 8)
    ; Plus 40 bytes interrupt frame = 160 bytes (160 mod 16 = 0)
    ; Wait, let's recalculate:
    ; 15 pushes * 8 = 120 bytes
    ; Interrupt frame = 40 bytes
    ; Total = 160 bytes, which IS 16-byte aligned!
    ; So we DON'T need to push padding here
    ; But to be safe and consistent, let's add padding anyway
    push qword 0

    ; -------------------------------------------------------------------------
    ; Step 4: Construct syscall_frame_int80_t on stack
    ; -------------------------------------------------------------------------
    sub rsp, 56             ; Allocate syscall_frame_int80_t

    ; i386 convention (int 0x80): EBX, ECX, EDX, ESI, EDI, EBP
    ; We need to convert to: RDI, RSI, RDX, R10, R8, R9

    ; Read original registers from saved positions
    mov rdi, [rsp+64+8*1]   ; RBX = arg1 → RDI
    mov rsi, [rsp+64+8*2]   ; RCX = arg2 → RSI
    mov rdx, [rsp+64+8*3]   ; RDX = arg3 (same)
    mov rcx, [rsp+64+8*4]   ; RSI = arg4 → RCX (temp)
    mov r8,  [rsp+64+8*5]   ; RDI = arg5 → R8
    mov r9,  [rsp+64+8*6]   ; RBP = arg6 → R9

    ; Now construct the frame
    mov rax, [rsp+64+8*0]   ; RAX = syscall number
    mov qword [rsp], rax    ; syscall_number

    mov qword [rsp+8], rdi  ; arg0 (from EBX)
    mov qword [rsp+16], rsi ; arg1 (from ECX)
    mov qword [rsp+24], rdx ; arg2 (from EDX)
    mov qword [rsp+32], rcx ; arg3 (from ESI)
    mov qword [rsp+40], r8  ; arg4 (from EDI)
    mov qword [rsp+48], r9  ; arg5 (from EBP)

    ; -------------------------------------------------------------------------
    ; Step 5: Call C dispatcher (int80 version)
    ; -------------------------------------------------------------------------
    ; int64_t syscall_dispatch_int80(syscall_frame_int80_t* frame)
    mov rdi, rsp            ; RDI = frame pointer
    call syscall_dispatch_int80

    ; Return value in RAX

    ; -------------------------------------------------------------------------
    ; Step 6: Clean up frame
    ; -------------------------------------------------------------------------
    add rsp, 56             ; Deallocate frame

    ; -------------------------------------------------------------------------
    ; Step 7: Clean up alignment
    ; -------------------------------------------------------------------------
    add rsp, 8              ; Remove padding

    ; -------------------------------------------------------------------------
    ; Step 8: Restore saved registers
    ; -------------------------------------------------------------------------
    pop r15
    pop r14
    pop r13
    pop r12
    pop r11
    pop r10
    pop r9
    pop r8
    pop rbp
    pop rdi
    pop rsi
    pop rdx
    pop rcx
    pop rbx
    pop rax                 ; Restore original RAX

    ; -------------------------------------------------------------------------
    ; Step 9: Return from interrupt
    ; -------------------------------------------------------------------------
    ; RAX contains return value
    iretq
```

这段代码做了几件事：

第一，我们保存了所有通用寄存器。注意这里我们保存了 R8-R15，虽然 i386 约定不用这些寄存器，但我们需要保存完整的 CPU 状态。

第二，我们从保存的寄存器中读取 i386 约定的参数（EBX, ECX, EDX, ESI, EDI, EBP），然后转换为 AMD64 约定（RDI, RSI, RDX, RCX, R8, R9）。注意这里用 RCX 作为临时寄存器，因为最终 arg3 需要放到 R10 的位置。

第三，我们构造了 `syscall_frame_int80_t` 结构。这个结构包含所有 6 个参数，不像 `syscall_frame_t` 那样把 arg5 单独处理。

第四，我们调用了 `syscall_dispatch_int80`，这是专门为 int 0x80 设计的 C 分发器。

---

## 实现 syscall_dispatch_int80

现在让我们实现 C 分发器。打开 `syscall.c`，在文件末尾添加：

```c
int64_t syscall_dispatch_int80(syscall_frame_int80_t* frame) {
    /* Convert to regular frame and dispatch */
    syscall_frame_t regular_frame;
    regular_frame.syscall_number = frame->syscall_number;
    regular_frame.arg0 = frame->arg0;
    regular_frame.arg1 = frame->arg1;
    regular_frame.arg2 = frame->arg2;
    regular_frame.arg3 = frame->arg3;
    regular_frame.arg4 = frame->arg4;

    /* arg5 is passed separately to syscall_dispatch */
    return syscall_dispatch(&regular_frame, frame->arg5);
}
```

这个函数很简单：它把 `syscall_frame_int80_t` 转换为 `syscall_frame_t`，然后调用标准的 `syscall_dispatch` 函数。这样我们只需要维护一个分发逻辑，int 0x80 和 syscall 共用。

## IDT 注册

int 0x80 是一个软中断，需要在 IDT 中注册。我们之前在 `syscall_init()` 中已经做了这件事：

```c
/* Register int 0x80 as fallback (vector 128, after IRQ range) */
extern void int0x80_handler(void);
idt_set_gate(128, (uint64_t)int0x80_handler,
             IDT_USER_INTERRUPT_GATE, GDT_KERNEL_CODE);
```

这里我们使用向量 128（0x80），这是 Linux 传统的做法。`IDT_USER_INTERRUPT_GATE` 表示这是一个用户态可以调用的中断门（DPL=3）。

---

## 使用 int 0x80 的示例

用户程序可以通过以下方式使用 int 0x80：

```c
/* int 0x80 调用 write(fd, buf, count) */
int fd = 1;  /* stdout */
const char* msg = "Hello via int 0x80!\n";
int len = 19;

int ret;
__asm__ volatile(
    "int $0x80"
    : "=a"(ret)
    : "a"(SYS_WRITE), "b"(fd), "c"(msg), "d"(len)
    : "memory"
);
```

注意这里使用的是 i386 约定：EAX=系统调用号，EBX=第1个参数，ECX=第2个参数，EDX=第3个参数。

# 04 - 回退方案 E801 与 88h

说实话，实现 E801 和 88h 这两个回退方案，就像是在给古董机器做兼容性适配。虽然大多数现代机器都支持 E820，但总有一些边缘情况需要考虑。而且，实现这些回退方案的过程也能帮助我们更深入理解 x86 内存检测的历史。

---

## 我们现在要做什么

在上一篇文档中，我们实现了 E820 内存检测和主检测函数框架。现在我们需要实现两个回退方案：E801 和 88h。

这两个方法虽然不如 E820 详细，但至少能告诉我们系统有多少内存。我们会把它们的结果转换成 E820 格式，这样后续处理就可以统一了。

---

## 第一步 —— 实现 E801 检测

E801 是 1980 年代末推出的简化版内存检测方法。它只返回两个数字：1MB 以下的内存大小和 1MB 以上的内存大小。

### E801 检测函数

在 `boot/bootloader.asm` 中添加 E801 检测函数：

```asm
; ==============================================================================
; detect_memory_e801 - Detect memory using INT 15h/E801
; Input: none
; Output: Two entries stored at E820_STORAGE_ADDR + 1
;         CF=0 on success, CF=1 on failure
; Clobbers: AX, BX, CX, DX
bits 16
detect_memory_e801:
    pusha

    ; === Call INT 15h/E801 ===
    mov ax, 0xe801
    int 0x15

    ; Check CF
    jc .e801_error

    ; E801 succeeded - create two E820 entries manually
    ; Layout: [method (1)][count (2)][entries...]
    ; Entries start at E820_STORAGE_ADDR + 3
    mov di, E820_STORAGE_ADDR + 3

    ; --- Entry 1: Memory between 0 and 1MB ---
    ; Base = 0
    mov dword [di], 0          ; Base low
    mov dword [di+4], 0        ; Base high

    ; Length = AX (in KB), convert to bytes
    movzx eax, ax
    shl eax, 10                ; Multiply by 1024
    mov dword [di+8], eax      ; Length low
    mov dword [di+12], 0       ; Length high

    mov dword [di+16], E820_TYPE_USABLE  ; Type
    mov dword [di+20], 0       ; ACPI attrs

    ; --- Entry 2: Memory above 1MB ---
    add di, 24                 ; Move to next entry

    ; Base = 1MB = 0x100000
    mov dword [di], 0x00100000 ; Base low
    mov dword [di+4], 0        ; Base high

    ; Length: use CX or DX
    ; Check if DX is non-zero (memory above 16MB)
    test dx, dx
    jnz .use_dx

    ; Use CX (KB)
    movzx eax, cx
    shl eax, 10                ; Multiply by 1024
    mov dword [di+8], eax      ; Length low
    mov dword [di+12], 0       ; Length high
    jmp .entry2_done

.use_dx:
    ; Use DX (64KB units)
    movzx eax, dx
    shl eax, 16                ; Multiply by 65536
    mov dword [di+8], eax      ; Length low
    mov dword [di+12], 0       ; Length high

.entry2_done:
    mov dword [di+16], E820_TYPE_USABLE  ; Type
    mov dword [di+20], 0       ; ACPI attrs

    ; Store entry count = 2
    mov word [E820_STORAGE_ADDR + 1], 2

    clc                        ; Clear carry = success
    jmp .e801_exit

.e801_error:
    stc                        ; Set carry = error
.e801_exit:
    popa
    ret
```

### E801 的坑

这里有个容易踩的坑：DX 寄存器的使用。

E801 对于 1MB 以上的内存，用两个寄存器来表示：
- CX：以 KB 为单位
- DX：以 64KB 为单位

但这两个寄存器不是同时使用的。如果内存小于 16MB，只有 CX 有效；如果内存大于 16MB，只有 DX 有效。

所以我们需要检查 DX 是否为 0。如果 DX 不为 0，就使用 DX；否则使用 CX。

另一个坑是，有些老式 BIOS 会在 BX 中重复 1MB 以下的内存大小。所以我们应该使用 AX 而不是 BX。

## 第二步 —— 实现 88h 检测

88h 是最古老的内存检测方法，可以追溯到 1980 年代早期的 PC/AT。它只返回一个数字：从地址 0 开始的连续内存大小。

### 88h 检测函数

在 `boot/bootloader.asm` 中添加 88h 检测函数：

```asm
; ==============================================================================
; detect_memory_88h - Detect memory using INT 15h/AH=88h
; Input: none
; Output: One entry stored at E820_STORAGE_ADDR + 3
;         CF=0 on success, CF=1 on failure
; Clobbers: AX, CX
bits 16
detect_memory_88h:
    pusha

    ; === Call INT 15h/AH=88h ===
    mov ah, 0x88
    int 0x15

    jc .88h_error                 ; CF=1 means error

    ; 88h succeeded - create one E820 entry
    ; Layout: [method (1)][count (2)][entries...]
    ; Entries start at E820_STORAGE_ADDR + 3
    mov di, E820_STORAGE_ADDR + 3

    ; Base = 0
    mov dword [di], 0         ; Base low
    mov dword [di+4], 0       ; Base high

    ; Length = AX (in KB), convert to bytes
    movzx eax, ax
    shl eax, 10                ; Multiply by 1024
    mov dword [di+8], eax     ; Length low
    mov dword [di+12], 0      ; Length high

    mov dword [di+16], E820_TYPE_USABLE  ; Type
    mov dword [di+20], 0      ; ACPI attrs

    ; Store entry count = 1
    mov word [E820_STORAGE_ADDR + 1], 1

    clc                        ; Clear carry = success
    jmp .88h_exit

.88h_error:
    stc                        ; Set carry = error
.88h_exit:
    popa
    ret
```

### 88h 的局限性

88h 有几个严重的局限性，我们需要在后续处理中注意：

1. **最大 64MB**。AX 是 16 位寄存器，最大值是 65535，所以 88h 最多能报告 64MB 内存。

2. **假设从 0 开始连续**。88h 假设从地址 0 到报告的地址都是可用内存，但实际上低 1MB 有很多保留区域。

3. **没有区域信息**。它只给出一个总大小，不告诉我们哪些地址可用、哪些是保留的。

尽管如此，88h 仍然是最广泛支持的内存检测方法。在 E820 和 E801 都不支持的老机器上，88h 是我们最后的希望。

## 第三步 —— 测试回退方案

现在让我们测试一下回退方案是否正常工作。

### 编译和运行

```bash
# 构建
cmake --build build

# 运行 QEMU (强制使用 E801)
qemu-system-x86_64 -m 128M -drive format=raw,file=build/boot.img \
    -nographic -serial mon:stdio
```

### 如何测试 E801

QEMU 默认支持 E820，所以很难直接测试 E801。但我们可以临时修改代码，在 E820 检测后强制设置 CF 标志，让它回退到 E801：

```asm
; 临时修改：强制 E820 失败
call detect_memory_e820
stc                         ; 强制设置 CF，模拟 E820 失败
jc .try_e801
```

### 预期输出

如果 E801 正常工作，你应该能看到：

```
[MEM] Detecting system memory...
[MEM] Method: E801 (two regions)
[MEM] Memory detection complete.
```

## 第四步 —— 理解转换后的 E820 格式

现在我们已经实现了三种检测方法，它们都会将结果转换为 E820 格式存储。让我们理解一下这三种方法转换后的差异。

### E820 原生输出

E820 原生输出可能包含多个条目，每个条目有不同的类型：

```
 #  Base        Length      Type
 0  0x00000000  0x0009FC00  Usable
 1  0x0009FC00  0x00000400  Reserved
 2  0x000E0000  0x00200000  Reserved
 3  0x00100000  0x07F00000  Usable
 4  0x0FE00000  0x00200000  Reserved
 5  0x100000000 0x300000000 Usable
```

### E801 转换输出

E801 转换后只包含两个 Usable 类型的条目：

```
 #  Base        Length      Type
 0  0x00000000  0x000xxxxx  Usable    (1MB 以下)
 1  0x00100000  0x0xxxxxxx  Usable    (1MB 以上)
```

注意这里没有保留区域的信息，所以后续处理时需要手动排除低 1MB 的保留区域。

### 88h 转换输出

88h 转换后只包含一个 Usable 类型的条目：

```
 #  Base        Length      Type
 0  0x00000000  0x0xxxxxxx  Usable
```

这里同样没有保留区域的信息，而且最大只能表示 64MB。

## 第五步 —— 在内核中区分检测方法

内核在读取内存地图时，可以通过第一个字节知道使用的是哪种检测方法。这样就可以根据"质量"来决定如何使用这些信息。

### 检测方法的质量排序

```
E820 (最佳) > E801 (中等) > 88h (最差) > UNKNOWN (失败)
```

- E820：完整的内存地图，包括保留区域信息
- E801：知道 1MB 上下的内存大小，但没有保留区域信息
- 88h：只知道总大小，没有区域信息
- UNKNOWN：完全不知道，需要使用安全的默认值

### 在内核中的使用

内核可以根据检测方法做出不同的决策：

```c
uint8_t method = mem_map[0];

if (method == MEM_METHOD_E820) {
    // 可以安全地使用所有 Usable 类型的区域
} else if (method == MEM_METHOD_E801) {
    // 需要手动排除低 1MB 的保留区域
} else if (method == MEM_METHOD_88H) {
    // 需要更加保守，从 1MB 以上开始使用
} else {
    // 使用最保守的默认值
}
```

## 常见问题

### Q: 为什么 E801 的条目数是 2？

A: 因为 E801 只告诉我们两个信息：1MB 以下的内存大小和 1MB 以上的内存大小。所以转换成 E820 格式后就是两个条目。

### Q: 为什么 88h 的条目数是 1？

A: 因为 88h 只返回一个总大小，转换成 E820 格式后就是一个从 0 开始的大条目。

### Q: 如果 E801 返回的内存大小是 0 怎么办？

A: 这种情况说明检测失败或者系统真的没有内存。但 0 是一个非法值，我们应该把它当作检测失败处理。

### Q: 如果 88h 返回的内存大小小于 640KB 怎么办？

A: 这可能说明系统配置有问题。但我们应该相信 BIOS 的返回值，只是在使用时要注意保守一些。

## 到这里我们完成了什么

很好，到这里我们已经完成了三个内存检测方法的实现：

1. **E820 检测** - 最详细的内存地图，支持多种内存类型
2. **E801 检测** - 简化版，知道 1MB 上下的内存大小
3. **88h 检测** - 最古老的方法，只知道总大小

我们还实现了三级回退策略：E820 → E801 → 88h → 失败。这确保了最大兼容性，同时在新机器上获得最详细的内存信息。

所有方法都会将结果转换为统一的 E820 格式，方便后续处理。

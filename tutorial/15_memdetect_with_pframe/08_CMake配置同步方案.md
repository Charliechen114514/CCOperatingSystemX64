# 08 - CMake 配置同步方案

说实话，让汇编和 C 代码共享常量定义是个挺头疼的问题。Bootloader 是汇编写的，内核是 C 写的，它们需要知道相同的内存配置值。如果分别在两个地方定义，迟早会出问题 —— 修改了一个忘记修改另一个，然后就是各种莫名其妙的 bug。

---

## 我们现在要做什么

我们需要实现一个配置同步方案，让 Bootloader 和内核能够共享相同的常量定义。具体来说，我们会使用 CMake 的 `configure_file` 功能来生成 C 头文件和汇编 INC 文件。

这包括：
1. 创建配置模板文件
2. 使用 CMake 生成配置文件
3. 在 Bootloader 和内核中包含生成的配置
4. 使用验证脚本检查配置安全性

---

## 第一步 —— 理解问题

Bootloader 和内核需要共享以下配置：

| 配置项 | Bootloader 用途 | 内核 用途 |
|--------|-----------------|-----------|
| E820_STORAGE_ADDR | 存储内存地图的地址 | 读取内存地图的地址 |
| E820_MAX_ENTRIES | 限制条目数量 | 限制条目数量 |
| PAGE_SIZE | 页大小（计算帧号） | 页大小（计算帧号） |
| PFRAME_MIN_ALLOC_BASE | 最小分配基址 | 最小分配基址 |

如果这些值在两个地方定义，就可能出现不一致的问题。比如我们修改了 `E820_STORAGE_ADDR` 但只修改了汇编部分，内核就会去错误的地址读取内存地图。

---

## 第二步 —— 创建配置模板

我们使用 CMake 的模板语法来创建配置文件。模板文件使用 `@variable@` 作为占位符，CMake 会在配置时将它们替换成实际值。

### 创建 C 头文件模板 `cmake/MemConfig.h.in`

这个模板生成内核使用的 C 头文件：

```c
// clang-format off
/* ==============================================================================
 * CCOS - Memory Detection Constants (Kernel Header)
 * ==============================================================================
 * This file is AUTO-GENERATED by CMake from cmake/MemConfig.h.in
 * DO NOT EDIT DIRECTLY - Modify cmake/MemConfig.cmake and reconfigure
 * ==============================================================================
 */

#ifndef CCOS_KERNEL_MM_MEM_CONFIG_H
#define CCOS_KERNEL_MM_MEM_CONFIG_H

#include "defines/types.h"

/* ==============================================================================
 * Memory Configuration Constants
 * ==============================================================================
 * NOTE: E820_STORAGE_ADDR must match the value used by the bootloader
 * Current value: 0x@E820_STORAGE_ADDR_HEX@
 *
 * Memory Layout Constraints:
 *   - Bootloader code: 0x7C00 - 0x8C00 (~4KB)
 *   - Page tables: 0x9000 - 0xBFFF
 *   - E820 storage: 0x@E820_STORAGE_ADDR_HEX@
 * ==============================================================================
 */
#define E820_STORAGE_ADDR  0x@E820_STORAGE_ADDR_HEX@
#define E820_MAX_ENTRIES   @E820_MAX_ENTRIES@

#endif /* CCOS_KERNEL_MM_MEM_CONFIG_H */
```

注意文件顶部的警告：这是一个自动生成的文件，不应该直接编辑。如果要修改配置，应该修改 CMake 文件然后重新配置。

### 创建汇编 INC 文件模板 `cmake/MemConfig.inc.in`

这个模板生成 Bootloader 使用的汇编包含文件：

```asm
; ==============================================================================
; CCOS - Memory Detection Constants (Bootloader Include)
; ==============================================================================
; This file is AUTO-GENERATED by CMake from cmake/MemConfig.inc.in
; DO NOT EDIT DIRECTLY - Modify cmake/MemConfig.cmake and reconfigure
; ==============================================================================

; E820 Memory Storage Address
%define E820_STORAGE_ADDR   0x@E820_STORAGE_ADDR_HEX@

; Maximum number of E820 entries
%define E820_MAX_ENTRIES    @E820_MAX_ENTRIES@

; Entry size (fixed by BIOS spec)
%define E820_ENTRY_SIZE     24
```

## 第三步 —— 创建 CMake 配置脚本

现在我们创建 CMake 脚本来生成这些配置文件。

### 创建 `cmake/MemConfig.cmake`

```cmake
# ==============================================================================
# CCOS - Memory Configuration Generator
# ==============================================================================
# This script generates consistent memory configuration files for both
# bootloader (NASM .inc) and kernel (C .h) from a single source of truth.
# ==============================================================================

# ============================================================================
# Memory Configuration Options (Single Source of Truth)
# ============================================================================
# Modify these values to change the memory layout. Both bootloader and kernel
# will automatically use the new values after re-running CMake.

# E820 Storage Address - Where bootloader stores memory map for kernel
# Must not overlap with:
#   - Bootloader code (0x7C00 - 0x8C00, ~4KB)
#   - Page table areas (0x9000-0xBFFF)
# Default: 0x6000 (24KB, safely before bootloader)
set(E820_STORAGE_ADDR_DEFAULT "0x6000" CACHE STRING
    "E820 memory map storage address (hex format, e.g., 0x6000)")

# Maximum number of E820 memory entries
# Default: 128 entries (128 * 24 bytes = ~3KB, fits in 4KB space)
set(E820_MAX_ENTRIES_DEFAULT "128" CACHE STRING
    "Maximum number of E820 memory entries")

# Validate E820_STORAGE_ADDR format
if(NOT E820_STORAGE_ADDR_DEFAULT MATCHES "^0x[0-9A-Fa-f]+$")
    message(FATAL_ERROR "E820_STORAGE_ADDR must be in hex format (e.g., 0x6000)")
endif()

# ============================================================================
# Convert hex address to decimal and string formats for different targets
# ============================================================================
# Strip "0x" prefix for numeric processing
string(REGEX REPLACE "^0x" "" E820_ADDR_HEX_ONLY "${E820_STORAGE_ADDR_DEFAULT}")

# Calculate decimal value (for potential future use)
math(EXPR E820_ADDR_DECIMAL "0x${E820_ADDR_HEX_ONLY}")

# Set variables for @ substitution in template files
set(E820_STORAGE_ADDR_HEX "${E820_ADDR_HEX_ONLY}")
set(E820_MAX_ENTRIES "${E820_MAX_ENTRIES_DEFAULT}")

# ============================================================================
# Generate NASM Include File (for Bootloader)
# ============================================================================
configure_file(
    ${CMAKE_SOURCE_DIR}/cmake/MemConfig.inc.in
    ${CMAKE_BINARY_DIR}/mem_detect_constants.inc
    @ONLY
)

# ============================================================================
# Generate C Header File (for Kernel)
# ============================================================================
configure_file(
    ${CMAKE_SOURCE_DIR}/cmake/MemConfig.h.in
    ${CMAKE_BINARY_DIR}/include/mem_config.h
    @ONLY
)

# ============================================================================
# Validate Configuration with Python Script
# ============================================================================
# Run the validation script to check for memory conflicts
execute_process(
    COMMAND ${PYTHON} ${CMAKE_SOURCE_DIR}/scripts/validate_e820_config.py
        ${E820_STORAGE_ADDR_DEFAULT}
        ${E820_MAX_ENTRIES_DEFAULT}
        -q
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
    RESULT_VARIABLE VALIDATION_RESULT
    OUTPUT_VARIABLE VALIDATION_OUTPUT
    ERROR_VARIABLE VALIDATION_ERROR
)

# If validation failed, show output and error
if(NOT VALIDATION_RESULT EQUAL 0)
    message(WARNING "E820 configuration validation failed:")
    message(WARNING "${VALIDATION_OUTPUT}")
    if(VALIDATION_ERROR)
        message(WARNING "${VALIDATION_ERROR}")
    endif()
    message(WARNING "To see safe alternatives, run:")
    message(WARNING "  cd ${CMAKE_SOURCE_DIR}")
    message(WARNING "  python3 scripts/validate_e820_config.py ${E820_STORAGE_ADDR_DEFAULT} ${E820_MAX_ENTRIES_DEFAULT}")
endif()

# ============================================================================
# Configuration Summary
# ============================================================================
message(STATUS "Memory Configuration:")
message(STATUS "  E820 Storage Address: ${E820_STORAGE_ADDR_DEFAULT}")
message(STATUS "  E820 Max Entries:     ${E820_MAX_ENTRIES_DEFAULT}")
message(STATUS "  Generated files:")
message(STATUS "    - ${CMAKE_BINARY_DIR}/mem_detect_constants.inc (bootloader)")
message(STATUS "    - ${CMAKE_BINARY_DIR}/include/mem_config.h (kernel)")
if(NOT VALIDATION_RESULT EQUAL 0)
    message(STATUS "  WARNING: Configuration validation failed - see warnings above")
endif()
```

### 在主 CMakeLists.txt 中包含

在根目录的 `CMakeLists.txt` 中添加：

```cmake
# ============================================================================
# Memory Configuration
# ============================================================================
include(cmake/MemConfig.cmake)
```

## 第四步 —— 在 Bootloader 中使用生成的配置

现在我们需要在 Bootloader 中包含生成的配置文件。

### 修改 `boot/bootloader.asm`

在 Bootloader 的开头添加：

```asm
; ==============================================================================
; Memory Detection Configuration (Auto-Generated)
; ==============================================================================
; This file is generated by CMake from cmake/MemConfig.inc.in
%include "mem_detect_constants.inc"
```

### 移除硬编码的定义

删除 Bootloader 中之前硬编码的这些定义：

```asm
; 删除这些硬编码的定义
; %define E820_STORAGE_ADDR   0x6000
; %define E820_MAX_ENTRIES    128
```

因为我们现在从生成的文件中获取这些值。

---

## 第五步 —— 在内核中使用生成的配置

同样，内核也需要使用生成的配置文件。

### 修改 `kernel/mm/memory_detect/e820.h`

在内核头文件中添加：

```c
/* ==============================================================================
 * Memory Configuration (Auto-Generated)
 * ==============================================================================
 * This file is generated by CMake from cmake/MemConfig.h.in
 */
#include "mem_config.h"
```

或者直接在源文件中包含：

```c
/* In e820.c */
#include "mem_config.h"
```

### 更新 CMakeLists.txt

确保内核的 include 路径包含生成的头文件目录：

```cmake
# In kernel/CMakeLists.txt or appropriate place
target_include_directories(kernel PUBLIC
    ${CMAKE_BINARY_DIR}/include  # For generated headers
    ...
)
```

## 第六步 —— 验证脚本

我们还有一个 Python 验证脚本，用于检查配置的安全性。这个脚本位于 `scripts/validate_e820_config.py`。

### 验证脚本的功能

这个脚本会检查：

1. **地址冲突** - E820 存储地址是否与其他组件冲突
2. **对齐问题** - 地址是否正确对齐
3. **空间足够** - 是否有足够空间存储所有条目
4. **实模式限制** - 地址是否在实模式可访问范围内

### 运行验证脚本

```bash
# 使用默认配置
python3 scripts/validate_e820_config.py

# 使用自定义配置
python3 scripts/validate_e820_config.py 0x6000 128

# 只显示错误（静默模式）
python3 scripts/validate_e820_config.py -q
```

## 第七步 —— 修改配置的工作流程

现在如果我们想修改内存配置，只需要：

1. 修改 `cmake/MemConfig.cmake` 中的默认值
2. 运行 `cmake -B build` 重新配置
3. 重新编译项目

```bash
# 1. 修改 cmake/MemConfig.cmake
#    改变 E820_STORAGE_ADDR_DEFAULT 的值

# 2. 重新配置
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 3. 重新编译
cmake --build build
```

CMake 会自动：
1. 生成新的 `mem_detect_constants.inc`
2. 生成新的 `include/mem_config.h`
3. 运行验证脚本检查配置安全性
4. 显示配置摘要

## 常见问题

### Q: 为什么不用 `#define` 直接在头文件中定义？

A: 因为我们需要在汇编和 C 之间共享相同的值。如果在两个地方分别定义，迟早会出现不一致的问题。使用 CMake 生成可以确保"单一数据源"（Single Source of Truth）。

### Q: 如果我想临时改变配置怎么办？

A: 你可以通过 CMake 的 `-D` 选项临时覆盖默认值：

```bash
cmake -B build -DE820_STORAGE_ADDR_DEFAULT=0x5000
```

### Q: 验证脚本失败了怎么办？

A: 验证脚本失败说明配置不安全。你可以：
1. 查看警告信息，了解具体问题
2. 运行不带 `-q` 选项的验证脚本，查看详细输出
3. 根据建议的安全地址重新配置

### Q: 为什么不在汇编中直接使用 C 头文件？

A: 汇编器（NASM）不能直接包含 C 头文件。虽然 NASM 可以预处理一些简单的宏，但它不支持完整的 C 语法。所以我们为汇编生成单独的 INC 文件。

## 到这里我们完成了什么

很好，到这里我们已经完成了 CMake 配置同步方案：

1. **创建了配置模板** - C 头文件和汇编 INC 文件
2. **创建了 CMake 配置脚本** - 自动生成配置文件
3. **集成了验证脚本** - 检查配置安全性
4. **更新了 Bootloader 和内核** - 使用生成的配置文件
5. **定义了修改配置的工作流程** - 确保一致性

现在我们的内存配置是"单一数据源"，修改一处就会同步到所有地方，大大降低了出错的可能性。

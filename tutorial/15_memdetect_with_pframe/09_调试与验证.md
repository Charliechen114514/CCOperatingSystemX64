# 09 - 调试与验证

说实话，调试内存管理代码是一件很微妙的事情。问题往往不会立即显现，而是在你分配了几十次、几百次内存之后突然崩溃。而且这种崩溃很难追踪 —— 你不知道是哪个地方越界了、哪个地方双重释放了。所以我们非常需要在开发阶段就有完善的调试手段。

---

## 我们现在要做什么

我们已经实现了内存检测和物理帧分配器，现在需要验证它们是否正常工作。这包括：

1. 使用串口输出查看内存地图
2. 使用 GDB 调试 Bootloader
3. 打印位图状态进行可视化调试
4. 编写简单的分配/释放测试
5. 排查常见问题

---

## 第一步 —— 串口输出内存地图

最直接的调试方法是通过串口输出查看内存地图。我们已经在代码中添加了 `e820_dump_map()` 和 `pframe_dump()` 函数。

### 在内核中调用调试函数

确保在 `kernel_init()` 中调用了这些函数：

```c
void kernel_init(void) {
    /* ... 现有初始化代码 ... */

    /* === 内存检测 (Stage 15) === */
    e820_init();
    e820_dump_map();  /* 打印内存地图 */

    /* === 物理帧分配器 (Stage 15) === */
    pframe_init();
    pframe_dump();    /* 打印分配器状态 */

    /* ... 继续其他初始化 ... */
}
```

### 预期串口输出

运行 QEMU 后，你应该能在串口看到类似这样的输出：

```
[MEM] Detecting system memory...
[MEM] Method: E820 (detailed map)
[MEM] Memory detection complete.
=== CCOS Kernel ===
[E820] Initialized: method=E820, entries=5
[E820] Memory Map (method: E820, entries: 5)
[E820] Base               Length             Type
[E820] 0x0000000000000000  639 KB             Usable
[E820] 0x000000000009FC00  1 KB               Reserved
[E820] 0x00000000000E0000  2 MB               Reserved
[E820] 0x0000000000100000  127 MB             Usable
[E820] 0x000000000FE00000  2 MB               Reserved
[E820] Summary: Total=128 MB, Usable=127 MB
[PFRAME] Initialized: 32768 frames (127 MB managed)
[PFRAME] Free: 32512, Reserved: 256, Allocated: 256
[PFRAME] Allocator State:
[PFRAME]   Total frames:    32768 (127 MB)
[PFRAME]   Free frames:     32512
[PFRAME]   Allocated:       256
[PFRAME]   Reserved:        256
[PFRAME]   Bitmap size:     4096 bytes
[PFRAME]   Managed range:   0x100000 - 0x7FE0000
```

### 解读输出

让我来解释一下这些输出的含义：

1. **检测方法**: E820 表示我们使用了最详细的检测方法
2. **条目数量**: 5 个条目表示内存被分成了 5 个区域
3. **内存类型**: Usable 是可用内存，Reserved 是保留区域
4. **总内存**: 128 MB 是 QEMU 分配的内存总量
5. **可用内存**: 127 MB 是我们可以实际使用的内存（减去了保留区域）
6. **帧统计**: 32768 帧对应 127 MB（每帧 4KB）
7. **管理范围**: 从 1MB 开始到最高可用地址

## 第二步 —— 使用 GDB 调试 Bootloader

有时候我们需要调试 Bootloader 中的汇编代码，比如检查 E820 检测是否正确。

### 启动 QEMU 等待 GDB 连接

```bash
qemu-system-x86_64 -m 128M -drive format=raw,file=build/boot.img \
    -s -S -nographic -serial mon:stdio
```

- `-s`: 启用 GDB stub，监听 1234 端口
- `-S`: 启动时暂停 CPU，等待 GDB 连接

### 启动 GDB

在另一个终端：

```bash
# 对于 Bootloader (实模式代码)
gdb build/bootloader.bin

# 或者对于完整的 boot.img
gdb build/boot.img
```

### GDB 调试命令

```gdb
# 连接到 QEMU
target remote :1234

# 设置断点在 E820 检测函数
break detect_memory_e820

# 继续执行
continue

# 查看寄存器
info registers

# 查看内存 (比如 0x6000 的 E820 存储)
x/24x 0x6000

# 单步执行
si

# 查看当前位置的各种信息
info registers eax
info registers ebx
print $eax
```

### 检查 E820 存储

在 E820 检测完成后，我们可以查看存储的内容：

```gdb
# 查看前 24 字节 (第一个 E820 条目)
x/6x 0x6000

# 查看存储格式
# +0x00: method
# +0x01: entry_count (little endian)
# +0x03: entries[]

# 查看 method 字节
x/bx 0x6000

# 查看 entry_count
x/hx 0x6001
```

## 第三步 —— 位图可视化调试

位图分配器的一个好处是可以直接"看到"内存分配状态。我们可以添加一个函数来打印位图的缩略图。

### 添加位图打印函数

```c
void pframe_dump_bitmap_snippet(void) {
    if (!s_pframe_state.initialized) {
        return;
    }

    klog_info("[PFRAME] Bitmap snippet (first 64 frames):\n");

    /* 打印前 64 帧的状态 */
    for (int i = 0; i < 64; i++) {
        char c = bitmap_test(&s_pframe_state.frame_map, i) ? 'X' : '.';
        klog_putc(c);
        if ((i + 1) % 16 == 0) {
            klog_putc('\n');
        }
    }

    klog_putc('\n');
}
```

### 输出示例

```
[PFRAME] Bitmap snippet (first 64 frames):
XXXXXXXXXXXXXXXX
................
XXXXXXXXXXXXXXXX
................
```

- `X` 表示该帧已分配或保留
- `.` 表示该帧空闲可用

前 32 个 `X` 对应低 128KB（保留给 BIOS），接下来的 32 个 `.` 对应 128KB-256KB（可用区域）。

## 第四步 —— 编写简单的分配测试

现在我们来编写一个简单的测试，验证分配器是否正常工作。

### 在内核中添加测试代码

```c
void kernel_test_pframe_alloc(void) {
    klog_info("[TEST] Testing physical frame allocator...\n");

    pframe_stats_t stats_before, stats_after;

    /* 获取初始统计 */
    pframe_get_stats(&stats_before);
    klog_info("[TEST] Before: Free=%llu, Allocated=%llu\n",
              stats_before.free_frames, stats_before.allocated_frames);

    /* 测试 1: 分配单个帧 */
    physical_addr_t frame1;
    pframe_result_t res = pframe_alloc(&frame1);
    if (res == PFRAME_OK) {
        klog_info("[TEST] Allocated frame at 0x%llX\n", frame1);
        klog_info("[TEST] Is allocated: %s\n",
                  pframe_is_allocated(frame1) ? "yes" : "no");
    } else {
        klog_error("[TEST] Failed to allocate frame\n");
    }

    /* 测试 2: 再分配一个帧 */
    physical_addr_t frame2;
    res = pframe_alloc(&frame2);
    if (res == PFRAME_OK) {
        klog_info("[TEST] Allocated frame at 0x%llX\n", frame2);
    }

    /* 测试 3: 释放第一个帧 */
    res = pframe_free(frame1);
    if (res == PFRAME_OK) {
        klog_info("[TEST] Freed frame at 0x%llX\n", frame1);
        klog_info("[TEST] Is allocated: %s\n",
                  pframe_is_allocated(frame1) ? "yes" : "no");
    }

    /* 获取最终统计 */
    pframe_get_stats(&stats_after);
    klog_info("[TEST] After: Free=%llu, Allocated=%llu\n",
              stats_after.free_frames, stats_after.allocated_frames);

    /* 验证统计 */
    uint64_t expected_allocated = stats_before.allocated_frames + 1;
    if (stats_after.allocated_frames == expected_allocated) {
        klog_info("[TEST] Statistics check: PASSED\n");
    } else {
        klog_error("[TEST] Statistics check: FAILED (expected %llu, got %llu)\n",
                   expected_allocated, stats_after.allocated_frames);
    }

    /* 打印位图状态 */
    pframe_dump_bitmap_snippet();
}
```

### 调用测试函数

```c
void kernel_init(void) {
    /* ... 现有初始化代码 ... */

    pframe_init();
    pframe_dump();

    /* 运行测试 */
    kernel_test_pframe_alloc();

    /* ... 继续其他初始化 ... */
}
```

## 第五步 —— QEMU 内存配置

有时候问题出在 QEMU 的内存配置上。我们需要确保给 QEMU 分配了足够的内存。

### 检查当前内存配置

```bash
# 查看当前内存大小
qemu-system-x86_64 -m 128M ...
```

### 常用内存配置

```bash
# 128MB (最小推荐配置)
qemu-system-x86_64 -m 128M ...

# 256MB
qemu-system-x86_64 -m 256M ...

# 512MB
qemu-system-x86_64 -m 512M ...

# 1GB
qemu-system-x86_64 -m 1G ...
```

### 内存太小的影响

如果 QEMU 内存配置太小（比如小于 128MB），可能会出现：

1. E820 条目减少
2. 可用内存不足以初始化位图
3. 分配器初始化失败
4. 内核启动后立即 OOM

## 第六步 —— 常见问题排查

让我们来看看一些常见的问题及其排查方法。

### 问题 1: E820 条目数量为 0

**症状**: `[E820] Invalid entry count: 0`

**可能原因**:
- Bootloader 的内存检测失败
- 存储地址配置错误
- 串口输出函数有问题

**排查方法**:
1. 检查 Bootloader 的串口输出，看是否检测成功
2. 用 GDB 查看 0x6000 处的数据
3. 确认 E820_STORAGE_ADDR 配置一致

### 问题 2: 位图大小超出限制

**症状**: `[PFRAME] Bitmap size XXXXX exceeds maximum 2097152`

**可能原因**:
- QEMU 内存配置太大（超过 64GB）
- 最高可用地址计算错误

**排查方法**:
1. 检查 QEMU 的 `-m` 参数
2. 查看 E820 内存地图，确认最高地址
3. 如果内存确实很大，考虑增加 PFRAME_MAX_BITMAP_SIZE

### 问题 3: 分配总是返回 OOM

**症状**: `[PFRAME] Out of memory: no free frames`

**可能原因**:
- 可用内存确实很少
- 位图初始化有问题（全部标记为已用）
- 请求的连续帧太多

**排查方法**:
1. 打印分配器统计，确认空闲帧数
2. 打印位图状态，查看是否有空闲帧
3. 尝试分配单个帧而不是多个连续帧

### 问题 4: 双倍释放检测

**症状**: `[PFRAME] Double-free detected: 0x...`

**可能原因**:
- 代码逻辑错误，重复释放同一帧
- 初始化时标记区域出错

**排查方法**:
1. 用 GDB 在释放处设置断点
2. 查看调用栈，找到重复释放的位置
3. 确认分配和释放的配对

### 问题 5: 检测方法不是 E820

**症状**: `[E820] Method: E801` 或 `[E820] Method: INT 15h/88h`

**可能原因**:
- QEMU 版本太老
- 某些 QEMU 配置禁用了 E820
- E820 检测代码有 bug

**排查方法**:
1. 检查 QEMU 版本：`qemu-system-x86_64 --version`
2. 尝试更新 QEMU
3. 用其他机器（真实硬件）测试

## 常用调试技巧

### 技巧 1: 使用 GDB 条件断点

```gdb
# 当 EAX 寄存器等于某个值时停止
break *0x7E00 if $eax == 0x534D4150
```

### 技巧 2: 查看内存的变化

```gdb
# 设置监视点，当内存被修改时停止
watch *0x6000

# 继续执行，当 0x6000 被修改时暂停
continue
```

### 技巧 3: 使用 QEMU monitor 命令

在 QEMU 运行时按 `Ctrl+A` 然后 `C` 进入 monitor：

```
(qemu) info mem
(qemu) x/10x 0x6000
(qemu) xp/10x 0x6000
```

### 技巧 4: 保存串口输出到文件

```bash
qemu-system-x86_64 -m 128M -drive format=raw,file=build/boot.img \
    -nographic -serial file:serial.log
```

然后可以事后查看 `serial.log` 文件。

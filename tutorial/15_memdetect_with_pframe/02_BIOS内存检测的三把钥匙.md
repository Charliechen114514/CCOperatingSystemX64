# 02 - BIOS 内存检测的三把钥匙

说实话，x86 的内存检测机制像是一部活生生的计算机史。三种方法分别代表了三个不同的时代，我们现在要做的就是把它们全都实现，确保我们的内核能在从 386 到最新处理器的各种机器上运行。

---

## 我们现在要做什么

我们需要了解 x86 平台上三种 BIOS 内存检测方法：E820、E801 和 88h。这三种方法通过 INT 15h 中断调用，分别对应不同的 BIOS 版本和硬件时代。

我们的目标是实现一个三级回退策略：先尝试最新的 E820，如果不支持就回退到 E801，最后再尝试 88h。这样可以确保最大兼容性，同时在新机器上获得最详细的内存信息。

---

## 第一把钥匙：INT 15h/E820

E820 是最详细、最现代的内存检测方法。它最早出现在 1994 年左右的 BIOS 中，至今仍然是主流。

### E820 能告诉我们什么

E820 返回的是一张"内存地图"，其中每个条目包含：
- 基地址（64 位）
- 长度（64 位）
- 内存类型（32 位）
- ACPI 扩展属性（32 位）

这意味着 E820 不仅能告诉我们有多少内存，还能告诉我们每个内存区域的用途。

### E820 的内存类型

| 类型值 | 名称 | 描述 |
|--------|------|------|
| 1 | Usable | 可用 RAM，可以自由使用 |
| 2 | Reserved | 保留区域，包含 BIOS、内存映射 I/O |
| 3 | ACPI Reclaimable | ACPI 数据，可以被内核回收使用 |
| 4 | ACPI NVS | ACPI NVS 内存，必须保留 |
| 5 | Unusable | 内存区域存在但不可用 |
| 其他 | 保留 | 未来使用 |

这些类型非常重要。比如类型 3（ACPI Reclaimable）表示这是 ACPI 使用的数据，但在 ACPI 初始化完成后可以回收用作普通内存。类型 4（ACPI NVS）则必须永久保留，不能动。

### E820 调用约定

E820 的调用约定有点复杂，因为它是为 32 位保护模式设计的，但我们需要在 16 位实模式下调用。

**输入寄存器：**
```
AX    = 0xE820
BX    = 连续值 (Continuation Value)
         - 首次调用: 0
         - 后续调用: 上一次返回的 BX 值
ES:DI = 缓冲区地址 (指向 E820_ENTRY 结构)
CX    = 缓冲区大小 (建议 24 字节)
EDX   = 'SMAP' 签名 (0x534D4150)
```

**输出寄存器：**
```
CF    = 0 成功, 1 失败
AX    = 'SMAP' 签名 (验证用)
CX    = 实际写入的字节数
ES:DI = 填充后的缓冲区
BX    = 下一次调用的连续值 (0 表示最后一条)
```

### E820 条目结构

每个 E820 条目固定 24 字节：

```c
struct e820_entry {
    uint64_t base;       // 基地址 (8 字节)
    uint64_t length;     // 长度 (8 字节)
    uint32_t type;       // 类型 (4 字节)
    uint32_t acpi_attrs; // ACPI 属性 (4 字节)
};  // 总共 24 字节
```

### E820 的连续值机制

E820 的一个独特之处在于它使用"连续值"（Continuation Value）来获取多个条目。这就像是迭代器一样：

1. 首次调用时，BX = 0
2. BIOS 返回第一个条目，并在 BX 中设置连续值
3. 下次调用时，用上次的 BX 值
4. BIOS 返回下一个条目
5. 重复直到 BX = 0，表示没有更多条目

这种设计允许 BIOS 返回任意数量的条目，而不需要预先知道有多少。

### E820 的一个真实例子

在典型的现代 PC 上，E820 返回的内存地图可能长这样：

```
 #  Base        Length      Type
 0  0x00000000  0x0009FC00  Usable       (639KB 可用)
 1  0x0009FC00  0x00000400  Reserved    ( BIOS 区域)
 2  0x000E0000  0x00200000  Reserved    (选项 ROM 等)
 3  0x00100000  0x07F00000  Usable       (127MB 延展内存)
 4  0x0FE00000  0x00200000  Reserved    (内存映射 I/O)
 5  0x100000000 0x300000000 Usable       (12GB 上位内存)
```

你可以看到，内存并不是连续的一整块。有可用区域（Usable），也有保留区域（Reserved）。如果我们不知道这些信息，盲目地使用内存，很可能会踩到保留区域。

## 第二把钥匙：INT 15h/E801

E801 是一个简化版的内存检测方法，大约出现在 1980 年代末到 1990 年代初。

### E801 能告诉我们什么

E801 只返回两个数字：
- 1MB 以下的内存大小（最大 640KB）
- 1MB 以上的内存大小

也就是说，E801 把内存分成两块来报告，一块在 1MB 以下，一块在 1MB 以上。它不会告诉你具体的地址范围，也不会告诉你内存的类型。

### E801 调用约定

E801 的调用约定比 E820 简单得多。

**输入寄存器：**
```
AX    = 0xE801
```

**输出寄存器：**
```
CF    = 0 成功, 1 失败
AX    = 1MB 以下的内存大小 (KB), 最大 640KB
BX    = 1MB 以下的内存大小 (KB), 最大 640KB (重复)
CX    = 1MB 以上的内存大小 (KB), 最大 16MB-1MB
DX    = 1MB 以上的内存大小 (64KB 单位), 用于超过 16MB 的情况
```

### E801 的返回值解读

E801 的返回值有点奇怪。对于 1MB 以上的内存，它用两个寄存器来表示：
- CX：以 KB 为单位，最大表示 16MB
- DX：以 64KB 为单位，用于表示超过 16MB 的部分

为什么要这样设计？因为当初设计这个接口的时候，没人想到会有那么多内存。CX 是 16 位寄存器，最大只能表示 65535KB，也就是约 64MB。但实际上 1MB 以下已经有约 640KB，所以 1MB 以上最多只能表示到约 63MB。为了支持更大的内存，后来又加了 DX 寄存器，以 64KB 为单位。

### E801 转换为 E820 格式

虽然 E801 返回的信息有限，但我们可以把它转换成 E820 格式，这样后续处理就可以统一了。

转换逻辑很简单：
```c
// Entry 0: 0 ~ 1MB
entry0.base = 0;
entry0.length = ax * 1024;  // 转换为字节
entry0.type = E820_TYPE_USABLE;

// Entry 1: 1MB 以上
if (dx != 0) {
    entry1.length = dx * 64 * 1024;  // 使用 DX (64KB 单位)
} else {
    entry1.length = cx * 1024;       // 使用 CX (KB 单位)
}
entry1.base = 0x100000;  // 1MB
entry1.type = E820_TYPE_USABLE;
```

## 第三把钥匙：INT 15h/AH=88h

88h 是最古老的内存检测方法，可以追溯到 1980 年代早期的 PC/AT。

### 88h 能告诉我们什么

88h 只返回一个数字：从地址 0 开始的连续内存大小（以 KB 为单位），最大 64MB。

它不告诉我们：
- 内存的分布情况
- 哪些区域是保留的
- 1MB 以上是否有内存

### 88h 调用约定

88h 的调用约定最简单。

**输入寄存器：**
```
AH    = 0x88
```

**输出寄存器：**
```
CF    = 0 成功, 1 失败
AX    = 连续内存大小 (KB), 最大 65536 = 64MB
```

### 88h 的局限性

88h 有几个严重的局限性：

1. **最大 64MB**。这是因为在设计这个接口的时候，没人想到会有超过 64MB 内存的机器。

2. **假设从 0 开始连续**。但实际上低 1MB 有很多保留区域，88h 不会告诉我们这些。

3. **没有区域信息**。它只给出一个总大小，不告诉我们哪些地址可用。

尽管如此，88h 仍然是最广泛支持的内存检测方法，几乎所有从 PC/AT 开始的机器都支持它。

### 88h 转换为 E820 格式

我们同样可以把 88h 的结果转换成 E820 格式：

```c
entry.base = 0;
entry.length = (uint64_t)ax * 1024;  // 转换为字节
entry.type = E820_TYPE_USABLE;
```

但要注意，88h 返回的结果包含了低 1MB 的保留区域，所以后续处理时需要手动排除这些区域。

## 三级回退策略

现在我们有三种方法，问题是 —— 我们该用哪一个？

答案是：全部都要实现，按照优先级依次尝试。

### 回退流程

```
尝试 E820
    │
    ├─ 成功 → 使用 E820 结果
    │
    └─ 失败
        │
        ├─ 尝试 E801
        │   │
        │   ├─ 成功 → 使用 E801 结果
        │   │
        │   └─ 失败
        │       │
        │       ├─ 尝试 88h
        │       │   │
        │       │   ├─ 成功 → 使用 88h 结果
        │       │   │
        │       │   └─ 失败 → 检测失败，无法启动
        │       │
        │       └─ ...
        │
        └─ ...
```

### 为什么这样设计

首先，E820 是最详细的，它能给我们完整的内存地图，包括每个区域的类型。这是最理想的情况。

其次，E801 虽然不如 E820 详细，但至少能告诉我们 1MB 以上有多少内存。对于大多数情况来说这已经足够了。

最后，88h 虽然最简陋，但几乎所有机器都支持它。即使前面两个方法都不支持，88h 也能给我们一个最基本的内存信息。

### 检测失败怎么办

如果三种方法都失败了怎么办？说实话，这种情况下基本上是无法启动的。但我们可以选择一个安全的默认值，比如假设至少有 1MB 可用内存，然后打印警告信息。这总比直接崩溃要好。

## 存储内存地图

Bootloader 检测到内存地图后，需要把它存储在一个固定地址，让内核能够读取。

### 存储地址选择

我们选择 `0x6000` 作为存储地址。为什么是这个地址？

看一下低内存的布局：
```
地址          内容
0x0000 - 0x04FF  BIOS 数据区 (IVT + BDA)
0x0500 - 0x05FF  可用 (但我们不用)
0x0600 - 0x73FF  E820 存储 ← 我们选这里
0x7400 - 0x7BFF  可用
0x7C00 - 0x7DFF  MBR (Stage 1)
0x7E00 - 0x8FFF  Stage 2 Bootloader
0x9000 - 0xBFFF  页表
```

`0x6000` 位于 BIOS 数据区和 MBR 之间，是一个相对安全的空隙。16KB 的空间足够存储 128 个 E820 条目（每个 24 字节）。

### 存储格式

我们采用以下格式存储内存地图：

```
+0x00: method (1 byte)      - 检测方法 (0=E820, 1=E801, 2=88h)
+0x01: entry_count (2 bytes) - 条目数量 (little endian)
+0x03: entries[]             - E820 条目数组 (每个 24 字节)
```

第一个字节记录使用的是哪种检测方法，这样内核知道这些信息的"质量"如何。接下来两个字节记录条目数量，剩下的就是 E820 条目数组。

## 实现前的准备

在开始编写代码之前，我们需要准备一些东西。

### 定义 E820 条目结构

在 Bootloader 中，我们需要定义 E820 条目的结构：

```asm
struc e820_entry
    .base:      resq 1    ; 基地址 (8 字节)
    .length:    resq 1    ; 长度 (8 字节)
    .type:      resd 1    ; 类型 (4 字节)
    .acpi_attrs:resd 1    ; ACPI 属性 (4 字节)
endstruc
; 总大小 = 24 字节
```

### 定义内存类型常量

```asm
%define E820_TYPE_USABLE       1
%define E820_TYPE_RESERVED     2
%define E820_TYPE_ACPI_RECLAIM 3
%define E820_TYPE_NVS          4
%define E820_TYPE_UNUSABLE     5
```

### 定义检测方法常量

```asm
%define MEM_METHOD_E820     0
%define MEM_METHOD_E801     1
%define MEM_METHOD_88H      2
%define MEM_METHOD_UNKNOWN  3
```

### 定义存储地址

```asm
%define E820_STORAGE_ADDR   0x6000
%define E820_MAX_ENTRIES    128
```

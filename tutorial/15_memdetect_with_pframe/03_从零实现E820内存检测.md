# 03 - 从零实现 E820 内存检测

说实话，在实模式下调用 BIOS 中断是个很有意思的体验。你既要处理 16 位寄存器的限制，又要和 32 位数据打交道，稍不注意就会出错。但一旦做对了，那种成就感是难以形容的。

---

## 我们现在要做什么

我们要在 Bootloader 中实现 INT 15h/E820 内存检测。这包括：

1. 准备 E820 条目结构定义
2. 实现首次 E820 调用
3. 实现循环获取后续条目
4. 处理连续值和签名验证
5. 将结果存储到固定地址

我们会在 `boot/bootloader.asm` 中添加这段代码。

---

## 第一步 —— 定义数据结构和常量

首先，我们需要在 Bootloader 中定义 E820 相关的数据结构和常量。

打开 `boot/bootloader.asm`，在适当位置添加以下定义：

```asm
; ==============================================================================
; Memory Detection Constants
; ==============================================================================

; E820 内存类型
%define E820_TYPE_USABLE       1
%define E820_TYPE_RESERVED     2
%define E820_TYPE_ACPI_RECLAIM 3
%define E820_TYPE_NVS          4
%define E820_TYPE_UNUSABLE     5

; 检测方法
%define MEM_METHOD_E820     0
%define MEM_METHOD_E801     1
%define MEM_METHOD_88H      2
%define MEM_METHOD_UNKNOWN  3

; 存储配置
%define E820_STORAGE_ADDR   0x6000
%define E820_MAX_ENTRIES    128
%define E820_ENTRY_SIZE     24
```

这些常量定义了：
- E820 的五种内存类型
- 我们的检测方法标识
- 存储地址和最大条目数

### 为什么选择 0x6000

这里解释一下为什么选择 `0x6000` 作为存储地址。

看一下低内存的布局：

```
地址范围              内容
0x000000 - 0x0004FF  IVT 和 BDA (BIOS 数据区)
0x000500 - 0x05FFF  可用空隙
0x000600 - 0x073FF  ← E820 存储 (我们的选择)
0x07400 - 0x07BFF  可用空隙
0x07C00 - 0x07DFF  MBR (Stage 1 Bootloader)
0x07E00 - 0x08FFF  Stage 2 Bootloader
0x09000 - 0x0BFFF  页表 (PML4, PDPT, PD)
0x0C000 - 0x0FFFF  可用
0x10000 - ...      内核
```

`0x6000` 正好位于 BIOS 数据区（结束于 0x500）和 MBR（开始于 0x7C00）之间的空隙。这个位置安全地避开了所有已知的保留区域。

## 第二步 —— 实现 E820 检测函数

现在我们来实现 E820 检测的核心函数。这个函数会在实模式下被调用。

### 函数框架

```asm
; ==============================================================================
; detect_memory_e820 - Detect memory using INT 15h/E820
; Input: none
; Output: Memory map stored at E820_STORAGE_ADDR + 3
;         CF=0 on success, CF=1 on failure
;         CX = entry count (stored at E820_STORAGE_ADDR + 1)
; Clobbers: AX, BX, CX, DX, SI, DI, BP
bits 16
detect_memory_e820:
    pusha
    push ds
    push es

    ; Set ES:DI to point to storage area
    ; Layout: [method (1)][count (2)][entries...]
    ; So entries start at E820_STORAGE_ADDR + 3
    mov ax, 0x0000
    mov es, ax
    mov di, E820_STORAGE_ADDR + 3

    ; Initialize entry count (use BP to avoid conflicts with CX, SI, DI)
    xor bp, bp                 ; BP = entry counter

    ; === First E820 call (before loop) ===
    ; E820 requires 32-bit registers even in real mode!
    ; We use the 0x66 operand-size prefix to access 32-bit registers
    mov di, E820_STORAGE_ADDR + 3
    xor ebx, ebx              ; EBX = 0 for first call
    mov edx, 'PAMS'           ; EDX = 'SMAP' signature (0x534D4150)
                                ; 'PAMS' in little-endian = 'SMAP'
    mov eax, 0xe820           ; EAX = E820 function
    mov ecx, 24               ; ECX = buffer size (24 bytes)
    int 0x15

    ; Check carry flag immediately
    jc .e820_cf_set

    ; Verify signature in EAX (should return 'SMAP' = 0x534D4150 = 'PAMS')
    cmp eax, 'PAMS'
    jne .e820_sig_mismatch

    ; EBX=0 after first call means no more entries (single entry system)
    ; This is actually OK, not an error
    test ebx, ebx
    jz .process_entry_first
```

### 签名验证的坑

这里有个容易踩的坑：签名字节序。

BIOS 规范规定签名是 `'SMAP'`，即 `0x534D4150`。但在小端序系统中，这四个字节在内存中的存储顺序是 `'PAMS'`。

所以在汇编代码中，我们比较 `EAX` 和 `'PAMS'`，而不是 `'SMAP'`。如果你写错了，签名验证就会失败，E820 检测也会失败。

### 主循环

```asm
.e820_loop:
    ; Setup E820 call - use 32-bit registers
    mov eax, 0xe820           ; EAX = E820 function
    mov ecx, 24               ; ECX = buffer size
    ; EDX already set to 'PAMS', EBX contains continuation value

    int 0x15

    ; Check carry flag immediately
    jc .e820_cf_set             ; CF=1 means error

    ; Verify signature in EAX
    cmp eax, 'PAMS'
    jne .e820_sig_mismatch

.process_entry_first:
    ; Entry processing
    ; BIOS may have modified ES, so restore it to 0
    mov ax, 0x0000
    mov es, ax

    ; Skip zero-length entries
    ; Check if length field (at offset 8) is zero
    mov si, di
    add si, 8                  ; Point to length.low
    cmp dword [es:si], 0
    jne .entry_has_length
    cmp dword [es:si+4], 0     ; Check length.high
    jne .entry_has_length
    ; Length is zero, skip this entry
    jmp .skip_entry

.entry_has_length:
    ; Entry stored successfully
    inc bp                     ; Increment entry count

.skip_entry:
    ; Check if we've reached max entries
    cmp bp, E820_MAX_ENTRIES
    jae .e820_done             ; Too many entries

    ; Check for continuation (EBX=0 means last entry)
    test ebx, ebx              ; Test full 32-bit EBX
    jz .e820_done

    ; Advance DI to next entry
    add di, 24

    ; Continue loop
    jmp .e820_loop
```

### 错误处理和退出

```asm
.e820_cf_set:
    ; CF is set - error occurred
    jmp .e820_error

.e820_sig_mismatch:
    ; EAX signature doesn't match 'SMAP'
    jmp .e820_error

.e820_done:
    ; Success - store entry count after method byte (at offset 1-2)
    mov word [E820_STORAGE_ADDR + 1], bp

    clc                        ; Clear carry = success
    jmp .e820_exit

.e820_error:
    stc                        ; Set carry = error
.e820_exit:
    pop es
    pop ds
    popa
    ret
```

## 第三步 —— 调用 E820 检测

现在我们需要在 Bootloader 的主流程中调用 E820 检测。

### 主检测函数

我们创建一个主函数来尝试三种检测方法：

```asm
; ==============================================================================
; detect_memory_map - Detect system memory map using E820/E801/INT 15h/88h
; Input: none
; Output: E820 map stored at E820_STORAGE_ADDR (0x6000)
;         Detection method stored at E820_STORAGE_ADDR (first byte)
; Clobbers: AX, BX, CX, DX, SI, DI, BP
bits 16
detect_memory_map:
    pusha
    push ds

    ; Print memory detection start message
    mov si, msg_mem_detect_start
    call serial_write_string

    ; -----------------------------------------------------------------
    ; Try E820 first (most detailed)
    ; -----------------------------------------------------------------
    call detect_memory_e820
    jc .try_e801              ; CF=1 means E820 failed

    ; E820 succeeded!
    mov byte [E820_STORAGE_ADDR], MEM_METHOD_E820

    mov si, msg_mem_method_e820
    call serial_write_string

    jmp .detect_done

.try_e801:
    ; -----------------------------------------------------------------
    ; Try E801 (fallback)
    ; -----------------------------------------------------------------
    call detect_memory_e801
    jc .try_88h               ; CF=1 means E801 failed

    ; E801 succeeded!
    mov byte [E820_STORAGE_ADDR], MEM_METHOD_E801

    mov si, msg_mem_method_e801
    call serial_write_string

    jmp .detect_done

.try_88h:
    ; -----------------------------------------------------------------
    ; Try INT 15h/88h (last resort)
    ; -----------------------------------------------------------------
    call detect_memory_88h
    jc .detect_failed         ; CF=1 means 88h failed

    ; 88h succeeded!
    mov byte [E820_STORAGE_ADDR], MEM_METHOD_88H

    mov si, msg_mem_method_88h
    call serial_write_string

    jmp .detect_done

.detect_failed:
    ; All methods failed
    mov byte [E820_STORAGE_ADDR], MEM_METHOD_UNKNOWN

    mov si, msg_mem_method_failed
    call serial_write_string

    jmp .detect_exit

.detect_done:
    mov si, msg_mem_detect_done
    call serial_write_string

.detect_exit:
    pop ds
    popa
    ret
```

### 调试消息

我们还需要定义一些调试消息：

```asm
; ==============================================================================
; Memory Detection Messages
; ==============================================================================
msg_mem_detect_start:
    db "[MEM] Detecting system memory...", 0x0d, 0x0a, 0

msg_mem_method_e820:
    db "[MEM] Method: E820 (detailed map)", 0x0d, 0x0a, 0

msg_mem_method_e801:
    db "[MEM] Method: E801 (two regions)", 0x0d, 0x0a, 0

msg_mem_method_88h:
    db "[MEM] Method: INT 15h/88h (legacy)", 0x0d, 0x0a, 0

msg_mem_method_failed:
    db "[MEM] ERROR: All memory detection methods failed!", 0x0d, 0x0a, 0

msg_mem_detect_done:
    db "[MEM] Memory detection complete.", 0x0d, 0x0a, 0
```

## 第四步 —— 在 Bootloader 主流程中调用

现在我们需要在 Bootloader 的主流程中调用内存检测函数。

在 `boot/bootloader.asm` 中找到 Stage 2 的主函数，在进入保护模式之前调用内存检测：

```asm
bits 16
; ==============================================================================
; Stage 2 Main Entry Point
; ==============================================================================
stage2_main:
    ; ... 现有初始化代码 ...

    ; === 检测内存地图 ===
    call detect_memory_map

    ; === 进入保护模式 ===
    ; ... 现有代码 ...
```

### 为什么要在进入保护模式之前检测

这是因为 BIOS 中断只能在实模式下调用。一旦我们进入保护模式或长模式，就不能再直接调用 BIOS 中断了。

所以在进入保护模式之前，我们需要完成所有需要 BIOS 的操作，包括内存检测、磁盘读取等。

## 第五步 —— 编译和测试

现在让我们编译并测试 E820 检测是否正常工作。

```bash
# 配置构建
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 构建
cmake --build build

# 运行 QEMU (带串口输出)
qemu-system-x86_64 -m 128M -drive format=raw,file=build/boot.img \
    -nographic -serial mon:stdio
```

### 预期输出

如果一切正常，你应该能在串口输出中看到：

```
[MEM] Detecting system memory...
[MEM] Method: E820 (detailed map)
[MEM] Memory detection complete.
=== CCOS Bootloader v1.0 ===
...
```

### 如果看到 E801 或 88h

如果你看到 `[MEM] Method: E801` 或 `[MEM] Method: INT 15h/88h`，这说明 E820 检测失败了。这可能是因为：

1. QEMU 版本太老，不支持 E820
2. 某些参数配置问题
3. 我们的代码有 bug

检查一下代码，确保签名验证、连续值处理等都正确。

### 如果看到检测失败

如果看到 `[MEM] ERROR: All memory detection methods failed!`，这说明三种方法都失败了。这可能是因为：

1. 串口输出函数有问题
2. 调用约定有误
3. 存储地址冲突

建议用 GDB 单步调试，检查 BIOS 调用是否正确。

## 第六步 —— 验证存储的数据

为了验证 E820 检测是否正确存储了数据，我们可以在内核启动后读取并打印内存地图。

但在此之前，我们可以先检查一下存储格式是否正确。

### 使用 GDB 检查

```bash
# 启动 QEMU 并等待 GDB 连接
qemu-system-x86_64 -m 128M -drive format=raw,file=build/boot.img \
    -s -S

# 在另一个终端启动 GDB
gdb build/bootloader.o
(gdb) target remote :1234
(gdb) x/10hx 0x6000
```

这会显示 `0x6000` 地址开始的内存内容。你应该能看到：
- 第一个字节是检测方法 (0=E820, 1=E801, 2=88h)
- 接下来两个字节是条目数量 (little endian)
- 然后是 E820 条目数据

## 常见问题

### Q: 为什么我的 E820 总是失败？

A: 检查以下几点：
1. 确保签名验证使用 `'PAMS'` 而不是 `'SMAP'`
2. 确保缓冲区大小是 24 字节
3. 确保在调用前设置了 EDX='SMAP'
4. 检查 CF 标志的位置，应该在 INT 0x15 之后立即检查

### Q: 为什么我只能检测到第一个条目？

A: 这可能是因为循环逻辑有问题。检查以下几点：
1. 确保 EBX 的连续值正确传递给下一次调用
2. 确保在 EBX=0 时才退出循环
3. 检查 DI 指针是否正确移动到下一个条目

### Q: 存储地址为什么是 E820_STORAGE_ADDR + 3？

A: 因为存储格式是：
- +0x00: method (1 byte)
- +0x01: entry_count (2 bytes)
- +0x03: entries[] (从这里开始)

所以条目数组的起始地址是 `E820_STORAGE_ADDR + 3`。

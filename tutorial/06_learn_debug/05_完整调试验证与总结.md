# 完整调试验证与总结

我们已经把整套调试基础设施搭建起来了，这篇文章来做个完整的验证，并总结一下调试技巧。

---

## 完整调试流程验证

### 方式一：命令行调试

适合喜欢 GDB 命令行的开发者。

#### 步骤

1. **启动调试**

```bash
./scripts/debug.sh
```

2. **设置断点**

```
(gdb) b kernel_main
Breakpoint 1 at 0x...
```

3. **继续执行**

```
(gdb) c
Continuing.

Breakpoint 1, kernel_main () at kernel_main.c:10
10     system_vga_init();
```

4. **单步执行**

```
(gdb) s
system_vga_init () at vga.c:10
10     internal_vga_instance.height = VGA_HEIGHT;
```

5. **查看变量**

```
(gdb) p internal_vga_instance.height
$1 = 25
```

6. **查看内存**

```
(gdb) x/10x 0xB8000
0xb8000: 0x0f41  0x0f43  0x0f4f  0x0f53  ...
```

7. **退出**

```
(gdb) quit

正在关闭 QEMU...
调试会话结束
```

### 方式二：VSCode 图形化调试

适合喜欢图形界面的开发者。

#### 步骤

1. **启动 QEMU**

```bash
./scripts/launch_qemu_for_vscode_debug.sh
```

2. **在 VSCode 中设置断点**

点击代码行号左侧设置断点（红点）

3. **按 F5 启动调试**

4. **使用调试工具栏**

- F5：继续
- F10：单步跳过
- F11：单步进入
- Shift+F11：单步跳出
- Shift+F5：停止

5. **查看变量和监视**

- 左侧「变量」面板显示局部变量
- 左侧「监视」面板可以添加自定义表达式

6. **停止调试**

按 Shift+F5，QEMU 会自动停止。

### 两种方式对比

| 特性 | 命令行 (GDB) | VSCode |
|------|-------------|--------|
| 学习曲线 | 较陡 | 较平 |
| 效率 | 熟练后很高 | 直观高效 |
| 可视化 | 无 | 丰富 |
| 远程调试 | 方便 | 需要额外配置 |
| 自动化 | 脚本化 | 需要扩展 |

建议：
- **初学者**：从 VSCode 开始
- **老手**：GDB 命令行更灵活
- **结合使用**：VSCode 日常调试，GDB 处理复杂情况

## 常用 GDB 命令速查

### 程序控制

| 命令 | 缩写 | 说明 |
|------|------|------|
| `continue` | `c` | 继续执行 |
| `step` | `s` | 单步执行（进入函数） |
| `next` | `n` | 单步执行（不进入函数） |
| `stepi` | `si` | 单步执行指令 |
| `nexti` | `ni` | 执行下一条指令 |
| `finish` | - | 跳出当前函数 |
| `jump` | - | 跳到指定位置 |

### 断点管理

| 命令 | 说明 |
|------|------|
| `break *0x10000` | 在地址处设置断点 |
| `break kernel_main` | 在函数处设置断点 |
| `break kernel_main.c:42` | 在文件:行号处设置断点 |
| `break kernel_main if x == 42` | 条件断点 |
| `info breakpoints` | 查看所有断点 |
| `delete 1` | 删除断点 1 |
| `disable 1` | 禁用断点 1 |
| `enable 1` | 启用断点 1 |

### 查看信息

| 命令 | 说明 |
|------|------|
| `info registers` | 查看所有寄存器 |
| `info registers rax` | 查看特定寄存器 |
| `backtrace` / `bt` | 查看调用栈 |
| `info frame` | 查看当前栈帧 |
| `info symbol 0x...` | 查看地址对应的符号 |
| `disassemble` | 反汇编当前函数 |

### 内存和变量

| 命令 | 说明 |
|------|------|
| `print x` / `p x` | 打印变量 |
| `print/x x` | 以十六进制打印 |
| `print/t x` | 以二进制打印 |
| `x/10x 0xB8000` | 查看内存（16进制） |
| `x/10i $pc` | 查看指令 |
| `x/10s 0xB8000` | 查看字符串 |

## 常见问题排查

### 问题 1：GDB 连接失败

```
Remote communication error. Target disconnected.: Connection refused
```

**诊断**：

```bash
# 检查 QEMU 是否运行
ps aux | grep qemu-system

# 检查端口是否监听
lsof -ti:1234
```

**解决**：

1. 启动 QEMU：`./scripts/launch_qemu_for_vscode_debug.sh`
2. 或停止占用端口的进程：`kill -9 $(lsof -ti:1234)`

### 问题 2：符号文件找不到

```
(no debugging symbols found)
```

**诊断**：

```bash
file build/kernel.elf
```

应该看到 `with debug_info`。

**解决**：

```bash
# 重新构建 Debug 版本
rm -rf build
cmake -DCMAKE_BUILD_TYPE=Debug -B build
cmake --build build
```

### 问题 3：VGA 显示异常

**症状**：黑屏、乱码、颜色不对

**诊断**：

在 GDB 中检查：

```
(gdb) x/10x 0xB8000
```

**检查点**：

1. 确认调用了 `system_vga_init()`
2. 确认显存地址是 `0xB8000`
3. 确认 VGA 条目格式正确

**解决**：

检查 `vga_entry` 函数的实现：

```c
// 正确的格式
return (uint16_t)c | ((uint16_t)(background << 4 | font) << 8);
```

### 问题 4：QEMU 进程残留

**症状**：调试结束后 QEMU 还在运行

**解决**：

```bash
# 使用脚本停止
./scripts/launch_qemu_for_vscode_debug.sh --stop

# 或手动停止
killall qemu-system-x86_64
```

### 问题 5：VSCode 不能调试

**检查**：

1. `.vscode/launch.json` 存在且格式正确
2. `miDebuggerPath` 指向正确的 GDB 路径
3. QEMU 已经在运行
4. 端口 1234 没有被占用

## 调试技巧总结

### 技巧 1：条件断点

当某个函数被频繁调用时，可以用条件断点：

```
(gdb) break vga_putc if c == '\n'
```

这样只在遇到换行符时才会停下来。

### 技巧 2：显示变量

每次停顿都自动显示变量：

```
(gdb) display/x $rax
(gdb) display internal_vga_instance.width
```

用 `undisplay` 取消。

### 技巧 3：宏定义

在 `.gdbinit` 中定义常用命令：

```
define print_regs
    info registers
end

define dump_vga
    x/80x 0xB8000
end
```

### 技巧 4：日志点（VSCode）

在 VSCode 中，可以添加日志点而不中断程序：

右键行号 → 添加日志点 → 输入 `x = {x}`

### 技巧 5：调用函数

在 GDB 中可以直接调用函数：

```
(gdb) call vga_print_string(vga_instance(), "Debug message\n")
```

## 性能对比

### Debug vs Release

| 构建类型 | 优化 | 符号 | 大小 | 调试支持 |
|----------|------|------|------|----------|
| Debug | -O0 -g | 完整 | 大 | 完整 |
| Release | -O2 -DNDEBUG | 无/有限 | 小 | 有限 |

**建议**：
- 开发阶段：Debug
- 发布版本：Release

### 调试开销

- QEMU 虚拟化：比原生慢 10-100 倍
- GDB 单步：每步需要通信
- VGA 输出：直接写显存，开销小

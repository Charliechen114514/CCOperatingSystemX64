# 完整测试与故障排查 —— 确保一切正常工作

经过漫长的开发，我们的 EXT2 文件系统和 VFS 终于完成了！但在庆祝之前，我们需要进行完整的测试和验证，确保所有功能正常工作。

这篇文章将总结测试方法、常见问题排查方案，以及未来可以改进的方向。

## 编译和构建

首先确保代码能够正确编译：

```bash
cd /path/to/CCOperatingSystemX64
mkdir build && cd build
cmake ..
make -j$(nproc)
```

如果编译出错，检查以下几点：

1. **CMakeLists.txt 配置**：确保所有新文件都被添加到构建系统
2. **头文件依赖**：检查头文件是否正确包含
3. **链接顺序**：VFS、EXT2、块设备的链接顺序是否正确

常见编译错误包括未定义的引用（undefined reference），这通常是因为某个源文件没有被编译或链接。

## 创建测试磁盘镜像

我们需要一个格式化为 EXT2 的测试磁盘镜像：

```bash
# 创建 64MB 镜像
dd if=/dev/zero of=disk.img bs=1M count=64

# 格式化为 EXT2（块大小 1024）
mkfs.ext2 -b 1024 disk.img

# 挂载
sudo mount -o loop disk.img /mnt

# 添加测试文件
echo "Hello from CCOS!" > /mnt/test.txt
echo "This is line 2" >> /mnt/test.txt
mkdir /mnt/bin
mkdir /mnt/etc
echo "config data" > /mnt/config.conf

# 查看文件系统信息
dumpe2fs disk.img | head -30

# 卸载
sudo umount /mnt
```

注意使用 `-b 1024` 选项创建 1024 字节块大小的文件系统，这与我们当前实现的假设一致。如果使用其他块大小，需要相应调整代码。

## QEMU 测试

使用 QEMU 进行测试是最方便的方式：

```bash
qemu-system-x86_64 \
    -drive format=raw,file=disk.img,index=0,media=disk \
    -serial stdio \
    -m 512M \
    -kernel build/kernel.bin
```

查看串口输出，应该看到类似：

## 常见问题排查

### 问题 1：魔数错误

```
ext2: Invalid magic number 0x0 (expected 0xEF53)
```

**原因**：磁盘镜像没有正确格式化，或者读取位置错误。

**解决**：
1. 使用 `dumpe2fs` 验证磁盘镜像
2. 检查超级块偏移计算是否正确（1024 字节）
3. 确认块设备读取正常

### 问题 2：块读取失败

```
ext2: Failed to read superblock (got 0 sectors)
```

**原因**：块设备未正确初始化或设备号错误。

**解决**：
1. 检查 ATA 驱动初始化
2. 验证设备号映射（hda → 0, hdb → 1 等）
3. 确认块设备注册成功

### 问题 3：inode 读取失败

```
ext2: Failed to read inode 2
```

**原因**：块组描述符读取失败或计算错误。

**解决**：
1. 检查块组描述符起始位置计算
2. 验证 inode 表起始块号
3. 使用 `debugfs` 检查文件系统结构

### 问题 4：文件未找到

```
vfs: Path lookup failed
```

**原因**：路径解析失败或文件不存在。

**解决**：
1. 使用 `debugfs -R "ls -l" disk.img` 验证文件存在
2. 检查目录遍历逻辑
3. 确认文件名匹配正确

## 调试技巧

在开发过程中，以下调试技巧很有帮助：

**1. 添加详细日志**

```c
klog_trace("ext2: inode %lu, group=%u, index=%u\n", ino, group, index);
klog_trace("ext2: block_num=%lu, offset=%u\n", block_num, offset);
```

**2. 使用 GDB**

```bash
qemu-system-x86_64 -s -S ... # -s 启用 gdb, -S 暂停启动
gdb build/kernel.bin
(gdb) target remote :1234
(gdb) break ext2_read_inode
(gdb) continue
```

**3. 打印数据结构**

```c
void print_ext2_sb(ext2_superblock_t* sb) {
    klog_info("=== EXT2 Superblock ===\n");
    klog_info("Magic: 0x%x\n", sb->s_magic);
    klog_info("Blocks: %u\n", sb->s_blocks_count);
    klog_info("Block size: %u\n", 1024 << sb->s_log_block_size);
    /* ... */
}
```

## 功能限制

当前实现有一些限制需要注意：

1. **只读支持**：文件写入功能未完全实现
2. **无文件创建**：不能创建新文件或目录
3. **大文件支持有限**：只实现了直接块和单间接块
4. **无权限检查**：所有操作都假设有权限
5. **无文件锁**：多进程同时访问可能出问题

## 性能分析

当前实现的性能瓶颈在于：

1. **每次读取都访问磁盘**：没有块缓存
2. **同步 I/O**：等待磁盘操作完成
3. **无预读**：顺序读取没有优化

可以通过添加块缓存、异步 I/O、预读等机制来改善。

# 实现目录项缓存 —— 加速路径查找

inode 缓存解决了文件元数据的存储问题，但我们还需要解决另一个问题：如何快速通过文件名找到对应的 inode？

每次路径解析都需要查找文件名，比如查找 `/usr/bin/ls` 需要先在根目录找到 "usr"，再在 "usr" 目录找到 "bin"，最后在 "bin" 目录找到 "ls"。如果没有缓存，每次查找都要读取磁盘目录内容，性能会很差。

dentry（目录项）缓存就是为了解决这个问题。它缓存文件名到 inode 的映射，让路径解析可以在内存中完成。

## Dentry 缓存的设计

dentry 缓存与 inode 缓存类似，也使用哈希表来实现快速查找。但 dentry 的哈希键不仅是文件名，还包括父目录，因为不同目录下可以有同名的文件。

```c
#define DENTRY_HASH_BITS   8
#define DENTRY_HASH_SIZE   (1 << DENTRY_HASH_BITS)

static struct {
    list_head hash_table[DENTRY_HASH_SIZE];  /* 哈希表 */
    list_head lru_list;                      /* LRU 链表 */
    uint32_t count;                          /* 缓存的 dentry 数量 */
} dentry_cache;
```

除了哈希表，dentry 缓存还维护了一个 LRU（最近最少使用）链表。当内存紧张时，可以从 LRU 链表尾部开始释放 dentry，因为尾部是最久未使用的。

## 哈希函数

dentry 的哈希函数需要结合文件名和父目录：

```c
static uint32_t dentry_hash(const char* name, vfs_dentry_t* parent) {
    uint32_t hash = 0;
    uint64_t parent_ptr = (uint64_t)(uintptr_t)parent;

    /* 字符串哈希 */
    while (*name) {
        hash = (hash << 5) + hash + *name++;
    }

    /* 与父目录指针混合 */
    hash ^= (uint32_t)(parent_ptr >> 3);
    hash ^= (uint32_t)parent_ptr;

    return hash & (DENTRY_HASH_SIZE - 1);
}
```

这个哈希函数同时考虑了文件名和父目录。字符串哈希部分使用了经典的乘法哈希，父目录指针部分采用了与 inode 哈希类似的处理方式。把两者混合在一起，可以确保不同目录下的同名文件有不同的哈希值。

## 分配和释放 dentry

dentry 的分配函数需要初始化所有字段，并与父目录建立关系：

```c
vfs_dentry_t* vfs_d_alloc(vfs_dentry_t* parent, const char* name) {
    vfs_dentry_t* dentry = kmalloc(sizeof(vfs_dentry_t));
    if (!dentry) {
        return NULL;
    }

    memset(dentry, 0, sizeof(vfs_dentry_t));
    INIT_LIST_HEAD(&dentry->d_hash);
    INIT_LIST_HEAD(&dentry->d_lru);
    INIT_LIST_HEAD(&dentry->d_subdirs);

    dentry->d_parent = parent;
    dentry->d_inode = NULL;
    dentry->d_flags = DENTRY_FLAG_CACHED;
    dentry->d_count = 1;

    /* 复制文件名 */
    if (name) {
        strncpy(dentry->d_name, name, sizeof(dentry->d_name) - 1);
    } else {
        dentry->d_name[0] = '\0';
    }

    /* 从父目录继承超级块 */
    if (parent) {
        dentry->d_sb = parent->d_sb;
        /* 加入父目录的子目录链表 */
        list_add(&dentry->d_subdirs, &parent->d_subdirs);
    }

    /* 加入哈希表和 LRU 链表 */
    dentry_hash_insert(dentry);
    list_add(&dentry->d_lru, &dentry_cache.lru_list);
    dentry_cache.count++;

    return dentry;
}
```

这个函数建立了一个重要的关系：父子目录关系。每个 dentry 都有指向父目录的指针，同时也被加入父目录的子目录链表。这构成了一个树状结构，可以方便地遍历整个目录树。

释放函数需要处理更多的清理工作：

```c
void vfs_d_free(vfs_dentry_t* dentry) {
    if (!dentry) {
        return;
    }

    /* 从各种数据结构中移除 */
    dentry_hash_remove(dentry);
    list_del(&dentry->d_lru);
    dentry_cache.count--;

    if (dentry->d_parent) {
        list_del(&dentry->d_subdirs);
    }

    /* 释放关联的 inode 引用 */
    if (dentry->d_inode) {
        vfs_iput(dentry->d_inode);
    }

    /* 调用文件系统的释放函数 */
    if (dentry->d_op && dentry->d_op->d_release) {
        dentry->d_op->d_release(dentry);
    }

    kfree(dentry);
}
```

这里有个重要的细节：dentry 持有 inode 的引用。当 dentry 被释放时，需要调用 `vfs_iput()` 来释放这个引用。这确保了 inode 的引用计数始终正确。

## 查找 dentry

dentry 查找是路径解析的核心操作：

```c
vfs_dentry_t* vfs_d_lookup(vfs_dentry_t* parent, const char* name) {
    if (!parent || !name) {
        return NULL;
    }

    uint32_t hash = dentry_hash(name, parent);

    /* 在哈希表中查找 */
    vfs_dentry_t* dentry;
    list_for_each_entry(dentry, &dentry_cache.hash_table[hash], d_hash) {
        if (dentry->d_parent == parent &&
            strcmp(dentry->d_name, name) == 0) {
            /* 找到了，递增引用计数 */
            vfs_dget(dentry);
            return dentry;
        }
    }

    return NULL;
}
```

查找逻辑很直接：计算哈希值，遍历对应桶中的 dentry，匹配父目录和文件名。如果找到就递增引用计数后返回，没找到就返回 NULL。

## 引用计数管理

dentry 也有引用计数机制，管理方式与 inode 类似：

```c
vfs_dentry_t* vfs_dget(vfs_dentry_t* dentry) {
    if (dentry) {
        dentry->d_count++;
    }
    return dentry;
}

void vfs_dput(vfs_dentry_t* dentry) {
    if (!dentry) {
        return;
    }

    if (dentry->d_count > 0) {
        dentry->d_count--;
    }

    /* 移动到 LRU 链表头部 */
    list_del(&dentry->d_lru);
    list_add(&dentry->d_lru, &dentry_cache.lru_list);

    /* 引用计数为 0 时释放 */
    if (dentry->d_count == 0) {
        vfs_d_free(dentry);
    }
}
```

`vfs_dput()` 中有个有趣的操作：每次调用时都把 dentry 移动到 LRU 链表头部。这意味着最近被访问的 dentry 总是在链表前端，最久未访问的在尾部。当需要释放缓存时，从尾部开始释放即可。

## 负 dentry

负 dentry 是一个巧妙的设计。当查找一个不存在的文件时，我们创建一个没有关联 inode 的 dentry，并标记为"负"：

```c
vfs_dentry_t* vfs_d_negative(vfs_dentry_t* parent, const char* name) {
    vfs_dentry_t* dentry = vfs_d_alloc(parent, name);
    if (dentry) {
        dentry->d_flags |= DENTRY_FLAG_NEGATIVE;
        dentry->d_inode = NULL;
    }
    return dentry;
}

bool vfs_d_is_negative(vfs_dentry_t* dentry) {
    return dentry && (dentry->d_flags & DENTRY_FLAG_NEGATIVE);
}
```

这个设计有什么用呢？想象一下这个场景：你尝试打开一个不存在的文件，系统返回"文件不存在"。如果下次你又尝试打开同一个文件，没有负 dentry 的话，系统又要去磁盘查找一遍才能确定文件不存在。有了负 dentry，可以立即知道文件不存在，节省了磁盘 I/O。

## 实例化 dentry

当我们找到文件对应的 inode 后，需要把它关联到 dentry：

```c
void vfs_d_instantiate(vfs_dentry_t* dentry, vfs_inode_t* inode) {
    if (!dentry) {
        return;
    }

    dentry->d_inode = inode;
    if (inode) {
        inode->i_count++;
    }

    /* 清除负 dentry 标志 */
    dentry->d_flags &= ~DENTRY_FLAG_NEGATIVE;
}
```

这个函数把 dentry 和 inode 关联起来，同时清除负 dentry 标志。注意这里递增了 inode 的引用计数，因为 dentry 现在持有了 inode 的引用。

## 获取完整路径

有时候我们需要从 dentry 获取完整的文件路径，这对于调试和日志很有用：

```c
int vfs_d_get_path(vfs_dentry_t* dentry, char* buffer, size_t size) {
    if (!dentry || !buffer || size == 0) {
        return -1;
    }

    /* 从 dentry 向根目录构建路径 */
    char temp[512];
    int offset = sizeof(temp) - 1;
    temp[offset] = '\0';

    vfs_dentry_t* current = dentry;
    while (current && current->d_parent != current) {
        size_t name_len = strlen(current->d_name);
        offset -= name_len;
        if (offset < 0) {
            return -1;  /* 路径太长 */
        }
        memcpy(&temp[offset], current->d_name, name_len);

        offset--;
        if (offset < 0) {
            return -1;
        }
        temp[offset] = '/';

        current = current->d_parent;
    }

    /* 复制到输出缓冲区 */
    if ((size_t)offset >= size) {
        return -1;  /* 缓冲区太小 */
    }

    strcpy(buffer, &temp[offset]);
    return 0;
}
```

这个函数从目标 dentry 开始，沿着父指针向上遍历到根目录，逐层构建路径。由于遍历方向与路径字符串的构建方向相反，我们使用了一个临时缓冲区来反向构建，然后再复制到输出缓冲区。

## 缓存初始化

最后，dentry 缓存也需要初始化：

```c
void vfs_dentry_cache_init(void) {
    for (int i = 0; i < DENTRY_HASH_SIZE; i++) {
        INIT_LIST_HEAD(&dentry_cache.hash_table[i]);
    }
    INIT_LIST_HEAD(&dentry_cache.lru_list);
    dentry_cache.count = 0;
}
```

## 使用场景示例

让我们看一个典型的使用场景：路径查找 `/usr/bin/ls`。

```c
/* 假设我们已经有了根目录的 dentry */
vfs_dentry_t* root_dentry = /* ... */;
vfs_dentry_t* usr_dentry = vfs_d_lookup(root_dentry, "usr");

if (!usr_dentry) {
    /* 缓存未命中，需要从磁盘查找 */
    vfs_inode_t* root_inode = root_dentry->d_inode;
    vfs_inode_t* usr_inode = NULL;

    if (root_inode->i_op->lookup(root_inode, "usr", &usr_inode) == 0) {
        /* 找到了，创建并缓存 dentry */
        usr_dentry = vfs_d_alloc(root_dentry, "usr");
        vfs_d_instantiate(usr_dentry, usr_inode);
    }
}

/* 继续查找 bin */
vfs_dentry_t* bin_dentry = vfs_d_lookup(usr_dentry, "bin");
/* 类似的流程... */

/* 最后查找 ls */
vfs_dentry_t* ls_dentry = vfs_d_lookup(bin_dentry, "ls");
/* 类似的流程... */

/* 使用完毕后释放引用 */
vfs_dput(ls_dentry);
vfs_dput(bin_dentry);
vfs_dput(usr_dentry);
```

这个例子展示了 dentry 缓存如何加速路径查找。第一次查找时可能需要访问磁盘，但后续查找相同的路径时，所有组件都在缓存中，完全不需要磁盘 I/O。

## 小结

dentry 缓存是路径解析性能的关键。通过缓存文件名到 inode 的映射，我们避免了重复的磁盘查找。负 dentry 优化了不存在文件的查找，LRU 链表支持缓存淘汰策略。

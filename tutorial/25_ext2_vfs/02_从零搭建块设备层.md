# 从零搭建块设备层 —— 给文件系统打好地基

好了，废话不多说，让我们开始写代码。我们要实现的第一层是块设备层，它位于文件系统和 ATA 驱动之间，负责把底层的硬件差异抽象掉，给上层提供一个统一的接口。

这一层的设计很重要，因为一旦文件系统代码开始依赖特定的硬件接口，以后想换个存储设备就麻烦了。我们希望以后无论添加 SATA、NVMe 还是虚拟磁盘，文件系统代码都不需要修改。

## 设计思路

块设备层的核心思想是"抽象"。具体来说，我们定义一套标准的接口，任何符合这个接口的存储设备都可以被文件系统使用。

在操作系统中，这种抽象通常通过"函数指针表"来实现。你可能听说过面向对象编程中的"多态"概念，在 C 语言中，我们通过函数指针可以实现类似的效果。每个具体的块设备（ATA、未来的 SATA 等）都有自己的实现函数，但都通过相同的接口暴露给上层。

这样设计有几个好处：首先，上层代码不需要知道底层设备的具体类型，只需要调用统一的接口；其次，添加新的设备类型只需要实现这个接口并注册，不需要修改上层代码；最后，这种设计让代码结构更清晰，便于维护和测试。

## 第一步：定义数据结构和接口

首先创建 `kernel/fs/block/` 目录，然后编写头文件 `block.h`。这个头文件定义了块设备层的所有公开接口和数据结构。

```c
/* 在 kernel/fs/block/block.h 中 */

#pragma once

#include "defines/types.h"
#include "list/list.h"

/* 前向声明 */
typedef struct block_device block_device_t;
typedef struct block_operations block_operations_t;

/* 请求类型 */
typedef enum block_req_type {
    BLOCK_REQ_READ,
    BLOCK_REQ_WRITE,
    BLOCK_REQ_FLUSH,
} block_req_type_t;

/* 块设备操作函数指针表 */
struct block_operations {
    int (*read_blocks)(block_device_t* dev, uint64_t block,
                       void* buffer, uint32_t nblocks);
    int (*write_blocks)(block_device_t* dev, uint64_t block,
                        const void* buffer, uint32_t nblocks);
    int (*flush)(block_device_t* dev);
    int (*get_geometry)(block_device_t* dev, block_geometry_t* geo);
};

/* 块设备结构 */
struct block_device {
    list_head list;                /* 所有块设备的链表 */
    int dev_id;                    /* 设备 ID (0-3) */
    char name[32];                 /* 设备名称 (如 "hda") */

    uint64_t size;                 /* 设备大小（字节） */
    uint32_t block_size;           /* 块大小（通常是 512） */
    uint64_t nblocks;              /* 块数量 */

    list_head request_queue;       /* 请求队列 */
    bool processing;               /* 是否正在处理请求 */
    uint32_t ref_count;            /* 引用计数 */

    const block_operations_t* ops; /* 操作函数指针表 */
    void* private_data;            /* 设备私有数据 */
};
```

这个设计有几个关键点。首先是 `block_operations` 结构体，它包含了一组函数指针，定义了块设备必须支持的操作。这是实现多态的关键 —— 不同的设备类型有不同的函数实现，但都符合相同的接口。

其次是 `block_device` 结构体，它代表一个块设备实例。注意这里的 `ops` 成员是一个指向操作表的指针，而不是直接嵌入函数。这意味着所有同类型的设备可以共享同一个操作表，节省内存。`private_data` 成员则用于存储设备特定的数据，比如 ATA 设备的设备号。

## 第二步：实现 ATA 设备的封装

现在我们有了接口定义，接下来就是把现有的 ATA 驱动封装成符合这个接口的形式。我们需要实现一个"适配器"，把 ATA 驱动的函数调用转换成块设备层定义的标准接口。

在 `block.c` 中，我们首先定义 ATA 设备的私有数据结构：

```c
/* ATA 块设备的私有数据 */
typedef struct ata_block_dev {
    int ata_device;               /* ATA 设备号 (0-3) */
    bool initialized;             /* 初始化标志 */
} ata_block_dev_t;
```

这个结构体很简单，只存储了 ATA 设备号。实际使用时，`block_device` 结构体的 `private_data` 字段会指向这个结构体，这样我们就可以在需要时获取原始的 ATA 设备信息。

接下来是 ATA 操作的实现。每个函数都需要做两件事：首先从 `block_device` 结构体中提取 ATA 设备信息，然后调用相应的 ATA 驱动函数。

```c
/* 从 ATA 设备读取块 */
static int ata_block_read(block_device_t* dev, uint64_t block,
                          void* buffer, uint32_t nblocks) {
    if (!dev || !dev->private_data || !buffer) {
        return BLOCK_ERR_INVAL;
    }

    ata_block_dev_t* ata_dev = (ata_block_dev_t*)dev->private_data;

    /* 调用 ATA 驱动的读取函数 */
    ata_result_t result = ata_read(ata_dev->ata_device, block, buffer, nblocks);

    if (result == ATA_OK) {
        return (int)nblocks;
    }

    klog_error("block: ATA read failed on device %d\n", ata_dev->ata_device);
    return BLOCK_ERR_IO;
}

/* 写操作类似 */
static int ata_block_write(block_device_t* dev, uint64_t block,
                           const void* buffer, uint32_t nblocks) {
    /* 类似的实现... */
}
```

你看，这里的关键是把 `block_device*` 转换成 `ata_block_dev*`，然后调用我们之前实现的 ATA 函数。这种设计让块设备层完全不需要知道 ATA 的具体实现细节。

最后，我们创建一个操作表，把所有函数指针组织起来：

```c
/* ATA 块设备操作表 */
static const block_operations_t ata_block_ops = {
    .read_blocks = ata_block_read,
    .write_blocks = ata_block_write,
    .flush = ata_block_flush,
    .get_geometry = ata_block_get_geometry,
};
```

这个操作表是一个全局常量，所有 ATA 块设备都共享同一个操作表实例。

## 第三步：设备注册机制

有了设备抽象，接下来我们需要一个注册机制。文件系统可以通过设备 ID 来查找和使用块设备，而不需要关心设备的具体类型。

我们用一个简单的数组来存储已注册的设备：

```c
/* 块设备注册表 */
static struct {
    block_device_t* devices[4];   /* 最多支持 4 个 ATA 设备 */
    uint32_t count;               /* 已注册设备数量 */
} block_registry = {0};
```

注册函数负责将设备添加到注册表：

```c
int block_device_register(block_device_t* dev) {
    if (!dev) {
        return BLOCK_ERR_INVAL;
    }

    if (dev->dev_id < 0 || dev->dev_id >= 4) {
        klog_error("block: Invalid device ID %d\n", dev->dev_id);
        return BLOCK_ERR_INVAL;
    }

    if (block_registry.devices[dev->dev_id] != NULL) {
        klog_warn("block: Device %d already registered\n", dev->dev_id);
        return BLOCK_ERR_BUSY;
    }

    /* 初始化请求队列 */
    INIT_LIST_HEAD(&dev->request_queue);
    dev->processing = false;
    dev->ref_count = 1;

    /* 注册设备 */
    block_registry.devices[dev->dev_id] = dev;
    block_registry.count++;

    klog_info("block: Registered device %d as %s (size=%lu MB)\n",
              dev->dev_id, dev->name, dev->size / (1024 * 1024));

    return BLOCK_OK;
}
```

这里有几个细节值得注意。首先是设备 ID 的范围检查，我们只支持 0-3 的 ID，对应四个 ATA 设备位置。其次是重复注册检查，防止同一个设备被注册两次。最后是引用计数初始化为 1，这是因为注册本身就相当于对设备的第一次引用。

对应的，获取设备函数会递增引用计数：

```c
block_device_t* block_device_get(int dev_id) {
    if (dev_id < 0 || dev_id >= 4) {
        return NULL;
    }

    block_device_t* dev = block_registry.devices[dev_id];
    if (dev) {
        dev->ref_count++;  /* 递增引用计数 */
    }

    return dev;
}

void block_device_put(block_device_t* dev) {
    if (dev && dev->ref_count > 0) {
        dev->ref_count--;  /* 递减引用计数 */
    }
}
```

引用计数是资源管理的重要机制。每次获取设备时递增，使用完毕后递减。虽然我们目前的实现还不会真正释放设备，但这个框架为以后的生命周期管理打好了基础。

## 第四步：同步 I/O 实现

块设备层需要提供读写接口给上层使用。为了简单起见，我们先实现同步版本 —— 调用后会等待操作完成后才返回。

```c
int block_read_sync(block_device_t* dev, uint64_t block,
                    void* buffer, uint32_t nblocks) {
    if (!dev || !buffer) {
        return BLOCK_ERR_INVAL;
    }

    if (!dev->ops || !dev->ops->read_blocks) {
        return BLOCK_ERR_NODEV;
    }

    return dev->ops->read_blocks(dev, block, buffer, nblocks);
}
```

这个函数非常简洁，但体现了一个重要的设计原则：通过函数指针调用具体设备的实现。这样，无论底层是什么设备，上层都可以用同样的方式读写。

你可能注意到这里有个 `!dev->ops` 的检查。这是一个防御性编程的实践 —— 如果设备没有正确初始化操作表，我们宁可比早发现报错，也不要让系统莫名其妙崩溃。

## 第五步：创建和初始化 ATA 块设备

最后一步是把所有组件组合起来，在系统初始化时自动创建和注册 ATA 块设备。

```c
block_device_t* ata_create_block_device(int ata_device) {
    /* 分配 block_device 结构 */
    block_device_t* dev = kmalloc(sizeof(block_device_t));
    if (!dev) {
        return NULL;
    }

    /* 分配私有数据 */
    ata_block_dev_t* ata_dev = kmalloc(sizeof(ata_block_dev_t));
    if (!ata_dev) {
        kfree(dev);
        return NULL;
    }

    /* 初始化私有数据 */
    ata_dev->ata_device = ata_device;
    ata_dev->initialized = true;

    /* 获取设备信息 */
    ata_device_info_t info;
    if (ata_get_info(ata_device, &info) != ATA_OK) {
        kfree(ata_dev);
        kfree(dev);
        return NULL;
    }

    /* 初始化块设备 */
    dev->dev_id = ata_device;
    dev->block_size = 512;
    dev->nblocks = info.lba_sectors;
    dev->size = info.lba_sectors * 512;
    dev->ops = &ata_block_ops;
    dev->private_data = ata_dev;

    /* 设置设备名称 */
    switch (ata_device) {
        case ATA_PRIMARY_MASTER:   strcpy(dev->name, "hda"); break;
        case ATA_PRIMARY_SLAVE:    strcpy(dev->name, "hdb"); break;
        case ATA_SECONDARY_MASTER: strcpy(dev->name, "hdc"); break;
        case ATA_SECONDARY_SLAVE:  strcpy(dev->name, "hdd"); break;
    }

    return dev;
}
```

这个函数展示了资源分配的一个常见模式：先分配所有需要的资源，如果任何一步失败，就释放之前分配的资源并返回错误。这样可以避免资源泄漏。

系统初始化函数会探测所有可能的 ATA 设备，并为存在的设备创建块设备：

```c
int ata_block_init(void) {
    int count = 0;

    /* 先初始化 ATA 驱动 */
    if (ata_init() != 0) {
        return 0;
    }

    /* 探测并创建块设备 */
    for (int i = 0; i < 4; i++) {
        if (ata_device_exists(i)) {
            block_device_t* dev = ata_create_block_device(i);
            if (dev && block_device_register(dev) == BLOCK_OK) {
                count++;
            }
        }
    }

    klog_info("block: Initialized %d ATA block device(s)\n", count);
    return count;
}
```

这种自动探测的设计让系统可以灵活地适应不同的硬件配置。有的机器可能只有一块硬盘，有的可能有多个，我们的代码都能正确处理。

## 验证测试

现在我们可以测试一下块设备层是否正常工作。修改内核初始化代码，在 ATA 驱动初始化之后调用 `block_init()`：

```c
/* 在 kernel_init() 中 */
int block_count = block_init();
klog_info("Found %d block device(s)\n", block_count);

/* 测试读取 */
if (block_count > 0) {
    block_device_t* dev = block_device_get(0);
    if (dev) {
        char buffer[512];
        int result = block_read_sync(dev, 0, buffer, 1);
        if (result > 0) {
            klog_info("Successfully read %d sectors from %s\n", result, dev->name);
        }
        block_device_put(dev);
    }
}
```

编译并运行，你应该能在串口输出中看到类似这样的信息：

```
[ATA] Initialized ATA subsystem
[block] Registered device 0 as hda (size=8192 MB)
[block] Initialized 1 ATA block device(s)
Found 1 block device(s)
Successfully read 1 sectors from hda
```

如果看到这个输出，恭喜你，块设备层已经正常工作了！

## 小结

到这里我们已经完成了块设备层的实现。这一层虽然代码不多，但设计上的考虑不少。

通过函数指针表实现的多态机制，我们把底层硬件差异抽象掉了。文件系统代码只需要调用 `block_read_sync()` 和 `block_write_sync()`，不需要关心底层是 ATA、SATA 还是其他什么设备。引用计数机制为资源生命周期管理打下了基础，自动探测设计让系统能适应不同的硬件配置。

最重要的是，我们建立了一个清晰的分层架构。块设备层专注于设备的抽象和管理，文件系统层专注于数据的组织和命名，每一层都有明确的职责。这种分层设计是操作系统架构的核心思想，理解了这一点，后面实现 VFS 和 EXT2 就会顺畅很多。

接下来我们将进入 VFS 层，开始设计文件系统的核心数据结构。那将是更加精彩的部分。

# EXT2 磁盘结构解析 —— 读懂硬盘上的数据

现在我们从 VFS 抽象层深入到具体的文件系统实现 —— EXT2。EXT2 的磁盘结构设计非常经典，理解它不仅让我们能实现文件系统，还能学到很多存储系统设计的智慧。

EXT2 把磁盘分成固定大小的块，然后用多种数据结构来管理这些块：超级块存储文件系统全局信息，块组描述符管理块组，inode 存储文件元数据，数据块存储实际内容。这种分层设计让 EXT2 既高效又可靠。

## EXT2 磁盘布局

EXT2 的磁盘布局如下：

```
┌────────────────────────────────────────────────────────────┐
│                      引导块 (1024 字节)                     │
├────────────────────────────────────────────────────────────┤
│                      超级块 (1024 字节)                     │
│                    - 文件系统全局信息                        │
│                    - 魔数 0xEF53                            │
├────────────────────────────────────────────────────────────┤
│  块组 0                        │  块组 1        │  ...      │
│  ├─ 块位图                      │  (重复结构)      │           │
│  ├─ inode 位图                  │                 │           │
│  ├─ inode 表                    │                 │           │
│  └─ 数据块                      │                 │           │
└────────────────────────────────────────────────────────────┘
```

引导块是留给 bootloader 的，EXT2 不使用。超级块从 1024 字节偏移开始，包含文件系统的关键参数。每个块组都有块位图、inode 位图、inode 表和数据块，管理一部分磁盘空间。

块组的设计有几个好处：首先，把文件系统分成多个块组可以减少寻址时间 —— 相关的数据（目录和其中的文件）往往在同一个块组内。其次，块位图和 inode 位图只需要管理一个块组的大小，不会太大。最后，这种结构方便并行管理和扩展。

## 超级块结构

超级块是 EXT2 最重要的数据结构，它在磁盘上的定义如下：

```c
typedef struct PACKED ext2_superblock {
    uint32_t s_inodes_count;       /* inode 总数 */
    uint32_t s_blocks_count;       /* 块总数 */
    uint32_t s_r_blocks_count;     /* 保留块数 */
    uint32_t s_free_blocks_count;  /* 空闲块数 */
    uint32_t s_free_inodes_count;  /* 空闲 inode 数 */
    uint32_t s_first_data_block;   /* 第一个数据块 */
    uint32_t s_log_block_size;     /* 块大小 = 1024 << s_log_block_size */
    uint32_t s_log_frag_size;      /* 片段大小 */
    uint32_t s_blocks_per_group;   /* 每组块数 */
    uint32_t s_frags_per_group;    /* 每组片段数 */
    uint32_t s_inodes_per_group;   /* 每组 inode 数 */
    uint32_t s_mtime;              /* 挂载时间 */
    uint32_t s_wtime;              /* 写入时间 */
    uint16_t s_mnt_count;          /* 挂载计数 */
    uint16_t s_max_mnt_count;      /* 最大挂载计数 */
    uint16_t s_magic;              /* 魔数 0xEF53 */
    uint16_t s_state;              /* 文件系统状态 */
    /* ... 更多字段 ... */
} ext2_superblock_t;
```

超级块在磁盘的 1024 字节偏移处，我们可以这样读取：

```c
static int ext2_read_sb_raw(block_device_t* dev, ext2_superblock_t* ext2_sb) {
    /* 计算扇区号 */
    uint64_t sector = EXT2_SUPERBLOCK_OFFSET / 512;  /* 扇区 2 */

    /* 读取两个扇区 (1024 字节) */
    int result = block_read_sync(dev, sector, ext2_sb, 2);
    if (result != 2) {
        return -1;
    }

    /* 验证魔数 */
    if (ext2_sb->s_magic != EXT2_SUPERBLOCK_MAGIC) {
        klog_error("ext2: Invalid magic number 0x%x\n", ext2_sb->s_magic);
        return -1;
    }

    return 0;
}
```

注意这里读取了两个扇区（1024 字节），虽然超级块本身可能不到 1024 字节，但完整的读取可以确保我们获取所有数据。

## 块大小计算

EXT2 支持多种块大小，通过 `s_log_block_size` 字段指定：

```c
/* 块大小 = 1024 << s_log_block_size */
uint32_t block_size = 1024 << ext2_sb->s_log_block_size;
```

- `s_log_block_size = 0`：块大小 1024 字节
- `s_log_block_size = 1`：块大小 2048 字节
- `s_log_block_size = 2`：块大小 4096 字节

这种设计让 EXT2 可以适应不同的使用场景。小块适合小文件多的场景，大块适合大文件多的场景。

## 块组描述符

每个块组都有一个块组描述符，记录该组的关键信息：

```c
typedef struct PACKED ext2_block_group_desc {
    uint32_t bg_block_bitmap;      /* 块位图块号 */
    uint32_t bg_inode_bitmap;      /* inode 位图块号 */
    uint32_t bg_inode_table;       /* inode 表块号 */
    uint16_t bg_free_blocks_count; /* 空闲块数 */
    uint16_t bg_free_inodes_count; /* 空闲 inode 数 */
    uint16_t bg_used_dirs_count;   /* 已用目录数 */
    uint16_t bg_pad;
    uint32_t bg_reserved[3];
} ext2_block_group_desc_t;
```

块组描述符紧跟在超级块后面。我们需要先计算有多少个块组，然后读取相应数量的描述符：

```c
/* 计算块组数量 */
uint32_t blocks_per_group = ext2_sb->s_blocks_per_group;
uint32_t blocks_count = ext2_sb->s_blocks_count;
uint32_t ngroups = (blocks_count + blocks_per_group - 1) / blocks_per_group;

/* 计算描述符占用的块数 */
uint32_t bg_desc_size = ngroups * sizeof(ext2_block_group_desc_t);
uint32_t bg_desc_blocks = (bg_desc_size + block_size - 1) / block_size;

/* 读取块组描述符 */
ext2_block_group_desc_t* bg_desc = kmalloc(bg_desc_blocks * block_size);
uint32_t start_block = (block_size == 1024) ? 2 : 1;  /* 描述符起始块 */
block_read_sync(dev, start_block * (block_size / 512), bg_desc, bg_desc_blocks * (block_size / 512));
```

块组描述符的起始位置取决于块大小。对于 1024 字节块，超级块占用块 1，描述符从块 2 开始。对于更大的块，超级块在块 0 的偏移 1024 处，描述符从块 1 开始。

## 块组内部结构

每个块组内部包含以下内容：

```
┌────────────────────────────────────────┐
│  块位图 (1 块)                         │  标记数据块使用情况
├────────────────────────────────────────┤
│  inode 位图 (1 块)                     │  标记 inode 使用情况
├────────────────────────────────────────┤
│  inode 表 (多块)                       │  存储该组的 inode
├────────────────────────────────────────┤
│  数据块 (剩余块)                       │  存储实际数据
└────────────────────────────────────────┘
```

块位图的每一位对应一个数据块，1 表示已使用，0 表示空闲。inode 位图类似，标记 inode 的使用情况。这种位图设计非常高效，可以快速查找和分配空间。

## 计算辅助宏

为了方便计算，我们定义了一些辅助宏：

```c
/* 获取块大小 */
#define EXT2_BLOCK_SIZE(sb) (1024 << (sb)->s_log_block_size)

/* 计算块包含的块组 */
#define EXT2_BLOCK_GROUP(sb, block) ((block) / (sb)->s_blocks_per_group)

/* 计算 inode 所属的块组 */
#define EXT2_INODE_GROUP(sb, inode) (((inode) - 1) / (sb)->s_inodes_per_group)

/* 计算块组内的局部 inode 号 */
#define EXT2_LOCAL_INODE(sb, inode) (((inode) - 1) % (sb)->s_inodes_per_group)

/* 计算块组描述符占用的块数 */
#define EXT2_BG_DESC_BLOCKS(sb, ngroups) ((((ngroups) * sizeof(ext2_block_group_desc_t)) + \
                                           EXT2_BLOCK_SIZE(sb) - 1) / EXT2_BLOCK_SIZE(sb))
```

这些宏简化了常见的计算，让代码更清晰易读。

## 数据的端序处理

EXT2 磁盘数据使用小端序（little-endian）存储。x86 架构也是小端序，所以在我们的环境中不需要特殊处理。但如果移植到大端序架构，就需要进行字节序转换。

```c
/* 小端序到大端序的转换（如果需要） */

#define le16_to_cpu(x) (x)
```

## 验证和调试

读取超级块后，我们应该验证数据的正确性：

```c
/* 验证魔数 */
if (ext2_sb->s_magic != EXT2_SUPERBLOCK_MAGIC) {
    klog_error("ext2: Bad magic number 0x%x\n", ext2_sb->s_magic);
    return -1;
}

/* 检查块大小是否合理 */
uint32_t block_size = EXT2_BLOCK_SIZE(ext2_sb);
if (block_size < 1024 || block_size > 4096) {
    klog_warn("ext2: Unusual block size %u\n", block_size);
}

/* 打印关键信息 */
klog_info("ext2: Block size: %u bytes\n", block_size);
klog_info("ext2: Blocks per group: %u\n", ext2_sb->s_blocks_per_group);
klog_info("ext2: Inodes per group: %u\n", ext2_sb->s_inodes_per_group);
klog_info("ext2: Block groups: %u\n", ngroups);
```

这些验证可以及早发现问题，比如读取了错误的磁盘或者文件系统被损坏。

## 小结

EXT2 的磁盘结构设计非常经典。超级块存储全局参数，块组把磁盘分成可管理的单元，块位图和 inode 位图高效管理空间，inode 表存储文件元数据，数据块存储实际内容。这种分层设计让 EXT2 既高效又可靠。

理解 EXT2 的磁盘布局是实现文件系统的基础。下一步我们将学习如何读取和操作 inode，它是文件系统的核心数据结构。

# EXT2 文件读写 —— 终于能读文件了

经过这么多准备工作，我们终于可以实现文件读写了。这是文件系统的核心功能 —— 把数据从磁盘读入内存，或者把内存数据写入磁盘。

文件读写的实现依赖于之前建立的所有组件：块设备层提供 I/O，VFS 提供接口，inode 缓存管理元数据，dentry 缓存加速查找，EXT2 提供具体实现。所有组件协同工作，才能实现完整的文件读写功能。

## 文件读取实现

`ext2_file_read()` 函数实现从文件读取数据：

```c
ssize_t ext2_file_read(struct file* file, char* buffer, size_t count, uint64_t* pos) {
    vfs_inode_t* inode = file->f_inode;
    ext2_fs_info_t* fs_info = inode->i_sb->s_fs_info;
    uint32_t block_size = fs_info->block_size;

    /* 检查文件位置是否超出文件大小 */
    if (*pos >= inode->i_size) {
        return 0;  /* EOF */
    }

    /* 调整读取量，不超过文件剩余部分 */
    uint64_t remaining = inode->i_size - *pos;
    if (count > remaining) {
        count = remaining;
    }

    size_t total_read = 0;
    uint8_t* block_buffer = kmalloc(block_size);

    while (count > 0) {
        /* 计算当前块内偏移 */
        uint32_t offset_in_block = *pos % block_size;
        uint32_t bytes_in_block = block_size - offset_in_block;

        /* 本次要读的字节数 */
        size_t to_read = (count < bytes_in_block) ? count : bytes_in_block;

        /* 获取文件块号 */
        uint64_t block_num;
        if (ext2_get_block(inode, *pos, &block_num) != 0) {
            break;
        }

        if (block_num == 0) {
            /* 稀疏文件的空洞 */
            memset(buffer + total_read, 0, to_read);
        } else {
            /* 读取块 */
            block_read_sync(fs_info->device, block_num * (block_size / 512),
                            block_buffer, block_size / 512);

            /* 复制数据到用户缓冲区 */
            memcpy(buffer + total_read, block_buffer + offset_in_block, to_read);
        }

        /* 更新状态 */
        *pos += to_read;
        total_read += to_read;
        count -= to_read;
    }

    kfree(block_buffer);
    return total_read;
}
```

这个函数处理了几个重要的细节。首先，它检查文件位置是否超出文件大小，如果超出就返回 EOF。其次，它使用 `ext2_get_block()` 把文件偏移转换成块号。再次，它处理了跨块读取的情况 —— 一次读取可能跨越多个块。最后，它正确处理了稀疏文件的空洞。

## 文件写入实现

文件写入比读取复杂，因为可能需要分配新块：

```c
ssize_t ext2_file_write(struct file* file, const char* buffer, size_t count, uint64_t* pos) {
    vfs_inode_t* inode = file->f_inode;
    ext2_fs_info_t* fs_info = inode->i_sb->s_fs_info;
    uint32_t block_size = fs_info->block_size;

    size_t total_written = 0;
    uint8_t* block_buffer = kmalloc(block_size);

    while (count > 0) {
        /* 计算当前块内偏移 */
        uint32_t offset_in_block = *pos % block_size;
        uint32_t bytes_in_block = block_size - offset_in_block;

        /* 本次要写的字节数 */
        size_t to_write = (count < bytes_in_block) ? count : bytes_in_block;

        /* 获取文件块号 */
        uint64_t block_num;
        if (ext2_get_block(inode, *pos, &block_num) != 0) {
            break;
        }

        /* 如果块不存在，需要分配 */
        if (block_num == 0) {
            block_num = ext2_alloc_block(fs_info);
            if (block_num == 0) {
                break;  /* 分配失败 */
            }
            /* 更新 inode 的块指针 */
            ext2_set_block(inode, *pos, block_num);
        }

        /* 如果不是完全覆盖块，先读取原内容 */
        if (offset_in_block != 0 || to_write < bytes_in_block) {
            block_read_sync(fs_info->device, block_num * (block_size / 512),
                            block_buffer, block_size / 512);
        }

        /* 修改数据 */
        memcpy(block_buffer + offset_in_block, buffer + total_written, to_write);

        /* 写回块 */
        block_write_sync(fs_info->device, block_num * (block_size / 512),
                         block_buffer, block_size / 512);

        /* 更新状态 */
        *pos += to_write;
        total_written += to_write;
        count -= to_write;

        /* 更新文件大小 */
        if (*pos > inode->i_size) {
            inode->i_size = *pos;
        }
    }

    kfree(block_buffer);

    /* 标记 inode 为脏 */
    vfs_mark_inode_dirty(inode);

    return total_written;
}
```

写入函数需要注意几个问题。首先，如果写入不是从块边界开始，或者没有完全覆盖块，需要先读取原内容。这叫做"读-改-写"模式。其次，写入可能需要分配新块，这涉及块位图的管理。最后，写入后需要更新文件大小并标记 inode 为脏。

## 文件定位

`ext2_file_llseek()` 实现文件定位：

```c
uint64_t ext2_file_llseek(struct file* file, uint64_t offset, int whence) {
    uint64_t new_pos;

    switch (whence) {
        case SEEK_SET:
            new_pos = offset;
            break;
        case SEEK_CUR:
            new_pos = file->f_pos + offset;
            break;
        case SEEK_END:
            new_pos = file->f_inode->i_size + offset;
            break;
        default:
            return -1;
    }

    /* 不允许定位到文件开头之前 */
    if (new_pos > UINT64_MAX - offset) {
        return -1;
    }

    file->f_pos = new_pos;
    return new_pos;
}
```

这个函数支持三种定位方式：从文件开头（SEEK_SET）、从当前位置（SEEK_CUR）、从文件结尾（SEEK_END）。

## VFS 层的读写函数

VFS 层提供统一的读写接口，内部调用具体文件系统的实现：

```c
ssize_t vfs_read(file_t* file, char* buffer, size_t count) {
    if (!file || !buffer || count == 0) {
        return -1;
    }

    /* 检查权限 */
    if ((file->f_flags & O_ACCMODE) == O_WRONLY) {
        return -1;
    }

    /* 调用文件系统的 read 函数 */
    if (file->f_op && file->f_op->read) {
        return file->f_op->read(file, buffer, count, &file->f_pos);
    }

    return -1;
}

ssize_t vfs_write(file_t* file, const char* buffer, size_t count) {
    if (!file || !buffer || count == 0) {
        return -1;
    }

    /* 检查权限 */
    if ((file->f_flags & O_ACCMODE) == O_RDONLY) {
        return -1;
    }

    /* 调用文件系统的 write 函数 */
    if (file->f_op && file->f_op->write) {
        return file->f_op->write(file, buffer, count, &file->f_pos);
    }

    return -1;
}
```

这些函数检查权限后，调用具体文件系统的操作。这种设计让上层代码不需要关心文件系统类型。

## 文件操作表

EXT2 文件操作通过函数指针表注册：

```c
const file_operations_t ext2_file_ops = {
    .llseek = ext2_file_llseek,
    .read = ext2_file_read,
    .write = ext2_file_write,
    .readdir = NULL,  /* 普通文件没有 readdir */
    .open = NULL,
    .release = NULL,
};
```

## 性能考虑

文件读写的性能涉及多个因素。首先是块大小，较大的块可以减少 I/O 次数，但可能浪费空间。其次是缓存，我们目前使用同步 I/O，每次都访问磁盘。未来可以添加块缓存来减少磁盘访问。

最后是顺序访问模式，EXT2 的块分配策略会尝试让文件的数据块连续存储，这可以提高顺序读取的性能。

## 小结

文件读写是文件系统的最终目标。通过层层抽象，我们实现了从路径名到磁盘数据的完整通路：VFS 提供接口，dentry 缓存加速查找，inode 缓存管理元数据，块设备层执行 I/O，EXT2 实现具体逻辑。

目前实现的是同步 I/O，每次读写都直接访问磁盘。这虽然简单，但性能有限。未来可以添加块缓存、预读、延迟写等优化，大幅提升性能。

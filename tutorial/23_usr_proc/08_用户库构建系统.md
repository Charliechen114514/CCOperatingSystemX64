# 用户库构建系统 —— Freestanding 与 CMake

## 前言

在之前的一些教程中，我们实现了内核和用户态支持。现在有一个问题：用户程序怎么编译？

用户程序和内核程序有一个关键区别：
- 内核程序是我们自己控制的，可以和内核代码链接
- 用户程序是独立的，不能依赖内核符号

而且，用户程序运行在一个"freestanding"环境中。这是 C 标准的一个术语，指的是没有标准库支持的环境。

说实话，配置 freestanding 环境的编译系统比我预想的要麻烦。有太多编译器标志需要设置，有太多陷阱要避免。如果配置不对，程序可能会用上 libc 的函数（但我们没有 libc），或者生成的代码有 Red Zone（用户态不能有），或者地址模型不对...

这篇文章我们会从头建立一个用户库的构建系统，确保用户程序能在我们的用户态环境中正确运行。

---

## Freestanding 环境是什么？

首先，我们需要理解什么是 freestanding 环境。

### Hosted vs Freestanding

C 标准定义了两种执行环境：

**Hosted 环境**
- 完整的 C 运行时支持
- 标准库函数可用（`printf`, `malloc`, etc.）
- 程序从 `main()` 开始
- 这是大多数应用程序运行的环境

**Freestanding 环境**
- 最小的运行时支持
- 只有少数必需的库函数
- 程序从自定义入口点开始
- 这是操作系统内核和嵌入式程序的环境

### 我们的场景

我们的用户程序运行在一个特殊的 freestanding 环境中：
- 没有 libc
- 只有我们提供的 userlib
- 通过系统调用访问内核服务
- 程序从 `_start()` 开始

## CMakeLists.txt 主配置

创建 `user/CMakeLists.txt`：

```cmake
# ============================================================================
# CCOS User Mode C Library
# ============================================================================

cmake_minimum_required(VERSION 3.20)

# Add the user library
add_library(userlib STATIC
    src/stdio.c
    src/stdlib.c
    src/unistd.c
    syscall/x86_64/syscall.c
)

# Include directories
target_include_directories(userlib PUBLIC
    ${CMAKE_SOURCE_DIR}/user/include
    ${CMAKE_SOURCE_DIR}/user/syscall/include
    ${CMAKE_SOURCE_DIR}/kernel/defines
)

# Compiler flags for freestanding environment
target_compile_options(userlib PRIVATE
    ${CCOS_FREESTANDING_COMPILE_FLAGS}
    -mno-red-zone
)

# Disable PIC for user library
set_target_properties(userlib PROPERTIES
    POSITION_INDEPENDENT_CODE FALSE
)
```

### 解释各个部分

**库定义**

```cmake
add_library(userlib STATIC
    src/stdio.c
    src/stdlib.c
    src/unistd.c
    syscall/x86_64/syscall.c
)
```

我们创建一个静态库 `userlib`，包含所有用户库的源文件。

**头文件路径**

```cmake
target_include_directories(userlib PUBLIC
    ${CMAKE_SOURCE_DIR}/user/include
    ${CMAKE_SOURCE_DIR}/user/syscall/include
    ${CMAKE_SOURCE_DIR}/kernel/defines
)
```

注意我们还包含了 `kernel/defines`，因为我们需要类型定义（`uint64_t` 等）。

**编译器标志**

```cmake
target_compile_options(userlib PRIVATE
    ${CCOS_FREESTANDING_COMPILE_FLAGS}
    -mno-red-zone
)
```

`CCOS_FREESTANDING_COMPILE_FLAGS` 应该在主 `CMakeLists.txt` 中定义。

## Freestanding 编译标志

在主 `CMakeLists.txt` 中，我们需要定义 freestanding 编译标志：

```cmake
# ============================================================================
# Freestanding Compilation Flags
# ============================================================================

# Common flags for freestanding environment (kernel and user)
set(CCOS_FREESTANDING_COMPILE_FLAGS
    -ffreestanding          # Freestanding environment
    -fno-builtin            # Don't use builtin functions
    -fno-stack-protector    # No stack protector
    -fno-exceptions         # No C++ exceptions (for C++)
    -fno-rtti              # No RTTI (for C++)
    -fno-pie               # Not position independent executable
    -fno-pic               # Not position independent code
    -mcmodel=large         # Large code model (for kernel address space)
    -mno-mmx               # Disable MMX
    -mno-sse               # Disable SSE
    -mno-sse2              # Disable SSE2
    -Wall                  # All warnings
    -Wextra                # Extra warnings
    -Werror                # Treat warnings as errors
)

# Additional flags for user programs
set(CCOS_USER_COMPILE_FLAGS
    ${CCOS_FREESTANDING_COMPILE_FLAGS}
    -mno-red-zone          # No red zone (critical for user mode!)
)
```

### 每个标志的含义

**`-ffreestanding`**

告诉编译器这是一个 freestanding 环境，不需要提供标准库支持。

**`-fno-builtin`**

禁用内置函数。没有这个标志，编译器可能会用内置的 `memcpy`、`strlen` 等，但我们没有提供这些实现。

**`-fno-stack-protector`**

禁用栈保护。栈保护需要特定的运行时支持，在 freestanding 环境中不可用。

**`-mcmodel=large`**

使用大代码模型。这对于内核很重要，因为内核地址空间跨越整个 64 位范围。

**`-mno-red-zone`**

⚠️ **这是最重要的标志！**

x86_64 ABI 定义了一个 128 字节的"红区"在栈指针之下。系统调用会破坏这个区域，所以用户代码不能使用它。

**`-mno-mmx -mno-sse -mno-sse2`**

禁用 SIMD 指令集。这些指令需要保存额外的寄存器状态，增加了上下文切换的复杂度。

## 系统调用包装

用户库需要提供系统调用的包装函数。

### syscall.h

创建 `user/syscall/include/syscall.h`：

```c
/**
 * @file syscall.h
 * @brief System call wrapper definitions
 */

#pragma once

#include <stdint.h>

/* System call numbers */
#define SYS_EXIT        0
#define SYS_READ        3
#define SYS_WRITE       13
#define SYS_FORK        57
#define SYS_GETPID      39
#define SYS_GETPPID     110
#define SYS_BRK         20
#define SYS_MMAP        21
#define SYS_MUNMAP      22
#define SYS_UNAME       30

/* System call wrapper functions */
static inline long _syscall0(long num) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num)
                      : "rcx", "r11", "memory");
    return ret;
}

static inline long _syscall1(long num, long arg1) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1)
                      : "rcx", "r11", "memory");
    return ret;
}

static inline long _syscall2(long num, long arg1, long arg2) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1), "S"(arg2)
                      : "rcx", "r11", "memory");
    return ret;
}

static inline long _syscall3(long num, long arg1, long arg2, long arg3) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1), "S"(arg2), "d"(arg3)
                      : "rcx", "r11", "memory");
    return ret;
}

static inline long _syscall6(long num, long arg1, long arg2, long arg3,
                             long arg4, long arg5, long arg6) {
    long ret;
    register long r8 asm("r8") = arg4;
    register long r9 asm("r9") = arg5;
    register long r10 asm("r10") = arg6;
    __asm__ volatile("syscall"
                      : "=a"(ret)
                      : "a"(num), "D"(arg1), "S"(arg2), "d"(arg3), "r"(r8), "r"(r9), "r"(r10)
                      : "rcx", "r11", "memory");
    return ret;
}
```

### syscall.c

创建 `user/syscall/x86_64/syscall.c`：

```c
/**
 * @file syscall.c
 * @brief System call wrapper implementations
 */

#include "syscall.h"

/* This file primarily exists for compilation consistency.
 * The actual syscall wrappers are inline functions in syscall.h
 */

/* Some non-inline wrappers might be added here if needed */
```

## 用户库头文件

### stdint.h

创建 `user/include/stdint.h`：

```c
/**
 * @file stdint.h
 * @brief Standard integer types
 */

#pragma once

typedef __INT8_TYPE__ int8_t;
typedef __INT16_TYPE__ int16_t;
typedef __INT32_TYPE__ int32_t;
typedef __INT64_TYPE__ int64_t;

typedef __UINT8_TYPE__ uint8_t;
typedef __UINT16_TYPE__ uint16_t;
typedef __UINT32_TYPE__ uint32_t;
typedef __UINT64_TYPE__ uint64_t;

typedef __INT64_TYPE__ intptr_t;
typedef __INT64_TYPE__ uintptr_t;

typedef __INT64_TYPE__ intmax_t;
typedef __UINT64_TYPE__ uintmax_t;
```

⚠️ **使用编译器内置类型**

我们使用编译器内置的类型宏（`__INT64_TYPE__` 等），这样可以跨不同编译器工作。

```c
/**
 * @file unistd.h
 * @brief POSIX standard symbolic constants and types
 */

#pragma once

#include <stddef.h>
#include <stdint.h>

/* Standard file descriptors */
#define STDIN_FILENO    0
#define STDOUT_FILENO   1
#define STDERR_FILENO   2

/* utsname structure for uname() */
struct utsname {
    char sysname[65];
    char nodename[65];
    char release[65];
    char version[65];
    char machine[65];
    char domainname[65];
};

/* Process management */
void exit(int status) __attribute__((noreturn));
int fork(void);
int getpid(void);
int getppid(void);

/* File I/O */
ssize_t write(int fd, const void* buf, size_t count);
ssize_t read(int fd, void* buf, size_t count);
int close(int fd);

/* Memory management */
void* sbrk(intptr_t incr);
void* mmap(void* addr, size_t length, int prot, int flags,
          int fd, size_t offset);
int munmap(void* addr, size_t length);

/* System information */
int uname(struct utsname* buf);

/* Constants for mmap */
#define PROT_READ      0x1
#define PROT_WRITE     0x2
#define PROT_EXEC      0x4

#define MAP_SHARED     0x01
#define MAP_PRIVATE    0x02
#define MAP_FIXED      0x10
#define MAP_ANONYMOUS  0x20
```

## 验证测试

让我们写一个简单的测试程序来验证用户库：

```c
/* test_userlib.c - Simple test of user library */

#include "stdio.h"
#include "stdlib.h"
#include "unistd.h"

void _start(void) {
    /* Test printf */
    printf("Testing user library...\n");

    /* Test malloc/free */
    void* ptr = malloc(100);
    if (ptr) {
        printf("malloc(100) = %p\n", ptr);
        free(ptr);
        printf("free() succeeded\n");
    } else {
        printf("malloc() failed!\n");
    }

    /* Test uname */
    struct utsname uts;
    if (uname(&uts) == 0) {
        printf("System: %s %s\n", uts.sysname, uts.release);
    } else {
        printf("uname() failed!\n");
    }

    /* Exit */
    exit(0);
}
```

⚠️ **注意：测试程序需要单独配置**

这个测试程序不能直接链接 userlib，因为它需要配置为用户程序。我们会在下一篇文章中详细介绍如何配置用户程序。

## 常见问题

### 问题 1：Red Zone 错误

**症状**：程序在系统调用后崩溃

**原因**：编译器使用了 Red Zone，但系统调用破坏了它

**解决**：确保使用 `-mno-red-zone` 标志

```cmake
target_compile_options(userlib PRIVATE
    -mno-red-zone  # 必须有！
)
```

### 问题 2：未定义的引用

**症状**：链接时报错 `undefined reference to 'memcpy'`

**原因**：编译器生成了对内置函数的调用

**解决**：添加 `-fno-builtin` 标志，或者提供缺失的函数实现

### 问题 3：栈不对齐

**症状**：程序在 SSE 指令处崩溃

**原因**：栈没有 16 字节对齐

**解决**：确保 `_start()` 入口正确设置栈，或者链接脚本正确对齐栈

### 问题 4：段寄存器错误

**症状**：访问用户变量时崩溃

**原因**：段寄存器设置错误

**解决**：这在汇编代码中处理，确保在切换到用户态前设置正确的段选择器

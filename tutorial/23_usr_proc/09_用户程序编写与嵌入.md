# 用户程序编写与嵌入

## 前言

在上一篇文章中，我们建立了用户库的构建系统。现在我们可以编译用户库了，但还有一个关键问题：**用户程序怎么加载到内核中？**

在有文件系统的操作系统上，这个问题很简单：内核从磁盘读取 ELF 文件，解析它，加载到内存。但我们还没有文件系统。

所以我们采用一个简化的方案：**在编译时将用户程序嵌入内核镜像**。

这样做的好处：
- 不需要文件系统
- 不需要 ELF 加载器
- 程序在编译时就确定了

代价：
- 添加或修改程序需要重新编译内核
- 不能动态加载程序
- 程序大小受内核镜像限制

对于早期开发来说，这是一个合理的权衡。

这篇文章我们会学习如何编写用户程序，并将它们嵌入到内核镜像中。

---

## 用户程序的结构

用户程序有几个特殊要求：

### 1. 入口点

用户程序不从 `main()` 开始，而是从 `_start()` 开始：

```c
void _start(void) {
    /* 用户程序代码 */
    exit(0);  /* 必须显式退出 */
}
```

### 2. 不返回

`_start()` 是程序的真正入口点，它不应该返回。如果返回，行为是未定义的。程序必须显式调用 `exit()` 系统调用。

### 3. 独立的系统调用包装

用户程序可以使用 userlib，但也可以直接使用内联系统调用：

```c
static inline long syscall1(long num, long arg1) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1)
                      : "rcx", "r11", "memory");
    return ret;
}

void exit(int status) {
    syscall1(SYS_EXIT, status);
    __builtin_unreachable();
}
```

## 编写用户程序

让我们写一个完整的用户程序示例。

### uname_test.c

```c
/* ==============================================================================
 * User Mode Demo Program - uname syscall test
 * ==============================================================================
 *
 * This is a simple user mode program that:
 * 1. Calls uname() syscall to get system information
 * 2. Prints the uname structure using write() syscall
 * 3. Exits with exit() syscall
 *
 * NOTE: This program is compiled separately and loaded by the kernel.
 * It must NOT link against any library functions to avoid symbol conflicts.
 * ==============================================================================
 */

/* System call numbers (must match kernel) */
#define SYS_EXIT        0
#define SYS_WRITE       13
#define SYS_UNAME       30

/* File descriptors */
#define STDOUT_FILENO   1

/* utsname structure */
struct utsname {
    char sysname[65];
    char nodename[65];
    char release[65];
    char version[65];
    char machine[65];
    char domainname[65];
};

/* ==============================================================================
 * System Call Wrappers (inline to avoid external dependencies)
 * ============================================================================== */

static inline long syscall0(long num) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num) : "rcx", "r11", "memory");
    return ret;
}

static inline long syscall1(long num, long arg1) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1) : "rcx", "r11", "memory");
    return ret;
}

static inline long syscall3(long num, long arg1, long arg2, long arg3) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1), "S"(arg2), "d"(arg3)
                      : "rcx", "r11", "memory");
    return ret;
}

static void exit(int status) {
    syscall1(SYS_EXIT, status);
    __builtin_unreachable();
}

static long write(int fd, const void* buf, long count) {
    return syscall3(SYS_WRITE, fd, (long)buf, count);
}

static int uname(struct utsname* buf) {
    return (int)syscall1(SYS_UNAME, (long)buf);
}

/* ==============================================================================
 * Simple string length (inline to avoid conflicts)
 * ============================================================================== */

static long str_len(const char* s) {
    long len = 0;
    while (s[len]) len++;
    return len;
}

/* ==============================================================================
 * Main Program
 * ============================================================================== */

void _start(void) {
    struct utsname uts;
    char newline = '\n';

    /* Call uname */
    int ret = uname(&uts);
    if (ret != 0) {
        /* Error: write error message */
        const char* err = "uname() failed!\n";
        write(STDOUT_FILENO, err, 16);
        exit(1);
    }

    /* Print sysname */
    const char* sysname_label = "sysname: ";
    write(STDOUT_FILENO, sysname_label, 9);
    long len = str_len(uts.sysname);
    write(STDOUT_FILENO, uts.sysname, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Print nodename */
    const char* nodename_label = "nodename: ";
    write(STDOUT_FILENO, nodename_label, 10);
    len = str_len(uts.nodename);
    write(STDOUT_FILENO, uts.nodename, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Print release */
    const char* release_label = "release: ";
    write(STDOUT_FILENO, release_label, 9);
    len = str_len(uts.release);
    write(STDOUT_FILENO, uts.release, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Print version */
    const char* version_label = "version: ";
    write(STDOUT_FILENO, version_label, 9);
    len = str_len(uts.version);
    write(STDOUT_FILENO, uts.version, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Print machine */
    const char* machine_label = "machine: ";
    write(STDOUT_FILENO, machine_label, 9);
    len = str_len(uts.machine);
    write(STDOUT_FILENO, uts.machine, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Print domainname */
    const char* domainname_label = "domainname: ";
    write(STDOUT_FILENO, domainname_label, 13);
    len = str_len(uts.domainname);
    write(STDOUT_FILENO, uts.domainname, len);
    write(STDOUT_FILENO, &newline, 1);

    /* Exit successfully */
    exit(0);
}
```

### 代码解释

**内联系统调用包装**

我们使用内联函数而不是外部函数，这样避免链接依赖。每个系统调用包装都是一个小的汇编函数：

```c
static inline long syscall1(long num, long arg1) {
    long ret;
    __asm__ volatile("syscall" : "=a"(ret) : "a"(num), "D"(arg1) : "rcx", "r11", "memory");
    return ret;
}
```

**自定义字符串函数**

我们实现了一个简单的 `strlen()`，避免依赖标准库。

**错误处理**

```c
int ret = uname(&uts);
if (ret != 0) {
    const char* err = "uname() failed!\n";
    write(STDOUT_FILENO, err, 16);
    exit(1);
}
```

系统调用失败时，我们打印错误消息并退出。

## CMake 配置

现在我们需要配置 CMake 来编译和嵌入用户程序。

### 添加用户程序目标

在 `user/CMakeLists.txt` 中添加：

```cmake
# ============================================================================
# User Mode Programs (compiled as object files for kernel embedding)
# ============================================================================

# Compile uname_test as a standalone user program
add_executable(uname_test
    programs/demo/uname_test.c
)

# Configure as freestanding user program
target_compile_options(uname_test PRIVATE
    ${CCOS_FREESTANDING_COMPILE_FLAGS}
    -mno-red-zone
    -fno-pic
    -fno-pie
)

# Set entry point
target_link_options(uname_test PRIVATE
    -Wl,-e_start
    -nostdlib
    -static
)

# No include directories for user programs (they use inline syscalls)
# Only add types definition
target_include_directories(uname_test PRIVATE
    ${CMAKE_SOURCE_DIR}/kernel/defines
)

# Disable PIC
set_target_properties(uname_test PROPERTIES
    POSITION_INDEPENDENT_CODE FALSE
)
```

### 转换为二进制

接下来，我们需要将可执行文件转换为纯二进制：

```cmake
# Convert the executable to a binary file (raw machine code)
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/uname_test.bin
    DEPENDS uname_test
    COMMAND ${CMAKE_OBJCOPY} -O binary $<TARGET_FILE:uname_test> ${CMAKE_BINARY_DIR}/uname_test.bin
    COMMENT "Converting uname_test to binary"
)
```

`objcopy -O binary` 会去除所有 ELF 格式信息，只保留纯机器码。

### 创建对象文件

然后，我们将二进制文件转换为对象文件，这样就可以链接到内核：

```cmake
# Create object file from binary for kernel linking
# IMPORTANT: The section must be aligned to 4096 bytes (PAGE_SIZE) for proper page mapping
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/uname_test.o
    DEPENDS ${CMAKE_BINARY_DIR}/uname_test.bin
    COMMAND ${CMAKE_OBJCOPY} -I binary -O elf64-x86-64 -B i386
        --rename-section .data=.user_uname_test,alloc,load,readonly,data,contents
        ${CMAKE_BINARY_DIR}/uname_test.bin ${CMAKE_BINARY_DIR}/uname_test.o
    COMMENT "Creating object file from uname_test binary"
)
```

⚠️ **注意：段重命名**

我们使用 `--rename-section` 将 `.data` 段重命名为 `.user_uname_test`。这样可以避免与内核的其他数据段冲突。

## 页对齐

这是一个关键但容易被忽略的细节：用户程序必须页对齐。

### 为什么需要页对齐？

用户程序会被映射到用户空间的页上。如果程序没有页对齐：
1. 映射会变得复杂
2. 可能跨越多个页
3. 页权限设置会变得困难

### 设置对齐

```cmake
# Set the section alignment to 4096 bytes (PAGE_SIZE)
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/uname_test_aligned.o
    DEPENDS ${CMAKE_BINARY_DIR}/uname_test.o
    COMMAND ${CMAKE_OBJCOPY} --set-section-alignment .user_uname_test=4096
        ${CMAKE_BINARY_DIR}/uname_test.o ${CMAKE_BINARY_DIR}/uname_test_aligned.o
    COMMENT "Aligning .user_uname_test section to 4096 bytes"
)
```

## 符号重命名

当我们用 `objcopy` 将二进制文件转换为对象文件时，它会生成一些特殊的符号：
- `_binary_<path>_start`
- `_binary_<path>_end`
- `_binary_<path>_size`

问题是 `<path>` 包含完整的构建路径，这是不可移植的。我们需要重命名这些符号。

### 重命名脚本

创建 `user/cmake/rename_symbols.py.in`：

```python
#!/usr/bin/env python3
"""
Script to dynamically rename binary symbols for user programs
Handles the fact that objcopy generates path-based symbol names
"""
import subprocess
import sys

def main():
    if len(sys.argv) != 4:
        print("Usage: rename_symbols.py <objcopy> <input.o> <output.o>", file=sys.stderr)
        sys.exit(1)

    objcopy = sys.argv[1]
    input_obj = sys.argv[2]
    output_obj = sys.argv[3]

    # Get the symbols from the input object file
    result = subprocess.run(
        ['nm', input_obj],
        capture_output=True,
        text=True
    )

    if result.returncode != 0:
        print(f"Error running nm: {result.stderr}", file=sys.stderr)
        sys.exit(1)

    # Find the binary symbols (they start with _binary_)
    binary_start = None
    binary_end = None
    binary_size = None

    for line in result.stdout.splitlines():
        parts = line.split()
        if len(parts) >= 3:
            symbol = parts[2]
            if symbol.startswith('_binary_') and symbol.endswith('_start'):
                # Extract the base name (without _start)
                base = symbol[:-6]  # remove '_start'
                binary_start = symbol
                binary_end = base + '_end'
                binary_size = base + '_size'
                break

    if binary_start is None:
        print("Error: Could not find binary symbols in object file", file=sys.stderr)
        print(f"nm output:\n{result.stdout}", file=sys.stderr)
        sys.exit(1)

    # Build the objcopy command with symbol redefinitions
    cmd = [
        objcopy,
        f'--redefine-sym={binary_start}=_binary_user_programs_demo_uname_test_start',
        f'--redefine-sym={binary_end}=_binary_user_programs_demo_uname_test_end',
        f'--redefine-sym={binary_size}=_binary_user_programs_demo_uname_test_size',
        '--set-section-alignment=.user_uname_test=4096',
        input_obj,
        output_obj
    ]

    print(f"Renaming symbols: {binary_start} -> _binary_user_programs_demo_uname_test_start")

    result = subprocess.run(cmd, capture_output=True, text=True)

    if result.returncode != 0:
        print(f"Error running objcopy: {result.stderr}", file=sys.stderr)
        sys.exit(1)

    sys.exit(0)

if __name__ == '__main__':
    main()
```

### 配置脚本

在 `user/CMakeLists.txt` 中：

```cmake
# Helper script to dynamically rename symbols based on the actual binary path
configure_file(
    ${CMAKE_CURRENT_SOURCE_DIR}/cmake/rename_symbols.py.in
    ${CMAKE_BINARY_DIR}/rename_symbols.py
    @ONLY
)

# Create symbol mapping for the binary
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/uname_test_symbols.o
    DEPENDS ${CMAKE_BINARY_DIR}/uname_test_aligned.o ${CMAKE_BINARY_DIR}/rename_symbols.py
    COMMAND python3 ${CMAKE_BINARY_DIR}/rename_symbols.py
        ${CMAKE_OBJCOPY}
        ${CMAKE_BINARY_DIR}/uname_test_aligned.o
        ${CMAKE_BINARY_DIR}/uname_test_symbols.o
    COMMENT "Adding symbols to uname_test object"
)

# Final object file with proper symbols
add_custom_target(uname_test_obj ALL
    DEPENDS ${CMAKE_BINARY_DIR}/uname_test_symbols.o
)
```

## 常见问题

### 问题 1：符号找不到

**症状**：链接时报错 `undefined reference to _binary_user_programs_demo_uname_test_start`

**原因**：符号重命名失败，或者对象文件没有链接到内核

**解决**：
1. 检查 `nm build/uname_test_symbols.o` 的输出
2. 确保对象文件添加到内核链接列表
3. 检查符号名称是否匹配

### 问题 2：程序没有对齐

**症状**：运行时页错误，或映射失败

**原因**：段没有正确对齐到 4096 字节

**解决**：
1. 检查 `objdump -h build/uname_test_symbols.o` 的输出
2. 确保 `--set-section-alignment` 正确执行
3. 检查对齐值是否为 4096

### 问题 3：程序大小不正确

**症状**：程序执行异常或崩溃

**原因**：可能是 objcopy 转换问题

**解决**：
1. 检查 `uname_test.bin` 的大小
2. 用 `hexdump` 或 `od` 查看二进制内容
3. 确认 ELF 头被正确剥离

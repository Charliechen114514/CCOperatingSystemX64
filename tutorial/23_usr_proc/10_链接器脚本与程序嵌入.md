# 链接器脚本与程序嵌入

## 前言

在上一篇文章中，我们学习了如何将用户程序编译成二进制并转换为对象文件。但这些对象文件如何被内核访问？答案是通过链接器脚本。

说实话，链接器脚本（linker script）是我最不喜欢的东西之一。它的语法晦涩难懂，错误消息毫无帮助，而且一个小错误就会导致莫名其妙的崩溃。但是，对于嵌入式程序和操作系统开发，它是必不可少的。

链接器脚本告诉链接器如何组织程序的各个段。对于我们的内核来说，我们需要：
1. 确保内核代码和数据在正确的位置
2. 将用户程序嵌入到特定的段
3. 生成符号来定位用户程序

这篇文章我们会深入研究链接器脚本，并确保用户程序被正确嵌入。

---

## 链接器脚本基础

### 什么是链接器脚本？

链接器脚本是一个文本文件，描述了输出文件的内存布局。它控制：
- 段（sections）的放置
- 符号的赋值
- 内存区域的定义

### 基本语法

```ld
SECTIONS {
    . = 0x100000;  /* 设置当前位置 */

    .text : {      /* 定义 .text 段 */
        *(.text)   /* 将所有输入文件的 .text 段放这里 */
    }

    .data : {      /* 定义 .data 段 */
        *(.data)
    }
}
```

### 特殊符号

- `.` ：当前位置计数器（location counter）
- `*` ：通配符，匹配任意输入文件
- `ALIGN(x)` ：对齐到 x 字节边界

## 内核链接器脚本

让我们看看我们的内核链接器脚本。

### kernel/kernel.ld

```ld
/* ==============================================================================
 * CCOS Kernel Linker Script
 * ==============================================================================
 *
 * This script defines the memory layout of the CCOS kernel.
 * It ensures that kernel code and data are placed at the correct addresses.
 *
 * ==============================================================================
 */

OUTPUT_FORMAT(elf64-x86-64)
ENTRY(_start)

/* Kernel virtual memory base */
KERNEL_VMA = 0xFFFF800000001000;

/* Physical memory base (where bootloader loads kernel) */
KERNEL_LMA = 0x100000;

/* Page size */
PAGE_SIZE = 0x1000;

/* Memory regions */
MEMORY
{
    KERNEL_CODE (rx)  : ORIGIN = KERNEL_VMA, LENGTH = 16M
    KERNEL_DATA (rw)  : ORIGIN = KERNEL_VMA + 16M, LENGTH = 240M
}

/* ==============================================================================
 * Sections
 * ==============================================================================
 */

SECTIONS
{
    /* ------------------------------------------------------------------
     * Kernel code section
     * ------------------------------------------------------------------ */
    . = KERNEL_VMA;

    .text : AT(ADDR(.text) - KERNEL_VMA + KERNEL_LMA)
    {
        _code = .;  /* Start of kernel code */
        *(.text)
        *(.text.*)
        _code_end = .;
    } > KERNEL_CODE

    /* ------------------------------------------------------------------
     * Read-only data section
     * ------------------------------------------------------------------ */
    .rodata : ALIGN(PAGE_SIZE)
    {
        _rodata = .;
        *(.rodata)
        *(.rodata.*)
        _rodata_end = .;
    } > KERNEL_CODE

    /* ------------------------------------------------------------------
     * Initialized data section
     * ------------------------------------------------------------------ */
    .data : ALIGN(PAGE_SIZE)
    {
        _data = .;
        *(.data)
        *(.data.*)
        _data_end = .;
    } > KERNEL_DATA

    /* ------------------------------------------------------------------
     * BSS section
     * ------------------------------------------------------------------ */
    .bss : ALIGN(PAGE_SIZE)
    {
        _bss = .;
        *(.bss)
        *(.bss.*)
        *(COMMON)
        _bss_end = .;
    } > KERNEL_DATA

    /* ------------------------------------------------------------------
     * User programs embedded section
     * ------------------------------------------------------------------ */
    .user_programs : ALIGN(PAGE_SIZE)
    {
        _user_programs_start = .;
        KEEP(*(.user_uname_test))
        _user_programs_end = .;
    } > KERNEL_DATA

    /* ------------------------------------------------------------------
     * End of kernel image
     * ------------------------------------------------------------------ */
    _kernel_end = .;

    /* ------------------------------------------------------------------
     * Discard unwanted sections
     * ------------------------------------------------------------------ */
    /DISCARD/ :
    {
        *(.comment)
        *(.eh_frame*)
        *(.note.gnu.build-id)
    }
}
```

### 解释各个部分

**输出格式和入口点**

```ld
OUTPUT_FORMAT(elf64-x86-64)
ENTRY(_start)
```

指定输出文件格式为 ELF 64-bit x86-64，入口点为 `_start`。

**VMA 和 LMA**

```ld
KERNEL_VMA = 0xFFFF800000001000;  /* Virtual address */
KERNEL_LMA = 0x100000;             /* Load address */
```

- VMA（Virtual Memory Address）：程序运行时的虚拟地址
- LMA（Load Memory Address）：程序加载时的物理地址

内核被加载到物理地址 `0x100000`，但在高虚拟地址 `0xFFFF800000001000` 运行。

**内存区域定义**

```ld
MEMORY
{
    KERNEL_CODE (rx)  : ORIGIN = KERNEL_VMA, LENGTH = 16M
    KERNEL_DATA (rw)  : ORIGIN = KERNEL_VMA + 16M, LENGTH = 240M
}
```

定义两个内存区域：
- `KERNEL_CODE`：可读可执行，16MB
- `KERNEL_DATA`：可读写，240MB

**代码段**

```ld
.text : AT(ADDR(.text) - KERNEL_VMA + KERNEL_LMA)
{
    _code = .;
    *(.text)
    *(.text.*)
    _code_end = .;
} > KERNEL_CODE
```

`AT(...)` 指定段的加载地址（LMA）。这里我们计算出差值，确保内核被加载到正确的物理位置。

**用户程序段**

```ld
.user_programs : ALIGN(PAGE_SIZE)
{
    _user_programs_start = .;
    KEEP(*(.user_uname_test))
    _user_programs_end = .;
} > KERNEL_DATA
```

这是关键部分！我们：
1. 页对齐（`ALIGN(PAGE_SIZE)`）
2. 创建边界符号（`_user_programs_start`, `_user_programs_end`）
3. 使用 `KEEP()` 确保段不会被垃圾回收
4. 匹配所有 `.user_uname_test` 段

## 符号访问

有了链接器脚本定义的符号，内核代码可以访问用户程序：

```c
/* External symbols from embedded user programs */
extern const uint8_t _user_programs_start[];
extern const uint8_t _user_programs_end[];

/* Convenience macros */
#define USER_PROGRAM(addr, name) \
    ((const uint8_t*)(addr))

/* Function to find a specific user program */
const uint8_t* find_user_program(const char* name, size_t* size) {
    /* For now, we only have one program */
    extern const uint8_t _binary_user_programs_demo_uname_test_start[];
    extern const uint64_t _binary_user_programs_demo_uname_test_size;

    if (strcmp(name, "uname_test") == 0) {
        *size = (size_t)_binary_user_programs_demo_uname_test_size;
        return _binary_user_programs_demo_uname_test_start;
    }

    return NULL;
}
```

## 将用户程序加载到用户空间

现在我们需要将嵌入的程序复制到用户空间并执行。

### user_process_loader.c

```c
/* ==============================================================================
 * User Process Loader
 * ==============================================================================
 */

#include "user/user.h"
#include "mm/vmm/vmm.h"
#include "mm/pframe/pframe.h"
#include "process/process.h"
#include "klogs/kprintf.h"
#include "base/memory.h"

/* External symbols from embedded user programs */
extern const uint8_t _binary_user_programs_demo_uname_test_start[];
extern const uint8_t _binary_user_programs_demo_uname_test_end[];
extern const uint64_t _binary_user_programs_demo_uname_test_size;

/**
 * @brief Load a user program into memory and create a process
 */
int load_user_program(const char* name, pcb_t* pcb) {
    const uint8_t* program_data;
    size_t program_size;
    virtual_addr_t entry_point;

    /* Find the program */
    if (strcmp(name, "uname_test") == 0) {
        program_data = _binary_user_programs_demo_uname_test_start;
        program_size = (size_t)_binary_user_programs_demo_uname_test_size;
        entry_point = USER_BASE;  /* Load at 4MB */
    } else {
        klog_error("[USER] Unknown program: %s\n", name);
        return -1;
    }

    klog_info("[USER] Loading program '%s': %zu bytes\n", name, program_size);

    /* Create user address space */
    if (vmm_create_user_space(&pcb->mm.pml4_phys) != 0) {
        klog_error("[USER] Failed to create user address space\n");
        return -1;
    }

    /* Calculate how many pages we need */
    size_t num_pages = (program_size + PAGE_SIZE - 1) / PAGE_SIZE;

    /* Map program pages into user space */
    for (size_t i = 0; i < num_pages; i++) {
        physical_addr_t paddr;

        /* Allocate a physical page */
        if (pframe_alloc(&paddr) != PFRAME_OK) {
            klog_error("[USER] Failed to allocate program page %zu\n", i);
            /* Cleanup */
            vmm_destroy_user_space(pcb->mm.pml4_phys);
            return -1;
        }

        /* Map to user space */
        virtual_addr_t vaddr = entry_point + (i * PAGE_SIZE);
        vmm_result_t result = vmm_map_to_user(pcb->mm.pml4_phys, vaddr,
                                               paddr, 1,
                                               VMAP_FLAG_USER | VMAP_FLAG_NO_EXEC);
        if (result != VMM_OK) {
            klog_error("[USER] Failed to map program page at 0x%llX\n", vaddr);
            pframe_free(paddr);
            vmm_destroy_user_space(pcb->mm.pml4_phys);
            return -1;
        }

        /* Copy program data to the page */
        size_t copy_size = PAGE_SIZE;
        size_t offset = i * PAGE_SIZE;
        if (offset + copy_size > program_size) {
            copy_size = program_size - offset;
        }

        void* dest = (void*)phys_to_virt_offset(paddr);
        memcpy(dest, program_data + offset, copy_size);

        /* Zero the rest of the page */
        if (copy_size < PAGE_SIZE) {
            memset((char*)dest + copy_size, 0, PAGE_SIZE - copy_size);
        }
    }

    /* Create user process (sets up stack) */
    if (user_create_process(entry_point, pcb) != 0) {
        klog_error("[USER] Failed to create user process\n");
        vmm_destroy_user_space(pcb->mm.pml4_phys);
        return -1;
    }

    klog_info("[USER] Program loaded successfully: entry=0x%llX\n", entry_point);

    return 0;
}

/**
 * @brief Execute the uname_test user program
 */
int execute_uname_test(void) {
    /* Allocate a PCB */
    pcb_t* pcb = allocate_pcb();
    if (!pcb) {
        klog_error("[USER] Failed to allocate PCB\n");
        return -1;
    }

    /* Set basic PCB fields */
    pcb->pid = proc_alloc_pid();
    pcb->state = PROC_READY;
    pcb->priority = PROC_PRIORITY_NORMAL;
    pcb->sched_class = SCHED_CLASS_NORMAL;

    /* Load the program */
    if (load_user_program("uname_test", pcb) != 0) {
        kfree(pcb);
        return -1;
    }

    /* Add to ready queue */
    proc_add_to_ready_queue(pcb);

    klog_info("[USER] uname_test process created: pid=%d\n", pcb->pid);

    return 0;
}
```

### 代码解释

**查找程序数据**

```c
if (strcmp(name, "uname_test") == 0) {
    program_data = _binary_user_programs_demo_uname_test_start;
    program_size = (size_t)_binary_user_programs_demo_uname_test_size;
    entry_point = USER_BASE;  /* Load at 4MB */
}
```

我们使用外部符号来定位嵌入的程序数据。

**逐页复制**

```c
for (size_t i = 0; i < num_pages; i++) {
    /* Allocate physical page */
    /* Map to user space */
    /* Copy program data */
}
```

我们逐页分配物理内存，映射到用户空间，然后复制程序数据。

**创建用户进程**

```c
if (user_create_process(entry_point, pcb) != 0) {
    /* Error handling */
}
```

最后，我们调用 `user_create_process()` 来设置用户栈和标志。

## 调试链接器脚本

链接器脚本的错误消息通常很晦涩。这里有一些调试技巧。

### 使用 nm 查看符号

```bash
nm build/kernel.elf | grep user_programs
```

你应该看到：

```
0000000000123456 A _user_programs_start
0000000000123890 A _user_programs_end
```

### 使用 objdump 查看段

```bash
objdump -h build/kernel.elf | grep user
```

你应该看到：

```
 15 .user_programs 000003a0  0000000000123456  0000000000123456  00034656  2**12
                  ALLOC
```

注意 `2**12` 表示 4096 字节对齐（2^12 = 4096）。

### 使用 readelf 查看详细段信息

```bash
readelf -S build/kernel.elf
```

这会显示所有段的详细信息，包括地址、大小、标志等。

## 常见问题

### 问题 1：段被垃圾回收

**症状**：用户程序数据不在内核镜像中

**原因**：链接器认为段没有被使用，将其优化掉了

**解决**：使用 `KEEP()` 命令

```ld
KEEP(*(.user_uname_test))
```

### 问题 2：符号未定义

**症状**：链接时报错 `undefined reference to _user_programs_start`

**原因**：符号在链接器脚本中定义，但在 C 代码中声明不正确

**解决**：确保声明为 `extern`，类型匹配

```c
extern const uint8_t _user_programs_start[];
```

### 问题 3：程序未对齐

**症状**：运行时页错误

**原因**：段没有正确对齐

**解决**：在链接器脚本中使用 `ALIGN()`

```ld
.user_programs : ALIGN(PAGE_SIZE)
{
    /* ... */
}
```

### 问题 4：LMA 不正确

**症状**：内核无法启动或立即崩溃

**原因**：加载地址不匹配

**解决**：使用 `AT()` 显式设置 LMA

```ld
.text : AT(ADDR(.text) - KERNEL_VMA + KERNEL_LMA)
{
    /* ... */
}
```

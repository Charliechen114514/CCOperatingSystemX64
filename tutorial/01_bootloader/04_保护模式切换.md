# 保护模式切换 —— 踏入 32 位世界的第一步

## 前言

说实话，这部分内容是我写 Bootloader 时最头疼的。

保护模式（Protected Mode）是 x86 处理器从 16 位实模式进入 32 位世界的第一步。但问题是：

1. 你需要理解 GDT（全局描述符表）
2. 你需要正确设置段描述符
3. 一个错误就会导致 Triple Fault，系统直接重启

我当时在这部分卡了好几天，看了无数资料才搞明白。现在我来帮你节省这些时间。

---

## 理解保护模式

### 什么是保护模式？

在实模式（Real Mode）下：
- CPU 使用 20 位地址线，可以访问 1MB 内存
- 段地址直接左移 4 位加上偏移地址得到物理地址
- 没有内存保护，任何程序可以访问任何内存

在保护模式（Protected Mode）下：
- CPU 使用 32 位地址线，可以访问 4GB 内存
- 段选择子指向 GDT 中的描述符
- 有内存保护，不同程序有独立的地址空间
- 支持分页（虚拟内存）

### 为什么需要保护模式？

简单来说：
1. **访问更多内存**：1MB 根本不够用
2. **内存保护**：防止程序互相干扰
3. **为长模式做准备**：进入 64 位必须先经过保护模式

## 第一步：理解 GDT（全局描述符表）

GDT 是一个数据结构，告诉 CPU 内存段的布局。

### GDT 结构

```
GDT 包含多个段描述符，每个描述符 8 字节：

┌─────────────────────────────────────────────┐
│ 描述符 0 (空描述符，必须存在)                 │
├─────────────────────────────────────────────┤
│ 描述符 1 (代码段)                            │
├─────────────────────────────────────────────┤
│ 描述符 2 (数据段)                            │
├─────────────────────────────────────────────┤
│ 描述符 3 (64 位代码段)                       │
├─────────────────────────────────────────────┤
│ 描述符 4 (64 位数据段)                       │
└─────────────────────────────────────────────┘
```

### 段描述符格式

每个描述符 8 字节（64 位）：

```
63                  56 55    52 51  48 47   40 39                32
┌────────────────────┬───────┬──────┬───────┬────────────────────┐
│ Base Address 31:24 │ Flags │ Limit │ Base  │ Base Address 23:16 │
├────────────────────┴───────┴──────┴───────┴────────────────────┤
│ 31│                      │                     │                │
│   │    Base Address      │       Segment       │                │
│15 │       15:00          │       Limit 15:00   │    Access      │
│   │                      │                     │    Rights      │
│ 0 │                      │                     │                │
└───┴──────────────────────┴─────────────────────┴────────────────┘
```

**别被吓到了**，我们不会手动计算这些。NASM 可以直接用 `dq` 指令定义描述符。

### 描述符类型

我们需要 5 个描述符：

| 索引 | 名称 | 说明 |
|------|------|------|
| 0 | 空描述符 | 必须存在，不能使用 |
| 1 | 32 位代码段 | 保护模式代码段 |
| 2 | 32 位数据段 | 保护模式数据段 |
| 3 | 64 位代码段 | 长模式代码段 |
| 4 | 64 位数据段 | 长模式数据段 |

## 第二步：编写 GDT 代码

在 `boot/bootloader.asm` 的 Stage 2 部分添加 GDT：

```asm
; ==============================================================================
; Stage 2: 从偏移 512 开始，加载到 0x7E00
; ==============================================================================
section .stage2 vstart=0x7E00
    bits 16

stage2_entry:
    jmp short stage2_main
    nop

; ==============================================================================
; GDT（全局描述符表）
; ==============================================================================
gdt_start:
    ; 描述符 0：空描述符（必须存在）
    dq 0x0000000000000000

    ; 描述符 1：32 位代码段（保护模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Code, Execute/Read
    dq 0x00CF9A000000FFFF

    ; 描述符 2：32 位数据段（保护模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Data, Read/Write
    dq 0x00CF92000000FFFF

    ; 描述符 3：64 位代码段（长模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Code, Execute/Read, Long
    dq 0x00AF9A000000FFFF

    ; 描述符 4：64 位数据段（长模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Data, Read/Write
    dq 0x00CF92000000FFFF

gdt_end:

; ==============================================================================
; GDT 指针（用于 lgdt 指令）
; ==============================================================================
gdt_ptr:
    dw gdt_end - gdt_start - 1    ; GDT 限长（字节数 - 1）
    dd 0x00007E03                 ; GDT 基地址（Stage 2 开始 + 3 字节）
                                  ; 3 字节是因为 jmp short+nop
```

⚠️ **关键点**

`gdt_ptr` 的基址是 `0x00007E03`，不是 `0x7E00`。这是因为：
- Stage 2 从 `0x7E00` 开始
- 但我们有 `jmp short stage2_main`（2 字节）+ `nop`（1 字节）
- 所以 GDT 实际从 `0x7E03` 开始

## 第三步：切换到保护模式

现在添加保护模式切换代码：

```asm
stage2_main:
    ; ========== 重新初始化环境 ==========
    cli
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7E00
    sti

    ; ========== 打印 Stage 2 消息 ==========
    mov si, stage2_start_msg
    call print_string

    ; ========== 加载 GDT ==========
    lgdt [gdt_ptr]

    ; ========== 打印 GDT 加载消息 ==========
    mov si, gdt_loaded_msg
    call print_string

    ; ========== 启用保护模式 ==========
    ; 设置 CR0 的 PE 位（位 0）
    mov eax, cr0
    or eax, 1
    mov cr0, eax

    ; ========== Far Jump 到 32 位代码 ==========
    ; 这一步非常关键！
    ; 1. 刷新流水线（CPU 需要重新解码指令）
    ; 2. 加载 CS 段选择子
    db 0x66        ; 32 位 operand prefix
    db 0xEA        ; far jmp 指令
    dd pm_entry    ; 32 位目标地址
    dw 0x08        ; 段选择子（描述符 1 = 8）

; ========== 这里不会到达 ==========
.hang:
    hlt
    jmp .hang
```

## 第四步：编写 32 位保护模式代码

在同一文件中添加 32 位代码：

```asm
; ==============================================================================
; 32 位保护模式代码
; ==============================================================================
bits 32

pm_entry:
    ; ========== 设置段寄存器 ==========
    mov ax, 0x10    ; 数据段选择子（描述符 2 = 16）
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov esp, 0x7E00

    ; ========== 打印保护模式消息 ==========
    mov esi, pm_success_msg
    call print_string_pm

    ; ========== TODO: 设置页表并切换到长模式 ==========
    ; 下一篇文章会实现

    ; ========== 暂时停在这里 ==========
.hang:
    hlt
    jmp .hang

; ==============================================================================
; 32 位字符串打印函数（使用 VGA 直接写内存）
; ==============================================================================
print_string_pm:
    pusha
    mov edi, 0xB8000    ; VGA 显存地址
    mov ah, 0x0F        ; 白色字符

.loop:
    lodsb               ; 加载 [ESI] 到 AL
    test al, al
    jz .done

    stosw               ; 写入显存（AX -> [EDI]）
    jmp .loop

.done:
    popa
    ret
```

## 第五步：添加消息字符串

在数据段添加新的消息：

```asm
; ========== Stage 2 消息 ==========
stage2_start_msg:
    db "[2] Stage 2: Running from 0x7E00", 0x0d, 0x0a, 0

gdt_loaded_msg:
    db "[2] GDT loaded, enabling protected mode...", 0x0d, 0x0a, 0

pm_success_msg:
    db "[3] Protected Mode: Now in 32-bit!", 0x0d, 0x0a, 0
```

## 第六步：理解 Far Jump

**为什么需要 Far Jump？**

切换到保护模式后，我们需要：
1. **刷新 CPU 指令流水线**：CPU 预取的实模式指令需要被清空
2. **加载新的 CS 段选择子**：CS 不能用 `mov` 直接修改

**Far Jump 格式**：

```asm
jmp 段选择子:偏移地址
```

但在 NASM 中，我们用 `db` 指令手动编码：

```asm
db 0x66        ; 0x66 prefix = 32 位操作数
db 0xEA        ; 0xEA = JMP far opcode
dd pm_entry    ; 32 位偏移地址
dw 0x08        ; 16 位段选择子
```

**段选择子格式**：

```
15      3   2   0
┌───────┬───┬───┐
│ Index │ TI│ RPL│
└───────┴───┴───┘

Index: GDT 描述符索引（8 的倍数）
TI:    0 = GDT, 1 = LDT
RPL:   Requested Privilege Level (0-3)
```

`0x08 = 0000 0000 1000b`：
- Index = 1（描述符 1）
- TI = 0（使用 GDT）
- RPL = 0（最高特权级）

## 第八步：调试技巧

### 问题 1：Triple Fault（系统重启）

**症状**：QEMU 直接重启或卡死。

**原因**：
1. GDT 描述符错误
2. Far Jump 编码错误
3. 段选择子指向了不存在的描述符

**调试方法**：

使用 QEMU monitor 查看状态：

```bash
# 按 Ctrl+Alt+2 进入 monitor
(qemu) info registers
(qemu) xp /10x 0x7E00
```

### 问题 2：Far Jump 不工作

**检查 Far Jump 编码**：

```bash
ndisasm -b 16 -o 0x7E00 ../build/bootloader.bin | grep -A5 "lgdt"
```

你应该看到类似：

```
00007E20  0F0116            lgdt [esi]
00007E23  660FE8            call far eax:...
```

### 问题 3：32 位代码不执行

**确认 bits 32**：

确保保护模式代码部分有 `bits 32` 伪指令。

## GDT 描述符详解

如果你想深入理解描述符的每一个位：

```
位     说明        值        含义
63-56  Base[31:24] 0x00      基地址高 8 位
55     Granularity  1        1 = 4KB 页粒度
54     Size         1        1 = 32 位，0 = 16 位
53     Long mode    0        0 = 兼容模式
52-52  AVL          0        系统软件可用
51-48  Limit[19:16] 0xF      段限高 4 位
47     Present      1        描述符有效
46-46  DPL          0        特权级 0
45-45  System       1        系统段
44-44  Type         1010/0010 代码段/数据段
43-43  Accessed     0        是否被访问
42-40  Reserved     0        保留
39-32  Base[23:16] 0x00      基地址中 8 位
31-16  Base[15:0]  0x0000    基地址低 16 位
15-00  Limit[15:0]  0xFFFF    段限低 16 位
```

# 保护模式切换 —— 踏入 32 位世界的第一步

## 前言

说实话，这部分内容是我写 Bootloader 时最头疼的。

保护模式（Protected Mode）是 x86 处理器从 16 位实模式进入 32 位世界的第一步。但问题是：你需要理解 GDT（全局描述符表），需要正确设置段描述符，一个错误就会导致 Triple Fault，系统直接重启。

我当时在这部分卡了好几天，看了无数资料才搞明白。最崩溃的是，Triple Fault 的时候 QEMU 直接重启，连错误信息都没有，你根本不知道是哪里出错了。后来慢慢学会用 GDB 单步调试，才一步步找到问题。

现在我来帮你节省这些时间。我们会一起理解保护模式，一起设置 GDT，一起完成模式切换。别担心，我们一步一步来。

## 理解保护模式

### 什么是保护模式？

在实模式（Real Mode）下，CPU 使用 20 位地址线，可以访问 1MB 内存。地址计算方式是段地址 × 16 + 偏移地址，比如 `0x07C0:0x0100` = `0x07C0 × 16 + 0x0100` = `0x07D00`。这种寻址方式是 8086 处理器遗留下来的，非常古老。而且没有内存保护，任何程序可以访问任何内存，一个错误的指针就可能把整个系统搞崩。

在保护模式（Protected Mode）下，CPU 使用 32 位地址线，可以访问 4GB 内存。寻址方式完全不同，段选择子指向 GDT 中的描述符，描述符里存放段的基地址和限长。这样 CPU 就可以检查每个内存访问是否合法，提供了内存保护。同时支持分页（虚拟内存），可以实现更复杂的内存管理。

### 为什么需要保护模式？

简单来说有三个原因。首先是访问更多内存，1MB 根本不够用，现代程序动辄几百 MB。其次是内存保护，防止程序互相干扰，一个程序崩溃不会影响整个系统。最后是为长模式做准备，进入 64 位必须先经过保护模式。你无法直接从实模式跳到长模式，必须先进入保护模式。

### 实模式 vs 保护模式对比

我们来看一下两种模式的对比，这样你更容易理解区别。

在实模式下：
- 地址空间是 1MB（0x00000 - 0xFFFFF）
- 寄存器是 16 位的（AX, BX, CX, DX, SI, DI, BP, SP）
- 段地址直接左移 4 位加上偏移地址得到物理地址
- 没有内存保护，任何程序可以访问任何内存
- 没有特权级概念，所有代码都在同一特权级

在保护模式下：
- 地址空间是 4GB（0x00000000 - 0xFFFFFFFF）
- 寄存器是 32 位的（EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP）
- 段选择子指向 GDT 中的描述符，描述符包含基地址和限长
- 有内存保护，不同程序有独立的地址空间
- 有 4 个特权级（0-3），内核在 Ring 0，用户程序在 Ring 3

## 理解 GDT（全局描述符表）

GDT 是保护模式的核心概念，我们来仔细看看。

### GDT 是什么？

GDT（Global Descriptor Table，全局描述符表）是一个数据结构，告诉 CPU 内存段的布局。你可以把它理解成一个目录，里面记录了各个内存段的信息。每个段描述符 8 字节，包含段的基地址、限长、访问权限等。

CPU 通过段选择子来索引 GDT。段选择子是一个 16 位值，包含 GDT 索引、特权级等信息。当 CPU 访问内存时，它会用段选择子在 GDT 中找到对应的描述符，然后根据描述符里的基地址和限长来检查访问是否合法。

### GDT 结构

GDT 包含多个段描述符，每个描述符 8 字节。第一个描述符必须是空描述符（全 0），不能使用。这是 Intel 的规定，你必须遵守。后面的描述符可以是代码段、数据段、系统段等。

我们需要 5 个描述符：空描述符（必须）、32 位代码段、32 位数据段、64 位代码段、64 位数据段。32 位的描述符用于保护模式，64 位的描述符用于长模式。

### 段选择子格式

段选择子是一个 16 位值，格式是这样的：

```
15              3   2   0
┌───────────────┬───┬───┐
│    Index      │ TI│RPL│
└───────────────┴───┴───┘
```

Index 是 GDT 中的描述符索引，从 0 开始，每个 8 字节。所以 Index = 1 表示第二个描述符（偏移 8），Index = 2 表示第三个描述符（偏移 16），以此类推。TI 是表指示器，0 表示使用 GDT，1 表示使用 LDT（Local Descriptor Table，本地描述符表）。我们只用 GDT，所以 TI 总是 0。RPL 是请求特权级，0-3，0 是最高特权级（内核），3 是最低特权级（用户程序）。

举个例子，`0x08 = 0000 1000b`：Index = 1（描述符 1），TI = 0（GDT），RPL = 0（最高特权级）。`0x10 = 0001 0000b`：Index = 2（描述符 2），TI = 0，RPL = 0。

## 编写 GDT 代码

现在我们来编写 GDT 代码。在 Stage 2 中添加 GDT 定义：

```asm
; ==============================================================================
; Stage 2: 从偏移 512 开始，加载到 0x7E00
; ==============================================================================
section .stage2 vstart=0x7E00
    bits 16

stage2_entry:
    jmp short stage2_main
    nop                 ; 填充对齐

; ==============================================================================
; GDT（全局描述符表）
; ==============================================================================
gdt_start:
    ; 描述符 0：空描述符（必须存在）
    dq 0x0000000000000000

    ; 描述符 1：32 位代码段（保护模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Code, Execute/Read
    dq 0x00CF9A000000FFFF

    ; 描述符 2：32 位数据段（保护模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Data, Read/Write
    dq 0x00CF92000000FFFF

    ; 描述符 3：64 位代码段（长模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Code, Execute/Read, Long
    dq 0x00AF9A000000FFFF

    ; 描述符 4：64 位数据段（长模式）
    ; Base = 0x00000000, Limit = 0xFFFFF, Present, DPL=0, System, Data, Read/Write
    dq 0x00CF92000000FFFF

gdt_end:

; ==============================================================================
; GDT 指针（用于 lgdt 指令）
; ==============================================================================
gdt_ptr:
    dw gdt_end - gdt_start - 1    ; GDT 限长（字节数 - 1）
    dd 0x00007E03                 ; GDT 基地址（Stage 2 开始 + 3 字节）
                                  ; 3 字节是因为 jmp short+nop
```

这段代码我们来仔细讲解。首先是空描述符，全 0，这是必须的。然后是 32 位代码段描述符，`0x00CF9A000000FFFF`。这个值我们等下详细解释。接着是 32 位数据段描述符，`0x00CF92000000FFFF`。然后是 64 位代码段描述符，`0x00AF9A000000FFFF`，注意这里是 `0xAF` 而不是 `0xCF`，因为 L 位（Long Mode）是 1。最后是 64 位数据段描述符，和 32 位的一样。

GDT 指针用于 `lgdt` 指令。`lgdt` 需要一个 6 字节的值：前 2 字节是 GDT 限长（字节数 - 1），后 4 字节是 GDT 基地址。限长是 `gdt_end - gdt_start - 1`，也就是 5 × 8 - 1 = 39。基址是 `0x00007E03`，因为 GDT 从 Stage 2 开始加 3 字节（jmp short 2 字节 + nop 1 字节）。

⚠️ **GDT 基地址的计算**

这个问题真的坑了我半天。GDT 基地址必须准确，不能错。`0x7E00` 是 Stage 2 的起始地址，但 GDT 不在 Stage 2 的开头，前面有 `jmp short stage2_main`（2 字节）和 `nop`（1 字节），所以 GDT 实际从 `0x7E03` 开始。如果你用 `0x7E00`，`lgdt` 会读取错误的位置，导致保护模式切换失败。

还有一个问题，在 `bits 16` 下计算地址可能不准确，所以这里直接硬编码 `0x00007E03`。这样虽然不够优雅，但能保证正确。

## 段描述符详解

我们来详细解释一下段描述符的格式。这部分比较复杂，但很重要。

### 段描述符格式

每个段描述符 8 字节（64 位），格式如下：

```
63                  56 55    52 51  48 47   40 39                32
┌────────────────────┬───────┬──────┬───────┬────────────────────┐
│ Base Address 31:24 │ Flags │ Limit│Base   │ Base Address 23:16 │
├────────────────────┴───────┴──────┴───────┴────────────────────┤
│ 31│                      │                     │                │
│   │    Base Address      │       Segment       │                │
│15 │       15:00          │       Limit 15:00   │    Access      │
│   │                      │                     │    Rights      │
│ 0 │                      │                     │                │
└───┴──────────────────────┴─────────────────────┴────────────────┘
```

这个格式看起来很复杂，我们把它拆开来看。描述符包含以下字段：

- Base Address（32 位）：段的基地址
- Segment Limit（20 位）：段的限长
- Access Rights（8 位）：访问权限
- Flags（4 位）：标志位

### Access Byte 格式

Access Byte 是描述符的第 6 字节（偏移 5），格式如下：

```
|7  |6 5|4   |3   2 1|0      |
|P  |DPL|S   |Type   |         |
```

- P（Present）：描述符是否有效，必须为 1
- DPL（Descriptor Privilege Level）：特权级，0-3，0 是最高
- S（System）：0 表示系统段，1 表示代码/数据段
- Type：段类型

对于代码段（S=1, Type=1010b）：
- E（Executable）= 1：这是代码段
- C（Conforming）= 0：非一致段
- R（Readable）= 1：可读

对于数据段（S=1, Type=0010b）：
- E（Executable）= 0：这是数据段
- ED（Expand Down）= 0：向上扩展
- W（Writable）= 1：可写

### Flags + Limit[19:16] 格式

这是描述符的第 7 字节（偏移 6），格式如下：

```
|7   |6   |5   |4   |3   |2 1 0      |
|G   |DB  |L   |AVL |Limit[19:16]   |
```

- G（Granularity）：0 = 字节粒度，1 = 4KB 页粒度
- DB（Default Size）：0 = 16 位，1 = 32 位（64 位模式下忽略）
- L（Long Mode）：0 = 兼容模式，1 = 64 位
- AVL：系统软件可用
- Limit[19:16]：段限长的高 4 位

### 32 位代码段描述符详解

我们的 32 位代码段描述符是 `0x00CF9A000000FFFF`。我们把它拆开来看：

```
0x00CF9A000000FFFF
└────┬───┘└──┬──┘└────┬───┘
     │       │        │
     │       │        └─ Base[15:0] = 0x0000, Limit[15:0] = 0xFFFF
     │       └────────── Access Byte = 0x9A
     └────────────────── Flags + Limit[19:16] = 0xCF
```

Access Byte `0x9A = 1001 1010b`：
- P = 1（有效）
- DPL = 00（Ring 0）
- S = 1（代码/数据段）
- Type = 1010（代码段，可读，非一致）

Flags + Limit[19:16] `0xCF = 1100 1111b`：
- G = 1（4KB 粒度）
- DB = 1（32 位）
- L = 0（兼容模式）
- AVL = 0
- Limit[19:16] = 1111（0xF）

所以这个描述符表示：基地址 = 0x00000000，限长 = 0xFFFFF（4GB，因为 G=1），32 位代码段，可执行可读，Ring 0。

### 64 位代码段描述符详解

我们的 64 位代码段描述符是 `0x00AF9A000000FFFF`。注意这里 Flags 部分是 `0xAF` 而不是 `0xCF`。

`0xAF = 1010 1111b`：
- G = 1（4KB 粒度，64 位模式下忽略）
- DB = 0（必须为 0，64 位模式下忽略）
- L = 1（这是 64 位代码段！）
- AVL = 0
- Limit[19:16] = 1111（0xF）

所以这个描述符表示：64 位代码段，其他属性和 32 位代码段一样。

⚠️ **64 位代码段必须 L=1, DB=0**

这个坑我踩了。一开始我设置 `L=1, DB=1`，结果切换到长模式后代码执行出错。查了半天文档才发现，64 位代码段必须 `L=1, DB=0`。DB 位在 64 位模式下被忽略，但为了兼容性，应该设为 0。

## 切换到保护模式

现在我们来编写保护模式切换代码。在 `stage2_main` 中添加：

```asm
stage2_main:
    ; ========== 重新初始化环境 ==========
    cli
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7E00
    sti

    ; ========== 打印 Stage 2 消息 ==========
    mov si, stage2_start_msg
    call print_string

    ; ========== 加载 GDT ==========
    lgdt [gdt_ptr]

    ; ========== 打印 GDT 加载消息 ==========
    mov si, gdt_loaded_msg
    call print_string

    ; ========== 启用保护模式 ==========
    ; 设置 CR0 的 PE 位（位 0）
    mov eax, cr0
    or eax, 1
    mov cr0, eax

    ; ========== Far Jump 到 32 位代码 ==========
    ; 这一步非常关键！
    ; 1. 刷新流水线（CPU 需要重新解码指令）
    ; 2. 加载 CS 段选择子
    db 0x66        ; 32 位 operand prefix
    db 0xEA        ; far jmp 指令
    dd pm_entry    ; 32 位目标地址
    dw 0x08        ; 段选择子（描述符 1 = 8）

; ========== 这里不会到达 ==========
.hang:
    hlt
    jmp .hang
```

这段代码我们来逐段讲解。首先是环境初始化和打印消息，和之前一样。

然后是 `lgdt [gdt_ptr]`，加载 GDT。`lgdt` 是 Load GDT 的缩写，它从内存读取 6 字节的 GDT 指针，加载到 GDTR 寄存器。

接下来是启用保护模式。CR0 是控制寄存器 0（Control Register 0），位 0 是 PE 位（Protection Enable）。把 PE 位设为 1 就启用了保护模式。`mov eax, cr0` 读取 CR0 到 EAX，`or eax, 1` 设置位 0，`mov cr0, eax` 写回 CR0。

然后是 Far Jump 到 32 位代码。这一步非常关键，有两个作用。首先刷新 CPU 指令流水线，因为 PE 位改变后，CPU 需要重新解码指令。其次加载新的 CS 段选择子，CS 不能用 `mov` 直接修改，只能通过 Far Jump 修改。

Far Jump 的机器码是手动编码的。`db 0x66` 是 32 位操作数前缀，`db 0xEA` 是 Far Jump 操作码，`dd pm_entry` 是 32 位目标地址，`dw 0x08` 是 16 位段选择子。`0x08` 是描述符 1 的段选择子（Index = 1, TI = 0, RPL = 0）。

⚠️ **Far Jump 必须手动编码**

在 NASM 中，你不能直接写 `jmp 0x08:pm_entry`，因为 NASM 默认生成 16 位代码。我们需要手动编码 Far Jump，确保是 32 位跳转。`0x66` 前缀告诉 CPU 这是一个 32 位操作数。

## 编写 32 位保护模式代码

现在我们来编写 32 位保护模式代码。在 Stage 2 中添加：

```asm
; ==============================================================================
; 32 位保护模式代码
; ==============================================================================
bits 32

pm_entry:
    ; ========== 设置段寄存器 ==========
    mov ax, 0x10    ; 数据段选择子（描述符 2 = 16）
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov esp, 0x7E00

    ; ========== 打印保护模式消息 ==========
    mov esi, pm_success_msg
    call print_string_pm

    ; ========== TODO: 设置页表并切换到长模式 ==========
    ; 下一篇文章会实现这个

    ; ========== 暂时停在这里 ==========
.hang:
    hlt
    jmp .hang

; ==============================================================================
; 32 位字符串打印函数（使用 VGA 直接写内存）
; ==============================================================================
print_string_pm:
    pusha
    mov edi, 0xB8000    ; VGA 显存地址
    mov ah, 0x0F        ; 白色字符

.loop:
    lodsb               ; 加载 [ESI] 到 AL
    test al, al
    jz .done

    stosw               ; 写入显存（AX -> [EDI]）
    jmp .loop

.done:
    popa
    ret
```

这段代码我们来讲解。首先 `bits 32` 告诉 NASM 这是 32 位代码。然后设置段寄存器，数据段选择子是 `0x10`（描述符 2）。`mov esp, 0x7E00` 设置栈指针，注意现在是 ESP（32 位）而不是 SP（16 位）。

然后是打印消息。我们用 VGA 直接写内存的方式，而不是 BIOS 中断。为什么？因为进入保护模式后，BIOS 中断可能不可用（取决于 BIOS）。最安全的方式是直接写 VGA 显存。

VGA 显存地址是 `0xB8000`，每个字符 2 字节：1 字节 ASCII 码，1 字节属性。`stosw` 把 AX 写入 [EDI]，然后 EDI += 2。`lodsb` 从 [ESI] 加载到 AL，然后 ESI += 1。

## 理解 Far Jump

Far Jump 是保护模式切换的关键，我们来深入理解一下。

### 为什么需要 Far Jump？

切换到保护模式后，CPU 的寻址方式改变了。实模式下，段地址直接左移 4 位加上偏移地址得到物理地址。保护模式下，段选择子指向 GDT 中的描述符，描述符里存放段的基地址。

当我们设置 CR0.PE = 1 后，CPU 进入保护模式，但 CS 寄存器还保留着实模式的值。这样 CPU 仍然用实模式的方式解析地址，会导致错误。Far Jump 做了两件事：刷新 CPU 指令流水线，让 CPU 重新解码指令；加载新的 CS 段选择子，让 CPU 用保护模式的方式解析地址。

### Far Jump 格式

Far Jump 的格式是 `jmp 段选择子:偏移地址`。但在 NASM 中，我们用手动编码的方式：

```asm
db 0x66        ; 32 位操作数前缀
db 0xEA        ; Far Jump 操作码
dd pm_entry    ; 32 位偏移地址
dw 0x08        ; 16 位段选择子
```

`0x66` 前缀告诉 CPU 这是一个 32 位操作数。`0xEA` 是 Far Jump 操作码。`dd` 定义双字（4 字节），是 32 位偏移地址。`dw` 定义字（2 字节），是 16 位段选择子。

### 段选择子计算

段选择子的计算是这样的：Index × 8。描述符 1 的段选择子是 1 × 8 = 8 = 0x08。描述符 2 的段选择子是 2 × 8 = 16 = 0x10。所以我们的代码里 `0x08` 表示描述符 1（32 位代码段），`0x10` 表示描述符 2（32 位数据段）。

## 常见问题

这里我总结一些保护模式切换中常见的问题。

### 问题 1：Triple Fault（系统重启）

症状是 QEMU 不断重启。原因可能有几个。GDT 描述符错误，Far Jump 编码错误，段选择子指向了不存在的描述符。

调试方法：使用 GDB 单步调试。启动 QEMU 时加 `-s -S` 参数，然后在另一个终端启动 GDB。在保护模式切换前后设置断点，单步执行，查看寄存器的值。

```bash
qemu-system-x86_64 -drive format=raw,file=../build/boot.img,if=floppy -nographic -s -S
```

```bash
gdb
(gdb) target remote localhost:1234
(gdb) set architecture i386
(gdb) break *0x7E03
(gdb) continue
(gdb) si 100
(gdb) info registers
```

### 问题 2：Far Jump 不工作

症状是看到 "GDT loaded" 但之后卡住。原因可能是 Far Jump 编码错误，或者目标地址不正确。

检查方法：用 `ndisasm` 反汇编，检查 Far Jump 的机器码是否正确。

```bash
ndisasm -b 16 -o 0x7E00 ../build/bootloader.bin | grep -A5 "lgdt"
```

你应该看到类似：

```
00007E20  0F0116            lgdt [esi]
00007E23  660FE8            call far eax:...
```

如果看到 `0xEA`，说明 Far Jump 指令正确。

### 问题 3：32 位代码不执行

症状是看到 "Protected Mode" 消息但之后卡住。原因可能是 `bits 32` 没有设置，或者目标地址不正确。

解决方法：确保 32 位代码部分有 `bits 32` 伪指令。确保 `pm_entry` 标签的地址正确。

你可以在 32 位代码的开始添加一些调试代码，比如直接写 VGA 显存打印一个字符，看看是否到达那里。

### 问题 4：GDT 基地址错误

症状是 `lgdt` 指令执行后立即崩溃。原因可能是 GDT 基地址不正确。

解决方法：检查 `gdt_ptr` 的基址是否正确。GDT 从 `0x7E03` 开始，不是 `0x7E00`。

你可以用 GDB 查看 `gdt_ptr` 的值：

```bash
(gdb) x/3x 0x7E00
```

这会显示 0x7E00 开始的 3 个双字，你应该能看到 GDT 的内容。

## 完整的内存布局图

现在我们的内存布局是这样的：

```
┌─────────────────────────────────────────────────────┐
│ 0x00000                                             │
│ └─ IVT / BDA                                         │
├─────────────────────────────────────────────────────┤
│ 0x07C00                                             │
│ ├─ Stage 1 (MBR) - 512 字节                          │
│ │   • 环境初始化                                      │
│ │   • 磁盘读取                                        │
│ │   • 跳转到 Stage 2                                 │
├─────────────────────────────────────────────────────┤
│ 0x07E00                                             │
│ ├─ Stage 2 - 最多 1536 字节                          │
│ │   • GDT (0x7E03 - 0x7E2A)                          │
│ │   • 保护模式切换                                    │
│ │   • 32 位代码                                       │
│ │   • 长模式切换（下一篇文章）                         │
│ │   • 内核加载                                        │
├─────────────────────────────────────────────────────┤
│ 0x08400                                             │
│ └─ 栈区域（向下增长）                                  │
├─────────────────────────────────────────────────────┤
│ 0x09000                                             │
│ └─ 页表（PML4, PDPT, PD）                            │
├─────────────────────────────────────────────────────┤
│ 0x10000                                             │
│ └─ 内核加载地址                                       │
└─────────────────────────────────────────────────────┘
```

# 从零开始的 MBR —— 让屏幕打印出你的第一行字

## 前言

上一篇文章我们已经把环境搭好了。现在我们来做点真正有趣的事情 —— 写一个能显示完整消息的 MBR。

说实话，看到屏幕上出现自己写的文字，那种感觉真的很难形容。尤其是当你知道这行字是直接操作硬件显示出来的，而不是通过任何操作系统的时候。

准备好了吗？我们开始。

---

## 理解 MBR 的结构

在我们开始写代码之前，先搞清楚 MBR 到底是什么。

MBR（Master Boot Record，主引导记录）是硬盘的第一个扇区（512 字节）。当 BIOS 完成自检后，它会读取硬盘的第一个扇区到内存地址 `0x7C00`，然后跳转过去执行。

⚠️ **关键点**

MBR 的大小 **严格限制为 512 字节**。这点真的坑了我半天。一开始我写了好多代码，结果编译出来发现超过了 512 字节，BIOS 根本不会加载它。

MBR 的结构是这样的：

```
Offset  大小    说明
0x000   446     Bootloader 代码（就是我们写的程序）
0x1BE   64      分区表（4 个分区，每个 16 字节）
0x1FE   2       签名（必须是 0x55AA）
```

等等，446 + 64 + 2 = 512。完美的 512 字节。

## 第一步：编写字符串打印函数

在上一篇文章中，我们只打印了一个字符。现在我们来写一个能打印完整字符串的函数。

打开 `boot/bootloader.asm`，把它改成这样：

```asm
; ==============================================================================
; CCOS Bootloader - MBR Stage
; ==============================================================================
; 这是我们的第一个真正能用的 MBR
; 功能：在屏幕上打印欢迎消息
; ==============================================================================

section .mbr
    org 0x7c00      ; BIOS 加载 MBR 到这个地址
    bits 16         ; 16 位实模式

start:
    ; ========== 环境初始化 ==========
    cli             ; 关闭中断
    xor ax, ax      ; AX = 0
    mov ds, ax      ; Data Segment = 0
    mov es, ax      ; Extra Segment = 0
    mov ss, ax      ; Stack Segment = 0
    mov sp, 0x7c00  ; Stack Pointer
    sti             ; 开启中断

    ; ========== 清屏 ==========
    mov ah, 0x00    ; BIOS 显示功能：设置显示模式
    mov al, 0x03    ; 模式 3：80x25 文本模式
    int 0x10

    ; ========== 打印欢迎消息 ==========
    mov si, welcome_msg    ; SI 指向消息
    call print_string      ; 调用打印函数

    ; ========== 死循环 ==========
.hang:
    hlt             ; Halt CPU
    jmp .hang       ; 无限循环

; ==============================================================================
; print_string - 打印以 null 结尾的字符串
; 输入: SI = 字符串地址
; 修改: AX, SI
; ==============================================================================
print_string:
    pusha           ; 保存所有寄存器

.loop:
    lodsb           ; 加载 [SI] 到 AL，SI++
    test al, al     ; 检查 AL 是否为 0（字符串结尾）
    jz .done        ; 如果是 0，结束

    mov ah, 0x0e    ; BIOS 显示功能：显示字符
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性：白色字符，黑色背景
    int 0x10

    jmp .loop       ; 继续下一个字符

.done:
    popa            ; 恢复所有寄存器
    ret             ; 返回

; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db "Hello from CCOS Bootloader!", 0x0d, 0x0a, 0
    ; 0x0d = CR (Carriage Return)
    ; 0x0a = LF (Line Feed)
    ; 0 = 字符串结尾

; ==============================================================================
; MBR 填充和签名
; ==============================================================================
times 510-($-$$) db 0    ; 填充到 510 字节
dw 0xaa55               ; MBR 签名（小端序：55 AA）
```

保存这个文件，然后编译运行：

```bash
cd boot
make clean
make
make run
```

你应该看到屏幕上显示：

```
Hello from CCOS Bootloader!
```

🎉 **恭喜你！**

这就是你的第一个真正能用的 MBR！

## 第二步：理解代码的每一部分

现在我们来回看一下代码，确保你理解每一行在做什么。

### 2.1 环境初始化

```asm
cli             ; 关闭中断
xor ax, ax      ; AX = 0
mov ds, ax      ; Data Segment = 0
mov es, ax      ; Extra Segment = 0
mov ss, ax      ; Stack Segment = 0
mov sp, 0x7c00  ; Stack Pointer
sti             ; 开启中断
```

**为什么要这样做？**

当 BIOS 把控制权交给我们的时候，段寄存器的值是不确定的。我们先把它们全部设为 0，这样才能安全地访问内存。(PS,之前我在bochs上干活的时候发现bochs的BIOS已经贴心的给我寄存器清零了，但是，额，别赌博，是不是？)

`cli` 和 `sti` 是为了在初始化期间防止中断干扰。

**为什么栈指针设在 `0x7C00`？**

因为我们的代码从 `0x7C00` 开始，栈向下增长。把栈设在代码起始位置，栈会和代码"背对背"生长，互不干扰。

### 2.2 清屏操作

```asm
mov ah, 0x00    ; BIOS 显示功能：设置显示模式
mov al, 0x03    ; 模式 3：80x25 文本模式
int 0x10
```

**INT 10h 是什么？**

这是 BIOS 提供的视频中断。不同的 `AH` 值对应不同的功能：

- `AH = 0x00`：设置显示模式
- `AH = 0x0E`：在当前位置显示一个字符

**AL = 0x03 是什么意思？**

这是显示模式编号：
- `0x03` = 80x25 文本模式，16 色
- `0x12` = 80x25 文本模式，单色
- `0x13` = 320x200 图形模式，256 色

我们用文本模式就够了，图形模式后面再说。

### 2.3 print_string 函数

```asm
print_string:
    pusha           ; 保存所有寄存器

.loop:
    lodsb           ; 加载 [SI] 到 AL，SI++
    test al, al     ; 检查 AL 是否为 0
    jz .done        ; 如果是 0，结束

    mov ah, 0x0e    ; BIOS 显示功能
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性
    int 0x10        ; 调用 BIOS

    jmp .loop       ; 继续下一个字符

.done:
    popa            ; 恢复所有寄存器
    ret             ; 返回
```

**`lodsb` 做了什么？**

这条指令等价于：

```asm
mov al, [si]    ; 加载 SI 指向的字节到 AL
inc si          ; SI++
```

它是一条专门为字符串处理设计的指令，非常方便。

**`pusha` 和 `popa` 是什么？**

`pusha` 把所有 8 个通用寄存器压栈，`popa` 把它们全部恢复。这样我们就可以在函数内部随意使用这些寄存器，而不影响调用者的代码。

## 第三步：添加更多的消息

现在我们来打印更多的内容，包括换行和颜色。

修改 `welcome_msg` 部分：

```asm
; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db 0x1b, '[32m'              ; ANSI 颜色码（绿色） - 但 BIOS 不支持
    db "=================================", 0x0d, 0x0a
    db "     CCOS Bootloader v1.0", 0x0d, 0x0a
    db "=================================", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "System is starting...", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "Press any key to continue...", 0x0d, 0x0a
    db 0
```

等等，我刚才想用 ANSI 颜色码，但 BIOS 不支持这个。在实模式下我们只能用 BIOS 的属性字节。

让我们来写一个支持颜色的版本：

```asm
; ==============================================================================
; print_string_color - 打印带颜色的字符串
; 输入: SI = 字符串地址
;       BL = 颜色属性
; ==============================================================================
print_string_color:
    pusha

.loop:
    lodsb
    test al, al
    jz .done

    mov ah, 0x0e    ; BIOS 显示功能
    ; bh = 0（页号）
    ; bl = 颜色（调用时设置）
    int 0x10

    jmp .loop

.done:
    popa
    ret
```

然后这样调用：

```asm
; 打印绿色标题
mov si, title_msg
mov bl, 0x0A        ; 绿色字符
call print_string_color
```

**颜色属性值**

```
0x00 = 黑色      0x08 = 暗灰色
0x01 = 蓝色      0x09 = 亮蓝色
0x02 = 绿色      0x0A = 亮绿色
0x03 = 青色      0x0B = 亮青色
0x04 = 红色      0x0C = 亮红色
0x05 = 品红      0x0D = 亮品红
0x06 = 棕色      0x0E = 黄色
0x07 = 白色      0x0F = 亮白色
```

## 第四步：验证二进制文件

现在我们来验证一下编译出来的文件是否正确。

```bash
# 查看文件大小
ls -lh ../build/bootloader.bin

# 查看十六进制内容
xxd ../build/bootloader.bin | tail -5
```

你应该看到：

```
-rw-r--r-- 1 user user 512 Feb 16 12:00 ../build/bootloader.bin
```

文件大小正好是 **512 字节**。

十六进制输出的最后应该是：

```
00001f0: 0000 0000 0000 0000 0000 0000 0000 0000  ................
00001fe: 55aa                                U.
```

等等，`55 aa` 是小端序存储，实际值是 `0xAA55`。这是正确的 MBR 签名。

⚠️ **如果文件不是 512 字节**

如果文件小于 512 字节，说明 `times 510-($-$$) db 0` 没有正常工作。

如果文件大于 512 字节... 那就有问题了。BIOS 只会读取 512 字节，超出的部分会被忽略。你需要精简代码。

## 第五步：常见陷阱

### 陷阱 1：忘记填充到 512 字节

**错误代码**：

```asm
; 忘记写这行
times 510-($-$$) db 0
```

**结果**：文件大小小于 512 字节，BIOS 无法识别。

### 陷阱 2：MBR 签名错误

**错误代码**：

```asm
dw 0xaa55    ; 错误！这是大端序
```

**正确代码**：

```asm
dw 0xaa55    ; NASM 会自动处理为小端序 55 AA
```

### 陷阱 3：字符串忘记 null 结尾

**错误代码**：

```asm
welcome_msg:
    db "Hello", 0x0d, 0x0a
    ; 忘记写 0
```

**结果**：`print_string` 会继续打印内存中的垃圾数据，直到遇到 0。

## 第六步：调试技巧

当你发现代码不工作的时候，这些技巧很有用：

### 6.1 使用 GDB 调试

启动 QEMU 时加 `-s -S` 参数：

```bash
qemu-system-x86_64 -drive format=raw,file=../build/boot.img,if=floppy -nographic -s -S
```

在另一个终端启动 GDB：

```bash
gdb
(gdb) target remote localhost:1234
(gdb) set architecture i8086
(gdb) break *0x7c00
(gdb) continue
(gdb) si       # 单步执行
(gdb) info registers   # 查看寄存器
```

### 6.2 反汇编检查

```bash
ndisasm -b 16 ../build/bootloader.bin | head -30
```

这会显示编译后的机器码对应的汇编指令，方便你确认代码是否正确。

### 6.3 检查字符串位置

```bash
xxd ../build/bootloader.bin | grep -i "hello"
```

这会帮你确认字符串数据是否正确放进了二进制文件。

## 完整代码

为了方便你对照，这里是完整的 `boot/bootloader.asm`：

```asm
; ==============================================================================
; CCOS Bootloader - MBR Stage
; ==============================================================================
; 功能：在屏幕上打印欢迎消息
; ==============================================================================

section .mbr
    org 0x7c00
    bits 16

start:
    ; ========== 环境初始化 ==========
    cli
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7c00
    sti

    ; ========== 清屏 ==========
    mov ah, 0x00
    mov al, 0x03
    int 0x10

    ; ========== 打印欢迎消息 ==========
    mov si, welcome_msg
    call print_string

    ; ========== 死循环 ==========
.hang:
    hlt
    jmp .hang

; ==============================================================================
; print_string - 打印以 null 结尾的字符串
; ==============================================================================
print_string:
    pusha
.loop:
    lodsb
    test al, al
    jz .done
    mov ah, 0x0e
    mov bh, 0
    mov bl, 0x07
    int 0x10
    jmp .loop
.done:
    popa
    ret

; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db "=================================", 0x0d, 0x0a
    db "     CCOS Bootloader v1.0", 0x0d, 0x0a
    db "=================================", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "System is starting...", 0x0d, 0x0a
    db 0

; ==============================================================================
; MBR 填充和签名
; ==============================================================================
times 510-($-$$) db 0
dw 0xaa55
```

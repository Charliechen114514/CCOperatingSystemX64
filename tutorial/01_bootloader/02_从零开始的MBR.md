# 从零开始的 MBR —— 让屏幕打印出你的第一行字

## 前言

上一篇文章我们已经把环境搭好了，屏幕上也成功打印出了一个字符 'A'。说实话，看到屏幕上出现自己写的文字，那种感觉真的很难形容。尤其是当你知道这行字是直接操作硬件显示出来的，而不是通过任何操作系统的时候。

但只有一个字符 'A' 实在太单调了。现在我们来做点真正有趣的事情——写一个能显示完整消息的 MBR。我们会实现一个字符串打印函数，然后打印出一段欢迎消息。虽然听起来很简单，但这里面有一些细节需要注意，尤其是 MBR 的 512 字节限制。

准备好了吗？我们开始。

## 理解 MBR 的结构

在我们开始写代码之前，先搞清楚 MBR 到底是什么。说实话，这个概念我一开始也没完全搞明白，直到踩了不少坑才真正理解。

MBR（Master Boot Record，主引导记录）是硬盘的第一个扇区。一个扇区是 512 字节，所以 MBR 的大小也就是 512 字节。当 BIOS 完成自检后，它会读取硬盘的第一个扇区到内存地址 `0x7C00`，然后跳转过去执行。这个地址是 x86 架构的标准约定，所有 BIOS 都会这么做。

⚠️ **512 字节的严格限制**

MBR 的大小严格限制为 512 字节。这一点真的坑了我半天。一开始我写了好多代码，结果编译出来发现超过了 512 字节，BIOS 根本不会加载它。而且这个限制不是编译器会报错的，你的代码可以编译得很好，但就是不会被执行。所以写 MBR 代码的时候，一定要时刻注意代码大小。

MBR 的结构是这样的：开头 446 字节是引导代码，就是我们写的程序。后面 64 字节是分区表，用来记录硬盘的分区信息。分区表有 4 个表项，每个 16 字节，所以 4 × 16 = 64 字节。最后 2 字节是签名，必须是 `0x55AA`。注意这里是小端序，所以实际存储为 `55 AA`。你可能会问为什么是 `0x55AA` 而不是别的值，这是 IBM 在 1983 年制定的标准，一直沿用到现在。

我们算一下：446 + 64 + 2 = 512。完美的 512 字节。不过等等，如果引导代码不到 446 字节怎么办？这时候需要填充。我们用 `times 510-($-$$) db 0` 来填充。这个指令的意思是，从当前位置填充 0 到 510 字节，留出最后 2 字节给签名。`$` 是当前地址，`$$` 是段起始地址，所以 `$-$$` 是当前段的字节数。

你可能还注意到签名用的是 `dw 0xaa55`，而不是 `db 0x55, 0xaa`。`dw` 是定义字（word，2 字节），NASM 会自动处理为小端序。如果你用 `db 0xaa, 0x55`，那就是大端序了，BIOS 不会识别。这个问题我也踩过，花了半天时间才发现是字节序的问题。

## 编写完整的 MBR 代码

现在我们来编写一个能打印完整消息的 MBR。打开 `boot/bootloader.asm`，把它改成这样：

```asm
; ==============================================================================
; CCOS Bootloader - MBR Stage
; ==============================================================================
; 这是我们的第一个真正能用的 MBR
; 功能：在屏幕上打印欢迎消息
; ==============================================================================

section .mbr
    org 0x7c00      ; BIOS 加载 MBR 到这个地址
    bits 16         ; 16 位实模式

start:
    ; ========== 环境初始化 ==========
    cli             ; 关闭中断
    xor ax, ax      ; AX = 0
    mov ds, ax      ; Data Segment = 0
    mov es, ax      ; Extra Segment = 0
    mov ss, ax      ; Stack Segment = 0
    mov sp, 0x7c00  ; Stack Pointer
    sti             ; 开启中断

    ; ========== 清屏 ==========
    mov ah, 0x00    ; BIOS 显示功能：设置显示模式
    mov al, 0x03    ; 模式 3：80x25 文本模式
    int 0x10

    ; ========== 打印欢迎消息 ==========
    mov si, welcome_msg    ; SI 指向消息
    call print_string      ; 调用打印函数

    ; ========== 死循环 ==========
.hang:
    hlt             ; Halt CPU
    jmp .hang       ; 无限循环

; ==============================================================================
; print_string - 打印以 null 结尾的字符串
; 输入: SI = 字符串地址
; 修改: AX, SI
; ==============================================================================
print_string:
    pusha           ; 保存所有寄存器

.loop:
    lodsb           ; 加载 [SI] 到 AL，SI++
    test al, al     ; 检查 AL 是否为 0（字符串结尾）
    jz .done        ; 如果是 0，结束

    mov ah, 0x0e    ; BIOS 显示功能：显示字符
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性：白色字符，黑色背景
    int 0x10

    jmp .loop       ; 继续下一个字符

.done:
    popa            ; 恢复所有寄存器
    ret             ; 返回

; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db "Hello from CCOS Bootloader!", 0x0d, 0x0a, 0
    ; 0x0d = CR (Carriage Return)
    ; 0x0a = LF (Line Feed)
    ; 0 = 字符串结尾

; ==============================================================================
; MBR 填充和签名
; ==============================================================================
times 510-($-$$) db 0    ; 填充到 510 字节
dw 0xaa55               ; MBR 签名（小端序：55 AA）
```

这段代码我们来逐段讲解。首先是环境初始化部分，和之前一样，关闭中断，清零段寄存器，设置栈指针。然后是清屏操作，这里我们用 BIOS 的 INT 10h 中断，功能号 0x00，设置显示模式。AL = 0x03 表示 80×25 文本模式，16 色。这个操作会清空屏幕，把光标移到左上角。

然后是打印欢迎消息。`mov si, welcome_msg` 把字符串地址放到 SI 寄存器，`call print_string` 调用打印函数。

`print_string` 函数是我们的核心。首先 `pusha` 保存所有通用寄存器，这样函数内部可以随意使用这些寄存器，而不影响调用者的代码。然后是一个循环。`lodsb` 加载 SI 指向的字节到 AL，然后 SI 自增。这条指令是专门为字符串处理设计的，非常方便。`test al, al` 检查 AL 是否为 0，`test` 是逻辑与指令，结果影响标志位但不保存结果。如果 AL 是 0，说明字符串结束，跳到 `.done`。否则，调用 BIOS 显示字符。`mov ah, 0x0e` 设置功能号，`mov bh, 0` 设置页号，`mov bl, 0x07` 设置属性。`int 0x10` 调用 BIOS 中断。然后 `jmp .loop` 继续下一个字符。

在 `.done` 标签，`popa` 恢复所有寄存器，`ret` 返回调用者。

数据段定义了欢迎消息。`db` 是定义字节（define byte）。我们定义了字符串 "Hello from CCOS Bootloader!"，然后是回车符 0x0d 和换行符 0x0a，最后是 0 表示字符串结束。

文件末尾是填充和签名，和之前一样。

保存这个文件，然后编译运行：

```bash
cd boot
make clean
make
make run
```

你应该看到屏幕上显示：

```
Hello from CCOS Bootloader!
```

🎉 **恭喜你！**

这就是你的第一个真正能用的 MBR！虽然只是打印一行字，但这是一个完整的 MBR，它有完整的初始化、清屏、字符串打印、死循环。更重要的是，你理解了 MBR 的结构，知道如何在 512 字节的限制内写代码。

## 理解代码的每一部分

现在我们来回看一下代码，确保你理解每一行在做什么。这部分很重要，如果你不完全理解，后面写更复杂的代码时会很吃力。

### 环境初始化

环境初始化的代码是这样的：

```asm
cli             ; 关闭中断
xor ax, ax      ; AX = 0
mov ds, ax      ; Data Segment = 0
mov es, ax      ; Extra Segment = 0
mov ss, ax      ; Stack Segment = 0
mov sp, 0x7c00  ; Stack Pointer
sti             ; 开启中断
```

为什么要这样做？当 BIOS 把控制权交给我们的时候，段寄存器的值是不确定的。你可能会想，BIOS 不是应该把寄存器清零吗？理论上应该，但实际上不同 BIOS 的行为不一样。我之前在 Bochs 上测试的时候，发现 Bochs 的 BIOS 确实贴心地给我清零了，但别赌博，不是所有 BIOS 都这么友好。所以我们要自己清零，这样才能安全地访问内存。

`cli` 和 `sti` 是为了在初始化期间防止中断干扰。`cli` 清除中断标志（Clear Interrupts），`sti` 设置中断标志（Set Interrupts）。在这两条指令之间，中断被禁用，我们可以安全地初始化环境。

为什么栈指针设在 `0x7C00`？因为我们的代码从 `0x7C00` 开始，栈向下增长。把栈设在代码起始位置，栈会和代码"背对背"生长，互不干扰。如果栈向上生长，可能会覆盖代码；如果向下生长太远，可能会覆盖 BIOS 数据区。`0x7C00` 是一个安全的位置。

### 清屏操作

清屏操作的代码是这样的：

```asm
mov ah, 0x00    ; BIOS 显示功能：设置显示模式
mov al, 0x03    ; 模式 3：80x25 文本模式
int 0x10
```

这里我们用 BIOS 的 INT 10h 中断。INT 10h 是 BIOS 提供的视频中断，不同的 AH 值对应不同的功能。AH = 0x00 是设置显示模式，AL 是模式号。0x03 表示 80×25 文本模式，16 色。这个操作会清空屏幕，把光标移到左上角。

你可能想知道有哪些显示模式。常用的有：0x03 = 80×25 文本模式，16 色；0x12 = 80×25 文本模式，单色；0x13 = 320×200 图形模式，256 色。我们用文本模式就够了，图形模式后面再说。

### print_string 函数

`print_string` 函数是这段代码的核心，我们来仔细分析一下：

```asm
print_string:
    pusha           ; 保存所有寄存器

.loop:
    lodsb           ; 加载 [SI] 到 AL，SI++
    test al, al     ; 检查 AL 是否为 0
    jz .done        ; 如果是 0，结束

    mov ah, 0x0e    ; BIOS 显示功能
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性
    int 0x10        ; 调用 BIOS

    jmp .loop       ; 继续下一个字符

.done:
    popa            ; 恢复所有寄存器
    ret             ; 返回
```

`lodsb` 做了什么？这条指令等价于 `mov al, [si]` 和 `inc si` 的组合。它加载 SI 指向的字节到 AL，然后 SI 自增。这是一条专门为字符串处理设计的指令，非常方便。类似的指令还有 `stosb`（存储 AL 到 [DI]，DI++）、`movsb`（从 [SI] 复制到 [DI]，SI++，DI++）等。

`pusha` 和 `popa` 是什么？`pusha` 把所有 8 个通用寄存器（AX, CX, DX, BX, SP, BP, SI, DI）压栈，`popa` 把它们全部恢复。这样我们就可以在函数内部随意使用这些寄存器，而不影响调用者的代码。这是一个好习惯，尤其是在写可能会被复用的函数时。

INT 10h 的 AH = 0x0E 功能是显示字符。AL 是要显示的字符，BH 是页号，BL 是属性。属性字节的格式是：低 4 位是前景色，高 4 位是背景色。0x07 表示黑色背景（0）、白色前景（7）。如果你想要蓝底白字，可以用 0x1F。

### 字符串格式

我们的欢迎消息是这样定义的：

```asm
welcome_msg:
    db "Hello from CCOS Bootloader!", 0x0d, 0x0a, 0
```

`db` 是定义字节（define byte），用来定义字节序列。我们定义了字符串，然后是回车符和换行符。你可能奇怪为什么要有两个字符。在早期的打字机时代，回车（Carriage Return）是把打印头移到行首，换行（Line Feed）是进纸。所以换一行需要两个操作。这个传统一直保留到现在。

最后是 0，表示字符串结束。我们的 `print_string` 函数遇到 0 就停止打印。如果你忘记这个 0，函数会继续打印内存中的垃圾数据，直到遇到 0。这个问题我也踩过，屏幕上会出现一堆乱码。

## 添加更多的消息

现在我们来打印更多的内容，包括换行和颜色。修改 `welcome_msg` 部分：

```asm
; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db "=================================", 0x0d, 0x0a
    db "     CCOS Bootloader v1.0", 0x0d, 0x0a
    db "=================================", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "System is starting...", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "Press any key to continue...", 0x0d, 0x0a
    db 0
```

这里我们把消息分成了多行，每行末尾都有回车换行。中间还有一个空行（两个回车换行）。最后提示用户按任意键继续。

不过等等，我们还没有实现按键检测。如果你想让用户按任意键后继续，需要添加等待按键的代码。在 `.hang` 之前添加：

```asm
    ; ========== 等待按键 ==========
    mov ah, 0x00    ; BIOS 键盘功能：等待按键
    int 0x16        ; 调用 BIOS
    ; AL = ASCII 字符，AH = 扫描码
```

INT 16h 是 BIOS 的键盘中断。AH = 0x00 是等待按键，函数会阻塞直到用户按下某个键。返回时 AL 是 ASCII 字符，AH 是扫描码。如果你不关心按键值，可以忽略返回值。

重新编译运行，你应该看到更完整的欢迎界面。

### 关于颜色

你可能想给消息加一些颜色，让它更醒目。但在实模式下，我们只能用 BIOS 的属性字节，不能用 ANSI 颜色码。ANSI 颜色码需要终端支持，而我们现在直接操作 VGA 硬件，BIOS 不支持 ANSI。

BIOS 的颜色属性是这样定义的：低 4 位是前景色，高 4 位是背景色。比如 0x07 表示黑色背景（0）、白色前景（7）。如果你想蓝底白字，用 0x1F。这里 1 是蓝色，F 是亮白色。

不过我们的 `print_string` 函数目前不支持颜色参数。如果你想打印带颜色的字符串，需要写一个新的函数：

```asm
; ==============================================================================
; print_string_color - 打印带颜色的字符串
; 输入: SI = 字符串地址
;       BL = 颜色属性
; ==============================================================================
print_string_color:
    pusha

.loop:
    lodsb
    test al, al
    jz .done

    mov ah, 0x0e    ; BIOS 显示功能
    ; bh = 0（页号）
    ; bl = 颜色（调用时设置）
    int 0x10

    jmp .loop

.done:
    popa
    ret
```

这个函数和 `print_string` 几乎一样，只是颜色值由调用者通过 BL 寄存器传入。你可以这样调用：

```asm
; 打印绿色标题
mov si, title_msg
mov bl, 0x0A        ; 绿色字符
call print_string_color
```

颜色属性值是这样的：0x00 = 黑色，0x01 = 蓝色，0x02 = 绿色，0x03 = 青色，0x04 = 红色，0x05 = 品红，0x06 = 棕色，0x07 = 白色。0x08 = 暗灰色，0x09 = 亮蓝色，0x0A = 亮绿色，0x0B = 亮青色，0x0C = 亮红色，0x0D = 亮品红，0x0E = 黄色，0x0F = 亮白色。你可以用这些值来组合前景色和背景色。

## 验证二进制文件

现在我们来验证一下编译出来的文件是否正确。这是一个好习惯，尤其是在调试 MBR 这种底层代码的时候。

首先查看文件大小：

```bash
ls -lh ../build/bootloader.bin
```

你应该看到类似这样的输出：

```
-rw-r--r-- 1 user user 512 Feb 16 12:00 ../build/bootloader.bin
```

文件大小正好是 512 字节。如果不是，说明有问题。回到代码，检查 `times 510-($-$$) db 0` 和签名是否正确。

然后查看十六进制内容：

```bash
xxd ../build/bootloader.bin | tail -5
```

你应该看到类似这样的输出：

```
00001f0: 0000 0000 0000 0000 0000 0000 0000 0000  ................
00001fe: 55aa                                U.
```

最后 4 个字节是 `55 aa`。等等，不是 `aa55` 吗？这是小端序存储。`dw 0xaa55` 定义的是字，NASM 会自动处理为小端序，所以实际存储是 `55 aa`。如果看到 `55 aa`，说明 MBR 签名正确。如果看到 `aa 55` 或者别的值，说明有问题。

⚠️ **如果文件不是 512 字节**

如果文件小于 512 字节，说明 `times 510-($-$$) db 0` 没有正常工作。检查这一行是否正确，是否有多余的空格或缩进问题。如果文件大于 512 字节，那就有问题了。BIOS 只会读取 512 字节，超出的部分会被忽略。你需要精简代码，或者考虑迁移到 Stage 2。

## 常见陷阱

这里我总结一些写 MBR 时常见的陷阱，希望你能避免。说实话，这些坑我都踩过，希望你不要重复我的错误。

### 陷阱 1：忘记填充到 512 字节

错误代码：

```asm
; 忘记写这行
times 510-($-$$) db 0
```

结果：文件大小小于 512 字节，BIOS 无法识别。症状是 QEMU 启动后直接跳过你的 MBR，或者显示 "No bootable device"。

### 陷阱 2：MBR 签名错误

错误代码：

```asm
dd 0xaa55    ; 错误！这是大端序
```

正确代码：

```asm
dw 0xaa55    ; NASM 会自动处理为小端序 55 AA
```

结果：BIOS 不识别 MBR。症状和陷阱 1 类似。

### 陷阱 3：字符串忘记 null 结尾

错误代码：

```asm
welcome_msg:
    db "Hello", 0x0d, 0x0a
    ; 忘记写 0
```

结果：`print_string` 会继续打印内存中的垃圾数据，直到遇到 0。症状是屏幕上出现一堆乱码。

### 陷阱 4：段寄存器没有清零

错误代码：

```asm
start:
    ; 忘记清零段寄存器
    mov si, welcome_msg
    call print_string
```

结果：访问内存时地址不正确。症状是程序行为不可预测，可能直接崩溃。

### 陷阱 5：栈指针设置不正确

错误代码：

```asm
mov sp, 0x0000    ; 错误！栈会和代码冲突
```

正确代码：

```asm
mov sp, 0x7c00    ; 栈设在代码起始位置
```

结果：栈可能覆盖代码，或者被代码覆盖。症状是程序行为不可预测，可能莫名其妙崩溃。

## 调试技巧

当你发现代码不工作的时候，这些技巧很有用。说实话，MBR 调试真的很痛苦，因为你没有任何调试工具，甚至连 print 都没有。不过还是有一些方法的。

### 使用 GDB 调试

启动 QEMU 时加 `-s -S` 参数：

```bash
qemu-system-x86_64 -drive format=raw,file=../build/boot.img,if=floppy -nographic -s -S
```

`-s` 创建 GDB server，监听 1234 端口。`-S` 启动时暂停 CPU，等待 GDB 连接。

在另一个终端启动 GDB：

```bash
gdb
(gdb) target remote localhost:1234
(gdb) set architecture i8086
(gdb) break *0x7c00
(gdb) continue
(gdb) si       # 单步执行
(gdb) info registers   # 查看寄存器
```

`set architecture i8086` 告诉 GDB 我们在调试 16 位代码。`break *0x7c00` 在 MBR 入口设置断点。`si` 是 step instruction，单步执行。`info registers` 查看寄存器值。

### 反汇编检查

```bash
ndisasm -b 16 ../build/bootloader.bin | head -30
```

这会显示编译后的机器码对应的汇编指令，方便你确认代码是否正确。`-b 16` 告诉 ndisasm 这是 16 位代码。`head -30` 只显示前 30 行。

### 检查字符串位置


## 完整代码

为了方便你对照，这里是完整的 `boot/bootloader.asm`：

```asm
; ==============================================================================
; CCOS Bootloader - MBR Stage
; ==============================================================================
; 功能：在屏幕上打印欢迎消息
; ==============================================================================

section .mbr
    org 0x7c00
    bits 16

start:
    ; ========== 环境初始化 ==========
    cli
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7c00
    sti

    ; ========== 清屏 ==========
    mov ah, 0x00
    mov al, 0x03
    int 0x10

    ; ========== 打印欢迎消息 ==========
    mov si, welcome_msg
    call print_string

    ; ========== 等待按键 ==========
    mov ah, 0x00
    int 0x16

    ; ========== 死循环 ==========
.hang:
    hlt
    jmp .hang

; ==============================================================================
; print_string - 打印以 null 结尾的字符串
; ==============================================================================
print_string:
    pusha
.loop:
    lodsb
    test al, al
    jz .done
    mov ah, 0x0e
    mov bh, 0
    mov bl, 0x07
    int 0x10
    jmp .loop
.done:
    popa
    ret

; ==============================================================================
; 数据段
; ==============================================================================
welcome_msg:
    db "=================================", 0x0d, 0x0a
    db "     CCOS Bootloader v1.0", 0x0d, 0x0a
    db "=================================", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "System is starting...", 0x0d, 0x0a
    db 0x0d, 0x0a
    db "Press any key to continue...", 0x0d, 0x0a
    db 0

; ==============================================================================
; MBR 填充和签名
; ==============================================================================
times 510-($-$$) db 0
dw 0xaa55
```

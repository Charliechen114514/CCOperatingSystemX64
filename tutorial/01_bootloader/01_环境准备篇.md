## 为什么从 Bootloader 开始？

很多朋友会问：为什么不直接用 GRUB？为什么不先学 Linux 内核？

说实话，我也想过这个问题。但如果你真的想理解操作系统是怎么从 BIOS/UEFI 一路启动到内核的，Bootloader 是绕不过的一关。你可以把它理解为你和硬件之间的第一道桥梁——没有这座桥，你写的再厉害的内核也只是一堆躺在硬盘上的字节。

更重要的是，写 Bootloader 会逼着你理解很多东西。实模式、保护模式、长模式，这三个词你以后会经常听到。在 Bootloader 里，你亲手从实模式一路切换到长模式，这个过程会让你对 x86 处理器的工作方式有非常直观的理解。内存管理是怎么工作的？磁盘 I/O 是怎么实现的？串口调试有多重要？这些问题你在写内核的时候全部都会用到。所以，不如现在就把它们搞清楚。

还有一个很实际的原因：GRUB 确实很强大，但它帮你做了太多事情。如果你直接用 GRUB，你可能会错过很多底层的细节。而这些细节，恰恰是理解操作系统本质的关键。

## 环境说明

在开始之前，我先说一下我的开发环境，这样你心里有个数。说实话，环境问题真的坑了我不少时间，尤其是刚开始的时候，各种工具版本不兼容，真的是非常折磨。

笔者的开发环境是这样的：操作系统是 Ubuntu 22.04 LTS，不过我是在 WSL2 上跑的。说到 WSL2，我这里要多嘴几句。一开始我在 Windows 上直接搞这些东西，结果遇到了各种权限问题、路径问题、文件系统问题，真的是让我血压拉满。后来切换到 WSL2，这些问题基本都消失了。所以如果你是 Windows 用户，强烈建议用 WSL2，它会给你一个接近原生的 Linux 环境，省去很多麻烦。当然，如果你是 Arch 用户（就像我一样），用 yay 安装软件也是完全没问题的。

汇编器我用的是 NASM，版本是 2.15.05 或者更高。为什么是 NASM 而不是 GAS 或者其他汇编器？说实话，NASM 的语法更直观，尤其是对于 x86 汇编来说，而且它的错误提示也比较友好。新版本对 64 位长模式的支持更好，所以如果你的版本低于 2.15，建议升级一下。

模拟器是 QEMU 7.0 或者更高版本。QEMU 是我们的测试环境，没有它的话，你每次都要重启真机，那会非常痛苦。而且 QEMU 支持 GDB 调试，这在后面会非常有用。调试器用的是 GDB 12.1 或者更高版本，这个在 Bootloader 开发中是救命神器，你一定会用到它。

构建工具我用的是 CMake 3.25 或者更高版本。不过 CMake 我们后面再说，现在先用 Makefile 快速开始。说实话，CMake 的优势在项目变大之后才会体现出来，刚开始的话，一个简单的 Makefile 反而更直接。

## 第一步：安装必需的工具

现在我们来安装这些工具。说实话，这部分比较枯燥，但真的很重要。如果你跳过这一步，后面一定会遇到各种奇怪的问题。

首先是 NASM 汇编器。在 Ubuntu 或者 Debian 上，你直接 `sudo apt-get install nasm` 就行了。如果你是 Arch 用户，用 `yay -S nasm` 也可以。安装完成之后，记得用 `nasm -v` 验证一下。你应该看到类似这样的输出：`NASM version 2.15.05 compiled on Jan 1 2024`。如果版本号低于 2.15，建议升级。新版本对 64 位长模式的支持更好，而且修复了一些旧版本的 bug。

接下来是 QEMU 模拟器。同样，在 Ubuntu/Debian 上用 `sudo apt-get install qemu-system-x86`，Arch 上用 yay 安装。安装完成后，用 `qemu-system-x86_64 --version` 验证。这里要注意一点，千万别装成 `qemu-system` 而不带 `-x86` 后缀，否则你会发现自己少了很多 x86_64 专用的选项。这个问题我一开始就踩了，花了半天时间才发现是包名的问题。

然后是 GDB 调试器。`sudo apt-get install gdb` 或者 `yay -S gdb` 就可以了。GDB 在 Bootloader 开发中是救命神器，你一定会用到它。说实话，刚开始我觉得单步调试很麻烦，总是喜欢用 print 语句。但到了 Bootloader 这种底层代码，你连 print 都没有，GDB 就成了你唯一的朋友。

CMake 也是类似的安装方式。不过 CMake 我们后面再说，现在先用 Makefile 快速开始。

除了这些必需的工具，还有一些实用工具虽然不是必须的，但会让你的开发体验好很多。比如 `xxd`，这是一个十六进制查看器，以后你会经常用它看二进制文件。当你怀疑编译出来的文件有问题的时候，用 `xxd` 看一眼往往能发现问题所在。还有 `ndisasm`，这是 NASM 自带的反汇编工具，调试的时候很有用。你可以用它来看编译出来的机器码对应的汇编指令，确认代码是否正确。最后是 `minicom`，这是一个串口工具，用来查看串口输出。虽然我们现在用的是 VGA 输出，但后面加了串口支持之后，这个工具就很有用了。

## 第三步：编写第一个 Makefile

说实话，CMake 我们后面再说。现在先用 Makefile 快速开始。Makefile 虽然语法有点怪，但用来编译几个汇编文件还是绰绰有余的。

创建 `boot/Makefile`，我们先从一个最简单的版本开始。你需要定义几个变量：`NASM` 是汇编器名称，`QEMU` 是模拟器名称，`DEBUGGER` 是调试器名称。然后定义源文件和目标文件。`BOOT_SRC` 是源文件名，`BOOT_BIN` 是编译后的二进制文件名，`BOOT_IMG` 是最终的磁盘镜像文件名。`BUILD_DIR` 是构建目录，我们把它设为 `../build`。

接下来是编译规则。`all` 是默认目标，它依赖 `$(BOOT_IMG)`。`$(BOOT_BIN)` 依赖 `$(BOOT_SRC)`，编译命令是 `$(NASM) -f bin $< -o $@`。`-f bin` 告诉 NASM 输出纯二进制格式，这是 bootloader 需要的格式。`$(BOOT_IMG)` 依赖 `$(BOOT_BIN)`，我们用 `dd` 命令创建磁盘镜像。先用 `dd if=/dev/zero of=$@ bs=512 count=2880` 创建一个空的 1.44MB 软盘镜像，然后用 `dd if=$< of=$@ bs=512 conv=notrunc` 把 bootloader 写入镜像的开头。`conv=notrunc` 很重要，它告诉 dd 不要截断输出文件，否则你的镜像会被压缩成 512 字节。

最后是运行规则和清理规则。`run` 目标直接调用 QEMU 启动镜像。`clean` 目标删除 build 目录。

⚠️ **注意 Tab 缩进**

Makefile 对缩进非常敏感。命令前面必须是 **Tab**，不是空格！如果你用的是 VSCode，记得设置 `"editor.insertSpaces": false`。这个问题我一开始也踩了，花了半天时间才发现是 Tab 和空格的问题。

## 完整的 Makefile

下面是完整的 `boot/Makefile`，你可以直接复制过去，然后我们逐段讲解。

```makefile
# CCOS Bootloader Makefile
# 这是我们从零开始的第一步

NASM = nasm
QEMU = qemu-system-x86_64
DEBUGGER = gdb

# 源文件和目标文件
BOOT_SRC = bootloader.asm
BOOT_BIN = $(BUILD_DIR)/bootloader.bin
BOOT_IMG = $(BUILD_DIR)/boot.img

# 构建目录
BUILD_DIR = ../build

# 默认目标
.PHONY: all
all: $(BOOT_IMG)

# 编译 bootloader
$(BOOT_BIN): $(BOOT_SRC)
	@echo "==> Building bootloader..."
	@mkdir -p $(BUILD_DIR)
	$(NASM) -f bin $< -o $@
	@echo "==> Build complete: $@"

# 创建磁盘镜像（1.44MB 软盘）
$(BOOT_IMG): $(BOOT_BIN)
	@echo "==> Creating disk image..."
	dd if=/dev/zero of=$@ bs=512 count=2880 status=none
	dd if=$< of=$@ bs=512 conv=notrunc status=none
	@echo "==> Disk image created: $@"

# 运行 QEMU
.PHONY: run
run: $(BOOT_IMG)
	$(QEMU) -drive format=raw,file=$(BOOT_IMG),if=floppy -nographic

# 清理
.PHONY: clean
clean:
	rm -rf $(BUILD_DIR)
	@echo "==> Clean complete"
```

这个 Makefile 不长，我们来逐段讲解。首先是变量定义部分，这里定义了汇编器、模拟器、调试器的名称。这些变量放在前面，方便后面修改。比如如果你想用别的模拟器，只需要改 `QEMU` 变量就行了。

然后是源文件和目标文件。`BOOT_SRC` 是源文件名，`BOOT_BIN` 是编译后的二进制文件名，`BOOT_IMG` 是最终的磁盘镜像文件名。注意这里我们用了 `$(BUILD_DIR)` 变量，这样所有的编译产物都会放在 build 目录里，保持项目根目录的整洁。

接下来是构建规则。`all` 是默认目标，它依赖 `$(BOOT_IMG)`。`.PHONY:` 告诉 Make 这是一个伪目标，不对应实际文件。`$(BOOT_BIN)` 规则编译源文件。`@echo` 命令打印一些信息，`@` 前缀告诉 Make 不要打印命令本身。`mkdir -p` 创建目录，如果目录已存在也不会报错。`$(NASM) -f bin $< -o $@` 编译源文件，`$<` 是依赖文件（源文件），`$@` 是目标文件（二进制文件）。

`$(BOOT_IMG)` 规则创建磁盘镜像。第一条 `dd` 命令创建空镜像，`if=/dev/zero` 表示从零设备读取（也就是全零），`of=$@` 是输出文件，`bs=512` 是块大小，`count=2880` 是块数，所以总共是 512 × 2880 = 1474560 字节，正好是 1.44MB。第二条 `dd` 命令把 bootloader 写入镜像开头，`conv=notrunc` 很重要，它告诉 dd 不要截断输出文件。

`run` 规则启动 QEMU。`-drive format=raw,file=$(BOOT_IMG),if=floppy` 告诉 QEMU 用软盘接口加载我们的镜像。`-nographic` 表示不使用图形界面，所有输出都到终端。如果你想用图形界面，可以去掉这个选项。

`clean` 规则删除 build 目录。`rm -rf` 强制删除目录及其内容，`-rf` 表示递归删除且不提示。

保存这个文件，然后试试看。`cd boot` 进入 boot 目录，然后 `make clean` 清理一下。你应该看到 `==> Clean complete`。很好，现在 Makefile 工作正常。

## 第四步：验证环境

现在我们来写一个最简单的测试程序，确保所有工具都工作正常。这个程序很简单，只是在屏幕上打印一个字符 'A'，然后死循环。虽然简单，但它能验证我们的环境配置是否正确。

创建 `boot/bootloader.asm`：

```asm
; ==============================================================================
; CCOS Bootloader - 测试程序
; ==============================================================================
; 这是我们写的第一个 bootloader，功能很简单：只是在屏幕上打印一个字符
; 然后死循环。但这能验证我们的环境配置是否正确。
; ==============================================================================

section .mbr
    org 0x7c00      ; BIOS 加载 MBR 到这个地址
    bits 16         ; 我们从 16 位实模式开始

start:
    ; 关闭中断，设置段寄存器
    cli             ; Clear Interrupts - 暂时不需要中断
    xor ax, ax      ; AX = 0
    mov ds, ax      ; Data Segment = 0
    mov es, ax      ; Extra Segment = 0
    mov ss, ax      ; Stack Segment = 0
    mov sp, 0x7c00  ; Stack Pointer = MBR 起始地址
    sti             ; Enable Interrupts

    ; 在屏幕上打印一个字符 'A'
    mov al, 'A'     ; 字符
    mov ah, 0x0e    ; BIOS 显示功能
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性（白色字符）
    int 0x10        ; 调用 BIOS 中断

.hang:
    hlt             ; Halt CPU
    jmp .hang       ; 无限循环

; 填充到 510 字节
times 510-($-$$) db 0

; MBR 签名（必须有！）
dw 0xaa55
```

这个文件我们来逐段讲解。首先是 `section .mbr`，这告诉 NASM 我们要创建一个叫 `.mbr` 的段。`org 0x7c00` 告诉 NASM 我们的代码会被加载到内存地址 `0x7c00`，这是 BIOS 加载 MBR 的标准地址。`bits 16` 告诉 NASM 我们要生成 16 位代码，因为我们从实模式开始。

然后是 `start` 标签，这是我们代码的入口点。首先 `cli` 关闭中断，`xor ax, ax` 把 AX 设为 0。`xor` 是异或指令，一个数和自己异或结果是 0，这是一种常见的清零寄存器的方法。然后把 0 放入 DS、ES、SS 段寄存器，把栈指针 SP 设为 `0x7c00`。最后 `sti` 重新开启中断。

接下来是打印字符的部分。`mov al, 'A'` 把字符 'A' 放入 AL，`mov ah, 0x0e` 设置 AH 为 0x0e，这是 BIOS 的显示字符功能。`mov bh, 0` 设置页号为 0，`mov bl, 0x07` 设置属性为白色字符黑色背景。`int 0x10` 调用 BIOS 中断。

最后是死循环。`hlt` 让 CPU 停止执行，等待中断。`jmp .hang` 跳回前面，形成一个无限循环。

文件末尾是填充和签名。`times 510-($-$$) db 0` 填充 0 到 510 字节。`$` 是当前地址，`$$` 是段起始地址，所以 `$-$$` 是当前段的字节数。`510-($-$$)` 就是还需要填充的字节数。`dw 0xaa55` 是 MBR 签名，必须是 `0xaa55`，小端序存储为 `55 aa`。

现在编译并运行。`cd boot` 进入 boot 目录，`make clean` 清理，`make` 编译。你应该看到类似这样的输出：

```
==> Building bootloader...
==> Build complete: ../build/bootloader.bin
==> Creating disk image...
==> Disk image created: ../build/boot.img
```

很好，编译成功了！现在运行它。`make run` 启动 QEMU。你应该在屏幕上看到一个 `A`。

🎉 **恭喜你！**

这就是你的第一个 bootloader！虽然它只是打印一个字符，但这是一个完整的 bootloader，它证明了你的环境配置是正确的，你的工具链工作正常，你的 QEMU 也能正确启动。

## 第五步：如果出错了怎么办

如果你没有看到字符 'A'，或者编译出错了，别慌，我们一步步排查。

### 问题 1：`nasm: command not found`

这说明 NASM 没安装或没在 PATH 里。回去检查第一步，确认 NASM 已经安装。你可以用 `which nasm` 查看 NASM 在哪里，用 `nasm -v` 查看版本。如果提示命令不存在，说明安装失败了。在 Ubuntu/Debian 上，你可以用 `dpkg -L nasm` 查看 NASM 安装了哪些文件。在 Arch 上，用 `pacman -Ql nasm` 查看。

### 问题 2：`make: *** No rule to make target 'xxx'`

这个错误通常是 Makefile 的格式问题。检查几个点：命令前面必须是 Tab，不是空格。文件名是否拼写正确。当前目录是否正确。你可以在 Makefile 里加一些 `@echo` 命令，看看 Makefile 读到了哪些变量值。

### 问题 3：QEMU 启动后什么都没有

这个问题比较复杂，可能是几个原因。检查几个点：`bootloader.asm` 是否保存了，编译是否成功（看 `bootloader.bin` 是否存在），MBR 签名 `0xaa55` 是否在正确位置。

你可以用 `xxd ../build/bootloader.bin | tail -5` 查看二进制文件的最后几行。你应该看到最后的签名是 `55 aa`（小端序）。如果看到了，说明 MBR 签名正确。如果没看到，或者文件大小不是 512 字节，说明有问题。回到代码，检查 `times 510-($-$$) db 0` 和 `dw 0xaa55` 这两行是否正确。

还有一个可能的问题是，你的 bootloader.asm 文件可能有隐藏字符或者编码问题。尤其是如果你是从网上复制的代码，可能会有一些不可见字符。最好的办法是手动输入一遍，确保没有问题。

### 问题 4：`dd: failed to open 'xxx': Permission denied`

这是权限问题。确认你对 build 目录有写权限。你可以用 `ls -la ../build` 查看权限。如果没有权限，用 `chmod u+w ../build` 添加写权限。或者直接用 `sudo`，虽然这不是最好的做法，但在开发阶段可以临时使用。

## 第六步：检查清单

在继续下一篇文章之前，请确认以下几点。这个检查清单很重要，如果你跳过任何一项，后面可能会遇到问题。

首先确认 NASM 已安装并且版本 >= 2.15。你可以用 `nasm -v` 查看。如果版本低于 2.15，建议升级。新版本对 64 位长模式的支持更好，而且修复了一些旧版本的 bug。

然后确认 QEMU 已安装并能正常启动。用 `qemu-system-x86_64 --version` 查看版本。试着启动一下你编译的镜像，看看是否正常工作。

确认 GDB 已安装。虽然我们暂时不用，但后面调试的时候会用到。用 `gdb --version` 查看版本。

确认 CMake 已安装。同样，虽然我们暂时不用 Makefile，但后面会迁移到 CMake。用 `cmake --version` 查看版本。

确认项目目录结构正确。你应该有 boot、build、tutorial 三个目录。boot 目录放 bootloader 代码，build 目录放编译产物，tutorial 目录放教程文档。

确认第一个测试程序能编译并运行。这是最重要的一点。如果你到现在还没有看到屏幕上的字符 'A'，不要继续。回头检查每一步，确保环境配置正确。

确认屏幕上能看到字符 'A'。如果能看到，恭喜你，你已经跨过了第一个门槛！

准备好了吗？我们继续。

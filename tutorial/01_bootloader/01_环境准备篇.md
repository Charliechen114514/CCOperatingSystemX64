## 为什么从 Bootloader 开始？

很多朋友会问：为什么不直接用 GRUB？为什么不先学 Linux 内核？

说实话，我也想过这个问题。但如果你真的想理解操作系统是怎么从 BIOS/UEFI 一路启动到内核的，Bootloader 是绕不过的一关。

更重要的是，写 Bootloader 会逼着你理解：
- x86 处理器的三种模式（实模式、保护模式、长模式）
- 内存管理是怎么工作的
- 磁盘 I/O 是怎么实现的
- 串口调试有多重要

这些东西，你以后写内核的时候全部都会用到。所以，不如现在就把它们搞清楚。

## 环境说明

在开始之前，我先说一下我的开发环境：

```
操作系统: Ubuntu 22.04 LTS / WSL2 （笔者更幽默一点，是Arch WSL孩子们）
汇编器:   NASM 2.15.05 或更高版本
模拟器:   QEMU 7.0 或更高版本
调试器:   GDB 12.1 或更高版本
构建工具: CMake 3.25 或更高版本
```

**为什么是 WSL2？**

老实说，在 Windows 上直接搞这些东西会非常痛苦。你会遇到各种权限问题、路径问题、文件系统问题。WSL2 可以让你在一个接近原生的 Linux 环境里工作，省去很多麻烦。

如果你是用 macOS，也没问题，命令基本都一样。

## 第一步：安装必需的工具

### 1.1 安装 NASM 汇编器

NASM 是我们在 x86 平台上最好的朋友。 trust me。

```bash
# Ubuntu/Debian
sudo apt-get install nasm

# 我是Arch
yay -S nasm

# 验证安装
nasm -v
```

你应该看到类似这样的输出：

```
NASM version 2.15.05 compiled on Jan 1 2024
```

如果版本号低于 2.15，建议升级。新版本对 64 位长模式的支持更好。

### 1.2 安装 QEMU 模拟器

QEMU 是我们的测试环境。没有它，你每次都要重启真机，那会非常痛苦。

```bash
# Ubuntu/Debian
sudo apt-get install qemu-system-x86

# 验证安装
qemu-system-x86_64 --version
```

⚠️ **注意**

千万别装成 `qemu-system` 而不带 `-x86` 后缀，否则你会发现自己少了很多 x86_64 专用的选项。

### 1.3 安装 GDB 调试器

GDB 在 Bootloader 开发中是救命神器。你一定会用到它。

```bash
# Ubuntu/Debian
sudo apt-get install gdb

# 验证安装
gdb --version
```

### 1.4 安装 CMake

我们的项目用 CMake 来管理构建流程。

```bash
# Ubuntu/Debian
sudo apt-get install cmake

# 验证安装
cmake --version
```

### 1.5 其他实用工具

这些工具不是必须的，但会让你的开发体验好很多：

```bash
# 十六进制查看器 - 以后你会经常用它看二进制文件
sudo apt-get install xxd

# 反汇编工具 - 调试的时候很有用
sudo apt-get install ndisasm

# 串口工具 - 用来查看串口输出
sudo apt-get install minicom
```

## 第三步：编写第一个 Makefile

说实话，CMake 我们后面再说。现在先用 Makefile 快速开始。

创建 `boot/Makefile`：

```makefile
# CCOS Bootloader Makefile
# 这是我们从零开始的第一步

NASM = nasm
QEMU = qemu-system-x86_64
DEBUGGER = gdb

# 源文件和目标文件
BOOT_SRC = bootloader.asm
BOOT_BIN = $(BUILD_DIR)/bootloader.bin
BOOT_IMG = $(BUILD_DIR)/boot.img

# 构建目录
BUILD_DIR = ../build

# 默认目标
.PHONY: all
all: $(BOOT_IMG)

# 编译 bootloader
$(BOOT_BIN): $(BOOT_SRC)
	@echo "==> Building bootloader..."
	@mkdir -p $(BUILD_DIR)
	$(NASM) -f bin $< -o $@
	@echo "==> Build complete: $@"

# 创建磁盘镜像（1.44MB 软盘）
$(BOOT_IMG): $(BOOT_BIN)
	@echo "==> Creating disk image..."
	dd if=/dev/zero of=$@ bs=512 count=2880 status=none
	dd if=$< of=$@ bs=512 conv=notrunc status=none
	@echo "==> Disk image created: $@"

# 运行 QEMU
.PHONY: run
run: $(BOOT_IMG)
	$(QEMU) -drive format=raw,file=$(BOOT_IMG),if=floppy -nographic

# 清理
.PHONY: clean
clean:
	rm -rf $(BUILD_DIR)
	@echo "==> Clean complete"
```

保存这个文件，然后试试看：

```bash
cd boot
make clean
```

你应该看到：

```
==> Clean complete
```

⚠️ **注意 Tab 缩进**

Makefile 对缩进非常敏感。命令前面必须是 **Tab**，不是空格！如果你用的是 VSCode，记得设置 `"editor.insertSpaces": false`。

## 第四步：验证环境

现在我们来写一个最简单的测试程序，确保所有工具都工作正常。

创建 `boot/bootloader.asm`：

```asm
; ==============================================================================
; CCOS Bootloader - 测试程序
; ==============================================================================
; 这是我们写的第一个 bootloader，功能很简单：只是在屏幕上打印一个字符
; 然后死循环。但这能验证我们的环境配置是否正确。
; ==============================================================================

section .mbr
    org 0x7c00      ; BIOS 加载 MBR 到这个地址
    bits 16         ; 我们从 16 位实模式开始

start:
    ; 关闭中断，设置段寄存器
    cli             ; Clear Interrupts - 暂时不需要中断
    xor ax, ax      ; AX = 0
    mov ds, ax      ; Data Segment = 0
    mov es, ax      ; Extra Segment = 0
    mov ss, ax      ; Stack Segment = 0
    mov sp, 0x7c00  ; Stack Pointer = MBR 起始地址
    sti             ; Enable Interrupts

    ; 在屏幕上打印一个字符 'A'
    mov al, 'A'     ; 字符
    mov ah, 0x0e    ; BIOS 显示功能
    mov bh, 0       ; 页号
    mov bl, 0x07    ; 属性（白色字符）
    int 0x10        ; 调用 BIOS 中断

.hang:
    hlt             ; Halt CPU
    jmp .hang       ; 无限循环

; 填充到 510 字节
times 510-($-$$) db 0

; MBR 签名（必须有！）
dw 0xaa55
```

现在编译并运行：

```bash
cd boot
make
```

你应该看到：

```
==> Building bootloader...
==> Build complete: ../build/bootloader.bin
==> Creating disk image...
==> Disk image created: ../build/boot.img
```

很好，编译成功了！现在运行它：

```bash
make run
```

你应该在屏幕上看到一个 `A`。

## 第五步：如果出错了怎么办

### 问题 1：`nasm: command not found`

这说明 NASM 没安装或没在 PATH 里。回去检查第一步。

### 问题 2：`make: *** No rule to make target 'xxx'`

检查你的 Makefile 格式：
- 命令前面必须是 Tab
- 文件名是否拼写正确
- 当前目录是否正确

### 问题 3：QEMU 启动后什么都没有

检查几个点：
- `bootloader.asm` 是否保存了
- 编译是否成功（看 `bootloader.bin` 是否存在）
- MBR 签名 `0xaa55` 是否在正确位置

用这个命令检查二进制文件：

```bash
xxd ../build/bootloader.bin | tail -5
```

你应该看到最后的签名：

```
00001f0: 0000 0000 0000 0000 0000 0000 0000 0000  ................
00001fe: 0000                                ..
```

等等，不对。最后 4 个字节应该是 `55 aa`。如果看到了，说明 MBR 签名正确。

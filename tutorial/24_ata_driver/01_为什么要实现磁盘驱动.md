# 为什么要实现磁盘驱动 —— Stage 24 ATA 驱动实战指南

## 前言

写到 Stage 24 的时候，我意识到一个被我们忽略很久的问题：内核虽然跑起来了，有了进程管理，有了系统调用，但它本质上还是个"失忆症患者"。所有数据都只能存在内存里，一旦断电或者重启，辛辛苦苦创建的进程、写入的数据全部消失。

说实话，这种体验我太熟了。你在 QEMU 里折腾半天，实现了一个很酷的功能，结果下一次启动一切归零。更糟糕的是，没有磁盘驱动意味着我们无法实现文件系统，无法保存配置，无法加载用户程序 —— 操作系统变成了一个只能跑在内存里的"玩具"。

所以这一篇我们会一起实现一个完整的 ATA 磁盘驱动。别担心，我们不会跳过任何步骤，每写一个函数都会解释清楚它是怎么工作的，为什么要这么写，有哪些坑需要避开。准备好了吗？我们开始。

---

## 环境说明

在开始之前，先确认一下你的开发环境。这篇文章假设你已经完成了 Stage 23，用户进程系统已经实现完毕。

```
操作系统: Ubuntu 22.04 LTS / WSL2 / Arch WSL
编译器:   GCC x86_64-elf-gcc 或类似交叉编译器
构建工具: CMake 3.25 或更高版本
模拟器:   QEMU 7.0 或更高版本
汇编器:   NASM 2.15 或更高版本
```

可能有人会问，为什么需要 QEMU？因为真实的硬件环境调试起来太麻烦了，QEMU 提供了很好的磁盘模拟，而且支持 GDB 调试，非常适合驱动开发。

## 当前系统的局限性

让我们先看看 Stage 23 结束时系统的状态。虽然有进程管理，但存储能力严重受限。

### 只有内存存储的问题

```c
// 当前我们能做的
void process_a(void) {
    char buffer[1024];
    // 做一些计算
    strcpy(buffer, "Hello, World!");
    // ... 使用数据

    // 问题：进程结束后数据就丢失了
    // 下次启动无法恢复
}
```

你看到了问题在哪里吗？

第一，**数据无法持久化**。所有数据只存在于 RAM 中，断电就没了。

第二，**容量受限**。物理内存有多少，系统就能用多少。128MB 的内存意味着最多 128MB 数据。

第三，**无法加载程序**。用户程序必须编译进内核镜像，无法动态加载。

第四，**没有文件系统基础**。文件系统需要磁盘支持，没有磁盘驱动就什么都免谈。

### 我们需要什么

一个完整的操作系统需要：

```
┌─────────────────────────────────────────────────────────┐
│                   应用程序                               │
├─────────────────────────────────────────────────────────┤
│                   文件系统                               │  ← 需要
├─────────────────────────────────────────────────────────┤
│                   块设备驱动                             │  ← 我们要做的
├─────────────────────────────────────────────────────────┤
│                   ATA 硬件                               │
└─────────────────────────────────────────────────────────┘
```

磁盘驱动是文件系统的基础，没有它就没有 ext2、没有 FAT、没有你熟悉的任何文件系统。

## 技术背景：ATA/IDE 是什么

在我们开始写代码之前，先了解一下我们要控制的硬件是什么。

### ATA 简史

ATA（Advanced Technology Attachment）是 1980 年代由 IBM 和 WD 等公司开发的磁盘接口标准。你可能更熟悉它的另一个名字 —— IDE（Integrated Drive Electronics）。

实际上 ATA 和 IDE 基本上是一回事，IDE 是更早期的叫法。后来又发展出了 SATA（Serial ATA），但我们现在要做的是传统的并行 ATA（PATA），因为：

1. **硬件简单** - 直接通过 I/O 端口控制
2. **规范清晰** - 协议相对简单
3. **QEMU 支持** - 模拟器默认支持
4. **学习友好** - 适合理解驱动原理

### ATA 控制器架构

x86 系统中的 ATA 控制器布局是这样的：

```
┌─────────────────────────────────────────────────────────┐
│                      CPU                                 │
│                     (x86_64)                             │
└────────────────────┬────────────────────────────────────┘
                     │ I/O 端口
┌────────────────────▼────────────────────────────────────┐
│                   ATA 控制器                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────────────┐        ┌──────────────────┐      │
│  │ Primary Channel  │        │ Secondary Channel│      │
│  │ I/O: 0x1F0       │        │ I/O: 0x170       │      │
│  │ IRQ: 14          │        │ IRQ: 15          │      │
│  ├──────────────────┤        ├──────────────────┤      │
│  │  Master (dev 0)  │        │  Master (dev 2)  │      │
│  │  Slave  (dev 1)  │        │  Slave  (dev 3)  │      │
│  └──────────────────┘        └──────────────────┘      │
│                                                         │
└─────────────────────────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│                   ATA 设备                               │
│              (HDD / SSD / CD-ROM)                       │
└─────────────────────────────────────────────────────────┘
```

- **Primary Channel**：传统主通道，I/O 端口 0x1F0，IRQ 14
- **Secondary Channel**：传统从通道，I/O 端口 0x170，IRQ 15
- **Master/Slave**：每个通道可以连接两个设备，通过跳线或线缆选择

我们主要关注 Primary Master（设备 0），这是大多数系统启动盘的位置。

## 设计决策：PIO vs DMA

实现 ATA 驱动之前，我们面临一个重要的选择：使用 PIO 模式还是 DMA 模式。

### PIO (Programmed I/O)

PIO 是最简单的数据传输方式，CPU 直接通过 IN/OUT 指令读写数据：

```c
// PIO 读取示例
uint16_t data = inw(io_base + ATA_REG_DATA);
```

**优点**：
- 实现简单，直接使用 I/O 指令
- 不需要额外的 DMA 控制器
- 易于理解和调试
- 学习友好

**缺点**：
- CPU 占用高，每次传输都需要 CPU 参与
- 速度相对较慢

### DMA (Direct Memory Access)

DMA 让磁盘控制器直接与内存交换数据，CPU 只需要启动传输：

```c
// DMA 读取示例（概念）
setup_dma_prd(buffer, sectors);
start_dma_transfer();
// CPU 可以做其他事情...
wait_dma_complete();
```

**优点**：
- CPU 占用低，可以并行工作
- 传输速度快
- 适合大块数据

**缺点**：
- 实现复杂，需要配置 Bus Master
- 需要 DMA 缓冲区管理
- 调试困难

### 我们的选择：PIO

经过权衡，我决定使用 PIO 模式。原因很简单：

1. **这是教程** - PIO 模式更容易理解 ATA 协议的本质
2. **足够使用** - 对于操作系统开发初期，PIO 的速度完全够用
3. **渐进式** - 掌握 PIO 后可以再升级 DMA
4. **稳定可靠** - 简单意味着更少的 bug

如果你对 DMA 感兴趣，可以在理解 PIO 代码后自行实现 Bus Master DMA。代码架构已经考虑了这一点。

## 寻址方式：LBA vs CHS

另一个需要选择的磁盘寻址方式。

### CHS（柱面-磁头-扇区）

早期的磁盘使用 CHS 寻址：

```c
typedef struct {
    uint16_t cylinder;  // 柱面号
    uint8_t  head;      // 磁头号
    uint8_t  sector;    // 扇区号
} chs_address_t;
```

这种方式直接对应磁盘物理结构，但有个致命问题：容量限制在 8GB。

### LBA（逻辑块地址）

LBA 把整个磁盘看作一个线性数组：

```c
uint64_t lba = 0;  // 第 0 个扇区
uint64_t lba = 1;  // 第 1 个扇区
// ...
```

**LBA28** 使用 28 位地址，最大支持 128GB。
**LBA48** 使用 48 位地址，最大支持 128PB。

### 我们的选择：LBA 优先，LBA48 扩展

我们的实现会：
1. 优先使用 LBA28 寻址（兼容性好）
2. 检测并支持 LBA48（大容量磁盘）
3. 保留 CHS 回退（理论上需要，实际上很少用）

```c
// 我们的读写接口直接使用 LBA
ata_read(ATA_PRIMARY_MASTER, 0, buffer, 1);    // 读第 0 个扇区
ata_read(ATA_PRIMARY_MASTER, 1000000, buffer, 1); // 读第 100 万个扇区
```

驱动内部会自动选择 LBA28 或 LBA48，使用者无需关心。

## 同步 vs 异步 I/O

最后一个设计选择：I/O 操作的执行方式。

### 同步阻塞模式

```c
// 同步读取
ata_read(device, lba, buffer, sectors);
// 在这里等待操作完成...
// CPU 被阻塞，无法做其他事情
```

**优点**：简单、直观、易于理解
**缺点**：CPU 浪费、响应慢

### 异步中断驱动模式

```c
// 异步读取
ata_read_async(device, lba, buffer, sectors, callback, NULL);
// 立即返回，CPU 可以做其他事情
// ... 在某个时候回调被调用 ...
```

**优点**：高效、CPU 并行、响应快
**缺点**：复杂、需要中断系统支持

### 我们的选择：两者都支持

我们的 API 设计提供两种模式：

```c
// 同步初始化（默认）
ata_init();  // 使用轮询模式

// 异步初始化（可选）
ata_init_ex(ATA_MODE_ASYNC);  // 使用中断驱动模式

// 同步 I/O
ata_read(device, lba, buffer, sectors);

// 异步 I/O
ata_read_async(device, lba, buffer, sectors, callback, NULL);
```

默认使用同步模式，因为：
1. 更简单，适合调试
2. 中断系统可能有 bug
3. 初始化阶段不需要高性能

需要的时候可以切换到异步模式：
```c
ata_init_async_mode();  // 启用中断驱动
```

## 我们要实现什么

现在我们明确了设计方向，让我们列出这一阶段要完成的目标。

### 核心功能

1. **设备检测与识别**
   - 探测 Primary/Secondary 通道的设备
   - 发送 IDENTIFY 命令获取设备信息
   - 解析设备能力（LBA/LBA48/DMA）
   - 解析设备信息（型号、序列号、容量）

2. **PIO 模式读写**
   - LBA28 寻址的读写操作
   - 多扇区连续传输
   - 状态轮询与错误处理
   - 写入后的缓存刷新

3. **LBA48 扩展支持**
   - 检测 LBA48 能力
   - 64 位 LBA 地址处理
   - 大容量磁盘支持

4. **异步 I/O 支持**
   - 中断驱动的异步操作
   - 操作队列管理
   - 回调机制
   - IRQ 14/15 处理

### API 设计

```c
// 初始化
int ata_init(void);
int ata_init_ex(ata_init_mode_t mode);

// 同步 I/O
ata_result_t ata_read(int device, uint64_t lba, void* buffer, uint16_t sectors);
ata_result_t ata_write(int device, uint64_t lba, const void* buffer, uint16_t sectors);

// 设备信息
bool ata_device_exists(int device);
ata_result_t ata_get_info(int device, ata_device_info_t* info);
uint64_t ata_get_sector_count(int device);

// 异步 I/O
ata_result_t ata_read_async(int device, uint64_t lba, void* buffer,
                            uint16_t sectors, ata_read_callback_fn callback, void* context);
ata_result_t ata_write_async(int device, uint64_t lba, const void* buffer,
                             uint16_t sectors, ata_write_callback_fn callback, void* context);
bool ata_async_is_idle(int device);

// 辅助
const char* ata_error_string(ata_result_t result);
```

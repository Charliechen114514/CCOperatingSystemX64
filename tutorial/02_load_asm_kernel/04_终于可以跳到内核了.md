# 终于可以跳到内核了

## 前言：见证奇迹的时刻

如果你跟着前三篇做下来，现在应该是这样的状态：
- ✅ 有一个 20 字节的内核
- ✅ bootloader 能把它加载到 0x10000
- ✅ bootloader 已经切换到 64 位长模式

但问题是 —— 内核还没执行！

今天，我们终于要完成这最后一步：跳转到内核并看到那个期待已久的 'X'。

---

## 第一步：理解跳转方式

在 64 位模式下，我们有几种跳转方式：

### jmp vs call

| 指令 | 效果 | 返回 |
|------|------|------|
| `jmp address` | 无条件跳转 | 不返回 |
| `call address` | 调用子程序 | 可以返回 |

对于内核跳转，我们应该用 `call` 而不是 `jmp`，因为：
1. 内核可能返回（虽然大概率不会）
2. `call` 符合函数调用约定
3. 如果内核崩溃，我们至少知道返回到哪里

### 函数指针调用

在 64 位模式下，间接调用是这样的：

```nasm
mov rdi, 0x10000     ; 把地址存入 RDI
call rdi             ; 调用 RDI 指向的函数
```

为什么要用 RDI？这涉及到 System V AMD64 ABI 调用约定。

---

## 第二步：System V AMD64 ABI 简述

System V AMD64 ABI 是 Unix-like 系统（Linux、*BSD）上的 64 位调用约定。

### 参数传递

| 参数顺序 | 寄存器 |
|----------|--------|
| 第 1 个 | RDI |
| 第 2 个 | RSI |
| 第 3 个 | RDX |
| 第 4 个 | RCX |
| 第 5 个 | R8 |
| 第 6 个 | R9 |
| 更多 | 栈 |

### 返回值

- RAX 存放返回值

### 栈

- 必须保持 16 字节对齐

### 我们的跳转

```nasm
mov rdi, 0x10000     ; 内核地址（也是第 1 个参数）
call rdi             ; 调用内核
```

虽然我们的内核不使用参数，但把地址放在 RDI 是符合规范的。

---

## 第三步：在 boot2.asm 中添加跳转代码

在 `long_mode:` 标签的打印消息之后，添加：

```nasm
long_mode:
    mov ax, 0x20
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov rsp, 0x7E00

    ; 打印消息（VGA）
    mov rdi, 0xB8000 + 160 * 2
    mov rsi, msg_long_mode
    mov ah, 0x0F
.print_loop:
    lodsb
    test al, al
    jz .print_done
    stosw
    jmp .print_loop
.print_done:

    ; ===== 新增：跳转到内核 =====
    mov rdi, 0x10000     ; 内核地址
    call rdi             ; 调用内核

    ; 如果内核返回，打印错误
    mov rdi, 0xB8000 + 160 * 3
    mov rsi, msg_kernel_returned
    mov ah, 0x0F
.err_loop:
    lodsb
    test al, al
    jz .err_done
    stosw
    jmp .err_loop
.err_done:

.hang:
    hlt
    jmp .hang
```

### 添加消息

在数据区添加：

```nasm
msg_long_mode:
    db "[OK] Entered Long Mode!", 0x0D, 0x0A, 0

msg_kernel_returned:
    db "[WARN] Kernel returned!", 0x0D, 0x0A, 0
```

---

## 第四步：确认内核代码

我们的内核应该长这样（来自第一篇）：

```nasm
; CCOS 最小内核
section .text
    org 0x10000
    bits 64

kernel_start:
    ; 在 VGA 第 5 行第 0 列写一个 'X'
    mov rdi, 0xB8000 + 160 * 5
    mov rax, 0x1F58
    mov word [rdi], ax

    ; 停机
    cli
    hlt
    jmp kernel_start
```

### 重要检查

⚠️ **确认 `org 0x10000`**：内核必须告诉 NASM 它会被加载到哪里！

⚠️ **确认 `bits 64`**：内核是 64 位代码！

⚠️ **确认 VGA 位置**：我们用第 5 行（160 * 5），和 bootloader 的输出不冲突。

---

## 第五步：完整编译和测试

```bash
# 编译
$ nasm -f bin boot/boot.asm -o build/boot.bin
$ nasm -f bin boot/boot2.asm -o build/boot2.bin
$ nasm -f bin kernel/kernel.asm -o build/kernel.bin

# 检查大小
$ ls -lh build/*.bin
-rw-r--r-- 1 user user  512 Feb 17 00:05 build/boot.bin
-rw-r--r-- 1 user user  743 Feb 17 00:05 build/boot2.bin
-rw-r--r-- 1 user user   20 Feb 17 00:05 build/kernel.bin

# 合并
$ dd if=build/boot.bin of=build/boot.img bs=512 count=1
$ dd if=build/boot2.bin of=build/boot.img bs=512 seek=1 conv=notrunc
$ dd if=build/kernel.bin of=build/boot.img bs=512 seek=3 conv=notrunc

# 运行
$ qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic
```

### 预期输出

```
[1] Stage 1: Loading Stage 2...
[2] Stage 2: Running...
[LOAD] Loading kernel...
[OK] Entered Long Mode!
```

然后屏幕应该会在第 5 行显示一个白字蓝底的 `X`。

### 用 QEMU 图形模式查看

如果想看 VGA 输出，用图形模式：

```bash
$ qemu-system-x86_64 -drive format=raw,file=build/boot.img
```

你应该能看到：

```
                    [OK] Entered Long Mode!
X
```

（X 在第 5 行，白字蓝底）

## 第六步：验证内存

如果你想确认内核确实被执行了，可以用 QEMU monitor：

```bash
$ qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic -monitor stdio
```

启动后，按 Ctrl+A 然后 C 进入 monitor：

```
(qemu) xp /20hx 0xB8000
00000000000b8000: 0x1f5b 0x1f4f 0x1f4b 0x1f5d  [...]
```

然后在 0xB8140（第 5 行）应该能看到 0x1F58（'X'）。

```
(qemu) xp /hx 0xB8140
00000000000b8140: 0x1f58
```

## 第七步：调试技巧

如果看不到 'X'，哪里出了问题？

### VGA 调试法

在关键点写入不同的字符：

```nasm
; 在 long_mode 开始时
mov qword [0xB8000], 'A'    ; 证明到了 long_mode

; 在跳转前
mov qword [0xB8000 + 8], 'B' ; 证明准备跳转

; 跳转
mov rdi, 0x10000
call rdi
```

如果在内核中看到 'A' 但没看到 'B'，说明跳转前崩溃了。

### GDB 调试法

用 GDB 连接 QEMU：

```bash
# 终端 1
$ qemu-system-x86_64 -drive format=raw,file=build/boot.img -s -S

# 终端 2
$ gdb
(gdb) target remote :1234
(gdb) break *0x7E00     ; Stage 2 入口
(gdb) break *0x10000    ; 内核入口
(gdb) continue
```

## 第八步：完整启动流程回顾

让我们回顾整个启动流程：

```
1. BIOS 加载 MBR 到 0x7C00
   ↓
2. Stage 1 (0x7C00) 加载 Stage 2 到 0x7E00
   ↓
3. Stage 2 (0x7E00, 16-bit)
   - 打印消息
   - 加载内核到 0x10000
   - 设置页表
   - 加载 GDT
   ↓
4. 切换到保护模式 (32-bit)
   - 设置段寄存器
   - 启用 PAE
   - 加载 PML4
   - 启用长模式
   - 启用分页
   ↓
5. 切换到长模式 (64-bit)
   - 打印消息
   - 跳转到内核 (0x10000)
   ↓
6. 内核 (0x10000)
   - 写 'X' 到 VGA
   - 停机
```

---

## 踩坑预警

⚠️ **注意**：内核地址必须和 bootloader 一致

如果 bootloader 把内核加载到 0x10000，但内核代码里写 `org 0x20000`，跳转后会崩溃。

⚠️ **注意**：VGA 位置冲突

如果 bootloader 和内核都用 VGA 第 0 行，后面的输出会覆盖前面的。我们选择第 5 行来避免冲突。

⚠️ **注意**：内核必须在 64 位模式下跳转

如果你在保护模式（32 位）下跳转到 64 位内核，会立即崩溃。必须先进入长模式！

⚠️ **注意**：内核大小限制

我们的 bootloader 只读取 1 个扇区（512 字节）。如果你的内核超过 512 字节，会被截断。

# 从 16 位到 64 位的漫长旅途

## 前言：Intel 的历史包袱

如果你之前接触过 ARM 或 MIPS，可能会觉得："切换个模式而已，写个寄存器不就行了？"但在 x86 上，情况完全不同。Intel 保持了 40 年的向后兼容，导致我们从 16 位切换到 64 位需要经过一系列复杂步骤。

简单来说，我们需要这样走：实模式（16-bit）→ 保护模式（32-bit）→ 长模式（64-bit）。这还不算完，中间还要设置 GDT（全局描述符表）、设置页表（PML4 → PDPT → PD → PT）、启用 PAE（物理地址扩展）、启用分页。听起来很吓人？别担心，我们一起拆解每一步。

说实话，当年我第一次看到这个流程的时候也是一脸懵。ARM 的模式切换就是写个系统控制寄存器的事，x86 非要搞这么复杂。但理解了之后你会发现，每一步都有它的道理，这都是为了保持向后兼容而付出的代价。

---

## 先搞懂我们身在何处：x86 的三种模式

首先我们得理解三种模式的区别。实模式是 CPU 上电后的初始状态，地址空间只有 1 MB，使用段:偏移的寻址方式，完全兼容 1978 年的 8086，BIOS 中断可用。这就是我们 Stage 1 和 Stage 2 开始时所在的地方——你可能觉得它很古老，但它确实能工作。

保护模式是 Intel 在 80286 时代引入的，它把地址空间扩展到 4 GB，使用段选择子 + 偏移的寻址方式，支持内存保护和多任务。这个名字听起来像是为了安全，但实际上更多是为了提供更大的地址空间和更强大的内存管理能力。我们需要经过它作为跳板到长模式，没办法绕过去。

长模式是我们最终要到达的地方，地址空间理论上是 2^64 字节（虽然实际实现没这么大，目前 AMD64 实现了 48 位地址），使用平坦的 64 位地址，有完整的 64 位寄存器和指令集。我们的内核就运行在这里，也是我们折腾了这么久要到达的终点。

---

## GDT 这关绕不过去

GDT（Global Descriptor Table，全局描述符表）是进入保护模式必须设置的。在实模式下，内存访问是"自由的"——任何程序可以访问任何地址，这显然很危险。保护模式引入了"段描述符"的概念，每个段有基地址、限长、权限（Read/Write/Execute）、特权级（Ring 0-3）。GDT 就是存放这些段描述符的表。

我们的 GDT 有 5 个描述符。第一个是空描述符，这是硬件强制要求的，必须放一个全零的描述符在开头。第二个是 32 位代码段，第三个是 32 位数据段，第四个是 64 位代码段，第五个是 64 位数据段。这些描述符用 64 位整数表示，比如 `gdt_code = 0x00CF9A000000FFFF`。

让我拆解一下这个值。从低到高看，基地址部分是 0，限长部分是 0xFFFFF。访问权限字节是 0x9A，二进制是 10011010，表示这是一个代码段（Executable=1），可读（Readable=1），在 Ring 0 运行（DPL=00），并且是存在的（Present=1）。标志字节是 0xCF，其中 G 位（粒度）为 1 表示限长以 4KB 为单位，所以实际限长是 0xFFFFF × 4KB = 4GB。D/B 位为 1 表示 32 位代码段。简单说就是：32 位代码段，4GB 限长，可执行可读，Ring 0。

GDT 指针有两个字段：限长是 5 个描述符乘以 8 字节减 1 等于 39（0x27），基地址是 0x7E03。等等，为什么是 0x7E03 而不是 0x7E04？因为我们在 `start:` 后面有个 `jmp short main` 和 `nop`，GDT 实际上从 0x7E04 开始，但限长是"最大索引"而不是"大小"，所以是 表大小-1 = 40-1 = 39。这个细节很容易搞错，当年我就在这里卡了好久。

---

## 动手：切换到保护模式

现在我们来实际切换模式。首先是加载 GDT：

```nasm
    lgdt [gdt_ptr]          ; 加载 GDT
```

`lgdt` 指令加载 GDTR 寄存器，它指向我们的 GDT。这一步很直接，但接下来就有意思了。我们需要设置 CR0 寄存器的 PE 位：

```nasm
    mov eax, cr0            ; 读取 CR0
    or eax, 1               ; 设置 PE 位（bit 0）
    mov cr0, eax            ; 写回 CR0
```

CR0 的 bit 0 是 PE（Protection Enable）位，设置为 1 就进入保护模式。这一步很关键，但也很简单。复杂的是接下来——我们需要跳转到 32 位代码。

为什么要远跳转？因为跳转不仅改变了执行流（EIP/RIP），还改变了代码段寄存器（CS）。在保护模式下，CS 不再是一个简单的段基址，而是一个段选择子，它指向 GDT 中的某个描述符。所以我们需要用 `jmp far` 来同时设置 CS 和 EIP。

但这里有个坑——NASM 在 16 位模式下生成的 `jmp far 0x08:pm_entry` 会出错，所以我们需要手动编码：

```nasm
    ; 远跳转：手动编码
    db 0x66                 ; operand-size prefix（32 位偏移）
    db 0xEA                 ; jmp far 操作码
    dd pm_entry             ; 32 位偏移
    dw 0x08                 ; 段选择子（gdt_code 的索引）
```

`0x66` 是操作数前缀，告诉 CPU 这是一个 32 位跳转。`0xEA` 是 far jmp 的操作码。`0x08` 是第 2 个描述符的索引（每个描述符 8 字节，1 × 8 = 8）。`pm_entry` 是目标地址的 32 位偏移。这个跳转会加载 CS 为 `gdt_code` 选择子，并跳转到 `pm_entry`。

说实话，这种手动编码的方式看起来很原始，但在这种底层启动代码中，我们没法依赖汇编器的"聪明"，必须明确告诉 CPU 每一个字节是什么意思。

跳转后我们进入 32 位代码，需要设置数据段寄存器：

```nasm
bits 32

pm_entry:
    mov ax, 0x10            ; gdt_data 的索引
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov esp, 0x7E00
```

`0x10` 是第 3 个描述符的索引（2 × 8 = 16 = 0x10）。现在我们在保护模式了，下一步是设置页表。

---

## 页表：长模式的必经之路

长模式强制要求使用页表，这是没办法的事。x86_64 使用四级页表：PML4 → PDPT → PD → PT。这听起来很复杂，但对于我们的简单场景（只映射前 2MB 内存），可以简化很多。

我们的页表布局是这样的：PML4 在 0x9000，PDPT 在 0xA000，PD 在 0xB000。每个表 4KB，正好是一个页的大小。为什么选这些地址？因为它们在低内存区域，不会和 bootloader（0x7C00-0x7DFF）和内核（0x10000）冲突。

首先我们需要清空这三个页表。`rep stosd` 这个指令组合很有用：

```nasm
    ; 清空 PML4
    mov edi, 0x9000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd
```

`rep stosd` 会重复把 EAX 的值写入 ES:DI 指向的内存，ECX 次，每次 DI 自动加 4。这样我们快速把 4KB 的页表清零。然后我们用同样的方式清空 PDPT 和 PD。

接下来是设置页表项。我们只需要设置一个 PML4 项，指向 PDPT：

```nasm
    ; PML4[0] -> PDPT
    mov dword [0x9000], 0x0000A003
```

`0x0000A003` 的意思是什么呢？低 12 位是标志位：bit 0 是 Present 位（1=存在），bit 1 是 Writable 位（1=可写），bit 2 是 User/Supervisor 位（0= supervisor 级别）。高 20 位是页表地址的 bits 39-12，也就是 0xA000 >> 12 = 0xA。所以组合起来就是：地址 0xA000，存在且可写。

我们还设置了 PML4[511] 指向同一个 PDPT，这样高地址映射也能工作：

```nasm
    ; PML4[511] -> PDPT（映射高地址）
    mov dword [0x9FF8], 0x0000A003
```

511 × 8 = 4088 = 0xFF8，这是 PML4 的最后一项。这样设置后，地址 0xFFFF800000000000 也会映射到同样的物理内存，这是内核常用的"高地址映射"技巧。

然后是 PDPT 指向 PD：

```nasm
    ; PDPT[0] -> PD
    mov dword [0xA000], 0x0000B003
```

最后是 PD[0] 设置为 2MB 页：

```nasm
    ; PD[0] -> 2MB 页（0x000000 - 0x1FFFFF）
    mov dword [0xB000], 0x00000083    ; 位 0 = present, 位 7 = 2MB 页
    mov dword [0xB004], 0x00000000
```

注意这里我们写入了两个 dword，因为 PD 项在 PAE 模式下是 64 位的。`0x00000083` 的低 32 位包含：地址（0），Present 位（bit 0=1），Writable 位（bit 1=1），以及 Page Size 位（bit 7=1，表示这是 2MB 页而不是 4KB 页表的指针）。高 32 位是 0，因为我们只使用低 32 位物理地址。

---

## 启用 PAE：打开 36 位地址之门

PAE（Physical Address Extension）允许访问超过 4GB 的物理内存，是长模式的前置要求。设置很简单：

```nasm
    mov eax, cr4            ; 读取 CR4
    or eax, 1 << 5          ; 设置 PAE 位（bit 5）
    mov cr4, eax            ; 写回 CR4
```

CR4 的 bit 5 是 PAE 位，设置为 1 就启用了 PAE。这样我们就可以使用 36 位物理地址，最多支持 64GB 内存。说实话，现在的电脑都有 64GB 了，这个限制看起来有点小，但在 1995 年 Intel 设计 PAE 时，64GB 已经是天文数字了。

---

## 加载 PML4：告诉 CPU 页表在哪里

CR3 寄存器存储页表的根地址：

```nasm
    mov eax, 0x9000         ; PML4 的地址
    mov cr3, eax            ; 加载到 CR3
```

现在 CPU 知道页表的根在 0x9000 了。每次访问内存时，CPU 会用 CR3 找到 PML4，然后一步步查表找到最终的物理地址。这个过程是硬件完成的，速度很快。

---

## 启用长模式：最后的门槛

长模式是通过 EFER（Extended Feature Enable Register）MSR 控制的。MSR 是 Model-Specific Register，是 CPU 特有的寄存器，不能用普通的 `mov` 指令访问，必须用 `rdmsr` 和 `wrmsr`：

```nasm
    mov ecx, 0xC0000080     ; EFER MSR 的编号
    rdmsr                   ; 读取 MSR 到 EDX:EAX
    or eax, 1 << 8          ; 设置 LME 位（bit 8）
    wrmsr                   ; 写回 MSR
```

EFER.LME（Long Mode Enable）位启用长模式。但仅仅设置这个位还不够，我们还不能进入长模式。我第一次做的时候就在这里卡住了——设置了 LME 但什么都没发生，CPU 还是在 32 位模式运行。

---

## 启用分页：真正进入长模式

分页是最后一步，也是最关键的一步：

```nasm
    mov eax, cr0            ; 读取 CR0
    or eax, 1 << 31         ; 设置 PG 位（bit 31）
    mov cr0, eax            ; 写回 CR0
```

当同时满足以下条件时，处理器进入长模式：EFER.LME = 1，CR4.PAE = 1，CR0.PG = 1。这三个条件我们现在都满足了！从这一刻起，CPU 就在 64 位长模式下运行了。

说实话，这个设计有点"魔法"的感觉——你不是直接"切换"到长模式，而是设置一系列条件，当条件都满足时，CPU 自动进入长模式。这跟 ARM 的"写一个寄存器就切换"的方式完全不同。

---

## 跳转到 64 位代码：最后一步

现在我们需要跳转到 64 位代码。这次我们不需要手动编码了，因为我们已经在 32 位模式下：

```nasm
    ; 远跳转到 64 位代码
    jmp 0x18:long_mode      ; 0x18 = gdt_code64 的索引

bits 64

long_mode:
    mov ax, 0x20            ; gdt_data64 的索引
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov rsp, 0x7E00
```

`0x18` 是第 4 个描述符的索引（3 × 8 = 24 = 0x18）。现在我们在 64 位长模式了！我们可以打印消息证明一下：

```nasm
    ; 打印消息（VGA）
    mov rdi, 0xB8000 + 160 * 2
    mov rsi, msg_long_mode
    mov ah, 0x0F
.print_loop:
    lodsb
    test al, al
    jz .print_done
    stosw
    jmp .print_loop
.print_done:
```

`lodsb` 从 RSI 读取一个字节到 AL，RSI 自动加 1。`stosw` 把 AX 写入 [RDI]，RDI 自动加 2。这样我们逐个字符把消息写到 VGA 显存。`0x0F` 是白字蓝底的颜色值。

---

## 完整测试：见证奇迹

现在我们编译并测试：

```bash
$ nasm -f bin boot/boot.asm -o build/boot.bin
$ nasm -f bin boot/boot2.asm -o build/boot2.bin
$ nasm -f bin kernel/kernel.asm -o build/kernel.bin

$ dd if=build/boot.bin of=build/boot.img bs=512 count=1
$ dd if=build/boot2.bin of=build/boot.img bs=512 seek=1 conv=notrunc
$ dd if=build/kernel.bin of=build/boot.img bs=512 seek=3 conv=notrunc

$ qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic
```

你应该能看到：

```
[1] Stage 1: Loading Stage 2...
[2] Stage 2: Running...
[LOAD] Loading kernel...
[OK] Entered Long Mode!
```

如果你看到这个，恭喜！你已经成功从 16 位实模式切换到 64 位长模式了。这是一段漫长的旅程，但我们做到了。

说实话，有个坑千万别踩——GDT 基址必须正确。如果你的 GDT 基址设错了，lgdt 会加载错误的地址，导致跳转时崩溃。我第一次做的时候把 `0x7E03` 写成了 `0x7E00`，结果 CPU 读到了一堆乱码，直接 triple fault。另外不要忘记 `bits 32` 和 `bits 64` 指令，NASM 会根据这个生成正确的指令编码。远跳转的段选择子也要算对，`0x08` 是第 2 个描述符，`0x18` 是第 4 个描述符。还有页表必须清零，如果在设置页表前不清零，可能会有垃圾数据导致崩溃。

到这里，我们理解了 x86 的三种模式，理解了 GDT 和段描述符，理解了页表的四级结构，成功从实模式切换到保护模式，也成功从保护模式切换到长模式。下一步，我们终于可以跳转到内核了！

# 从 16 位到 64 位的漫长旅途

## 前言：Intel 的历史包袱

如果你之前接触过 ARM 或 MIPS，可能会觉得："切换个模式而已，写个寄存器不就行了？"

但在 x86 上，情况完全不同。Intel 保持了 40 年的向后兼容，导致我们从 16 位切换到 64 位需要经过一系列复杂步骤：

```
实模式 (16-bit) → 保护模式 (32-bit) → 长模式 (64-bit)
```

这还不算完，中间还要：
- 设置 GDT（全局描述符表）
- 设置页表（PML4 → PDPT → PD → PT）
- 启用 PAE（物理地址扩展）
- 启用分页

听起来很吓人？别担心，我们一起拆解每一步。

---

## 第一步：理解 x86 处理器模式

### 实模式（Real Mode）

- **地址空间**：1 MB（0x00000 - 0xFFFFF）
- **寻址方式**：段:偏移（segment:offset）
- **特点**：兼容 8086，BIOS 中断可用
- **我们在这里**：Stage 1 和 Stage 2 开始时

### 保护模式（Protected Mode）

- **地址空间**：4 GB（32 位地址）
- **寻址方式**：段选择子 + 偏移
- **特点**：内存保护、多任务支持
- **我们需要经过这里**：作为跳板到长模式

### 长模式（Long Mode）

- **地址空间**：2^64 字节（理论值）
- **寻址方式**：平坦 64 位地址
- **特点**：64 位寄存器和指令
- **我们的终点**：内核运行的地方

---

## 第二步：理解 GDT

GDT（Global Descriptor Table，全局描述符表）是进入保护模式必须设置的。

### 为什么需要 GDT？

在实模式下，内存访问是"自由的" —— 任何程序可以访问任何地址。这显然很危险。

保护模式引入了"段描述符"的概念，每个段有：
- 基地址（Base Address）
- 限长（Limit）
- 权限（Read/Write/Execute）
- 特权级（Ring 0-3）

GDT 就是存放这些段描述符的表。

### 我们的 GDT

```nasm
gdt_start:
    dq 0x0000000000000000   ; 空描述符（必须）
gdt_code:
    dq 0x00CF9A000000FFFF   ; 32 位代码段
gdt_data:
    dq 0x00CF92000000FFFF   ; 32 位数据段
gdt_code64:
    dq 0x00AF9A000000FFFF   ; 64 位代码段
gdt_data64:
    dq 0x00CF92000000FFFF   ; 64 位数据段
gdt_end:
```

### 描述符结构拆解

以 `gdt_code = 0x00CF9A000000FFFF` 为例：

```
Base  [31:24] = 0x00
G     = 0
D/B   = 1 (32 位)
L     = 0 (不是 64 位)
AVL   = 0
Limit [19:16] = 0xF
P     = 1 (存在)
DPL   = 00 (Ring 0)
S     = 1 (代码/数据段)
Type  = 1010 (代码段，可读，可执行)
Base  [23:16] = 0x00
Base  [15:0]  = 0x0000
Limit [15:0]  = 0xFFFF
```

简单说：
- `0x00CF` = 32 位代码段，4GB 限长
- `0x9A` = 可执行、可读、Ring 0
- `0x00...FFFF` = 基地址 0，限长 0xFFFFF

### GDT 指针

```nasm
gdt_ptr:
    dw 5 * 8 - 1            ; 限长 = 5 个描述符 * 8 字节 - 1
    dd 0x00007E03           ; 基地址 = 0x7E03（GDT 从 0x7E04 开始）
```

为什么是 0x7E03 而不是 0x7E04？因为 GDT 的基址字段指向的是整个表的开始，而我们在 `start:` 后面有个 `jmp short main` 和 `nop`，GDT 实际上从 0x7E04 开始。

---

## 第三步：切换到保护模式

现在我们来实际切换模式。

### 加载 GDT

```nasm
    lgdt [gdt_ptr]          ; 加载 GDT
```

`lgdt` 指令加载 GDTR 寄存器，它指向我们的 GDT。

### 设置 PE 位

```nasm
    mov eax, cr0            ; 读取 CR0
    or eax, 1               ; 设置 PE 位（bit 0）
    mov cr0, eax            ; 写回 CR0
```

CR0 的 bit 0 是 PE（Protection Enable）位，设置为 1 就进入保护模式。

### 远跳转到 32 位代码

```nasm
    ; 远跳转：手动编码
    db 0x66                 ; operand-size prefix（32 位偏移）
    db 0xEA                 ; jmp far 操作码
    dd pm_entry             ; 32 位偏移
    dw 0x08                 ; 段选择子（gdt_code 的索引）
```

为什么要手动编码？因为 NASM 在 16 位模式下生成 `jmp far 0x08:pm_entry` 会出错。

- `0x08` = 第 2 个描述符的索引（每个描述符 8 字节）
- `pm_entry` = 目标地址（32 位）

### 进入 32 位代码

```nasm
bits 32

pm_entry:
    ; 设置数据段寄存器
    mov ax, 0x10            ; gdt_data 的索引
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov esp, 0x7E00

    ; 现在我们在保护模式了！
    ; 下一步：设置页表
```

## 第四步：设置页表

长模式强制要求使用页表，这是没办法的事。

### 页表层次结构

x86_64 使用四级页表：

```
                    PML4
              ┌─────┴─────┐
            PDPT0       PDPT1
         ┌───┴───┐     ...
       PD0     PD1
     ┌──┴──┐  ...
    PT0  PT1
   ┌─┴─┐ ...
 P0  P1
```

但对于我们的简单场景（只映射前 2MB 内存），可以简化很多。

### 我们的页表布局

```
地址        内容          大小
──────────────────────────────────
0x9000      PML4         4KB
0xA000      PDPT         4KB
0xB000      PD           4KB
```

### 设置代码

```nasm
setup_page_tables:
    pusha

    ; 清空 PML4
    mov edi, 0x9000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    ; 清空 PDPT
    mov edi, 0xA000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    ; 清空 PD
    mov edi, 0xB000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    ; PML4[0] -> PDPT
    mov dword [0x9000], 0x0000A003
    ; PML4[511] -> PDPT（映射高地址）
    mov dword [0x9FF8], 0x0000A003

    ; PDPT[0] -> PD
    mov dword [0xA000], 0x0000B003

    ; PD[0] -> 2MB 页（0x000000 - 0x1FFFFF）
    mov dword [0xB000], 0x00000083    ; 位 0 = present, 位 7 = 2MB 页
    mov dword [0xB004], 0x00000000

    ; PD[511] -> 2MB 页（0xFFE00000 - 0xFFFFFFFF）
    mov dword [0xBFF0], 0x00000083
    mov dword [0xBFF4], 0x00000000

    popa
    ret
```

### 描述符解释

`0x0000A003`:
- `0xA000` = PDPT 的物理地址
- `0x003` = Present + Writable

`0x00000083`:
- `0x80` = 2MB 页标志
- `0x03` = Present + Writable

---

## 第五步：启用 PAE

PAE（Physical Address Extension）允许访问超过 4GB 的物理内存，是长模式的前置要求。

```nasm
    mov eax, cr4            ; 读取 CR4
    or eax, 1 << 5          ; 设置 PAE 位（bit 5）
    mov cr4, eax            ; 写回 CR4
```

---

## 第六步：加载 PML4

```nasm
    mov eax, 0x9000         ; PML4 的地址
    mov cr3, eax            ; 加载到 CR3
```

CR3 寄存器存储页表的根地址。

---

## 第七步：启用长模式

长模式是通过 EFER（Extended Feature Enable Register）MSR 控制的。

### 设置 LME 位

```nasm
    mov ecx, 0xC0000080     ; EFER MSR 的编号
    rdmsr                   ; 读取 MSR 到 EDX:EAX
    or eax, 1 << 8          ; 设置 LME 位（bit 8）
    wrmsr                   ; 写回 MSR
```

EFER.LME（Long Mode Enable）位启用长模式。

---

## 第八步：启用分页

```nasm
    mov eax, cr0            ; 读取 CR0
    or eax, 1 << 31         ; 设置 PG 位（bit 31）
    mov cr0, eax            ; 写回 CR0
```

当同时满足以下条件时，处理器进入长模式：
1. EFER.LME = 1
2. CR4.PAE = 1
3. CR0.PG = 1

---

## 第九步：跳转到 64 位代码

```nasm
    ; 远跳转到 64 位代码
    jmp 0x18:long_mode      ; 0x18 = gdt_code64 的索引

bits 64

long_mode:
    ; 设置数据段寄存器
    mov ax, 0x20            ; gdt_data64 的索引
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov rsp, 0x7E00

    ; 现在我们在 64 位长模式了！
    ; 可以调用内核了
```

## 第十步：完整的 boot2.asm

把所有代码整合起来：

```nasm
; ==============================================================================
; CCOS Bootloader - Stage 2
; ==============================================================================

section .text
    org 0x7E00
    bits 16

start:
    jmp short main
    nop

; ============================================================================
; GDT
; ============================================================================
gdt_start:
    dq 0x0000000000000000   ; 空描述符
gdt_code:
    dq 0x00CF9A000000FFFF   ; 32 位代码段
gdt_data:
    dq 0x00CF92000000FFFF   ; 32 位数据段
gdt_code64:
    dq 0x00AF9A000000FFFF   ; 64 位代码段
gdt_data64:
    dq 0x00CF92000000FFFF   ; 64 位数据段
gdt_end:

gdt_ptr:
    dw 5 * 8 - 1
    dd 0x00007E03

; ============================================================================
; 16 位代码
; ============================================================================
main:
    cli
    xor ax, ax
    mov ds, ax
    mov es, ax
    mov ss, ax
    mov sp, 0x7E00

    ; 打印消息
    mov si, msg_stage2
    call print_string

    ; 加载内核
    call load_kernel
    jc load_error

    ; 设置页表
    call setup_page_tables

    ; 加载 GDT
    lgdt [gdt_ptr]

    ; 启用保护模式
    mov eax, cr0
    or eax, 1
    mov cr0, eax

    ; 跳转到保护模式
    db 0x66
    db 0xEA
    dd pm_entry
    dw 0x08

    ; 永远不会到这里
.hang:
    hlt
    jmp .hang

load_error:
    mov si, msg_error
    call print_string
    jmp .hang

print_string:
    pusha
.loop:
    lodsb
    test al, al
    jz .done
    mov ah, 0x0E
    int 0x10
    jmp .loop
.done:
    popa
    ret

load_kernel:
    pusha
    mov si, msg_loading
    call print_string

    mov ax, 0x1000
    mov es, ax
    xor bx, bx

    mov ah, 0x02
    mov al, 0x01
    mov ch, 0x00
    mov cl, 0x04
    mov dh, 0x00
    mov dl, 0x80
    int 0x13

    jc .error
    cmp al, 0x01
    jne .error

    popa
    clc
    ret

.error:
    popa
    stc
    ret

setup_page_tables:
    pusha

    mov edi, 0x9000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    mov edi, 0xA000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    mov edi, 0xB000
    mov ecx, 4096 / 4
    xor eax, eax
    rep stosd

    mov dword [0x9000], 0x0000A003
    mov dword [0x9FF8], 0x0000A003
    mov dword [0xA000], 0x0000B003
    mov dword [0xB000], 0x00000083
    mov dword [0xB004], 0x00000000

    popa
    ret

; ============================================================================
; 32 位代码
; ============================================================================
bits 32

pm_entry:
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov esp, 0x7E00

    ; 设置页表已经完成，现在启用 PAE
    mov eax, cr4
    or eax, 1 << 5
    mov cr4, eax

    ; 加载 PML4
    mov eax, 0x9000
    mov cr3, eax

    ; 启用长模式
    mov ecx, 0xC0000080
    rdmsr
    or eax, 1 << 8
    wrmsr

    ; 启用分页
    mov eax, cr0
    or eax, 1 << 31
    mov cr0, eax

    ; 跳转到 64 位
    jmp 0x18:long_mode

.hang:
    hlt
    jmp .hang

; ============================================================================
; 64 位代码
; ============================================================================
bits 64

long_mode:
    mov ax, 0x20
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax
    mov rsp, 0x7E00

    ; 打印消息（VGA）
    mov rdi, 0xB8000 + 160 * 2
    mov rsi, msg_long_mode
    mov ah, 0x0F
.print_loop:
    lodsb
    test al, al
    jz .print_done
    stosw
    jmp .print_loop
.print_done:

    ; （下一篇）跳转到内核
.hang:
    hlt
    jmp .hang

; ============================================================================
; 数据
; ============================================================================
msg_stage2:
    db "[2] Stage 2: Running...", 0x0D, 0x0A, 0

msg_loading:
    db "[LOAD] Loading kernel...", 0x0D, 0x0A, 0

msg_error:
    db "[ERR] Failed to load kernel", 0x0D, 0x0A, 0

msg_long_mode:
    db "[OK] Entered Long Mode!", 0x0D, 0x0A, 0
```

## 第十一步：测试

```bash
# 编译
$ nasm -f bin boot/boot.asm -o build/boot.bin
$ nasm -f bin boot/boot2.asm -o build/boot2.bin
$ nasm -f bin kernel/kernel.asm -o build/kernel.bin

# 合并
$ dd if=build/boot.bin of=build/boot.img bs=512 count=1
$ dd if=build/boot2.bin of=build/boot.img bs=512 seek=1 conv=notrunc
$ dd if=build/kernel.bin of=build/boot.img bs=512 seek=3 conv=notrunc

# 运行
$ qemu-system-x86_64 -drive format=raw,file=build/boot.img -nographic
```

你应该能看到：

```
[1] Stage 1: Loading Stage 2...
[2] Stage 2: Running...
[LOAD] Loading kernel...
[OK] Entered Long Mode!
```

## 踩坑预警

⚠️ **注意**：GDT 基址必须正确

如果你的 GDT 基址设错了，lgdt 会加载错误的地址，导致跳转时崩溃。确认你的 GDT 实际地址！

⚠️ **注意**：`bits 32` 和 `bits 64` 指令

不要忘记切换这些！NASM 会根据这个生成正确的指令编码。

⚠️ **注意**：远跳转的段选择子

- `0x08` = 第 2 个描述符（gdt_code）的索引
- `0x18` = 第 4 个描述符（gdt_code64）的索引

计算方式：`索引 = 描述符位置 / 8`

⚠️ **注意**：页表必须清零

如果在设置页表前不清零，可能会有垃圾数据导致崩溃。

# 从零实现字符串操作函数 —— strlen、strnlen、strcpy、strncpy

好了，废话不多说，让我们开始写代码。今天我们要实现的是字符串操作中最基础的四个函数：`strlen` 计算字符串长度、`strnlen` 有长度限制的字符串长度计算、`strcpy` 字符串复制、`strncpy` 有长度限制的字符串复制。这些函数虽然看起来简单，但它们是所有字符串操作的基础，而且里面有一些细节值得仔细讨论。

## 第一步：创建目录和头文件

首先，我们需要一个地方来放字符串函数。按照项目的组织结构，我们把它们放在 `kernel/base/` 目录下。这个目录专门用来存放那些基础的工具函数，不依赖其他内核模块。

创建目录和文件很简单，用 `mkdir -p kernel/base` 然后 `touch` 创建头文件和源文件就行了。重点是头文件的内容，它定义了我们整个字符串库的接口。

头文件里我们用了 `#pragma once` 而不是传统的 include guard。这两种方式功能相同，但 `#pragma once` 更简洁。不过要注意，不是所有编译器都支持，好在 GCC 和 Clang 都支持，我们这两个就够了。

先看看函数声明部分。每个函数都有详细的文档注释，说明它的用途、参数和返回值。这不是为了凑字数，而是当你几个月后再看代码时，会感谢当初写下这些注释的自己。

```c
/* 在 kernel/base/string.h 中 */

#pragma once

#include "defines/types.h"

/* 基础字符串操作函数声明 */
size_t strlen(const char* s);
size_t strnlen(const char* s, size_t maxlen);
char* strcpy(char* dest, const char* src);
char* strncpy(char* dest, const char* src, size_t n);
```

这些声明看起来很简单，但有几个细节需要注意。首先，所有字符串参数都是 `const char*` 或 `char*`，这里的 `const` 很重要 —— 它告诉编译器和调用者这个字符串会不会被修改。比如 `strlen` 只需要读取字符串，所以参数是 `const char*`，而 `strcpy` 需要修改目标缓冲区，所以第一个参数是 `char*`。

## 第二步：实现 strlen

`strlen` 是最简单的字符串函数 —— 它就是数数，数到第一个 `'\0'` 为止。但就是这个简单的函数，也有几种不同的写法。

最直观的写法是用索引：

```c
size_t strlen(const char* s) {
    size_t len = 0;
    while (s[len] != '\0') {
        len++;
    }
    return len;
}
```

这个版本容易理解，但我们可以用指针运算来优化一下：

```c
size_t strlen(const char* s) {
    const char* p = s;
    while (*p != '\0') {
        p++;
    }
    return p - s;
}
```

这个版本用指针运算代替了索引，可能稍微快一点，因为避免了索引计算。不过现代编译器通常会把这两种形式优化成相同的汇编代码，所以选择哪种更多是风格问题。

在我们的实际代码中，还加了一个调试断言：

```c
size_t strlen(const char* s) {
    CCOS_DEBUG_ASSERT(s);  // 确保指针不是 NULL

    const char* p = s;
    while (*p) {
        p++;
    }
    return (size_t)(p - s);
}
```

这个断言只在 Debug 模式启用，用来捕获明显的错误。有人说应该用 `CCOS_ASSERT` 让它始终启用，但我觉得对于这种"几乎不可能出错"的情况，调试断言就够了。如果有人传了 NULL 指针给 `strlen`，那代码本身就有问题了。

## 第三步：实现 strnlen

`strnlen` 是 `strlen` 的安全版本 —— 它不会读取超过 `maxlen` 个字符。这个函数在处理不可信的输入时特别有用，因为你不能保证输入字符串一定是正确格式。

```c
size_t strnlen(const char* s, size_t maxlen) {
    CCOS_DEBUG_ASSERT(s);

    const char* index_p = s;
    while (*index_p && maxlen > 0) {
        index_p++;
        maxlen--;
    }
    return (size_t)(index_p - s);
}
```

想象一下这个场景：你从网络或者文件读取了一些数据，想要计算它的长度。如果数据不是以 `'\0'` 结尾，用 `strlen` 就会一直读下去，可能访问到不属于你的内存。而用 `strnlen`，你可以指定最大长度，避免这个问题。

## 第四步：实现 strcpy

`strcpy` 把一个字符串复制到另一个位置。这个函数的实现有一个经典的技巧，值得我们仔细看看。

```c
char* strcpy(char* dest, const char* src) {
    CCOS_DEBUG_ASSERT(dest && src);

    char* d = dest;
    while ((*d++ = *src++) != '\0') {
        /* Copy until null terminator */
    }
    return dest;
}
```

这个实现的精华在于 `while ((*d++ = *src++) != '\0')` 这一行。它做了四件事：把 `*src` 复制到 `*d`，递增 `dest` 指针，递增 `src` 指针，检查复制的字符是否是 `'\0'`。所有这些都在一个表达式里完成，非常简洁。

返回原始目标指针也是 C 标准库的惯例，方便链式调用。虽然这种用法不是很常见，但保持与标准库的兼容性是好事。

不过要注意，`strcpy` 是一个危险的函数，因为它不检查目标缓冲区的大小。如果你复制一个很长的字符串到一个很小的缓冲区，就会发生缓冲区溢出。这个问题在后续阶段我们可能会实现更安全的函数来解决，但现在先记住这一点。

## 第五步：实现 strncpy

`strncpy` 是 `strcpy` 的带长度限制版本，但它的行为有点特殊。

```c
char* strncpy(char* dest, const char* src, size_t n) {
    CCOS_DEBUG_ASSERT(dest && src);

    char* d = dest;
    while ((*d++ = *src++) != '\0' && n > 0) {
        n--;
    }
    return dest;
}
```

这里的实现和标准库有一点不同。标准库的 `strncpy` 会在源字符串短于 `n` 时用 `'\0'` 填充剩余空间，但我们的实现不会这样做。这是一个有意的选择，因为填充操作通常不是必需的，而且会影响性能。

更重要的是要记住，如果源字符串长度大于等于 `n`，结果**不会**以 `'\0'` 结尾。这会导致后续的字符串操作出错。正确用法是手动添加结尾：

```c
char buf[5];
strncpy(buf, "Hello, World!", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';  // 手动添加结尾
```

这也是为什么很多人推荐使用 `strlcpy`（可惜它不是标准 C 函数）。如果我们在实际使用中遇到这个问题，可以考虑实现一个。

## 验证

现在我们想验证这些函数是否正确工作。但在内核环境里调试不太方便，所以我们先在主机环境测试。创建一个简单的测试程序，包含我们的函数实现，然后编译运行。

```c
/* 在项目根目录创建 test_strlen.c */

#include <stdio.h>
#include <stddef.h>

// 我们的函数实现
size_t strlen(const char* s) {
    const char* p = s;
    while (*p) p++;
    return p - s;
}

// ... 其他函数 ...

int main(void) {
    printf("Testing strlen...\n");
    printf("strlen(\"\") = %zu (expected: 0)\n", strlen(""));
    printf("strlen(\"hello\") = %zu (expected: 5)\n", strlen("hello"));

    printf("\nTesting strcpy...\n");
    char buf1[20];
    strcpy(buf1, "test");
    printf("strcpy result: \"%s\"\n", buf1);

    return 0;
}
```

编译运行：`gcc -o test_strlen test_strlen.c && ./test_strlen`。如果所有测试都通过了，恭喜你，基础的字符串操作函数已经完成了。

说实话，看到这些简单的测试全部通过，心里还是挺有成就感的。这些函数虽然基础，但它们是以后所有字符串操作的基石。有了这些，我们就可以继续实现更复杂的函数了。

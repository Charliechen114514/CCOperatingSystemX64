# 为什么需要自实现字符串库 —— 手把手建立内核基础设施

说实话，写内核的时候最让人崩溃的不是那些复杂的内存管理或者中断处理，而是那些最基础的东西。你想打印个错误信息，结果连字符串拼接都要自己实现；你想验证个参数，结果连个断言宏都没有；你想调试一下，只能靠 VGA 上那点可怜的输出，简直就是盲人摸象。

还记得之前写代码的时候，每次想用个 `strlen` 或者 `strcmp` 都要犹豫半天 —— 我们这可是内核环境，没有标准库可以用啊。这种感觉真的很痛苦，就像你想做饭但是连把刀都没有，只能用手掰。

## 现在我们有什么

在 stage 07 阶段结束时，我们已经有了 VGA 文本驱动、串口输出、GDB 调试支持和基础类型定义。看起来工具不少，但真要用起来的时候才发现，这些只是"基础设施"，真正能帮我们快速开发的"工具库"还是一片空白。

你想做点字符串操作？没门儿。`#include <string.h>` 是个美好的幻想，我们这是 freestanding 环境，没有标准库。你想验证参数？自己写 if 吧，然后呢？怎么报告错误？VGA 上打印？太麻烦了，而且打印了之后呢？系统该怎么处理？

每次想用点字符串功能都得自己从头实现，或者从之前的代码里复制粘贴。这不仅浪费时间，还容易出错 —— 你复制粘贴的代码真的是正确的吗？上次测试过吗？边界情况处理了吗？这些问题每次都要重新思考一遍，真的很累。

## 什么是 Freestanding 环境

你可能听说过 hosted 和 freestanding 这两个词，听起来挺学术的，但其实道理很简单。Hosted 环境就像你住酒店，什么东西都有人给你准备好 —— 有完整的标准库支持，像你平时写的用户态程序那样。而 freestanding 环境就像你自己建房，只有最基础的材料，其他什么都要自己来。

内核开发就是典型的 freestanding 环境。我们不能用 `<string.h>` 的字符串函数，不能用 `<stdio.h>` 的输入输出，不能用 `<assert.h>` 的断言。我们能用的只有 `<stddef.h>` 的几个类型定义和 `<stdint.h>` 的固定宽度整数，剩下的都要自己动手。

这听起来挺惨的，但换个角度想，这也是内核开发有趣的地方。你可以完全控制每个函数的实现，知道它们在做什么，不会有任何隐藏的副作用。而且，自己实现一遍这些基础函数，你会对它们的工作原理有更深的理解 —— 这在调试优化的时候特别有用。

## 我们要达成什么

所以，这一阶段我们要干两件事：给 CCOS 一个完整的字符串工具库，以及建立断言系统让 Bug 无处遁形。

字符串工具库方面，我们想要实现一个与标准 C 库兼容的字符串工具集。这里说的是"兼容"，不是"照搬"。我们会实现那些最常用的函数：长度计算、字符串复制、大小写敏感和不敏感的比较、各种搜索功能（查找字符、子串、字符集匹配）、以及字符串分割。

这些函数看起来简单，但它们是所有字符串操作的基础。你想想，解析命令行参数、处理配置文件、匹配设备名、格式化输出，哪一样离得开字符串操作？没有这些函数，内核开发就像戴着镣铐跳舞。

断言系统方面，我们想要一个能报告错误的断言机制。这里有两种断言：关键检查和调试辅助。关键检查始终启用，用于空指针检查、数组边界检查、状态不变式验证这类绝对不能出问题的地方。调试辅助则只在 Debug 模式启用，用于函数参数验证、内部状态检查这类在开发阶段有帮助但在发布版本可能影响性能的检查。

当断言失败时，我们希望系统能做几件事：在 VGA 上显示白字红底的错误信息，在 Debug 模式触发 `int3` 断点通知 GDB，然后停止系统运行。这样我们就能在问题发生时立刻知道"哪里出了问题"，而不是等系统莫名其妙崩溃后再去排查。

## 技术路线

我们分几个阶段来实现这些目标。首先是基础字符串函数，实现最常用的长度计算和字符串复制功能。这是所有字符串操作的基础，我们会一步一步来，确保每个函数都理解透彻。

然后是字符串比较功能，包括基础比较和忽略大小写的比较。这里我们会实现 `tolower` 函数，用一种巧妙的方式处理大小写转换。

接着是字符串搜索功能，我们会实现查找字符、查找子串、字符集匹配等各种函数。这些函数在处理文本时非常有用，比如查找配置项、解析命令等。

再然后是字符串分割功能，我们会实现 `strtok` 和 `strtok_r`。这个函数在解析命令行参数、配置文件等场景非常有用，但也有一些陷阱需要注意，我们到时候会详细讨论。

之后是断言系统，我们会实现断言宏和 VGA 错误显示后端。这里有个有趣的问题：断言系统需要 VGA 驱动，但 VGA 驱动可能也想使用断言，这会产生循环依赖。我们有个巧妙的解决方案，到时候细说。

最后是测试框架。在内核环境里调试不太方便，所以我们先在主机环境测试。这会让开发效率提升很多 —— 几秒钟就能验证一个函数，而不是每次都要重新编译启动内核。

## 环境确认

在开始之前，我们先确认一下环境。你应该已经完成了 stage 07 的工作，拥有 VGA 驱动、串口驱动、类型定义和基础构建系统。检查一下当前代码能正常构建，VGA 上有启动信息，串口也有日志输出。如果以上都 OK，那我们就可以开始了。

说实话，这一阶段的内容虽然基础，但真的很重要。等你有了这些工具，以后的开发会顺畅很多。就像做饭一样，有了好的刀具和砧板，切菜就会变成一种享受而不是折磨。

准备好了吗？让我们开始吧。

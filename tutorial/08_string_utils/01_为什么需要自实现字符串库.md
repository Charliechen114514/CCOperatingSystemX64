# 为什么需要自实现字符串库 —— 字符串工具与断言系统

说实话，之前写代码的时候每次想用个 `strlen` 或者 `strcmp` 都要犹豫半天 —— 我们这可是内核环境，没有标准库可以用啊。

这种感觉真的很痛苦。你想打印个错误信息，结果连字符串拼接都要自己实现；你想验证个参数，结果连个断言宏都没有。每次调试都得靠 VGA 上那点可怜的输出，真的是盲人摸象。

所以，这一阶段我们要干两件事：

1. **给 CCOS 一个完整的字符串工具库** —— 像标准库那样好用的字符串函数
2. **建立断言系统** —— 让 Bug 无处遁形

每次想用点字符串功能都得自己从头实现，或者从之前的代码里复制粘贴。这不仅浪费时间，还容易出错。

## 什么是 Freestanding 环境？

你可能听说过 **hosted** 和 **freestanding** 这两个词。简单来说：

- **Hosted 环境**：有完整的标准库支持，像你平时写的用户态程序
- **Freestanding 环境**：只有最基础的语言支持，没有标准库

内核开发就是典型的 freestanding 环境。我们：

- ❌ 不能用 `<string.h>` 的字符串函数
- ❌ 不能用 `<stdio.h>` 的输入输出
- ❌ 不能用 `<assert.h>` 的断言
- ✅ 只能用 `<stddef.h>` 的几个类型定义
- ✅ 可以用 `<stdint.h>` 的固定宽度整数

所以，如果我们想用字符串函数，就得自己实现。

## 我们要达成什么？

### 目标 1：完整的 C 标准字符串库

我们想实现一个与标准 C 库兼容的字符串工具集：

**基础操作**：
- `strlen` - 计算字符串长度
- `strnlen` - 有长度限制的字符串长度计算
- `strcpy` - 字符串复制
- `strncpy` - 有长度限制的字符串复制

**字符串比较**：
- `strcmp` - 大小写敏感比较
- `strncmp` - 有长度限制的比较
- `strcasecmp` - 忽略大小写比较
- `strncasecmp` - 有长度限制的忽略大小写比较

**字符串搜索**：
- `strchr` - 查找字符首次出现
- `strrchr` - 查找字符最后出现
- `strstr` - 子串查找
- `strpbrk` - 字符集匹配
- `strspn` / `strcspn` - 前缀长度计算

**字符串分割**：
- `strtok` - 非线程安全分割
- `strtok_r` - 线程安全分割

### 目标 2：断言系统

我们想要一个能报告错误的断言机制：

```c
// 关键检查，始终启用
CCOS_ASSERT(ptr != NULL);

// 调试辅助，Release 模式禁用
CCOS_DEBUG_ASSERT(count > 0);
```

当断言失败时：
- VGA 上显示白字红底的错误信息
- Debug 模式触发 `int3` 断点通知 GDB
- 系统停止运行（`cli + hlt`）

## 技术路线

我们分几个步骤来实现这些目标：

### 第一阶段：基础字符串函数

实现最常用的字符串操作：
- 长度计算（`strlen`, `strnlen`）
- 字符串复制（`strcpy`, `strncpy`）

### 第二阶段：字符串比较

实现比较功能：
- 基础比较（`strcmp`, `strncmp`）
- 忽略大小写（`strcasecmp`, `strncasecmp`）
- 大小写转换（`tolower`）

### 第三阶段：字符串搜索

实现各种查找功能：
- 字符查找（`strchr`, `strrchr`）
- 子串查找（`strstr`）
- 字符集操作（`strpbrk`, `strspn`, `strcspn`）

### 第四阶段：字符串分割

实现分割功能：
- `strtok` - 简单但非线程安全
- `strtok_r` - 可重入版本

### 第五阶段：断言系统

实现错误检测：
- 断言宏（`CCOS_ASSERT`, `CCOS_DEBUG_ASSERT`）
- VGA 错误显示后端
- 断言上下文收集

### 第六阶段：测试框架

确保代码质量：
- 主机环境单元测试
- 独立测试程序
- 快速反馈循环

# 美化输出与格式化 —— Stage 12 栈回溯系统实战指南

## 前言

上一篇文章我们实现了基础的栈回溯功能，能够打印出调用链的地址。但说实话，那个输出太简陋了，只有一堆十六进制数字，看起来费劲又不专业。

今天就让我们把输出格式做得漂亮一点。我们要实现一个带边框的表格格式，还要把原始地址转换成可读的函数名。这样当问题发生时，一眼就能看出调用路径，而不是对着地址表发呆。

---

## 第一步：设计输出格式

在写代码之前，我们先想清楚输出要长什么样。一个好的栈回溯输出应该包含：

1. **清晰的标题** - 让人一眼就知道这是什么
2. **寄存器信息** - 当前的 RSP 和 RBP 值
3. **表格形式的调用链** - 每帧一行，列号、地址、函数名
4. **边框装饰** - 用制表符画框，更专业

理想输出应该是这样的：

```
╔═══════════════════════════════════════════════════════════════╗
║                      Stack Trace                             ║
╠═══════════════════════════════════════════════════════════════╣
║  RSP: 0x0000000000007f00                                    ║
║  RBP: 0x0000000000007f20                                    ║
╠═══════════════════════════════════════════════════════════════╣
║  #  Address           Function                           ║
╠═══════════════════════════════════════════════════════════════╣
║  0   0x0000000000010120  kernel_main                    ║
║  1   0x00000000000100a0  test_function+0x1c            ║
║  2   0x0000000000010050  another_function              ║
╚═══════════════════════════════════════════════════════════════╝
```

这个格式看起来很专业，不是吗？边框用的是 Unicode 的制表符，虽然会增加一点复杂度，但效果值得。

## 第二步：更新 dump_stack 函数

现在我们来重写 `dump_stack` 函数，使用新的输出格式。打开 `kernel/stacktrace/stacktrace.c`，把原来的 `dump_stack` 函数替换成：

```c
void dump_stack(int max_frames) {
    // Use default if 0 specified
    if (max_frames <= 0)
        max_frames = DUMP_STACK_DEFAULT_FRAMES;

    // Cap at maximum to prevent infinite loops
    if (max_frames > DUMP_STACK_MAX_FRAMES)
        max_frames = DUMP_STACK_MAX_FRAMES;

    uintptr_t rbp = get_rbp();
    uintptr_t rsp = get_rsp();

    // Print header
    kprintf(KLOG_BACKEND_SERIAL, "\n");
    kprintf(KLOG_BACKEND_SERIAL, "╔═══════════════════════════════════════════════════════════════╗\n");
    kprintf(KLOG_BACKEND_SERIAL, "║                      Stack Trace                             ║\n");
    kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
    kprintf(KLOG_BACKEND_SERIAL, "║  RSP: 0x%016lx                                    ║\n", rsp);
    kprintf(KLOG_BACKEND_SERIAL, "║  RBP: 0x%016lx                                    ║\n", rbp);
    kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
    kprintf(KLOG_BACKEND_SERIAL, "║  #  Address           Function                           ║\n");
    kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");

    int frame = 0;
    bool found_valid_frame = false;

    while (rbp != 0 && frame < max_frames) {
        // Validate frame pointer
        if (!is_valid_frame(rbp)) {
            kprintf(KLOG_BACKEND_SERIAL, "║  %-2d <invalid frame: 0x%016lx>                    ║\n", frame, rbp);
            break;
        }

        found_valid_frame = true;

        // Get return address (saved RIP is at RBP + 8)
        uintptr_t* frame_ptr = (uintptr_t*)rbp;
        uintptr_t prev_rbp = frame_ptr[0];      // Saved RBP
        uintptr_t rip = frame_ptr[1];           // Saved return address

        // Print the frame with symbol information
        if (rip != 0) {
            const char* sym_name;
            uintptr_t sym_offset;

            if (find_symbol(rip, &sym_name, &sym_offset)) {
                // Symbol found - print address + name + offset
                if (sym_offset == 0) {
                    kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %-34s║\n", frame, rip, sym_name);
                } else {
                    kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %s+0x%lx                 ║\n",
                            frame, rip, sym_name, sym_offset);
                }
            } else {
                // No symbol found - just print address
                kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %-34s║\n", frame, rip, "???");
            }
        } else {
            kprintf(KLOG_BACKEND_SERIAL, "║  %d   %-49s║\n", frame, "<no return address>");
        }

        // Move to previous frame
        rbp = prev_rbp;
        frame++;

        // Check for potential loop (same frame repeating)
        if (rbp == get_rbp()) {
            kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
            kprintf(KLOG_BACKEND_SERIAL, "║  <frame loop detected>                                     ║\n");
            break;
        }
    }

    // Print footer
    if (!found_valid_frame) {
        kprintf(KLOG_BACKEND_SERIAL, "║  <no valid stack frames>                                   ║\n");
    } else if (frame >= max_frames && rbp != 0) {
        kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
        kprintf(KLOG_BACKEND_SERIAL, "║  ... (truncated, max frames reached)                        ║\n");
    }

    kprintf(KLOG_BACKEND_SERIAL, "╚═══════════════════════════════════════════════════════════════╝\n");
    kprintf(KLOG_BACKEND_SERIAL, "\n");
}
```

这个版本的 `dump_stack` 有几个改进：

1. **美观的边框** - 使用 Unicode 制表符绘制表格
2. **符号解析** - 调用 `find_symbol()` 尝试查找函数名
3. **偏移量显示** - 如果地址不在函数入口，显示 `function+0xoffset`
4. **更好的格式化** - 使用 `%-2d`、`%016lx`、`%-34s` 等格式化占位符

关于格式化占位符的说明：
- `%-2d` - 左对齐，宽度 2，用于帧号
- `%016lx` - 十六进制，零填充到 16 位，用于地址
- `%-34s` - 左对齐，宽度 34，用于函数名

## 第三步：确保 kprintf 支持所需格式

等等，我们的 kprintf 支持 `%lx` 吗？如果不支持，需要先扩展它。打开 `kernel/klogs/kprintf.c`，检查一下格式化字符串的处理。

在 `format_string` 函数中，应该已经有对 `%x` 的处理，但我们需要确保它支持长度修饰符 `l` 和宽度格式化。如果之前的版本不支持，这里有一个简要的实现：

在 `kprintf.c` 的 `format_string` 函数中，找到处理 `%x` 的部分，确保支持 64 位：

```c
case 'x': {
    uint64_t val = is_long ? va_arg(args, uint64_t) : va_arg(args, unsigned int);
    uitoa64(val, g_format_buffer, 16);

    // Handle width padding
    int len = 0;
    char* s = g_format_buffer;
    while (*s != '\0') {
        len++;
        s++;
    }

    // Pad with spaces or zeros if needed
    if (width > len) {
        char pad_char = pad_with_zero ? '0' : ' ';
        int pad_count = width - len;
        for (int i = 0; i < pad_count && pos < size - 1; i++) {
            buffer[pos++] = pad_char;
        }
    }

    // Output the number
    s = g_format_buffer;
    while (*s != '\0' && pos < size - 1) {
        buffer[pos++] = *s++;
    }
    break;
}
```

以及 `%p` 格式（指针格式）：

```c
case 'p': {
    void* ptr = va_arg(args, void*);
    buffer[pos++] = '0';
    if (pos < size - 1)
        buffer[pos++] = 'x';
    uitoa64((uint64_t)(uintptr_t)ptr, g_format_buffer, 16);
    char* s = g_format_buffer;
    while (*s != '\0' && pos < size - 1) {
        buffer[pos++] = *s++;
    }
    break;
}
```

这些格式化功能在 Stage 10 中应该已经实现了。如果还没有，可以参考那个教程补充。

## 第五步：添加更多错误处理

在实际使用中，栈帧可能损坏或异常。让我们增加一些额外的检查和处理：

在 `dump_stack` 函数中，我们已经有基本的验证，但可以再加一些细节：

```c
// 在循环开始之前，记录初始 RBP 用于循环检测
uintptr_t initial_rbp = get_rbp();
// ...

// 在循环中，除了检查 rbp == get_rbp()，还可以检测重复帧
static uintptr_t last_rbp = 0;
if (rbp == last_rbp) {
    kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
    kprintf(KLOG_BACKEND_SERIAL, "║  <duplicate frame detected>                                  ║\n");
    break;
}
last_rbp = rbp;
```

还有一个常见的陷阱：如果函数没有使用帧指针（比如被编译器内联了），栈帧链就会中断。这是正常的，我们无法恢复。只能打印 `???` 表示无法解析。

## 第六步：在错误处理中使用

现在我们的栈回溯功能已经基本可用了。最典型的使用场景是在错误处理函数中：

```c
void kernel_panic(const char* message) {
    kprintf(KLOG_BACKEND_SERIAL, "\n");
    kprintf(KLOG_BACKEND_SERIAL, "╔═══════════════════════════════════════════════════════════════╗\n");
    kprintf(KLOG_BACKEND_SERIAL, "║                      KERNEL PANIC                           ║\n");
    kprintf(KLOG_BACKEND_SERIAL, "╠═══════════════════════════════════════════════════════════════╣\n");
    kprintf(KLOG_BACKEND_SERIAL, "║  %s                                                       ║\n", message);
    kprintf(KLOG_BACKEND_SERIAL, "╚═══════════════════════════════════════════════════════════════╝\n");

    dump_stack_full();

    klog_error("System halted.\n");
    system_halt();
}
```

这样当内核出现严重错误时，不仅能看到错误消息，还能看到完整的调用栈，调试效率提升很多。

## 踩坑预警

这里有几个你可能会遇到的问题：

### Unicode 字符显示问题

如果你的终端或串口工具不支持 UTF-8，那些漂亮的边框字符可能会显示成乱码。解决方案有两个：

1. 使用支持 UTF-8 的终端（如现代 Linux 终端、Windows Terminal）
2. 改用 ASCII 边框（`+`、`-`、`|`）

如果你的串口工具不支持 UTF-8，可以修改输出格式：

```c
kprintf(KLOG_BACKEND_SERIAL, "+=============================================================+\n");
kprintf(KLOG_BACKEND_SERIAL, "|                      Stack Trace                            |\n");
// ... 以此类推
```

### 格式化字符串不支持

如果编译时报错提示格式化字符串不支持，检查 kprintf 的实现。确保支持：
- `%016lx` - 16 位十六进制，零填充
- `%-34s` - 左对齐字符串
- `%ld` - 长整型

这些格式化功能应该在 Stage 10 的 kprintf 实现中已经支持。

### 栈帧数量不够

如果你的函数调用层次很深，16 帧可能不够。可以增加 `DUMP_STACK_DEFAULT_FRAMES` 的值，或者在调用时指定更大的帧数：

```c
dump_stack(64);  // 打印最多 64 帧
```

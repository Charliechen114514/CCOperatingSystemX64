# 实现符号解析系统 —— Stage 12 栈回溯系统实战指南

## 前言

上一篇文章我们实现了美观的栈回溯输出，但函数名还是显示为 `???`。说实话，光看地址没有函数名，调试起来还是很费劲，你得不停地查地址映射表，或者用 GDB 来查找每个地址对应的函数。

今天我们就来解决这个问题，实现一个完整的符号解析系统。这样当栈回溯打印时，就能直接显示函数名，甚至还能告诉你地址在函数内部的偏移量，比如 `kernel_main+0x1c`。这种信息对于定位问题非常有帮助。

---

## 第一步：设计符号表数据结构

在写代码之前，我们需要先想清楚符号表应该长什么样。符号表的核心功能是：给定一个地址，找到对应的函数名。

最直观的设计是一个结构体数组，每个条目包含地址和函数名：

```c
typedef struct {
    uintptr_t address;  // 函数的起始地址
    const char* name;   // 函数名
} symbol_entry_t;
```

但光有这个还不够。我们需要一个完整的符号表结构，包含条目数组、数量，以及代码段的地址范围：

```c
typedef struct {
    const symbol_entry_t* entries;  // 符号条目数组
    int count;                      // 符号数量
    uintptr_t text_start;           // .text 段起始地址
    uintptr_t text_end;             // .text 段结束地址
} symbol_table_t;
```

`text_start` 和 `text_end` 用于快速判断一个地址是否在代码段内。如果一个地址不在代码段，那它肯定不是有效的函数地址，直接跳过查找。

现在来完善 `kernel/stacktrace/symbol.h`，把它从占位版本替换成完整版本：

```c
/**
 * @file symbol.h
 * @brief Symbol table for stack trace symbol resolution
 * @date 2026-02-17
 */

#pragma once

#include "defines/types.h"

/**
 * @brief Symbol entry structure
 *
 * Each entry represents a function or symbol with its address and name.
 */
typedef struct {
    uintptr_t address;  /**< Symbol address */
    const char* name;   /**< Symbol name (pointer to string table) */
} symbol_entry_t;

/**
 * @brief Symbol table structure
 */
typedef struct {
    const symbol_entry_t* entries;  /**< Array of symbol entries */
    int count;                      /**< Number of symbols */
    uintptr_t text_start;           /**< Start of .text section */
    uintptr_t text_end;             /**< End of .text section */
} symbol_table_t;

/**
 * @brief Get the kernel symbol table
 *
 * @return Pointer to the symbol table
 */
const symbol_table_t* get_symbol_table(void);

/**
 * @brief Find symbol name for an address
 *
 * @param addr The address to look up
 * @param out_name Pointer to store the symbol name
 * @param out_offset Pointer to store the offset from symbol start
 * @return true if a symbol was found
 */
bool find_symbol(uintptr_t addr, const char** out_name, uintptr_t* out_offset);

/**
 * @brief Format address with symbol information
 *
 * Writes a string like "function_name + 0x12" to the buffer.
 *
 * @param buffer Output buffer
 * @param size Buffer size
 * @param addr Address to format
 */
void format_symbol(char* buffer, size_t size, uintptr_t addr);
```

## 第二步：实现符号表访问

符号表数据是由外部脚本自动生成的（我们下一篇会讲），现在我们先实现访问它的接口。

符号表会被定义在外部文件中，我们需要用 `extern` 声明它们。打开 `kernel/stacktrace/symbol.c`：

```c
/**
 * @file symbol.c
 * @brief Symbol table implementation
 * @date 2026-02-17
 */

#include "symbol.h"

// External symbol table generated by scripts/extract_symbols.py
extern const symbol_entry_t _symbol_table_start[];
extern const symbol_entry_t _symbol_table_end[];
extern const char _symbol_string_table[];
extern const uintptr_t _symbol_text_start;
extern const uintptr_t _symbol_text_end;

// Symbol table that references external symbols
static symbol_table_t g_symbol_table = {
    .entries = NULL,  // Will be set at runtime
    .count = 0,       // Will be computed at runtime
    .text_start = 0x10000,
    .text_end = 0x20000,
};

// Runtime-computed symbol count
static int g_symbol_count = 0;

static bool g_symbols_initialized = false;
```

这里有一个巧妙的设计。符号表数据（`_symbol_table_start` 等）是由外部脚本生成的，我们在编译时不知道有多少个符号。所以我们需要在运行时计算符号数量。

为什么要延迟初始化？因为首次构建时符号表文件可能是空的占位符，我们不能假设它总是有效的。运行时检查更安全。

## 第三步：实现符号表初始化

```c
static void init_symbol_table(void) {
    if (g_symbols_initialized) {
        return;
    }

    // Check if we have real symbols (not the placeholder)
    if (_symbol_table_start[0].address != 0) {
        g_symbol_table.entries = _symbol_table_start;

        // Count entries until we hit the terminator
        int count = 0;
        const symbol_entry_t* entry = _symbol_table_start;
        while (entry->address != 0 || entry->name != NULL) {
            count++;
            entry++;
        }
        g_symbol_count = count;
        g_symbol_table.count = count;

        // Use actual text bounds if available
        if (_symbol_text_start != 0) {
            g_symbol_table.text_start = _symbol_text_start;
            g_symbol_table.text_end = _symbol_text_end;
        }
    }

    g_symbols_initialized = true;
}
```

这个函数做了几件事：

1. **检查是否已初始化** - 避免重复初始化
2. **检查符号表是否有效** - 第一个符号的地址不为 0 说明有真实数据
3. **计算符号数量** - 遍历数组直到遇到终止符 `{0, NULL}`
4. **使用实际的代码段边界** - 如果外部提供了

这种设计允许符号表是空的（首次构建时），不会导致系统崩溃。

## 第四步：实现符号查找 —— 二分查找

现在到了核心部分：给定一个地址，找到对应的函数名。符号表是按地址排序的，所以可以用二分查找，时间复杂度 O(log n)。

```c
const symbol_table_t* get_symbol_table(void) {
    init_symbol_table();
    return &g_symbol_table;
}

bool find_symbol(uintptr_t addr, const char** out_name, uintptr_t* out_offset) {
    const symbol_table_t* table = get_symbol_table();

    // No symbols available
    if (table->count == 0) {
        return false;
    }

    // Check if address is in text section
    if (addr < table->text_start || addr >= table->text_end) {
        return false;
    }

    // Binary search for the symbol (table is sorted by address)
    int left = 0;
    int right = table->count - 1;

    while (left <= right) {
        int mid = (left + right) / 2;
        const symbol_entry_t* entry = &table->entries[mid];
        uintptr_t entry_addr = entry->address;
        uintptr_t next_addr = (mid < table->count - 1)
                              ? table->entries[mid + 1].address
                              : 0;

        // Debug: check if name pointer is valid
        if (entry->name == NULL) {
            // Skip entries with NULL names
            right = mid - 1;
            continue;
        }

        if (addr < entry_addr) {
            right = mid - 1;
        } else if (addr >= entry_addr && (mid == table->count - 1 || addr < next_addr)) {
            // Found the symbol - this entry covers our address
            if (out_name) {
                *out_name = entry->name;
            }
            if (out_offset) {
                *out_offset = addr - entry_addr;
            }
            return true;
        } else {
            left = mid + 1;
        }
    }

    return false;
}
```

这个二分查找的逻辑有点特殊。普通的二分查找是找一个等于目标值的元素，但这里我们要找一个"覆盖"目标地址的符号。

每个符号覆盖的地址范围是 `[symbol.address, next_symbol.address)`。比如：
- `kernel_main` 在 0x1000，`next_function` 在 0x1100
- 地址 0x1000 到 0x10ff 都属于 `kernel_main`
- 地址 0x1050 对应 `kernel_main + 0x50`

所以查找条件是 `addr >= entry_addr && (mid == count - 1 || addr < next_addr)`：
- 地址大于等于当前符号的起始地址
- 且（是最后一个符号 或 小于下一个符号的起始地址）

## 第五步：实现符号格式化

现在我们有了一个辅助函数，可以把地址格式化成带符号名的字符串。这在其他地方也很有用：

```c
void format_symbol(char* buffer, size_t size, uintptr_t addr) {
    const char* name;
    uintptr_t offset;

    if (find_symbol(addr, &name, &offset)) {
        if (offset == 0) {
            // Simple snprintf implementation
            int i = 0;
            while (*name && i < (int)size - 1) {
                buffer[i++] = *name++;
            }
            buffer[i] = '\0';
        } else {
            // Format: "name + 0xoffset"
            int i = 0;
            while (*name && i < (int)size - 20) {
                buffer[i++] = *name++;
            }
            const char* suffix = " + 0x";
            while (*suffix && i < (int)size - 10) {
                buffer[i++] = *suffix++;
            }

            // Convert offset to hex
            uintptr_t val = offset;
            if (val == 0) {
                buffer[i++] = '0';
            } else {
                char hex_rev[20];
                int rev_pos = 0;
                while (val > 0 && rev_pos < 16) {
                    int digit = val & 0xF;
                    hex_rev[rev_pos++] = (digit < 10) ? ('0' + digit) : ('a' + digit - 10);
                    val >>= 4;
                }
                // Reverse
                while (rev_pos > 0 && i < (int)size - 1) {
                    buffer[i++] = hex_rev[--rev_pos];
                }
            }
            buffer[i] = '\0';
        }
    } else {
        // No symbol found, just print address
        int i = 0;
        const char* prefix = "0x";
        while (*prefix && i < (int)size - 1) {
            buffer[i++] = *prefix++;
        }

        // Convert address to hex
        char hex_rev[20];
        int rev_pos = 0;
        uintptr_t val = addr;
        if (val == 0) {
            hex_rev[rev_pos++] = '0';
        } else {
            while (val > 0 && rev_pos < 16) {
                int digit = val & 0xF;
                hex_rev[rev_pos++] = (digit < 10) ? ('0' + digit) : ('a' + digit - 10);
                val >>= 4;
            }
        }
        // Reverse
        while (rev_pos > 0 && i < (int)size - 1) {
            buffer[i++] = hex_rev[--rev_pos];
        }
        buffer[i] = '\0';
    }
}
```

这个函数没用 `snprintf`，因为内核环境可能没有标准库。它手动实现字符串格式化，输出类似 `kernel_main + 0x1c` 或 `0x10045a` 的字符串。

## 第六步：更新 stacktrace.c 集成符号解析

现在 `symbol.c` 已经完整实现了，我们需要确保 `stacktrace.c` 正确使用它。打开 `kernel/stacktrace/stacktrace.c`，确保顶部有正确的 include：

```c
#include "stacktrace.h"
#include "symbol.h"  // 确保包含这个头文件
#include "klogs/kprintf.h"
```

`dump_stack` 函数中已经有调用 `find_symbol` 的代码，应该不需要修改。如果你之前没有加，现在补上：

```c
if (find_symbol(rip, &sym_name, &sym_offset)) {
    // Symbol found - print address + name + offset
    if (sym_offset == 0) {
        kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %-34s║\n", frame, rip, sym_name);
    } else {
        kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %s+0x%lx                 ║\n",
                frame, rip, sym_name, sym_offset);
    }
} else {
    // No symbol found - just print address
    kprintf(KLOG_BACKEND_SERIAL, "║  %d   0x%016lx  %-34s║\n", frame, rip, "???");
}
```

## 第七步：创建空符号表占位符

在下一篇我们会写符号生成脚本，但现在为了让编译通过，我们需要创建一个空的符号表文件。

编辑 `kernel/stacktrace/CMakeLists.txt`，确保在符号文件不存在时创建占位符：

```cmake
# 首次构建时，如果符号文件不存在，创建一个空占位符
if(NOT EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c)
    file(WRITE ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c
"/* Auto-generated placeholder - will be overwritten by extract_symbols.py */\n"
"#include \"stacktrace/symbol.h\"\n"
"\n"
"/* Empty symbol table */\n"
"const char _symbol_string_table[] = \"\";\n"
"const symbol_entry_t _symbol_table_start[] = { { 0, NULL } };\n"
"const symbol_entry_t _symbol_table_end[] = { { 0, NULL } };\n"
"const uintptr_t _symbol_text_start = 0x10000;\n"
"const uintptr_t _symbol_text_end = 0x20000;\n"
)
endif()
```

这样首次构建时不会因为缺少 `symbols.c` 而失败。占位符定义了一个空的符号表，`find_symbol` 会正确返回 `false`，栈回溯会显示 `???` 而不是崩溃。

## 踩坑预警

这里有几个常见的坑，你可能会遇到：

### 符号表未正确初始化

如果你发现 `find_symbol` 总是返回 `false`，可能是符号表初始化有问题。检查一下：

1. `symbols.c` 文件是否存在
2. `_symbol_table_start[0].address` 是否不为 0
3. 代码是否调用了 `init_symbol_table` 或 `get_symbol_table`

你可以加一些调试输出来验证：

```c
static void init_symbol_table(void) {
    if (g_symbols_initialized) {
        return;
    }

    kprintf(KLOG_BACKEND_SERIAL, "[DEBUG] Initializing symbol table...\n");

    if (_symbol_table_start[0].address != 0) {
        kprintf(KLOG_BACKEND_SERIAL, "[DEBUG] Real symbols found\n");
        // ...
    } else {
        kprintf(KLOG_BACKEND_SERIAL, "[DEBUG] Using empty placeholder\n");
    }

    g_symbols_initialized = true;
}
```

### 二分查找越界

如果符号表数据格式不对，可能会导致越界访问。确保符号表以 `{0, NULL}` 结尾，并且 `name` 指针有效。

### 地址范围判断错误

如果你的内核 `.text` 段不是从 0x10000 开始，需要调整默认的 `text_start` 和 `text_end` 值。可以用 `readelf` 查看：

```bash
readelf -S build/kernel/kernel.elf | grep .text
```

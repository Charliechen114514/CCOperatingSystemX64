# 增强字符串处理支持 —— Stage 12 栈回溯系统实战指南

## 前言

上一篇文章我们完成了符号表的自动生成，栈回溯已经能显示函数名了。但在实现过程中，我发现了一个问题：我们的字符串工具库和 kprintf 对 64 位整数的支持还不够完善。

说实话，x86_64 架构上的地址和指针都是 64 位的，如果字符串处理函数不支持 64 位，会非常麻烦。我们在栈回溯中需要打印 64 位地址，也需要把 64 位整数转换成字符串。

今天我们就来补齐这块短板，扩展字符串处理库，让 kprintf 支持更多格式化选项。

---

## 第一步：评估现有功能

先看看我们现在的字符串工具库有什么。打开 `kernel/base/strhelpers.h`：

```c
// 现有功能
char* itoa(int value, char* str, int base);
char* uitoa(unsigned int value, char* str, int base);
long strtol(const char* nptr, char** endptr, int base);
int atoi(const char* nptr);
```

这些函数的问题是什么？在 x86_64 上，`int` 通常是 32 位的，而我们的地址是 64 位的。用 `uitoa` 转换 64 位地址会导致截断，只能打印低 32 位。

kprintf 也有类似的问题。检查一下 `kernel/klogs/kprintf.c`，看看 `%lx` 和 `%p` 是否正确支持。在 Stage 10 中我们添加了基本支持，但可能不够完善。

---

## 第二步：实现 64 位整数转字符串

首先添加 64 位整数转字符串的函数。打开 `kernel/base/strhelpers.h`，添加声明：

```c
/**
 * @brief Convert signed 64-bit integer to string
 *
 * @param value The value to convert
 * @param str Buffer to store the result
 * @param base Base for conversion (10, 16, etc.)
 * @return Pointer to str
 */
char* itoa_signed(int64_t value, char* str, int base);

/**
 * @brief Convert unsigned 64-bit integer to string
 *
 * @param value The value to convert
 * @param str Buffer to store the result
 * @param base Base for conversion (10, 16, etc.)
 * @return Pointer to str
 */
char* uitoa64(uint64_t value, char* str, int base);
```

然后在 `kernel/base/strhelpers.c` 中实现：

```c
char* itoa_signed(int64_t value, char* str, int base) {
    // Check base range
    if (base < 2 || base > 36) {
        str[0] = '\0';
        return str;
    }

    int i = 0;
    bool neg = false;
    uint64_t uval;

    // Handle negative numbers (only for decimal)
    if (value < 0 && base == 10) {
        neg = true;
        // Avoid overflow for INT64_MIN
        uval = (uint64_t)(-(value + 1)) + 1;
    } else {
        uval = (uint64_t)value;
    }

    // Generate digits from low to high
    do {
        int digit = uval % base;
        // 0-9 use '0'-'9', 10-35 use 'a'-'z'
        str[i++] = (digit < 10) ? ('0' + digit) : ('a' + digit - 10);
        uval /= base;
    } while (uval != 0);

    // Add negative sign
    if (neg)
        str[i++] = '-';

    str[i] = '\0';

    // Reverse the string
    reverse_str(str, i);

    return str;
}

char* uitoa64(uint64_t value, char* str, int base) {
    // Check base range
    if (base < 2 || base > 36) {
        str[0] = '\0';
        return str;
    }

    int i = 0;
    uint64_t uval = value;

    // Generate digits from low to high
    do {
        int digit = uval % base;
        // 0-9 use '0'-'9', 10-35 use 'a'-'z'
        str[i++] = (digit < 10) ? ('0' + digit) : ('a' + digit - 10);
        uval /= base;
    } while (uval != 0);

    str[i] = '\0';
    reverse_str(str, i);

    return str;
}
```

这两个函数和 32 位版本几乎一样，只是数据类型换成了 `int64_t` 和 `uint64_t`。有一个细节要注意：处理 `INT64_MIN` 时不能直接取负，因为 `-INT64_MIN` 会溢出。我们用 `-(value + 1) + 1` 来避免这个问题。

## 第三步：确保 reverse_str 存在

上面的代码用到了 `reverse_str`，这个函数在 Stage 10 应该已经实现了。如果没有，这里是一个快速实现：

```c
static void reverse_str(char* str, int len) {
    int i = 0, j = len - 1;
    while (i < j) {
        // Swap characters
        char tmp = str[i];
        str[i] = str[j];
        str[j] = tmp;
        i++;
        j--;
    }
}
```

## 第四步：扩展 kprintf 支持 64 位格式

现在来确保 kprintf 正确支持 `%lx` 和 `%p` 格式。打开 `kernel/klogs/kprintf.c`，找到 `format_string` 函数中处理 `%x` 的部分：

```c
case 'x': {
    // Determine if 64-bit based on 'l' modifier
    uint64_t val = is_long ? va_arg(args, uint64_t) : va_arg(args, unsigned int);
    uitoa64(val, g_format_buffer, 16);

    // Handle width padding
    int len = 0;
    char* s = g_format_buffer;
    while (*s != '\0') {
        len++;
        s++;
    }

    // Pad with spaces or zeros if needed
    if (width > len) {
        char pad_char = pad_with_zero ? '0' : ' ';
        int pad_count = width - len;
        for (int i = 0; i < pad_count && pos < size - 1; i++) {
            buffer[pos++] = pad_char;
        }
    }

    // Output the number
    s = g_format_buffer;
    while (*s != '\0' && pos < size - 1) {
        buffer[pos++] = *s++;
    }
    break;
}
```

这里的关键是 `is_long` 标志，当格式字符串中有 `%lx` 时，`is_long` 会被设置为 1，然后我们用 `va_arg(args, uint64_t)` 来获取 64 位参数。

对于 `%p`（指针格式），处理类似：

```c
case 'p': {
    void* ptr = va_arg(args, void*);
    buffer[pos++] = '0';
    if (pos < size - 1)
        buffer[pos++] = 'x';
    uitoa64((uint64_t)(uintptr_t)ptr, g_format_buffer, 16);
    char* s = g_format_buffer;
    while (*s != '\0' && pos < size - 1) {
        buffer[pos++] = *s++;
    }
    break;
}
```

指针在 x86_64 上是 64 位的，所以需要用 `(uint64_t)(uintptr_t)` 转换后再调用 `uitoa64`。

## 第五步：支持宽度格式化

栈回溯输出中我们需要 `%016lx` 这种格式，表示十六进制、零填充、宽度 16。这需要 kprintf 支持宽度解析。

在 `format_string` 函数中，处理格式字符串的部分应该已经能解析宽度了。大概逻辑是这样的：

```c
// Parse width and flags: %0Nx or %Nx or %-Ns
int width = 0;
int pad_with_zero = 0;
int left_align = 0;

// Check for left-align flag
if (*p == '-') {
    left_align = 1;
    p++;
}

// Check for zero-padding flag (only for right-align)
if (*p == '0' && !left_align) {
    pad_with_zero = 1;
    p++;
}

// Parse width digits
while (*p >= '0' && *p <= '9') {
    width = width * 10 + (*p - '0');
    p++;
}

// Length modifier: 'l' for long (64-bit on x86_64)
int is_long = 0;
if (*p == 'l') {
    is_long = 1;
    p++;
}
```

这样解析后，`%016lx` 会被解析为：`width=16`, `pad_with_zero=1`, `is_long=1`，格式字符是 `'x'`。

## 第六步：处理有符号整数的 64 位版本

同样，`%d` 和 `%i` 格式也应该支持 64 位。在 `kprintf.c` 中处理 `%d` 的部分：

```c
case 'd':
case 'i': {
    int64_t val = is_long ? va_arg(args, int64_t) : va_arg(args, int);
    itoa_signed(val, g_format_buffer, 10);

    int len = 0;
    char* s = g_format_buffer;
    while (*s != '\0') {
        len++;
        s++;
    }

    if (width > len && !left_align) {
        char pad_char = pad_with_zero ? '0' : ' ';
        int pad_count = width - len;
        for (int i = 0; i < pad_count && pos < size - 1; i++) {
            buffer[pos++] = pad_char;
        }
    }

    s = g_format_buffer;
    while (*s != '\0' && pos < size - 1) {
        buffer[pos++] = *s++;
    }

    if (width > len && left_align) {
        int pad_count = width - len;
        for (int i = 0; i < pad_count && pos < size - 1; i++) {
            buffer[pos++] = ' ';
        }
    }
    break;
}
```

`%u`（无符号整数）的处理类似：

```c
case 'u': {
    uint64_t val = is_long ? va_arg(args, uint64_t) : va_arg(args, unsigned int);
    uitoa64(val, g_format_buffer, 10);

    // ... 格式化逻辑与 %d 类似
    break;
}
```

## 踩坑预警

这里有几个常见的坑，你可能会遇到：

### 变长参数的类型提升

在 C 语言中，调用变长参数函数时，小整型会被自动提升为 `int`，`float` 会被提升为 `double`。但对于 64 位整数，需要显式指定：

```c
// 错误：传递的 int 会被当成 32 位
kprintf("%lx", 123456789);

// 正确：使用 LL 后缀
kprintf("%lx", 123456789LL);
```

### va_arg 的类型必须匹配

使用 `va_arg` 时，指定的类型必须和实际传递的类型一致，否则会读取错误的值：

```c
// 如果格式是 %ld，必须用 va_arg(args, int64_t)
int64_t val = va_arg(args, int64_t);
```

### 宽度填充的顺序

宽度解析的顺序很重要：先解析标志（`-`、`0`），再解析宽度数字，最后解析长度修饰符（`l`）。

比如 `%016lx` 的解析顺序：
1. `0` → `pad_with_zero = 1`
2. `16` → `width = 16`
3. `l` → `is_long = 1`
4. `x` → 格式字符

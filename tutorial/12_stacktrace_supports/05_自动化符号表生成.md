# 自动化符号表生成 —— Stage 12 栈回溯系统实战指南

## 前言

上一篇文章我们实现了符号解析系统，但符号表还是空的占位符。说实话，手工维护符号表简直是噩梦，每次函数地址变化都要更新，我绝不会干这种事。

今天我们就来写一个 Python 脚本，从编译出来的 ELF 文件中自动提取符号，生成 C 代码。这样每次编译内核后，符号表会自动更新，完全不需要人工干预。

---

## 第一步：理解 ELF 符号表

在写脚本之前，我们需要先理解 ELF 文件的符号表结构。ELF 文件的 `.symtab` 段存储了所有符号信息，每个符号包含：

| 字段 | 含义 |
|------|------|
| Value | 符号的地址（对于函数是入口地址） |
| Size | 符号的大小 |
| Type | 符号类型（FUNC, OBJECT, 等） |
| Bind | 绑定类型（LOCAL, GLOBAL, WEAK） |
| Ndx | 所在的段索引 |
| Name | 符号名称 |

我们可以用 `readelf` 命令查看符号表：

```bash
readelf -s build/kernel/kernel.elf
```

输出类似这样：

```
Symbol table '.symtab' contains 65 entries:
   Num:    Value          Size Type    Bind   Vis      Ndx Name
     0: 0000000000000000     0 NOTYPE  LOCAL  DEFAULT  UND
     1: 0000000000010000     0 SECTION LOCAL  DEFAULT    1 .text
     2: 0000000000010000     0 FUNC    LOCAL  DEFAULT    1 kernel_entry
     3: 0000000000010050    32 FUNC    GLOBAL DEFAULT    1 kernel_main
     ...
```

我们需要解析这个输出，提取函数类型（`FUNC`）的符号，忽略段和文件类型。

---

## 第二步：创建 Python 脚本框架

现在来创建符号提取脚本。在项目根目录创建 `scripts/extract_symbols.py`：

```python
#!/usr/bin/env python3
"""
Extract symbol table from kernel ELF for stack trace symbol resolution.

Generates C files with symbol table data that can be linked into the kernel.
"""

import argparse
import subprocess
import sys
from pathlib import Path
```

这个脚本会做三件事：
1. 调用 `readelf` 获取符号信息
2. 解析符号信息，筛选出我们需要的内容
3. 生成 C 代码文件

---

## 第三步：实现 readelf 调用

首先实现一个函数来调用 `readelf` 并获取输出：

```python
def readelf_get_symbols(elf_path):
    """Get symbols from ELF using readelf."""
    try:
        result = subprocess.run(
            ['readelf', '-s', '-W', str(elf_path)],
            capture_output=True,
            text=True,
            check=True
        )
        return result.stdout
    except subprocess.CalledProcessError as e:
        print(f"Error running readelf: {e}", file=sys.stderr)
        return None
    except FileNotFoundError:
        print("Error: readelf not found. Install binutils.", file=sys.stderr)
        return None
```

这里使用了 `-s` 选项显示符号表，`-W` 选项宽行显示（避免长符号名被截断）。如果 `readelf` 命令不存在，脚本会给出友好的错误提示。

## 第四步：解析符号信息

现在来解析 `readelf` 的输出。这是脚本的 core 部分：

```python
def parse_symbols(readelf_output):
    """Parse readelf output to extract symbol information."""
    symbols = []

    for line in readelf_output.split('\n'):
        # Skip header and empty lines
        if not line or 'Num:' in line or 'Symbol table' in line:
            continue

        # Parse the readelf output format
        # Num:    Value          Size Type    Bind   Vis      Ndx Name
        parts = line.split()
        if len(parts) < 8:
            continue

        try:
            # Get value (address)
            value = int(parts[1], 16)

            # Get type and binding
            sym_type = parts[3]
            sym_bind = parts[4] if len(parts) > 4 else ''

            # Include FUNC, NOTYPE (for labels like halt_loop)
            # Skip SECTION and FILE
            if sym_type in ('SECTION', 'FILE'):
                continue

            # Get section index - we only want code sections (section 1 is .text)
            ndx = parts[6]
            if ndx == 'UND' or ndx == 'ABS':
                continue

            # Get symbol name (might have spaces)
            name = ' '.join(parts[7:])

            # Filter out unwanted symbols
            if name.startswith('__') and name.endswith('__'):
                continue
            if name in ('_init', '_fini'):
                continue
            # Skip unnamed symbols
            if not name or name.startswith('$'):
                continue

            symbols.append((value, name))

        except (ValueError, IndexError):
            continue

    return symbols
```

这个解析逻辑做了几件事：

1. **跳过标题行** - 包含 `Num:` 或 `Symbol table` 的行
2. **分割字段** - 按空格分割
3. **提取地址** - 第二列是十六进制地址
4. **过滤类型** - 只要 FUNC 和 NOTYPE 类型，跳过 SECTION 和 FILE
5. **过滤段** - 只要代码段（Ndx 不是 UND 或 ABS）的符号
6. **过滤特殊符号** - 跳过 `__xxx__` 格式的内部符号

过滤规则是经过调试优化的，既能覆盖我们需要的函数符号，又不会包含太多垃圾数据。

## 第五步：获取 .text 段边界

我们需要知道 `.text` 段的起始和结束地址，用于判断一个地址是否在代码段内：

```python
def get_text_section_bounds(elf_path):
    """Get the start and end of .text section from ELF."""
    try:
        result = subprocess.run(
            ['readelf', '-S', str(elf_path)],
            capture_output=True,
            text=True,
            check=True
        )

        text_start = None
        text_size = None

        lines = result.stdout.split('\n')
        for i, line in enumerate(lines):
            if '.text' in line and 'PROGBITS' in line:
                # Combine current line with next line (readelf splits section info)
                parts = line.split()
                # Format: [Nr] Name Type Address Off
                # Parts can be: ['[', '1]', '.text', 'PROGBITS', '0000000000010000', '00001000']
                if len(parts) >= 5:
                    # Address is at index 4 (after Name, Type, PROGBITS)
                    try:
                        text_start = int(parts[4], 16)
                    except ValueError:
                        # Maybe different format, try next position
                        if len(parts) >= 6:
                            text_start = int(parts[5], 16)

                # Get size from next line
                if i + 1 < len(lines):
                    next_parts = lines[i + 1].split()
                    if len(next_parts) >= 1:
                        try:
                            text_size = int(next_parts[0], 16)
                        except ValueError:
                            pass
                break

        if text_start is not None and text_size is not None:
            return text_start, text_start + text_size

    except (subprocess.CalledProcessError, FileNotFoundError, ValueError) as e:
        print(f"Debug: Error reading section: {e}", file=sys.stderr)

    # Fallback to known values
    print("Warning: Could not read .text section, using defaults", file=sys.stderr)
    return 0x10000, 0x20000
```

这个函数解析 `readelf -S` 的输出，找到 `.text` 段的地址和大小。如果解析失败，返回默认值。

## 第六步：生成 C 代码

现在我们有符号数据了，来生成 C 代码文件：

```python
def generate_symbol_files(symbols, text_start, text_end, output_dir):
    """Generate C source files with symbol table data."""
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)

    # Sort symbols by address
    symbols.sort(key=lambda x: x[0])

    # Generate symbols.c
    symbols_c = output_dir / 'symbols.c'
    with open(symbols_c, 'w') as f:
        f.write("/* Auto-generated by scripts/extract_symbols.py */\n")
        f.write("/* DO NOT EDIT */\n\n")
        f.write('#include "stacktrace/symbol.h"\n\n')

        # String table
        f.write("/* String table for symbol names */\n")
        f.write("__attribute__((section(\".rodata\")))\n")
        f.write("const char _symbol_string_table[] =\n")

        string_offsets = {}
        current_offset = 0

        for addr, name in symbols:
            if name not in string_offsets:
                # Escape special characters in name
                escaped_name = name.encode('utf-8').decode('unicode_escape') \
                               .encode('unicode_escape').decode('ascii')
                escaped_name = escaped_name.replace('"', '\\"')
                f.write(f'    "{escaped_name}\\0"\n')
                string_offsets[name] = current_offset
                current_offset += len(name) + 1

        f.write(";\n\n")

        # Symbol table entries
        f.write("/* Symbol table entries */\n")
        f.write("__attribute__((section(\".rodata\")))\n")
        f.write("const symbol_entry_t _symbol_table_start[] = {\n")

        for addr, name in symbols:
            # Calculate offset in string table
            offset = 0
            for n, o in string_offsets.items():
                if n == name:
                    offset = o
                    break

            f.write(f"    {{ 0x{addr:x}, &_symbol_string_table[{offset}] }},\n")

        # Add terminator to the symbol table
        f.write("    { 0, NULL }\n")  # Terminator marker
        f.write("};\n\n")
        f.write("__attribute__((section(\".rodata\")))\n")
        f.write("const symbol_entry_t _symbol_table_end[] = {\n")
        f.write("    { 0, NULL }\n")
        f.write("};\n\n")

        # Text section bounds
        f.write("/* Text section bounds */\n")
        f.write(f"const uintptr_t _symbol_text_start = 0x{text_start:x};\n")
        f.write(f"const uintptr_t _symbol_text_end = 0x{text_end:x};\n")

    print(f"Generated {symbols_c}")

    # Generate symbols.h (for reference)
    symbols_h = output_dir / 'symbols.h'
    with open(symbols_h, 'w') as f:
        f.write("/* Auto-generated by scripts/extract_symbols.py */\n")
        f.write("/* Symbol count: {} */\n".format(len(symbols)))
        f.write("/* Text range: 0x{:x} - 0x{:x} */\n".format(text_start, text_end))

    print(f"Generated {symbols_h}")
    print(f"Total symbols: {len(symbols)}")
```

这个函数生成两个文件：

1. **symbols.c** - 包含实际的符号表数据
   - `_symbol_string_table` - 字符串表，存储所有符号名
   - `_symbol_table_start` - 符号表条目数组
   - `_symbol_text_start/end` - 代码段边界

2. **symbols.h** - 参考文件，只包含注释

字符串表的设计很巧妙：所有符号名连续存储，用 `\0` 分隔。符号表条目中的 `name` 指针指向字符串表中的偏移位置。这样避免了重复存储相同的字符串。

## 第七步：主函数

最后加上主函数，把所有部分串起来：

```python
def main():
    parser = argparse.ArgumentParser(description='Extract symbols from kernel ELF')
    parser.add_argument('elf', help='Path to kernel ELF file')
    parser.add_argument('-o', '--output', default='kernel/stacktrace',
                       help='Output directory (default: kernel/stacktrace)')
    args = parser.parse_args()

    # Get symbol information
    readelf_output = readelf_get_symbols(args.elf)
    if readelf_output is None:
        sys.exit(1)

    symbols = parse_symbols(readelf_output)
    if not symbols:
        print("No symbols found!", file=sys.stderr)
        sys.exit(1)

    # Get text section bounds
    text_start, text_end = get_text_section_bounds(args.elf)

    # Generate output files
    generate_symbol_files(symbols, text_start, text_end, args.output)


if __name__ == '__main__':
    main()
```

## 第九步：集成到 CMake 构建流程

现在每次手动运行脚本太麻烦了，我们把它集成到 CMake 中。编辑 `kernel/CMakeLists.txt`，在链接 kernel 之后添加：

```cmake
# 符号表生成 - 在链接后执行
add_custom_command(TARGET kernel POST_BUILD
    COMMAND python3 ${CMAKE_SOURCE_DIR}/scripts/extract_symbols.py
        $<TARGET_FILE:kernel>
        -o ${CMAKE_SOURCE_DIR}/kernel/stacktrace
    COMMENT "Extracting symbols from kernel ELF"
)
```

这样每次编译完成后会自动运行符号提取脚本。

但这样有个问题：CMake 每次都会运行脚本，即使符号没变。更好的方式是让 CMake 跟踪依赖关系。修改 `kernel/stacktrace/CMakeLists.txt`：

```cmake
# 符号文件的时间戳，用于触发重新编译
set(SYMBOLS_C ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c)
set(SYMBOLS_TIMESTAMP ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c.timestamp)

# 自定义命令：生成符号表
add_custom_command(
    OUTPUT ${SYMBOLS_C} ${SYMBOLS_TIMESTAMP}
    COMMAND python3 ${CMAKE_SOURCE_DIR}/scripts/extract_symbols.py
            $<TARGET_FILE:kernel>
            -o ${CMAKE_CURRENT_SOURCE_DIR}
    COMMAND ${CMAKE_COMMAND} -E touch ${SYMBOLS_TIMESTAMP}
    DEPENDS $<TARGET_FILE:kernel>
            ${CMAKE_SOURCE_DIR}/scripts/extract_symbols.py
    COMMENT "Extracting symbols from kernel ELF"
)
```

然后在 stacktrace 库的源文件中添加 `symbols.c` 的依赖：

```cmake
add_library(stacktrace STATIC
    stacktrace.c
    symbol.c
)

# 符号表作为自定义目标
add_custom_target(symbols DEPENDS ${SYMBOLS_C})
add_dependencies(stacktrace symbols)
```

这样 CMake 会正确处理依赖关系：只有当 ELF 文件变化时才重新生成符号表。

## 踩坑预警

这里有几个你可能会遇到的问题：

### readelf 命令找不到

如果你的系统没有安装 binutils，`readelf` 命令会不存在。安装方法：

```bash
# Ubuntu/Debian
sudo apt install binutils

# Arch Linux
sudo pacman -S binutils

# macOS (使用 Homebrew)
brew install binutils
```

### Python 版本问题

脚本使用 Python 3，如果你的系统默认 Python 是 2.x，需要显式指定：

```bash
python3 scripts/extract_symbols.py ...
```

或者在脚本开头指定解释器路径：

```bash
#!/usr/bin/env python3
```

### 符号数量为 0

如果 `readelf -s` 输出的格式和预期不同，可能导致解析失败。用 GDB 调试一下：

```bash
python3 -m pdb scripts/extract_symbols.py build/kernel/kernel.elf
```

或者添加调试输出，看看解析到什么：

```python
# 在 parse_symbols 中添加
print(f"DEBUG: Parsing line: {line}")
```

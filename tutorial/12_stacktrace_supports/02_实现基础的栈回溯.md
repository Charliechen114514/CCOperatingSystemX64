# 实现基础的栈回溯 —— Stage 12 栈回溯系统实战指南

## 前言

上一篇文章我们讲了为什么要实现栈回溯，以及 x86_64 的调用约定。现在到了真正动手的时候了。

说实话，写内核代码最怕的就是纸上谈兵。看得再多，不如自己动手写一遍。今天我们要实现的是栈回溯的核心逻辑：遍历栈帧链表，收集返回地址。这部分的代码不多，但每一行都有它的道理，我们一步一步来。

## 第二步：实现头文件 —— 定义接口

先写头文件，定义我们的接口。这样可以先确定 API 设计，实现细节可以后面再填。

创建 `kernel/stacktrace/stacktrace.h`：

```c
/**
 * @file stacktrace.h
 * @brief Stack trace dump functionality for kernel debugging
 * @date 2026-02-17
 */

#pragma once

#include "defines/types.h"

/**
 * @brief Default maximum number of stack frames to dump
 */
#define DUMP_STACK_DEFAULT_FRAMES 16

/**
 * @brief Maximum allowed frames to prevent infinite loops
 */
#define DUMP_STACK_MAX_FRAMES 64

/**
 * @brief Dump the current stack trace
 *
 * Walks the stack frame chain using RBP and prints return addresses.
 *
 * @param max_frames Maximum number of frames to dump (0 for default)
 *
 * Example:
 *   void some_function() {
 *       dump_stack(16);  // Print up to 16 stack frames
 *   }
 */
void dump_stack(int max_frames);

/**
 * @brief Dump stack trace with default frame count
 */
void dump_stack_full(void);
```

这个头文件定义了两个公共函数和一些常量。`dump_stack()` 允许指定最大帧数，`dump_stack_full()` 使用默认值。为什么要限制帧数？因为如果栈帧链表坏了，可能会进入无限循环，我们必须有个安全上限。

你可能注意到有两个常量：`DUMP_STACK_DEFAULT_FRAMES` 是 16，`DUMP_STACK_MAX_FRAMES` 是 64。这些数字是怎么来的？16 层对于大多数情况已经足够了，64 层是硬上限，防止真的出问题的时候把系统跑死。当然你可以根据需要调整这些值。

## 第三步：读取寄存器 —— 内联汇编入门

现在我们来实现核心功能。第一步是读取当前寄存器的值。我们需要 RSP（栈指针）和 RBP（帧指针）。

在 C 语言中，我们不能直接访问寄存器（除非用编译器扩展）。GCC 提供了内联汇编功能，让我们可以在 C 代码中嵌入汇编指令。语法有点特殊，我们来看一下：

在 `kernel/stacktrace/` 目录下创建 `stacktrace.c`：

```c
/**
 * @file stacktrace.c
 * @brief Stack trace dump implementation
 * @date 2026-02-17
 */

#include "stacktrace.h"
#include "klogs/kprintf.h"

// Stack bounds for validation
#define STACK_BASE    0x80000UL    // Approximate stack top (from kernel_entry.asm)
#define STACK_SIZE    0x10000UL    // 64KB stack size

/**
 * @brief Get current stack pointer
 *
 * @return current RSP value
 */
static inline uintptr_t get_rsp(void) {
    uintptr_t rsp;
    __asm__ volatile("mov %%rsp, %0" : "=r"(rsp));
    return rsp;
}

/**
 * @brief Get current frame pointer
 *
 * @return current RBP value
 */
static inline uintptr_t get_rbp(void) {
    uintptr_t rbp;
    __asm__ volatile("mov %%rbp, %0" : "=r"(rbp));
    return rbp;
}
```

这里用到了 GCC 内联汇编的扩展语法。让我解释一下 `"mov %%rsp, %0" : "=r"(rsp)` 是什么意思：

- `mov %%rsp, %0` 是汇编指令，`%%` 表示一个 `%`，`%0` 是占位符
- `"=r"(rsp)` 是操作数约束，`=` 表示输出操作数，`r` 表示使用任意通用寄存器，`(rsp)` 是 C 变量
- `volatile` 告诉编译器不要优化掉这条指令

简单来说，这条指令的意思是：把 RSP 寄存器的值移动到一个寄存器中，然后把这个寄存器的值赋给 C 变量 `rsp`。

为什么要用 `volatile`？因为编译器可能会认为读取 RSP 没有副作用，把它优化掉。`volatile` 告诉编译器"别动这条指令"，确保它一定会执行。

## 第四步：验证栈帧 —— 安全第一

在遍历栈帧之前，我们必须验证帧指针是否有效。如果栈帧坏了（比如被越界写破坏了），盲目遍历会导致二次崩溃，那就更难调试了。

```c
/**
 * @brief Validate if a pointer looks like a valid stack frame
 *
 * @param ptr The pointer to validate
 * @return true if the pointer is likely a valid frame pointer
 */
static bool is_valid_frame(uintptr_t ptr) {
    // Check alignment (frames should be 8-byte aligned on x86_64)
    if (ptr & 0x7)
        return false;

    // Check if within reasonable stack bounds
    // Stack grows downward, so valid addresses are below STACK_BASE
    if (ptr > STACK_BASE)
        return false;

    // Check if not too far down (reasonable lower bound)
    if (ptr < (STACK_BASE - STACK_SIZE))
        return false;

    return true;
}
```

这个函数做了三件事：

1. **检查对齐** - x86_64 的栈地址必须 8 字节对齐。如果 `ptr & 0x7` 不为 0，说明地址没有对齐，不可能是合法的栈帧。
2. **检查上界** - 栈从高地址向低地址增长，`STACK_BASE` 是栈的起始位置。帧指针不能超过这个值。
3. **检查下界** - 栈大小是 64KB，帧指针不能低于 `STACK_BASE - STACK_SIZE`。

这三个检查能过滤掉大多数无效地址。当然这不是完美的，但在实际使用中已经足够了。如果你的内核栈大小不是 64KB，记得修改 `STACK_SIZE` 的值。

## 第五步：实现基础栈遍历

现在我们有了所有需要的工具，可以实现栈遍历了。我们先写一个简单版本，只打印地址，不管格式美观。

在 `stacktrace.c` 中添加：

```c
void dump_stack(int max_frames) {
    // Use default if 0 specified
    if (max_frames <= 0)
        max_frames = DUMP_STACK_DEFAULT_FRAMES;

    // Cap at maximum to prevent infinite loops
    if (max_frames > DUMP_STACK_MAX_FRAMES)
        max_frames = DUMP_STACK_MAX_FRAMES;

    uintptr_t rbp = get_rbp();
    uintptr_t rsp = get_rsp();

    kprintf(KLOG_BACKEND_SERIAL, "\n");
    kprintf(KLOG_BACKEND_SERIAL, "=== Stack Trace ===\n");
    kprintf(KLOG_BACKEND_SERIAL, "RSP: 0x%016lx\n", rsp);
    kprintf(KLOG_BACKEND_SERIAL, "RBP: 0x%016lx\n", rbp);
    kprintf(KLOG_BACKEND_SERIAL, "------------------\n");

    int frame = 0;
    bool found_valid_frame = false;

    while (rbp != 0 && frame < max_frames) {
        // Validate frame pointer
        if (!is_valid_frame(rbp)) {
            kprintf(KLOG_BACKEND_SERIAL, "#%d <invalid frame: 0x%016lx>\n", frame, rbp);
            break;
        }

        found_valid_frame = true;

        // Get return address (saved RIP is at RBP + 8)
        uintptr_t* frame_ptr = (uintptr_t*)rbp;
        uintptr_t prev_rbp = frame_ptr[0];      // Saved RBP
        uintptr_t rip = frame_ptr[1];           // Saved return address

        // Print the frame
        if (rip != 0) {
            kprintf(KLOG_BACKEND_SERIAL, "#%d 0x%016lx\n", frame, rip);
        } else {
            kprintf(KLOG_BACKEND_SERIAL, "#%d <no return address>\n", frame);
        }

        // Move to previous frame
        rbp = prev_rbp;
        frame++;

        // Check for potential loop (same frame repeating)
        if (rbp == get_rbp()) {
            kprintf(KLOG_BACKEND_SERIAL, "<frame loop detected>\n");
            break;
        }
    }

    if (!found_valid_frame) {
        kprintf(KLOG_BACKEND_SERIAL, "<no valid stack frames>\n");
    } else if (frame >= max_frames && rbp != 0) {
        kprintf(KLOG_BACKEND_SERIAL, "... (truncated, max frames reached)\n");
    }

    kprintf(KLOG_BACKEND_SERIAL, "==================\n");
    kprintf(KLOG_BACKEND_SERIAL, "\n");
}

void dump_stack_full(void) {
    dump_stack(DUMP_STACK_DEFAULT_FRAMES);
}
```

这个函数的逻辑很清晰：

1. **参数处理** - 如果 `max_frames` 是 0，使用默认值；如果超过最大值，截断到最大值
2. **获取当前寄存器值** - 读取 RSP 和 RBP
3. **打印标题** - 显示当前的 RSP 和 RBP
4. **遍历栈帧** - 循环处理每个栈帧：
   - 验证帧指针是否有效
   - 从 `RBP` 读取保存的上一个 RBP
   - 从 `RBP + 8` 读取返回地址
   - 打印返回地址
   - 移动到上一个栈帧
   - 检测循环（防止无限循环）
5. **处理结束情况** - 如果没有有效帧、达到最大帧数，打印相应消息

这里有个细节要注意：`uintptr_t* frame_ptr = (uintptr_t*)rbp;` 这行代码把 RBP 当作指针来用，然后 `frame_ptr[0]` 是 `*frame_ptr`（保存的 RBP），`frame_ptr[1]` 是 `*(frame_ptr + 1)`（返回地址）。这种写法比直接用指针解引用更清晰。

## 第六步：配置 CMake 构建

现在我们需要把这个模块加入到构建系统中。创建 `kernel/stacktrace/CMakeLists.txt`：

```cmake
# ============================================================================
# Stacktrace 模块 - 栈回溯等调试功能
# ============================================================================

# 创建空符号文件占位符（首次构建时）
if(NOT EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c)
    file(WRITE ${CMAKE_CURRENT_SOURCE_DIR}/symbols.c
"/* Auto-generated placeholder - will be overwritten by extract_symbols.py */\n"
"#include \"stacktrace/symbol.h\"\n"
"\n"
"/* Empty symbol table */\n"
"const char _symbol_string_table[] = \"\";\n"
"const symbol_entry_t _symbol_table_start[] = { { 0, NULL } };\n"
"const symbol_entry_t _symbol_table_end[] = { { 0, NULL } };\n"
"const uintptr_t _symbol_text_start = 0x10000;\n"
"const uintptr_t _symbol_text_end = 0x20000;\n"
)
endif()

add_library(stacktrace STATIC
    stacktrace.c
    symbol.c
    symbols.c
)

target_include_directories(stacktrace PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}
    ${CMAKE_CURRENT_SOURCE_DIR}/..
    ${CMAKE_BINARY_DIR}/include
)

target_compile_options(stacktrace PUBLIC ${CCOS_FREESTANDING_FLAGS})

set_target_properties(stacktrace PROPERTIES
    POSITION_INDEPENDENT_CODE FALSE
)
```

## 踩坑预警

这里有几个常见的坑，你可能会遇到：

### 帧指针被优化掉

如果你发现栈回溯只打印一帧就结束了，可能是编译器优化掉了帧指针。检查一下编译选项，确保有 `-fno-omit-frame-pointer`。

在根目录的 `CMakeLists.txt` 中添加：

```cmake
option(CCOS_ENABLE_FRAME_POINTER "Enable frame pointer for stack tracing" ON)

if(CCOS_ENABLE_FRAME_POINTER)
    target_compile_options(kernel PRIVATE -fno-omit-frame-pointer)
endif()
```

### 无效的帧指针

如果输出显示 `<invalid frame>`，可能是你的栈地址范围设置不对。用 GDB 调试一下，看看实际的 RBP 值是多少，然后调整 `STACK_BASE` 和 `STACK_SIZE`。

```bash
gdb build/kernel/kernel.elf
(gdb) target remote :1234
(gdb) print $rbp
(gdb) print $rsp
```

### 没有输出

如果完全没看到输出，检查串口初始化是否正确，以及 kprintf 是否已经初始化。

# 04 - 链接脚本与内存布局

上一篇我们用了 `linker.ld` 但没解释。这一篇我们深入理解它。

---

## 什么是链接脚本

**你可以把链接脚本理解为给链接器的"装修说明书"。**

编译器把每个源文件编译成 .o 目标文件，链接器要把这些 .o 文件拼成一个完整的程序。**拼在哪里？按什么顺序？哪些段放在哪里？** 这就是链接脚本决定的。

没有链接脚本，链接器会用默认布局，但那个布局不适合裸机编程。

### 为什么我们需要链接脚本

1. **指定加载地址** — 内核必须加载到 0x10000，因为 bootloader 是这么跳转的
2. **控制段顺序** — .text、.rodata、.data、.bss 的顺序和位置
3. **导出符号** — 供汇编代码使用（如 `__bss_start`、`__bss_end`）
4. **丢弃无用段** — 减小最终二进制大小

---

## linker.ld 逐段解析

我们来看完整的链接脚本（[linker.ld](../linker.ld)）：

```ld
/* CCOS Kernel Linker Script */
/* Kernel is loaded at 0x10000 by bootloader */

ENTRY(kernel_start)

SECTIONS
{
    /* Kernel starts at 0x10000 */
    . = 0x10000;

    /* Text section - code */
    .text : {
        *(.text)
        *(.text.*)
    }

    /* Read-only data */
    .rodata : {
        *(.rodata)
        *(.rodata.*)
    }

    /* Initialized data */
    .data : {
        *(.data)
        *(.data.*)
    }

    /* Uninitialized data */
    .bss : {
        __bss_start = .;
        *(.bss)
        *(.bss.*)
        *(COMMON)
        __bss_end = .;
    }

    /* Discard sections we don't need */
    /DISCARD/ : {
        *(.comment)
        *(.eh_frame)
        *(.note.gnu.build-id)
    }
}
```

### ENTRY 声明

```ld
ENTRY(kernel_start)
```

告诉链接器：**程序的入口点是 `kernel_start` 这个符号**。

这个符号在 `kernel_entry.asm` 里定义：

```nasm
global kernel_start
kernel_start:
    cli
    ...
```

如果没有 `ENTRY`，链接器会随便选一个（通常是第一个出现的 .text 段符号），可能不是我们想要的。

### SECTIONS 块

```ld
SECTIONS
{
    ...
}
```

所有段定义都在这个块里。

### 设置加载地址

```ld
. = 0x10000;
```

**这个点的含义很有意思。**

`.` 是**位置计数器**（Location Counter），表示"当前放到了哪里"。赋值就是把位置计数器设为 0x10000，**后面的代码都从这个地址开始放**。

**为什么是 0x10000？**

因为我们的 bootloader 是这样加载内核的：

```nasm
; bootloader.asm
mov ax, 0x1000
mov es, ax          ; ES:BX = 0x1000:0000 = 0x10000
mov bx, 0
call load_kernel
```

所以内核必须链接到 0x10000，否则跳转会错位。

### .text 段（代码）

```ld
.text : {
    *(.text)
    *(.text.*)
}
```

**语法解释**：

- `.text :` — 定义一个叫 .text 的段
- `*(.text)` — 把所有输入文件的 .text 段放进来
- `*(.text.*)` — 把所有 .text.* 的段也放进来（如 .text.hot, .text.unlikely）

这里的 `*` 是通配符，匹配所有输入文件。

### .rodata 段（只读数据）

```ld
.rodata : {
    *(.rodata)
    *(.rodata.*)
}
```

存放常量、字符串字面量等只读数据。

```c
// 这些会放在 .rodata
const char *msg = "Hello";
const int config = 42;
```

### .data 段（已初始化数据）

```ld
.data : {
    *(.data)
    *(.data.*)
}
```

存放已初始化的全局变量和静态变量。

```c
// 这些会放在 .data
int count = 0;
char buffer[1024] = {1, 2, 3};
```

### .bss 段（未初始化数据）

```ld
.bss : {
    __bss_start = .;
    *(.bss)
    *(.bss.*)
    *(COMMON)
    __bss_end = .;
}
```

**这部分很重要**。

BSS 存放未初始化的全局变量和静态变量。**BSS 不占文件空间**，因为链接器只记录大小，不记录内容（反正都是 0）。

```c
// 这些会放在 .bss
int uninitialized_var;
char buffer[4096];
static int state;
```

**符号导出**：

```ld
__bss_start = .;
...  /* BSS 内容 */
__bss_end = .;
```

`__bss_start` 和 `__bss_end` 是两个符号，记录 BSS 段的起止地址。汇编代码用它们来清零 BSS：

```nasm
mov rdi, __bss_start
mov rcx, __bss_end
sub rcx, rdi    ; BSS 大小
...             ; 清零
```

### /DISCARD/ 段

```ld
/DISCARD/ : {
    *(.comment)
    *(.eh_frame)
    *(.note.gnu.build-id)
}
```

告诉链接器：**这些段直接扔掉，不要放进输出文件**。

- `.comment` — 编译器版本信息
- `.eh_frame` — 异常处理帧（我们不需要异常）
- `.note.gnu.build-id` — 构建 ID（调试用，不需要）

## 内存布局图解

让我们看看最终的内存布局：

```
地址范围          内容              说明
────────────────────────────────────────────────
0x7C00           Bootloader        BIOS 加载到这里
0x7E00           -                 512 字节

0x10000          内核 .text        代码段
0x1xxxx          内核 .rodata      只读数据
0x1xxxx          内核 .data        已初始化数据
0x1xxxx          内核 .bss         未初始化数据
约 0x7FFFF       内核结束

0x80000          栈顶              向下增长
0xB8000          VGA 缓冲区        文本模式显示
```

**内核大小约 448KB**（0x10000 到 0x7FFFF），栈在内核后面，从 0x80000 向下增长。

## 验证工具

链接脚本写对了没有？用工具验证一下。

### objdump - 查看段信息

```bash
objdump -h build/kernel.elf
```

**你会看到类似这样的输出**：

```
Sections:
Idx Name          Size      VMA       LMA       File off  Algn
  0 .text         00000120  00010000  00010000  00000100  2**4
  1 .rodata       00000000  00010120  00010120  00000120  2**0
  2 .data         00000000  00010120  00010120  00000120  2**0
  3 .bss          00000004  00010120  00010120  00000120  2**2
```

**关键信息**：

- `VMA` (Virtual Memory Address) = 0x10000，正确！
- `LMA` (Load Memory Address) = 0x10000，正确！
- `.bss` 的 `File off` 和前面的段一样，说明不占文件空间

### readelf - 查看符号

```bash
nm build/kernel.elf | grep __bss
```

**你会看到**：

```
0000000000010120 B __bss_end
0000000000010120 A __bss_start
```

`B` 表示 BSS 段符号，`A` 表示绝对符号。

### readelf - 查看入口点

```bash
readelf -h build/kernel.elf | grep Entry
```

**你会看到**：

```
Entry point address: 0x10000
```

正确！入口点和链接脚本的 `ENTRY(kernel_start)` 一致。

## ⚠️ 注意

**这个错误你会遇到**：

```
ld: warning: cannot find entry symbol _start; defaulting to 0000000000010000
```

**原因**：链接器找不到 `kernel_start` 符号。

**检查**：
1. `kernel_entry.asm` 里有 `global kernel_start` 吗？
2. 链接命令包含 `kernel_entry.o` 吗？

**这个错误你也会遇到**：

```
kernel_entry.asm: undefined reference to `__bss_start'
```

**原因**：链接脚本没定义 `__bss_start` 符号。

**检查**：linker.ld 的 `.bss` 段里有 `__bss_start = .;` 吗？

---

## 地址一致性检查

有个地方很容易出错：**所有地方的地址必须一致**。

| 位置 | 地址 | 说明 |
|------|------|------|
| bootloader 加载地址 | 0x10000 | `mov ax, 0x1000` |
| 链接脚本加载地址 | 0x10000 | `. = 0x10000` |
| QEMU 内存布局 | 0x10000 | 内核应该在的地方 |

**任何一个地方不一致，程序就会跑飞**。

# 03 - 创建内核 C 代码入口

现在我们开始真正写代码了。这一篇我们会实现从汇编到 C 的过渡。

---

## 两阶段入口设计

你可能会问：**为什么不能直接从 C 开始？为什么要先写一段汇编？**

好问题。在调用 C 代码之前，我们需要准备好运行环境：

1. **设置栈指针 (RSP)** — C 函数调用需要栈来传递参数、保存局部变量
2. **清零 BSS 段** — C 标准要求未初始化的全局变量必须是 0
3. **关中断** — 初始化期间不想被中断打断

这些操作用汇编更直接、更可控。

### 启动流程图

```
┌─────────────────────────────────────────┐
│   Bootloader (跳转到 0x10000)           │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│   kernel_entry.asm (汇编入口)            │
│   ┌─────────────────────────────────┐   │
│   │ 1. 关中断 (cli)                 │   │
│   │ 2. 设置栈 (rsp = 0x80000)      │   │
│   │ 3. 清零 BSS                     │   │
│   │ 4. 调用 kernel_main()           │   │
│   └─────────────────────────────────┘   │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│   kernel_main.c (C 主函数)              │
│   ┌─────────────────────────────────┐   │
│   │ - VGA 输出 'C'                  │   │
│   │ - 初始化代码                    │   │
│   │ - 主循环                        │   │
│   └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

## 编写 kernel_entry.asm

我们先来看完整的汇编入口代码（关键部分）：

```nasm
; CCOS Kernel Entry Point
section .text
    bits 64

; External C function
extern kernel_main

; Kernel entry point - bootloader jumps here
global kernel_start
kernel_start:
    ; Disable interrupts for setup
    cli

    ; Set up stack - grow down from 0x80000
    mov rsp, 0x80000 - 8
    and rsp, -16           ; Align to 16-byte boundary
    mov rbp, rsp

    ; Clear BSS section
    extern __bss_start
    extern __bss_end
    cld
    mov rdi, __bss_start
    mov rcx, __bss_end
    sub rcx, rdi
    shr rcx, 3  ; Convert to qwords
    xor eax, eax
    rep stosq

    ; Optional: Write 'X' to VGA to prove we got here
    mov rdi, 0xB8000 + 160 * 5  ; Line 5
    mov word [rdi], 0x1F58  ; 'X' in white on blue

    ; Jump to C kernel main
    call kernel_main

    ; If kernel_main returns, halt
halt_loop:
    cli
    hlt
    jmp halt_loop
```

**代码逐段解释**：

### 1. 声明外部符号

```nasm
extern kernel_main    ; C 函数，稍后实现
extern __bss_start    ; 链接脚本提供的符号
extern __bss_end
```

`extern` 告诉汇编器："这个符号在别的地方定义，链接时会找到"。

### 2. 关中断

```nasm
cli    ; Clear Interrupts
```

关中断是为了在初始化期间不被打断。初始化完成后，C 代码里可以再开中断。

### 3. 设置栈

```nasm
mov rsp, 0x80000 - 8
and rsp, -16
mov rbp, rsp
```

**为什么是 0x80000？**

- 我们的内核加载在 0x10000
- 内核大小约 448KB（0x10000 到 0x7FFFF）
- 栈放在内核后面，从 0x80000 向下增长

**为什么减 8 再对齐？**

因为 bootloader 用 `call rdi` 跳转过来，已经在栈上压了 8 字节的返回地址。我们需要调整 RSP，使得调用 `kernel_main` 时栈是 16 字节对齐的（SSE/AVX 指令的要求）。

`and rsp, -16` 是一个常用的技巧：`-16` 的二进制是 `...11110000`，按位与就清除了低 4 位，实现 16 字节对齐。

### 4. 清零 BSS

```nasm
cld                     ; Clear Direction Flag
mov rdi, __bss_start    ; 目标地址
mov rcx, __bss_end
sub rcx, rdi            ; 计算大小
shr rcx, 3              ; 转换为 qwords
xor eax, eax            ; eax = 0
rep stosq               ; 填充 0
```

**这段代码做了什么？**

- `stosq` 把 `rax` 的值存到 `[rdi]`，然后 `rdi += 8`
- `rep` 重复 `rcx` 次
- 结果就是从 `__bss_start` 到 `__bss_end` 的内存全部填 0

### 5. 调用 C 函数

```nasm
call kernel_main
```

就这么简单！C 函数的返回值在 `rax` 里，但我们暂时不需要。

## 编写第一个 kernel_main.c

现在来看 C 入口：

```c
// CCOS Kernel Main Entry
// C code entry point called from kernel_entry.asm

void kernel_main(void) {
    // VGA buffer at 0xB8000
    volatile uint16_t *vga = (uint16_t *)0xB8000;

    // Write 'C' to line 6 (to prove C code ran)
    vga[160 * 6] = 0x1F43;  // 'C' in white on blue

    // Halt loop
    while (1) {
        __asm__ volatile("hlt");
    }
}
```

**代码解释**：

### 1. VGA 地址

```c
volatile uint16_t *vga = (uint16_t *)0xB8000;
```

VGA 文本缓冲区在物理地址 0xB8000。每个字符占 2 字节：
- 低字节：ASCII 码
- 高字节：颜色属性

**为什么用 `volatile`？**

告诉编译器："这个内存访问有副作用，别给我优化掉"。如果没有 `volatile`，编译器可能认为这段代码没用，直接删掉。

### 2. 颜色属性

```c
vga[160 * 6] = 0x1F43;
```

- `0x1F`：高字节，颜色属性（白色前景，蓝色背景）
- `0x43`：低字节，字母 'C' 的 ASCII 码

**VGA 颜色速查**：

| 前景色 | 值 | 背景色 | 值 |
|--------|-----|--------|-----|
| 黑 | 0 | 黑 | 0 |
| 蓝 | 1 | 蓝 | 16 |
| 绿 | 2 | 绿 | 32 |
| 青 | 3 | 青 | 48 |
| 红 | 4 | 红 | 64 |
| 紫 | 5 | 紫 | 80 |
| 棕 | 6 | 棕 | 96 |
| 白 | 7 | 白 | 112 |

`0x1F = 15 (白前景) + 16 (蓝背景) = 31`

### 3. Halt 循环

```c
while (1) {
    __asm__ volatile("hlt");
}
```

`hlt` 指令让 CPU 停机，等待中断。比 `jmp $` 更省电。

## 验证方法：两个字母

我们用两个字母来验证执行流程：

1. 汇编代码在第 5 行输出 'X'
2. C 代码在第 6 行输出 'C'

**预期结果**：

```
屏幕上应该看到：
第 5 行：X
第 6 行：C
```

**如果只看到 X** — C 代码没执行，检查链接

**如果两个都没看到** — 汇编入口没执行，检查 bootloader

## 编译与链接

现在我们把编译流程说清楚。

### 第一步：编译汇编

```bash
nasm -f elf64 kernel_entry.asm -o kernel_entry.o
```

`-f elf64` 生成 64 位 ELF 格式的目标文件。

### 第二步：编译 C

```bash
gcc -c kernel_main.c -o kernel_main.o \
    -ffreestanding \
    -fno-builtin \
    -nostdlib \
    -mcmodel=large
```

这些选项我们下一篇会详细解释。先记住：**没有标准库，一切都是我们自己提供的**。

### 第三步：链接

```bash
ld -m elf_x86_64 \
    -T linker.ld \
    -nostdlib \
    -o kernel.elf \
    kernel_entry.o \
    kernel_main.o
```

`-T linker.ld` 指定链接脚本，下一篇会讲。

### 第四步：提取二进制

```bash
objcopy -O binary kernel.elf kernel.bin
```

ELF 包含符号信息（调试用），但我们只需要纯二进制代码给 bootloader 加载。

---

## ⚠️ 注意

**这个错误你会遇到：**

```
kernel_entry.asm: undefined reference to `kernel_main'
```

**原因**：C 代码编译失败，或者链接时没包含 C 的 .o 文件。

**解决**：确认 `kernel_main.o` 存在，并且链接命令包含它。

---

## 完整验证命令

```bash
# 编译
nasm -f elf64 kernel_entry.asm -o kernel_entry.o
gcc -c kernel_main.c -o kernel_main.o -ffreestanding -nostdlib
ld -m elf_x86_64 -T linker.ld -o kernel.elf kernel_entry.o kernel_main.o
objcopy -O binary kernel.elf kernel.bin

# 检查符号
nm kernel.elf | grep kernel_main
# 应该看到： T kernel_main

# 检查入口点
readelf -h kernel.elf | grep Entry
# 应该看到：Entry point address: 0x10000
```

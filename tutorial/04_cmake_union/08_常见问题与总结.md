## 常见错误速查表

### 链接错误

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `undefined reference to 'kernel_main'` | C 代码没链接或没编译 | 检查链接命令是否包含 `kernel_main.o` |
| `undefined reference to '__bss_start'` | 链接脚本没定义符号 | 检查 `linker.ld` 的 `.bss` 段 |
| `undefined reference to 'memcpy'` | 用了 memcpy 但没实现 | 加 `-fno-builtin` 或实现 memcpy |
| `relocation truncated to fit` | 代码模型不对 | 加 `-mcmodel=large` |

### 编译错误

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `error: stdio.h: No such file` | 包含了标准头文件 | 移除 `#include <stdio.h>` 等 |
| `warning: implicit declaration of function` | 函数没声明 | 添加函数声明或自己实现 |
| `error: expected expression before 'volatile'` | volatile 位置不对 | `volatile` 在类型后面：`volatile int *p` |
| `error: conflicting types for 'size_t'` | 类型重复定义 | 检查是否同时包含多个 types.h |

### 运行时错误

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| Triple Fault（QEMU 立即退出） | 栈指针错误或栈溢出 | 检查 RSP 初始化，确保 16 字节对齐 |
| 只看到 'X' 不看到 'C' | C 代码没执行 | 检查 `kernel_main` 符号和链接 |
| 屏幕全黑 | bootloader 或入口点错误 | 检查 bootloader 和链接地址 |
| 'A' 显示（assert 失败） | 断言触发 | 用 GDB 查看哪个断言失败 |

## 完整验证清单

在确认迁移成功前，逐项检查：

### 1. 构建系统

- [ ] `cmake -B build` 配置成功
- [ ] `cmake --build build` 编译成功
- [ ] `build/kernel.elf` 存在
- [ ] `build/kernel.bin` 存在
- [ ] `build/boot.img` 存在

### 2. 符号和入口

- [ ] `nm build/kernel.elf | grep kernel_start` 显示 `T kernel_start`
- [ ] `nm build/kernel.elf | grep kernel_main` 显示 `T kernel_main`
- [ ] `readelf -h build/kernel.elf | grep Entry` 显示 `0x10000`

### 3. 内存布局

- [ ] `objdump -h build/kernel.elf` 显示 `.text` 在 `0x10000`
- [ ] `objdump -h build/kernel.elf` 显示 `.bss` 类型为 `BSS`
- [ ] `nm build/kernel.elf | grep __bss` 显示 `__bss_start` 和 `__bss_end`

### 4. 运行验证

- [ ] QEMU 启动正常（`qemu-system-x86_64 -drive format=raw,file=build/boot.img`）
- [ ] VGA 显示 'X'（汇编执行成功）
- [ ] VGA 显示 'C'（C 代码执行成功）
- [ ] 没有 Triple Fault

### 5. 调试验证

- [ ] `gdb build/kernel.elf` 能打开 ELF
- [ ] `target remote :1234` 能连接 QEMU
- [ ] `break kernel_main` 能设置断点
- [ ] `continue` 能运行到断点
- [ ] `print` 命令能查看变量

## 经验总结

### 做对的事情

1. **渐进式迁移** — 先迁移构建系统，再迁移代码
2. **保留 ELF 文件** — `.elf` 用于调试，`.bin` 用于加载
3. **模块化设计** — 每个子目录有自己的 CMakeLists.txt
4. **验证每个步骤** — 不要等到最后才发现问题

### 容易踩的坑

1. **地址不一致** — bootloader 加载地址、链接脚本地址、QEMU 内存布局必须一致
2. **栈对齐** — SSE/AVX 要求 16 字节对齐，不对齐会 GPF
3. **符号可见性** — 汇编和 C 之间共享的符号要用 `global`/`extern`
4. **BSS 清零** — 链接脚本要导出 `__bss_start` 和 `__bss_end`
5. **CMake 缓存** — 改了参数不生效，记得删缓存

### 调试技巧

1. **先用 objdump 看汇编** — 确认代码看起来合理
2. **用 nm 看符号** — 确认符号都存在且类型正确
3. **用 readelf 看布局** — 确认段地址正确
4. **用 GDB 单步调试** — 确认执行流程符合预期
5. **用 VGA 输出调试** — 在关键位置输出字符

## 迁移前后对比

### Makefile (stage/03)

```makefile
AS = nasm
ASFLAGS = -f bin
BOOTLOADER = boot/bootloader.asm
KERNEL = kernel/kernel.asm

all:
    $(AS) $(ASFLAGS) $(BOOTLOADER) -o build/bootloader.bin
    $(AS) $(ASFLAGS) $(KERNEL) -o build/kernel.bin
    dd if=build/bootloader.bin of=build/boot.img bs=512 count=1
    dd if=build/kernel.bin of=build/boot.img bs=512 seek=1

run:
    qemu-system-x86_64 -drive format=raw,file=build/boot.img
```

**优点**：简单、直观
**缺点**：不支持 Debug/Release、没有工具检测、难以扩展

### CMake (stage/04)

```cmake
cmake_minimum_required(VERSION 3.20)
project(CCOS_x64 ASM C)

find_program(NASM nasm REQUIRED)
find_program(QEMU qemu-system-x86_64 REQUIRED)

add_compile_options(
    $<$<COMPILE_LANGUAGE:C>:-Wall -Werror -std=c23>
)

add_subdirectory(boot)
add_subdirectory(kernel)

add_custom_target(run COMMAND ${QEMU} ...)
add_custom_target(debug COMMAND ${QEMU} ... -s -S)
```

**优点**：模块化、工具检测、多配置、IDE 友好
**缺点**：配置更复杂、学习曲线

## 最后的话

说实话，从 Makefile 迁移到 CMake 是个挺折腾的过程。但一旦完成，你会发现：

1. **调试更方便** — ELF + GDB 源码级调试
2. **开发更高效** — IDE 自动补全、跳转
3. **扩展更容易** — 添加新文件不需要改构建脚本
4. **配置更灵活** — Debug/Release 一键切换

**真正的大坑在后面** — 当我们开始添加中断、内存管理、多任务的时候，你会发现这些基础工作有多么重要。

所以，花时间把基础打牢，后面会轻松很多。

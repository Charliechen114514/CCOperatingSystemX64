# 类型定义与基础库

没有标准库，连个 `uint8_t` 都没有。说实话，第一次意识到这个问题的时候，我感觉好像被剥夺了所有的工具，赤手空拳地面对硬件。但这篇之后，你会发现，自己定义这些东西其实不难，而且你会对 C 语言有更深的理解。

---

## 为什么需要自己定义类型

在 Freestanding 环境下，我们没有 `<stdint.h>`、`<stddef.h>`、`<string.h>` 这些标准头文件。**但我们的代码需要这些类型和函数**：

```c
uint8_t byte = 0xFF;
uint64_t address = 0x10000;
size_t len = 1024;
NULL  // 空指针
memcpy(dest, src, n);
strlen(str);
```

如果你试着直接用这些，GCC 会报错 `undefined reference` 或 `implicit declaration`。怎么办？**自己定义！**

这不只是权宜之计。自己定义的好处是：你知道每一行做了什么，不会有"魔法"代码。标准库的实现可能很复杂、很通用，但我们只需要最基本的功能。而且理解了这些底层实现，你写代码时会更有把握。

---

## LP64 数据模型

x86_64 Linux 使用 LP64 数据模型。这个术语听起来很专业，但含义很简单：

| 类型 | 位数 | 说明 |
|------|------|------|
| `char` | 8 | 字符 |
| `short` | 16 | 短整数 |
| `int` | 32 | 整数 |
| `long` | 64 | 长整数 |
| `long long` | 64 | 超长整数 |
| `void*` | 64 | 指针 |
| `size_t` | 64 | 大小类型 |

**LP = Long and Pointer are 64-bit**

这意味着：`long` 和 `指针` 是 64 位的，其他类型可能不是。比如 `int` 是 32 位的，不管在 32 位还是 64 位系统上。

所以我们可以用 C 内置类型来定义固定宽度类型：

```c
typedef unsigned char      uint8_t;   // 8 位
typedef unsigned short     uint16_t;  // 16 位
typedef unsigned int       uint32_t;  // 32 位
typedef unsigned long long uint64_t;  // 64 位
```

**为什么用 `unsigned long long` 而不是 `unsigned long`？**

在 x86_64 上，`long` 和 `long long` 都是 64 位，所以两种都可以。但用 `long long` 更明确，因为 `long` 在某些平台上可能只有 32 位（比如 Windows）。用 `long long` 可以保证是 64 位。

## types.h 实现

现在我们来看完整的 `types.h` 实现。不要被代码长度吓到，我们一段一段来拆解。

```c
#ifndef CCOS_TYPES_H
#define CCOS_TYPES_H

/* Fixed-width integer types */
typedef unsigned char      uint8_t;
typedef unsigned short     uint16_t;
typedef unsigned int       uint32_t;
typedef unsigned long long uint64_t;

typedef signed char        int8_t;
typedef signed short       int16_t;
typedef signed int         int32_t;
typedef signed long long   int64_t;

/* Size type */
typedef unsigned long      size_t;
typedef signed long        ssize_t;

/* Boolean type */
typedef enum {
    false = 0,
    true  = 1
} bool;

/* NULL pointer constant */
#define NULL ((void*)0)

/* Offset type */
typedef signed long        ptrdiff_t;

/* Byte count */
typedef unsigned long      uintptr_t;

#endif /* CCOS_TYPES_H */
```

### 固定宽度整数类型

```c
typedef unsigned char      uint8_t;   // 0 ~ 255
typedef unsigned short     uint16_t;  // 0 ~ 65535
typedef unsigned int       uint32_t;  // 0 ~ 4294967295
typedef unsigned long long uint64_t;  // 0 ~ 18446744073709551615
```

这些类型定义确保了不管在什么平台上，`uint8_t` 始终是 8 位，`uint16_t` 始终是 16 位，等等。这对于内核开发非常重要，因为内核需要精确控制内存布局。

### 大小类型

```c
typedef unsigned long      size_t;
typedef signed long        ssize_t;
```

`size_t` 用于表示大小、长度、索引，保证足够大能放下任何对象大小。在 x86_64 上，它是 64 位的，可以表示非常大的对象（理论上最大 2^64-1 字节，这比实际可寻址内存大得多）。

`ssize_t` 是带符号版本，用于可能返回错误码的函数。比如 `read()` 函数返回读取的字节数，如果出错返回 -1。这种情况下需要带符号类型。

### 布尔类型

```c
typedef enum {
    false = 0,
    true  = 1
} bool;
```

C99 有 `_Bool` 类型，但用 enum 更清晰。而且 `enum` 可以有明确的值，方便调试时显示。

### NULL 指针

```c
#define NULL ((void*)0)
```

标准库的 `<stddef.h>` 定义了 `NULL`，我们手动定义。用 `((void*)0)` 而不是 `0`，因为 `0` 是整数，`((void*)0)` 是指针。虽然 C 标准规定 `0` 可以用作空指针常量，但显式转换更清晰。

## 简单的内存和字符串操作

没有 `<string.h>`，但我们需要一些基本操作。我们来实现几个最常用的。

### memcpy 实现

```c
static inline void* memcpy(void* dest, const void* src, size_t n) {
    uint8_t* d = (uint8_t*)dest;
    const uint8_t* s = (const uint8_t*)src;

    while (n--) {
        *d++ = *s++;
    }

    return dest;
}
```

这个实现虽然简单，但功能完整。它逐字节复制数据，从 `src` 到 `dest`，复制 `n` 字节。

**`static inline` 的好处**：

- `static` — 内部链接，不与其他文件冲突。每个文件可以有自己的 `memcpy`，不会链接冲突。
- `inline` — 建议编译器内联，减少函数调用开销。对于小函数，内联比调用更快。

**潜在问题**：这个实现比较慢，每次只复制一个字节。对于大块内存，可以用更优化的算法（比如按字复制、对齐后用 SIMD）。但对于内核早期阶段，简单够用就行。

### memset 实现

```c
static inline void* memset(void* s, int c, size_t n) {
    uint8_t* p = (uint8_t*)s;

    while (n--) {
        *p++ = (uint8_t)c;
    }

    return s;
}
```

`memset` 把一段内存设置为某个值。注意 `c` 是 `int` 类型，但只取低 8 位。所以我们转换成 `uint8_t`。

这个函数很有用，比如清零 BSS 段（虽然我们在汇编里做了，但有时也需要手动清零）、初始化缓冲区等。

### strlen 实现

```c
static inline size_t strlen(const char* s) {
    const char* p = s;
    while (*p) p++;
    return p - s;
}
```

`strlen` 计算字符串长度（不包括结尾的 `\0`）。它用一个指针从头扫描到结尾，然后用指针相减得到长度。

**潜在问题**：如果字符串没有 `\0` 结尾，这个函数会一直扫描下去，可能访问非法内存。但在内核里，我们控制所有字符串，所以可以保证正确性。

### memcmp 实现

```c
static inline int memcmp(const void* s1, const void* s2, size_t n) {
    const uint8_t* p1 = (const uint8_t*)s1;
    const uint8_t* p2 = (const uint8_t*)s2;

    while (n--) {
        if (*p1 != *p2) return *p1 - *p2;
        p1++;
        p2++;
    }

    return 0;
}
```

`memcmp` 比较两段内存。返回值是第一个不同字节的差值（`*p1 - *p2`）。如果完全相同，返回 0。

这个实现虽然简单，但有个微妙之处：返回值是 `int`，但差值可能超过 `int` 范围。不过在 x86_64 上，`int` 是 32 位的，差值被截断后仍然保持符号正确性（正数还是正数，负数还是负数），所以比较结果还是对的。

## 调试辅助宏

没有 `<assert.h>`，我们实现自己的断言。断言在内核开发中非常重要，可以快速发现逻辑错误。

```c
/* Simple assert */
#define CCOS_ASSERT(cond) \
    do { \
        if (!(cond)) { \
            volatile uint16_t* vga = (volatile uint16_t*)0xB8000; \
            vga[0] = 0x1F41;  /* 'A' for Assert */ \
            while (1) { __asm__ volatile("hlt"); } \
        } \
    } while (0)
```

**使用**：

```c
int ptr = get_pointer();
CCOS_ASSERT(ptr != NULL);  // 失败时显示 'A' 并停机
```

**为什么用 `do { ... } while (0)`？**

这是宏定义的常见技巧。如果没有这个包裹，宏在使用时可能会有问题：

```c
if (condition)
    CCOS_ASSERT(x);
else
    do_something();
```

如果没有 `do-while`，展开后会变成：

```c
if (condition)
    if (!(x)) { ... }
    ;
else
    do_something();
```

`else` 会和 `if` 配对错误（和最近的 `if` 配对，而不是最外层的 `if`）。用 `do { ... } while (0)` 把宏体变成单个语句，避免这个问题。

## BSS 清零验证

我们来写个测试验证 BSS 清零。这很重要，因为如果 BSS 没清零，未初始化的变量会有随机值，导致不可预测的行为。

```c
/* 未初始化的全局变量（在 BSS） */
static int uninitialized_var;
static char buffer[16];

void test_bss(void) {
    /* 检查变量是否为 0 */
    int all_zero = 1;

    if (uninitialized_var != 0) {
        all_zero = 0;
    }

    for (int i = 0; i < 16; i++) {
        if (buffer[i] != 0) {
            all_zero = 0;
            break;
        }
    }

    /* VGA 显示结果 */
    volatile uint16_t* vga = (volatile uint16_t*)0xB8000;
    if (all_zero) {
        vga[0] = 0x1F4F;  /* 'O' for OK */
    } else {
        vga[0] = 0x1F45;  /* 'E' for Error */
    }
}
```

**预期结果**：

- BSS 清零成功 → 显示 'O'
- BSS 未清零 → 显示 'E'

你可以在 `kernel_main` 开始时调用这个测试，确认 BSS 清零正常。如果看到 'E'，说明汇编入口的清零代码有问题，或者链接脚本的 BSS 符号没正确导出。

## 类型定义的常见问题

### 问题 1：类型大小不确定

```c
// 错误！int 的大小不固定
typedef int int32_t;  // 在某些平台上 int 可能是 16 位

// 正确
typedef signed int int32_t;  // 但这仍然依赖平台
```

**更好的做法**：用 `_Static_assert`（C11 特性）验证类型大小：

```c
_Static_assert(sizeof(int) == 4, "int must be 32-bit");
_Static_assert(sizeof(long) == 8, "long must be 64-bit");
```

这样如果类型大小不对，编译时会报错，而不是运行时出现奇怪的问题。

### 问题 2：对齐问题

某些结构体需要特定对齐，否则访问效率低或者 SSE 指令会出错：

```c
/* 强制 16 字节对齐 */
struct __attribute__((aligned(16))) align_struct {
    uint64_t a;
    uint64_t b;
};
```

`__attribute__((aligned(16)))` 告诉 GCC：这个结构体要 16 字节对齐。这样访问更快，而且可以用 SSE 指令一次读取两个 `uint64_t`。

### 问题 3：volatile 使用不当

```c
volatile int* ptr = (volatile int*)0x1000;
*ptr = 42;       // 正确，写入 volatile 内存
int x = *ptr;    // 正确，读取 volatile 内存

/* 但这样不行 */
int y = *ptr + *ptr;  // 可能读两次，值可能变化！
```

第二次读取 `*ptr` 时，值可能已经变了（比如硬件寄存器）。如果要避免这个问题，应该先读取到临时变量：

```c
int temp = *ptr;
int y = temp + temp;
```

## ⚠️ 目录组织

类型定义放在哪里？这看似简单，但组织不好会很混乱。

建议创建 `kernel/defines/` 目录，把 `types.h` 放进去。然后在需要的地方：

```c
#include "defines/types.h"
```

**不要用系统的 `<stdint.h>`**：

```c
// ❌ 错误！这会包含系统头文件
#include <stdint.h>

// ✅ 正确！用自己的定义
#include "defines/types.h"
```

为什么不能用系统头文件？因为系统头文件是为 hosted 环境设计的，可能包含我们不想要的东西。而且用系统头文件会失去对定义的控制，出问题很难排查。

## 实战示例：完整的小型库

我们来看一个完整的基础库文件，把这些都整合起来：

```c
#ifndef CCOS_MINILIB_H
#define CCOS_MINILIB_H

#include "defines/types.h"

/* Memory operations */
static inline void* memcpy(void* dest, const void* src, size_t n) {
    uint8_t* d = (uint8_t*)dest;
    const uint8_t* s = (const uint8_t*)src;
    while (n--) *d++ = *s++;
    return dest;
}

static inline void* memset(void* s, int c, size_t n) {
    uint8_t* p = (uint8_t*)s;
    while (n--) *p++ = (uint8_t)c;
    return s;
}

static inline int memcmp(const void* s1, const void* s2, size_t n) {
    const uint8_t* p1 = (const uint8_t*)s1;
    const uint8_t* p2 = (const uint8_t*)s2;
    while (n--) {
        if (*p1 != *p2) return *p1 - *p2;
        p1++; p2++;
    }
    return 0;
}

/* String operations */
static inline size_t strlen(const char* s) {
    const char* p = s;
    while (*p) p++;
    return p - s;
}

static inline char* strcpy(char* dest, const char* src) {
    char* d = dest;
    while ((*d++ = *src++));
    return dest;
}

/* Utility */
#define CCOS_MIN(a, b) ((a) < (b) ? (a) : (b))
#define CCOS_MAX(a, b) ((a) > (b) ? (a) : (b))
#define CCOS_ARRAY_SIZE(arr) (sizeof(arr) / sizeof((arr)[0]))

#endif /* CCOS_MINILIB_H */
```

这个文件包含了最常用的内存和字符串操作。`CCOS_MIN` 和 `CCOS_MAX` 是最小值和最大值宏，`CCOS_ARRAY_SIZE` 计算数组元素个数（比硬编码更安全）。

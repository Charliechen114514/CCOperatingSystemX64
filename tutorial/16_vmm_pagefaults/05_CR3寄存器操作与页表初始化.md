# 05 - CR3 寄存器操作与页表初始化

说实话，第一次读取 CR3 寄存器时，我盯着那个十六进制数值看了好久，心里想的居然是"这就完了？"

---

## CR3 寄存器的作用

CR3 寄存器（也叫做页目录基址寄存器，Page Directory Base Register）是 x86_64 中最重要的控制寄存器之一。它存储的是当前 PML4 表的物理地址。

当你访问一个虚拟地址时，CPU 的第一步就是从 CR3 读取 PML4 地址，然后开始四级页表查找。可以说，CR3 是整个虚拟内存机制的入口点。

### CR3 的格式

```
┌────────────────────────────────────────────────────────────────┐
│                        CR3 寄存器格式                          │
├────────────────────────────────┬───────────────────────────────┤
│         PML4 物理地址          │        标志位                │
│        位 51-12                │        位 11-0                │
└────────────────────────────────┴───────────────────────────────┘
```

- 位 51-12：PML4 表的物理地址（40位，支持 1TB 物理内存）
- 位 11-5：保留位，必须为 0
- 位 4-3：PCD/PWT，缓存控制
- 位 2：保留位，必须为 0
- 位 1-0：标志位

⚠️ 注意：PML4 地址必须 4KB 对齐，这意味着低 12 位必须为 0。这是硬件的要求，无法绕过。

---

## 读取 CR3 寄存器

在 C 代码中，我们需要使用内联汇编来读取 CR3 寄存器：

```c
static inline uint64_t page_get_cr3(void) {
    uint64_t cr3;
    __asm__ volatile("movq %%cr3, %0" : "=r"(cr3));
    return cr3;
}
```

这个函数我们在上一个文档中已经见过。它使用 `movq` 指令把 CR3 寄存器的值移动到一个通用寄存器中，然后返回这个值。

### 清除低 12 位

当我们读取 CR3 后，通常需要清除低 12 位来获取纯净的 PML4 物理地址：

```c
s_kernel_pml4 = page_get_cr3() & ~0xFFFULL;
```

`0xFFFULL` 是一个 12 位的掩码（二进制是 111111111111），`~0xFFFULL` 把它取反变成高 52 位为 1、低 12 位为 0。用这个掩码与 CR3 值做与运算，就清除了低 12 位的标志位。

⚠️ 注意：虽然 PML4 地址本身已经保证低 12 位为 0，但 CR3 的低 12 位可能包含标志位。为了安全起见，我们总是清除这些位。

---

## 设置 CR3 寄存器

修改页表后，我们需要重新加载 CR3 来刷新 TLB：

```c
static inline void page_set_cr3(uint64_t cr3) {
    __asm__ volatile("movq %0, %%cr3" : : "r"(cr3) : "memory");
}
```

这个函数把新的 CR3 值写入 CR3 寄存器。这会刷新 TLB 中所有的非全局页表项。

### `"memory"` clobber 的作用

你可能注意到了这个函数最后的 `"memory"` clobber。这告诉编译器：这个操作会影响内存（因为刷新了 TLB），编译器不能假设之前缓存在寄存器中的内存值仍然有效。

如果你不加这个 clobber，编译器可能会优化掉一些必要的内存访问，导致难以调试的 bug。

## page_init 的实现

`page_init` 函数是页表管理模块的入口点，它负责初始化内部状态并建立直接物理映射。

### 内部状态变量

```c
static physical_addr_t s_kernel_pml4 = 0;
static bool s_initialized = false;
static bool s_direct_map_established = false;
```

这些静态变量存储页表管理模块的内部状态：

- `s_kernel_pml4`：内核 PML4 表的物理地址
- `s_initialized`：模块是否已初始化
- `s_direct_map_established`：直接映射是否已建立

⚠️ 注意：这些变量使用 `static` 修饰，意味着它们只在 `page.c` 内部可见。这是良好的封装实践。

### page_init 的流程

```c
page_result_t page_init(void) {
    if (s_initialized) {
        klog_warn("[PAGE] Already initialized\n");
        return PAGE_OK;
    }

    /* Read the current PML4 from CR3 */
    s_kernel_pml4 = page_get_cr3() & ~0xFFFULL;

    klog_info("[PAGE] Initializing with PML4 at 0x%016llX\n", s_kernel_pml4);
    klog_info("[PAGE] Page size: %d bytes, %d entries per table\n",
              PAGE_SIZE, PT_ENTRIES);

    /* Establish direct physical mapping */
    page_result_t result = establish_direct_map();
    if (result != PAGE_OK) {
        klog_error("[PAGE] Failed to establish direct mapping!\n");
        return result;
    }

    s_initialized = true;
    klog_info("[PAGE] Initialization complete\n");

    return PAGE_OK;
}
```

这个函数的逻辑很清晰：

1. 检查是否已经初始化（防止重复初始化）
2. 从 CR3 读取 PML4 地址
3. 调用 `establish_direct_map` 建立直接映射
4. 标记模块已初始化

⚠️ 注意：`page_init` 必须在 `pframe_init` 之后调用，因为 `establish_direct_map` 需要使用物理帧分配器。

## 身份映射与直接映射的区别

在继续之前，我们需要理解两个概念：身份映射（Identity Mapping）和直接映射（Direct Mapping）。

### 身份映射（Identity Mapping）

身份映射是指虚拟地址等于物理地址的映射。比如，虚拟地址 0x1000 映射到物理地址 0x1000。

Bootloader 在启动时创建了低 2MB 的身份映射，这使得内核代码可以直接访问低 2MB 的物理内存。

```c
#define TEMP_IDENTITY_VIRT(phys)  ((void*)(uintptr_t)(phys))
```

这个宏把物理地址直接转换为虚拟地址指针，仅在身份映射有效时（低 2MB）可用。

⚠️ 注意：身份映射只在低 2MB 有效，不能用来访问其他物理内存。

### 直接映射（Direct Mapping）

直接映射是一种更通用的映射方式，它把整个物理地址空间映射到一个连续的虚拟地址区域。

在我们的内核中，直接映射区域的基地址是 `0xFFFF800000000000`。物理地址 `0x0` 映射到虚拟地址 `0xFFFF8000000000000`，物理地址 `0x1000` 映射到虚拟地址 `0xFFFF8000000001000`，以此类推。

```c
static inline void* phys_to_virt(physical_addr_t phys) {
    return (void*)(uintptr_t)(DIRECT_MAP_BASE + (uint64_t)phys);
}
```

⚠️ 注意：`phys_to_virt` 只能在直接映射建立之后使用。在 `establish_direct_map` 之前，你必须使用 `TEMP_IDENTITY_VIRT` 来访问低 2MB 的物理内存。

## establish_direct_map 的实现

Bootloader 只创建了低 2MB 的身份映射，这显然不够用。`establish_direct_map` 函数把这个映射扩展成一个完整的直接映射。

### Bootloader 的页表布局

在我们的 Bootloader 中，页表布局是这样的：

```
物理地址 0x9000: PML4 表
物理地址 0xA000: PDPT 表
物理地址 0xB000: PD 表（只有 PD[0] 映射了低 2MB）
```

PD[0] 是一个 2MB 的巨大页映射，覆盖物理地址 0x00000000 - 0x001FFFFF。

### 扩展 PD 表

我们的策略是扩展 PD 表，让它覆盖更多的物理内存：

```c
/* Get the bootloader's PD (at 0xB000) via identity mapping */
volatile pd_t* pd = (volatile pd_t*)TEMP_IDENTITY_VIRT(0xB000);

/* Map the first 512MB of physical memory using 2MB pages
 * We'll use PD entries 0-255 (256 entries * 2MB = 512MB)
 */
for (int i = 0; i < 256; i++) {
    if (!pd->entries[i].bits.present) {
        /* Map a 2MB page at physical address i * 2MB */
        physical_addr_t paddr = i * 0x200000;
        pd->entries[i].value = (paddr & PTE_ADDR_MASK) |
                               PAGE_PRESENT | PAGE_WRITE | PAGE_HUGE_PD;
    }
}
```

这段代码遍历 PD 表的前 256 个项，为每个项创建一个 2MB 巨大页映射。256 × 2MB = 512MB，这样我们就覆盖了前 512MB 的物理内存。

⚠️ 注意：我们使用 `PAGE_HUGE_PD` 标志（位 7）来表示这是一个 2MB 巨大页。这样 CPU 在查找页表时，会在 PD 级别停止，不会继续查找 PT。

### 设置 PML4[256]

直接映射区域对应的虚拟地址是 `0xFFFF800000000000`。这个地址的 PML4 索引是 256（因为 `(0xFFFF800000000000 >> 39) & 0x1FF = 256`）。

我们需要让 PML4[256] 指向 Bootloader 的 PDPT：

```c
/* Set PML4[256] to point to the bootloader's PDPT */
pml4->entries[256].value = (0xA000 & PTE_ADDR_MASK) | PAGE_PRESENT | PAGE_WRITE;
```

`0xA000` 是 Bootloader 的 PDPT 物理地址。`& PTE_ADDR_MASK` 清除低 12 位，确保地址 4KB 对齐。

### 刷新 TLB

修改页表后，我们必须刷新 TLB：

```c
/* Invalidate TLB to ensure the new mapping takes effect */
__asm__ volatile("mov %0, %%cr3" : : "r"((uint64_t)pml4_phys) : "memory");
```

重新加载 CR3 会刷新 TLB 中所有的非全局页表项，确保 CPU 使用新的页表。

⚠️ 注意：如果你忘记刷新 TLB，CPU 可能继续使用旧的映射结果，导致访问错误的内存地址。这是一个非常难以调试的 bug。

## 第一阶段验证

现在我们可以验证一下 `page_init` 是否正常工作。在 `kernel_init.c` 中添加以下代码：

```c
#include "mm/vmm/page.h"

void kernel_init(void) {
    /* ... 其他初始化代码 ... */

    /* Initialize page table management */
    page_result_t result = page_init();
    if (result != PAGE_OK) {
        klog_error("[KERNEL] Failed to initialize page tables!\n");
        return;
    }

    /* Get and print the PML4 address */
    physical_addr_t pml4 = page_get_pml4();
    klog_info("[KERNEL] Kernel PML4 at 0x%016llX\n", pml4);
}
```

编译并运行，你应该能看到类似的输出：

```
[PAGE] Initializing with PML4 at 0x0000000000009000
[PAGE] Page size: 4096 bytes, 512 entries per table
[PAGE] Direct mapping established at PML4[256]
[PAGE]   Virt base: 0xFFFF800000000000
[PAGE]   Phys range: 0x00000000 - 0x1FFFFFFF (512MB)
[PAGE] Initialization complete
[KERNEL] Kernel PML4 at 0x0000000000009000
```

## 常见问题

### 问题 1：系统崩溃，没有任何输出

这通常意味着你在直接映射建立之前就使用了 `phys_to_virt`。检查你的代码顺序，确保只有在 `s_direct_map_established = true` 之后才使用 `phys_to_virt`。

### 问题 2：输出乱码或者字符错位

这可能是 TLB 没有刷新导致的。在修改页表后，确保调用了 `page_invalidate_tlb` 或重新加载 CR3。

### 问题 3：PML4 地址不是预期的值

Bootloader 创建的 PML4 物理地址应该是 `0x9000`。如果你看到其他值，可能是 Bootloader 的代码有问题，或者 CR3 被其他代码修改了。

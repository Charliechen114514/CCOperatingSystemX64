# 03 - 页表项格式与标志位全解析

说实话，当我第一次看到页表项那 64 位标志位的定义时，我感觉自己像是在看天书。每一个标志位都有特定的作用，错一个都可能让系统崩溃。

---

## 页表项的 64 位布局

x86_64 的页表项是一个 64 位的数据结构。虽然叫"页表项"，但 PML4、PDPT、PD、PT 这四种级别的页表项格式是相同的。

```
┌────────────────────────────────────────────────────────────────┐
│                        64 位页表项                             │
├─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬──────────────────────────────────────┤
│││││││││││││         物理页号（40位）           │         │    │
│││││││││││││         位 51-12                  │ 位 63-52 │    │
└─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴──────────────────────────────────────┘
  ↑                         ↑                     ↑
  位 0                     位 12               位 52
```

低 12 位是标志位，位 12-51 是物理页号（40 位，支持 1TB 物理内存），位 52-62 是操作系统可用的位，位 63 是 NX（No-Execute）标志。

让我们逐个来看看这些标志位都是什么意思。

---

## 核心标志位（位 0-3）

### 位 0：Present（P）- 页是否在内存中

这是最重要的标志位。当 P=1 时，表示这个页表项是有效的，指向的物理页在内存中。当 P=0 时，表示这个页表项无效，访问对应的虚拟地址会触发页错误。

你可能会问：既然 P=0 表示无效，为什么还要有这个标志位？答案是按需分页（Demand Paging）。你可以在一开始就把虚拟地址空间映射好，但把所有页表项的 P 位设置为 0。当程序真正访问某块内存时，触发页错误，这时内核再分配物理内存并设置 P=1。

⚠️ 注意：如果你访问一个 P=0 的页表项，CPU 会触发页错误（#PF），而不是继续查找。这是硬件行为，无法绕过。

### 位 1：Read/Write（R/W）- 读写权限

当 R/W=1 时，这个页面是可写的。当 R/W=0 时，这个页面是只读的。试图写一个只读页面会触发页错误。

这个标志位是实现内存写保护的基础。你可以把代码段设置为只读，这样程序就无法意外修改自己的代码。你也可以让多个进程共享同一个只读页面（比如共享库），节省物理内存。

⚠️ 注意：这个标志位只在 CPL=3（用户态）时强制执行。内核态（CPL=0）可以写只读页面，除非设置了 CR0.WP 保护。

### 位 2：User/Supervisor（U/S）- 用户/内核权限

当 U/S=1 时，这个页面可以从用户态（CPL=3）访问。当 U/S=0 时，这个页面只能从内核态（CPL=0-2）访问。用户态程序访问内核页面会触发页错误。

这是实现用户空间和内核空间隔离的基础。所有内核相关的页面都应该设置 U/S=0，这样用户程序就无法访问内核内存。

⚠️ 注意：如果一个页表项的 U/S=0，但它的上级页表项的 U/S=1，用户程序仍然无法访问。权限检查是针对整个查找链的，任何一级不满足都会触发页错误。

### 位 3：Page-Level Write-Through（PWT）- 写通缓存

这个标志位控制页面使用的缓存策略。当 PWT=1 时，使用写通（Write-Through）策略；当 PWT=0 时，使用写回（Write-Back）策略。

写通意味着每次写入都立即更新到内存，写回意味着写入可以先缓存在 CPU 缓存中，稍后才刷新到内存。

坦白说，在内核开发的这个阶段，你不太需要关心这个标志位。写回策略性能更好，是大多数情况下的默认选择。只有在处理内存映射 I/O（MMIO）时，你才需要禁用缓存或使用写通策略。

---

## 缓存和访问标志位（位 4-6）

### 位 4：Page-Level Cache Disable（PCD）- 禁用缓存

当 PCD=1 时，这个页面的缓存被禁用。当 PCD=0 时，页面可以被缓存。

这个标志位在映射设备寄存器时非常重要。设备寄存器的读取可能有副作用，如果 CPU 缓存了寄存器的值，程序就无法看到设备状态的变化。

⚠️ 注意：映射 VGA 显存（0xB8000）或其他设备内存时，通常需要设置 PCD=1，否则你会看到缓存带来的奇怪问题。

### 位 5：Accessed（A）- 访问标志

这个标志位由硬件自动设置。当 CPU 访问一个页面时（无论是读还是写），硬件会把对应页表项的 A 位置为 1。

这个标志位可以用来实现页面替换算法：操作系统可以定期扫描页表，把那些 A=0 的页面（最近没有被访问）换出到磁盘。

⚠️ 注意：硬件只负责设置 A 位，不会清除它。如果你要使用这个标志位实现页面替换算法，需要由软件来定期清除 A 位。

### 位 6：Dirty（D）- 脏标志

这个标志位只在 PD 和 PT 项中有效，由硬件自动设置。当 CPU 写入一个页面时，硬件会把对应页表项的 D 位置为 1。

这个标志位可以用来优化页面换出：如果一个页面被修改过（D=1），换出到磁盘时需要写回；如果一个页面没有被修改过（D=0），可以直接丢弃，不需要写回。

⚠️ 注意：和 A 位一样，硬件只设置 D 位，不会清除它。清除 D 位是软件的责任。

---

## 页面大小和全局标志（位 7-8）

### 位 7：Page Size（PS）- 页面大小

这个标志位在 PD 和 PDPT 项中有不同的含义：

- 在 PD 项中：PS=1 表示这是一个 2MB 巨大页，不需要查找下一级 PT
- 在 PDPT 项中：PS=1 表示这是一个 1GB 巨大页，跳过 PD 和 PT

这是实现巨大页的关键。当你使用巨大页时，可以减少页表查找的次数和页表占用的内存。

⚠️ 注意：PS 位只在 PD 和 PDPT 项中有效。在 PML4 和 PT 项中，这个位是保留的，必须设置为 0。

### 位 8：Global（G）- 全局页

当 G=1 时，这个页面是全局的。在任务切换时（修改 CR3 寄存器），全局页的 TLB 条目不会被刷新。

这个标志位主要用于内核页面。内核页面在所有进程中都是相同的，不需要在任务切换时刷新 TLB。设置 G 位可以减少 TLB 刷新的开销，提高性能。

⚠️ 注意：G 位只有在 CR4.PGE（Page Global Enable）标志被设置时才有效。我们的内核会启用这个标志。

---

## 操作系统可用位（位 9-11）

位 9-11 是操作系统可以自由使用的位，硬件不会检查这些位。

这些位可以用来存储各种软件定义的信息。比如，你可以用其中一个位来表示这个页面是否被"锁定"在内存中（不允许换出），或者用来实现软件 dirty tracking。

在我们的实现中，目前不使用这些位，留着以后扩展用。

---

## 物理页号（位 12-51）

位 12-51 存储的是物理页号（Physical Frame Number），共 40 位，可以支持 1TB 的物理内存（2^40 × 4096）。

物理页号左移 12 位（乘以 4096）才是真正的物理地址。低 12 位总是 0，保证物理地址 4KB 对齐。

⚠️ 注意：虽然页表项是 64 位的，但当前 x86_64 实现只使用了位 12-51 来存储物理地址（40 位）。如果要支持更大的物理内存（比如 4PB），需要使用位 52-62 来存储额外的高位地址，但这需要启用特定的 CPU 特性。

---

## 软件可用位（位 52-62）

和位 9-11 一样，位 52-62 也是操作系统可以自由使用的位。这些位可以用来存储各种软件定义的信息。

在我们的实现中，目前不使用这些位。

---

## NX 位（位 63）- 禁止执行

### 位 63：No-Execute（NX）- 禁止执行

当 NX=1 时，这个页面不能执行指令。当 NX=0 时，页面可以执行指令。

这个标志位是实现 W^X（要么可写，要么可执行，但不能同时）安全策略的基础。你可以把数据段设置为可写但不可执行（NX=1），把代码段设置为可执行但只读（R/W=0, NX=0）。

⚠️ 注意：NX 位只在 CPU 支持 NX 比特特性时才有效（可以通过 CPUID 检查）。现代 x86_64 CPU 都支持这个特性。

⚠️ 注意：如果你试图从 NX=1 的页面取指令，CPU 会触发页错误。这是硬件强制执行的，无法绕过。

---

## 常见标志组合场景

让我们来看看几种常见的页表项标志组合：

### 内核可读写页面

```c
flags = PAGE_PRESENT | PAGE_WRITE | PAGE_GLOBAL
```

这是内核使用的普通页面的标志组合。页面存在、可写、全局（任务切换时不刷新 TLB）。

### 用户可读写页面

```c
flags = PAGE_PRESENT | PAGE_WRITE | PAGE_USER
```

这是用户程序的堆或数据段。页面存在、可写、用户可访问。

### 用户只读代码段

```c
flags = PAGE_PRESENT | PAGE_USER
```

注意这里没有设置 PAGE_WRITE，所以是只读的。可以防止程序意外修改自己的代码。

### 用户不可执行数据段（W^X）

```c
flags = PAGE_PRESENT | PAGE_WRITE | PAGE_USER | PAGE_NO_EXEC
```

这是一个可写但不可执行的用户页面。符合 W^X 安全策略：要么可写，要么可执行，不能同时。

### 只读内存映射 I/O

```c
flags = PAGE_PRESENT | PAGE_WRITE_THRU | PAGE_NO_CACHE
```

映射设备寄存器时使用。页面存在、写通缓存（或禁用缓存）、不设置用户位。

---

## C 语言的表示方法

在 C 代码中，我们通常用位运算来设置和检查这些标志位：

```c
// 定义标志位常量
#define PAGE_PRESENT     (1ULL << 0)
#define PAGE_WRITE       (1ULL << 1)
#define PAGE_USER        (1ULL << 2)
#define PAGE_NO_EXEC     (1ULL << 63)

// 设置标志位
uint64_t flags = PAGE_PRESENT | PAGE_WRITE;

// 检查标志位
if (entry & PAGE_PRESENT) {
    // 页面存在
}

// 清除标志位
entry &= ~PAGE_WRITE;  // 设置为只读
```

⚠️ 注意：NX 位在第 63 位，所以使用 `(1ULL << 63)` 而不是 `(1 << 63)`。如果你写成 `(1 << 63)`，在大多数系统上会导致未定义行为（因为 1 是 int 类型，左移 63 位超出了 int 的位数）。

---

## 联合体和位域的表示方法

为了方便访问页表项的各个字段，我们使用 C 语言的联合体和位域来定义页表项结构：

```c
typedef union {
    struct {
        uint64_t present      : 1;   // Bit 0
        uint64_t writable     : 1;   // Bit 1
        uint64_t user         : 1;   // Bit 2
        uint64_t pwt          : 1;   // Bit 3
        uint64_t pcd          : 1;   // Bit 4
        uint64_t accessed     : 1;   // Bit 5
        uint64_t dirty        : 1;   // Bit 6
        uint64_t pat          : 1;   // Bit 7
        uint64_t global       : 1;   // Bit 8
        uint64_t available    : 3;   // Bit 9-11
        uint64_t frame        : 40;  // Bit 12-51
        uint64_t available2   : 11;  // Bit 52-62
        uint64_t nx           : 1;   // Bit 63
    } bits;
    uint64_t value;
} page_table_entry_t;
```

这样你可以通过 `entry.bits.present` 来访问 Present 位，或者通过 `entry.value` 来访问整个 64 位值。

⚠️ 注意：位域的内存布局是由编译器实现的，不是 C 标准规定的。但在 x86_64 上，所有主流编译器（GCC、Clang、MSVC）对于这种结构的实现是一致的，都是从低位到高位排列。

# 07 - 页表查询与地址转换实现

说实话，实现映射函数只是完成了一半工作。很多时候，我们需要查询一个虚拟地址是否映射、映射到哪个物理地址、有什么权限……这时候就需要查询函数。

---

## 从 page_query 开始

`page_query` 函数用来查询一个虚拟地址的映射信息。它的签名很简单：

```c
page_result_t page_query(physical_addr_t pml4_phys,
                        virtual_addr_t vaddr,
                        page_query_result_t* result);
```

查询结果存储在 `page_query_result_t` 结构体中，这个结构包含了我们关心的所有信息：物理地址、页标志位、是否存在映射、是不是巨大页。

```c
typedef struct {
    physical_addr_t phys_addr;  /* Physical address of mapped page */
    uint64_t flags;             /* Page flags (combination of vmap_flags_t) */
    bool present;               /* Whether mapping exists */
    bool is_huge;               /* Whether this is a huge page (2MB/1GB) */
} page_query_result_t;
```

---

## 遍历四级页表

查询函数的流程和映射函数类似，都需要遍历四级页表。但查询函数更简单：它只读取页表项，不修改任何内容。我们先初始化结果结构体，设置默认值，这样如果查询失败（页面不存在），这些默认值就会被返回。

```c
/* Initialize result */
result->present = false;
result->is_huge = false;
result->phys_addr = 0;
result->flags = 0;
```

接下来我们逐级检查页表项的 Present 位。首先获取 PML4 表，找到对应的 PML4 项：

```c
/* Get PML4 */
pml4_t* pml4 = (pml4_t*)phys_to_virt(pml4_phys);
page_table_entry_t* pml4e = &pml4->entries[PML4_INDEX(vaddr)];

if (!pml4e->bits.present) {
    return PAGE_ERR_NOT_PRESENT;
}
```

如果 PML4 项不存在（Present 位为 0），我们立即返回 `PAGE_ERR_NOT_PRESENT`。注意这里查询函数不需要 `alloc_missing` 参数，因为它不会分配新的页表 —— 查询只是读取，不修改。

继续往下，获取 PDPT 表并检查对应项：

```c
/* Get PDPT */
pdpt_t* pdpt = (pdpt_t*)phys_to_virt(pml4e->bits.frame << PAGE_SHIFT);
page_table_entry_t* pdpte = &pdpt->entries[PDPT_INDEX(vaddr)];

if (!pdpte->bits.present) {
    return PAGE_ERR_NOT_PRESENT;
}
```

---

## 检测巨大页

现在我们到了有趣的部分：检测巨大页。在 `page_table_entry_t` 联合体中，位 7 的字段名是 `pat`。但对于 PDPT 项和 PD 项，这个位实际上存储的是 PS（Page Size）标志，而不是 PAT（Page-Attribute Table）。这是一个命名的妥协，因为 PD 和 PDPT 的位 7 有不同的含义。

如果 PDPT 项的 PS 位为 1，说明这是一个 1GB 巨大页。我们不需要继续查找 PD 和 PT，直接返回映射信息：

```c
/* Check for 1GB huge page */
if (pdpte->bits.pat) {  /* PS bit in PDPT */
    result->present = true;
    result->is_huge = true;
    result->phys_addr = pdpte->bits.frame << PAGE_SHIFT;
    result->flags = pdpte->value & 0xFFF;
    return PAGE_OK;
}
```

同样地，如果 PD 项的 PS 位为 1，说明这是一个 2MB 巨大页：

```c
/* Get PD */
pd_t* pd = (pd_t*)phys_to_virt(pdpte->bits.frame << PAGE_SHIFT);
page_table_entry_t* pde = &pd->entries[PD_INDEX(vaddr)];

if (!pde->bits.present) {
    return PAGE_ERR_NOT_PRESENT;
}

/* Check for 2MB huge page */
if (pde->bits.pat) {  /* PS bit in PD */
    result->present = true;
    result->is_huge = true;
    result->phys_addr = pde->bits.frame << PAGE_SHIFT;
    result->flags = pde->value & 0xFFF;
    return PAGE_OK;
}
```

如果 PD 项的 PS 位为 0，说明这是一个普通的 4KB 页面，我们继续查找 PT：

```c
/* Get PT */
pt_t* pt = (pt_t*)phys_to_virt(pde->bits.frame << PAGE_SHIFT);
page_table_entry_t* pte = &pt->entries[PT_INDEX(vaddr)];

if (!pte->bits.present) {
    return PAGE_ERR_NOT_PRESENT;
}

/* Return 4KB page mapping info */
result->present = true;
result->is_huge = false;
result->phys_addr = pte->bits.frame << PAGE_SHIFT;
result->flags = pte->value & 0xFFF;

return PAGE_OK;
```

## 取消映射与 TLB 刷新

取消映射函数 `page_unmap_page` 的流程和查询函数类似，但它在找到对应的页表项后，会清除该页表项。

```c
page_result_t page_unmap_page(physical_addr_t pml4_phys,
                             virtual_addr_t vaddr,
                             bool free_table) {
    /* ... 遍历四级页表 ... */

    /* Clear the PTE */
    pte->value = 0;

    /* Invalidate TLB */
    page_invalidate_tlb(vaddr);

    /* TODO: Free empty page tables if free_table is true */

    return PAGE_OK;
}
```

这里有个坑一定要踩过才知道：清除页表项后如果忘记刷新 TLB，CPU 会继续使用旧的映射结果，导致访问错误的物理地址。所以我们在清除 PTE 后立即调用 `page_invalidate_tlb`，确保 CPU 能看到最新的页表状态。`free_table` 参数用于控制是否释放空的页表，在当前实现中这个功能还没有实现，所以如果一个页表的所有项都被清除，这个页表仍然占用物理内存。

TLB（Translation Lookaside Buffer）是 CPU 中缓存虚拟地址到物理地址转换的硬件。`page_invalidate_tlb` 函数使用 `invlpg` 指令刷新单个地址的 TLB 条目：

```c
static inline void page_invalidate_tlb(virtual_addr_t vaddr) {
    __asm__ volatile("invlpg (%0)" : : "r"(vaddr) : "memory");
}
```

这个指令只刷新指定虚拟地址的 TLB 条目，其他地址的 TLB 条目保持不变。这是最高效的刷新方式，适合修改单个映射后使用。如果你修改了大量页表项，重新加载 CR3 寄存器会更高效，虽然它比 `invlpg` 慢一些，但当你需要刷新很多地址时，它可能比多次调用 `invlpg` 更快。

```c
__asm__ volatile("mov %0, %%cr3" : : "r"((uint64_t)pml4_phys) : "memory");
```

这里需要注意的是，全局页（设置了 `PAGE_GLOBAL` 标志的页）不会被 CR3 重新加载刷新，只有 `invlpg` 指令可以刷新全局页的 TLB 条目。如果你忘记刷新 TLB，CPU 可能继续使用旧的映射结果，这种 bug 非常难以调试，因为症状看起来是"随机"的 —— 有时候正常，有时候崩溃。

## 地址转换的便利函数

`page_virt_to_phys` 是一个便捷函数，它把虚拟地址转换成物理地址。这个函数调用 `page_query` 获取映射信息，然后把页内偏移加到物理地址上。

```c
page_result_t page_virt_to_phys(physical_addr_t pml4_phys,
                               virtual_addr_t vaddr,
                               physical_addr_t* out_phys) {
    CCOS_ASSERT(out_phys != NULL);

    page_query_result_t result;
    page_result_t res = page_query(pml4_phys, vaddr, &result);

    if (res == PAGE_OK && result.present) {
        *out_phys = result.phys_addr | (vaddr & (PAGE_SIZE - 1));
        return PAGE_OK;
    }

    return PAGE_ERR_NOT_PRESENT;
}
```

关键点在于页内偏移的处理。`page_query` 返回的是物理页的起始地址（页对齐的），我们需要把虚拟地址的页内偏移加到物理地址上：`vaddr & (PAGE_SIZE - 1)` 提取虚拟地址的低 12 位（页内偏移），然后把它或到物理页地址上。如果你只返回物理页地址而不加上页内偏移，地址转换就是错误的 —— 这是一个常见的错误。

## 范围映射辅助函数

`page_map_range` 函数用来映射连续的多个页面。这个函数循环调用 `page_map_page`，每次映射一个页面。如果某次映射失败，它会回滚之前已映射的页面。

```c
page_result_t page_map_range(physical_addr_t pml4_phys,
                            virtual_addr_t vaddr_base,
                            physical_addr_t paddr_base,
                            uint64_t page_count,
                            uint64_t flags) {
    CCOS_ASSERT(s_initialized);

    for (uint64_t i = 0; i < page_count; i++) {
        virtual_addr_t vaddr = vaddr_base + (i * PAGE_SIZE);
        physical_addr_t paddr = paddr_base + (i * PAGE_SIZE);

        page_result_t result = page_map_page(pml4_phys, vaddr, paddr, flags, true);
        if (result != PAGE_OK) {
            /* Rollback: unmap what we've mapped so far */
            page_unmap_range(pml4_phys, vaddr_base, i);
            return result;
        }
    }

    return PAGE_OK;
}
```

回滚机制非常重要。如果你在映射过程中失败，但不回滚之前的映射，可能会导致部分映射被遗留在页表中，引发难以调试的问题。

## 测试完整的映射-查询-取消映射流程

现在我们可以测试完整的映射、查询、取消映射流程：

```c
/* Test: Map, query, and unmap a page */
virtual_addr_t test_vaddr = 0xFFFFFFFF81000000;
physical_addr_t test_paddr;
pframe_alloc(&test_paddr);

/* Map */
page_result_t result = page_map_page(
    page_get_pml4(),
    test_vaddr,
    test_paddr,
    VMAP_FLAG_WRITE,
    true
);

if (result != PAGE_OK) {
    klog_error("[TEST] Failed to map page\n");
    return;
}

/* Query */
page_query_result_t query_result;
result = page_query(page_get_pml4(), test_vaddr, &query_result);

if (result == PAGE_OK && query_result.present) {
    klog_info("[TEST] Query successful:\n");
    klog_info("[TEST]   Physical: 0x%X\n", query_result.phys_addr);
    klog_info("[TEST]   Flags: 0x%llX\n", query_result.flags);
    klog_info("[TEST]   Is huge: %s\n", query_result.is_huge ? "yes" : "no");
}

/* Unmap */
result = page_unmap_page(page_get_pml4(), test_vaddr, false);

if (result == PAGE_OK) {
    klog_info("[TEST] Unmap successful\n");
}

/* Query again (should fail) */
result = page_query(page_get_pml4(), test_vaddr, &query_result);

if (result == PAGE_ERR_NOT_PRESENT) {
    klog_info("[TEST] Page no longer present (expected)\n");
}
```

## 调试时常见的几种情况

如果你发现查询返回成功但物理地址不对，这可能是页内偏移没有正确处理。检查 `page_virt_to_phys` 是否把页内偏移加到物理地址上。

如果取消映射后仍然能访问内存，这通常是因为 TLB 没有刷新。确保在取消映射后调用了 `page_invalidate_tlb`。

如果映射-查询-取消映射后，物理内存泄漏，当前实现没有释放空的页表，所以频繁映射和取消映射会导致物理内存泄漏。这是已知的限制，未来版本会改进。

# 13 - 页错误机制与错误码解析

说实话，第一次看到页错误（Page Fault）这个名词时，我以为是什么很可怕的东西。但实际上，页错误是虚拟内存管理中最常用的机制之一。

---

## 什么是页错误

页错误（Page Fault，#PF）是 x86_64 处理器在检测到内存访问违规时触发的异常，异常向量是 14。以下情况会触发页错误：页面不存在（访问的虚拟地址没有对应的物理页，页表项的 Present 位为 0），权限违规（试图写只读页面、试图执行不可执行页面、用户程序试图访问内核页面），保留位设置（页表项的保留位被设置为 1），或者取指令失败（试图从不可执行页面取指令）。

页错误不仅仅是错误处理机制，它还是实现高级内存管理功能的基础。按需分页（Demand Paging）利用页错误只在程序真正访问内存时才分配物理页，写时复制（Copy-on-Write）让多个进程共享只读页面，写入时才复制，内存映射文件则只在访问文件内容时才把文件内容加载到内存。

---

## 解析页错误码

当页错误发生时，CPU 会把一个错误码压入栈中。这个 32 位的错误码包含触发页错误的原因。我们定义了一组宏来检查错误码的各个位：

```c
#define PF_ERR_PRESENT   (1 << 0)  /* Bit 0: P=0 if page not present, P=1 if protection fault */
#define PF_ERR_WRITE     (1 << 1)  /* Bit 1: W=1 if write operation, W=0 if read */
#define PF_ERR_USER      (1 << 2)  /* Bit 2: U=1 if user mode, U=0 if supervisor mode */
#define PF_ERR_RESERVED  (1 << 3)  /* Bit 3: Reserved bit set in page table */
#define PF_ERR_INSTR     (1 << 4)  /* Bit 4: I=1 if instruction fetch, I=0 if data access */
```

`pf_parse_error_code` 函数把原始错误码解析成更易读的结构：

```c
void pf_parse_error_code(uint64_t error_code, page_fault_info_t* info) {
    info->error_code = error_code;
    info->present = (error_code & PF_ERR_PRESENT) != 0;
    info->write = (error_code & PF_ERR_WRITE) != 0;
    info->user = (error_code & PF_ERR_USER) != 0;
    info->reserved_bit = (error_code & PF_ERR_RESERVED) != 0;
    info->instruction_fetch = (error_code & PF_ERR_INSTR) != 0;
}
```

`page_fault_info_t` 结构存储解析后的信息，包括触发页错误的虚拟地址（从 CR2 寄存器读取）、原始错误码、各个标志位等。

```c
typedef struct {
    virtual_addr_t fault_addr;      /* CR2: Faulting virtual address */
    uint64_t error_code;            /* Raw error code from CPU */
    bool present;                   /* Was the page present? */
    bool write;                     /* Was it a write operation? */
    bool user;                      /* Did it occur in user mode? */
    bool reserved_bit;              /* Was a reserved bit set? */
    bool instruction_fetch;         /* Was it an instruction fetch? */
} page_fault_info_t;
```

---

## 读取 CR2 寄存器

当页错误发生时，CPU 把触发页错误的虚拟地址存储在 CR2 寄存器中。我们可以通过内联汇编读取 CR2：

```c
static inline virtual_addr_t pf_get_cr2(void) {
    virtual_addr_t cr2;
    __asm__ volatile("movq %%cr2, %0" : "=r"(cr2));
    return cr2;
}
```

CR2 只在页错误处理函数中有效。如果你在其他地方读取 CR2，值是无意义的。

---

## 实际调试中最常遇到的情况

实际调试中最常遇到的是这几种情况。第一种是访问未映射的页面，错误码为 0x00（P=0, R=0, U=0）。这种情况下页面不存在，处理方式是分配物理页并建立映射（Demand Paging）。

第二种是写只读页面，错误码为 0x02（P=1, W=1, U=0）。这是权限违规，试图写只读页面。在用户态会触发 SIGSEGV，在内核态会导致内核 panic。

第三种是用户程序访问内核页面，错误码为 0x06（P=1, W=0, U=1）。这也是权限违规，用户态访问内核页面，处理方式是触发 SIGSEGV。

第四种是保留位设置，错误码为 0x08（P=1, W=0, U=0, R=1）。这意味着页表项的保留位被设置，通常表示页表损坏，内核应该停止运行。

保留位设置通常意味着页表损坏，这是一个严重的问题，内核应该停止运行。

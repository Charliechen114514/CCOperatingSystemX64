# 08 - 扩展直接物理映射区域

说实话，第一次意识到 Bootloader 只映射了低 2MB 内存时，我有点懵。这意味着内核实际上只能访问前 2MB 的物理内存，这显然不够用。

---

## Bootloader 留下的映射

在之前的文档中我们讲过，Bootloader 创建了一个简单的页表结构，让内核能够启动。但这个映射非常有限：

```
物理地址 0x9000: PML4 表
物理地址 0xA000: PDPT 表
物理地址 0xB000: PD 表（只有 PD[0] 映射了低 2MB）
```

PD[0] 是一个 2MB 巨大页，覆盖物理地址 `0x00000000 - 0x001FFFFF`。这意味着内核代码可以访问低 2MB 的物理内存，可以访问自己的页表（因为它们都在低 2MB），但无法访问高于 2MB 的物理内存。

Bootloader 只需要加载内核并启动，不需要访问全部物理内存。创建一个完整的页表映射需要更多的页表内存和初始化代码，这在 Bootloader 阶段是不必要的。但对于内核来说，2MB 显然不够，物理帧管理器管理的内存可能远超 2MB，内核需要访问这些内存才能正常工作。

---

## 直接映射的概念

直接映射（Direct Mapping）是一种把整个物理地址空间映射到一个连续的虚拟地址区域的方法。在我们的内核中，直接映射区域的基地址是 `0xFFFF800000000000`。这个地址的特点是高 16 位全为 1（符合内核空间的规范地址要求），低 44 位足够覆盖我们需要的物理内存范围。

转换公式很简单：虚拟地址等于物理地址加上基地址，或者反过来，物理地址等于虚拟地址减去基地址。

```c
#define DIRECT_MAP_BASE  0xFFFF800000000000ULL

static inline void* phys_to_virt(physical_addr_t phys) {
    return (void*)(uintptr_t)(DIRECT_MAP_BASE + (uint64_t)phys);
}

static inline physical_addr_t virt_to_phys(virtual_addr_t virt) {
    return (physical_addr_t)(virt - DIRECT_MAP_BASE);
}
```

这里要特别小心，这些转换公式只在直接映射建立后有效。在 `establish_direct_map` 之前，你不能使用 `phys_to_virt`，否则会访问到无效内存。

---

## establish_direct_map 的实现

`establish_direct_map` 函数的任务是把低 2MB 的身份映射扩展成一个完整的直接映射，覆盖更多的物理内存。在直接映射建立之前，我们只能使用身份映射来访问页表：

```c
/* Use identity mapping to access PML4 (bootloader maps low 2MB) */
volatile pml4_t* pml4 = (volatile pml4_t*)TEMP_IDENTITY_VIRT(pml4_phys);

/* Get the bootloader's PD (at 0xB000) via identity mapping */
volatile pd_t* pd = (volatile pd_t*)TEMP_IDENTITY_VIRT(0xB000);
```

`TEMP_IDENTITY_VIRT` 是一个简单的宏，把物理地址直接转换为虚拟地址指针。身份映射只在低 2MB 有效，Bootloader 的页表都在低 2MB 范围内（0x9000、0xA000、0xB000），所以可以安全地使用身份映射访问。

```c
#define TEMP_IDENTITY_VIRT(phys)  ((void*)(uintptr_t)(phys))
```

接下来我们扩展 PD 表。Bootloader 的 PD 表只有一个有效项（PD[0]），映射了低 2MB。我们需要添加更多的项来映射更多的物理内存：

```c
/* Map the first 512MB of physical memory using 2MB pages
 * We'll use PD entries 0-255 (256 entries * 2MB = 512MB)
 */
for (int i = 0; i < 256; i++) {
    if (!pd->entries[i].bits.present) {
        /* Map a 2MB page at physical address i * 2MB */
        physical_addr_t paddr = i * 0x200000;
        pd->entries[i].value = (paddr & PTE_ADDR_MASK) |
                               PAGE_PRESENT | PAGE_WRITE | PAGE_HUGE_PD;
    }
}
```

这段代码遍历 PD 表的前 256 个项，为每个项创建一个 2MB 巨大页映射。256 × 2MB = 512MB，这样我们就覆盖了前 512MB 的物理内存。我们使用 `PAGE_HUGE_PD` 标志（位 7）来表示这是一个 2MB 巨大页，这样 CPU 在查找页表时，会在 PD 级别停止，不会继续查找 PT。

你可能会问：为什么是 512MB 而不是 1GB 或更多？这是一个折中。512MB 对于当前的系统来说足够了，而且不需要太多的页表内存。如果未来需要更多的直接映射，我们可以扩展这个范围。直接映射的大小受限于 PD 表的项数，一个 PD 表有 512 个项，如果每个项映射 2MB，最多可以映射 1GB，我们目前只使用前 256 个项，留有扩展空间。

---

## 设置 PML4[256]

直接映射区域对应的虚拟地址是 `0xFFFF800000000000`，这个地址的 PML4 索引是 256。我们需要设置 PML4[256] 来指向 Bootloader 的 PDPT：

```c
/* Set PML4[256] to point to the bootloader's PDPT */
pml4->entries[256].value = (0xA000 & PTE_ADDR_MASK) | PAGE_PRESENT | PAGE_WRITE;
```

`0xA000` 是 Bootloader 的 PDPT 物理地址，`& PTE_ADDR_MASK` 清除低 12 位，确保地址 4KB 对齐。我们没有设置 `PAGE_USER` 标志，这意味着直接映射区域只能在内核态访问，用户程序无法访问。

修改页表后，我们必须刷新 TLB，否则 CPU 可能继续使用旧的映射结果：

```c
/* Invalidate TLB to ensure the new mapping takes effect */
__asm__ volatile("mov %0, %%cr3" : : "r"((uint64_t)pml4_phys) : "memory");

s_direct_map_established = true;
```

重新加载 CR3 会刷新 TLB 中所有的非全局页表项，确保 CPU 使用新的页表。只有在刷新 TLB 后，新的映射才会生效。

---

## 直接映射建立后的变化

建立直接映射之前，虚拟地址空间的映射情况是这样的：低 2MB 有身份映射，高于 2MB 的地址没有映射，访问会触发页错误。

建立之后，我们可以通过 `0xFFFF800000000000 + 物理地址` 的方式访问任何物理内存。比如，要访问物理地址 0x100000，我们使用虚拟地址 `0xFFFF8000000100000`。所有这些转换都可以通过 `phys_to_virt` 和 `virt_to_phys` 宏来完成：

```c
/* 访问物理地址 0x100000 */
physical_addr_t paddr = 0x100000;
volatile uint32_t* ptr = (volatile uint32_t*)phys_to_virt(paddr);
*ptr = 0xDEADBEEF;

/* 从虚拟地址获取物理地址 */
virtual_addr_t vaddr = 0xFFFF8000000100000;
physical_addr_t phys = virt_to_phys(vaddr);
klog_info("Virtual 0x%llX maps to physical 0x%X\n", vaddr, phys);
```

`phys_to_virt` 和 `virt_to_phys` 只能用于直接映射区域的虚拟地址。如果你传入一个不在这个区域的虚拟地址，转换结果是错误的。

## 验证直接映射

我们可以写一个简单的测试来验证直接映射是否正常工作：

```c
/* Test direct mapping */
void test_direct_map(void) {
    /* Access physical memory via direct mapping */
    physical_addr_t test_paddr = 0x100000;  /* 1MB mark */
    virtual_addr_t test_vaddr = (virtual_addr_t)phys_to_virt(test_paddr);

    /* Write a pattern */
    volatile uint32_t* ptr = (volatile uint32_t*)test_vaddr;
    uint32_t pattern = 0xDEADBEEF;
    *ptr = pattern;

    /* Read back */
    if (*ptr == pattern) {
        klog_info("[TEST] Direct mapping test PASSED\n");
    } else {
        klog_error("[TEST] Direct mapping test FAILED\n");
    }

    /* Test virt_to_phys */
    physical_addr_t converted = virt_to_phys(test_vaddr);
    if (converted == test_paddr) {
        klog_info("[TEST] virt_to_phys test PASSED\n");
    } else {
        klog_error("[TEST] virt_to_phys test FAILED: got 0x%X, expected 0x%X\n",
                   converted, test_paddr);
    }
}
```

编译并运行，你应该能看到：

```
[TEST] Direct mapping test PASSED
[TEST] virt_to_phys test PASSED
```

---

## 调试过程中可能会遇到的几种情况

如果直接映射建立后仍无法访问高地址物理内存，首先检查 PD 表是否正确扩展。可能是循环次数不够（当前只映射 512MB），或者 PD 项的 Present 位没有设置，或者 TLB 没有刷新。

如果访问直接映射区域时崩溃，这通常意味着直接映射没有正确建立。检查 PML4[256] 是否指向正确的 PDPT，PDPT 是否指向正确的 PD，PD 项是否正确设置。

如果直接映射建立前就使用了 `phys_to_virt`，这会导致访问无效内存，因为直接映射区域还没有被映射。确保只有在 `s_direct_map_established = true` 之后才使用 `phys_to_virt`。

# 11 - 串口中断处理实现与优化

上一节我们了解了串口中断驱动的原理，这一节让我们把它实现出来。我们会从零构建一个完整的中断驱动串口模块，包括发送/接收缓冲区、中断处理器和用户 API。写完之后你会发现，整个实现其实挺直观的，但有几个细节需要特别注意。

---

## 环形缓冲区的实现细节

### 缓冲区结构设计

环形缓冲区的核心是两个指针：head 指向下一个写入位置，tail 指向下一个读取位置。我们使用 volatile 修饰符来告诉编译器不要优化对这些变量的访问，因为它们可能会在中断处理器中被修改。

缓冲区大小设置为 256 字节，这是一个折中的选择：既能容纳足够的数据，又不会占用太多内存。在实际使用中，可以根据数据速率和 CPU 处理能力来调整这个值。

### 辅助函数的实现

我们需要实现一些辅助函数来操作缓冲区。这些函数都很简单，但要注意的是，它们可能会在中断上下文和主程序上下文中同时被调用，所以需要考虑并发访问的问题。

判断缓冲区是否为空很简单，就是看 head 和 tail 是否相等。判断是否为满也简单，就是看 head 的下一个位置是否等于 tail。写入的时候先把数据放到 head 位置，然后 head 前进。读取的时候从 tail 位置读取数据，然后 tail 前进。

```c
#define UART_RX_BUFFER_SIZE 256
#define UART_TX_BUFFER_SIZE 256

typedef struct {
    char buffer[UART_RX_BUFFER_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} uart_rx_buffer_t;

typedef struct {
    char buffer[UART_TX_BUFFER_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} uart_tx_buffer_t;

static uart_rx_buffer_t rx_buffer = {0};
static uart_tx_buffer_t tx_buffer = {0};
```

## 中断处理器的核心逻辑

### 读取中断识别寄存器

中断处理器首先做的是读取中断识别寄存器，判断是什么类型的中断。这个寄存器的 bit 0 表示是否有中断待处理，如果为 0 表示有中断，为 1 表示无中断。bit 1 到 bit 3 表示中断源的代码。

我们使用一个 while 循环来处理所有待处理的中断，因为可能有多个中断同时发生。每次循环处理后，重新读取中断识别寄存器，直到 bit 0 变为 1。

### 接收数据的中断处理

当中断源代码是 0x04（接收数据可用）或 0x0C（字符超时）时，我们需要读取接收到的数据。由于有 FIFO，可能有多个字节可读，所以我们用 while 循环持续读取，直到线路状态寄存器表示没有更多数据。

读取每个字节后，我们把它写入接收缓冲区。如果缓冲区满了，只能丢弃数据。在实际应用中，可以考虑添加统计计数器来记录丢失的数据量。

```c
case 0x04:    // 接收数据可用
case 0x0C: {  // 字符超时
    // 读取所有可用数据
    while (inb(base + 5) & 0x01) {  // LSR 数据就绪
        char c = inb(base + 0);      // RBR
        if (!rx_is_full()) {
            rx_write(c);
        }
        // 如果满了，丢弃
    }
    break;
}
```

### 发送数据的中断处理

当中断源代码是 0x02（发送保持寄存器空）时，我们检查发送缓冲区是否还有数据。如果有，读取一个字节写入发送寄存器；如果没有，禁用发送中断。

这里有个关键点：必须在缓冲区空的时候立即禁用发送中断，否则会触发中断风暴。这是因为发送空中断会一直触发，直到被明确禁用。

```c
case 0x02: {  // 发送保持寄存器空
    if (!tx_is_empty()) {
        char c = tx_read();
        outb(base + 0, c);  // THR
    } else {
        // 缓冲区空，禁用 TX 中断
        uint8_t ier = inb(base + 1);
        outb(base + 1, ier & ~0x02);
    }
    break;
}
```

## 公共 API 的实现

### 初始化函数

初始化函数负责配置 UART 的工作模式并注册中断处理器。我们首先禁用所有中断，然后设置波特率为 115200，配置 8N1 格式（8 位数据，无奇偶校验，1 位停止位），接着使能 FIFO 并设置 14 字节阈值。

然后我们注册 IRQ 4 的中断处理器，启用接收和线状态中断，最后启用 IRQ 线。注意这里我们没有启用发送中断，它会在有数据要发送的时候被动态启用。

```c
int uart_init_intr_mode(void) {
    uint16_t base = SERIAL_COM1_BASE;

    // 禁用中断
    outb(base + 1, 0x00);

    // 使能 DLAB
    outb(base + 3, 0x80);

    // 设置波特率 115200 (divisor = 1)
    outb(base + 0, 0x01);
    outb(base + 1, 0x00);

    // 8N1 格式，禁用 DLAB
    outb(base + 3, 0x03);

    // 使能 FIFO，14 字节阈值
    outb(base + 2, 0xC7);

    // 启用 RX 和线状态中断
    outb(base + 1, 0x05);

    // 注册 IRQ 处理器
    uart_irq_desc.handler = uart_irq_handler;
    irq_register_handler(UART_COM1_IRQ, &uart_irq_desc);

    // 启用 IRQ 线
    pic_enable_irq(UART_COM1_IRQ);

    klog_info("UART interrupt mode initialized\n");
    return 0;
}
```

### 异步发送函数

异步发送函数首先把数据写入发送缓冲区，然后启用发送中断。如果缓冲区满了，函数会等待直到有空间可用。

这里有个细节需要注意：在写入缓冲区时需要禁用中断来保护临界区，防止中断处理器在同一时间修改缓冲区指针。我们使用 pushfq 和 popq 来保存和恢复中断标志。

```c
void async_serial_puts(const char* str) {
    if (str == NULL) return;

    uint16_t base = SERIAL_COM1_BASE;

    // 写入发送缓冲区
    while (*str) {
        // 等待缓冲区有空间
        while (tx_is_full()) {
            __asm__ volatile("pause");
        }

        // 禁用中断保护
        uint64_t rflags;
        __asm__ volatile("pushfq; popq %0" : "=r"(rflags));
        __asm__ volatile("cli");

        tx_write(*str++);

        if (rflags & 0x200) {
            __asm__ volatile("sti");
        }
    }

    // 启用 TX 中断
    uint8_t ier = inb(base + 1);
    if (!(ier & 0x02)) {
        outb(base + 1, ier | 0x02);
    }
}
```

## 性能对比与验证

### 轮询模式的开销

轮询模式的问题在于 CPU 要一直等待。发送 1000 字节的数据，在 115200 波特率下大约需要 87 毫秒，这段时间 CPU 基本上什么都不能做，就在那里空转。

### 中断驱动的优势

中断驱动模式下，主程序把数据写入缓冲区后就可以返回继续做其他事情，实际的发送由中断处理器在后台完成。虽然中断本身有开销，但整体 CPU 利用率大大提高。

我们可以写一个简单的测试来验证：发送 1000 字节数据，测量从开始到完成的时间。中断驱动模式下，主程序几乎立即返回，实际的发送工作在中断中完成。

## 调试技巧

### 中断计数统计

irq_descriptor_t 结构中的 invocation_count 字段可以用来统计中断触发次数。这对于诊断问题很有帮助，比如如果发现中断计数异常高，可能是有中断风暴。

### 缓冲区使用率监控

监控缓冲区的使用率可以帮助我们判断缓冲区大小是否合适。如果经常接近满，说明缓冲区可能太小或者主程序处理太慢。

```c
uint32_t rx_buffer_usage(void) {
    if (rx_buffer.head >= rx_buffer.tail) {
        return rx_buffer.head - rx_buffer.tail;
    } else {
        return UART_RX_BUFFER_SIZE - rx_buffer.tail + rx_buffer.head;
    }
}
```

## 常见问题排查

### 数据丢失

数据丢失通常是因为接收缓冲区溢出。解决方案包括增大缓冲区、提高主程序读取频率，或者确保硬件 FIFO 正确启用。

### 发送卡住

发送卡住通常是因为 TX 中断没有正确启用。检查中断使能寄存器的 bit 1 是否被设置，以及 IRQ 4 是否在 PIC 中被启用。

### 中断风暴

中断风暴是 TX 缓冲区空后没有禁用 TX 中断导致的。确保在中断处理器中，当缓冲区空的时候清除 IER 的 bit 1。

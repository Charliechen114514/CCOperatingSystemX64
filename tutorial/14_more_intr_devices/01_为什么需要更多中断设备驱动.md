# 01 - 为什么需要更多中断设备驱动

说实话，写操作系统写到这个阶段，我有时候会陷入一种奇怪的焦虑。

---

## 我们现在在哪里

如果你一路跟着前面的教程走过来，我们现在刚完成 `stage/13_interrupt_base`。这个阶段我们做了什么？我们实现了完整的中断处理框架：8259 PIC 驱动、IDT 设置、中断分发机制，还有一个简单的定时器滴答。

看起来挺美好的，对吧？系统已经能响应中断了，定时器在滴答滴答地走，我们终于从"单线程死循环"进化到了"中断驱动的死循环"。

但问题来了——你试过实际用这个系统吗？

### 那个让我清醒的下午

记得有一次，我想在 CCOS 里测试一个功能。我想让用户输入一个命令，然后系统执行。听起来很简单对吧？任何操作系统最基本的功能。

于是我坐下，打开终端，启动 QEMU，盯着 VGA 屏幕。屏幕上启动信息一闪而过，最后停在光标闪烁的位置。我想输入点什么，然后……然后我就一直在那盯着看。键盘？没反应。鼠标？也没反应。我只能眼睁睁看着屏幕，什么都做不了。

那一刻我突然意识到：**我们有了一个能处理中断的内核，但没有任何能跟用户交互的设备。**

这就像你建了一栋漂亮的大楼，有地基、有框架、有水电管道，但是——没有门。用户根本进不来。

---

## 当前阶段的四大痛点

### 痛点一：连个键盘都没有

你可能觉得这很基础，但事实上，键盘驱动是操作系统最复杂也最重要的驱动之一。PS/2 键盘使用 IRQ 1 中断，每个按键都会触发一个中断，发送一个扫描码。你需要：

1. 处理中断（IRQ 1）
2. 读取扫描码（0x60 端口）
3. 把扫描码转换成 ASCII
4. 处理修饰键（Shift、Ctrl、Alt）
5. 处理 Caps Lock 的状态
6. 管理输入缓冲区

而且扫描码还有 Make Code（按下）和 Break Code（释放），需要用状态机来处理。没做对的话，你按个 'A' 可能出来一串字符，或者 Shift 完全不生效。

### 痛点二：系统不知道现在是几点

你有没有想过，操作系统是怎么知道当前时间的？在用户态，你可以调用 `time()` 或者 `localtime()`，但在内核态，这些都不存在。

PC 上有一个 CMOS RTC（Real Time Clock）芯片，通过端口 I/O 可以读取当前时间。但问题是：

- CMOS 访问需要特殊序列（先写地址端口，再读数据端口）
- 时间数据可能是 BCD 编码，需要转换
- 读取时需要等待更新完成，否则可能读到不一致的数据
- RTC 还支持周期性中断和闹钟功能

没有 RTC，你的系统永远停留在"启动时间"，没法做任何与时间相关的事情。

### 痛点三：串口还是轮询模式

在 stage 09 我们实现了串口驱动，但那是轮询模式的。每次发送一个字符都要等待 UART 准备好，效率很低。而且在接收数据时，你必须不断轮询，否则会丢失数据。

中断驱动的串口可以：
- 发送时把数据放到缓冲区，让中断处理实际发送
- 接收时中断自动填充缓冲区，不会丢失数据
- CPU 可以做其他事情，不用傻傻地等待

这不仅仅是效率问题，这是系统能否正常工作的关键。

### 痛点四：没有 Shell

你想执行命令？你想查看系统状态？你想调试问题？没有 Shell，这些都做不了。VGA 上只会显示启动信息，然后就停在那里。

Shell 是操作系统与用户交互的核心接口。一个好的 Shell 需要：
- 命令解析和参数分割
- 命令注册机制
- 内置命令（help、clear、time 等）
- 支持多个后端（VGA 和串口）
- 历史记录（未来）
- Tab 补全（未来）

## 中断驱动 vs 轮询模式

在深入之前，我们先来聊聊为什么中断驱动这么重要。

### 轮询模式的困境

轮询模式很简单：你在循环里不断检查设备状态。

```c
// 轮询式串口发送
void serial_puts_polling(const char* str) {
    while (*str) {
        // 等待发送保持寄存器为空
        while ((inb(SERIAL_LINE_STATUS_REG(base)) & 0x20) == 0) {
            // 什么都不做，就是等待
        }
        // 发送字符
        outb(SERIAL_DATA_REG(base), *str++);
    }
}
```

问题在哪里？CPU 在空转。在等待 UART 准备好的这段时间里，CPU 什么都做不了，只能不停地读取寄存器、检查、再读取、再检查。

如果发送一个 1000 字节的字符串，每个字符需要等待 10 微秒，那就是 10 毫秒的纯浪费。10 毫秒听起来不多，但 CPU 在这段时间里可以执行数百万条指令。

### 中断驱动的优雅

中断驱动模式下，CPU 可以去做别的事情。

```c
// 中断驱动式串口发送
void serial_puts_interrupt(const char* str) {
    // 把数据复制到发送缓冲区
    memcpy(tx_buffer, str, strlen(str));
    // 启用发送空中断
    enable_tx_interrupt();
    // 返回！CPU 可以做别的事情了
}

// 中断处理程序
void serial_tx_irq_handler(void) {
    if (tx_buffer_has_data()) {
        outb(SERIAL_DATA_REG(base), tx_buffer_get_char());
    } else {
        // 缓冲区空了，禁用中断
        disable_tx_interrupt();
    }
}
```

CPU 只在真正需要发送字符的时候被打断，其他时间完全自由。这就像你从"守在门口等快递"变成了"快递到了门铃响，你再开门"。

## 我们要达成的目标

在这个阶段（`stage/14_more_intr_devices`），我们要完成四件大事。

### 第一件事：PS/2 键盘驱动

我们要实现一个完整的 PS/2 键盘驱动，包括：

- IRQ 1 中断处理
- 扫描码集 1 到 ASCII 的转换
- Shift 和 Caps Lock 修饰键支持
- 256 字节的环形缓冲区
- 阻塞和非阻塞读取 API

完成后，你就可以在键盘上敲击，字符会出现在屏幕上。这是操作系统历史上的一刻——你终于可以跟系统对话了。

### 第二件事：CMOS RTC 驱动

我们要实现 CMOS RTC 驱动，让系统知道时间：

- 读取当前日期和时间
- 自动处理 BCD 编码转换
- 周期性中断支持（2Hz ~ 8192Hz）
- 闹钟功能
- RTC 回调机制

完成后，你可以在 Shell 里输入 `time` 命令，看到当前时间显示出来。这感觉真的很奇妙。

### 第三件事：PIT 可配置定时器

虽然我们已经有定时器滴答了，但我们要让它更灵活：

- 可配置频率（默认 1000Hz）
- 回调机制支持
- `timer_mdelay()` 毫秒级延时
- `timer_get_ticks()` 获取滴答数

这样我们就可以实现精确的延时和定时任务。

### 第四件事：中断驱动的串口和 Shell

我们要把串口升级到中断驱动模式，然后实现一个通用的 Shell 系统：

- UART 中断驱动（TX/RX FIFO）
- 异步发送 API
- Shell 后端抽象接口
- VGA Shell 后端
- Serial Shell 后端
- 命令注册机制
- 内置命令（help、clear、time、echo 等）

完成后，你可以在 VGA 屏幕上看到光标闪烁，输入命令得到响应；也可以通过串口连接，远程操作你的内核。这是质的飞跃。

### 还有一些优化

我们还要做一些基础优化：

- kprintf 模块化，提取出 format 模块
- 实现 ksnprintf
- VGA 软件光标支持

这些看起来是小改动，但会让系统更健壮、更易用。

## 在开始之前

在正式开始之前，请确保你的 `stage/13` 能正常编译和运行。

验证一下：

```bash
cd /path/to/CCOperatingSystemX64

# 切换到 stage/13 分支
git checkout stage/13_interrupt_base

# 配置构建
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 构建
cmake --build build

# 运行
qemu-system-x86_64 -drive format=raw,file=build/boot.img
```

你应该能看到 QEMU 窗口启动，VGA 屏幕上有启动信息，串口（如果配置了）也有日志输出。定时器中断应该在工作，你可以通过 GDB 或者在代码里加打印来验证。

### 环境准备确认

虽然大部分工具在前面的阶段已经装好了，但我们再确认一遍：

## 前后对比

完成这个阶段后，我们的内核会有哪些变化？

### 在 stage/13，我们只有：
- 基础中断框架
- PIC 驱动
- 简单的定时器滴答
- 轮询式串口

### 在 stage/14，我们将拥有：
- PS/2 键盘驱动（中断驱动）
- CMOS RTC 驱动（时间读取 + 周期中断）
- 可配置 PIT 定时器（回调机制）
- 中断驱动串口（FIFO + 异步 I/O）
- 通用 Shell 系统（VGA + Serial 后端）
- VGA 软件光标
- 模块化的 kprintf/ksnprintf

这不是小改进，这是从"能跑的中断框架"到"可用的交互系统"的跨越。

## 我们即将要做的

在接下来的十几个文档中，我们会一步步完成这些功能。

首先，我们会重构中断系统，引入统一的 IRQ 注册机制。这是所有设备驱动的基础。

然后，我们会从零开始实现环形缓冲区。键盘和串口都要用它，所以先把基础打好。

接着是 PS/2 键盘驱动。我们会深入了解 PS/2 协议、扫描码、状态机，最后实现一个能用的键盘驱动。

之后是 CMOS RTC 驱动。我们会学习 CMOS 访问协议、BCD 编码、周期中断，让系统知道时间。

再之后是 PIT 可配置定时器。我们会让定时器更灵活，支持回调和精确延时。

然后是串口的中断驱动升级。我们会学习 UART FIFO、中断优化，让串口效率提升一个数量级。

最后是 Shell 系统。我们会设计后端抽象接口，实现 VGA 和 Serial 两个后端，打造一个能用的命令行界面。

每一步都是独立的，你可以跟着做一部分，也可以全部做完。相信我，等你完整实现之后，你会感谢现在努力的自己。

# 03 - 数据结构基础——环形缓冲区从零实现

在深入设备驱动之前，我们得先把一个基础数据结构搞定。说实话，环形缓冲区是中断驱动 I/O 的基石——键盘、串口、鼠标，几乎所有异步 I/O 都离不开它。

---

## 为什么需要环形缓冲区

### 问题场景

想象一下这个场景：键盘中断触发，处理器读到一个扫描码，转换成 ASCII 字符 'A'。现在怎么办？

你可能会说：直接存到一个变量里呗。但问题是，主程序可能正在忙别的，没来得及取走这个字符。如果用户继续按键，第二个字符、第三个字符怎么办？

或者串口接收数据：中断触发，收到一个字节。但如果主程序处理慢一点，后面的字节就来了，没地方存就丢失了。

### 环形缓冲区的优势

环形缓冲区（也叫循环队列）解决的就是这个问题：

- **固定大小**：不需要动态内存分配，在内核里特别重要
- **FIFO 语义**：先入先出，符合数据流的特点
- **中断安全**：设计得当的话，可以在中断和主程序之间安全共享
- **O(1) 操作**：读写都是常数时间，没有拷贝开销

基本上，环形缓冲区就是生产者-消费者模式的最简单实现。

---

## 环形缓冲区的原理

### 基本结构

环形缓冲区的结构很简单：

```
缓冲区大小：8（示意）

head = 5, tail = 2

[0]  [1]  [2]  [3]  [4]  [5]  [6]  [7]
 D    D    T    .    .    H    .    .

有效数据：[2] 到 [4]，共 3 个字节
```

- **head**：写入位置，下一个数据写在这里
- **tail**：读取位置，下一个数据从这里读
- **有效数据**：从 tail 到 head-1

当 head 或 tail 到达数组末尾时，自动绕回到开头：

```
写入 3 个字节后：

head = 0, tail = 2

[0]  [1]  [2]  [3]  [4]  [5]  [6]  [7]
 H    .    T    .    .    .    .    .

有效数据：[2] 到 [6]，绕回，共 6 个字节
```

### 满/空判断

有个微妙的问题：如何区分满和空？当 head == tail 时，可能是空的，也可能是满的。

常见有两种解决方案：

1. **牺牲一个字节**：始终留一个空位，满的定义是 `(head + 1) % size == tail`
2. **计数器**：额外维护一个元素计数

我们采用第一种方案，简单高效：

```c
// 空判断
bool is_empty = (head == tail);

// 满判断（牺牲一个字节）
bool is_full = ((head + 1) % SIZE) == tail;
```

这意味着大小为 256 的缓冲区实际最多存 255 个字节，但这个 trade-off 是值得的。

## 实现环形缓冲区

### 结构定义

首先定义结构体：

```c
#define BUFFER_SIZE 256

typedef struct {
    char buffer[BUFFER_SIZE];
    volatile uint32_t head;  // 写位置
    volatile uint32_t tail;  // 读位置
} ring_buffer_t;
```

注意 `volatile` 关键字。这告诉编译器这个变量可能被外部修改（比如中断处理器），不要做激进的优化。没有 volatile 的话，编译器可能会把 `head` 缓存到寄存器里，导致看不到中断里的修改。

### 基本操作

#### 判断空/满

```c
static inline bool ring_is_empty(ring_buffer_t* rb) {
    return rb->head == rb->tail;
}

static inline bool ring_is_full(ring_buffer_t* rb) {
    return ((rb->head + 1) % BUFFER_SIZE) == rb->tail;
}
```

用 `inline` 是因为这些函数很小，内联后性能更好。而且它们是 `static` 的，编译器可能会在多个编译单元生成各自的副本，但因为函数体很简单，这没问题。

#### 写入数据

```c
static inline void ring_write(ring_buffer_t* rb, char c) {
    rb->buffer[rb->head] = c;
    rb->head = (rb->head + 1) % BUFFER_SIZE;
}
```

写入前应该先检查 `ring_is_full()`，否则会覆盖未读的数据。

#### 读取数据

```c
static inline char ring_read(ring_buffer_t* rb) {
    char c = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1) % BUFFER_SIZE;
    return c;
}
```

读取前应该先检查 `ring_is_empty()`，否则会读到无效数据。

### 中断安全考虑

这里有个坑点：head 和 tail 是 32 位的，在某些架构上读写 32 位不是原子的。x86-64 上没问题，但在一些嵌入式平台上可能会出问题。

如果要更安全，可以用 `__atomic` 内置函数或者关中断保护：

```c
// 安全写入（中断中调用）
void ring_write_safe(ring_buffer_t* rb, char c) {
    uint32_t old_head = rb->head;
    uint32_t new_head = (old_head + 1) % BUFFER_SIZE;

    if (new_head != rb->tail) {  // 没满
        rb->buffer[old_head] = c;
        // 确保写入完成后再更新 head
        __asm__ volatile("mfence" ::: "memory");
        rb->head = new_head;
    }
}
```

不过对于我们的场景，在 x86-64 上简单的读写已经够用了。

## 单字节 vs 多字节操作

上面的函数是单字节操作的。如果我们想一次写入/读取多个字节，需要小心处理。

### 写入字符串

```c
int ring_write_string(ring_buffer_t* rb, const char* str) {
    int written = 0;

    while (*str) {
        if (ring_is_full(rb)) {
            break;  // 缓冲区满
        }
        ring_write(rb, *str++);
        written++;
    }

    return written;
}
```

这会写入直到缓冲区满或者字符串结束。返回值是实际写入的字节数，调用者可以判断是否全部写入。

### 读取 N 字节

```c
int ring_read_n(ring_buffer_t* rb, char* out, size_t n) {
    int read = 0;

    for (size_t i = 0; i < n; i++) {
        if (ring_is_empty(rb)) {
            break;
        }
        out[i] = ring_read(rb);
        read++;
    }

    return read;
}
```

## 完整实现示例

让我们把这些整合起来，写一个完整的环形缓冲区模块：

```c
// ring_buffer.h
#ifndef RING_BUFFER_H
#define RING_BUFFER_H

#include <stdbool.h>
#include <stdint.h>

#define RING_BUFFER_SIZE 256

typedef struct {
    char buffer[RING_BUFFER_SIZE];
    volatile uint32_t head;
    volatile uint32_t tail;
} ring_buffer_t;

// 初始化
void ring_init(ring_buffer_t* rb);

// 状态查询
bool ring_is_empty(ring_buffer_t* rb);
bool ring_is_full(ring_buffer_t* rb);
uint32_t_ring_available(ring_buffer_t* rb);  // 可读字节数
uint32_t ring_free(ring_buffer_t* rb);       // 空闲空间

// 单字节操作
bool ring_write(ring_buffer_t* rb, char c);  // 返回 false 表示满
bool ring_read(ring_buffer_t* rb, char* c);  // 返回 false 表示空

// 多字节操作
uint32_t ring_write_buffer(ring_buffer_t* rb, const char* data, uint32_t len);
uint32_t ring_read_buffer(ring_buffer_t* rb, char* out, uint32_t len);

// 非破坏性查看
bool ring_peek(ring_buffer_t* rb, char* c);  // 查看下一个字符但不移除

#endif
```

```c
// ring_buffer.c
#include "ring_buffer.h"

void ring_init(ring_buffer_t* rb) {
    rb->head = 0;
    rb->tail = 0;
}

bool ring_is_empty(ring_buffer_t* rb) {
    return rb->head == rb->tail;
}

bool ring_is_full(ring_buffer_t* rb) {
    return ((rb->head + 1) % RING_BUFFER_SIZE) == rb->tail;
}

uint32_t ring_available(ring_buffer_t* rb) {
    if (rb->head >= rb->tail) {
        return rb->head - rb->tail;
    } else {
        return RING_BUFFER_SIZE - rb->tail + rb->head;
    }
}

uint32_t ring_free(ring_buffer_t* rb) {
    return RING_BUFFER_SIZE - ring_available(rb) - 1;
}

bool ring_write(ring_buffer_t* rb, char c) {
    if (ring_is_full(rb)) {
        return false;
    }

    rb->buffer[rb->head] = c;
    rb->head = (rb->head + 1) % RING_BUFFER_SIZE;
    return true;
}

bool ring_read(ring_buffer_t* rb, char* c) {
    if (ring_is_empty(rb)) {
        return false;
    }

    *c = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1) % RING_BUFFER_SIZE;
    return true;
}

uint32_t ring_write_buffer(ring_buffer_t* rb, const char* data, uint32_t len) {
    uint32_t written = 0;

    for (uint32_t i = 0; i < len; i++) {
        if (!ring_write(rb, data[i])) {
            break;
        }
        written++;
    }

    return written;
}

uint32_t ring_read_buffer(ring_buffer_t* rb, char* out, uint32_t len) {
    uint32_t read_count = 0;

    for (uint32_t i = 0; i < len; i++) {
        if (!ring_read(rb, &out[i])) {
            break;
        }
        read_count++;
    }

    return read_count;
}

bool ring_peek(ring_buffer_t* rb, char* c) {
    if (ring_is_empty(rb)) {
        return false;
    }

    *c = rb->buffer[rb->tail];
    return true;
}
```

## 在中断环境中使用

环形缓冲区最常见的用法就是：中断处理器写入，主程序读取。

### 示例：键盘中断

```c
static ring_buffer_t keyboard_buffer;

// 中断处理器（IRQ 1）
void keyboard_irq_handler(interrupt_frame_t* frame, void* context) {
    (void)frame;
    (void)context;

    uint8_t scancode = inb(0x60);
    char c = scancode_to_ascii(scancode);

    if (c != 0) {
        ring_write(&keyboard_buffer, c);  // 中断中写入
    }

    pic_send_eoi(1);
}

// 主程序读取
char keyboard_getchar(void) {
    char c;

    // 等待有数据
    while (ring_is_empty(&keyboard_buffer)) {
        __asm__ volatile("pause");
    }

    // 读取（需要关中断保护）
    interrupt_disable();
    ring_read(&keyboard_buffer, &c);
    interrupt_enable();

    return c;
}
```

注意这里关中断保护。因为 head 和 tail 虽然是 volatile 的，但 `ring_read()` 里有两个操作：读取数据、更新 tail。如果这两步之间被中断打断，可能会出问题。

不过更仔细想一下，在我们的场景里：
- 中断只修改 head（写）
- 主程序只修改 tail（读）

它们操作不同的变量，所以其实不会冲突。这是生产者-消费者模式的一个优化：读写分离。但如果你不确定，关中断保护总是安全的。

### 更优雅的关中断保护

```c
char keyboard_getchar(void) {
    char c;

    while (ring_is_empty(&keyboard_buffer)) {
        __asm__ volatile("pause");
    }

    // 保存中断状态并禁用
    uint64_t rflags;
    __asm__ volatile("pushfq; popq %0" : "=r"(rflags));
    __asm__ volatile("cli");

    ring_read(&keyboard_buffer, &c);

    // 恢复原来的中断状态
    if (rflags & 0x200) {
        __asm__ volatile("sti");
    }

    return c;
}
```

这样不会破坏之前的中断状态，更安全。

## 常见陷阱

### 陷阱 1：忘记 volatile

如果你忘记给 head/tail 加 volatile，编译器可能会这样优化：

```c
// 你的代码
while (ring_is_empty(&keyboard_buffer)) {
    __asm__ volatile("pause");
}

// 编译器可能优化成
if (ring_is_empty(&keyboard_buffer)) {
    while (true) {
        __asm__ volatile("pause");
    }
}
```

因为编译器认为 `rb->head` 和 `rb->tail` 没有在这个代码路径里被修改，所以只检查一次就够了。这会导致你的程序永远等待，即使中断已经写入数据。

### 陷阱 2：满判断错误

常见的错误是：

```c
// 错误！
bool ring_is_full(ring_buffer_t* rb) {
    return rb->head == rb->tail;  // 这和空的判断一样！
}
```

这会导致满和空无法区分。正确的做法是牺牲一个字节或者使用计数器。

### 陷阱 3：溢出检查

写入前必须检查是否满，否则会覆盖未读数据：

```c
// 危险！没有检查
void ring_write_unsafe(ring_buffer_t* rb, char c) {
    rb->buffer[rb->head] = c;
    rb->head = (rb->head + 1) % RING_BUFFER_SIZE;
    // 如果满了，这里会覆盖 tail 位置的数据！
}
```

好的实践是返回一个 bool 表示是否成功：

```c
bool ring_write(ring_buffer_t* rb, char c) {
    if (ring_is_full(rb)) {
        return false;  // 缓冲区满，写入失败
    }
    // ...写入逻辑...
    return true;
}
```

## 大小选择

多大合适？这取决于你的数据速率和处理速度。

**键盘**：打字速度大约 5-10 字符/秒，峰值可能 20-30。256 字节绰绰有余。

**串口**：115200 波特率 = 11520 字节/秒。如果中断延迟 10ms，期间可能有 115 字节。256 字节够用，但再大点更安全。

**网络**：网卡可能需要更大的缓冲区，几个 KB 甚至几十 KB。

选择 2 的幂是个好习惯，因为取模运算可以优化成位运算：

```c
// 对于 256 = 2^8
head = (head + 1) % 256;
// 等价于
head = (head + 1) & 0xFF;
```

不过现代编译器已经很聪明了，对于 2 的幂的常数除法会自动优化，所以手动优化意义不大。

## 验证实现

写个简单测试来验证你的环形缓冲区：

```c
void test_ring_buffer(void) {
    ring_buffer_t rb;
    ring_init(&rb);

    // 测试空
    assert(ring_is_empty(&rb));
    assert(!ring_is_full(&rb));

    // 写入一些数据
    for (int i = 0; i < 10; i++) {
        assert(ring_write(&rb, 'A' + i));
    }

    // 检查状态
    assert(!ring_is_empty(&rb));
    assert(ring_available(&rb) == 10);

    // 读回
    for (int i = 0; i < 10; i++) {
        char c;
        assert(ring_read(&rb, &c));
        assert(c == 'A' + i);
    }

    // 应该又是空的
    assert(ring_is_empty(&rb));

    // 测试绕回
    for (int i = 0; i < 250; i++) {
        ring_write(&rb, i);
    }
    // 现在 head 在 250，tail 在 0
    // 读写几次触发绕回
    for (int i = 0; i < 10; i++) {
        char c;
        ring_read(&rb, &c);
        ring_write(&rb, 'X');
    }

    klog_info("Ring buffer test passed!\n");
}
```

可以在内核初始化时调用这个测试，确保环形缓冲区工作正常。

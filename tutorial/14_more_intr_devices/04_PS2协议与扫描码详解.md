# 04 - PS/2协议与扫描码详解

现在我们有了环形缓冲区这个工具，可以开始实现键盘驱动了。但首先，我们得搞清楚 PS/2 协议到底是怎么回事。说实话，PS/2 是个古老但生命力极强的协议——从 1987 年 IBM PS/2 电脑诞生至今，已经快 40 年了，但你现在的电脑主板上依然有 PS/2 接口（或者 USB 键盘内部模拟的 PS/2）。

---

## PS/2 接口历史

### 起源

PS/2 接口是 IBM 在 1987 年随 PS/2 系列电脑引入的，用来取代早期的 PC/AT 键盘接口。它有两个主要优点：

1. **更小的接口**：比原来的 DIN-5 接口小得多
2. **双向通信**：键盘和主机可以互相发送命令

虽然 USB 已经普及，但 PS/2 在某些场景下仍然有优势：
- 硬件级中断，延迟更低
- 简单，不需要复杂的 USB 协议栈
- 支持全键无冲（某些高端键盘）

### 硬件接口

PS/2 使用两个 I/O 端口：

| 端口 | 名称 | 方向 | 描述 |
|------|------|------|------|
| 0x60 | 数据寄存器 | 双向 | 传输数据 |
| 0x64 | 状态/命令寄存器 | 输入/命令 | 读取状态或发送命令 |

注意 0x64 是双重功能的：
- 读取时：状态寄存器
- 写入时：命令寄存器（用于向键盘发送命令）

---

## 状态寄存器 (0x64)

读取 0x64 得到状态寄存器：

```
┌──┬──┬──┬──┬──┬──┬──┬──┐
│ 7│ 6│ 5│ 4│ 3│ 2│ 1│ 0│
└──┴──┴──┴──┴──┴──┴──┴──┘
  │  │           │     │
  │  │           │     └─ 输出满 (1=数据可读)
  │  │           └─────── 输入满 (1=正在处理)
  │  └─────────────────── 系统标志
  └────────────────────── 命令/数据 (1=数据是命令)
```

最重要的位是 bit 0（输出满）：当它为 1 时，表示键盘发送了数据，可以从 0x60 读取。

### 读取流程

```c
// 等待数据可读
while (!(inb(0x64) & 0x01)) {
    // 等待...
}

// 读取数据
uint8_t data = inb(0x60);
```

## 扫描码集

PS/2 键盘发送的不是 ASCII 字符，而是**扫描码**（scancode）。扫描码是按键的物理标识，与键盘布局无关。

更麻烦的是，PS/2 有三套扫描码集：

| 扫描码集 | 简介 | 使用场景 |
|---------|------|---------|
| Set 1 | PC/AT 标准，单字节 | 大多数现代键盘默认 |
| Set 2 | PS/2 原始，双字节 | 某些旧键盘 |
| Set 3 | 扩展，更复杂 | 很少使用 |

我们的实现只支持 Set 1，因为它是现代键盘的默认设置，而且最简单。

### Set 1 扫描码格式

Set 1 的特点：

- **Make Code**（按下）：通常是单字节
- **Break Code**（释放）：Make Code | 0x80

例如：
- 'A' 键的 Make Code = 0x1E
- 'A' 键的 Break Code = 0x9E (0x1E | 0x80)

这意味着我们可以通过检查最高位来判断是按下还是释放：

```c
uint8_t scancode = inb(0x60);
uint8_t code = scancode & 0x7F;   // 去掉 break 位
bool is_break = (scancode & 0x80) != 0;

if (!is_break) {
    // 按键按下
} else {
    // 按键释放
}
```

## 扩展扫描码

有些键（如右 Ctrl、右 Alt、方向键）会发送以 0xE0 开头的双字节扫描码：

```
按下右 Ctrl: 0xE0 0x1D
释放右 Ctrl: 0xE0 0x9D
```

处理方式是：如果收到 0xE0，下一个字节才是真正的扫描码。

```c
static bool escape_prefix = false;

uint8_t scancode = inb(0x60);

if (scancode == 0xE0) {
    escape_prefix = true;
    return;  // 等待下一个字节
}

if (escape_prefix) {
    // 处理扩展扫描码
    escape_prefix = false;
    // ...
} else {
    // 处理普通扫描码
    // ...
}
```

我们的基础实现暂不支持扩展扫描码，但结构上可以很容易添加。

## 键盘命令

主机可以向键盘发送命令，配置它的行为。命令通过 0x60 端口发送：

### 发送命令流程

```c
// 1. 等待输入缓冲区空
while (inb(0x64) & 0x02) {
    // 等待...
}

// 2. 发送命令
outb(0x60, command);

// 3. 等待响应（如果需要）
// ...
```

### 常用命令

| 命令 | 描述 |
|------|------|
| 0xED | 设置 LED（参数：bit0=Scroll, bit1=Num, bit2=Caps） |
| 0xEE | 回显测试（键盘会回送 0xEE） |
| 0xF0 | 获取/设置扫描码集 |
| 0xF2 | 读取键盘 ID |
| 0xF3 | 设置 typematic rate（重复速率） |
| 0xF4 | 启用键盘扫描 |
| 0xF5 | 禁用键盘扫描 |
| 0xFF | 复位键盘 |

最常用的是 0xF4（启用扫描）和 0xF5（禁用扫描）。

### 设置 LED 示例

```c
void keyboard_set_led(bool caps, bool num, bool scroll) {
    uint8_t leds = 0;
    if (scroll) leds |= 0x01;
    if (num)    leds |= 0x02;
    if (caps)   leds |= 0x04;

    // 发送命令
    while (inb(0x64) & 0x02);  // 等待输入空
    outb(0x60, 0xED);          // 设置 LED 命令

    // 等待确认
    while (!(inb(0x64) & 0x01));
    inb(0x60);  // 丢弃 ACK

    // 发送 LED 状态
    while (inb(0x64) & 0x02);
    outb(0x60, leds);
}
```

## 响应码

键盘对命令的响应：

| 响应 | 描述 |
|------|------|
| 0xFA | ACK（命令收到） |
| 0xFE | Resend（主机重发上一个命令） |
| 0xFC | 错误/失败 |
| 0xFD | 错误/失败 |

发送命令后，应该等待并检查响应：

```c
outb(0x60, 0xF4);  // 启用扫描

// 等待响应
while (!(inb(0x64) & 0x01));
uint8_t response = inb(0x60);

if (response == 0xFA) {
    // 成功
} else if (response == 0xFE) {
    // 重发
} else {
    // 错误
}
```

不过在实际应用中，通常简化处理：假设命令会成功，不等待响应。这在小规模驱动中是可以接受的。

## 中断触发

键盘使用 IRQ 1。每次有数据可读时，触发中断。

中断处理流程：

```c
void keyboard_irq_handler(interrupt_frame_t* frame, void* context) {
    (void)frame;
    (void)context;

    // 1. 读取状态
    uint8_t status = inb(0x64);

    // 2. 检查输出缓冲区是否满
    if (!(status & 0x01)) {
        // 伪中断，没有数据
        pic_send_eoi(1);
        return;
    }

    // 3. 读取扫描码
    uint8_t scancode = inb(0x60);

    // 4. 处理扫描码...

    // 5. 发送 EOI
    pic_send_eoi(1);
}
```

## 常见问题

### 问题 1：扫描码集不匹配

**症状**：按下 'A'，收到的扫描码对不上。

**原因**：键盘可能使用 Set 2 扫描码。

**解决方案**：发送命令切换到 Set 1：

```c
outb(0x60, 0xF0);  // 切换扫描码集命令
outb(0x60, 0x01);  // 选择 Set 1
```

或者干脆在初始化时强制切换。

### 问题 2：数据丢失

**症状**：快速打字时丢失字符。

**原因**：中断处理太慢，或者没有及时读取数据。

**解决方案**：确保中断处理尽快，使用环形缓冲区缓存数据。

### 问题 3：键盘不响应

**症状**：按键无反应。

**原因**：可能键盘被禁用了，或者 IRQ 没启用。

**解决方案**：检查是否调用了 `pic_enable_irq(1)`，以及是否发送了 0xF4（启用扫描）命令。

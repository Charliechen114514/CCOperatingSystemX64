# 15 - 完整集成与系统验证

恭喜！我们已经完成了所有核心组件的开发。现在让我们把它们全部集成起来，进行完整的系统验证。这一节会汇总初始化流程、运行实际测试、验证所有功能正常工作。

---

## 我们实现了什么

### 完整的组件清单

回顾一下我们在 Stage 14 中实现的所有组件：

首先是 **IRQ 注册机制**，这是我们整个中断系统的基础，位于 `kernel/interrupt/idt.c`。它提供了一个统一的 API 来注册中断处理器，让各个设备驱动可以方便地注册自己的 IRQ 处理函数。

然后是 **环形缓冲区**，这是中断驱动 I/O 的基础数据结构。我们把它内嵌在各个驱动中，用于在中断处理器和主程序之间传递数据。

**PS/2 键盘驱动** 让我们可以接收用户输入。它实现了扫描码到 ASCII 的转换，支持修饰键（Shift、CapsLock 等），并通过 IRQ 1 中断高效工作。

**CMOS RTC 驱动** 提供了时间读取功能，还实现了周期性中断和闹钟功能。这样系统既能知道当前时间，也能在指定时刻触发任务。

**PIT 定时器** 是系统的滴答源，我们实现了可配置频率的功能，支持运行时改变频率，还有回调机制让其他模块可以订阅定时事件。

**中断驱动串口** 让串口 I/O 效率大幅提升。通过 16550 的 FIFO 机制和中断驱动模式，CPU 不再需要轮询等待，可以同时处理其他任务。

**Shell 系统** 是用户与系统交互的核心接口。我们设计了后端抽象架构，支持 VGA 和 Serial 两种 I/O 方式，实现了命令解析和执行机制。

最后是 **kprintf 优化**，我们提取了独立的 format 模块，实现了 ksnprintf，让格式化输出更加灵活。

## 内核初始化顺序

### 初始化顺序的重要性

初始化顺序真的很关键，搞错了会导致各种奇怪的问题。基本原则是：基础设施先初始化，然后是底层驱动，再是中断依赖的驱动，最后是高层功能。

具体来说，中断系统必须先初始化，因为其他驱动都会注册中断处理器。PIC 也要先配置好，因为所有 IRQ 都要经过它。然后是定时器、键盘、RTC、串口这些中断设备。最后才是 Shell 这样依赖所有其他组件的高层功能。

### 完整的初始化流程

我们把初始化分成几个阶段，每个阶段做一组相关的初始化工作。这样做的好处是逻辑清晰，出现问题的时候容易定位哪个阶段出了问题。

```c
void kernel_init(void) {
    // ========== 第一阶段：基础架构 ==========
    klog_trace("=== Stage 1: Basic Infrastructure ===\n");

    // 中断系统初始化（不启用中断）
    interrupt_init();
    klog_trace("Interrupt framework initialized\n");

    // ========== 第二阶段：底层驱动 ==========
    klog_trace("=== Stage 2: Low-level Drivers ===\n");

    // PIT 定时器初始化
    timer_init(1000);  // 1000 Hz
    klog_trace("PIT timer initialized at 1000 Hz\n");

    // ========== 第三阶段：中断设备驱动 ==========
    klog_trace("=== Stage 3: Interrupt-driven Devices ===\n");

    // PS/2 键盘驱动
    keyboard_init();
    klog_trace("PS/2 keyboard driver initialized\n");

    // CMOS RTC 驱动
    rtc_init();
    klog_trace("CMOS RTC driver initialized\n");

    // 中断驱动串口
    uart_init_intr_mode();
    klog_trace("UART interrupt mode initialized\n");

    // ========== 第四阶段：高层功能 ==========
    klog_trace("=== Stage 4: High-level Features ===\n");

    // 注册 Shell 内置命令
    register_builtin_commands();
    klog_trace("Shell commands registered\n");

    // ========== 第五阶段：启用中断 ==========
    klog_trace("=== Stage 5: Enable Interrupts ===\n");

    interrupt_finalize();
    klog_trace("Interrupts enabled\n");

    klog_info("Kernel initialization complete!\n");
}
```

## 功能测试实战

### 键盘输入测试

第一个测试是键盘输入，这是最直接的交互方式。我们读取用户输入并回显，验证键盘驱动是否正常工作。

```c
void test_keyboard_input(void) {
    klog_info("=== Keyboard Input Test ===\n");
    klog_info("Type something and press Enter...\n");

    char buffer[128];
    int pos = 0;

    while (true) {
        if (keyboard_haschar()) {
            char c = keyboard_getchar();

            if (c == '\n') {
                buffer[pos] = '\0';
                klog_info("You typed: %s\n", buffer);
                pos = 0;
            } else if (c == '\b') {
                if (pos > 0) pos--;
            } else if (pos < 127) {
                buffer[pos++] = c;
            }
        }
    }
}
```

### RTC 时间测试

RTC 时间测试验证 CMOS RTC 驱动是否正常工作。我们读取当前时间，格式化后输出。如果时间显示合理，说明 BCD 转换、时间读取逻辑都正确。

```c
void test_rtc_time(void) {
    klog_info("=== RTC Time Test ===\n");

    rtc_time_t time;
    if (rtc_get_time(&time) == 0) {
        char buffer[32];
        rtc_format_time(&time, buffer, sizeof(buffer));
        klog_info("Current time: %s\n", buffer);
    } else {
        klog_error("Failed to read RTC time\n");
    }
}
```

### 串口回显测试

串口回显测试验证中断驱动的串口是否工作。我们读取串口输入并原样发回，如果连接到终端，用户可以看到自己输入的内容。

```c
void test_serial_echo(void) {
    klog_info("=== Serial Echo Test ===\n");
    klog_info("Type on serial port, characters will be echoed...\n");

    while (true) {
        if (uart_haschar()) {
            char c = uart_getchar();
            async_serial_putc(c);  // 回显
        }
    }
}
```

## Shell 实战

### VGA Shell 启动

VGA Shell 是主要的用户界面。初始化完成后，我们直接启动 VGA Shell，用户可以通过键盘与系统交互。

```c
void kernel_main(void) {
```

## Serial Shell 配置

### QEMU 参数配置

使用 Serial Shell 需要配置 QEMU 的串口重定向。关键参数是 `-serial stdio`，它把串口输出重定向到标准输入输出。

```bash
qemu-system-x86_64 \
    -drive format=raw,file=build/boot.img \
    -serial stdio \
    -nographic
```

`-nographic` 参数可以禁用 VGA 输出，只使用串口。这在无显示头的环境中很有用。

### Serial Shell 启动

如果只想使用串口，可以在 kernel_main 中直接启动 Serial Shell，或者在 VGA Shell 退出后自动切换到 Serial Shell。

```c
void kernel_main(void) {
    kernel_init();

    klog_info("Starting Serial Shell...\n");

    shell_run(serial_shell_backend());

    klog_info("Serial Shell exited\n");
}
```

## 性能与调试

### 中断频率统计

每个驱动都会统计中断次数，我们可以通过这些统计信息来了解系统的运行状态。比如键盘中断次数可以反映用户的输入频率，定时器滴答数可以测量系统运行时间。

```c
void test_interrupt_frequency(void) {
    klog_info("=== Interrupt Frequency Test ===\n");

    // 记录初始值
    uint64_t keyboard_count = keyboard_get_interrupt_count();
    uint64_t rtc_count = rtc_get_interrupt_count();

    // 等待 1 秒
    uint64_t start = timer_get_ticks();
    while (timer_get_ticks() - start < 1000) {
        __asm__ volatile("hlt");
    }

    // 打印结果
    klog_info("Keyboard interrupts: %llu\n", keyboard_get_interrupt_count() - keyboard_count);
    klog_info("RTC interrupts: %llu\n", rtc_get_interrupt_count() - rtc_count);
}
```

### 缓冲区性能测试

缓冲区性能测试可以验证中断驱动的串口在高负载下的表现。我们发送大量数据，测量发送所需的时间。

```c
void test_buffer_performance(void) {
    klog_info("=== Buffer Performance Test ===\n");

    const int DATA_SIZE = 10000;
    char* data = "Hello, World! ";

    uint64_t start = timer_get_ticks();

    for (int i = 0; i < DATA_SIZE; i++) {
        async_serial_puts(data);
    }

    // 等待发送完成
    while (!tx_is_empty()) {
        __asm__ volatile("pause");
    }

    uint64_t end = timer_get_ticks();
    klog_info("Sent %d bytes in %llu ms\n", DATA_SIZE * 13, end - start);
}
```

## 常见问题排查

### 系统启动后无反应

这是个让人头疼的问题，但通常有几个常见的坑。第一个是中断没有启用，我们最后调用了 interrupt_finalize() 吗？第二个是 PIC 没有正确初始化，IRQ 被屏蔽了。

排查的时候可以先检查中断是否启用，然后查看 PIC 的状态寄存器。如果还不行，可以用调试输出逐步定位问题。

### 键盘输入无响应

键盘不工作有几个可能：键盘初始化失败、IRQ 1 没启用、或者扫描码集不对。我们可以检查 keyboard_init 的返回值，也可以查看键盘中断计数是否在增加。

如果完全没有中断，说明 IRQ 1 可能被屏蔽了。如果有中断但行为不对，可能是扫描码解析的问题。

### 串口无输出

串口无输出首先要确认 QEMU 参数是否正确，是否包含了 `-serial stdio`。然后检查串口初始化是否成功，IRQ 4 是否启用。

如果这些都没问题，但仍然没有输出，可能是串口参数配置错误，比如波特率不匹配。可以用串口调试工具先确认连接正常。

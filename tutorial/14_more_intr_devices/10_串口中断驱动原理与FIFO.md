# 10 - 串口中断驱动原理与 FIFO

在之前的阶段我们实现了一个轮询模式的串口驱动，说实话，虽然能用，但效率真的很低。每次发送或接收数据，CPU 都要在那里空等，什么其他事情都做不了。这一节我们要把串口升级到中断驱动模式，充分利用 UART 16550 的 FIFO 机制，让串口效率上一个台阶。

---

## 轮询模式的问题在哪

### 发送端的困境

轮询发送的代码写起来很简单，就是不断检查发送保持寄存器是否为空，空了就写入下一个字节。问题在于，如果我们要发送一个长字符串，CPU 大部分时间都在等待串口硬件把数据发出去。在 115200 波特率下，发送一个字节大约需要 87 微秒，这对于现代 CPU 来说简直是漫长得要命。

### 接收端的困境

接收端的问题更严重。轮询模式下，我们必须不断检查是否有数据到达，否则就会丢失数据。这意味着 CPU 要么高频轮询，要么就可能错过数据。而且，如果数据来得太快，轮询间隔太大会导致缓冲区溢出。

---

## 中断驱动的优势

中断驱动模式的核心思想是让硬件在需要 CPU 注意的时候主动通知 CPU，而不是让 CPU 主动去查询。对于串口来说，这意味着当发送保持寄存器空的时候触发中断，当有数据到达的时候也触发中断。

这样，CPU 可以在串口操作之间做其他有用的工作，不用一直等待。对于发送，我们可以把数据放到缓冲区，然后让中断处理器自动处理发送。对于接收，中断处理器会自动把数据放到缓冲区，主程序随时可以取用。这就是典型的生产者-消费者模式。

---

## UART 16550 的 FIFO 机制

### 从单字节到 FIFO

早期的 8250 UART 确实只有一个字节的缓冲区，每次只能收发一个字节，这意味着每传输一个字节就要触发一次中断。16550 及后续型号引入了 14 字节的 FIFO 缓冲区，这是个巨大的改进。

FIFO 的好处是显而易见的：中断频率降低了 14 倍，CPU 开销大幅减少。而且，FIFO 还可以设置触发阈值，当 FIFO 中达到一定数量的字节时才触发中断，进一步优化性能。

### FIFO 控制寄存器

FIFO 控制寄存器位于端口偏移 +2，它的位定义有点复杂，但我们需要关心的主要是几个位：bit 0 控制 FIFO 使能，bit 1 和 bit 2 分别控制 RX 和 TX FIFO 的清空，bit 6 到 bit 7 设置中断阈值。

常用的配置值是 0xC7，这个值做了几件事：使能 FIFO，清空 RX 和 TX FIFO，设置 14 字节的中断阈值。这样配置后，当接收 FIFO 中有 14 字节数据时，或者发送 FIFO 空的时候，才会触发中断。

---

## 中断使能与识别

### 中断使能寄存器

中断使能寄存器位于端口偏移 +1，它的四个低位分别控制四种中断类型：bit 0 使能接收数据可用中断，bit 1 使能发送保持寄存器空中断，bit 2 使能接收线状态中断，bit 3 使能 Modem 状态中断。

对于我们的实现，通常只需要使能接收和线状态中断。发送中断在有数据要发送的时候才启用，发送完成后立即禁用，这样可以避免中断风暴。

### 中断识别寄存器

当 IRQ 4 触发时，我们需要读取中断识别寄存器来判断具体是什么类型的中断。这个寄存器的 bit 0 表示是否有中断待处理，bit 1 到 bit 3 表示中断源。

中断源代码有几种：0x06 表示接收线状态（通常是错误），0x04 表示接收数据可用，0x0C 表示字符超时，0x02 表示发送保持寄存器空，0x00 表示 Modem 状态。我们需要在中断处理器中根据这些代码执行相应的操作。

---

## 环形缓冲区的设计

### 为什么需要环形缓冲区

中断驱动模式下，我们需要在主程序和中断处理器之间传递数据。环形缓冲区（也叫循环队列）是实现这个的好方法。它有两个指针：head 指向下一个写入位置，tail 指向下一个读取位置。

当 head 和 tail 相等时，缓冲区为空；当 (head + 1) % size == tail 时，缓冲区为满。这种设计的好处是读写操作都是 O(1) 时间复杂度，而且不需要移动数据。

### 发送缓冲区的实现

发送缓冲区用于暂存等待发送的数据。当主程序调用发送函数时，数据被写入缓冲区，然后启用发送中断。中断处理器会在发送保持寄存器空的时候从缓冲区读取数据并发送。

关键的一点是，当缓冲区空的时候要立即禁用发送中断，否则会触发中断风暴——发送空中断会一直触发，直到被禁用。这是个常见的坑，很多新手都会在这里卡住。

### 接收缓冲区的实现

接收缓冲区用于暂存接收到的数据。中断处理器在收到数据时把它写入缓冲区，主程序随时可以读取。如果缓冲区满了，新到的数据只能丢弃，所以要根据实际数据速率选择合适的缓冲区大小。

---

## 中断处理流程

### 发送中断处理

当发送保持寄存器空的中断触发时，我们首先检查发送缓冲区是否还有数据。如果有，就读取一个字节写入发送寄存器；如果没有，就禁用发送中断。

这个逻辑很简单，但实现时要小心竞态条件。主程序可能在检查缓冲区和启用中断之间被中断打断，所以通常需要禁用中断来保护临界区。

### 接收中断处理

当接收到数据的中断触发时，我们读取线路状态寄存器来判断是否有错误。如果一切正常，就从接收寄存器读取数据并写入接收缓冲区。由于有 FIFO，我们可能一次中断要读取多个字节。

处理接收超时中断（0x0C）的逻辑类似，也是读取所有可用数据直到 FIFO 空。这确保了即使在低数据速率的情况下，数据也不会长时间停留在 FIFO 中。

### 线状态中断处理

线状态中断通常表示发生了某种错误，比如溢出错误、奇偶错误或帧错误。我们读取线路状态寄存器来清除中断，然后可以记录错误统计或者采取其他恢复措施。

---

## 中断驱动的数据流

### 发送流程

主程序调用 async_serial_puts("hello")，函数把字符串写入发送缓冲区，然后启用发送中断。此时主程序可以返回继续做其他事情。当 UART 的发送保持寄存器变空时，触发中断，中断处理器从缓冲区读取一个字节并发送。如果缓冲区空了，禁用发送中断。

### 接收流程

数据到达 UART，硬件把它放入接收 FIFO。当 FIFO 达到阈值或者超时，触发接收中断。中断处理器读取所有可用数据并写入接收缓冲区。主程序调用 uart_getchar() 从缓冲区读取数据，如果没有数据就阻塞等待。

---

## 关键优化点

### 动态控制发送中断

发送中断不需要一直启用。正确的做法是：当有数据要发送时启用中断，缓冲区空的时候禁用中断。这样可以避免不必要的中断，提高整体效率。

### 中断保护

在访问共享的缓冲区指针时，需要禁用中断来保护临界区。这通常通过 cli 指令实现，但在临界区要尽可能短，以免影响系统的实时性。

### FIFO 阈值选择

14 字节的阈值是默认值，但可以根据实际需求调整。如果数据包大小固定，可以调整阈值到接近数据包大小，减少中断次数。

# 实现核心数据结构

在上一篇中，我们讨论了堆分配器的设计基础。现在让我们把这些设计转化为代码。说实话，写代码之前的准备工作其实比写代码本身更重要，因为如果设计有问题，后面改起来会非常痛苦。但好在我们已经把设计讨论清楚了，现在可以放心地开始实现了。

首先，我们需要在内核源码树中创建一个新的目录来存放堆分配器的代码。按照项目的组织结构，我们把堆分配器放在 `kernel/mm/heap/` 目录下。

```bash
cd /home/charliechen/CCOperatingSystemX64

# 创建堆分配器目录
mkdir -p kernel/mm/heap

# 确认目录创建成功
ls -la kernel/mm/
```

你应该能看到 `heap` 目录已经创建成功。这步虽然简单，但有个细节值得注意：我们把堆分配器放在 `mm`（Memory Management）目录下，而不是直接放在 `kernel` 根目录。这体现了良好的代码组织原则 —— 相关的模块放在一起，结构清晰，便于维护。

## 第二步：创建配置文件

我们先把一些配置常量定义在一个单独的头文件中。这样做的好处是，如果以后需要调整参数，只需要修改这一个文件。

创建 `kernel/mm/heap/heap_config.h`：

```c
#pragma once

/* ==============================================================================
 * Heap Allocator Configuration Constants
 * ==============================================================================
 * These constants control the behavior of the heap allocator.
 * Modify with care - changing these can affect performance and memory usage.
 * ============================================================================== */

/* Heap block alignment (must be power of 2)
 * This ensures user pointers are aligned, which is important for performance
 * and required by some instructions (SSE, AVX, etc.)
 */
#define HEAP_ALIGN 16

/* Minimum allocation size
 * Requests smaller than this will be rounded up to HEAP_MIN_ALLOC.
 * Setting this too low can lead to excessive fragmentation.
 */
#define HEAP_MIN_ALLOC 16

/* Minimum block size (header + minimum user data)
 * Blocks smaller than this won't be split during allocation.
 * This prevents creating tiny free blocks that are useless.
 */
#define HEAP_MIN_BLOCK 32

/* Initial heap size in pages (64KB = 16 pages)
 * The heap starts small and grows on demand.
 * This value balances startup overhead and initial capacity.
 */
#define HEAP_INIT_PAGES 16
```

这些常量的选择都是有理由的。`HEAP_ALIGN` 设为 16 字节，满足大多数性能要求，同时不会浪费太多内存。`HEAP_MIN_ALLOC` 设为 16 字节，因为块头部本身就要占空间，太小的分配没有意义。`HEAP_MIN_BLOCK` 设为 32 字节，确保分割后的剩余部分至少能容纳一个块头部加上一些数据。`HEAP_INIT_PAGES` 设为 16 页（64KB），这是堆的初始大小，后续会按需扩展。

## 第三步：定义返回码和统计结构

接下来我们定义堆分配器的返回码和统计信息结构。这些是公共 API 的一部分，会放在头文件中供其他模块使用。

创建 `kernel/mm/heap/heap.h`：

```c
/* ==============================================================================
 * CCOS - Kernel Heap Allocator
 * ==============================================================================
 * This module provides dynamic memory allocation (kmalloc/kfree) for the
 * kernel. It implements a best-fit allocator with free block coalescing.
 * ============================================================================== */

#pragma once

#include "defines/types.h"

/* ==============================================================================
 * Result Codes
 * ============================================================================== */

typedef enum {
    HEAP_OK = 0,
    HEAP_ERR_NOT_INIT = -1,
    HEAP_ERR_OOM = -2,
    HEAP_ERR_INVALID = -3,
    HEAP_ERR_DOUBLE_FREE = -4,
    HEAP_ERR_CORRUPTED = -5,
} heap_result_t;

/* ==============================================================================
 * Statistics
 * ============================================================================== */

typedef struct {
    uint64_t total_bytes;  /* Total heap bytes managed */
    uint64_t used_bytes;   /* Bytes currently allocated */
    uint64_t free_bytes;   /* Bytes available */
    uint64_t total_blocks; /* Total blocks in heap */
    uint64_t used_blocks;  /* Allocated blocks */
    uint64_t free_blocks;  /* Free blocks */
    uint64_t alloc_count;  /* Total allocations */
    uint64_t free_count;   /* Total frees */
    uint64_t expand_count; /* Times heap expanded */
} heap_stats_t;
```

返回码的设计很直观。`HEAP_OK` 表示成功，其他各种错误码对应不同的失败情况。注意我们把错误码定义为负数，这样可以用一个返回值同时表示成功（0）和失败（非零），这在 C 语言中是个常见的做法。

统计结构包含了各种有用的信息。`total_bytes` 是堆管理的总字节数，`used_bytes` 是已使用字节数，`free_bytes` 是空闲字节数。`total_blocks`、`used_blocks`、`free_blocks` 分别是总块数、已用块数、空闲块数。`alloc_count` 和 `free_count` 是累计分配和释放次数，这两个值可以用来检测内存泄漏 —— 如果分配次数远大于释放次数，说明可能有内存泄漏。`expand_count` 记录堆扩展的次数，可以用来分析堆的增长模式。

## 第四步：声明公共 API

现在我们来声明堆分配器的公共 API。这些函数会被内核的其他模块调用，所以接口设计要清晰易用。

在 `heap.h` 中继续添加：

```c
/* ==============================================================================
 * API
 * ============================================================================== */

/**
 * heap_init - Initialize the kernel heap allocator
 *
 * Sets up the heap region and initial free block.
 * Must be called after vmm_init().
 *
 * @return HEAP_OK on success, error code otherwise
 */
heap_result_t heap_init(void);

/**
 * kmalloc - Allocate memory from kernel heap
 *
 * @param size Number of bytes to allocate
 * @return Pointer to allocated memory, or NULL if out of memory
 */
void* kmalloc(size_t size);

/**
 * kfree - Free memory allocated from kernel heap
 *
 * @param ptr Pointer to memory to free (NULL is safe)
 */
void kfree(void* ptr);

/**
 * krealloc - Reallocate memory with new size
 *
 * If ptr is NULL, equivalent to kmalloc(new_size).
 * If new_size is 0, equivalent to kfree(ptr).
 *
 * @param ptr Original pointer (may be NULL)
 * @param new_size New size in bytes
 * @return Pointer to reallocated memory, or NULL if failed
 */
void* krealloc(void* ptr, size_t new_size);

/**
 * kmalloc_aligned - Allocate aligned memory
 *
 * @param size Number of bytes to allocate
 * @param alignment Alignment in bytes (must be power of 2)
 * @return Pointer to aligned memory, or NULL if failed
 */
void* kmalloc_aligned(size_t size, size_t alignment);

/**
 * heap_get_stats - Get heap statistics
 *
 * @param stats Pointer to stats structure to fill
 * @return HEAP_OK on success
 */
heap_result_t heap_get_stats(heap_stats_t* stats);

/**
 * heap_dump - Dump heap state for debugging
 *
 * Prints current heap status and block information.
 */
void heap_dump(void);
```

这些 API 的设计与标准 C 库的 `malloc`、`free`、`realloc` 类似，但有一些针对内核环境的调整。比如 `kfree(NULL)` 是安全的，不需要像标准 C 库那样检查。`kmalloc_aligned` 是标准 C 库没有的，但在内核环境中很重要，用于 DMA 和 SIMD 等需要特定对齐的场景。

## 第五步：实现内部数据结构

接下来我们实现堆分配器的内部数据结构。这些结构只在 `heap.c` 内部使用，外部不需要知道细节。

创建 `kernel/mm/heap/heap.c`：

```c
/* ==============================================================================
 * CCOS - Kernel Heap Allocator Implementation
 * ============================================================================== */

#include "mm/heap/heap.h"
#include "assert/assert.h"
#include "base/memory.h"
#include "heap_config.h"
#include "klogs/kprintf.h"
#include "math/bits.h"
#include "mm/pframe/pframe.h"
#include "mm/vmm/vmm.h"
#include "sync/spinlock.h"

/* ==============================================================================
 * Internal Constants
 * ============================================================================== */

#define HEAP_BLOCK_MAGIC 0x00114514 /* "HEAP" magic number for debugging */

/* ==============================================================================
 * Internal Data Structures
 * ============================================================================== */

/**
 * @brief Heap block header
 *
 * Each block (free or allocated) has this header.
 * The heap is a contiguous sequence of blocks.
 * Aligned to 16 bytes to ensure user pointers are also aligned.
 */
typedef struct heap_block {
    uint64_t size;           /* Total block size including header */
    bool used;               /* true = allocated, false = free */
    struct heap_block* prev; /* Previous block in physical order */
    struct heap_block* next; /* Next block in free list (only valid if free) */
    uint32_t magic;          /* Magic number for corruption detection */
    uint32_t _padding;       /* Explicit padding to make size 16-byte aligned */
} __attribute__((aligned(16))) heap_block_t;

/**
 * @brief Heap state
 */
typedef struct {
    virtual_addr_t heap_start; /* Start of heap region */
    virtual_addr_t heap_end;   /* End of heap region */
    virtual_addr_t heap_brk;   /* Current heap break (top of allocated space) */
    heap_block_t* free_list;   /* Head of free list (best-fit search) */
    heap_stats_t stats;        /* Statistics */
    bool initialized;
} heap_state_t;

/* ==============================================================================
 * Internal State
 * ============================================================================== */

static heap_state_t s_heap = {0};

/* Spinlock protecting the heap allocator state */
static spinlock_t s_heap_lock = SPIN_LOCK_INIT;
```

`heap_block_t` 结构体我们在上一篇中详细讨论过，这里就不重复了。`heap_state_t` 结构体保存了堆的全局状态，包括堆的起始地址、结束地址、当前堆顶、空闲链表头、统计信息和初始化标志。

`s_heap` 是静态全局变量，保存堆的当前状态。`s_heap_lock` 是一个自旋锁，用于在多核环境下保护堆的状态。虽然我们现在还没有实现多核，但提前加上锁是个好习惯，避免以后忘记。

## 第六步：实现辅助函数

现在我们来实现一些辅助函数，这些函数会被核心逻辑调用。它们虽然不是 API 的一部分，但非常重要。

在 `heap.c` 中继续添加：

```c
/* ==============================================================================
 * Internal Helper Functions
 * ============================================================================== */

/**
 * align_size - Align size to HEAP_ALIGN boundary
 */
static inline size_t align_size(size_t size) {
    return (size + HEAP_ALIGN - 1) & ~(HEAP_ALIGN - 1);
}

/**
 * total_block_size - Calculate total block size including header
 */
static inline size_t total_block_size(size_t user_size) {
    return align_size(user_size) + sizeof(heap_block_t);
}

/**
 * block_to_ptr - Convert block pointer to user pointer
 */
static inline void* block_to_ptr(heap_block_t* block) {
    return (void*)((virtual_addr_t)block + sizeof(heap_block_t));
}

/**
 * ptr_to_block - Convert user pointer to block pointer
 */
static inline heap_block_t* ptr_to_block(void* ptr) {
    return (heap_block_t*)((virtual_addr_t)ptr - sizeof(heap_block_t));
}

/**
 * next_block - Get the next block in physical memory order
 */
static inline heap_block_t* next_block(heap_block_t* block) {
    return (heap_block_t*)((virtual_addr_t)block + block->size);
}

/**
 * is_last_block - Check if this is the last block
 */
static inline bool is_last_block(heap_block_t* block) {
    virtual_addr_t next_addr = (virtual_addr_t)next_block(block);
    return (next_addr >= s_heap.heap_brk) || (next_addr >= s_heap.heap_end);
}
```

`align_size` 函数把大小向上对齐到 HEAP_ALIGN 边界。这个函数使用了一个巧妙的位运算技巧：`(size + HEAP_ALIGN - 1) & ~(HEAP_ALIGN - 1)`。因为 HEAP_ALIGN 是 16，它的二进制是 `0b10000`，`HEAP_ALIGN - 1` 是 `0b01111`，取反后是 `...11110000`。与上这个掩码就把低 4 位清零，实现了向上对齐。

`total_block_size` 计算包含头部在内的总块大小。它先对齐用户请求的大小，然后加上块头部的大小。

`block_to_ptr` 和 `ptr_to_block` 是两个互相逆转换的函数。`block_to_ptr` 从块指针计算出用户数据指针，就是块指针加上头部大小。`ptr_to_block` 从用户数据指针计算出块指针，就是用户数据指针减去头部大小。这两个转换会被频繁使用，所以做成内联函数。

`next_block` 根据当前块的地址和大小，计算出下一个块的地址。因为块是连续排列的，下一个块的地址就是当前块地址加上当前块大小。

`is_last_block` 判断当前块是否是最后一个块。如果下一个块的地址已经达到或超过堆顶，或者已经超出堆区域，那当前块就是最后一个了。

## 第七步：配置 CMake 构建系统

现在我们需要把这些文件加入到构建系统中。创建 `kernel/mm/heap/CMakeLists.txt`：

```cmake
# ============================================================================
# Kernel Heap Allocator
# ============================================================================

add_library(kernel_heap STATIC
    heap.c
)

target_include_directories(kernel_heap PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}
    ${CMAKE_CURRENT_SOURCE_DIR}/..
    ${CMAKE_CURRENT_SOURCE_DIR}/../..
    ${CMAKE_BINARY_DIR}/include
)

target_compile_options(kernel_heap PUBLIC ${CCOS_FREESTANDING_FLAGS})

if(CCOS_ENABLE_FRAME_POINTER)
    target_compile_options(kernel_heap PUBLIC ${CCOS_FRAME_POINTER_FLAGS})
endif()

target_link_libraries(kernel_heap PUBLIC
    kernel_vmm
    klogs
    base
    assert
)

set_target_properties(kernel_heap PROPERTIES
    POSITION_INDEPENDENT_CODE FALSE
)
```

这个 CMake 配置文件定义了一个静态库 `kernel_heap`，包含 `heap.c`。我们设置了头文件搜索路径，确保能找到 `defines/types.h`、`mm/vmm/vmm.h` 等头文件。我们还指定了编译选项，比如 `CCOS_FREESTANDING_FLAGS`，这是编译内核代码所需的特殊选项。最后，我们列出了依赖的库：`kernel_vmm`（虚拟内存管理）、`klogs`（日志输出）、`base`（基础工具函数）、`assert`（断言）。

确保 `kernel/mm/CMakeLists.txt` 包含 `heap` 子目录。检查一下，应该有这一行：

```cmake
add_subdirectory(heap)
```

如果没有就加上。这步很简单，但很容易漏掉。如果忘记添加子目录，CMake 不会编译我们的代码，链接时会报找不到符号的错误。

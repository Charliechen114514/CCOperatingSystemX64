# 实现高级功能

在之前的文章中，我们实现了堆分配器的核心功能：`kmalloc` 分配、`kfree` 释放、堆扩展。这些功能已经能让堆分配器正常工作了。但还有一些高级功能，虽然不是必需的，但在实际使用中非常方便。这篇文章我们会实现 `krealloc`（重新分配内存大小）和 `kmalloc_aligned`（对齐分配）。

---

## 环境说明

这篇文章假设你已经完成了前面的步骤，堆分配器的核心功能已经实现。我们会在 `heap.c` 中继续添加代码。

## 第一步：实现 krealloc

`krealloc` 是一个很实用的函数，它可以调整已分配内存的大小。想想看，你分配了一个缓冲区来存储数据，但数据量增长超出了预期，这时候 `krealloc` 就能派上用场了。

`krealloc` 的行为是这样的：
- 如果 `ptr` 是 NULL，等同于 `kmalloc(new_size)`
- 如果 `new_size` 是 0，等同于 `kfree(ptr)`，返回 NULL
- 如果新大小小于等于旧大小，直接返回原指针（不缩小）
- 如果新大小大于旧大小，分配新块、复制数据、释放旧块

在 `heap.c` 中添加：

```c
/**
 * krealloc - Reallocate memory with new size
 *
 * @param ptr Original pointer (may be NULL)
 * @param new_size New size in bytes
 * @return Pointer to reallocated memory, or NULL if failed
 *
 * Note: If allocation fails, original block is not freed.
 */
void* krealloc(void* ptr, size_t new_size) {
    /* Handle NULL pointer - equivalent to kmalloc */
    if (ptr == NULL) {
        return kmalloc(new_size);
    }

    /* Handle zero size - equivalent to kfree */
    if (new_size == 0) {
        kfree(ptr);
        return NULL;
    }

    spinlock_flags_t flags;
    spin_lock_irqsave(&s_heap_lock, &flags);

    if (!s_heap.initialized) {
        klog_error("[HEAP] Not initialized\n");
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return NULL;
    }

    /* Get current block */
    heap_block_t* old_block = ptr_to_block(ptr);

    if (!validate_block(old_block) || !old_block->used) {
        klog_error("[HEAP] Invalid pointer in krealloc\n");
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return NULL;
    }

    size_t old_user_size = old_block->size - sizeof(heap_block_t);

    /* If new size fits in old block, just return it */
    size_t new_total = total_block_size(new_size);
    if (new_total <= old_block->size) {
        /* Shrink or same size - could split here but skip for simplicity */
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return ptr;
    }

    spin_unlock_irqrestore(&s_heap_lock, flags);

    /* Need to allocate new block */
    void* new_ptr = kmalloc(new_size);
    if (new_ptr == NULL) {
        return NULL;
    }

    /* Copy data - only the smaller of old and new size */
    size_t copy_size = old_user_size < new_size ? old_user_size : new_size;
    memcpy(new_ptr, ptr, copy_size);

    /* Free old block */
    kfree(ptr);

    return new_ptr;
}
```

`krealloc` 的逻辑分为几个情况处理。首先处理边界情况：`ptr` 为 NULL 等同于分配新内存，`new_size` 为 0 等同于释放内存。这两种情况可以直接调用已有的函数。

然后我们验证原指针的有效性，获取原块的信息。如果新大小能放进旧块里，直接返回原指针。这里我们没有实现块的收缩（虽然可以分割块），为了简单起见，只有扩大分配才申请新块。

如果需要扩大，我们先分配新块，然后把旧块的数据复制到新块。复制的大小取新旧大小的较小值，避免越界。最后释放旧块，返回新指针。

注意这里有个重要的细节：如果分配新块失败，我们返回 NULL，但旧块没有被释放。这是标准 `realloc` 的约定，调用者仍然可以使用旧块。如果我们在分配失败时释放了旧块，数据就丢失了，这是个严重的 bug。

## 第二步：实现 kmalloc_aligned

对齐分配是一个特殊的需求。普通的 `kmalloc` 只保证 16 字节对齐，但有些场景需要更大的对齐。比如 DMA 操作通常需要 4KB 对齐，AVX 指令可能需要 32 字节对齐。`kmalloc_aligned` 就是为此设计的。

在 `heap.c` 中添加：

```c
/**
 * kmalloc_aligned - Allocate aligned memory
 *
 * @param size Number of bytes to allocate
 * @param alignment Alignment in bytes (must be power of 2)
 * @return Pointer to aligned memory, or NULL if failed
 *
 * Note: Allocated memory must be freed with normal kfree.
 * The original pointer is stored just before the returned pointer.
 */
void* kmalloc_aligned(size_t size, size_t alignment) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&s_heap_lock, &flags);

    if (!s_heap.initialized) {
        klog_error("[HEAP] Not initialized\n");
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return NULL;
    }

    if (size == 0) {
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return NULL;
    }

    /* Validate alignment: must be power of 2 */
    if (alignment == 0 || (alignment & (alignment - 1)) != 0) {
        klog_error("[HEAP] Invalid alignment: %lu (must be power of 2)\n",
                   alignment);
        spin_unlock_irqrestore(&s_heap_lock, flags);
        return NULL;
    }

    /* Minimum alignment is HEAP_ALIGN */
    if (alignment < HEAP_ALIGN) {
        alignment = HEAP_ALIGN;
    }

    spin_unlock_irqrestore(&s_heap_lock, flags);

    /* Allocate extra space for alignment and storing original pointer */
    size_t total_size = total_block_size(size) + alignment + sizeof(virtual_addr_t*);

    void* raw_ptr = kmalloc(total_size);
    if (raw_ptr == NULL) {
        return NULL;
    }

    /* Calculate aligned address */
    virtual_addr_t raw_start = (virtual_addr_t)raw_ptr;
    virtual_addr_t aligned_addr = align_up(raw_start + sizeof(virtual_addr_t*),
                                           alignment);

    /* Store original pointer just before aligned address */
    virtual_addr_t* orig_ptr_loc = (virtual_addr_t*)(aligned_addr -
                                                      sizeof(virtual_addr_t*));
    *orig_ptr_loc = raw_start;

    klog_trace("[HEAP] Aligned allocation: raw=0x%llX, aligned=0x%llX, align=%lu\n",
               raw_start, aligned_addr, alignment);

    return (void*)aligned_addr;
}
```

`kmalloc_aligned` 的实现有个巧妙的技巧。为了返回一个对齐的地址，我们分配比需要更多的空间，然后在这段空间中找到对齐的位置返回给用户。但这里有个问题：释放时我们需要找到真正的块头部，否则 `kfree` 会计算出错误的地址。

解决方案是：在对齐地址之前存储原始指针。这样释放时，我们可以通过这个原始指针找到真正的块头部。具体来说，我们分配 `total_block_size(size) + alignment + sizeof(virtual_addr_t*)` 这么多空间，其中 `alignment` 确保我们能找到一个对齐的位置，`sizeof(virtual_addr_t*)` 用于存储原始指针。

找到对齐地址后，我们在这个地址前存储原始指针。这样 `kfree` 可以通过 `ptr_to_block` 函数检测到这是对齐分配，恢复原始指针。

对齐验证使用了一个位运算技巧：`(alignment & (alignment - 1)) != 0` 可以检测一个数是否不是 2 的幂。如果 `alignment` 是 2 的幂，它的二进制表示只有一个 1，减 1 后这个 1 变成 0，后面的位都变成 1，与上原值就是 0。如果不是 2 的幂，结果就不是 0。

## 第三步：更新 ptr_to_block 支持对齐分配

为了让 `kfree` 能正确处理对齐分配的指针，我们需要更新 `ptr_to_block` 函数，让它能检测并恢复原始指针。

修改 `heap.c` 中的 `ptr_to_block` 函数：

```c
/**
 * ptr_to_block - Convert user pointer to block pointer
 *
 * This function handles both normal and aligned allocations.
 * For aligned allocations, it recovers the original pointer.
 */
static inline heap_block_t* ptr_to_block(void* ptr) {
    virtual_addr_t addr = (virtual_addr_t)ptr;

    /* Check if there's an original pointer stored before this address */
    /* This happens with kmalloc_aligned allocations */
    virtual_addr_t* orig_ptr_loc = (virtual_addr_t*)(addr - sizeof(virtual_addr_t*));

    /* Check if the value at orig_ptr_loc points to a valid heap region */
    if (*orig_ptr_loc >= s_heap.heap_start &&
        *orig_ptr_loc < s_heap.heap_brk &&
        (*orig_ptr_loc & 0xF) == 0) {  /* 16-byte aligned hint */

        /* orig_ptr_loc stores the user pointer of the raw allocation,
         * so we need to go back further to get the block header */
        virtual_addr_t raw_user_ptr = *orig_ptr_loc;
        heap_block_t* potential_block = (heap_block_t*)
                                        (raw_user_ptr - sizeof(heap_block_t));

        /* Verify this is a valid block with correct magic */
        if (potential_block->magic == HEAP_BLOCK_MAGIC) {
            /* Verify the aligned address is actually within this block */
            virtual_addr_t block_start = raw_user_ptr;
            virtual_addr_t block_end = raw_user_ptr +
                                       potential_block->size - sizeof(heap_block_t);
            if (addr >= block_start && addr < block_end) {
                return potential_block;
            }
        }
    }

    /* Normal allocation: block header is immediately before user pointer */
    return (heap_block_t*)(addr - sizeof(heap_block_t));
}
```

更新后的 `ptr_to_block` 函数首先尝试检测这是否是对齐分配。它检查指针前面的地址是否存储了一个有效的堆指针。如果是，并且这个指针指向的块有正确的魔数，并且当前对齐地址确实在这个块的范围内，我们就认为这是对齐分配，返回真正的块头部。

如果检测失败，我们就假设这是普通分配，块头部紧挨着用户数据指针。这样 `kfree` 可以正确处理两种分配方式，用户不需要记住是用哪种方式分配的，统一用 `kfree` 释放就行。

## 第四步：测试 krealloc

让我们写一个测试来验证 `krealloc` 是否正常工作：

```c
void test_krealloc(void) {
    klog_info("=== krealloc 测试 ===\n");

    /* 测试扩大分配 */
    char* str = (char*)kmalloc(16);
    if (str != NULL) {
        strcpy(str, "Hello, World!");
        klog_info("Original: %s\n", str);

        str = (char*)krealloc(str, 64);
        if (str != NULL) {
            strcat(str, " How are you?");
            klog_info("Expanded: %s\n", str);
            kfree(str);
        }
    }

    /* 测试缩小分配 */
    int* arr = (int*)kmalloc(100 * sizeof(int));
    if (arr != NULL) {
        for (int i = 0; i < 100; i++) {
            arr[i] = i;
        }

        arr = (int*)krealloc(arr, 10 * sizeof(int));
        if (arr != NULL) {
            klog_info("After shrink: arr[0]=%d, arr[9]=%d\n", arr[0], arr[9]);
            kfree(arr);
        }
    }

    /* 测试 NULL 输入 */
    void* ptr = krealloc(NULL, 32);
    if (ptr != NULL) {
        klog_info("krealloc(NULL, 32) works like kmalloc\n");
        kfree(ptr);
    }

    /* 测试零大小 */
    ptr = kmalloc(32);
    ptr = krealloc(ptr, 0);
    if (ptr == NULL) {
        klog_info("krealloc(ptr, 0) works like kfree\n");
    }

    klog_info("krealloc 测试完成\n");
}
```

这个测试涵盖了 `krealloc` 的各种使用场景。首先是扩大分配，分配一个小字符串，然后扩展成更大的字符串。其次是缩小分配，虽然我们的实现没有真正缩小，但至少验证了功能不会出错。然后是边界情况，`krealloc(NULL, size)` 应该等同于 `kmalloc`，`krealloc(ptr, 0)` 应该等同于 `kfree`。

## 第五步：测试 kmalloc_aligned

让我们写一个测试来验证 `kmalloc_aligned` 是否正常工作：

```c
void test_aligned_allocation(void) {
    klog_info("=== 对齐分配测试 ===\n");

    /* 测试 4KB 对齐（DMA 需求） */
    void* ptr1 = kmalloc_aligned(1024, 4096);
    if (ptr1 != NULL) {
        klog_info("Allocated 1024 bytes with 4KB alignment at 0x%llX\n",
                  (virtual_addr_t)ptr1);
        if (((virtual_addr_t)ptr1 & 0xFFF) == 0) {
            klog_info("Address is correctly 4KB aligned\n");
        } else {
            klog_error("Address is NOT 4KB aligned!\n");
        }
        kfree(ptr1);
    }

    /* 测试 32 字节对齐（AVX 需求） */
    void* ptr2 = kmalloc_aligned(256, 32);
    if (ptr2 != NULL) {
        klog_info("Allocated 256 bytes with 32-byte alignment at 0x%llX\n",
                  (virtual_addr_t)ptr2);
        if (((virtual_addr_t)ptr2 & 0x1F) == 0) {
            klog_info("Address is correctly 32-byte aligned\n");
        } else {
            klog_error("Address is NOT 32-byte aligned!\n");
        }
        kfree(ptr2);
    }

    /* 测试无效对齐 */
    void* ptr3 = kmalloc_aligned(100, 100);  /* 100 不是 2 的幂 */
    if (ptr3 == NULL) {
        klog_info("Correctly rejected invalid alignment\n");
    }

    klog_info("对齐分配测试完成\n");
}
```

这个测试验证了几种对齐分配场景。首先是 4KB 对齐，这是 DMA 操作常用的对齐要求。我们检查返回的地址是否真的是 4KB 对齐的（地址的低 12 位应该为 0）。其次是 32 字节对齐，这是 AVX 指令可能需要的。最后是无效对齐，100 不是 2 的幂，应该被拒绝。

## 第六步：高级功能的使用场景

让我们讨论一下这些高级函数的实际使用场景。

`krealloc` 在动态数据结构中非常有用。比如你实现一个动态数组，初始分配一些空间，当元素数量增长超出容量时，用 `krealloc` 扩展。这比每次都重新分配更高效，因为如果新大小能放进旧块，就不需要复制数据。

```c
typedef struct {
    int* data;
    size_t size;
    size_t capacity;
} vector_t;

void vector_push(vector_t* vec, int value) {
    if (vec->size >= vec->capacity) {
        /* 扩展容量 */
        vec->capacity *= 2;
        vec->data = (int*)krealloc(vec->data,
                                   vec->capacity * sizeof(int));
        if (vec->data == NULL) {
            /* 处理内存不足 */
            return;
        }
    }
    vec->data[vec->size++] = value;
}
```

`kmalloc_aligned` 在底层编程中必不可少。DMA 操作需要物理地址连续且对齐的内存，很多硬件都有这样的要求。SIMD 指令（SSE、AVX）对内存对齐有要求，不对齐的访问可能导致性能下降甚至异常。

```c
/* DMA 缓冲区示例 */
void setup_dma_transfer(void) {
    /* 分配 4KB 对齐的 DMA 缓冲区 */
    void* dma_buffer = kmalloc_aligned(8192, 4096);
    if (dma_buffer == NULL) {
        return;
    }

    /* 配置 DMA 控制器使用这个缓冲区 */
    // dma_controller_set_buffer(dma_buffer, 8192);

    /* 使用完毕后释放 */
    kfree(dma_buffer);
}

/* SIMD 数据示例 */
void process_with_avx(void) {
    /* 分配 32 字节对齐的数据，适合 AVX */
    float* data = (float*)kmalloc_aligned(256, 32);
    if (data == NULL) {
        return;
    }

    /* 使用 AVX 指令处理数据 */
    // __m256* vec = (__m256*)data;
    // ... AVX 操作 ...

    kfree(data);
}
```

## 到这里我们完成了什么

这篇文章我们实现了堆分配器的两个高级功能：`krealloc` 和 `kmalloc_aligned`。`krealloc` 可以调整已分配内存的大小，在动态数据结构中非常有用。`kmalloc_aligned` 可以分配满足特定对齐要求的内存，对于 DMA 操作和 SIMD 指令是必须的。我们还更新了 `ptr_to_block` 函数，让它能正确处理对齐分配的指针释放。

这些高级功能虽然不是堆分配器的核心，但在实际使用中非常方便。有了这些功能，我们的堆分配器就更加完整了，可以满足内核开发的各种需求。

# 进程管理与调度器集成 —— Stage 22 调度类框架实战指南（七）

## 前言

前面几篇文章我们实现了调度类框架、RR 调度类、Priority 调度类，还有时间片管理机制。但这些东西还独立运行着，没有和进程管理真正集成起来。

进程创建时需要设置调度策略，调度器需要从 PCB 中获取调度信息，进程切换需要调用调度器的接口。这些集成工作是让整个系统跑起来最后的一环。

说实话，集成工作往往比实现独立模块更让人头疼。因为你需要理解两个模块的边界在哪里，哪些数据应该由哪边负责。而且集成的时候往往会发现一些设计上的不一致，需要回头调整。

这篇文章我们会把调度类框架和进程管理真正集成起来。完成后，创建新进程时会自动设置调度策略，调度器可以正常调度各个进程，整个系统就能跑起来了。

---

## 现在我们要做什么

这篇文章的目标是完成调度器与进程管理的集成：

1. 扩展 PCB 结构体，嵌入调度实体
2. 修改 `proc_alloc_pcb()`，初始化调度实体
3. 修改 `proc_fork()`，为子进程设置调度策略
4. 修改 `schedule()` 函数，使用新的调度框架
5. 确保 `switch_to()` 与调度框架协调工作

---

## 扩展 PCB 结构

### sched_entity 嵌入 PCB

在 Stage 21 中，PCB 已经有了调度相关的字段（`run_list`），但没有完整的调度实体。现在我们需要把 `sched_entity_t` 嵌入 PCB：

```c
/* 在 process.h 中 */

typedef struct pcb {
    /* ... 原有字段 ... */

    /* ==============================================================================
     * Scheduling Entity
     * ==============================================================================
     */

    /**
     * @brief Per-task scheduling data
     * This structure is embedded directly in the PCB for efficiency.
     */
    sched_entity_t sched_entity;

    /* ... 其他字段 ... */

} pcb_t;
```

这里使用的是"嵌入"而不是"指针"。`sched_entity` 是 PCB 的一个直接字段，而不是动态分配的内存。这样做的好处是访问更快，不需要额外的内存分配和释放操作。

### scheduler_t 扩展

`scheduler_t` 结构体也需要扩展，添加调度类框架需要的字段：

```c
typedef struct scheduler {
    struct pcb* current;           /* 当前运行的任务 */
    struct pcb* idle;              /* idle 任务 */
    uint32_t     nr_running;       /* 运行中的任务数 */
    bool         need_resched;     /* 是否需要重调度 */

    /* 兼容 Stage 21 的运行队列 */
    list_head    run_queue;        /* 传统的全局运行队列（兼容） */

    /* 调度类框架字段 */
    sched_rq_t*  rq;               /* Per-policy 运行队列数组 */
    sched_class_t** classes;       /* 已注册的调度类数组 */

} scheduler_t;
```

`rq` 和 `classes` 字段会在 `sched_class_init()` 中设置，分别指向运行队列数组和调度类数组。

## PCB 分配集成

### proc_alloc_pcb() 修改

PCB 分配函数需要初始化调度实体：

```c
pcb_t* proc_alloc_pcb(void) {
    pcb_t* pcb = (pcb_t*)kmalloc(sizeof(pcb_t));
    if (!pcb) {
        return NULL;
    }

    /* 初始化为 0 */
    memset(pcb, 0, sizeof(pcb_t));

    /* ... 分配 cpu_ctx 和 kernel_stack ... */

    /* 初始化链表 */
    INIT_LIST_HEAD(&pcb->run_list);
    INIT_LIST_HEAD(&pcb->sched_entity.run_list);  /* 调度实体的队列节点 */

    /* 初始化 sched_entity 为默认值 */
    pcb->sched_entity.policy = SCHED_NORMAL;
    pcb->sched_entity.sched_class = NULL;  /* 稍后在 set_policy 中设置 */
    pcb->sched_entity.time_slice = DEF_TIMESLICE_MS;
    pcb->sched_entity.time_slice_total = DEF_TIMESLICE_MS;
    pcb->sched_entity.priority = PRIO_DEFAULT;
    pcb->sched_entity.nice = 0;
    pcb->sched_entity.last_ran = 0;

    /* ... 其他初始化 ... */

    return pcb;
}
```

这里我们把 `sched_entity` 初始化为默认值：使用 SCHED_NORMAL（RR）调度策略，默认优先级，默认时间片。

注意 `sched_class` 设为 NULL，这是正常的。调度类指针会在 `sched_set_policy()` 中设置。

## 进程创建集成

### proc_fork() 修改

进程创建函数需要为子进程设置调度策略：

```c
int32_t proc_fork(void) {
    /* 分配 PCB */
    pcb_t* child = proc_alloc_pcb();
    if (!child) {
        return -1;
    }

    /* ... 复制父进程状态、分配内存等 ... */

    /* 设置子进程的调度策略 */
    /* 默认使用 RR 调度，优先级为 0 */
    if (sched_set_policy(child, SCHED_NORMAL, 0) != 0) {
        kfree(child->cpu_ctx);
        kfree((void*)child->kernel_stack_base);
        kfree(child);
        return -1;
    }

    /* 初始化时间片 */
    sched_init_time_slice(child);

    /* 把子进程加入运行队列 */
    sched_enqueue_task(child, false);

    /* ... 其他操作 ... */

    return child->pid;
}
```

关键步骤：

1. 调用 `sched_set_policy()` 设置调度策略
2. 调用 `sched_init_time_slice()` 初始化时间片
3. 调用 `sched_enqueue_task()` 把任务加入运行队列

`sched_set_policy()` 内部会调用调度类的 `task_fork()` 函数，完成调度实体的初始化。

### 为关键进程设置 Priority 调度

有些关键进程（比如 init 进程）可能需要使用 Priority 调度：

```c
/* 创建 init 进程 */
pcb_t* init_proc = proc_create_init_process();

/* 使用 Priority 调度，优先级 0（最高） */
sched_set_policy(init_proc, SCHED_PRIORITY, 0);
sched_enqueue_task(init_proc, false);
```

Priority 调度会给予这些进程更快的响应速度，确保系统能够及时处理关键任务。

## 调度函数集成

### schedule() 完整实现

`schedule()` 函数是调度器的入口，需要与调度类框架紧密集成：

```c
void schedule(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    struct pcb* prev = scheduler.current;
    struct pcb* next;

    /* 选择下一个任务 */
    next = sched_pick_next_task();

    if (next == NULL) {
        /* 没有可运行的任务，切换到 idle */
        next = scheduler.idle;
    }

    if (next == prev) {
        /* 选择的还是当前任务，不需要切换 */
        sched_clear_resched_locked();
        spin_unlock_irqrestore(&g_scheduler_lock, flags);
        return;
    }

    /* 处理当前任务 */
    if (prev->state == PROC_RUNNING) {
        /* 当前任务仍在运行状态，重新入队 */
        /* 注意：pick_next_task 已经把 next 从队列中取出了
         * 但 prev 还在队列上（如果它还在 RUNNING 状态）
         * 我们需要先把 prev 出队，稍后在 switch_to 之后可能需要重新入队
         * 但实际上，pick_next_task 的实现中已经处理了这个问题
         * 所以这里不需要额外操作
         */
    } else {
        /* 当前任务已阻塞或退出，从队列中移除 */
        sched_dequeue_task(prev);
    }

    /* 重置下一个任务的时间片 */
    sched_reset_time_slice(next);

    /* 更新当前任务 */
    scheduler.current = next;

    /* 清除重调度标志 */
    sched_clear_resched_locked();

    /* 准备切换上下文 */
    spin_unlock_irqrestore(&g_scheduler_lock, flags);

    /* 切换上下文 */
    switch_to(prev, next);
}
```

### 调度流程详解

让我们详细分析 `schedule()` 的流程：

**第一步：获取锁**

```c
spin_lock_irqsave(&g_scheduler_lock, &flags);
```

调度器操作必须持有锁，而且需要禁用中断。因为调度可能在任何时候发生（包括中断处理中），我们需要确保数据结构的一致性。

**第二步：选择下一个任务**

```c
next = sched_pick_next_task();
```

这个函数会：
1. 检查当前任务是否还有时间片
2. 检查是否有更高优先级的任务
3. 优先从 Priority 队列选择
4. 如果没有，从 RR 队列选择
5. 如果都没有，返回 NULL

**第三步：处理 idle 情况**

```c
if (next == NULL) {
    next = scheduler.idle;
}
```

没有可运行的任务时，切换到 idle 任务。idle 任务是一个特殊的内核任务，它永远不会阻塞，用于在 CPU 空闲时占用时间。

**第四步：检查是否需要切换**

```c
if (next == prev) {
    sched_clear_resched_locked();
    spin_unlock_irqrestore(&g_scheduler_lock, flags);
    return;
}
```

如果选择的任务还是当前任务，不需要切换。这种情况发生在当前任务还有时间片，且没有更高优先级任务时。

**第五步：处理当前任务的状态**

```c
if (prev->state == PROC_RUNNING) {
    /* 当前任务仍在运行，不需要特殊处理 */
    /* 它已经通过 pick_next_task 保持在队列上了 */
} else {
    /* 当前任务已阻塞或退出，从队列中移除 */
    sched_dequeue_task(prev);
}
```

这里有个微妙的地方。如果当前任务还在 `PROC_RUNNING` 状态，说明它只是被抢占（时间片用完或有更高优先级任务）。`pick_next_task()` 的实现已经把它保留在队列上了，所以我们不需要再做什么。

但如果当前任务已经变成其他状态（阻塞、退出等），它应该从队列中移除。这种情况在任务调用 `sys_exit()` 或阻塞等待某个事件时发生。

**第六步：重置时间片并切换**

```c
sched_reset_time_slice(next);
scheduler.current = next;
sched_clear_resched_locked();

spin_unlock_irqrestore(&g_scheduler_lock, flags);

switch_to(prev, next);
```

最后，重置下一个任务的时间片，更新 `scheduler.current`，清除重调度标志，然后调用 `switch_to()` 完成实际的上下文切换。

## 主动让出 CPU

### sys_yield() 实现

系统调用 `sys_yield()` 允许进程主动让出 CPU：

```c
int32_t sys_yield(void) {
    /* 设置当前任务的时间片为 0，强制调度 */
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    if (scheduler.current) {
        scheduler.current->sched_entity.time_slice = 0;
        sched_set_resched_locked();
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);

    /* 触发调度 */
    schedule();

    return 0;
}
```

通过把时间片设为 0，我们强制调度器选择其他任务。这对于礼貌的进程协作很有用，比如一个长时间计算的任务可以在检查点主动让出 CPU，让其他任务有机会运行。

## 进程退出集成

### sys_exit() 与调度器

进程退出时，需要从运行队列中移除：

```c
int32_t sys_exit(int32_t status) {
    pcb_t* current = scheduler.current;

    /* 设置退出状态 */
    current->exit_status = status;
    current->state = PROC_ZOMBIE;

    /* 从运行队列中移除 */
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);
    sched_dequeue_task(current);
    scheduler.nr_running--;
    spin_unlock_irqrestore(&g_scheduler_lock, flags);

    /* 通知父进程 */
    /* ... */

    /* 触发调度，选择下一个任务 */
    schedule();

    /* 永远不会到这里 */
    return 0;
}
```

进程退出后变成 ZOMBIE 状态，从运行队列中移除，然后触发调度。调度器会选择下一个任务运行，而 ZOMBIE 进程会被父进程回收。

## 常见问题

**问题：fork 后子进程没有运行**

检查 `sched_set_policy()` 是否成功。如果调度类没有注册，`sched_set_policy()` 会失败。

```c
if (sched_set_policy(child, SCHED_NORMAL, 0) != 0) {
    klog_error("[PROC] Failed to set scheduling policy for child\n");
    /* 处理错误 */
}
```

**问题：调度器总是选择 idle 任务**

这说明运行队列中没有任务。检查 `sched_enqueue_task()` 是否被正确调用。可以在 `schedule()` 中加日志：

```c
klog_info("[SCHED] nr_running=%d, RR nr_running=%d, Prio nr_running=%d\n",
          scheduler.nr_running,
          scheduler.rq[SCHED_NORMAL].nr_running,
          scheduler.rq[SCHED_PRIORITY].nr_running);
```

**问题：调度器锁死锁**

确保所有获取 `g_scheduler_lock` 的地方都正确释放了锁。特别注意错误路径，比如在 `proc_alloc_pcb()` 失败时。

**问题：上下文切换后崩溃**

检查 `switch_to()` 是否正确保存和恢复了所有寄存器。调度器锁必须在调用 `switch_to()` 之前释放，因为 `switch_to()` 可能会切换到其他任务，锁的持有者就变了。

## 调试技巧

### 跟踪调度事件

在关键调度点添加日志：

```c
void schedule(void) {
    /* ... */

    klog_info("[SCHED] Schedule: prev=PID:%d state=%d, next=PID:%d policy=%d\n",
              prev ? prev->pid : -1,
              prev ? prev->state : -1,
              next ? next->pid : -1,
              next ? next->sched_entity.policy : -1);

    /* ... */
}
```

### 检查运行队列

定期打印运行队列状态：

```c
void sched_debug_dump_queues(void) {
    extern scheduler_t scheduler;

    klog_info("[SCHED] Queue dump:\n");
    klog_info("[SCHED]   RR: %d tasks\n", scheduler.rq[SCHED_NORMAL].nr_running);
    klog_info("[SCHED]   Prio: %d tasks\n", scheduler.rq[SCHED_PRIORITY].nr_running);
    klog_info("[SCHED]   Total: %d tasks\n", scheduler.nr_running);
}
```

### 监控调度延迟

测量从设置 `need_resched` 到实际调度的时间：

```c
uint64_t resched_time;
uint64_t sched_time;

/* 设置 need_resched 时记录时间 */
void sched_set_resched(void) {
    resched_time = rdtsc();
    /* ... */
}

/* schedule() 中计算延迟 */
void schedule(void) {
    sched_time = rdtsc();
    uint64_t latency = sched_time - resched_time;
    klog_info("[SCHED] Scheduling latency: %llu cycles\n", latency);
    /* ... */
}
```

# 搭建调度类框架脚手架 —— Stage 22 调度类框架实战指南（三）

## 前言

前两篇文章我们讲了为什么需要调度类框架，以及它的设计思路。现在终于到了动手写代码的时候了。说实话，写代码比讲设计要痛快多了——设计的时候要考虑各种可能性，写代码的时候只需要把设计方案落实到具体的函数和结构体。

这篇文章我们会搭建调度类框架的"脚手架"。脚手架是什么意思呢？就是那些支撑性的代码：数据结构定义、初始化函数、注册机制。这些东西本身不直接参与调度决策，但没有它们，整个框架就跑不起来。

我们会在 `kernel/process/` 目录下创建两个新文件：`sched.h` 和 `sched.c`。`.h` 文件放结构体定义和函数声明，`.c` 文放实现。这是内核代码的标准组织方式。

---

## 现在我们要做什么

我们的目标是在这一篇文章里完成以下工作：

1. 创建 `sched.h` 文件，定义所有核心数据结构
2. 创建 `sched.c` 文件，实现框架初始化和调度类注册
3. 修改 `kernel/process/CMakeLists.txt`，把新文件加入构建
4. 在内核初始化流程中调用 `sched_class_init()`

完成后，我们就有了一个可以工作的框架骨架。它还不能调度任务，但已经支持调度类的注册，后续的 RR 和 Priority 类可以基于这个骨架来开发。

## 从0开始 —— 创建 sched.h

### 文件头部与包含

首先创建 `kernel/process/sched.h`。文件开头的注释和包含很重要：

```c
/* ==============================================================================
 * CCOS - Scheduling Class Framework
 * ==============================================================================
 * This module provides an extensible scheduler class system inspired by Linux's
 * modular scheduling architecture. Multiple scheduling classes (Round-Robin,
 * Priority, etc.) can coexist and new algorithms can be easily added.
 * ==============================================================================
 */

#pragma once

#include "defines/types.h"
#include "list/list.h"
#include "sync/spinlock.h"
```

我们使用 `#pragma once` 而不是传统的头文件保护宏，这是现代 C 编译器都支持的写法，更简洁。

需要的依赖包括：类型定义（`types.h`）、链表操作（`list.h`）、自旋锁（`spinlock.h`）。这些都是内核中已有的基础模块。

### 前向声明

接下来我们需要一些前向声明。这是因为调度类结构和 PCB 结构体互相引用——调度类需要操作 PCB，PCB 中有调度实体指向调度类。在 C 语言中，这种循环引用需要用前向声明来解决：

```c
/* ==============================================================================
 * Forward Declarations
 * ==============================================================================
 */

struct pcb;
struct sched_class;
struct sched_rq;
```

这样我们就可以在定义这些结构体之前使用它们的指针类型了。

### 调度策略枚举

然后是调度策略的枚举定义：

```c
/* ==============================================================================
 * Scheduling Policy Enumeration
 * ==============================================================================
 */

/**
 * @brief Scheduling policy types
 */
typedef enum sched_policy {
    SCHED_NORMAL   = 0,    /* Normal Round-Robin scheduling */
    SCHED_PRIORITY = 1,    /* Priority-based scheduling (system only) */
    SCHED_MAX      = 2,    /* Number of scheduling policies */
} sched_policy_t;
```

这里定义了两种调度策略和一个哨兵值 `SCHED_MAX`。`SCHED_MAX` 很重要，它告诉我们有多少种策略，这样我们就可以定义对应大小的数组了。

### 调度类结构

接下来是调度类结构，这是框架的核心：

```c
/* ==============================================================================
 * Scheduling Class Structure
 * ==============================================================================
 */

/**
 * @brief Scheduling class operations
 *
 * Each scheduling class implements these operations to define
 * its scheduling behavior.
 */
typedef struct sched_class {
    const char* name;              /* Class name for debugging */
    sched_policy_t policy;         /* Policy identifier */

    /**
     * @brief Enqueue a task on this class's run queue
     * @param rq The run queue
     * @param pcb The task to enqueue
     * @param head If true, add to head; otherwise add to tail
     */
    void (*enqueue_task)(struct sched_rq* rq, struct pcb* pcb, bool head);

    /**
     * @brief Dequeue a task from this class's run queue
     * @param rq The run queue
     * @param pcb The task to dequeue
     */
    void (*dequeue_task)(struct sched_rq* rq, struct pcb* pcb);

    /**
     * @brief Pick the next task to run
     * @param rq The run queue
     * @param prev The previously running task
     * @return The next task to run, or NULL if queue is empty
     */
    struct pcb* (*pick_next_task)(struct sched_rq* rq, struct pcb* prev);

    /**
     * @brief Check if a task can preempt another
     * @param p The preempting task
     * @param curr The currently running task
     * @return true if p should preempt curr
     */
    bool (*should_preempt)(struct pcb* p, struct pcb* curr);

    /**
     * @brief Called when a task's time slice expires
     * @param rq The run queue
     * @param pcb The task whose time slice expired
     */
    void (*task_tick)(struct sched_rq* rq, struct pcb* pcb);

    /**
     * @brief Initialize a new task for this class
     * @param pcb The task to initialize
     * @param nice Priority modifier (for future use)
     */
    void (*task_fork)(struct pcb* pcb, int nice);

    /**
     * @brief Get the default time slice for a task
     * @param pcb The task
     * @return Time slice in milliseconds
     */
    uint32_t (*get_time_slice)(const struct pcb* pcb);

} sched_class_t;
```

每个函数指针都有详细的注释说明参数和用途。这不是多余的——内核代码会长期维护，良好的文档能帮助后来者（包括几个月后的你自己）快速理解代码。

### 运行队列结构

接下来是 per-policy 运行队列结构：

```c
/* ==============================================================================
 * Per-Class Run Queue Structure
 * ==============================================================================
 */

/**
 * @brief Per-policy run queue
 *
 * Each scheduling class maintains its own run queue.
 */
typedef struct sched_rq {
    sched_class_t* sched_class;    /* Associated scheduling class */
    list_head        queue;         /* Run queue for this class */
    uint32_t         nr_running;    /* Number of tasks on this queue */

    /* Class-specific data */
    void*            class_data;    /* Opaque pointer to class-specific data */

} sched_rq_t;
```

`class_data` 字段用 `void*` 类型，这样不同调度类可以存放完全不同的数据结构。RR 类可能不需要这个字段（设为 NULL），Priority 类会存放一个包含 256 个队列的结构体。

### 调度实体结构

然后是调度实体，它会嵌入到 PCB 中：

```c
/* ==============================================================================
 * Per-Task Scheduling Entity
 * ==============================================================================
 */

/**
 * @brief Per-task scheduling data
 */
typedef struct sched_entity {
    sched_policy_t    policy;         /* Scheduling policy for this task */
    sched_class_t*    sched_class;    /* Associated scheduling class */
    uint32_t          time_slice;     /* Remaining time slice (in ms) */
    uint32_t          time_slice_total; /* Full time slice (in ms) */
    int               priority;       /* Priority level (0-127, lower = higher) */
    int               nice;           /* Nice value for future extensions */
    uint64_t          last_ran;       /* Last time this task ran */
    list_head         run_list;       /* Node for class-specific run queue */

} sched_entity_t;
```

这个结构体会直接嵌入到 `pcb_t` 中，而不是用指针。这样访问更快，也不需要额外的内存分配。

### 时间片常量

定义一些时间片相关的常量：

```c
/* ==============================================================================
 * Time Slice Constants
 * ==============================================================================
 */

/**
 * @brief Default time slices (in milliseconds, at 1000Hz)
 */
#define DEF_TIMESLICE_MS     10      /* Default 10ms time slice */
#define MIN_TIMESLICE_MS     2       /* Minimum 2ms */
#define MAX_TIMESLICE_MS     100     /* Maximum 100ms */
```

默认 10ms 的时间片是一个经验值。太小会导致频繁切换，上下文切换开销变大；太大又会导致调度不够精细。10ms 在大多数场景下是一个合理的折中。

## 框架实现 —— 创建 sched.c

`sched.h` 定义了接口，现在我们来实现它们。创建 `kernel/process/sched.c`：

### 头文件包含

```c
/* ==============================================================================
 * CCOS - Scheduling Class Framework Implementation
 * ==============================================================================
 */

#include "process/sched.h"
#include "driver/timer/timer.h"
#include "klogs/kprintf.h"
#include "process/process.h"
#include "sync/spinlock.h"
```

这里包含了必要的头文件。`timer.h` 是因为我们需要注册定时器回调，`process.h` 包含了 `scheduler_t` 的定义。

### 全局状态

框架需要维护一些全局状态：

```c
/* ==============================================================================
 * Global Scheduler State
 * ==============================================================================
 */

/* Global scheduler instance */
extern scheduler_t scheduler;

/* Static arrays for scheduler class data */
static sched_rq_t s_run_queues[SCHED_MAX];
static sched_class_t* s_classes[SCHED_MAX];

/* Global scheduler lock - exported for use in process.c */
spinlock_t g_scheduler_lock = SPIN_LOCK_INIT;
```

`s_run_queues` 是 per-policy 运行队列数组，`s_classes` 是已注册的调度类数组。两者都是静态的，外部代码通过 `scheduler_t` 结构体来间接访问它们。

`g_scheduler_lock` 被声明为 `extern`，因为 `process.c` 中也需要使用这个锁。

### 定时器回调

框架需要处理定时器中断，用于递减时间片：

```c
/* ==============================================================================
 * Timer Tick Handler
 * ==============================================================================
 */

/**
 * @brief Timer tick callback for scheduling
 * Called from timer_irq_handler at 1000Hz
 *
 * NOTE: Runs in interrupt context, must use irqsave variants
 */
static void sched_timer_tick_handler(uint64_t ticks) {
    (void)ticks;

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    /* Only tick if we have a running process with a scheduling class */
    if (scheduler.current && scheduler.rq != NULL) {
        if (scheduler.current->sched_entity.sched_class) {
            sched_rq_t* rq = &scheduler.rq[scheduler.current->sched_entity.policy];
            scheduler.current->sched_entity.sched_class->task_tick(rq, scheduler.current);
        }
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

这个函数每毫秒被调用一次（1000Hz 定时器）。它获取调度器锁，然后调用当前进程的调度类的 `task_tick` 函数。注意这里使用 `irqsave` 变体，因为我们在中断上下文中，需要正确处理中断状态。

### 时间片管理函数

接下来是时间片管理的两个函数：

```c
/* ==============================================================================
 * Time Slice Management Functions
 * ==============================================================================
 */

/**
 * @brief Initialize time slice for a task
 */
void sched_init_time_slice(struct pcb* pcb) {
    if (!pcb || !pcb->sched_entity.sched_class) {
        return;
    }

    uint32_t slice = pcb->sched_entity.sched_class->get_time_slice(pcb);
    pcb->sched_entity.time_slice = slice;
    pcb->sched_entity.time_slice_total = slice;
}

/**
 * @brief Reset time slice for a task
 */
void sched_reset_time_slice(struct pcb* pcb) {
    if (!pcb || !pcb->sched_entity.sched_class) {
        return;
    }

    pcb->sched_entity.time_slice = pcb->sched_entity.time_slice_total;
}
```

`sched_init_time_slice` 在进程创建时调用，通过调度类的 `get_time_slice` 函数获取时间片长度并设置。`sched_reset_time_slice` 在进程重新获得 CPU 时调用，把剩余时间片恢复到完整值。

### 框架初始化

这是框架的入口函数：

```c
/* ==============================================================================
 * Scheduler Class Initialization
 * ==============================================================================
 */

/**
 * @brief Initialize the scheduler class framework
 */
int sched_class_init(void) {
    klog_info("[SCHED] Initializing scheduler class framework\n");

    /* Initialize static run queues */
    for (int i = 0; i < SCHED_MAX; i++) {
        INIT_LIST_HEAD(&s_run_queues[i].queue);
        s_run_queues[i].sched_class = NULL;
        s_run_queues[i].nr_running = 0;
        s_run_queues[i].class_data = NULL;
        s_classes[i] = NULL;
    }

    /* Link to scheduler */
    scheduler.rq = s_run_queues;
    scheduler.classes = s_classes;

    /* Initialize legacy run queue for compatibility */
    INIT_LIST_HEAD(&scheduler.run_queue);

    /* Register timer callback */
    timer_set_callback(sched_timer_tick_handler);

    klog_info("[SCHED] Scheduler class framework initialized\n");
    return 0;
}
```

这个函数做几件事：
1. 初始化所有运行队列，把队列头初始化为空链表，清空计数器和指针
2. 把运行队列数组和调度类数组链接到 `scheduler_t` 结构体
3. 为了兼容 Stage 21 的代码，初始化 `scheduler.run_queue`
4. 注册定时器回调函数

## 调度类注册机制

### 注册函数

调度类通过这个函数注册到框架：

```c
/* ==============================================================================
 * Class Registration
 * ==============================================================================
 */

/**
 * @brief Register a scheduling class
 */
int sched_class_register(sched_class_t* class, sched_policy_t policy) {
    if (!class || policy >= SCHED_MAX) {
        return -1;
    }

    if (s_classes[policy] != NULL) {
        klog_warn("[SCHED] Class already registered for policy %d\n", policy);
        return -1;
    }

    s_classes[policy] = class;
    s_run_queues[policy].sched_class = class;

    klog_info("[SCHED] Registered class '%s' for policy %d\n", class->name, policy);
    return 0;
}
```

这个函数首先检查参数的有效性，然后检查该策略是否已经有注册的类。如果都没问题，就把调度类指针存入数组，同时关联到对应的运行队列。

### 策略管理函数

用于设置和获取进程的调度策略：

```c
/* ==============================================================================
 * Policy Management
 * ==============================================================================
 */

/**
 * @brief Set scheduling policy for a task
 */
int sched_set_policy(struct pcb* pcb, sched_policy_t policy, int priority) {
    if (!pcb || policy >= SCHED_MAX) {
        return -1;
    }

    if (s_classes[policy] == NULL) {
        klog_error("[SCHED] No class registered for policy %d\n", policy);
        return -1;
    }

    pcb->sched_entity.policy = policy;
    pcb->sched_entity.sched_class = s_classes[policy];

    if (pcb->sched_entity.sched_class) {
        pcb->sched_entity.sched_class->task_fork(pcb, priority);
    }

    return 0;
}

/**
 * @brief Get scheduling policy for a task
 */
sched_policy_t sched_get_policy(const struct pcb* pcb) {
    if (!pcb) {
        return SCHED_NORMAL;
    }
    return pcb->sched_entity.policy;
}
```

`sched_set_policy` 为进程设置调度策略。它首先检查策略是否已注册，然后更新进程的调度实体，最后调用调度类的 `task_fork` 函数进行初始化。

## 任务队列操作

框架提供了一组函数来管理任务的入队和出队：

### 入队函数

```c
/* ==============================================================================
 * Task Queue Operations
 * ==============================================================================
 */

/**
 * @brief Enqueue a task on its class's run queue
 */
void sched_enqueue_task(struct pcb* pcb, bool head) {
    if (!pcb || !pcb->sched_entity.sched_class) {
        return;
    }

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    sched_rq_t* rq = &scheduler.rq[pcb->sched_entity.policy];

    pcb->sched_entity.sched_class->enqueue_task(rq, pcb, head);

    /* Update legacy nr_running */
    scheduler.nr_running++;

    /* Also add to legacy run_queue for compatibility */
    list_add_tail(&pcb->run_list, &scheduler.run_queue);

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

这个函数根据进程的调度策略找到对应的运行队列，然后调用该调度类的 `enqueue_task` 函数。同时为了兼容 Stage 21，也把进程加入到传统的 `run_queue` 中。

### 出队函数

```c
/**
 * @brief Dequeue a task from its class's run queue
 */
void sched_dequeue_task(struct pcb* pcb) {
    if (!pcb || !pcb->sched_entity.sched_class) {
        return;
    }

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    sched_rq_t* rq = &scheduler.rq[pcb->sched_entity.policy];

    pcb->sched_entity.sched_class->dequeue_task(rq, pcb);

    /* Update legacy nr_running */
    if (scheduler.nr_running > 0) {
        scheduler.nr_running--;
    }

    /* Also remove from legacy run_queue */
    list_del_init(&pcb->run_list);

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

与入队函数类似，调用调度类的 `dequeue_task` 函数，同时维护兼容性。

### 任务选择函数

```c
/* ==============================================================================
 * Task Selection
 * ==============================================================================
 */

/**
 * @brief Pick the next task to run
 *
 * Selection order:
 * 1. If current is still runnable and has time slice, keep it
 * 2. Otherwise, pick from priority queues first
 * 3. Then pick from normal RR queue
 *
 * NOTE: Caller must hold g_scheduler_lock
 */
struct pcb* sched_pick_next_task(void) {
    struct pcb* prev = scheduler.current;

    /* If current is still runnable, check if we should keep it */
    if (prev && prev->state == PROC_RUNNING) {
        if (prev->sched_entity.time_slice > 0) {
            /* Check if any higher priority task wants to run */
            sched_rq_t* prio_rq = &scheduler.rq[SCHED_PRIORITY];
            if (prio_rq->nr_running > 0 && prio_rq->sched_class) {
                struct pcb* prio_task = prio_rq->sched_class->pick_next_task(prio_rq, prev);
                if (prio_task &&
                    prio_task->sched_entity.sched_class->should_preempt(prio_task, prev)) {
                    /* Re-enqueue current and return priority task */
                    return prio_task;
                }
            }
            /* Keep current */
            return prev;
        }
    }

    /* Check priority queue first */
    sched_rq_t* prio_rq = &scheduler.rq[SCHED_PRIORITY];
    if (prio_rq->nr_running > 0 && prio_rq->sched_class) {
        struct pcb* next = prio_rq->sched_class->pick_next_task(prio_rq, prev);
        if (next) {
            return next;
        }
    }

    /* Fall back to normal RR queue */
    sched_rq_t* rr_rq = &scheduler.rq[SCHED_NORMAL];
    if (rr_rq->nr_running > 0 && rr_rq->sched_class) {
        struct pcb* next = rr_rq->sched_class->pick_next_task(rr_rq, prev);
        if (next) {
            return next;
        }
    }

    /* No tasks available */
    return NULL;
}
```

这个函数实现了任务选择的策略：优先检查 Priority 队列，如果没有再检查 RR 队列。这保证了高优先级任务总是优先被调度。

## 重调度标志管理

调度器使用一个标志来延迟调度操作：

```c
/* ==============================================================================
 * Reschedule Management
 * ==============================================================================
 */

/**
 * @brief Check if we need to reschedule
 */
bool sched_needs_reschedule(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);
    bool needs = scheduler.need_resched;
    spin_unlock_irqrestore(&g_scheduler_lock, flags);
    return needs;
}

/**
 * @brief Set the need_resched flag
 */
void sched_set_resched(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);
    scheduler.need_resched = true;
    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}

/**
 * @brief Clear the need_resched flag
 */
void sched_clear_resched(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);
    scheduler.need_resched = false;
    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

`need_resched` 标志用于延迟调度。当时间片用完时，我们在中断上下文中设置这个标志，真正的调度操作会在稍后安全的时候执行。

## 常见问题

**问题：编译报错说 `scheduler_t` 未定义**

这是因为 `sched.c` 包含了 `process.h`，但 `process.h` 中的 `scheduler_t` 定义可能还没有加入 `sched_rq` 和 `classes` 字段。你需要修改 `process.h`，在 `scheduler_t` 结构体中添加：

```c
typedef struct scheduler {
    /* ... 原有字段 ... */

    sched_rq_t* rq;              /* Per-policy run queues */
    sched_class_t** classes;      /* Registered scheduling classes */

} scheduler_t;
```

**问题：链接错误 undefined reference to `timer_set_callback`**

这是因为定时器驱动可能还没有实现 `timer_set_callback` 函数。你需要检查 `kernel/driver/timer/timer.h` 和对应的实现文件，确保这个函数存在。如果没有，你需要先实现它，或者在暂时不使用定时器功能的情况下手动触发调度。

# 常见问题与调试技巧 —— Stage 22 调度类框架实战指南（九）

## 前言

这是教程的最后一篇文章。前面的文章我们讲了调度类框架的设计、实现、测试，但说实话，写代码只是工作的一部分，更多时候你可能在与各种奇怪的问题作斗争：调度器不工作、任务不切换、时间片没生效、系统死锁……

这篇文章会总结我在实现调度类框架时遇到的各种坑，以及对应的解决方案。希望这些经验能帮你节省一些调试时间。当然，你遇到的问题可能和我遇到的不一样，但调试的思路是相通的：理解系统的工作原理，缩小问题范围，逐步定位故障点。

## 初始化问题

### 问题 1：调度类注册失败

**症状**：启动时日志显示"Failed to register class"或者后续调度操作崩溃。

**原因**：调度类注册失败通常有几个可能：
1. `sched_class_init()` 没有被调用
2. 尝试重复注册同一个策略
3. 调度类的函数指针不完整（有 NULL 值）

**调试方法**：

在 `sched_class_register()` 中添加更详细的日志：

```c
int sched_class_register(sched_class_t* class, sched_policy_t policy) {
    klog_info("[SCHED] Registering class '%s' for policy %d\n", class->name, policy);

    if (!class || policy >= SCHED_MAX) {
        klog_error("[SCHED] Invalid arguments: class=%p, policy=%d\n", class, policy);
        return -1;
    }

    if (s_classes[policy] != NULL) {
        klog_error("[SCHED] Policy %d already registered by '%s'\n",
                  policy, s_classes[policy]->name);
        return -1;
    }

    /* 验证所有必需的函数指针 */
    if (!class->enqueue_task || !class->dequeue_task || !class->pick_next_task ||
        !class->task_tick || !class->task_fork || !class->get_time_slice) {
        klog_error("[SCHED] Class '%s' has NULL function pointers\n", class->name);
        return -1;
    }

    s_classes[policy] = class;
    s_run_queues[policy].sched_class = class;

    klog_info("[SCHED] Registered class '%s' for policy %d\n", class->name, policy);
    return 0;
}
```

**解决方案**：

确保初始化顺序正确：

```c
void kernel_init(void) {
    /* 1. 先初始化框架 */
    sched_class_init();

    /* 2. 再注册调度类 */
    sched_rr_init();
    sched_prio_init();

    /* 3. 最后创建进程 */
    /* ... */
}
```

### 问题 2：class_data 未初始化

**症状**：Priority 调度类的操作崩溃，访问空指针。

**原因**：Priority 调度类需要 `prio_rq_data_t` 结构体，它在 `sched_prio_init()` 中分配并赋给 `rq->class_data`。如果初始化失败或顺序不对，`class_data` 会是 NULL。

**调试方法**：

在使用 `class_data` 前添加检查：

```c
static inline prio_rq_data_t* prio_rq_data(struct sched_rq* rq) {
    if (rq->class_data == NULL) {
        klog_error("[PRIO] class_data is NULL!\n");
        return NULL;
    }
    return (prio_rq_data_t*)rq->class_data;
}
```

**解决方案**：

确保在注册 Priority 调度类之前，内核堆已经初始化：

```c
/* 内核初始化顺序 */
heap_init();           /* 1. 内核堆必须先初始化 */
sched_class_init();    /* 2. 然后才能分配 class_data */
sched_prio_init();     /* 3. Priority 类需要分配内存 */
```

## 调度问题

### 问题 3：任务不被调度

**症状**：进程创建成功，但永远不被调度执行，系统一直运行 idle 任务。

**原因**：可能的原因很多：
1. 任务没有加入运行队列
2. 调度器没有选择这个任务
3. `pick_next_task()` 返回 NULL
4. `schedule()` 没有被调用

**调试方法**：

第一步：验证任务确实在队列上

```c
void sched_debug_dump_queues(void) {
    extern scheduler_t scheduler;

    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    klog_info("[SCHED] Queue dump:\n");
    klog_info("[SCHED]   Current: PID=%d\n",
              scheduler.current ? scheduler.current->pid : -1);
    klog_info("[SCHED]   RR queue: %d tasks\n",
              scheduler.rq[SCHED_NORMAL].nr_running);
    klog_info("[SCHED]   Prio queue: %d tasks\n",
              scheduler.rq[SCHED_PRIORITY].nr_running);

    /* 打印 RR 队列中的任务 */
    struct pcb* pcb;
    list_for_each_entry(pcb, &scheduler.rq[SCHED_NORMAL].queue, sched_entity.run_list) {
        klog_info("[SCHED]     PID=%d, state=%d, time_slice=%d\n",
                  pcb->pid, pcb->state, pcb->sched_entity.time_slice);
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

第二步：跟踪 `schedule()` 的调用

```c
void schedule(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    struct pcb* prev = scheduler.current;
    struct pcb* next = sched_pick_next_task();

    klog_info("[SCHED] schedule(): prev=PID:%d, next=PID:%s\n",
              prev ? prev->pid : -1, next ? "..." : "NULL");

    if (next == NULL) {
        klog_warn("[SCHED] No tasks to run, switching to idle\n");
        next = scheduler.idle;
    }

    /* ... */
}
```

**解决方案**：

根据调试结果定位问题：
- 如果队列中没有任务，检查 `sched_enqueue_task()` 是否被调用
- 如果队列中有任务但 `pick_next_task()` 返回 NULL，检查调度类的实现
- 如果 `next` 正确但没有切换，检查 `switch_to()` 的实现

### 问题 4：时间片不生效

**症状**：进程运行一次后，永远不再被调度；或者进程一直运行不被切换。

**原因**：
1. 时间片没有被递减（定时器回调没有注册）
2. 时间片用完后没有设置 `need_resched`
3. 时间片重置函数没有被调用

**调试方法**：

在 `rr_task_tick()` 中添加日志：

```c
static void rr_task_tick(struct sched_rq* rq, struct pcb* pcb) {
    if (pcb->sched_entity.time_slice > 0) {
        pcb->sched_entity.time_slice--;
    }

    /* 每 100 次打印一次 */
    static int count = 0;
    if (++count % 100 == 0) {
        klog_info("[RR] PID=%d tick, time_slice=%d\n",
                  pcb->pid, pcb->sched_entity.time_slice);
    }
}
```

在 `schedule()` 中检查时间片重置：

```c
/* 重置下一个任务的时间片 */
klog_info("[SCHED] Resetting time slice for PID=%d: %d -> %d\n",
          next->pid,
          next->sched_entity.time_slice,
          next->sched_entity.time_slice_total);

sched_reset_time_slice(next);
```

**解决方案**：

1. 确保定时器回调已注册：
```c
timer_set_callback(sched_timer_tick_handler);
```

2. 确保时间片重置在 `schedule()` 中被调用：
```c
sched_reset_time_slice(next);
```

### 问题 5：Priority 调度不工作

**症状**：高优先级任务没有优先运行，Priority 任务和 RR 任务没有区别。

**原因**：
1. 任务的调度策略没有正确设置
2. `pick_next_task()` 没有优先检查 Priority 队列
3. 优先级字段没有正确初始化

**调试方法**：

检查任务的调度策略：

```c
void sched_debug_dump_task(struct pcb* pcb) {
    if (!pcb) return;

    klog_info("[SCHED] Task dump:\n");
    klog_info("[SCHED]   PID=%d\n", pcb->pid);
    klog_info("[SCHED]   Policy=%d (%s)\n",
              pcb->sched_entity.policy,
              pcb->sched_entity.policy == SCHED_NORMAL ? "RR" : "Priority");
    klog_info("[SCHED]   Priority=%d\n", pcb->sched_entity.priority);
    klog_info("[SCHED]   Time slice=%d/%d\n",
              pcb->sched_entity.time_slice,
              pcb->sched_entity.time_slice_total);
    klog_info("[SCHED]   Sched class=%p\n", pcb->sched_entity.sched_class);
}
```

**解决方案**：

确保在创建进程后正确设置策略：

```c
sched_set_policy(child, SCHED_PRIORITY, 50);  /* priority = 50 */
sched_init_time_slice(child);
sched_enqueue_task(child, false);
```

## 抢占问题

### 问题 6：高优先级任务不抢占低优先级任务

**症状**：高优先级任务就绪后，低优先级任务继续运行，没有被抢占。

**原因**：
1. `should_preempt()` 实现不正确
2. 抢占检查逻辑没有在任务就绪时被调用
3. 高优先级任务没有加入正确的队列

**调试方法**：

在 `sched_pick_next_task()` 中添加抢占检查日志：

```c
struct pcb* sched_pick_next_task(void) {
    struct pcb* prev = scheduler.current;

    /* 检查是否有高优先级任务需要抢占 */
    sched_rq_t* prio_rq = &scheduler.rq[SCHED_PRIORITY];
    if (prio_rq->nr_running > 0 && prio_rq->sched_class) {
        struct pcb* prio_task = prio_rq->sched_class->pick_next_task(prio_rq, prev);
        if (prio_task) {
            bool should = prio_task->sched_entity.sched_class->should_preempt(prio_task, prev);
            klog_info("[SCHED] Preemption check: prio PID=%d (prio=%d) vs curr PID=%d (prio=%d): %s\n",
                      prio_task->pid, prio_task->sched_entity.priority,
                      prev ? prev->pid : -1, prev ? prev->sched_entity.priority : -1,
                      should ? "YES" : "NO");

            if (should) {
                return prio_task;
            }
        }
    }

    /* ... */
}
```

**解决方案**：

1. 确保 `should_preempt()` 实现正确：
```c
static bool prio_should_preempt(struct pcb* p, struct pcb* curr) {
    /* 更高优先级（更小数值）应该抢占 */
    if (p->sched_entity.priority < curr->sched_entity.priority) {
        return true;
    }
    /* ... */
}
```

2. 确保在任务就绪时检查抢占：
```c
void sched_enqueue_task(struct pcb* pcb, bool head) {
    /* ... 入队操作 ... */

    /* 如果新任务优先级更高，设置重调度标志 */
    if (pcb->sched_entity.policy == SCHED_PRIORITY) {
        if (scheduler.current &&
            pcb->sched_entity.priority < scheduler.current->sched_entity.priority) {
            sched_set_resched();
        }
    }
}
```

## 内存问题

### 问题 7：class_data 内存泄漏

**症状**：长时间运行后内存耗尽。

**原因**：`prio_rq_data_t` 在 `sched_prio_init()` 中分配，但没有在系统关闭时释放。

**解决方案**：

虽然内核通常不会关闭，但为了完整性，可以添加清理函数：

```c
/**
 * @brief Cleanup Priority scheduling class
 */
void sched_prio_cleanup(void) {
    extern scheduler_t scheduler;
    sched_rq_t* rq = &scheduler.rq[SCHED_PRIORITY];

    if (rq->class_data) {
        kfree(rq->class_data);
        rq->class_data = NULL;
    }

    klog_info("[SCHED] Priority class cleaned up\n");
}
```

### 问题 8：PCB 分配失败

**症状**：创建进程时返回 NULL。

**原因**：内核堆内存不足，或者 PCB 结构体太大。

**调试方法**：

```c
pcb_t* proc_alloc_pcb(void) {
    klog_info("[PROC] Allocating PCB (size=%zu bytes)\n", sizeof(pcb_t));

    pcb_t* pcb = (pcb_t*)kmalloc(sizeof(pcb_t));
    if (!pcb) {
        klog_error("[PROC] Failed to allocate PCB: out of memory\n");
        /* 打印堆状态 */
        heap_dump_info();
        return NULL;
    }

    /* ... */
}
```

**解决方案**：

1. 检查内核堆大小是否足够
2. 检查是否有内存泄漏
3. 考虑使用 slab 分配器优化小对象分配

## 并发问题

### 问题 9：调度器死锁

**症状**：系统停止响应，CPU 空转。

**原因**：调度器锁没有正确释放，或者获取锁的顺序不对导致死锁。

**调试方法**：

使用锁依赖检测工具（如果有的话），或者在获取锁时记录调用栈：

```c
#define SCHED_LOCK_ENTER() \
    do { \
        klog_info("[SCHED] Lock acquired at %s:%d\n", __FILE__, __LINE__); \
    } while(0)

void schedule(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);
    SCHED_LOCK_ENTER();

    /* ... */
}
```

**解决方案**：

确保每个 `spin_lock_irqsave()` 都有对应的 `spin_unlock_irqrestore()`：

```c
void some_function(void) {
    spinlock_flags_t flags;
    spin_lock_irqsave(&g_scheduler_lock, &flags);

    /* 临界区 */
    if (error_condition) {
        /* 错误处理也要释放锁！ */
        spin_unlock_irqrestore(&g_scheduler_lock, flags);
        return -1;
    }

    spin_unlock_irqrestore(&g_scheduler_lock, flags);
}
```

### 问题 10：中断上下文中的调度

**症状**：定时器中断中设置 `need_resched`，但调度没有发生。

**原因**：调度器可能只在某些检查点检查 `need_resched`，如果检查点设置不当，调度会延迟很久。

**解决方案**：

在关键检查点添加调度检查：

1. 中断返回前
2. 系统调用返回前
3. 自旋锁释放后
4. 主动让出 CPU 时

```c
/* 在中断处理返回前 */
void irq_handler_common(void) {
    /* ... 处理中断 ... */

    /* 检查是否需要调度 */
    if (sched_needs_reschedule()) {
        schedule();
    }

    /* ... 恢复上下文，返回 ... */
}
```

## 调试工具和技巧

### 技巧 1：使用编译时断言

对于编译时可以确定的条件，使用 `static_assert`：

```c
/* 确保调度策略数量正确 */
static_assert(SCHED_MAX == 2, "SCHED_MAX must be 2");

/* 确保优先级范围正确 */
static_assert(PRIO_MAX == 0, "PRIO_MAX must be 0");
static_assert(PRIO_MIN == 127, "PRIO_MIN must be 127");
```

### 技巧 2：使用运行时断言

对于运行时条件，使用 `assert`：

```c
void sched_enqueue_task(struct pcb* pcb, bool head) {
    assert(pcb != NULL);
    assert(pcb->sched_entity.sched_class != NULL);
    assert(pcb->sched_entity.policy < SCHED_MAX);

    /* ... */
}
```

### 技巧 3：使用统计信息

收集调度统计信息有助于理解系统行为：

```c
typedef struct sched_stats {
    uint64_t nr_schedules;      /* 总调度次数 */
    uint64_t nr_rr_schedules;   /* RR 调度次数 */
    uint64_t nr_prio_schedules; /* Priority 调度次数 */
    uint64_t nr_preemptions;    /* 抢占次数 */
    uint64_t nr_time_slices;    /* 时间片用完次数 */
} sched_stats_t;

void sched_print_stats(void) {
    klog_info("[SCHED] Statistics:\n");
    klog_info("[SCHED]   Total schedules: %llu\n", sched_stats.nr_schedules);
    klog_info("[SCHED]   RR schedules: %llu\n", sched_stats.nr_rr_schedules);
    klog_info("[SCHED]   Priority schedules: %llu\n", sched_stats.nr_prio_schedules);
    klog_info("[SCHED]   Preemptions: %llu\n", sched_stats.nr_preemptions);
}
```

### 技巧 4：使用 GDB 调试

如果使用 QEMU + GDB 调试，可以在关键函数设置断点：

```
(gdb) break schedule
(gdb) break sched_pick_next_task
(gdb) break rr_task_tick
(gdb) continue
```

在断点处检查变量：

```
(gdb) print scheduler.current
(gdb) print scheduler.rq[0].nr_running
(gdb) print scheduler.current->sched_entity.time_slice
```

1. **框架设计**：实现了模块化的调度类框架，支持多种调度算法共存

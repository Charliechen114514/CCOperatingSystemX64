# 后端抽象与串口输出 —— Stage 10 可扩展架构实战指南

## 前言

上一篇文章我们实现了一个 `kprintf`，但是有一个问题：所有的输出都硬编码到串口上了。

你想想，如果以后你想：
- 同时输出到串口和 VGA
- 把日志写到文件
- 通过网络发送日志

难道要为每种情况都写一个不同的 `kprintf` 吗？那也太麻烦了。

所以，我们需要一个更灵活的设计：**后端抽象**。

这个想法很简单：把"格式化"和"输出"分开。`kprintf` 只负责格式化，至于输出到哪里，由后端决定。

这样，将来你想添加新的输出方式，只需要写一个新的后端，注册一下就行了。不需要修改任何现有的代码。

准备好了吗？我们开始。

## 第一步：设计后端抽象接口

首先，我们来定义后端接口。一个后端需要做什么？

1. **输出字符串**：接收格式化好的字符串，输出到具体设备
2. **检查就绪状态**：判断后端是否可以工作

创建 `kernel/klogs/kprintf_backends.h`：

```c
/**
 * @file kprintf_backends.h
 * @brief kprintf 后端抽象接口
 * @date 2026-02-16
 */

#pragma once
#include "defines/types.h"

/**
 * @brief 后端类型枚举
 */
typedef enum {
    KLOG_BACKEND_NONE = 0,
    KLOG_BACKEND_SERIAL,
    KLOG_BACKEND_VGA,
    KLOG_BACKEND_COUNT  // 用于边界检查
} klog_backend_t;

/**
 * @brief 后端操作接口
 *
 * 每个后端需要实现这个结构体中的函数
 */
typedef struct {
    /**
     * @brief 输出字符串
     *
     * @param str 要输出的字符串
     * @param level 日志级别（-1 表示无级别，使用默认颜色）
     */
    void (*process)(const char* str, int level);

    /**
     * @brief 检查后端是否就绪
     *
     * @return true 后端可以工作
     * @return false 后端未初始化或不可用
     */
    bool (*is_ready)(void);
} KLogBackendOps;

/**
 * @brief 注册后端
 *
 * @param backend 后端类型
 * @param ops 后端操作接口
 */
void klog_register_backend(klog_backend_t backend, const KLogBackendOps* ops);

/**
 * @brief 获取后端操作接口
 *
 * @param backend 后端类型
 * @return 后端操作接口，如果后端未注册则返回 NULL
 */
const KLogBackendOps* klog_get_backend_ops(klog_backend_t backend);

/**
 * @brief 设置默认后端
 *
 * @param backend 后端类型
 */
void klog_set_default_backend(klog_backend_t backend);

/**
 * @brief 获取默认后端
 *
 * @return 默认后端类型
 */
klog_backend_t klog_get_default_backend(void);
```

**为什么用函数指针？**

你可能会问。函数指针让我们可以在运行时决定调用哪个函数。这样，不同的后端可以有不同的实现，但 `kprintf` 不需要知道具体是哪个后端。

这是一个典型的**多态**设计，在 C 语言中用函数指针来实现。

## 第二步：实现后端注册表

现在我们来实现后端管理系统。

创建 `kernel/klogs/kprintf_backends.c`：

```c
/**
 * @file kprintf_backends.c
 * @brief kprintf 后端管理实现
 * @date 2026-02-16
 */

#include "kprintf_backends.h"

// 后端注册表（存储所有已注册的后端）
static const KLogBackendOps* g_backend_ops[KLOG_BACKEND_COUNT] = {NULL};

// 默认后端
static klog_backend_t g_default_backend = KLOG_BACKEND_NONE;

void klog_register_backend(klog_backend_t backend, const KLogBackendOps* ops) {
    if (backend >= KLOG_BACKEND_COUNT) {
        return;  // 无效的后端类型
    }

    g_backend_ops[backend] = ops;
}

const KLogBackendOps* klog_get_backend_ops(klog_backend_t backend) {
    if (backend >= KLOG_BACKEND_COUNT) {
        return NULL;  // 无效的后端类型
    }

    return g_backend_ops[backend];
}

void klog_set_default_backend(klog_backend_t backend) {
    g_default_backend = backend;
}

klog_backend_t klog_get_default_backend(void) {
    return g_default_backend;
}
```

**这个设计的优点**

1. **类型安全**：使用枚举而不是字符串，编译器会帮我们检查错误
2. **O(1) 查找**：直接用数组索引，不需要遍历
3. **可扩展**：添加新后端只需要：
   - 在枚举中添加新类型
   - 实现后端操作接口
   - 调用 `klog_register_backend` 注册

## 第三步：实现串口后端

现在我们来实现第一个后端：串口后端。

创建 `kernel/klogs/backends/serial_backends.h`：

```c
/**
 * @file serial_backends.h
 * @brief 串口后端接口
 * @date 2026-02-16
 */

#pragma once
#include "kprintf_backends.h"

/**
 * @brief 初始化串口后端
 *
 * @return true 初始化成功
 * @return false 初始化失败
 */
bool klog_serial_backend_init(void);

/**
 * @brief 获取串口后端操作接口
 *
 * @return 后端操作接口
 */
const KLogBackendOps* klog_serial_backend_get_ops(void);
```

创建 `kernel/klogs/backends/serial_backends.c`：

```c
/**
 * @file serial_backends.c
 * @brief 串口后端实现
 * @date 2026-02-16
 */

#include "serial_backends.h"
#include "driver/serial/serial.h"

// 串口就绪标志
static bool g_serial_ready = false;

// 串口输出函数
static void serial_process(const char* str, int level) {
    if (!g_serial_ready) {
        return;  // 串口未初始化
    }

    // 遍历字符串，逐个字符输出
    while (*str != '\0') {
        serial_write(*str);
        str++;
    }
}

// 检查串口是否就绪
static bool serial_is_ready(void) {
    return g_serial_ready;
}

// 后端操作接口
static const KLogBackendOps serial_backend_ops = {
    .process = serial_process,
    .is_ready = serial_is_ready,
};

bool klog_serial_backend_init(void) {
    // 初始化串口
    serial_init();
    g_serial_ready = true;
    return true;
}

const KLogBackendOps* klog_serial_backend_get_ops(void) {
    return &serial_backend_ops;
}
```

**为什么不用 `serial_write_string`？**

你可能会问。使用 `serial_write` 逐字符输出有两个好处：

1. **更底层**：不依赖 `serial_write_string` 的实现
2. **灵活性**：可以在 `process` 函数中添加额外的处理逻辑（比如颜色支持）

## 第四步：更新 kprintf 使用后端

现在我们需要修改 `kprintf.c`，让它使用后端系统而不是直接调用串口函数。

更新 `kernel/klogs/kprintf.c`：

```c
/**
 * @file kprintf.c
 * @brief kprintf 核心实现（使用后端抽象）
 * @date 2026-02-16
 */

#include "kprintf.h"
#include "kprintf_backends.h"
#include "kprintf_config.h"
#include "base/strhelpers.h"

// 格式化缓冲区
static char g_buffer[KPRINTF_BUFFER_SIZE];

// 数字转换缓冲区
static char g_format_buffer[32];

// format_string 函数保持不变
static int format_string(char* buffer, size_t size, const char* format, va_list args) {
    // ... 和之前一样的实现 ...
    // （省略，和上一篇完全一样）
}

void kvprintf(klog_backend_t backend, const char* format, va_list args) {
    // 获取后端操作接口
    const KLogBackendOps* ops = klog_get_backend_ops(backend);
    if (ops == NULL || !ops->is_ready()) {
        return;  // 后端未注册或未就绪
    }

    // 格式化字符串
    format_string(g_buffer, KPRINTF_BUFFER_SIZE, format, args);

    // 使用后端输出（level = -1 表示无级别）
    ops->process(g_buffer, -1);
}

void kprintf(klog_backend_t backend, const char* format, ...) {
    va_list args;
    va_start(args, format);
    kvprintf(backend, format, args);
    va_end(args);
}
```

**注意变化**

1. **不再直接调用串口函数**：而是通过后端接口
2. **检查后端就绪状态**：避免使用未初始化的后端
3. **使用默认后端**：如果传入 `KLOG_BACKEND_NONE`，可以使用默认后端

## 第六步：编写测试

现在我们来测试后端系统是否正常工作。

在 `kernel_main.c` 中添加测试代码：

```c
#include "klogs/kprintf.h"
#include "klogs/backends/serial_backends.h"

void test_backends(void) {
    // 初始化串口后端
    klog_serial_backend_init();

    // 注册串口后端
    klog_register_backend(KLOG_BACKEND_SERIAL, klog_serial_backend_get_ops());

    // 设置默认后端
    klog_set_default_backend(KLOG_BACKEND_SERIAL);

    // 测试直接指定后端
    kprintf(KLOG_BACKEND_SERIAL, "Test 1: Direct backend specification\n");

    // 测试使用默认后端
    kprintf(KLOG_BACKEND_SERIAL, "Test 2: Using default backend\n");

    // 测试格式化输出
    kprintf(KLOG_BACKEND_SERIAL, "Test 3: %s = %d (0x%x)\n", "answer", 42, 42);

    // 测试未注册后端（应该没有输出）
    kprintf(KLOG_BACKEND_VGA, "Test 4: This should not appear\n");

    // 测试未就绪后端
    kprintf(KLOG_BACKEND_SERIAL, "Test 5: Backend is ready\n");
}

void kernel_main(void) {
    // ... 其他初始化代码 ...

    test_backends();

    // ... 其他代码 ...
}
```

编译并运行：

```bash
cd build

./run.sh
```

你应该在串口输出中看到：

## 第七步：演示如何添加新后端

现在我们来演示一下添加新后端有多简单。我们来实现一个"空后端"（什么都不做），这在测试时很有用。

在 `kprintf_backends.c` 中添加：

```c
// 空后端：什么都不做
static void null_process(const char* str, int level) {
    (void)str;   // 避免未使用参数警告
    (void)level;
}

static bool null_is_ready(void) {
    return true;  // 空后端总是就绪
}

static const KLogBackendOps null_backend_ops = {
    .process = null_process,
    .is_ready = null_is_ready,
};
```

在 `klog_register_backend` 之后添加：

```c
// 自动注册空后端
void klog_backends_init(void) {
    klog_register_backend(KLOG_BACKEND_NONE, &null_backend_ops);
}
```

在 `kprintf_backends.h` 中添加声明：

```c
/**
 * @brief 初始化后端系统（注册默认后端）
 */
void klog_backends_init(void);
```

现在你可以在初始化时调用：

```c
klog_backends_init();  // 注册空后端
klog_serial_backend_init();
klog_register_backend(KLOG_BACKEND_SERIAL, klog_serial_backend_get_ops());
```

⚠️ **注意**

`KLOG_BACKEND_NONE` 现在是一个有效的后端（空后端），而不是"无后端"。如果需要表示"无后端"，可以检查返回的 `ops` 是否为 `NULL`。

## 踩坑预警

### 坑 1：后端未初始化

```c
// 错误写法
klog_register_backend(KLOG_BACKEND_SERIAL, klog_serial_backend_get_ops());
kprintf(KLOG_BACKEND_SERIAL, "Hello\n");  // 串口未初始化！

// 正确写法
klog_serial_backend_init();  // 先初始化
klog_register_backend(KLOG_BACKEND_SERIAL, klog_serial_backend_get_ops());
kprintf(KLOG_BACKEND_SERIAL, "Hello\n");
```

后端的 `is_ready()` 函数会检查这一点，但最好在注册前初始化。

### 坑 2：后端数组越界

```c
// 危险写法
klog_register_backend(999, &ops);  // 越界！

// 安全写法
if (backend >= KLOG_BACKEND_COUNT) {
    return;  // 拒绝无效后端
}
```

我们在 `klog_register_backend` 中检查了这一点，但调用者也应当注意。

### 坑 3：静态变量初始化顺序

```c
// 如果这样写：
static const KLogBackendOps* g_ops = &my_ops;  // 可能在 my_ops 定义之前！

// 更安全的做法：
static const KLogBackendOps* g_ops = NULL;

void init(void) {
    g_ops = &my_ops;  // 显式初始化
}
```

C 语言的静态变量初始化顺序是不确定的，最好显式控制初始化流程。
